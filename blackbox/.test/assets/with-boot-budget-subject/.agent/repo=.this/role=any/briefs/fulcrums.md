# fulcrums

the heavier of the two subjects. it carries the full argument behind each fork this
role has weighed, so it is long on purpose — a selection that adds it crosses the cap
the spec declares, where a selection that omits it does not.

## .the first fork

a fork is a point where a small choice tips a large outcome. the record states the
options fairly, names the one taken, and says what a reversal would cost. a reader who
disputes the take reads the argument rather than re-derives it.

## .the second fork

the same shape again: two options, one taken, a rework grade beside it. the value of
the record is that it survives the round that made it, so a later reviewer can reopen
the question without a second payment for the analysis.

## .the third fork

and again. the point of the repetition here is bulk rather than substance — this file
exists to make one subject measurably heavier than its peer, so a budget can sit
between them and a `--subject` selection can decide which side of it a boot lands on.

## .the fourth fork

each entry states the question, the options, the take, the rework grade, and the
confidence. a row with no confidence is a claim with no error bar, which reads as
settled when it was a guess.

## .the fifth fork

the last one. a reader who reached this line has read more tokens than the lighter
subject costs in total, which is the whole arrangement this fixture is built to make
checkable.
