# domain.term.choice.reason: spawn.leaf

## .etymology

**leaf** is the tree word, the peer of `spawn.depth`. a spawn chain is a tree; a leaf is the node
with no children. the ehmpathy/rhachet#577 vision states its rule in the same words — *reviewer
clones as leaves* — so the term is adopted, never coined.

the rejected peers:
- `terminal`. overloaded: a tty, the very thing `spawn.depth` reads at the enroll door
- `sink`. a stream word; a leaf still answers upward
- `endpoint`. an api word
- `final`. reads as a state in time (the last call), where a leaf is a kind of spawn

## .disputes

### dispute: mark the leaf by the roleset — raised 2026-10-20 — status: RESOLVED (the door is the mark)
- raised.by  = the S68 patch storefronts sent as a reference
- claim      = a clone that holds the `reviewer` role is the reviewer; mark it by role
- counter    = the ambient actor carries `reviewer`, so every everyday `claude` would read as a
               leaf and could never stand up a reviewer of its own — the stall S68 set out to cure
- resolution = the door decides: a print-mode enroll and every repl child are leaves (F23)

### dispute: a repl child is a work brain — raised 2026-10-20 — status: RESOLVED (it is a leaf)
- raised.by  = the S68 patch, which marks only a `-p` enroll
- claim      = only an enroll mints a clone, so only an enroll needs the mark
- counter    = `rhx review` from a reviewer started one brain per rubric unchecked — the fan-out
               the wish names. a repl brain is called to answer, which is a reviewer's shape
- resolution = every repl child carries the mark
