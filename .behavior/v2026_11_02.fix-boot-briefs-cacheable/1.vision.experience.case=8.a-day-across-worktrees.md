## .narrative

one realistic day, eight boundaries crossed in one walk:

the driver measures a baseline before the change lands. a maintainer lands the fix; ci's clamps are green.
the driver opens a clone in worktree A — a cold write, correct. ten minutes later, a clone in worktree B,
same branch base, same roles — call 1 reads the boot. turns in B read it every call. in B the driver edits
one `repo=.this` brief and restarts — only the local tail re-writes; the published prefix still reads. that
afternoon a maintainer, on a new branch, adds a "rendered at" line to the intro; the render clamp turns red
before any clone ever pays for it. a week later a claude upgrade lands; the assembly clamp, not the
driver's bill, is the first to know whether the vendor moved a volatile value ahead of the boot.

the risk the density brief warns of sits at the seams: [t2]→[t3] is the cross-worktree seam (render ×
spawn door × brain-cli assembly × api cache); [t5] is the boundary-split seam, which only holds if the
split adds a breakpoint (case=5 🟡); [t7] is the vendor seam.

## .[tn] sketch

```
given a repo with worktrees A and B on one branch base, one role set
  when [t0] the driver measures a clone in A, before the change   # baseline boundary
    then `rhx clone.cache.usage` row 1 is a write of ~the boot's tokens
  when [t1] the fix lands and ci runs
    then the render, spawn, and assembly clamps are green          # clamp boundary
  when [t2] a clone starts in A
    then call 1 writes the boot (a cold cache is correct)          # ttl boundary
  when [t3] within the TTL, a clone starts in B
    then call 1 reads the boot from cache                          # cross-worktree seam
  when [t4] B sends call N > 1
    then each call reads the boot                                  # per-turn boundary
  when [t5] a repo=.this brief is edited in B, and B's clone restarts
    then call 1 reads at least the published prefix ¹             # partial-prefix seam
  when [t6] a maintainer plants a timestamp in the intro
    then the render clamp fails and names the byte                 # leak rejection
  when [t7] a claude upgrade moves the cwd into the system block, ahead of the boot
    then the assembly clamp fails and names the request field      # vendor seam
```

¹ only if the boundary line adds a breakpoint (open question 2 in the yield); else the reorder is harmless
and [t5] re-writes the whole boot once.
