# 1.vision.experience.case=3.volatile-value-reddens-the-clamp

> cell `* × leak.volatile` · actor maintainer · feel sharp · care critipath

## .narrative

a maintainer adds a friendly "rendered at 2026-11-02T09:14" line to the rhachet intro, so a human who
reads `boot.md` can tell how fresh it is. every clone still boots and answers; every behavior test is
green. nobody would notice — except the bill, where each start would now write ~137k–185k tokens again.

instead, `npm run test:integration` goes red before the pr is up. the failure reads like a diff, not a
riddle: the first byte that differs, the file it came from (`boot.md`, the intro block), and both values
side by side — `rendered at 2026-11-02T09:14` vs `rendered at 2026-11-02T09:15`. the maintainer sees at
once that a clock leaked into the prefix, moves the date to a file the boot does not include, and the
clamp goes green. a minute lost, a month of cache writes saved, and they learned where volatile values
may not live.

the same encounter waits at two other seats, each with its own clamp:

| source | example | clamp grain |
|---|---|---|
| our render | a "rendered at" line in the intro; a skill header that prints `$PWD` | integration — `boot.md` bytes |
| our spawn | a spawn change that puts a path, a date, or a serial into the system prompt we pass | integration — the spawn argv and the file it names |
| the brain-cli | a claude upgrade that puts the cwd or a date into the system block, ahead of the boot | acceptance — the raw request claude sends |

- **render clamp** (extant, keep) — `setBrainDirBoot.integration.test.ts` [t1]–[t3]: byte-equal across
  role order, re-render, and two repo paths
- **spawn clamp** (owed) — for two temp repos at different paths with one role set, the system prompt
  rhachet hands claude (the spawn argv's prompt flag and the bytes of the file it names) is byte-equal
- **assembly clamp** — two real brain-cli spawns with **different prompts** and
  `OTEL_LOG_RAW_API_BODIES=file:<dir>`; the tools and system blocks are byte-equal, and the second session
  reads the boot from cache. this is the only clamp that sees a vendor change. held for one repo by
  `brain-dir-boot.journey.acceptance.test.ts` [t3] (M2); the two-repo half, four spawns at two paths, is
  measured byhand by `rhx boot.cache.probe --across worktree` and still owed as a clamp

each failure names the first byte that differs, the source file or request field, and both values, so the
fix is one look away.

## .[tn] sketch

```
given two temp repos with the same role set, at different absolute paths
  [t0] the boot renders for each, at two different times
    then the two boot.md are byte-equal                         # render clamp
    then the system prompts rhachet passes are byte-equal       # spawn clamp
  [t1] two clones spawn in each, one after another, with different prompts and raw request logs on
    then the tools and system blocks are byte-equal across all four    # assembly clamp
    then each second clone reads the boot from cache
  [t2] a maintainer plants a timestamp in the rhachet intro; the clamps run
    then the render clamp fails
    then the error names the first byte that differs, its file, and both values
  [t3] the maintainer moves the date out of the boot; the clamps run
    then all three are green
  [t4] a spawn change plants a worktree path in the system prompt; the clamps run
    then the spawn clamp fails and names the path
    then the render clamp stays green — the defect is named at its own seat
```
