# 1.vision.experience.case=5.local-edit-costs-only-the-suffix

> cell `session.same-actor.same-tree × edit.repo-local` · actor driver · feel happy · care alterpath

## .narrative

a driver edits one `repo=.this/role=any` brief. today roles sort by slug alone, so `.this/any` renders
first, and an edit voids the cache for every byte after it — the whole published corpus re-writes.

after: published roles render first, then a `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` line, then `repo=.this`
roles. claude splits the system prompt at that line into two blocks, each with its own breakpoint
(documented, v2.1.275+). a local edit then changes only the second block; the published block still reads
from cache. published roles change only on upgrade; local briefs change on any branch — the stable bytes go
in front.

🟡 the split adds a breakpoint. the measure shows two in the system block already and one on the last
message; the api allows four. the blueprint measures it before the split is claimed as a win. without the
split, the reorder is harmless and gains naught.

## .[tn] sketch

```
given an actor whose boot holds published roles and repo=.this roles
  [t0] the boot renders
    then every published role precedes every repo=.this role
    then one boundary line separates them
  [t1] a clone starts and its first response begins
    then both blocks are written, once
  [t2] the driver edits a repo=.this brief; the boot re-renders
    then the published block is byte-equal to [t0]
  [t3] a new clone starts within the TTL
    then call 1 reads the published block from cache
    then call 1 writes only the repo=.this block
  [t4] a second clone starts after [t3]'s first response
    then call 1 reads both blocks from cache
```
