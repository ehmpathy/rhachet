# vision: every clone's boot briefs land in a cache-eligible prefix

## .the measure first

measured 2026-11-02, haiku, actor `-driver`, with `rhx boot.cache.probe` (two `-p` sessions back-to-back,
**different prompts**, as two real sessions open):

| | boot prefix | session 2 cache write | session 2 cache read |
|---|---|---|---|
| **today** — boot via `CLAUDE.md → @boot.md` | 121,069 tokens | 125,844 | 11,237 |
| **candidate** — boot as the system prompt | 120,873 tokens | 4,779 | 132,116 |

today, a new session re-writes the whole boot at the cache-write rate, every time. with the boot in the
system prompt, it reads it. within one session, later turns already read the boot (live session, calls
2–23 read 197k–243k each) — that half of the wish holds today and must keep to hold.

## .why — read from the raw request, not inferred

`OTEL_LOG_RAW_API_BODIES` (documented) logged both requests. claude code sends:

| part | content | per-session? |
|---|---|---|
| tools | tool definitions | no |
| system 📌 | ~218 chars base (`--system-prompt ''`) | no |
| messages[0] [0] | SessionStart hook — permissions; prints an absolute log path (names worktree + actor) | per worktree |
| messages[0] [1] | SessionStart hook — behaver boot-behavior; 13KB, so persisted to `tool-results/hook-<uuid>-stdout.txt` | **per session** |
| messages[0] [2] | environment (cwd, platform) | per worktree |
| messages[0] [3]–[7] | model, deferred tools, agent types, skills, token budget | no |
| messages[0] [8] | **the boot** — `CLAUDE.md` memory, 398,041 chars | no |
| messages[0] [9]–[11] | user email + git status, date, attribution | per repo state / day |
| messages[0] [12] 📌 | the prompt | **per session** |

📌 = a `cache_control` breakpoint. there are two: the system block and the last block of the first message.
a new session reads the cache only up to the last breakpoint whose whole prefix matched an earlier one.
the boot sits between the two, behind per-session hook output and ahead of a per-session prompt — so no
cleanup of the hooks could rescue it: the prompt alone differs. the render itself is clean (no time, env,
cwd, uuid; three extant clamps, `setBrainDirBoot.integration.test.ts` [t1]–[t3]).

⇒ the door is the defect, not the corpus. in the system prompt, the boot sits ahead of the system
breakpoint and ahead of every per-session and per-worktree value.

## .the outcome world

### a day in the life

the driver opens clones in eight worktrees, one role set. the first clone of the hour writes the boot
(~121k tokens). every other clone, in any of the eight worktrees ¹, and every restart, reads it at a tenth
of the input rate. hooks keep their output; the cwd, the git status, the prompt, all vary freely — none of
them sits in front of the boot any more. `rhx boot.cache.probe` shows it in one call.

¹ measured 2026-11-02, `rhx boot.cache.probe --across worktree`: a second session in a temp worktree at
another path reads 132,111 and writes 4,147.

### before / after

| | before | after |
|---|---|---|
| new session, same roles, same worktree | boot re-written (125,844) | boot read (132,116) |
| new session, another worktree | boot re-written | boot read (132,111) ¹ |
| later turns of one session | boot read | boot read (clamped) |
| a local brief edit | whole boot re-writes once | only the local tail re-writes ² |
| a volatile value enters the boot | silent; the bill rises | a clamp goes red and names the byte |
| how a driver checks | by hand, in a jsonl | `rhx boot.cache.probe`, `rhx clone.cache.usage` |

² via the documented `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` line: published roles before it, `repo=.this`
roles after, each part with its own breakpoint (F3)

### the aha

"the boot held no volatile byte — but we filed it behind the prompt." the corpus was byte-stable all
along; it sat in the one part of the request that can never be shared, after the hooks and before the
breakpoint that only a byte-identical first message can reach.

## .the contract, testdriven

```sh
# measure — before and after, one call
rhx boot.cache.probe --roles -driver
#   ├─ first run = <n> tokens of prefix
#   ├─ second run = <n> tokens of prefix
#   │  ├─ 4811 cache write
#   │  └─ 132111 cache read
#   └─ ✓ the second session read the boot from cache
# .note = no "boot prefix" line: once the boot rides the system prompt, no baseline run isolates it
#   (a passthrough `--system-prompt ''` is refused by the guard). the yield derives the figure from
#   two runs: the after session-2 read less the before session-2 read
rhx boot.cache.probe --roles -driver --diff     # + the request's block order, breakpoints, first byte that differs

# per turn, on a live clone
rhx clone.cache.usage --clone .agent/.actors/<actor>/clones/serial=<uuid>

# enroll — no new flag; the spawn passes the actor's boot.md as the system prompt
rhx enroll claude --roles -driver
```

  the hooks and before the bookmark at the end of your first message — so only a word-for-word identical
  first message could reuse them. we moved them in front of the first bookmark."*

## .evaluation

| goal (from the wish) | met by |
|---|---|
| boot prefix tokens, cache-creation, cache-read per turn, before and after, on a real clone | `rhx boot.cache.probe` (prefix, per session) + `rhx clone.cache.usage` (per turn); before = this round |
| byte-stable across turns and sessions with the same role set; no per-session value inside | the corpus already is; the door change moves every per-session value behind it |
| a clamp that goes red if a volatile value enters | render clamp (extant) + spawn clamp + assembly clamp on the raw request (case=3) |
| the extant boot keeps every brief | the same `boot.md` bytes, by a different door; entry-set clamp (case=4) |

pros: measured, not argued (~26× less cache write per start); no brief cut, no corpus change; the
system prompt is also the more authoritative seat (`define.claude-md-vs-system-prompt`); the size limit
that persists large hook output (13KB → a 2KB preview) never touches the boot.

cons, named:
- **the door changes.** the wish names "the CLAUDE.md render" (F2). the corpus is kept whole; its door is not
- **recorded once.** claude records the system prompt at a session's first request; a `--resume` keeps the
  boot it started with until its first compaction. today the boot is re-read at `/compact` and restart; after,
  at restart and at the first compaction of a resumed session. the actor's sync invariant (live clones
  pick up changes at next spawn) still holds
- **a vendor detail.** breakpoint placement is claude's, not ours, and undocumented. the assembly clamp is the
  honest answer: if claude moves it, the clamp sees it before the bill does
- **a layout change.** `define.brain-dir-layout-is-one-for-every-actor` names `CLAUDE.md → AGENTS.md →
  @boot.md` as the door in every actor dir. the new door means `AGENTS.md` stops its `@boot.md` import (else
  the boot loads twice), in every actor dir at once (`rule.forbid.brain-dir-layout-divergence`), and that
  brief is revised with it. `boot.md` stays the one real file; only who reads it changes

### edgecases → pit of success

| edgecase | guard |
|---|---|
| a passthrough `--system-prompt[-file]` | already refused (`assertBrainCliPassthroughLeavesSystemPromptOwned.ts`); rhachet owns the seat |
| a passthrough `--append-system-prompt[-file]` | lands after the boot; the boot's prefix holds |
| boot.md also read as memory (double boot) | the door is one or the other, never both — case=4 clamps the entry set once |
| two role sets | distinct system prompts ⇒ distinct entries, by construction (case=_ ⁴) |
| a resumed session after a role change | keeps its recorded boot until compaction — same as today's system prompt; named in the con above (questions 16, 17) |
| N clones of one role set start at once, cold | the api shares an entry only after the first response starts; rhachet holds the rest of a fleet until the first clone's first response begins (case=9) |
| `-p` vs interactive | the system block is the same in both, so one entry serves both (to measure) |
| the boot exceeds the os argv limit | pass it by file (`--append-system-prompt-file` / `--system-prompt-file`), never inline |

## .open questions & assumptions

assumptions, each with its evidence:
- the ~218-char base system block holds no per-worktree value — it read 11,237 from cache across every probe,
  in every mode, so it is shared today
- the system breakpoint stays where it is measured today — no contract; the assembly clamp watches it
- haiku stands for the models clones run — the request shape is claude code's, not the model's; partial
  evidence: this repo actor's own opus session read only 11,222 on call 1, the same miss shape. the
  candidate was measured on sonnet and opus at execution, with the same win (5.1 yield)
- clones start within the TTL of one another — 1h on a subscription's main conversation, 5m on an api key.
  the many-parallel-clones pattern is inferred from PR #398, not stated in this wish; with one clone a day,
  the gain is per-turn only, which holds today
- the boot's authority holds in the new seat — today claude wraps the memory with "Codebase and user
  instructions are shown below … These instructions OVERRIDE any default behavior and you MUST follow them
  exactly as written". in the system prompt that wrapper is absent. `define.claude-md-vs-system-prompt`
  rates the system seat the more authoritative, but no adherence was measured

## .what is awkward

- the wish's own words name the door it must leave (F2). the vision keeps the corpus and moves the door; that
  is the wisher's call, and the measure is the argument
- a prior route chose `CLAUDE.md` over the system prompt on purpose. the reason (recorded once) is still
  true; what changed is that we now know the cost of the other side
- the acceptance test M2 passes while real sessions miss: it holds the prompt fixed. a test that agrees with
  the defect is the strongest case for the assembly clamp on distinct prompts
- the behaver boot-behavior hook (13KB) is persisted to disk with a 2KB preview, so most of what it prints
  never reaches the brain. outside this wish and outside this repo — caught as a dream for bhuild
