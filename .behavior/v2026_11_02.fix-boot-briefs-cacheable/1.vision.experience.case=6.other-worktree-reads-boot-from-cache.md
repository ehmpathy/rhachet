## .narrative

the driver runs clones in many worktrees of one repo, one role set, one branch base. today each start in
each worktree re-writes the boot: case 1's miss holds in one worktree already, and across worktrees more
bytes ahead of the boot differ — the cwd in the environment block, and absolute paths that hook output
prints (the permissions hook names the worktree and the actor dir).

after: the boot sits in the system prompt. the request's system block then holds the ~218-char base and
the boot — no path, no cwd, no hook output; all of those ride in the first message, after the system
breakpoint. a clone in worktree B, started within the TTL of a clone in worktree A with the same role set,
reads the boot from cache on call 1.

the prediction follows from the measured request shape; the blueprint owes the two-worktree measure. the
actor dir stays the owner of its `boot.md` (`rule.forbid.per-clone-config`); only the door changes.
