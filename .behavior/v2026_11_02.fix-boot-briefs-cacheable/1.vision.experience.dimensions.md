# 1.vision.experience.dimensions

> the experience space of "a clone's boot lands in a cache-eligible prefix", factored into orthogonal
> dimensions. the inventory (`1.vision.experience.case=_.md`) walks their product.

## .the actors

| actor | encounters the boot as |
|---|---|
| **clone** | the brain-cli process; reads `boot.md` once at spawn, via `--system-prompt-file`, pays per call |
| **driver** | the human or robot who enrolls clones and pays the bill; measures it |
| **maintainer** | the rhachet contributor who edits the render; the clamp test guards them |

## .D1 — reuse grain (when is the boot read again?)

| value | sense |
|---|---|
| `turn` | call N>1 of one session |
| `compact` | the first call after `/compact` in one session |
| `resume` | the first call of a session reopened via `--resume` / `--continue` |
| `session.same-actor.same-tree` | a fresh session of the same actor, same worktree, after a prior session's write landed, within TTL |
| `session.same-roles.other-tree` | a fresh session with the same role set, another worktree or repo, after a prior write landed, within TTL |
| `session.concurrent` | N fresh sessions with the same role set that start at once, cold — no prior write has landed |
| `session.other-roles` | a fresh session with a different role set |
| `session.after-ttl` | a fresh session after the cache TTL lapsed |

`session.concurrent` is the time axis folded into D1: the two `session.same-*` values are sequential (a
write landed first); `concurrent` is the race where every start is cold at once. a separate time axis
would add only this one value, so it lives here.

## .D2 — boot content delta (what changed since the last read?)

| value | sense |
|---|---|
| `unchanged` | byte-identical render |
| `edit.repo-local` | a `repo=.this` brief edited |
| `edit.published` | a published role upgraded |

## .D3 — actor identity form

`repo` (ambient) · `hash` (bare enroll) · `slug` · `derived`. per `catalog.of=actor-clone-design`, each
form owns one `boot.md`; the form decides *which* file, never *how* it is cached. ⇒ D3 collapses:
every cell holds for every form, proven once per form at the render, not per cache cell.

## .D4 — render defect (did the render or the spawn break the prefix?)

| value | sense |
|---|---|
| `none` | the render and spawn are clean |
| `leak.volatile` | a per-turn / per-session / per-host value entered the prefix |
| `drop.brief` | a brief booted today is absent from the render |
| `quote.boundary` | a role brief quotes the render's boundary line, so the prefix would split at the wrong place |

a defect is caught by a clamp at render, spawn, or assembly time — before any session exists. so for
each D4 defect, D1 × D2 collapses to one cell: the defect is the experience, the
reuse grain is moot. D4 is orthogonal to D2 in that a defect can ride an edit or no edit; it is the clamp
grain that sees it, never the reuse grain.

## .D5 — first-request channel (how does a clone send its first request?)

| value | sense |
|---|---|
| `say` | a `rhx clone say` to an `--async` clone; the fleet gate holds it (F5) |
| `spawn.prompt` | `rhx enroll … -p` or `--await -p`: the first request rides the spawn itself |
| `human.typed` | a human types into an attached clone's pty; no `say` runs |

D5 varies only `session.concurrent`: for a lone or sequential session the channel changes no cache
figure, since no peer is in flight to share with. so it adds two cells, both on `session.concurrent ×
unchanged` (`say` is case 9).

the `say` cell has six sub-paths of the gate itself, each its own row: a **gate fault** (the lead record
cannot be read, so the say goes unheld), a **later say** (a clone that already sent a request is never
held), **no boot** (an actor with no rendered `boot.md` has no boot to share, so the say goes at once and
no lead is claimed), a **stale lead** (a claim prunes the records of boots long gone), a **client
command** (a first say of `/model …` sends no request, so it neither claims nor waits), and a **raced
claim** (two first says at once: the read and the claim sit inside one mutex, so only one claims). they
are boundaries of case 9's cell, not values of a new axis.

## .observers — a lens on every cell, not an axis

| observer | sense |
|---|---|
| `measure` | the driver reads per-call usage (`rhx clone.cache.usage`, `rhx boot.cache.probe`) |
| `measure.no-history` | the driver points the measure at a clone with no transcript (a `-p` clone, a typo) |
| `measure.compact` | `rhx boot.compact.probe` — does `/compact` re-read a boot edit? (question 16) |
| `measure.resume` | `rhx boot.resume.probe` — does `--resume` send a boot edit? (question 17) |
| `measure.subagent` | `rhx boot.subagent.probe` — does a clone's subagent boot with the clone's boot? (F12) |
| `measure.adherence` | `rhx boot.adherence.probe` — does a clone follow a brief its boot carries? |
| `clamp.render` · `clamp.spawn` · `clamp.assembly` | the three clamp grains of D4, spelled in case=3 |

an observer sees a cell; it does not vary the cell. so it is not an axis of the product. an observer path
that a maintainer or driver lives through gets its own inventory row: `measure.no-history` (case 7, a
sharp path of the measure itself), and the four probes, one row for the three that settle a question and
one for adherence.

## .the walked product

D1 (8) × D2 (3) at D4 = `none` → 24 cells, less two: `session.other-roles` is one cell, since D2 ("what
changed since the last read") has no last read to compare for a role set's first start. so 22 cache
cells, plus the three D4 defects (`leak.volatile`, `drop.brief`, `quote.boundary`, 1 cell each), plus
the two D5 cells off `say` (`spawn.prompt`, `human.typed`), plus the gate's six sub-paths on the `say`
cell, plus three observer rows (`measure.no-history`; the three question probes; adherence), plus two
rows off the axes (a bare session's read of the boundary line; a brain cli between the version floor and
the first release that honors `CLAUDE_CODE_DISABLE_CLAUDE_MDS`). 38 rows, every one verdicted in the
inventory.
