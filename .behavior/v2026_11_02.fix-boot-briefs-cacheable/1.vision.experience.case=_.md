## .the defect rows — D4, any D1 × D2

| D4 | verdict |
|---|---|
| `leak.volatile` | case=3 demoed ³ |
| `drop.brief` | case=4 demoed ³ |

- ¹ **impossible** (nature) — a turn does not re-read `boot.md`; an edit lands at the next compact, resume,
  or spawn, never mid-turn
- ³ a defect row. a clamp catches it at render, spawn, or assembly time, before any session; one demo
  covers every D1 × D2
- ⁴ a session of role set B cold-writes its own boot and never reads A's. D2 asks "what changed since the
  last read", and B's content has no last read, so the row is one cell, not three. that B cannot read A's
  entry is nature: the cache keys on the exact prefix bytes, so no guard is owed. the safety half — a
  clone never boots briefs it was not enrolled with — is held by the render (one `boot.md` per actor),
  which case=4's snapshot already pins
- ⁵ two worktrees on different branches hold different `repo=.this` briefs, so their boots differ by
  content. the shared prefix is then only what precedes the first byte that differs — see case=5
- ⁶ under the system-prompt-file door a compact keeps the boot the clone read at spawn (question 16,
  answered: `rhx boot.compact.probe`, 2026-11-02; journey [t4] asserts it on `LIVE_BRAIN=1`, skipped by
  default, since a live clone reply spends the paid key). an edit reaches a clone at
  its next spawn, never at a compact (inventory case 11)
- ⁷ a resumed session sends the boot it first recorded, while the spawn's `boot.md` holds the edit
  (question 17, answered: `rhx boot.resume.probe`, 2026-11-03). an edit waits for a new session
- ⁸ a role brief that quotes the render's boundary line would split the cached prefix at the wrong
  place, silently. it is neither a volatile value nor an absent brief, so it is a D4 value of its own;
  enroll refuses it with exit 2 before any spawn, and the hint names the fix per role source. an
  alterpath: the literal is rare in prose, and the refusal is loud and names the way out

care rationale, by `freq × cost`: cases 6 and 9 are the wish's core load (many parallel clones, one role
set); each cold start pays ~137k–185k tokens at the write rate instead of the read rate (measured 0.274 vs
0.014 usd on haiku), so the cost compounds with frequency — critipaths. case 9 is the fleet's first minute,
case 6 is every start after it. case 5 is an alterpath — local edits are frequent, but each costs one boot
re-write per edit per TTL (money, never the goal), so the fallback is workable. case 7 is an alterpath —
rare, and the `-p` json is a ~0-cost route to the same figure.
