# 1.vision.experience.case=2.later-turns-read-boot-from-cache

> cell `turn × unchanged` · actor clone · feel happy · care critipath (every call)

## .narrative

a clone is mid-task. each tool result sends one more api call. the boot (~137k–185k tokens) sits at the
front of every one of them, and every call after the first reads it at the cache-read rate. this holds
today (measured: calls 2–23 of a live session each read 197k–243k from cache). the wish owes that it
keeps to hold: a fix for the cross-session case must not move the boot to a place that changes between
turns. the system prompt qualifies — claude records it at the first request and reuses it until compaction
(agent-sdk guide). within one session the new door must read the boot on every call, as the old one does.

## .[tn] sketch

```
given a clone of the repo actor, the boot in the system prompt
  [t0] call 1 is sent
    then the boot is read (warm) or written (cold), once
  [t1] a tool result returns; call 2 is sent
    then cache_read_input_tokens >= the boot's tokens
    then cache_creation_input_tokens is only the new turn's delta
  [t2] calls 3…N follow, each within the TTL of the last
    then each reads the boot; none re-writes it
  [t3] the driver runs `rhx clone.cache.usage --clone <dir>`
    then each row after the first shows a read that covers the boot
```
