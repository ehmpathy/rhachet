# wish: bound the keyrack daemon leak — idle-timeout the guard, widen `@all` discovery

## .source of record

**`ehmpathy/rhachet#442`** — read it FIRST and in full. it is the authoritative spec: it
carries the census, the file:line citations, the measured cost, and the rationale behind
each fix. this wish only bounds the scope; the issue holds the detail.

## .what

two defects in the keyrack daemon lifecycle, in order:

1. **replace the `hasEverHadKeys` guard with an idle-connection timeout**
   (`svc/src/domain.operations/scheduleAutoTermination.js:18-29`)
2. **widen `@all` discovery past the caller's own `homeHash`**
   (`infra/getAllKeyrackDaemonSocketPaths.js:23-26`)

item 3 in the issue (re-key daemon identity off login session + owner instead of HOME) is
explicitly marked optional and larger — **out of scope for this behavior.** if it proves
unavoidable, surface that rather than absorb it.

## .why

both defenses already ship; each has a hole, and the two holes compose into an unbounded
leak. measured: **641 live daemons on a 76-day uptime, only 16 legitimate.**

- defect 1 makes the exit branch **structurally unreachable** for a daemon that never
  receives a key — the exit needs `hasEverHadKeys && entries.length === 0`, and the first
  term stays `false` forever. those daemons ticked ~7,300 times each and declined to exit
  every time.
- defect 2 means `prune --owner @all` matches only the *pruner's own* `sessionId + homeHash`
  — so it structurally cannot see the leaked daemons, whose divergent homeHash IS the leak.

the aggregate harm is not RSS: ~528 M PSS but **~5.3 G of swap**, which filled zram to
99.6%, after which every eviction goes to disk. it presents as whole-desktop stall, never as
a keyrack symptom.

## .the fix must preserve the guard's original purpose

the `hasEverHadKeys` guard is **not unreasonable** — it prevents a startup race where a
fresh daemon exits before its client connects. the defect is that it uses *key history* as a
proxy for *purpose*, and history cannot separate these two:

| state | key history | correct action |
|---|---|---|
| just spawned, unlock inbound | none yet | keep |
| spawned 76 days ago, no client ever came | none ever | **terminate** |

so gate on **demand**, not history: exit when no client has connected for N minutes, whether
or not keys ever landed. a fix that bounds the leak but reintroduces the startup race is not
a fix.

## .acceptance

- a daemon that never receives a key terminates on its own within the idle window
- a daemon whose client connects inside the startup window survives — the race the original
  guard prevented does NOT return
- `rhx keyrack prune --owner @all` reaches daemons whose `homeHash` differs from the
  caller's
- a regression clamp: run the suite twice, assert the daemon count does not double
- the daemon count plateaus and then decays toward live sessions, rather than climbs

## .the HOW is yours — this is advisory

per `rule.require.wish-outcome-over-proposal`, the authoritative parts are `.what`, `.why`,
and `.acceptance`. the issue proposes the shape; you have the repo and better context.

open questions to settle in-repo:

- what is the right idle window, and is there already a TTL/interval constant to reuse
  rather than mint a new one?
- does "client connected" have an extant signal on the server, or must one be added?
- for `@all`: glob `keyrack.${sessionId}.*`, match on uid, or whichever form the repo
  already prefers?
- do these two fixes belong in ONE pr (one worktree, per `rule.require.one-pr-per-worktree`)
  or are they genuinely separable deliverables? the issue calls them complementary — 1 stops
  the bleed, 2 cleans the backlog. if you conclude they must split, say so before you build.

## .scope

`ehmpathy/rhachet` only. the caller-side teardown (integration tests that mint throwaway
HOMEs and never reap) is filed separately against `ehmpathy/rhachet-roles-ehmpathy` — do NOT
pull that in. it is complementary, not duplicate: teardown is per-caller and deterministic,
while the expiry fixed here is the safety net that catches every caller.

## .the lesson the issue already paid for

its first draft asked for idle expiry and reuse as NEW features. both were already shipped —
the real defect was one boolean guard and one over-narrow glob prefix. **check whether the
mechanism already exists before you build it.**
