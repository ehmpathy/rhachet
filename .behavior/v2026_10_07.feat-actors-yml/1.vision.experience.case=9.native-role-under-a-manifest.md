# case=9 — a native `.this` role is named when no actor declares it

sharp · critipath · see `1.vision.experience.case=_.md` row 44

## .narrative

a repo carries a native role of its own, `.agent/repo=.this/role=tuner`, with a `boot.yml`. before
the manifest, every bare enroll booted it with the ambient roles. the repo then adopts
`actors.yml`:

```yaml
# .agent/actors.yml
ambient: '@solo'

actor:
  - slug: solo
    brain: claude
    roles: [ehmpathy/mechanic]
```

no actor names `.this/tuner`, so under the manifest no clone boots it. that is a quiet loss unless
it is said: `rhx init` names the native role in the drift report as booted by no actor, and prints
the fix — declare `.this/tuner` in an actor's roles; under the `ambient:` actor, every bare enroll
boots it. init adds none by itself, since the manifest is the one source of what each actor holds.

the human adds `.this/tuner` to `@solo`, runs `rhx init` again, and the native row is gone: the repo
actor's boot now carries the tuner.

## .the sketch — `[tn]`

```
given('[case9] a repo with a native .this/tuner role and a manifest that omits it', () => {
  when('[t0] rhx init', () => {
    then('the report names the native role: native → not booted, undeclared')
    then('the hint names the fix: declare .this/tuner under @solo in .agent/actors.yml')
    then('init links no role on its behalf')
  })
  when('[t1] .this/tuner declared under @solo, then rhx init', () => {
    then('the native row is gone, and the repo actor boots the role')
  })
})
```
