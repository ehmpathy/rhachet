wish =

## .what

in `ehmpathy/rhachet`, close issue #480: support `.agent/actors.yml`, a declarative manifest of
the 🎭 actors a repo makes available, and which one is the default — in place of the flat
`rhachet init --roles …` flag list repos carry in `pnpm prepare` today.

## .the outcome

- a repo declares its actors and its default in one readable `.agent/actors.yml`, and
  `pnpm prepare` reads that file rather than a flag list
- 🔴 **a role package can publish NAMED rolesets**, and a repo can reference one by name rather
  than list its roles. the first case: `rhachet-roles-ehmpathy` publishes its named actor
  rolesets (e.g. the builder set — mechanic, behaver, driver, reviewer …), and a repo adopts one
  by name
- 🔴 **a roleset can EXTEND another**: `rhachet-roles-ahbode` can take an `rhachet-roles-ehmpathy`
  roleset and add an ahbode role on top, without a copy of the base list — so when the base set
  gains a role, every extension gains it too
- an absent `actors.yml` keeps today's behavior, so repos adopt it with no flag day
- a declared-vs-installed diff is reported, so a hand edit under `.agent/` is never silently
  kept or silently reverted
- tests prove: a named roleset resolves to its roles, an extension adds to its base and tracks
  base changes, the default actor is honored, and the absent-file fallback holds

## .why now

we want to name actor rolesets once, in the package that owns the roles, and compose them per
repo — today every repo repeats a flat role list in a shell string, with no names, no default,
no extension, and no drift check.
