# 1.vision.experience.dimensions

the experience space of `.agent/actors.yml`, factored into orthogonal dimensions. the product is
walked in `1.vision.experience.case=_.md`.

## .the dimensions

| # | dimension | positions |
|---|---|---|
| D1 | **manifest** — the state of `.agent/actors.yml` | `absent` · `valid` · `invalid` (bad yaml, unknown key, unknown role, cycle) |
| D2 | **roleset source** — how one actor's roles are declared | `explicit` (a list of roles) · `named` (a published roleset, by ref) · `extended` (a named roleset ± roles) · `peer` (another actor in the same file ± roles) |
| D3 | **repo actor** — which actor `ambient:` names, which a bare invocation reaches. `ambient:` is required in every manifest, by name — no sole-actor fallback | `declared` · `undeclared` (invalid) · `declared, but names no actor` (invalid) |
| D4 | **install state** — `.agent/repo=*/role=*` vs what is declared | `in sync` · `extra` (a role linked that no actor declares) · `short` (a declared role not linked) · `package absent` (a ref names an uninstalled package) · `slug absent` (the package is installed, and publishes no such slug — row 50) |
| D5 | **invoker** — who reads the manifest | `prepare` (`rhachet init`) · `upgrade` (`rhx upgrade`, which re-links what the manifest declares — row 52) · `enroll` (`rhx enroll …`) · `clone` (`rhx clone @<slug>`) · `inspect` (a human or tool asks *"what actors does this repo have?"*) |
| D6 | **base evolution** — the owning package over time | `stable` · `grew` (a package upgrade adds a role to the base) · `shrank` (a role removed or renamed) |
| D7 | **author** — who writes the declaration | `repo` (a consumer repo's `actors.yml`) · `package` (a role package publishes rolesets) |
| D8 | **brain** — where the actor's brain comes from | `declared` (its own `brain:`) · `inherited` (propagated up from a base) · `absent` (no `brain:`, no base with one — invalid) |
| D9 | **invocation form** — how the invocation names its subject | `bare` (no actor, no brain, no `--roles`) · `actor` (`@<slug>` ± deltas) · `inline` (a brain and/or `--roles`) |

## .why these are orthogonal

- D1 is the subject state. D2–D4 are properties of a manifest, so they exist only when D1=`valid`;
  otherwise they are void (no position), not correlated with D1. every other axis (D5–D9) is
  independent of whether the manifest is valid
- D2 is per actor; one file may hold all four sources at once
- D3 is per file, independent of how each actor's roles are sourced. its two invalid positions are
  D1=`invalid` cells (rows 11, 12); they stay on D3 so the walk names which key is at fault
- D4 is mostly a property of the disk, not the file — the same valid manifest can meet `in sync`,
  `extra`, or `short`. one position leans on the file: `package absent` needs a ref that names a
  package, so it occurs only with D2 ∈ {`named`, `extended`} (the hidden-dimension check, below).
  it is defined as *declared vs linked*, so where no manifest declares a role (`D1 ≠ valid`) the
  declared side is empty and D4 has no position: the disk still exists, but there is no diff to report
- D5 is the reader of a consumer's manifest (D7=`repo`); each reader consumes the same resolved
  manifest differently. a package's declaration (D7=`package`) is validated by one reader,
  `repo introspect`, which is not a D5 position — it is fixed by D7. a consumer's readers also
  consume a package's actors, but only as the base a ref in the consumer's own manifest expands,
  so those cells are D7=`repo` (rows 1, 2, 22, 38)
- D6 is time, and it reaches every source that names a package's role: `named` and `extended` track
  the base (the wish's 🔴 tether), and `explicit` names a role the package may later drop — `shrank`
  then lands it in D1=`invalid` (an unknown role, the case=7 class)
- D7 splits the two authors the wish names: the package that owns roles, and the repo that composes them
- D8 is per actor: the actor form reads the brain from the actor's own `brain:`, or the one that
  propagates up from its base (contract row *brains*); `absent` is D1=`invalid`; the inline form
  names its own brain and never reads D8
- D9 is per invocation, independent of the file. `prepare` takes `bare` or `inline` (`--roles`);
  `enroll` takes all three; `clone` takes `actor` only (row 40 refuses `inline`)

## .the hidden-dimension check

a whole row or column of a cross that cannot occur means two axes are not orthogonal. the check, run:

| cross | can it occur? | what it surfaces |
|---|---|---|
| D1=`absent` × D2, D3, D4 | no | correct by construction: those axes describe a manifest that does not exist (stated above) |
| D7=`package` × D3 | no — `ambient:` is a consumer's choice | a latent axis, *who picks the repo actor*. surfaced as row 29: a package that declares `ambient:` is refused by `repo introspect` (F9) |
| D7=`package` × D5=`enroll` | no — a package's publish is read by consumers, never enrolled in place | none new: a package repo that wants to enroll itself writes its own `.agent/actors.yml`, which is D7=`repo` |
| D4=`package absent` × D2 ∈ {`explicit`, `peer`} | no — an explicit role or a peer names no published actor to fetch | none new: `package absent` is a resolution state that only a package ref reaches; an explicit role whose package is gone lands in D1=`invalid` (row 28). walked for `{named, extended}` in row 13 |
| D7=`package` × D4 | no — a package's declaration is published, never linked in its own consumer's sense | none new: introspect checks resolution only (rows 24, 29) |
| D3 × D5 | yes, every cross — each reader validates `ambient:`; only a `bare` enroll uses it to pick an actor | none new: the use is walked in rows 4, 10; the validation in rows 11, 12; the display in row 8 |
| D8 × D9 | yes; D8 is read only under D9=`actor`, or a `bare` enroll that reaches the repo actor | none new: declared + actor row 9; inherited + bare, via the repo actor, row 4; inherited + actor row 36; any + inline row 30, where it goes unread; absent + any, row 43, invalid |
| D9=`actor` × D5=`prepare` | no — prepare links every declared actor and takes no subject | none new: prepare's subject is the whole file (A4) |
| D9=`inline` × D5=`clone` | yes, and refused | none new: row 40 |
| D9 ≠ `bare` × D5=`inspect` | no — inspect takes no subject | none new |
| D6 ≠ `stable` × D2=`peer` | no — a peer is an actor in the same file, owned by no package | none new: a peer's base carries its own D2, and that source meets D6 in rows 2, 14, 28 |

## .the absent-axis check — concurrency

considered, and judged not to need an axis. this behavior adds one read (the manifest) and no new
write: the links under `.agent/repo=*/role=*` are written by the extant link step, whose behavior
when two `pnpm prepare` runs overlap is unchanged here. an `rhx enroll` that reads the manifest while
a prepare relinks sees the file as the editor last saved it; rhachet never writes the manifest, so
there is no half-written state to read. row 34 records it.

## .the absent-axis check — consumer rhachet version

considered, and judged not to need an axis. a consumer on an older rhachet that installs a package
whose `rhachet.repo.yml` carries `actors:` has one outcome: the older schema strips the unknown key
(`getRoleRegistryManifest.ts:65`, a plain `z.object`), so its roles load as before and the actors go
unseen. one position on a would-be axis with one verdict is a row, not an axis — row 37 records it,
and case=3 `[t2]` sketches it. a consumer on an older rhachet that writes its own `actors.yml` gets
today's behavior (the file is unread), which is the D1=`absent` verdict.

## .the walked product — reduced

the full product is 3 × 4 × 3 × 4 × 4 × 3 × 2 × 3 × 3 = 31104 cells. most collapse, and each collapse
names the axes it fixes:

- `D1=absent` ⇒ D2, D3, D4 have no position (no manifest declares aught; the repo actor is
  `actor.via.repo=ambient`, as main ships it); D6, D7, D8 are n/a → one row
  per invoker (D5 × 4), plus D9=`inline` as today's prepare line
- `D1=invalid` ⇒ every reader fails fast, before any write, with the same validator → one row per
  invoker group: `prepare` (row 7), `{enroll, clone}` (row 20), `inspect` (row 27), plus the
  package-side twin (row 24). D2–D4, D7, and D8 do not change the verdict. D6 does not change the
  verdict either, but D6=`shrank` is one way a once-valid manifest becomes invalid, so that
  transition gets its own row (row 28)
- D7=`package` ⇒ the reader is `repo introspect`, not D5 → rows for publish (valid), publish (invalid),
  and the barred D3 cross
- D6 matters wherever a package's role is named → crossed with `named`, `extended`, and `explicit`
- D3 × D5: only a `bare` enroll uses a well-formed `ambient:` to pick an actor → its verdict crosses
  that (rows 4, 10); every reader validates it — absent (row 11) or a typo (row 12) — and `inspect`
  shows it (row 8)
- D8 matters only where an actor is reached — the actor form, or a `bare` enroll that reaches the
  repo actor → a declared brain under `actor` (row 9, `@scholar`), an inherited brain under `bare`
  (row 4, `@builder`) and under `actor` (row 36); an actor that reaches no brain, or two bases with
  different brains and no local `brain:`, is D1=`invalid`, case=7's class (row 43)
- D9 crosses `prepare` as `bare` (row 1) and `inline` (rows 5, 19); `enroll` as `bare` (row 4),
  `actor` (rows 9, 32, 33), and `inline` (rows 16, 30); `clone` as `actor` (rows 9, 25, 39) and
  `inline` (row 40, refused). rows 9, 32, 33 name D5=`{enroll, clone}`, since `rhx enroll @<slug>`
  aliases `rhx clone @<slug>`

in the inventory, a cell column holds one position per axis. `any` means the verdict is uniform across
every position of that axis; `—` means the axis has no position in that cell (per the collapses above).
a row that splits an axis names both positions in separate rows.
