# 1.vision — `.agent/actors.yml`

> **a repo declares its actors by name; a role package publishes actors a repo can adopt or
> extend by name; `pnpm prepare` reads the declaration and reports any drift from it.**

## .the outcome world

### before

```json
"prepare:rhachet": "npm run build && rhachet init --hooks --roles mechanic behaver driver architect ergonomist reviewer dreamer dispatcher"
```

this exact string, or a near copy, sits in `rhachet-roles-ehmpathy` (`package.json:62`),
`rhachet-roles-bhuild` (`:63`), and `ahbode/rhachet-briefs-ahbode` (`:39`, the same list +
`playwright`). `rhachet-roles-bhrain` (`:74`) and this repo (`:98`) carry longer variants. five
hand-kept copies of one idea, no name for any of them, no default, and no step that notices when
`.agent/` disagrees.

### after

```yaml
# .agent/actors.yml  (ahbode)
ambient: '@builder'

actor:
  - slug: builder                 # brain propagates up from @ehmpathy/builder (F11)
    roles:
      - '@ehmpathy/builder'       # ehmpathy's published builder, by name
      - +bhrowser/playwright      # ahbode's addition
  - slug: scholar
    brain: anthropic/claude/code
    roles: [bhrain/librarian, bhrain/learner, ehmpathy/architect]
```

```json
"prepare:rhachet": "npm run build && rhachet init --hooks"
```

only the `--roles …` list leaves the line. the build step stays: a role package links its own
roles from `dist/`.

### a day in the life

- **monday** — ehmpathy adds `learner` to `@ehmpathy/builder` and ships a minor.
- **tuesday** — ahbode's routine upgrade bumps the package; `pnpm prepare` prints
  `bhrain/learner ↺ linked, via @ehmpathy/builder`. nobody at ahbode edited a list.
- **wednesday** — a human types `rhx enroll` and gets a `@builder` clone, on `@builder`'s own
  brain, not every role ever linked. `rhx clone @scholar` (or its alias `rhx enroll @scholar`) gets
  the reader. no brain is typed: each actor names its own.
- **thursday** — someone hand-links `ghlitch/observer` to try it. friday's prepare prints it as
  **extra → kept, undeclared**, with the one-line fix either way.

### the aha

the first ehmpathy release that grows `builder`, and every downstream repo just *has* it. the role
list stops as a string each repo maintains and becomes a **name the owner maintains**.

## .the contract, proposed

| concern | decision |
|---|---|
| **path** | `.agent/actors.yml` — a peer of `.agent/keyrack.yml`. an actor belongs to the repo, not to any role it hosts, and a repo may declare actors with no native roles at all (Q1, ruled) |
| **shape** | the extant brief's shape: `actor: [{ slug, brain, roles }]`, plus one top-level `ambient: '@<slug>'` that names the repo actor (contract row *repo actor*). `ambient:` is **required** in every manifest and names its actor **by name**: a file without it is invalid, even with one actor, so the repo actor is never inferred. the key is `ambient:`, never `default:` or `repo:` — main retired "default" on both axes, and the repo actor is the one that holds the ambient roles (`term=ambient`) (F12, ruled, S9). a value that opens with `@` is quoted — yaml reserves `@` at the start of a plain value, and `yaml@2.8.2` refuses it (`BAD_SCALAR_START`, `compose/resolve-flow-scalar.js:61-68`); the validator names the quote as the fix |
| **roles** | either fully-qualified roles (`repo/role`, or a bare slug if unambiguous — the same rule `getRoleFromManifests` applies to `--roles` today), **or** one base actor (`'@<slug>'` local, `'@<repo>/<slug>'` published) followed by `+role` / `-role` deltas. never both — the rule `getRoleDeltas` already enforces |
| **named roleset** | a **published actor**. not a new noun: a roleset a package names IS an actor it recommends. reached as `@ehmpathy/builder` — the `@` actor sigil, supplier-qualified, as `define.address-sigils` already reserves |
| **where a published actor lives** | the package declares it (shape of a consumer `actors.yml`, no `ambient:` — introspect refuses one, since the repo actor is the consumer's choice, F9); `rhachet repo introspect` emits it as `actors:` in `rhachet.repo.yml`, beside `roles:`. older rhachet strips the unknown key, so no consumer breaks |
| **extension** | by reference. the base is expanded at read time from the **installed** package version, so a base that grows reaches every extension on the next prepare; a repo that wants to pin, pins the package version it already controls |
| **brains** (#480 Q1) | every actor has a brain — that is what an actor is, `{ brain, roles }`. a base contributes its brain as well as its roles: the brain propagates up from the base to the actor that extends it, through any depth of `@ref`s, and a local `brain:` overrides it. an actor that extends `@ehmpathy/builder` or a peer may omit `brain:`; an actor with no base (explicit roles only) must state it. an actor that reaches no brain after expansion fails validation, which names the field. with more than one `@ref` base that carry different brains, the actor must state `brain:` itself. the value is any brain slug enroll accepts — a repl, or an atom (#590). an invocation of an actor names no brain: the actor supplies it (F11, ruled, S7, S8) |
| **invocation** | two forms (F10). **the actor form** — `rhx clone [--actor] @<slug> [--brain <brain>] [+role/-role …]`, aliased as `rhx enroll @<slug> …` — for a declared actor; the actor supplies brain and roles. an optional brain override and role deltas apply on top, and any override yields a delta clone in the derived actor `actor.via.slug=<slug>._.delta=<hash>`, still tethered to its base. **the inline form** — `rhx enroll [--brain] <brain> [--roles] <roles>` — for an undeclared, one-off composition, as today, with one change under a manifest: where `--roles` is omitted or is only deltas, its base is the repo actor's roles rather than every linked role (contract row *repo actor*; inventory rows 30, 32). use the actor form whenever the composition has a name worth reuse; use the inline form to try a combination before it earns one. beside `@<slug>`, `--roles` takes deltas only (`+x`, `-y`); a plain role list would replace the actor wholesale, which is the inline form, so it is refused and names the inline spelling. an unknown `@<slug>` fails fast and lists the declared actors. this matches #591's `rhx ask\|act [--actor] @$actor` vs `[--brain] $brain [--roles] $roles`, so one grammar serves enroll, clone, ask, and act |
| **`rhachet init`** (#480 Q2) | stays the verb. with a manifest and no `--roles`, it links the **union of every declared actor's roles**, then runs its other flags (`--hooks`, `--keys`) as today. `--roles` beside a manifest is refused (two sources of truth) |
| **absent file** (#480 Q3) | today's behavior on disk, byte for byte. the one new output: where `--roles` is passed, a single dim hint line names `.agent/actors.yml`; a brainless bare `rhx enroll` fails as today and names both the brain argument and `actors.yml`. adoption is per repo, no flag day (case=5; inventory rows 5, 16) |
| **drift** (#480 Q4) | every manifest-driven init computes declared vs linked first and prints it. **short** → restored · **extra** → kept and named, never silently removed. the report on every init is what the wish requires. a plan mode that prints the diff, writes naught, and exits 2 on drift is a **could**, not a must — no wish line asks for a gate, and prepare does not run in CI; cut it if it costs more than a flag |
| **repo actor** | main's invariant holds: a bare enroll (and a bare `claude`) reaches the **repo actor**, the one actor that holds the **ambient roles** (`term=ambient`). the manifest only decides who that actor is. with no manifest it is `actor.via.repo=ambient`, and the ambient roles are every linked role, as main ships it. with a manifest, `ambient: '@builder'` makes `@builder` the repo actor: the ambient roles are `@builder`'s roles, its brain is `@builder`'s brain, and `<repo>/.claude` points at `actor.via.slug=builder/brain/.claude`. so a bare enroll and `rhx clone @builder` are one actor in one dir, never twins — the same collapse main applies when `--roles` equals the ambient set. a change of `ambient:` repoints the link; no clone moves dirs. a manifest without `ambient:` fails validation in every reader and names the key — a sole actor is never promoted silently (F12, ruled, S9) |
| **clone identity** | the form picks the namespace, per `define.actor-clone-hierarchy`. **actor form** → the slug namespace: `rhx clone @builder` (and `rhx enroll @builder`, and a bare enroll under `ambient: '@builder'`) lands in `actor.via.slug=builder`, rewritten in place, so a base that grows reaches live clones at their next read. with deltas, `@builder -driver` lands in the derived form `actor.via.slug=builder._.delta=<hash>`. **inline form** → the hash namespace, as main ships it: absolute roles hash to `genEnrollmentHash({ brain, roles })`; a delta (`rhx enroll claude -driver`) hashes to `genEnrollmentHashOfDelta({ brain, base: 'ambient', delta })` and re-derives from the ambient roles at each init — under a manifest, from the repo actor's roles. ruled by the wisher (F7, S4) |
| **behavioral requirements** (`inventory.of=requirements`) | each entry holds as main ships it with no manifest, and under a manifest: **2** — a delta actor re-derives from the ambient roles, now the repo actor's roles, so an edit to that actor in `actors.yml` reaches every `-driver` actor at the next init. **3, 4** — `rhx enroll claude --roles -driver` and `rhx enroll claude -driver` still subtract driver, from the ambient roles. **9** — a slug or derived actor's `settings.of.repo.json` holds only its own roles' hooks, the same filter every actor dir gets. **1** — `rhx init --roles -xyz` edits `prepare:rhachet`; under a manifest the roles live in `actors.yml`, not that entry, so the flag is refused and names the `actors.yml` edit. that confines entry 1 to repos with no manifest, and only the wisher may amend an entry (F13) |
| **clone verb** | `rhx clone` today has `list · say · get · whoami · prune` and no verb that spawns from an actor. this behavior adds that one: `rhx clone @<slug> [deltas]`, a fresh clone of a declared actor, with `--as @:<slug>` for findsert. `fork` and `wake` stay the prior dream's |

## .mental model

- **to a friend:** *"it's a `package.json` for your AI crew. you name who's on the team; the role
  packages ship ready-made teams you can adopt or tweak."*
- **analogy:** eslint `extends` — `extends: ['airbnb']` plus a few overrides, and when airbnb
  updates its preset, you inherit it. a published actor is a preset; `+`/`-` are the overrides.
- **their words vs ours:**

| a human says | we say |
|---|---|
| preset, team, crew, profile | actor (published actor) |
| role list | roleset |
| "the one I get by default" | the repo actor |
| tweak, override | delta (`+role` / `-role`) |
| "it changed under me" | drift (short / extra) |

## .evaluation

### goals vs outcome

| wish outcome | met by |
|---|---|
| declare actors + the repo actor in one readable file; prepare reads it | case=1, the contract |
| 🔴 packages publish named rolesets, adopted by name | case=3 + case=1 |
| 🔴 a roleset extends another; tracks base growth | case=2 |
| absent file keeps today | case=5 |
| drift reported, never silent | case=6 |
| tests prove the four | each case's `[tn]` sketch feeds criteria |

### pros

- reuses every extant piece: the `@` sigil, the `+`/`-` delta grammar and its validator, the
  `rhachet.repo.yml` publish path, the `actors.yml` shape already documented in briefs
- one name, maintained by the owner, replaces five drifted copies
- drift becomes visible for the first time
- backward compatible on both sides: an absent file, and an older rhachet that reads a newer manifest

### cons

- base growth flows in quietly — stdout names it, but a reviewer must read prepare's output to
  notice a new role, and roles carry hooks
- the repo actor changes what a bare `rhx enroll` boots with, once a repo adopts a manifest —
  a real behavior change, scoped to repos that opt in
- scope grows past the wish: the clone verb from an actor, and the actor form on enroll. the wisher
  asked for both, and both are needed for a second declared actor to be reachable at all
- an actor now spans two homes (repo file, package manifest), so a reader may chase a base
  through one hop per level

### edgecases and the pit of success

| edge | the pit |
|---|---|
| typo in a base, a role, or `ambient:` | fail fast before any write, nearest match named (case=7) |
| package not installed | fail fast, names the package to add |
| extension cycle | fail fast, names the cycle path |
| bare roles mixed with deltas | refused, same rule as `--roles` |
| `-role` the base already lacks | warn — intent holds |
| `--roles` plus a manifest | refused, names which to keep |
| no `ambient:` (one actor or many) | invalid in every reader: fail fast, name the key, list the actors to pick from (S9) |
| `rhx init --roles -xyz` beside a manifest | refused: names the `actors.yml` edit (F13) |
| a hand-linked role | kept, named as extra, both fixes printed |
| `rhx enroll @scholar codex`, or `@scholar --roles +mechanic` | allowed: an override on the actor; spawns a delta clone in `scholar._.delta=<hash>` (F10, S5) |
| `@scholar --roles mechanic` (a plain list, no `+`/`-`) | refused: a plain list replaces the actor, which is the inline form; names `rhx enroll <brain> --roles mechanic` |
| `rhx clone @nobody` | fail fast, lists the declared actors |
| an actor that extends a base and omits `brain:` | allowed: the base's brain propagates up; a local `brain:` overrides (F11, S8) |
| an actor that reaches no brain — no `brain:` and no base with one | fail fast at validate, names the `brain:` field (F11) |
| two `@ref` bases with different brains, no local `brain:` | fail fast at validate: ambiguous, names both brains and asks for a local `brain:` (F11) |
| a base removes a role an extension relies on | the role is no longer declared, so it shows as **extra → kept**, with both fixes (A5: prepare cannot tell a base shrink from a hand link) |

## .open questions & assumptions

### assumptions

- **A1** — `rhachet-roles-ahbode` does not exist; the ahbode case is `ahbode/rhachet-briefs-ahbode`,
  which consumes roles. the extension demo holds equally for a consumer repo or a future role
  package
- **A2** — a published actor's roles may reference other packages' roles (ehmpathy's builder
  carries `bhuild/behaver`). today ehmpathy holds `rhachet-roles-bhuild` and `-bhrain` as
  **devDependencies only** (`rhachet-roles-ehmpathy` `package.json:81`, `:106-107`), so a consumer
  that installs only ehmpathy cannot expand `@ehmpathy/builder`. prepare fails fast and names the
  packages to add. a candidate cure, to verify at blueprint: a package that publishes an actor
  declares the foreign role packages as `peerDependencies`, so the install names them up front
- **A3** — base expansion reads the **installed** version; no lockfile of expanded roles is kept
  (the package version in `pnpm-lock.yaml` already pins it)
- **A4** — `rhachet init` with a manifest links the union of all actors, so `rhx clone @scholar`
  finds scholar's roles linked, rather than only the repo actor's roles
- **A5** — with no record of the prior expansion (A3), prepare sees only declared vs linked. a
  role a grown base adds and a role a human unlinked both read as **short**; a role a shrunk base
  drops and a role a human linked both read as **extra**. so the report names each role's declared
  source (`via @ehmpathy/builder`), not *why* it moved. labels like "new, base grew" need a stored
  prior expansion — see Q6

### open questions, triaged

each is marked **[answered]** (settled now, by logic or extant docs — the fulcrum stays open for
the council to overrule), **[research]** (settle at the research stone), or **[wisher]**.

- **Q1** [answered, by the wisher] — the path is `.agent/actors.yml`, a peer of `keyrack.yml`:
  actors belong to the repo, which may host no roles of its own. the extant briefs now say so (F1)
- **Q2** [answered] — `extra` drift is *kept* and reported, never removed. both keep-and-report
  and remove-and-report satisfy the wish's "never silent", so the tiebreak is safety: a removal
  destroys a deliberate hand edit, a keep destroys naught and names both fixes
  (`rule.require.safe-by-default`). (F4)
- **Q3** [answered] — yes, the repo actor drives the repo brain dir, and main already says how:
  `<repo>/.claude` links to the repo actor's brain dir, and that actor alone holds the ambient
  roles (`term=ambient`). under a manifest the `ambient:` actor IS the repo actor, so the link points
  at its slug dir and no second "repo" dir exists to drift. (F12, which absorbs F5)
- **Q4** [answered] — no acknowledgement gate on base growth. the wish asks for it outright:
  *"when the base set gains a role, every extension gains it too."* the report names each role's
  source, and a repo that wants a gate pins the package version (inventory row 15)
- **Q5** [answered by the wisher] — the form decides. the actor form (`rhx clone @builder`, its
  `rhx enroll @builder` alias, and a bare enroll under `ambient: '@builder'`) lands in
  `actor.via.slug=builder`, so an edit to the actor in `actors.yml` reaches live clones at their
  next read; the inline form (`rhx enroll claude --roles …`) stays hash-identified, as today. the
  brief `define.actor-clone-hierarchy` (*"`rhx enroll` is hash-only"*) is rewritten in execution (F7, S4)
- **Q6** [answered] — no stored prior expansion in v1. the wish asks that drift be *reported*,
  not attributed; the source name (`via @ehmpathy/builder`) tells a reader where to look, and a
  stored record is one more artifact to keep true (A5)
- **Q7** [answered, by the wisher] — a non-repo actor is reached as `rhx clone @scholar`, with
  `rhx enroll @scholar` as its alias, and no brain typed: the actor names its own. the `--roles
  @scholar` form is dropped; `@<slug>` is the actor form's positional subject (F8, F10). A4 rests on
  this reader
- **Q8** [research] — does pnpm install a package's `peerDependencies` by default, so that a
  package which publishes an actor with foreign roles can declare them as peers and spare the
  consumer a second install (A2)? check pnpm's `auto-install-peers` default and the version that
  set it

## .what is awkward

- **the repo actor changes home under a manifest.** main named it (`term=ambient`, the repo
  actor) and retired "default"; this vision only decides who it is. with no manifest it lives in
  `actor.via.repo=ambient`, with one it is the `ambient:` slug actor. a repo that adopts a manifest
  sees its bare clones move dirs once, at the next init (F12)
- **requirement 1 narrows.** `rhx init --roles -xyz` has no `prepare:rhachet` entry to edit once a
  manifest owns the roles; only the wisher may amend the requirement to say so (F13)
- **enroll gains a second identity rule.** today every enroll is hash-identified; with the alias,
  the actor form lands in the slug namespace and the inline form in the hash one. the form decides,
  which is simple to state, but two commands that look alike (`rhx enroll` vs `rhx enroll claude`)
  now produce clones that age differently (F7)
- **a published actor carries a brain into every consumer.** a consumer that adopts
  `@ehmpathy/builder` runs on ehmpathy's brain unless it states its own `brain:` — the brain
  propagates up with the roles (F11, S8). a consumer on a different supplier overrides it in one
  line
- **union vs repo actor at init.** init links every declared actor's roles, while a bare `claude`
  boots only the repo actor's — the brain dir renders per actor, so the two never mix (Q3)
- **quiet growth of roles that carry hooks.** the tether is the point, and also the risk: a base
  that gains a role gains its hooks in every downstream repo on the next bump
- **a published actor's foreign roles** make a role package's install footprint implicit — a
  consumer adopts `@ehmpathy/builder` and discovers it needs `rhachet-roles-bhuild` too
