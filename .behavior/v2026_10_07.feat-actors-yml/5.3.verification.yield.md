### the brain stub exits on parent loss

`src/.test/assets/stubBrainCli.cjs` used to park on stdin forever once its parent died: it was
reparented to init and never read again, so one suite left 310 alive (~18G heap). it now exits
on parent loss:

- stdin `end` / `close` / `error` — the pty master is gone
- a 500ms `unref()`d interval — `process.ppid` differs from its start value (reparented), or a
  signal-0 probe of the start ppid throws `ESRCH`
- the same interval — its cwd is deleted. a detached `run.jit enroll|clone` host outlives its
  test and keeps the stub's parent alive, so parent loss never fires; the test-fns prune of the
  repo is the one signal left (measured: 14 stubs after one `enroll.actors-yml` run, 11 in a
  pruned repo, each under a live enroll host)

its argv, modes, and replies are unchanged. and `enroll.actors-yml.integration` now ends what
it bakes: `blackbox/.test/infra/endClonesBakedIn.ts` says `/exit` into every clone of a scene's
repo, in that scene's `afterAll`.

| clamp | what it proves |
|---|---|
| `stubBrainCli.parentLoss.integration.test.ts` [case1] | a stub whose stdin stays open exits within 3s of a SIGKILL to its parent. red with the fix reverted (✕ 3033ms), green with it |
| `stubBrainCli.parentLoss.integration.test.ts` [case2] | a stub whose parent lives on exits within 3s of its cwd removal. red with the cwd check off (✕ 3022ms), green with it. an exited stub under a live parent is a zombie until reaped, so the clamp reads `/proc/<pid>/stat` state `Z` as gone |
