# 1.vision.experience.case=_ — the inventory

the product of `1.vision.experience.dimensions.md`, walked. the full box is
A(3) × B(3) × C(4) × D(3) × E(2) = 216 cells for the suite's own actors. it is walked as three
views, read together — each view names the axes it varies and the axes it holds, and why the
held axes add no verdict there:

| view | varies | holds, and why |
|---|---|---|
| slice 1 | actor × box | C, D, E — slice 1 only settles who can be where; impossible cells die here, and every live cell is walked further in slices 2–3 |
| slice 2 | box state × width ask, on the shared boxes and on ci | D — how a run ends does not change how it shares the cpu while live |
| slice 3 | run end × box | C, E — leftovers are born at the end, and neither box state nor width changes what the end leaves |

laptop vs grove inside slices 2 and 3: the contract keys on "shared", never on which kind, and the
bound is graded against each box's own baseline. so a laptop cell and its grove twin share a
verdict, except where a row says otherwise (an idle grove is rare; the saturated state is most
often a grove).

the two actors outside the suite (the prod human, the pr author) are walked after the slices.

## .slice 3 — run end × box (what a run leaves behind)

| run end | ci | shared box | verdict |
|---|---|---|---|
| pass | runner vm is discarded; leftovers cost naught | zero fixture dirs, zero live brain stubs after exit | **demoed** (case 4) — happy critipath |
| fail | same | same as pass — a red test reclaims its children too | **demoed** (case 4 `[t1]`) — the reclaim does not branch on the result |
| abort (ctrl-c, jest timeout, `--forceExit`, crash) | vm is discarded | no brain stub outlives the run (attached or detached); dirs of a crashed run are reported by the next run and cleared by the test-fns 24h age gate | **demoed** (case 5) — sharp critipath, must fail safe. proven through a real jest run aborted by ctrl-c (SIGINT to its process group) by `jestAbortLeavesNoStub.integration` [case1]: an attached stub, a detached stub, and a detached stub deaf to all but its cap, none left; red with the cap lifted. a non-stub child of an aborted run is not ended or named: caught as a dream (`v2026_11_16.fix.name-what-an-aborted-run-left`) |
| a new test leaks a child, any end | the suite goes red and names the leak | same | **demoed** (case 6) — sharp critipath: the guard that keeps the fix from rot. proven through real jest by `ReporterAcceptanceBox.jest.integration` [case1] (a leak: exit 1, one test passed, the leak report) and [case2] (no leak: exit 0) |
| a test drives a nested acceptance run (a skill test that runs jest), any end | the nested run sweeps only its own processes | same | itemized — sharp alterpath, found in verification: jest skips `globalSetup` when no file matches, so a nested run once inherited its parent's run id and swept the parent's own workers. the sweep now runs only on an id this process minted (`getOneRunIdMintedHere`). proven by `getOneRunIdMintedHere.test`, `ReporterAcceptanceBox.integration` [case6], and live by `test.acceptance.credfree.integration` [case4] |
| the run leaves only a keyrack session daemon, any end | vm is discarded | the run ends it and stays green, with an `ℹ reclaimed N keyrack daemon(s)` note; a brain stub or any other survivor still goes red | **demoed** (case 6 `[t3]`) — happy alterpath, found in execution: a session daemon outlives its test by design (it serves the whole session), so it is the run's to reclaim, never a leak. proven by `asLeftPartitioned` / `isProcessReclaimedByRun` / `asReclaimNote` and `ReporterAcceptanceBox.integration` [case2] (daemon only: green + note) vs [case1] (stub: red) |

## .the prod edge the leak exposed

| cell | verdict |
|---|---|
| a human runs `rhx enroll claude`, then its terminal dies (SIGHUP) or its parent is killed | **demoed** (case 10) — sharp critipath. a brain process that outlives `enroll` is a prod leak, not only a test leak. proven by `enroll.ends-its-brain` [case1]–[case3] (hangup, kill), [case5] (parent killed, terminal open), and [case6] (a brain deaf to the hangup, ended by the host's SIGKILL escalation; red with the host's SIGHUP handler removed) |
| an attached `rhx enroll claude` whose stdin is a pipe that ends (case 10 `[t1]`) | **itemized, must NOT end the brain** — found in verification: `enroll --await -p` runs attached with no tty, and its stdin ends at once when the caller has no input to give. that end is no loss: the brain must still answer. so an input end counts as a loss only on a tty (`genHostLossWatch` [case6]); a pipe's brain still ends on parent death. proven by `enroll.acceptance` print-leaf [case5] and no-tty [case1] [t2], red with the end read on a pipe, green with it read only on a tty |
