# case 7 — explicit-width-wins · runner · happy · alterpath

## .narrative

it is late, the laptop is quiet, no seat is live. mo wants the whole acceptance tier before a
release and is happy to let it eat the box. mo passes jest's own flag, `--maxWorkers 100%`. the
suite honors it — an explicit ask always beats the shared-box default — and the header says so,
so no one later wonders why the box was pegged. priority stays low regardless: nice costs naught
on an idle box, so there is no reason to raise it.

why alterpath: the bare default already runs the suite to green; the override only buys speed on
a box the runner knows is idle. if the override broke, mo would still get a green run, just a
slower one.

## .bdd `[tn]` timeline (sketch)

```
given an idle laptop with 12 cores, no GITHUB_ACTIONS
  when [t0] mo runs `pnpm run test:acceptance:locally -- --maxWorkers 100%`
    then the run header reads
      🐢 acceptance width
         ├─ box = shared
         ├─ workers = 12 of 12 cores (asked)
         └─ priority = nice 10
    and  jest spawns 12 workers
  when [t1] mo runs the same command with no flag
    then the header reads `workers = 3 of 12 cores (shared-box default)`
```

> the knob is jest's native `--maxWorkers`, not a new env var: one flag, already documented,
> already overrides the config. `rhx test.acceptance.credfree` passes it through.
