# case 1 — runner-on-a-busy-shared-box · runner · happy · critipath

## .narrative

kai is on a 12-core laptop with three claude seats live and a browser open. one seat changed the
actors-yml code, so kai runs the suites it touched:
`rhx test.acceptance.credfree --scope actors-yml`.

before: the run forked six jest workers (`'50%'`), each case spawned `bin/run` children and a
brain stub, load climbed to 55, cpu pressure hit 80%, and the seats stalled mid-reply. the run
left 225 fixture dirs in `/tmp` and a pile of stubs that held 18G between them.

after: the header says the box is shared, the suite takes three workers, and every process in its
tree runs at nice 10. the seats answer at their normal pace. if the scope matches three suite
files or fewer, the run takes as long as it did before — three files never needed six workers. a
scope that matches more files than the cap queues the rest, and takes longer in proportion; that
is the trade the cap makes, and the header says the width so kai can widen on purpose (case 7). when it exits, `/tmp` holds no
`rhachet-test-*` dir from this run and no stub from this run is alive.

the aha: the cap costs a scoped run naught. a local run is almost always scoped to a few files,
and a few files fill two workers; only a full local sweep — which
`rule.forbid.local-full-test-sweeps` already forbids — would feel the cap. so the box gets its
cores back for free on the path kai actually walks.

why critipath: this is the daily local loop for every crew and every clone. no fallback exists:
if the suite starved the box, the only escape is to not run it, which defeats the gate.

## .bdd `[tn]` timeline (sketch)

```
given a 12-core laptop, three claude seats live, load ≈ 3 before the run
  when [t0] kai runs `rhx test.acceptance.credfree --scope actors-yml`
    then the run header reads
      🐢 acceptance width
         ├─ box = shared
         ├─ workers = 3 of 12 cores (shared-box default)
         └─ priority = nice 10
    and  every node in the suite's tree (workers, `bin/run`, `bun install`, brain stubs) runs at nice 10
  when [t1] the run is mid-flight
    then the load the run adds stays inside the stated bound (see the yield: delta over baseline)
    and  cpu pressure the seats feel stays inside the stated bound
  when [t2] the run ends green
    then, for a scope of files ≤ the cap, its wall time is within noise of the same scoped run today
    and  for a wider scope, its wall time grows no worse than (files / cap) × today's per-file time
    and  zero `rhachet-test-*` dirs and zero brain stubs from this run remain

given a 4-core grove, baseline load ≈ 6 and cpu psi ≈ 29% (busy, not saturated), a clone as runner
  when [t3] the clone runs `rhx test.acceptance.credfree --scope keyrack.get`
    then the header reads `box = shared`, `workers = 1 of 4 cores (shared-box default)`, `priority = nice 10`
    and  the scope's one suite file runs as fast as it does today — one file never needed more than one worker
  when [t4] the run ends green
    then the grove's load falls back to its baseline, and no dir or stub from the run remains
```

> the grove walk is shorter because the experience is the same contract on a smaller box: one
> worker, same nice, same reclaim. the grove's own sharp edge — a box busy past the suite's
> share — is case 11.
