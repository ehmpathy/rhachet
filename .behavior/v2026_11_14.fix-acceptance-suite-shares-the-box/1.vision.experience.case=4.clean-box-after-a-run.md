# case 4 — clean-box-after-a-run · runner · happy · critipath

## .narrative

kai's scoped run ends — green this time, red the next. either way, kai never thinks about `/tmp`
again. before, every `genTestTempRepo` call minted `/tmp/rhachet-test-<ts>-<rand>` and no one
removed it ("OS handles cleanup" said its docblock, and on a box that stays up for weeks, the OS
does not). 225 such dirs sat in `/tmp` the day the issue was filed, some with a full
`node_modules` from a `bun install`.

after: every fixture dir the suite mints is one the run reclaims. the dirs are minted through the
repo's paved temp root (`genTempDir` from test-fns, whose autoprune teardown the acceptance config
already wires), so the run that stamped them reclaims them at its end. a run that crashed before
its teardown is reported as arrears by the next run's setup, and its dirs are removed by the
test-fns age gate once they pass 24h (`pruneStale.js:49-78`, `TEST_FNS_MAX_AGE_MS`); so a crash
leaves a bounded residue that clears itself, never a pile that grows. the brain stubs a case spawned
are reaped with the case (see case 5), so a pass or a fail leaves no process and no dir.

why critipath: this is every run's end. a leftover per run compounds, and a laptop that crawls
two weeks later has no fallback but a reboot.

## .bdd `[tn]` timeline (sketch)

```
given a laptop where `/tmp` holds 0 `rhachet-test-*` dirs and 0 stubBrainCli.cjs processes
  when [t0] kai runs a scoped acceptance run that passes
    then after jest exits, `/tmp` holds 0 fixture dirs this run minted
    and  0 stubBrainCli.cjs processes are alive
  when [t1] kai runs a scoped acceptance run where one test fails
    then after jest exits, the same counts read 0 — the reclaim does not branch on the result
```

> the repo already settles where the dirs go: `code.test.accept.blackbox` says to use
> `genTempDir` from test-fns and never raw `os.tmpdir`. so `genTestTempRepo` mints under
> `genTempDir`, not a cleanup of its own. a side effect: the snapshot mask `/TMP_REPO` gives way
> to `/TMP_TEST_DIR` on the 37 snapshot lines that carry it today.
