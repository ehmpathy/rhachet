# case 10 — enroll-dies-brain-dies · human (prod) · sharp · critipath

## .narrative

sam runs `rhx enroll claude` in a terminal tab, works a while, then closes the tab. or ssh drops.
or the tmux server is killed. the terminal sends a hangup, or simply vanishes.

before: `enroll` hosts the brain under a managed pty and wires only SIGINT and SIGTERM to it
(`genPtyCloneHostFromProcess.ts:46-55`). a hangup, an end of stdin, or a dead parent were not
wired, so `enroll` could stay alive with no terminal, its pty master open, the brain unaware.
the same shape that leaked stubs in the suite leaks a real claude in prod: a brain that burns
tokens or holds a socket for a human who has gone.

after: `enroll` treats every loss of its host as a stop. on SIGHUP, on stdin end, or when its
parent is gone, it ends its brain the same way it does on SIGINT, waits a short bound for the
brain to exit, ends it harder if it lingers, then exits itself with the brain's exit code. a
detached (async) clone is out of scope: it has no host terminal by design and lives until
`clone` ends it.

why critipath: every interactive enroll ends one of these ways sooner or later. a brain that
outlives its human is a cost and a privacy hazard, with no fallback for a human who does not
know it is there.

why it fails safe: fast (bounded wait, then forced), loud only where someone can hear (the exit
code is forwarded to whatever is left to read it), and the brain is never left without a parent.

## .bdd `[tn]` timeline (sketch)

```
given `rhx enroll claude` live in a terminal, the brain under its pty
  when [t0] the terminal sends SIGHUP (tab closed)
    then enroll ends the brain, waits a short bound, and exits
    and  no brain process remains
given `rhx enroll claude` whose brain ignores the hangup
  when [t4] the terminal sends SIGHUP, and the brain does not exit
    then enroll ends the brain harder once the short bound is spent
    and  no brain process remains — the bound, not the brain's goodwill, ends it
    (proof: `genBrainCliPtyClone.integration` [case6], the wait lands inside the bound)
given `rhx enroll claude` whose stdin is a pipe
  when [t1] the pipe closes (stdin end)
    then enroll ends the brain and exits — same as [t0]
given `rhx enroll claude` whose parent is SIGKILLed
  when [t2] enroll notices its parent is gone
    then enroll ends the brain and exits
given a detached clone baked via `rhx enroll claude --async`
  when [t3] the shell that baked it exits
    then the clone lives on, as designed — it is ended by `clone`, not by its baker
```
