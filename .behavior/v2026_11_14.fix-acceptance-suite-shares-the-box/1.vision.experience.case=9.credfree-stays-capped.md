# case 9 — credfree-stays-capped · runner · sharp · critipath

## .narrative

a clone on a laptop runs `rhx test.acceptance.credfree --scope actors-yml` — the exact lineage
the issue measured. that skill sets `CI=true` so jest verifies snapshots in `--ci` mode. a width
rule keyed on `CI` would read this laptop as a ci runner and hand it full width: the fix would
silently undo itself on the path most used locally.

so the width rule never reads `CI`. it widens only on a signal that only a real ci host sets
(`GITHUB_ACTIONS=true`), and it is shared-box by default everywhere else — a bare
`npx jest -c jest.acceptance.config.ts`, a credfree run, a husky hook. the run header prints the
box it chose and the signal it read, so if a future change ever picks the wrong box, the first
line of the log shows it.

why critipath: credfree is the main local entry to this suite. if this edge broke, every local
run would be back at today's width with no visible sign.

why it fails safe: the default is the safe box (shared). a host that sets no ci signal can only
err toward too narrow, never toward too wide; and the header makes either error loud.

## .bdd `[tn]` timeline (sketch)

```
given a laptop with 12 cores, CI=true, no GITHUB_ACTIONS
  when [t0] the clone runs `rhx test.acceptance.credfree --scope actors-yml`
    then the run header reads
      🐢 acceptance width
         ├─ box = shared (no ci host signal; CI=true alone does not widen)
         ├─ workers = 3 of 12 cores (shared-box default)
         └─ priority = nice 10
    and  snapshots are still verified in --ci mode
given the same laptop, with neither CI nor GITHUB_ACTIONS set
  when [t1] a human runs `npx jest -c jest.acceptance.config.ts actors-yml` direct
    then the header reads `box = shared` — the safe box is the default, not an opt-in
```
