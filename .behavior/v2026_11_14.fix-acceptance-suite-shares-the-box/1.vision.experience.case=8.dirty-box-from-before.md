# case 8 — dirty-box-from-before · runner · sharp · alterpath

## .narrative

jo pulls the fix onto a laptop that has run the suite for weeks. `/tmp` already holds hundreds of
`rhachet-test-*` dirs, and ~150 brain stubs from old runs sit reparented to init; they hold
memory. jo runs a scoped acceptance run.

the run adds no new dir that outlives it and no new stub. it does not reach back and reap the old
ones on its own: they carry no run id it minted, and a suite that kills processes it did not
spawn is a hazard of its own (`rule.forbid.unscoped-process-kills`). instead, the setup counts
the residue it can attribute to this checkout — `rhachet-test-*` dirs in the os temp root, and
`stubBrainCli.cjs` processes whose argv names this worktree's path — and, if it sees any, prints
one notice that names a reap scoped the same way:

```
ℹ leftovers from earlier runs on this box, which no run of this checkout adds to
   ├─ 212 rhachet-test-* test repo dirs in /tmp, from checkouts that predate the fix
   │  └─ to clear those a day old or more, run once
   │     └─ find /tmp -maxdepth 1 -name 'rhachet-test-*' -mmin +1440 -exec rm -rf {} +
   └─ 148 brain stubs of this checkout, older than any stub of today
      └─ a reboot clears them
```

jo runs the `find` once; the dirs a day old or more are gone, and a dir a live run still uses is
younger than a day, so it stays. the stubs go at the next reboot. the notice proposes no pattern
kill: a `pkill` by argv could hit a live peer's stub, so it names the reboot instead. the box is
clean from then on, because no new run adds to the pile.

why alterpath: the residue is a one-time cost of the pre-fix era. if this notice broke, jo would
still have a clean box from now on and could reap the old pile by hand or by reboot.

why sharp: jo meets an edge (a box that is not clean though the fix is in) and needs to know it
is not the fix that failed. the notice says so and names the reap.

## .bdd `[tn]` timeline (sketch)

```
given a laptop with 212 old `rhachet-test-*` dirs and 148 old stubs from pre-fix runs
  when [t0] jo runs a scoped acceptance run that passes
    then after exit the count of `rhachet-test-*` dirs is still 212 (none added)
    and  the count of stubs is still 148 (none added)
    and  the setup prints the leftovers notice: the age-bound `find` for the dirs, and the reboot
         hint for the stubs
    and  the notice proposes no pattern kill (no `pkill`, no `kill`)
  when [t1] jo runs the printed `find` once
    then every `rhachet-test-*` dir a day old or more is gone
    and  a dir younger than a day, and any dir of another name, is kept
given a peer worktree's stubs on the same box
  when [t2] jo reads the notice
    then naught in it would end the peer's stubs — the only cure it names for stubs is a reboot
```

> evolved in verification to the shipped form: a one-line hint, not a repo-local reap skill.
> proven by `asResidueNotice.test` [case1] (the render, and no pattern kill) and
> `asResidueNotice.integration` (the printed `find`, run for real in a temp root: the old dir
> goes, the fresh and the foreign dirs stay).
