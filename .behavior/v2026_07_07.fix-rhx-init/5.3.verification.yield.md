### expansion coverage (bare-sigil `rhx init +role` alias, cases x1–x6)

the wish/vision expansion (2026-07-14) adds an `rhx`-shorthand alias: a bare front `+role`/`-role`
on `rhx init` expands to `run init --keys --hooks --roles <tokens>`. it lives purely in the
`bin/rhx` proxy (not the `rhachet init` contract). the vision set the same coverage rule: **no case
x1–x6 ships without its named acceptance test green**. grain is acceptance — the proxy shells out to
the built binary, so tests invoke `bin/rhx` as a subprocess.

| case | behavior | test (`blackbox/cli/rhx.acceptance.test.ts`) | status |
|------|----------|----------------------------------------------|--------|
| x1 | `rhx init +architect` fresh → role linked + `--keys`/`--hooks` injected, exit 0 | case5 t0 | ✅ |
| x2 | `rhx init --roles +architect` explicit → NO keys/hooks inject | case5 t1 | ✅ |
| x3 | `rhx init -ergonomist` remove-sigil recognized (not a flag) → role unlinked | case5 t2 | ✅ |
| x4 | `rhx init +architect -ergonomist` multi-sigil → one expansion, add+remove | case5 t3 | ✅ |
| x5 | `rhx init architect ergonomist` bare absolute names → alias expands (flag-driven mode) → both linked + keys/hooks | case5 t4 | ✅ |
| x6 | `rhx init --help` / `-h` → recognized flag → flag mode; `-h` not read as remove-sigil | case5 t5 | ✅ |

markers: stdout `🔑 keyrack init` proves `--keys` was injected; stdout `🔭 search for linked roles
with hooks` proves `--hooks` was injected. the mode is **flag-driven** (refined 2026-07-14): any
recognized `init` flag → flag mode (no inject); a tokens-only tail (bare names or `+`/`-` sigils) →
alias mode. x2 (explicit `--roles`) and x6 (help flag) are the anti-regression guards that flag mode
still wins when a recognized flag is present.

net: all 6 expansion cases bound to a named green acceptance test. no gap.
