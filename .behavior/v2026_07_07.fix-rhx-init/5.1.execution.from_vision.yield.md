# 5.1 execution — incremental `--roles +role/-role` on `rhx init`

tracks the build of the vision (`1.vision.yield.md`) against wish [#411](https://github.com/ehmpathy/rhachet/issues/411).

---

## pivotal discovery (trust-but-verify during execution)

the vision assumed (a) commander flatly rejects `-role`, and (b) no incremental parse/compute logic exists. **both were partly wrong** — verified against source:

- **enroll already ships incremental `--roles`**: `invokeEnroll.ts` uses `-r, --roles <spec>` (single value) with `.allowUnknownOption(true)`; the test `invokeEnroll.integration.test.ts:195` proves `--roles -driver` is accepted by commander for a *single-value* option. so `-role` works for single-value options; the vision's rejection claim was true only for the *variadic* `<roles...>` form.
- **parse + compute semantics already exist**: `parseBrainCliEnrollmentSpec.ts` (mode replace/delta, `+`add/`-`remove, mixed-rejection `:66-70`, empty-after-prefix `:38/:49`, add+remove conflict `:73-85`) and `computeBrainCliEnrollment.ts` (delta mode: `+present` no-op, `-absent` no-op — `:81-88`). these match wish requirements e1, e2, e3, e7, e9 exactly.

**what is still genuinely new**: init *links symlinks* (`execRoleLink`); enroll only writes brain config. so the **removal-of-symlinks** path (`execRoleUnlink`) does not exist and is the core new build (e11 native `.this` guard, e12 empty-dir cleanup, e13 broken-symlink robustness, e8 removal-side repo ambiguity).

---

## design decision (autonomous, wish-faithful)

honor the wish's literal `-role` notation. keep init's variadic `--roles <roles...>` for backward-compat of the absolute form (`--roles mechanic behaver` — e16). handle the `-role` variadic-collection limit via **argv preprocess in the CLI entry** (real usage → `process.argv`; acceptance tests run the CLI as a subprocess per `accept.blackbox`, so they exercise the real argv path). integration + unit tests target the domain ops directly (no commander).

reuse posture: the *parse/classify* logic mirrors enroll but the input shape (token array vs comma string) and downstream (symlink vs config) differ; per wet-over-dry + bounded-contexts, init gets its own `classifyRoleTokens` transformer rather than a cross-domain import of enroll internals. potential future lift noted for the reviewer.
