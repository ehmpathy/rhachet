## expansion (scope addition) — 2026-07-14

> added by the wisher at dogfood of the base `--roles +role` feature. mirror to github #411.

### what

`rhx init +$role` (and `-$role`) as a **bare-sigil alias** — no `--roles` flag, no `--keys`/`--hooks`
flags needed:

```sh
rhx init +learner
```

is an alias for:

```sh
rhachet init --keys --hooks --roles +learner
```

i.e. a bare front `+role` / `-role` positional on `rhx init`:
1. implies `--roles` (the sigil tokens flow into the incremental role set), and
2. auto-includes `--keys` and `--hooks`, so the produced role set also gets its keyrack manifest +
   brain hooks synced in the same call.

### why

the incremental `--roles +role` form (the base of this task) still requires the `--roles` flag and
does not touch keys/hooks unless you also pass those flags. for the common "enroll a role and make it
fully usable" path, that is three flags to remember. the bare-sigil alias makes the one-liner
ergonomic: `rhx init +learner` enrolls the role AND wires its keys + hooks in one shot.

### notes

- this is an **`rhx`-shorthand-layer** alias (the `bin/rhx` proxy), not a change to the `rhachet init`
  contract. `rhachet init` continues to require explicit `--roles`/`--keys`/`--hooks`.
- the explicit form `rhx init --roles +learner` continues to work unchanged (no double-inject of
  keys/hooks).

### refinement (2026-07-14, at dogfood) — flag-driven mode select

> the wisher hit `rhx init learner` (bare absolute name) and expected it to work like `+learner`.

the alias no longer keys off the `+`/`-` sigil alone. the mode is **flag-driven**:

- **any recognized `init` flag in the tail** (`--roles`/`--keys`/`--hooks`/`--config`/`--prep`/
  `--mode`/`-h`/`--help`) → **flag mode**: pass through to `rhachet init` unchanged (the user drives
  explicitly).
- **tail carries only role tokens** — bare names (`learner`), add-sigils (`+learner`), or
  remove-sigils (`-learner`) — → **alias mode**: inject `--keys --hooks --roles` in front.
- **no args** (`rhx init`) → pass through, so usage still prints.

so all of `rhx init learner`, `rhx init +learner`, `rhx init -learner`, `rhx init a +b -c` are the
ready-to-use alias; only an explicit flag opts you into the raw `rhachet init` contract. bare absolute
names are now **in scope** (the earlier "future bare-positional sense of init" collision concern is
moot — `rhachet init` has no bare-positional contract today).
