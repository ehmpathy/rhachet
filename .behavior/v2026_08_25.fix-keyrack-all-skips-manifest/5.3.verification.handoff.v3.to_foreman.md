**the reviewer is right on the rule, and I said so.** `rule.forbid.acceptance.mocks` permits a mock

### why I did not simply fix it

the reviewer offered two exits. **both are worse than the violation.**

**1. rename to `.integration.test.ts`** — a misclassification, twice over:

- `rule.forbid.unit.remote-boundaries`'s own classification guide puts *"blackbox via built
  artifact's contract"* at **acceptance**. this suite spawns `bin/run` and asserts its
  stdout/exit-code. **it is correctly classified today.**
- `rule.forbid.integration.mocks` carries the identical prohibition and identical exception clause,
  so `.real = NONE` fails there too. the violation is relocated, not cured.

⇒ a suffix chosen to dodge a rubric is the move this repo already grades a blocker elsewhere
(*"a whole-tier run assembled by hand to dodge this rule"*). **a mock the gate can see is a mock
someone will fix.**

**2. build a real-github test** — that is the dream, and it is cross-vault.
