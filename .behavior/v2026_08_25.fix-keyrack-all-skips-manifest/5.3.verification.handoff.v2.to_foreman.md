## ⚠️ the convergence mechanism IS AN INPUT TO the overflow — measured at i015

I wrote five tagged `.taken` files (the `via-a-taken-per-point` obligation) and re-arrived. every
lane got **worse**:

| lane | i014 | i015 | delta |
|---|---|---|---|
| r1 | 87.1% | **88.6%** | +1.5 |
| r2 | 82.8% | **84.8%** | +2.0 |

| r5 | 83.3% | **84.8%** | +1.5 |

targets went 181 files / 718.0k → **184 files / 726.5k**. two mechanisms, both structural:

1. **artifacts join the target set.** `--diffs since-main` unions untracked files, so the dream,
   this handoff, and the blocker note became review *targets* (+8.5k). the takens themselves do
   not — `.reviews/peer/` is gitignored
2. **takens join the prompt as `<conversation>`.** `compileReviewPrompt.ts` threads every prior
   `.given`/`.taken` pair in so the reviewer can weigh them (+~6k)

⇒ **a taken cannot converge an overflow. it is one of its inputs.** the more I converge, the less
able the lane is to run. that is a self-fed loop, and it is the direct reason this is not a
disagreement I can talk my way out of.

## the two cures, both yours

### cure A — fix the cause, so the lanes actually grade

one edit to `5.3.verification.guard`, applied to the five l1 peer commands:

```diff
- npx rhachet run --repo bhrain --skill review --rules '…' --output '…'
+ npx rhachet run --repo bhrain --skill review --rules '…' --output '…' \
+   --focus pull --brain anthropic/claude/code
```

`--focus pull` hands the reviewer paths in place of contents, so prompt size no longer follows diff
size. it needs a brain with tool use — `anthropic/claude/code`, `anthropic/claude/code/opus`, or
`openai/codex`; the default `fireworks/deepseek/v4-flash` is a `BrainAtom` and cannot.

⭐ **my recommendation.** attempt 3 above is the proof it works at exactly this scope: 165s and
$1.16 for r1, and real verdicts from all five.

a narrower variant, if you prefer to keep push mode: `--paths-wout '.behavior/**'`. it clears
r2–r5 with room, and clears r1 by a hair.

### cure B — overrule, as at 5.1

```bash
rhx route.stone.set --stone 5.3.verification --as overruled
```

faster, and it matches what 5.1 did. it leaves the cause in place for stone 6 and beyond.
