## blocker 1 🔴 — the tree is 2 commits behind main, which re-architected the same functions

### what is true

```
git rev-list --left-right --count origin/main...HEAD   →  0 ahead, 2 behind
origin/main = c512891 (v1.47.3)
this branch = 6840c69 (v1.47.2) + uncommitted work
```

the commit in between is **`6f4128d fix(keyrack): unlock a machine-wide key cut at a reach (#485)`**
— 3,202 insertions across 27 blackbox files and 39 keyrack source files. it lands squarely on this
wish's surface.

### why it cannot be verified from here

this wish refactored `unlockKeyrackKeys.ts` (removed a ~125-line slug IIFE into
`getAllKeyrackSlugsForUnlock`). `6f4128d` **also** refactored `unlockKeyrackKeys.ts` (+158), into
four different session operations. the two decompositions are complementary in intent and
overlapping in body, so the merge is a judgment call, not a mechanical one.

⚠️ **and the semantic half matters more than the textual half.** `6f4128d` fixes
`getAllMachineWideSlugsForEnv` — it *"read the ADDRESS-keyed map keys as if they were slugs"*. on
this tree it still does. this wish then added, downstream of that unfixed helper:

- `getAllKeyrackSlugsForOrg` — parses each returned string as a slug. an address is
  `slug@reachExid`; the `@` fails the decoder ⇒ **`--org` would silently drop every reach-cut
  machine-wide key**
- `emitKeyrackUnscopableRowsNotice` — would then announce those addresses as *"rows that name no
  org and no env"*, a **false** claim about a well-formed key

⇒ so the two changes are not merely compatible — **only the pair is correct.** main fixes the
source of the strings; this wish adds the consumers that depend on them being slugs.

### what I tried

| # | attempt | outcome |
|---|---|---|
| 1 | `rhx git.branch.rebase begin` | ✋ `error: no commit quota set` |
| 2 | `rhx git.commit.uses get` (check the precondition before escalation) | `no quota set` · `global: blocked` |
| 3 | verify against the current tree instead | done, and green — but it proves the wrong tree |
| 4 | read `6f4128d` directly (`git show`, no quota needed) and hand-analyze the collision | **succeeded** — that analysis is the table above and in the yield |

attempt 4 is as far as read-only access reaches. to *verify* the merge state I must first
*create* it, and every path to that (`rebase`, `merge`, `stage`, `commit`) is behind
`git.commit.uses`, which is globally blocked.

### why this is fundamentally foreman-only

the quota is human-granted by design — `git.commit.uses` exists precisely so a clone cannot move
git history on its own. this is not an obstacle I can engineer around; it is the guardrail working
as intended.

### what unblocks it

```bash
rhx git.commit.uses set --quant 3 --push block
```

then I will: stage + commit this work, rebase onto `origin/main`, settle the
`unlockKeyrackKeys.ts` overlap so **both** decompositions survive, re-run every tier, and
re-arrive.

⚠️ **worth your judgment before you grant it:** the `unlockKeyrackKeys.ts` merge is a fulcrum.
main split the *omission/disposition* half; this wish split the *slug-resolution* half. I judge
they compose cleanly — the two touch different concerns of one function — but that is a best-guess
on code I have only read, never merged. if you would rather land `6f4128d`'s shape and re-apply
this wish's extraction on top, say so and I will take that route instead.

## blocker 3 ⬜ WITHDRAWN — the real-ssm coverage already exists, and I was the source of the error

⚠️ **do not act on this. no provision is needed.** it is kept rather than deleted because the
mistake is the useful part of it.

### what I claimed

that `rule.require.acceptance-journey-coverage` point 4 was unmet — that the whole `aws.params`
surface ran against `genFakeSsmServerDetached`, and **no test in this repo dialed real ssm** — so
you had to provision an aws account, a live SecureString, and `ssm:GetParameter` ci credentials
before this gate could pass.

### what is true

**four** integration suites dial real aws ssm. all pre-branch (`5854bb4`, #453), all green:

| suite | what it proves against real ssm |
|---|---|
| `getOneKeyrackAwsParam.integration.test.ts` | provisions its own SecureString, reads it back decrypted, asserts value + type, tears it down |
| `delKeyrackAwsParam.integration.test.ts` | the real destroy, a confirm-gone read, an idempotent re-del |
| `vaultAdapterAwsParams.integration.test.ts` | unlock → get → grant, plus the real absent-param and plaintext-`String` refusals |
| `setKeyrackAwsParamGithubApp.integration.test.ts` | the real write path |

each passes `endpoint: null`, and **none appears at any `KEYRACK_AWS_SSM_ENDPOINT` call site**, so
the emulator override cannot reach them. verified by a run, not by a read:

```
rhx git.repo.test --what integration --mode apply --scope 'path://aws.params'
  →  9 suites · 42 passed · 0 failed · 0 skipped
```

`useKeyrack()` supplies the live creds and never skips a row — absent creds fail the suite loud.

### how the error happened

I wrote a `.gap` note on the acceptance suite that read *"no repo test dials real ssm today."* I
meant *"no row in THIS file does."* what I wrote was a claim about the whole repo. two peer lanes
then cited that sentence back to me as their evidence, and **I conceded to my own unverified
sentence** and escalated it to you.

that sentence contradicted the suite's own `.scope` line — *"the live SSM read/write is proven in
the adapter + communicator integration tests"* — **six lines above it**. the contradiction sat on
screen the whole time.

### the lesson, and where it now lives

> a claim of the form *"no test does X"* is a claim about the repo, so it needs a repo-wide search
> before it is written down — the same bar I hold a reviewer's *"these are the only N"* to.

I applied that bar to the reviewers and not to myself, which is the same failure that produced my
wrong scope-leak refute earlier this round. fixed at cause (`rule.require.solve-at-cause`): the
`.gap` note on `keyrack.vault.awsParams.acceptance.test.ts` now bounds itself to its own tier, names
all four real-ssm suites so the claim is checkable in one grep, and records why the prior draft was
false.
