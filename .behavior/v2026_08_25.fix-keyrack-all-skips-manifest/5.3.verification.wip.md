## the defect, as the snapshots showed it

one remedy — *"this repo has no keyrack.yml; make one"* — was spelled two ways, in refusals a
human can meet minutes apart:

| site | fix text |
|---|---|
| `asKeyrackFilterOrg.ts:54` (the sweep verbs) | `run: rhx keyrack init --org <your-org> (or filter by --org @all for machine-wide keys)` |
| `getAllKeyrackGrantsByRepo.ts:47` (the repo-scoped fetch) | `create keyrack.yml in repo root with env and key definitions` |

the second is the weaker of the two, and not merely by symmetry: it names a **file** and leaves
its schema to guesswork, where the first names a **command** that writes that file correctly.
`rule.require.errors-name-the-fix` asks for the concrete next move, so the file-shaped text
describes the goal rather than a step toward it.

## the fix

`getAllKeyrackGrantsByRepo.ts` now offers `run: rhx keyrack init --org <your-org>`.

⚠️ **the parenthetical is deliberately absent here, and the reason is at the site.** the sweep
twin appends `(or filter by --org @all for machine-wide keys)` because a sweep CAN be re-scoped.
this throw serves a repo-scoped ask by definition, so no such re-scope exists — to append it
would name a fix that does not fix. a divergence with a stated cause is not fragmentation.

## proof

`grep 'create keyrack.yml in repo root'` now matches **one** file — the ⚠️ note that quotes the
prior text — and **zero** snapshots. every rendered fix reads:

```
└─ hint: run: rhx keyrack init --org <your-org>                                  # repo-scoped
└─ hint: run: rhx keyrack init --org <your-org> (or filter by --org @all …)      # sweep
```
