### ⚠️ the semantic collision — RAISED, THEN DISPROVEN BY TEST

main's fix says `getAllMachineWideSlugsForEnv` *"read the ADDRESS-keyed map keys as if they were
slugs"*. on **this** tree it still does — that half is confirmed
(`getAllMachineWideSlugsForEnv.ts:32` reads `Object.keys(hostManifest.hosts)`).

the hazard raised from it was:

1. **`getAllKeyrackSlugsForOrg`** — an ADDRESS is `slug@reachExid`, which holds an `@` and so
   "fails `asKeyrackSlugFullOrNull`" ⇒ *a reach-cut machine-wide key would be silently dropped
   by `--org`*
2. **`emitKeyrackUnscopableRowsNotice`** — would then report those addresses as *"rows that name
   no org and no env"*, a false statement about a well-formed key

**both are false, and the claim was not merely argued down — it was clamped.**
`getAllKeyrackSlugsForOrg.test.ts` `[case6]`, run green:

```
'@all.camp.GITHUB_TOKEN@bot@example.com'   --org @all  →  KEPT
```

⇒ **the decoder splits on `.`, never on `@`.** an address's `@` lands inside the KEY-NAME
segment — `parts.slice(2).join('.')` (`asKeyrackSlugFullOrNull.ts:20`) — which carries no shape
rule at all. the org segment still reads `@all`, so the row survives the narrow. claim 2 falls
with claim 1, because `getAllKeyrackSlugsWithNoScope.ts:25` calls **the same decoder**, so a
string that parses cannot also be classed unscopable.

⚠️ **the two operations agree BY CONSTRUCTION, and that is the wish's own discipline that paid
out.** had the filter used a `split('.')[0]` and the classifier a parser — the shape defect 8
closed — they would have disagreed on exactly this string, one keep and one "names no org". the
one-parser rule is why this collision is a non-event.

⇒ **the lesson worth a record: a blocker asserted from a code trace is a HYPOTHESIS until a test
runs it.** this one read as rigorous — it named two real operations, a real upstream defect, and
a plausible mechanism — and it was wrong at the first `split`. a verification gate that accepts a
traced blocker without a clamp ships fear as if it were fact, and the "fix" for a defect that
does not exist is how a real one gets introduced.

⇒ the merge remains **required** (main repairs a genuine upstream misread), but it is **not
urgent for this reason**, and no downstream repair is owed here.

#### family C.2 — nested objects expanded (2 renders, 2 files)

| snapshot | before → after |

**why.** these were the only two `key: {…}` leaves left in all of `blackbox/cli/__snapshots__` —
machine syntax inside a tree whose every other leaf is `key: value` prose. it is the same blemish

keeps its json rather than invent a recursive rail. a parent key that names a secret never expands —
it falls to the json path where the mask redacts the whole object at once, so a credential gains no
surface from a prettier render. both masks (key-name and value-shape) now apply at **every** depth.

### shape B — a mechanism inferred from its visible outcome (3, 4) — ⚠️ NO rule

both reason **backward from what I could see to how it must work**:

when the observation is perfect.

| shape | the counter-move | cost |
|---|---|---|
| A — absence | **widen** — grep the repo before the claim | one search |
| B — mechanism | **narrow** — read the one operation that decides it, or observe it once | one file, or one run |

for shape B the counter-move is cheap and exact:

- the prefix: `head -12` of the file that prints it
- the budget: one `--as arrived`, then read `4/11` against `3/11`

— *"have you tried to converse with the reviewers?"* — is what forced instance 4 into the open;
the measurement it prompted disproved my own claim inside two minutes.

### the rule this owes

shape A has `rule.require.search-before-you-claim-absence`. shape B now has its peer:
`rule.forbid.mechanism-inferred-from-outcome` — *an outcome is evidence a mechanism ran, never a

## the vocabulary this stone paved, and what each one cost before it existed

⇒ the general form, now in `term=clamp`: **a ban on a token is almost always a ban on the wrong

column it sits in. the same error in vocabulary form is a word that spans two cells of a matrix.
