# fix(keyrack): an `@all` read must not load a repo manifest it never consults

## .the authoritative source

**`ehmpathy/rhachet#467`** carries the full diagnosis, with source citations verified against
`rhachet@1.45.1`. read it first — this file is the dispatch, that issue is the spec
(`rule.require.handoffs-at-source`).

## .what

`rhx keyrack get` for an `@all` slug — a machine-wide key that needs **no repo manifest** — yields
the credential from inside a repo whose `.agent/keyrack.yml` `extends` a file the clone does not
vendor.

today it dies instead. so a credential that is correct, present, and unrelated to the repo is
unreadable from inside most of our clones.

## .why

the manifest load happens **before** the requested slug's org sigil is read, so an `@all` read pays
the full cost of a manifest it will not consult — and inherits every way that manifest can fail.

**rhachet's own comment already states the rationale** (`genContextKeyrackGrantGet.js:15-18`):

> that path serves only machine-wide `@all` keys, which need no repo manifest, so skip the load and
> leave `repoManifest` null (the no-manifest read path handles `@all` + full slugs)

that rationale is applied to the **null-gitroot** branch only. the identical logic holds for a
**non-null** gitroot with an `@all` slug, and there it is not applied. so the fix is not a new
policy — it is the extant policy, applied where it already belongs.

## .acceptance

- an `@all` slug read from inside a repo whose manifest `extends` an absent file **succeeds**
- it succeeds whether or not a gitroot is found — the two paths agree
- a **non-`@all`** slug still loads the manifest, and still fails loud on a broken `extends`
  (that failure is correct, and this must not soften it)
- a clamp covers the edge case: a repo manifest with a deliberately broken `extends`, read once
  with an `@all` slug (passes) and once with a repo slug (still fails loud) —
  `rule.require.clamp-edge-cases`

## .what was already verified

facts from the issue, ground for your search rather than instructions:

- `genContextKeyrackGrantGet.js:19` loads the manifest whenever a gitroot is found
- `hydrateKeyrackRepoManifest.js:181` throws `BadRequestError` when an `extends` target is absent
- the **twin defect is already fixed** at 1.45.1 — `getGitRepoRootOrNull` tolerates a null root,
  and its comment names this exact family of caller

  fails*
- **out of scope: any change to the `@all` credential's semantics.** it already works once read
