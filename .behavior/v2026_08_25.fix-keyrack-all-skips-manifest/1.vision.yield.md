# 1.vision — an `@all` read must not load a repo manifest it never consults

## the outcome

a machine-wide credential is a fact about **the box**, never about a repo. so no keyrack verb may
require a repo artifact — gitroot or manifest — to serve an `@all` ask.

| ask | before | after |
|---|---|---|
| `@all` read, clone with a self-contained manifest | ✅ | ✅ |
| `@all` read, clone whose manifest `extends` an unvendored file | ⛈️ `BadRequestError` | ✅ |
| `@all` read, cwd is not a repo | ✅ (fixed at 1.45.1) | ✅ |
| repo-org read, broken `extends` | ⛈️ throws loud | ⛈️ **unchanged** |

**the mis-key.** the load is branched on *"is there a repo?"*. it must branch on *"will this ask
consult one?"* those agree everywhere anyone tested, and diverge exactly where we live: a repo
present, a manifest that cannot hydrate.

## the invariant

> **all keyrack verbs serve `--org @all` identically** — no repo manifest required, no gitroot
> required. (wisher, 2026-08-25)

on a **repo-scoped** verb the bar is weaker but exact: an `@all` ask must be **well-defined** — a
stated refusal passes; an incidental one (a strict gitroot that happens to bite, a throw from a
manifest never consulted) does not.

## the two denial classes

| class | the denial | verbs |
|---|---|---|
| **1 — unspellable** | no `--org` flag declared | `source` `unlock` `relock` `status` `list` `fill` `firewall` |
| **2 — eager repo-fetch** | a repo artifact fetched **above** the `@all` branch | gitroot: `set` `del` `fill` `firewall` · manifest: `get` `source` `unlock` |

full per-verb inventory with line citations:
`.agent/repo=.this/role=any/briefs/define.keyrack-verb-machine-wide-support.md`

## the machinery is already complete

`@all` is handled at **~20 downstream sites** — the slug cast (`asKeyrackKeySlug.ts:76`), attempt
promotion (`asResolvedAttempt.ts:25`), grant read (`getOneKeyrackGrantByKey.ts:45`), unlock
session (`unlockKeyrackKeys.ts:261`), the daemon protocol (`handleGetCommand.ts:36-40`), the
aws.params adapter (`:25`, `:32`, `:33`), the host-manifest schema (`schema.ts:76`).

**`set` and `del` already implement `--org @all`:**

```ts
// invokeKeyrack.ts:1069-1071 — set
const gitroot = await getGitRepoRoot({ from: process.cwd() });   // ⛈️ dies here
const repoManifestFound = await daoKeyrackRepoManifest.get({ gitroot });
…
// :1122-1125 — the branch that would have served the ask
if (opts.org === '@all') { resolvedOrg = '@all'; }               // ✅ already correct
```

`del` carries the identical pair (`:1308`, `:1322`). **the denial is upstream; not one verb lacks
the logic.** so the full invariant is one fix shape applied at every mis-keyed site, not a set of
new features.

## the shape

three named operations (`rule.require.named-transformers`):

```ts
// asKeyrackAskOrg.ts — the ONE canonical read of an ask's org
// .why = an ask names its org two ways (--org flag, an `@all.`-prefixed slug) whose no-org
//        defaults DISAGREE ('@this' from cli, undefined from sdk). one cast is what makes
//        "identically" true by construction rather than by N careful edits
// .note = STRICT union — a mixed ask yields the repo org, never @all (e1)
export const asKeyrackAskOrg = (input: {
  for?: PickOne<{ keys: string[]; repo: true }>;
  org?: string;
}): string => { … };

// isKeyrackSlugMachineWide.ts — built on asKeyrackKeyOrg, never a raw startsWith (e9)
export const isKeyrackSlugMachineWide = (input: { slug: string }): boolean => { … };

// isKeyrackAskMachineWide.ts
export const isKeyrackAskMachineWide = (input: {…}): boolean =>
  asKeyrackAskOrg(input) === '@all';
```

applied:

```ts
// genContextKeyrackGrantGet.ts
const repoManifest =
  input.gitroot && !isKeyrackAskMachineWide({ for: input.for, org: input.org })
    ? await daoKeyrackRepoManifest.get({ gitroot: input.gitroot })
    : null;
```

new inputs are **optional** — an untold ask loads the manifest, as today. the published sdk
signature (`sdk.keyrack.ts:55`) is unchanged.

## the contract

```sh
# u1 — credential helper, from a broken-manifest clone
rhx keyrack get --owner ehmpath --org @all --env camp --key GITHUB_TOKEN --unlock --value
# before → BadRequestError   after → ghp_…

# u2 — full slug
rhx keyrack get --owner ehmpath --key @all.camp.GITHUB_TOKEN --unlock --value

# u3 — repo credential, same clone → STILL fails loud (deliberate)
rhx keyrack get --owner ehmpath --key MY_KEY --env prep --value
```

```ts
// manifest-free — the `@all.` prefix is what makes it so, never the env
await getKeyrackKeyGrants({
  for: { keys: ['@all.camp.GITHUB_TOKEN'] },
  with: { unlock: true }, owner: 'ehmpath', env: 'camp',
});
```

⚠️ `env` is **inert** for a full slug: `getOneKeyrackGrantByKey.ts:71-75` returns the slug without
a read of it, and the unlock derives env from the slug (`getKeyrackKeyGrants.ts:205`). the identity
gate's `env ?? 'all'` (`:192`) is **error metadata only** — so on one unlock it can disagree with
the slug's env. metadata-only today; noted, out of scope.

## `--org` on a sweep verb

`--org` on `unlock`/`source`/`list`/`status` is the class-1 fix. **its default must be the verb's
extant scope, never `@this`.**

`unlock`'s default scope is already a **union** — repo ∪ machine-wide
(`unlockKeyrackKeys.ts:178-187`, clamped at `.test.ts:257`, `:295`). an `@this` default would
silently drop every machine-wide key from the swept set.

| ask | scope | manifest |
|---|---|---|
| `unlock --env camp` (bare) | repo ∪ machine-wide | bound — **unchanged** |
| `unlock --env camp --org @all` | machine-wide only | free |
| `unlock --env camp --org @this` | repo only | bound |

**one sense of `--org`, two arities** — it names provenance on every verb
(`invokeKeyrack.ts:465-467`); a keyed ask **selects** a slug segment, a sweep **filters** the set.
`--env` already behaves this way. see
`domain.terms/term=sweep._.choice.example=org-filter-vs-selector.md`.

**additive and reversible** (wisher): the union default stays, so no extant caller observes a
change. a later swap to `@this` is then a one-line default change, reviewed on its own merits.

## edgecases

| # | case | behavior |
|---|---|---|
| e1 | ask names an `@all` key **and** a repo key | manifest **loads** — strict union; any member that needs it wins |
| e2 | `--org @this` | manifest-bound — `@this` *means* the manifest's org (`asKeyrackKeySlug.ts:77`) |
| e3 | full slug, real org (`ehmpathy.prep.FOO`) | manifest-bound — to skip retires the `ORG_MISMATCH` guard (`:80-85`) |
| e4 | `--for repo` | manifest-bound, hard — `getAllKeyrackGrantsByRepo.ts:44-49` throws on a null manifest |
| e5 | builder called with no ask | manifest-bound — backwards compatible |
| e6 | `@all` ask, non-repo cwd | works (1.45.1); now both paths agree |
| e7 | `@all` ask, locked, `--unlock` | a **second** load at `getKeyrackKeyGrants.ts:170-172` — also in scope |
| e8 | manifest merely **absent** | yields `null`, no throw (`loadManifestExplicit.ts:24-25`) — unaffected |
| e9 | `@allstar.prep.FOO` | manifest-**bound** — test the org segment, never a bare `startsWith('@all')` |
| e10 | no org at all — `'@this'` (cli) vs `undefined` (sdk) | manifest-bound on both ⇒ **test positively for `@all`** |
| e11 | bare `unlock --env camp` | manifest-bound — a **union** ask, not a machine-wide one. correctly `false` |

### the error is asymmetric

| the predicate errs by | cost |
|---|---|
| understatement (`false`, truth `true`) | one wasted load — today's behavior |
| **overstatement** (`true`, truth `false`) | load skipped ⇒ slug taken verbatim ⇒ **`ORG_MISMATCH` never runs** |

⇒ test **positively** for `org === '@all'`. never `org !== '@this'` — that reads the sdk's
`undefined` as machine-wide and disables the guard wholesale.

## `source` — key-scoped vs repo-scoped

wisher: *"either for a specific key or for a repo."*

| ask | manifest |
|---|---|
| `source --key @all.…` | not required |
| `source --key MY_KEY` | required |
| bare `source` (a repo sweep) | required, hard |

⇒ the `ConstraintError` at `:858-863` must become **conditional on the repo-scoped branch**.
today it fires whenever `repoManifest` is null, even for a key-scoped ask — which would grant at
`:852` then refuse for a manifest never needed.

## evidence

**the design intent** — `getAllMachineWideSlugsForEnv.ts:6-11`:

> *"an `@all` key is MACHINE-WIDE (the box's own namespace), so it must be unlockable with NO repo
> manifest at all — the bootstrap-to-clone credential path: the github-app install token is
> vaulted under `@all` precisely so it can be fetched from anywhere, even outside any repo,
> before any repo is cloned."*

**a manifest load has four throw modes**, so a skipped load neutralizes all four; a
caught-and-degraded load would have to enumerate them:

| throw | site |
|---|---|
| invalid yaml | `loadManifestExplicit.ts:35-39` |
| invalid schema | `loadManifestExplicit.ts:44-48` |
| circular extends | `hydrateKeyrackRepoManifest.ts:312-316` |
| extended keyrack not found | `hydrateKeyrackRepoManifest.ts:333-338` |

**the throw escapes as a malfunction** — `getAllKeyrackGrantsOrEmitBlocked.ts:32` catches only
`ConstraintError`, and `ConstraintError extends BadRequestError`, so a bare `BadRequestError` is
not caught. it lands on stderr, and a stdout-capture caller reads `''` — "not found."

**the premise reproduces in this repo.** `.agent/keyrack.yml` is tracked and extends six role
manifests; `git check-ignore` confirms **5 of 6 are gitignored**. a fresh clone of rhachet hits
`extended keyrack not found` until `rhachet init` runs.

**the cli promises this to users** — `invokeKeyrack.ts:1137`: *"for sudo credentials without
keyrack.yml, use `--org @all`"* (and `:1409`). `set` advertises it while its own strict gitroot
(`:1070`) forbids it.

**the rationale is written five times, mis-keyed at each** —
`genContextKeyrackGrantGet.ts:40-43`, `getKeyrackKeyGrants.ts:106-109`, `invokeKeyrack.ts:799-800`,
`:1586-1588`, `unlockKeyrackKeys.ts:178-181`. each says *"`@all` needs no manifest"*; each branches
on *"is there a repo?"* ⇒ a **named predicate** is the fix, not a sixth hand-rolled condition.

**a repo manifest can never emit an `@all.*` slug** — `getAllKeyrackSlugsForEnv.ts:19-21` derives
every slug from `manifest.org`. machine-wide and repo-scoped are disjoint by construction.

**downstream already tolerates a null manifest for `@all`** — `getOneKeyrackGrantByKey.ts:45-53`,
`:70-75`; `asResolvedAttempt.ts:22-25`; `unlockKeyrackKeys.test.ts:257` (*"[case5] repoManifest
absent — machine-wide @all keys unlock without a repo manifest"*).

## clamps

`rule.require.clamp-edge-cases`. teeth proven by dogfood: revert the fix → red; restore → green.

**branch clamp** — a temp dir whose `.agent/keyrack.yml` extends an absent file, read twice:

| row | ask | expect |
|---|---|---|
| the fix | an `@all` slug | no throw |
| the guard | a repo-org key | **still throws** `BadRequestError` |

plus a **second throw mode** (invalid yaml) with the same two asks — so the clamp pins the axis
*"can this manifest load?"* rather than any `extends`-shaped detail.

two tiers: **operation level** takes `gitroot` as an input, so it needs only a directory
(template: `getKeyrackKeyGrant.integration.test.ts:59-62`). **cli level** needs a real git repo
and proves the reported repro.

**predicate clamps** — a branch test cannot catch an over-report, because that failure is silent
and *successful*:

| clamp | axis | `false` for | `true` for |
|---|---|---|---|
| R13 | slug | `ehmpathy.prep.FOO`, `@allstar.prep.FOO`, `@this.prep.FOO`, `ehmpathy.all.FOO` | `@all.camp.TOKEN` |
| R14 | org input | `undefined`, `'@this'` | `'@all'` |

**sweep clamps** — for `--org` on `unlock`:

| clamp | ask | expect |
|---|---|---|
| R15 | bare `unlock --env camp`, repo manifest + `@all.camp.*` host key | **both** unlock — byte-identical to today |
| R16 | `--org @all`, broken-manifest repo | machine-wide unlocks; manifest never loaded |
| R17 | `--org @this` | repo keys only |

R15 is the one that matters and the easiest to skip — it asserts a new flag changed no extant
behavior. template: `unlockKeyrackKeys.test.ts:295`.

infra: `test-fns` given/when/then, `genTestTempDir`, `withTempHome`, `invokeRhachetCli`,
`getError`. never hand-roll a temp dir (`rule.forbid.adhoc-gentempdir-reimpl`).

## terms

- **`machine-wide`** — canon at ~20 sites; itemized at
  `domain.terms/term=machine-wide._.choice._.md`. forbidden synonyms: `org-agnostic` (RESERVED —
  it would correctly name a hypothetical `@any`), `manifest-free` (a stated *property of*
  machine-wide, not a second concept), `global`, `host-wide`, `box-wide`, `universal`
- **`@all` (org) vs `env.all` (env)** are different axes; `@all.all.FOO` is legal. the predicate
  tests the **org segment** exactly
- **`--for`** means a **scope** on `get` (`:422`) and an **alias for `--owner`** on every other
  verb. out of scope to rename; noted so the two senses do not cross

## shape decisions

| shape | verdict |
|---|---|
| **A — widen the builder with an optional ask** | ✅ chosen — one place owns the load and the decision |
| B — callers pass `gitroot: null` for `@all` | ✗ lies about the world to steer a branch |
| C — keep the load, make a hydrate failure non-fatal | ✗ swallows a bare `BadRequestError` (`rule.forbid.failhide`); must enumerate four throws; still pays the i/o |
| D — make `repoManifest` lazy | ✗ here — breaks a published sdk **value** type, scatters the throw, refactors a shared context. caught as a dream: `.dream/2026_08_25.keyrack-lazy-repo-manifest.dream.md`. A's transformers are what D would want |

**a warn-on-skip is unreachable** — to say *"this repo's manifest is broken"* you must first load
it and watch it fail, which is the cost the fix exists to avoid. so a broken manifest is surfaced
by repo-scoped asks alone.

## bounds

- **out of scope:** the `extends` hydrator's error. a broken `extends` on a slug that DOES need
  the manifest must still fail loud. this wish narrows *when* the manifest loads, never *how* it
  fails
- **out of scope:** any change to `@all` credential semantics
