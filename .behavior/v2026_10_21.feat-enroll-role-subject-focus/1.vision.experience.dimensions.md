# 1.vision.experience.dimensions — the axes

the experience space of "enroll a role at a subject focus", factored into orthogonal axes.
the walked product and every verdict live in `1.vision.experience.case=_.md`.

## .the actors

| actor | encounter |
|---|---|
| **the commander** | types `--roles …mechanic::flow` on `enroll` or `init`; reads the receipt or the refusal |
| **the clone** | the brain booted into the seat; meets the briefs it was given and the hooks that fire on its tools |
| **the auditor** | runs `roles cost --all` and reads what each seat costs |
| **the role author** | declares a subject in a role's `boot.yml`, and its `always` opt-out; often in another repo (rhachet-roles-ehmpathy) |

## .the primary axes

| axis | values | why it is an axis |
|---|---|---|
| **A — command** | `enroll` · `init` · `upgrade` | the wish names enroll and init. `upgrade` is the third because it re-renders every extant actor (`syncActiveActorBrainDirs.ts:101-125`), focused ones included, and it takes a `--roles` of its own. each command persists the roleset its own way: enroll merges into a clone's actor, init patches `prepare:rhachet` and the ambient actor, upgrade re-renders what is held. 🟡 upgrade's `--roles` selects packages to upgrade (`invokeUpgrade.ts:19-21`), never a roleset, so a focus has no sense there |
| **B — roles form** | `exact` (`any,mechanic::flow`) · `add` (`+mechanic::flow`) · `sub` (`-mechanic::flow`) | the wish names exact and add; `sub` is the delta's other half and must be decided here, not found later |
| **C — focus token** | `none` (bare `mechanic`) · `declared` (`mechanic::flow`) · `unknown` (`mechanic::nope`) · `on-simple` (focus on a role whose boot.yml declares no subjects) | requirements 1, 5, and the bound "no change to a role with no focus" |
| **D — `always` inheritance** | `inherits` (default) · `opts-out` | requirement 3 |

## .the secondary axes — they do not multiply into A × B × C × D

| axis | values | why it collapses |
|---|---|---|
| **H — hooks** | the role declares hooks · declares none | requirement 2: hooks follow the role, never the focus. so C never changes H's outcome; one cell (`declared × has-hooks`) carries the whole claim |
| **R — report surface** | `roles cost --all` · the `roles boot` budget gate · the `introspect` gate · the `--when hook.onStop` sweep | requirement 4. the first two read the per-role selection a focus feeds (`genBootPayload.ts:170`), so they vary together and are graded as a pair. the last two read a role's spec as its author publishes it, never an enrollment, so a focus never reaches them; each is one cell, verdicted as such |
| **K — the opt-out key as written** | `inherit: { always: false }` · a misspelled key that carries an `always` field (`inherits:`) · absent | requirement 3's own sharp edge. the section schema is non-strict (`RoleBootSpec.ts:87-91`), so a misspelled key parses and is dropped in silence; only the role author meets it |
| **V — what the clone can see** | the focused subject · the subjects it was not given | a focused boot omits the `<also>` roster (`computeBootPlan.ts:286-291`), so the clone cannot learn the rest exists unless the boot says so |
| **S — one role named twice** | `mechanic,mechanic::flow` · `mechanic::code.prod,mechanic::flow` | a conflict a caller can type in one call. one is a contradiction, the other a union — each a cell |
| **E — the role's prior entry** | `absent` · `whole` · `focused at the same subject` · `focused at another subject` | the state the target set already holds for the role when a delta arrives — the ambient set, `prepare:rhachet`, or an actor upgrade re-renders. S is one call; E is a second call atop the first. it matters only to a delta: an exact set replaces the whole set, so its prior entries do not reach the result |
| **L — the role's link state** | linked · not linked | dismissed as an axis, with reason: the focus is stripped before the link check, so a focused token meets the unlinked-role refusal enroll gives a bare token today (`computeBrainCliEnrollment.ts:99-127`), and init links the role whole. one cell, L2, same as the bare twin |
| **T — repeat and concurrency** | first · replayed · concurrent | dismissed as an axis, with reason: a replay is the `prepare:rhachet` re-run, which writes the same token and so the same boot (one cell, T1). a concurrent enroll or init shares today's actor dir writes and their locks (`inventory.of=requirements.case=6`); a focus adds no write that today's lock does not already cover |

## .the walk

A (3) × B (3) × C (4) × D (2) = 72 cells. most collapse by nature, each for one stated reason:

- **D varies only where C = `declared`.** with no focus, an unknown focus, or a simple-mode role, there is no selected subject to opt out of `always`. ⇒ the cells with C ≠ `declared` collapse to their `inherits` twin (impossible as distinct cells)
- **A = `upgrade` does not take B × C.** its `--roles` names packages, so every focus token typed there is one cell, U2 (refused before any selection). what upgrade does to a focus is re-render the ones extant actors already hold: U1 (the subject is gone) and U3 (the subject is still there)
- **enroll and init share the parse, the refusals and the selection, and differ in persistence.** one parser (`getRoleDeltas.ts`), one subject check, one boot render (`setBrainDirBoot.ts`). but enroll merges a delta into the ambient set (`computeBrainCliEnrollment.ts`) and re-derives at spawn, while init patches the `prepare:rhachet` entry (`asPrepareRhachetRolesDelta.ts`). ⇒ the parse and refusal rows hold for both and are demoed once; each persistence path is demoed on its own side (enroll: D1, S3 `[t4]`; init: P7, S3 `[t4.b]`)
- **B = `sub` with any focus token** is one cell, not four: the verdict (see the inventory) does not turn on C
- **E crosses B = `add` alone.** an exact set ignores the prior entry and a `sub` removes it whatever it was. so E × `add` × C = `declared` is walked in full (E1–E4 in the inventory), and the rest collapse to their `absent` twin

⇒ the collapsed product, every verdict, sits in `1.vision.experience.case=_.md`.
