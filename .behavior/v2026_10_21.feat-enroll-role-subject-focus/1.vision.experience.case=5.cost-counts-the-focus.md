# case=5 — the cost counts the focus

cells: **R1**, **R2**. feel happy × care criti.

## .narrative

the auditor asks what a director seat would cost with mechanic in it. today `roles cost --all`
sweeps one row per boot spec, so mechanic's row reads 65.1k whether a seat boots all of it or a
sliver. that number would push the commander to drop mechanic again, which is the very move this
wish exists to undo.

with this change, under mechanic's whole-role row sits one row per subject mechanic declares,
each priced at the payload that focus would boot: `mechanic::flow` at `always` + flow. the
commander reads the price of a focus before they enroll it, and the sweep still reads specs
alone, never actor dirs (`F4`). the `roles boot` budget gate measures the same focused payload,
because both read the one selection the boot render reads (`genBootPayload.ts:170`).

## .the timeline — a sketch

```
given('[case5] mechanic linked, boot.yml in subject mode with subjects arch, code.prod, code.test, flow')
  when('[t0] rhx roles cost --all')
    then('the whole-role mechanic row is present, unchanged')
    then('beneath it, one row per declared subject: mechanic::arch, mechanic::code.prod, mechanic::code.test, mechanic::flow')
    then('the mechanic::flow row equals `rhx roles cost --repo ehmpathy --role mechanic --subject flow`')
  when('[t1] rhx roles boot --repo ehmpathy --role mechanic --subject flow   (the roles boot gate)')
    then('it measures always + flow, never the whole role — the payload a mechanic::flow seat boots')
```

🟡 the row shape (per declared subject, not per enrolled seat) is fulcrum `F4`. `[t1]` names the
`roles boot` gate, the one of the three that a focus reaches. the `introspect` gate and the
`--when hook.onStop` sweep read a role's spec as its author publishes it, never an enrollment, so a
focus is no input they can receive (cells R3, R4). whether enroll owes a new gate on an actor's
`boot.md` is Q1b, for the wisher.
