# case=3 — an off-ec2 box whose blob lives only in aws.params

> cell c4 · sharp · critipath — the defect today, and the clamp's red half

## .narrative

a hetzner box was provisioned before the cure, or a commander skipped the one command. its host
manifest maps the key to `aws.params`. the crew asks for the token.

today the ask already fails clean: `✋ ConstraintError: aws.params found no AWS identity`
(`asKeyrackAwsParamErrorGate.ts:187`, gate 2). but its hint offers two roads, and neither exists off
ec2 — "run on a box whose instance role can read this param", or "unlock that org's AWS_PROFILE".
the reader is left at a dead end.

in the outcome world the same refusal names a third road, the one that exists here: for a github-app
key, file the blob into os.secure on this box (and the one command to do it). the crew's rung reads
an error whose fix it can hand straight to the commander.

## .the `[tn]` sketch

```
given('[case3] an off-ec2 box: no aws identity; host manifest maps the key to aws.params only')
  when('[t0] the crew asks for the token')
    $ rhx keyrack get --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env prep --unlock
    then('the key is not granted; the unlock omission carries ConstraintError: aws.params found no AWS identity')
    then('the hint names the off-ec2 cure: file the github-app blob into os.secure on this box')
    then('the extant ec2 and AWS_PROFILE hints stay')
    then('no secret, no blob, no param value appears in the output')
```

## .the clamp

this cell is the red half of the wish's clamp: blob only in aws.params, off ec2 → no token. case=1
is the green half: the same box, the blob in os.secure → a token github accepts.
