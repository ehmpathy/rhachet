# 1.vision.experience.dimensions

> the axes the experience of "a grove gets `EHMPATH_BEAVER_GITHUB_TOKEN` from keyrack" varies over.

## .the dimensions

| # | dimension | values | why it is its own axis |
|---|---|---|---|
| D1 | **actor** | `crew` (a grove's unattended provision task, no human) · `commander` (a human who files the blob, once) | the crew only reads; the commander only writes. one goal each, so goal folds into actor |
| D2 | **box** | `ec2` (holds an aws identity) · `offec2` (hetzner, holds none) | the box decides which vaults it *can* read; independent of where the blob was filed |
| D3 | **blob home on this box** (host manifest entry for the key) | `aws.params` · `os.secure` · `absent` | the host manifest is per box, per owner — a commander chooses it, the box does not imply it |
| D4 | **token state** (daemon) | `cold` (no cached token) · `warm` (a cached `ghs_` within its 55m expiry) · `stale` (the daemon dropped it at expiry) | `get` reads only the daemon; the mint runs at unlock (`get --unlock`) on cold/stale; warm is a daemon read |
| D5 | **input health** (for the commander's file act) | `valid` blob · `malformed` blob (not json, field absent) · `absent` (empty stdin, or stdin left as a tty) · `wrong-app` (json shape ok, github refuses it) | sharp edges of a file act are on the input, not the box |
| D6 | **filed via** (latent; for the commander's file act) | `piped` (`set --source @stdin`) · `guided` (the extant tty + gh flow) | surfaced by the grid — see `.the hidden dimensions` |
| D7 | **replica** (latent; wherever `D3 = os.secure`, on either box) | `current` · `rotated-upstream` | surfaced by the grid — see `.the hidden dimensions` |
| D8 | **cwd** (latent; surfaced at execution) | `repo` (a clone with `keyrack.yml`) · `bare` (`$HOME`, where `ssh <box> rhx …` lands) | a bare cwd has no repo manifest, so a short key name cannot compose a slug; the full slug, or `--org @all`, is the road there |
| D9 | **mint reach** (latent; surfaced at verification; crew, at a cold or stale unlock) | `answered` (github mints) · `refused` (github answers, and refuses the blob's app or install) · `unreached` (dns, egress, or proxy stops the call) | the mint is a network call the box makes; whether it lands is independent of where the blob lives |
| D10 | **piped flags** (latent; surfaced at verification; commander, piped) | `as-intended` (`--vault os.secure`, a github-app mech, `--source @stdin`) · `literal` (`--source <value>`) · `vault-other` (a vault that takes no piped source) · `mech-other` (a mech os.secure does not hold) · `replica` (`--mech PERMANENT_VIA_REPLICA`) | the flags around the pipe can each be wrong while the blob is right; each wrong flag owes its own refusal |

## .orthogonality

- D2 × D3 is the axis pair the wish lives on: `offec2 × aws.params` is today's defect; `offec2 × os.secure` is the cure; `ec2 × aws.params` is the regression guard
- D4 is **not** fully orthogonal to D3. a warm or stale token exists only on a box that has minted at
  least once, so two corners void it: `D3 = absent` (no host entry, so no unlock and no cache) and
  `offec2 × aws.params` (the mint always fails there). the correlation runs through a latent fact —
  *has this box ever minted?* — that the impossible cells c5, c6, c8, c9, c17, c18 record. it hides no
  experience (each impossible cell is reasoned), so the product is kept and the voids stand as cells.
  where a box *has* minted, D4 is independent of D3: a cached token reads the same whatever vault minted it
- D5 and D6 matter only on `commander` rows; on `crew` rows D5 collapses into "the blob the commander
  filed" (a `wrong-app` blob filed is a crew-time sharp edge: github refuses the mint)
- D7 is keyed on the vault, not the box: it exists wherever the key's home is a replica of the blob
  — `D3 = os.secure`, on ec2 (c13–c15, legal) as on off-ec2. a box whose home is aws.params reads the
  source live, so D7 is void there by nature, not walked

## .the walked product

- crew rows: D2 × D3 × D4 = 2 × 3 × 3 = **18 cells**
- commander rows, piped: D2 × D5 = 2 × 4 = **8 cells** (the commander files into `os.secure` on the target box; D3 is the *result*, not an input)
- commander rows, guided: D2 × {guided} × {as-intended, wrong-app} = **4 cells**. of D5, only
  `wrong-app` crosses: it is a property of the blob, however it arrives. `malformed` and `absent` are
  stdin edges the guided flow never meets — it builds the blob itself from a pem it reads
- replica rows: D2 × D7 `rotated-upstream` × D4 = 2 × 1 × 3 = **6 cells**, on `D3 = os.secure`.
  `current` × D4 is c1–c3 (off-ec2) and c13–c15 (ec2) — the same cells, not recounted

- cwd rows: `offec2` × D8 `bare` × the slug form {full slug, short key + `--org @all`, short key alone} = **3 cells**, plus the `repo` cwd, which every other row already walks = **1 cell**
- repeat and failure rows (surfaced at execution, on the commander's file act): a pipe with no `--mech` · a re-pipe over an extant os.secure entry · a box that missed `keyrack init` = **3 cells**

- mint reach rows: `offec2` × D9 `unreached` = **1 cell**. `answered` is c1–c3 and c10–c12; `refused` is the crew face of `wrong-app` (m3), not recounted
- piped flag rows: `offec2` × D10 {`literal`, `vault-other`, `mech-other`, `replica`} = **4 cells**. `as-intended` is m1, not recounted

⇒ 48 cells (18 crew + 8 piped + 4 guided + 6 replica + 4 cwd + 3 repeat/failure + 1 mint reach + 4 piped flags), each verdicted in `1.vision.experience.case=_.md`.

**D8, cwd.** surfaced at execution by a peer review: the commander's command lands in `$HOME` over
ssh, not in a repo clone, which is a different branch of the slug read. a short key from a bare cwd
is refused and names `--org @all`; the full slug and the `@all` form both work.

## .the hidden dimensions

**D6, filed via.** `commander × offec2`: the target box has no gh login and no aws identity, and the
commander's act must be one command. the extant guided `set` asks gh (keyrack-infra registry) and a
tty pem prompt — neither of which the hetzner box can answer. so a latent axis surfaced: `guided`
(tty + gh) vs `piped` (the blob arrives on stdin). the vision picks `piped` for off-ec2; `guided`
stays the path for a human at a terminal with gh login.

**D7, replica.** once the blob has two homes, a rotation of the app's private key in aws.params
leaves any box's os.secure copy stale — an off-ec2 box's, or an ec2 box's that chose to adopt os.secure. the axis crosses the token states because a cached token
outlives the rotation until it expires.
