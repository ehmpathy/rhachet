wish =

# wish: keyrack mints the beaver github-app token on a grove off ec2

task: ehmpathy/rhachet#752

## .the outcome

a grove that runs off ec2 (a hetzner box, which holds no aws identity) gets `EHMPATH_BEAVER_GITHUB_TOKEN` from keyrack the same way an ec2 grove does today: a fresh github-app installation token, minted on demand. no long-lived token is copied onto the box.

## .why

today the github-app blob lives in aws.params alone, so only a box with an aws identity can mint the token. the hetzner grove (ahbode decost: it replaces the camp ec2 grove) cannot, and its provision crew halts on that: its private repo clones, its gh login, and its identity checks all wait here.

## .done means

- on a box with no aws identity, `rhx keyrack get` of `EHMPATH_BEAVER_GITHUB_TOKEN` returns an installation token that github accepts
- an ec2 grove still mints it as it does today
- a clamp that fails with the blob only in aws.params and passes with the new source
- a pr on ehmpathy/rhachet, green on ci

## .bounds

- prod is read-only; no credential value is written or quoted in the tree, the pr, or a log
- no credential provision onto any box: to put the blob where the box reads it is the commander's act, named in the pr as one command
- open design questions (where the blob lives, how it is filed) go to the commander at the pr, each with its options and a lean
