## .the commander's one command (for the pr)

run from a box that can read the param, once per off-ec2 box:

```sh
aws ssm get-parameter --name /keyrack/infra/vault/aws.params/v1/ehmpath/_all_/all/EHMPATH_BEAVER_GITHUB_TOKEN \
  --with-decryption --query Parameter.Value --output text \
| ssh <hetzner box> rhx keyrack set --owner ehmpath --key @all.all.EHMPATH_BEAVER_GITHUB_TOKEN \
    --vault os.secure --mech EPHEMERAL_VIA_GITHUB_APP --source @stdin
```

then the crew on that box: `rhx keyrack unlock --owner ehmpath --key @all.all.EHMPATH_BEAVER_GITHUB_TOKEN`, and `rhx keyrack get` as today.
the param path is the one `asKeyrackAwsParamName` derives for that slug; the pr confirms it against the live param before it is run.

- file under the exact slug the crew asks for. a machine-wide ask matches `@all.<env>.<key>` only, with no fallback across envs (extant): a crew that asks `--env prep --key EHMPATH_BEAVER_GITHUB_TOKEN` needs `@all.prep.…` filed, not `@all.all.…`
- `@all` is the org a box with no repo clone can hold; a repo-org slug is set from inside that repo's clone (extant)
- the crew's `get` names the full slug from a non-repo cwd; a bare key name needs a `keyrack.yml` to compose its slug (extant)
- the `ssh <hetzner box> rhx …` form assumes `rhx` is on the box's non-interactive ssh PATH; where it is not, name its full path. the `aws ssm` read runs in the region and profile that hold the param (add `--region` / `--profile` where the default differs)
- `--mech EPHEMERAL_VIA_GITHUB_APP` stays in the command: a pipe whose value names no mech and fails the github-app shape check (ciphertext, a truncated read) is refused, and no byte of it is stored

  on one box shape; the green half is also held at the integration grain (os.secure `[case6]`)
