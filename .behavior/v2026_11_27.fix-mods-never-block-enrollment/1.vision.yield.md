# 1.vision — a mod never blocks enrollment

## .what this builds

one **mod gate** that every boot render reads, which never throws on a mod fault. per role it
returns one of three verdicts:

| verdict | the boot does |
|---|---|
| `modded` | boots the view, with the `<mod of=…>` notice, as today |
| `published` | no mod names the role; boots it as today |
| `skipped` | boots the role as published, with a `<mod.skipped>` notice that names the fault and its fix |

the gate wraps the two checks that throw today — `assertRoleModdedViewFresh` and
`assertRoleModSparesNativeRole` — and turns each fault into `skipped`. it catches every error
except a code defect (`isCodeDefectError`), so a bug in rhachet still throws loud.

four changes carry it:

1. **the boot gate** (`getOneRoleBootContent`, `genBootPayload`) reads the verdict. on `skipped` it
   walks the role dir less every file whose real path sits under the real path of
   `.agent/repo=.mods/` (a symlinked mods dir included), so the mod is skipped whole whatever the
   view on disk holds
2. **the sync** (`syncRoleModdedViews`) catches the classes that escape it today: a corrupt view
   record (`MalfunctionError`) in the apply arm, and an unreadable mods path (`ENOTDIR`, `EACCES`)
   at the entry read. each becomes a refusal of its role, or a repo fault
3. **the stop sweep** (`roles cost --all --when hook.onStop`) gains a third arm: every mod fault,
   with its fix. it holds the first stop of each turn until each is cured; a stop claude already
   held passes, so a fault the brain cannot cure never loops the seat (F02). it arms on any entry of the mods dir, a
   stray included. it reads each mod as it stands now — the spec, the plan, the hook check, the
   role dir, the mods path — never the view record. so a cured mod is silent at the next stop: the
   boot gate would still name it a stale view (C12) until a re-render, and a stale view of a sound
   mod is no fault for the stop to hold on
4. **enroll and init** print one readout of the skipped mods and exit 0 — enroll on stderr, so its json stdout stays one document; init on stdout, inside the mods tree it already prints there (F08)

a fault no role carries (a stray entry, an unreadable mods path, an `of:` to no linked role) is
named once in a `<mods.skipped>` block at the tail of boot.md. boot.md is ordered for the prompt
cache, published roles first and the local tail last (`setBrainDirBoot.ts:24-27`), so a block at
the tail leaves the cached prefix intact when a fault appears or is cured.

## .why it works

- the sync already returns a refused mod's view to its published form, and keeps the refusal in
  the view record (`syncRoleModdedViews.ts:333-348`). the boot gate is where a mod fault turns
  into a throw, at two sites: it re-raises the recorded refusal
  (`assertRoleModdedViewFresh.ts:111-123`), and it re-reads the spec and plan fresh, which throws
  for a mod refused before any record was written, such as C1 (`:77-79`, `:101-108`). change the
  gate, and the render already has a published view to boot
- the real-path filter covers the cases the sync cannot revert — a stray file in a kind dir (C10),
  a corrupt record (C11), a view that lags (C12) — so "skipped whole" holds by construction, not by
  trust in the sync
- the stop sweep already holds on a mod pin drift (`invokeRolesCost.ts:96-135`). a mod fault is the
  same kind of fact — a repo-owned declaration that needs a human — so it rides the same hook, and
  no new framework hook is born (`rule.forbid.framework-owned-hooks`)
- the fault reaches the clone twice: once in its system prompt (boot.md), once at each turn's first stop. the
  commander reads it once on stderr

## .the outcome world

**before**: a typo in a mod a human wrote for flavor refuses `rhx enroll … --resume=director` with
exit 2. the seat stays down until the commander finds the cause and repairs it by hand. on
2026-11-26 this happened twice.

**after**: the same resume lands. stderr names the skipped mod and its fix. the clone boots with
every sound mod applied and the faulty role as published, told so in its own boot. each turn's first
stop names the fault until it is cured; the next stop after the cure says naught.

**the aha**: the mod is flavor, the seat is the job. a bad flavor costs a notice, never the seat.

## .mental model

- to a friend: *"a broken mod gets switched off and you get nagged about it; it never locks you out"*
- analogy: a car whose aftermarket stereo shorts. the fuse blows, the stereo goes dark, the dash
  light stays on until you fix it — the car still starts
- their words vs ours: "broken mod" = refused mod · "switched off" = skipped, booted as published ·
  "nagged" = the boot notice and the stop hold

## .evaluation

| goal | how it lands |
|---|---|
| enroll never refuses on a mod fault | the one gate every render reads never throws on one |
| every fault class | fourteen classes (C0–C13) read off the code; each one routes through the gate or the sync catch |
| sound mods still render | each mod is judged alone; the walk already goes on past a refusal |
| pestered at boot and stop | `<mod.skipped>` in boot.md; a third arm of the stop sweep |

**pros**: one gate, one verdict, every render · reuses the extant stop hook · the real-path filter
makes "skipped whole" hold without trust in disk state.

**cons**: a faulty mod is now quieter — a human who never reads the boot notice or the stop hold
ships a seat without the mod they meant. the stop hold is the answer: it cannot be missed.

**edges kept in the pit of success**:
- a code defect in the gate still throws (inventory row 26, forbidden), so a rhachet bug is never
  hidden as a mod fault
- a cure clears the next stop with no re-enroll, since the stop reads the mod as it stands, never
  the record the last render wrote
- a host lock timeout is no mod fault and keeps its own failure path (inventory row 31)

## .what is awkward

- **a quieter failure**. a refusal was loud by design; a skip trades that loudness for the seat. the
  stop hold carries it, but a clone with no stop (a one-shot `-p`) sees only its boot notice
- **two notice homes**. a fault a role carries sits in that role's section; one no role carries
  sits at the tail of boot.md. one concept, two places, by necessity
- **init's exit code moves** (F01). a CI that leaned on `rhx init` exit 2 to catch a bad mod loses
  that signal; the stop sweep replaces it
