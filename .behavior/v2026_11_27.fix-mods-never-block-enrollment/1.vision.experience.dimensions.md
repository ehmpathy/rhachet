# 1.vision.experience.dimensions — a mod never blocks enrollment

## .the dimensions

| # | dimension | positions |
|---|---|---|
| D1 | actor | **commander** (types the enroll, reads stderr) · **pipeline** (a ci job or tool that runs `enroll --output json` and parses its stdout as one json document) · **clone** (reads boot.md, meets the stop hook) · **installer** (`pnpm install` → `prepare:rhachet` → `rhx init`) |
| D2 | entry | **enroll · resume** (one path: see below) · **boot** (the clone reads the boot.md the enroll wrote — in a session, or in a one-shot `-p` that never stops) · **init** (`rhx init`, `rhx upgrade`) · **stop** (`roles cost --all --when hook.onStop`) · **hand boot** (`roles boot`, or `roles cost`; one gate, F05) |
| D3 | fault class | the fifteen below, C0–C14, read off the code |
| D4 | where the fault lands | **carried** (an enrolled role of the mod's slug carries it) · **uncarried** (the mod's role is linked but not enrolled) · **repo** (no role of any actor can carry it: a stray, an unreadable mods path, an `of:` with no same-slug role linked) |
| D5 | neighbors | **alone** · **beside a sound mod** · **beside another faulty mod** |
| D6 | cure | **faulty** · **cured** (the fix applied, the next enroll or stop) |

### enroll and resume are one position

`rhx enroll claude --resume=director` carries `--resume` as a brain passthrough
(`getBrainCliPassthroughArgs`, `invokeEnroll.ts:480-489`); no branch in `invokeEnroll.ts` reads it.
so a resume walks the sync, the gate, and the render exactly as a fresh enroll does, and every cell
of one is a cell of the other. the matrix writes the position as `enroll · resume`.

## .why the axes are orthogonal

| axis | independent of the others because |
|---|---|
| D1 actor | each actor meets the same fault through a different surface (stderr, the json stdout, boot.md, the install exit) |
| D2 entry | an entry decides which code path reads the mods; any fault can sit on disk before any entry |
| D3 fault class | a fault is a fact of the mods dir, set by a human, before any actor or entry exists |
| D4 lands | set by which roles the actor enrolls, not by the fault — the same C4 mod is carried by an actor with the driver and uncarried by one without |
| D5 neighbors | set by the other mods dirs, which the fault does not touch |
| D6 cure | set by a later human act, after the fact |

🟡 one correlation, by construction: a G2 view fault lives in a role dir, so it is always `carried`
or `uncarried`, never `repo`; a G3 fault has no role, so it is always `repo`. G1 spans all three
(C3 alone can be `repo`). the matrix walks D4 within each group's legal values, and states the
barred pairs as impossible.

## .D3 — every fault class the code refuses today

each is a throw that reaches `rhx enroll` today, by one of two doors: the boot gate
(`assertRoleModdedViewFresh`, `assertRoleModSparesNativeRole`) re-raises it, or the sync lets it
escape (`syncRoleModdedViews` catches only some classes). C0 is the one class that already never
blocks; it stays on the axis because the stop does not yet pester it.

| class | the fault | where it throws today |
|---|---|---|
| C0 | a stray entry under `.agent/repo=.mods/`, not `role=*` | never blocks (`enroll.mods.integration.test.ts` case7); never arms the stop (`getAllRepoThisRolesWithHooks.ts:130`) |
| C1 | a mod dir with no `boot.yml` | `getOneRoleModSpec.ts:52` |
| C2 | a `boot.yml` the parser refuses: no `of:`, a bad role spec, an inexact pin, a role name mismatch, a `budget:`, an `inherit:` | `asRoleModTargetFromOf.ts`, `parseRoleModBootYaml.ts` |
| C3 | an `of:` to a `.this` role, an unlinked role, or a bare slug two repos ship | `getOneRoleModTargetLinked.ts` |
| C4 | a mod file at an unheld path no `say`/`ref` names | `computeRoleModPlan.ts:244` |
| C5 | an orphan `.md.min` in the mod | `computeRoleModPlan.ts:227` |
| C6 | an out-of-scope file: readme, init, keyrack | `computeRoleModPlan.ts:69` |
| C7 | a `not` that matches naught, overlaps a shadow, or drops an add | `computeRoleModPlan.ts:101,112,150` |
| C8 | a mode or subject mismatch against the role | `assertRoleModModeMatchesRole.ts` |
| C9 | a `not` of a skill a hook invokes, or a role package that fails to load | `assertRoleModNotsSpareHookSkills.ts`, `syncRoleModdedViews.ts:53` |
| C10 | a role kind dir that holds a file no link made | `assertRoleKindDirLinksOnly.ts`, `getAllRoleViewSources.ts` |
| C11 | a corrupt view record (`MalfunctionError`) | `getOneRoleModdedViewRecord.ts` — escapes the sync's apply arm, which catches only `ConstraintError` |
| C12 | a stale view: the mod changed, was removed, or retargeted after the last render | `assertRoleModdedViewFresh.ts:114-166` |
| C13 | the mods path itself unreadable: a file where the dir belongs (`ENOTDIR`), no read permission (`EACCES`) | `getAllRoleModEntries.ts:19` — rethrows every errno but `ENOENT` |
| C14 | a path WITHIN one mod unreadable: an fs errno (`EACCES`) on `role=<x>/boot.yml` or a mod file | the mod's own read; the verdict gate turns it into a skip of that one mod (`getOneRoleModVerdict` case5) — a role fault, so G1, never the repo fault C13 |

### C3 lands in two places

an `of:` to an unlinked role is raised by whichever role of the mod's **slug** is linked
(`syncRoleModdedViews.ts:193-199` keys "carried" on `ref.role === role`). so:

- a role of the slug is linked → C3 is G1, `carried` or `uncarried`, and its notice sits in that role's section
- no role of the slug is linked → C3 is `repo`, and its notice sits in the `<mods.skipped>` tail block

out of D3: a lock that times out (`withRepoMutex`) is an infra fault of the host, not a defect of a
mod a human wrote. it keeps its own failure path.

## .the walked product

D1 × D2 is not a full product: each actor meets its own entries.

| actor | entries met |
|---|---|
| commander | enroll · resume, hand boot |
| pipeline | enroll (`--output json`) |
| clone | boot, stop |
| installer | init |

the classes collapse into three behavior groups, since the fix routes them all through one gate:

| group | classes | what the boot can know | D4 values legal |
|---|---|---|---|
| **G1 refused mod** | C1–C9, C12, C14 | which role, which fault, the fix | carried · uncarried · repo (C3 only) |
| **G2 view fault** | C10, C11 | which role dir, the fix | carried · uncarried |
| **G3 repo fault** | C0, C13 | no role carries it | repo |

so the walked cells are (actor, entry) × {G1, G2, G3} × D4 (legal values) × D5 × D6, itemized in
`1.vision.experience.case=_.md`. each G1 class owes its own fix text, so each is also sketched on
its own in `case=7`.
