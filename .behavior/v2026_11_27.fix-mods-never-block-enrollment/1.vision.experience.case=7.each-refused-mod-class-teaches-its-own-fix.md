# case=7 — each refused-mod class teaches its own fix

## .narrative

the commander keeps a handful of mods across his director trees, and each one breaks a different
way over a month: a pin he typed as `@^1.39`, a `.md.min` he forgot to pair, a `not` aimed at a
brief the role since renamed. each time, the resume lands, and the clone's boot names that exact
fault with that exact fix — never a generic "your mod is broken". he copies the fix and moves on.

the gate is one for all of them; what each class owes is its own words. the fix text is the
refusal's own `fix:`, already written in the code, so the notice carries it verbatim.

## .bdd sketch — a caselist, one row per class

```
given role=driver linked and enrolled, role=mechanic modded (sound), and one mod of role=driver with the fault below
  when [t0] rhx enroll claude --resume=director
    then it exits 0
    then the mechanic boots modded
    then boot.md holds no file whose real path sits under the mods dir of role=driver
    then boot.md's driver section holds <mod.skipped> with the problem and the fix below
  when [t1] the stop hook runs
    then it exits 2, and names the same problem and fix
```

| class | the mod | the notice's problem | the notice's fix |
|---|---|---|---|
| C2 no `of:` | `boot.yml` with no `of:` | its boot.yml declares no `of:` | the `asRoleModFixForAbsentOf` text — the `of: <repo>/driver` line to add |
| C2 bad spec | `of: driver` with no repo | its `of: driver` is not a role spec | write `of: <repo>/<role>` or `of: <repo>/<role>@<version>` |
| C2 inexact pin | `of: rhachet-roles-bhrain/driver@^1.39` | its `of: …` pins `^1.39`, which is not an exact release | pin the exact installed version, as `@1.39.5`, or drop the `@` to pin none |
| C2 name mismatch | `of: rhachet-roles-bhrain/mechanic` in `role=driver/` | its `of: …` names role=mechanic, but the mod dir is role=driver | move the mod to `.agent/repo=.mods/role=mechanic/`, or set `of:` to a driver role |
| C2 budget | `budget: { tokens: 9000 }` | its boot.yml declares a `budget:` | delete the `budget:` key — the role's own budget caps the modded payload |
| C2 inherit | `inherit: …` | its boot.yml declares `inherit:`, which a mod cannot set | delete the `inherit:` key — the role's own spec owns what its subjects inherit |
| C3 `.this` | `of: .this/driver` | its `of: .this/driver` names a role this repo owns | edit `.agent/repo=.this/role=driver/` in place, and delete the mod |
| C3 ambiguous | bare `of: driver`, two repos ship it | its `of: driver` matches 2 linked roles | pin one: `of: <repo>/driver` |
| C3 unlinked | `of: rhachet-roles-xyz/driver`, xyz not linked | its `of: …` names a role that is not linked | link it first (`rhx init --roles …`), or point `of:` at a linked role |
| C5 orphan min | `briefs/x.md.min`, no `x.md` anywhere | it holds briefs/x.md.min, a minified brief with no .md beside it | add briefs/x.md beside it, or remove the orphan |
| C6 out of scope | `readme.md` in the mod | it holds readme.md, a kind a mod cannot change | a mod holds only briefs/ and skills/ files; for a readme, an init, or a keyrack.yml, use a .this role or an upstream pr |
| C7 not misses | `not: [briefs/gone.md]` | its not `briefs/gone.md` matches no briefs file the role holds | point the not at a held path, or delete the line |
| C7 not overlaps | `not` and a shadow of one path | its not … removes briefs/a.md, a path the mod also shadows | to shadow it, narrow the not so it leaves briefs/a.md; to drop it, delete the mod file |
| C7 not drops add | a `not` that matches a path the mod adds | its not … removes briefs/new.md, a path the mod adds | to add it, narrow the not so it leaves briefs/new.md; to drop it, delete the mod file |
| C8 mode | a subject-mode mod over a flat role | its boot.yml is in subject mode, but the role's is in flat mode | the `assertRoleModModeMatchesRole.ts:30` text |
| C8 subject | a subject the role does not declare | its boot.yml names a subject the role does not declare (…) | name one of the role subjects, or put the resources under `always:` |
| C9 hook skill | `not: [skills/route.drive.sh]`, a hook invokes it | its not of skills/route.drive.sh removes a skill one of the role's hooks invokes (`rhx route.drive`) | shadow skills/route.drive.sh rather than not it, so the hook still finds it |
| C9 package | the role package fails to load | its package did not load, so no hook can be checked against a not of a skill | repair the install (pnpm install), or drop each not of a skills/ path |
| C14 unreadable | `role=driver/boot.yml` with mode `000` | the errno as the fs raised it, `EACCES: permission denied`, on that path | grant read access, via `chmod u+r` on the path the errno names, from the repo root |

each row is a test in execution; its problem and fix are pinned by snapshot. the C3 unlinked row
lands in the role's section only while a role of the slug `driver` is linked; with none linked it
moves to the `<mods.skipped>` tail block, walked in case 4 [t4]–[t5]. the C14 row is one mod's own
path; an unreadable mods dir itself is C13, a repo fault, walked in case 4 [t3]. C14's text is
pinned by assert, not snapshot (`getOneRoleModVerdict` case5, `enroll.mods` case12): the errno path
is absolute, so it is no stable snapshot line.
