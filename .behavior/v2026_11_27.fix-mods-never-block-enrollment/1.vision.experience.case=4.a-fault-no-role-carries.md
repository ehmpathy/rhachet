# case=4 — a fault no role carries: a stray entry, an unreadable mods path

## .narrative

the commander meant to document his mods and saved `readme.md` straight into
`.agent/repo=.mods/`. it names no role, so today not one surface of the clone's world mentions it:
no role section can carry a notice for it, and with no `role=*` dir beside it, the stop sweep never
arms (`getAllRepoThisRolesWithHooks.ts:130`). the clone works for weeks beside a file it was never
told is out of place.

with the fix, the clone reads one `<mods.skipped>` block at the tail of its boot that names the
stray and the rename fix, and each stop repeats it until the commander moves the file. the block
sits after the last role — the part a local edit already rewrites — so it costs the cached prefix
naught.

## .bdd sketch

```
given .agent/repo=.mods/readme.md and no other mods entry (C0)
  when [t0] rhx enroll claude
    then it exits 0
    then boot.md ends with one <mods.skipped> block that names .agent/repo=.mods/readme.md and the rename fix
    then every byte of boot.md before that block matches a render with no stray
  when [t1] rhx init --hooks
    then the repo actor's dispatch manifest holds the one stop sweep
  when [t2] the stop hook runs
    then it exits 2 and names the stray with its fix
given .agent/repo=.mods is a file, not a dir (C13)
  when [t3] rhx enroll claude
    then it exits 0
    then every role boots as published
    then boot.md ends with a <mods.skipped> block that names .agent/repo=.mods as unreadable (ENOTDIR), with the fix: move the file aside, so .agent/repo=.mods is a dir or absent
given role=mechanic linked and enrolled, no role of the slug driver linked,
  and .agent/repo=.mods/role=driver/boot.yml with of: rhachet-roles-xyz/driver, xyz not linked (C3, repo split)
  when [t4] rhx enroll claude
    then it exits 0
    then the mechanic boots as published, and no role section holds a <mod.skipped>
    then boot.md ends with a <mods.skipped> block that names .agent/repo=.mods/role=driver
      its of: rhachet-roles-xyz/driver names a role that is not linked
      fix: link it first (rhx init --roles …), or point of: at a linked role
  when [t5] the stop hook runs
    then it exits 2 and names the same problem and fix
```

C3 is a G1 class; with no role of its slug linked it lands `repo` (`dimensions.md`, `.C3 lands in two
places`), which is why its notice joins C0 and C13 in the tail block.
