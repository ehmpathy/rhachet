# case=1 — the commander resumes his director seat; a mod holds a file no glob names

## .narrative

the commander's director tree carries two mods: `role=mechanic`, sound, and `role=driver`, which
holds `briefs/notes.md` — a path the driver does not hold, and no `say:` names it. on 2026-11-26
this refused his resume with exit 2, and he repaired it by hand in his shell.

now he types the same resume. it lands. stderr names the skipped mod once, with its fix. the
clone opens; its boot carries the mechanic mod as before and the driver as published, and the
driver's section opens with a `<mod.skipped>` block that says what is wrong and how to cure it.
the clone tells him at its first stop too. he fixes it when it suits him, not when it locks him out.

## .bdd sketch

```
given a director tree with role=mechanic modded (sound) and role=driver modded (C4: briefs/notes.md, named by no say)
  when [t0] the commander runs: rhx enroll claude --resume=director
    then it exits 0
    then stderr holds
      🧢 .agent/repo=.mods
         └─ skipped, booted as published until cured
            └─ role=driver — ✋ ConstraintError: the mod of role=driver is refused: it holds briefs/notes.md, a path the role does not hold, and no say or ref names it
               └─ fix: to shadow, move it to the held path; to add, say it in the mod boot.yml (briefs.say: [briefs/notes.md])
    then boot.md holds the mechanic `<mod of=…>` notice and its shadows
    then boot.md holds no file whose real path sits under .agent/repo=.mods/role=driver/
    then boot.md's driver section opens with
      <mod.skipped of="driver" mod=".agent/repo=.mods/role=driver/">
      the mod of role=driver is skipped: it holds briefs/notes.md, a path the role does not hold, and no say or ref names it
      fix: to shadow, move it to the held path; to add, say it in the mod boot.yml (briefs.say: [briefs/notes.md])
      </mod.skipped>
  when [t1] the clone stops
    then the stop hook names role=driver and the same fix (case=3)
  when [t2] a pipeline runs: rhx enroll claude --roles mechanic,driver --output json
    then it exits 0
    then stdout parses as one json document, and names no fault
    then stderr holds the same readout and fix as [t0]
```

a pipeline that reads `enroll --output json` parses stdout whole. a fault that leaked onto it would
break the parse with no fallback, so the readout rides stderr alone (`enroll.mods` case14 [t0]).
