# case=5 — a view fault: a stray file in a role kind dir, a corrupt view record

## .narrative

the commander, to test a brief, saved `scratch.md` straight into
`.agent/repo=bhrain/role=driver/briefs/` — a dir the mod view owns, where every entry must be a
link. or a disk-full night left the driver's view record half written. either way, his next enroll
fails: the first exits 2 on the stray, the second exits 1 on the corrupt record, and neither says
the seat itself is fine.

with the fix, the enroll lands. the clone's boot names the driver's mod as skipped, says which file
or record is at fault, and how to clear it. the driver boots with no file of the mod in it, and the
commander cleans up when he has a minute.

## .bdd sketch

```
given role=driver modded (sound), and a plain file briefs/scratch.md in its role dir (C10)
  when [t0] rhx enroll claude
    then it exits 0
    then boot.md's driver section holds <mod.skipped> that names briefs/scratch.md and the fix (move it out, then rhx init --hooks)
    then boot.md holds no file whose real path sits under .agent/repo=.mods/
given role=driver's view record holds invalid json (C11)
  when [t1] rhx enroll claude
    then it exits 0, where today the MalfunctionError escapes the sync and exits 1
    then the notice names the record path and its fix (delete the record, then rhx init --hooks)
given role=driver modded and rendered, then its mod edited with no render since (C12, a stale view)
  when [t2] rhx roles boot --repo bhrain --role driver
    then it exits 0
    then the output holds no file whose real path sits under .agent/repo=.mods/
    then the notice names the stale view, with the fix: rhx init --hooks
```

a stale view on the enroll path is rare, since enroll syncs first; the hand boot (`roles boot`)
reads the view with no sync before it, so it is where C12 is met.
