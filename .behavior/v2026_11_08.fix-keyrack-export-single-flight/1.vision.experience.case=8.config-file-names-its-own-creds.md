# case 8 — one profile name under another config file gets its own creds

**narrative (the caller).** keyrack's guided setup runs the aws cli with a temp `AWS_CONFIG_FILE`, where a
profile named `ahbode.test` may point at a different account than the `ahbode.test` in `~/.aws/config`.
the default config's creds sit in the cache, valid for 40 more minutes. a caller under the temp config asks
for `ahbode.test`. its identity hash covers the config paths, so its cache file and its mutex key differ:
it misses the cache, exports under its own config, and gets that account's creds. the default config's
entry is untouched.

**why it is a critipath:** a hit on the wrong entry would hand a caller another account's creds with no
error at all — the one change the wish forbids ("no change to which profile or key a caller gets").

**fail safe:** the identity is the profile plus a hash of both config paths, so no shared entry exists to
hit. and each file records its identity, so a read whose recorded identity differs counts as absent —
even a hash collision returns no foreign creds.

```
given('[case8] a valid cached export of ahbode.test under the default config')
  when('[t0] a caller with AWS_CONFIG_FILE=<temp> asks for ahbode.test')
    then('the aws cli ran, under the temp config')
    then('the result is the temp config\'s creds, not the cached ones')
    then('the default config\'s cache entry is unchanged')
  when('[t1] a caller with no AWS_CONFIG_FILE asks for ahbode.test')
    then('the aws cli did not run')
    then('the result is the default config\'s cached creds')
```
