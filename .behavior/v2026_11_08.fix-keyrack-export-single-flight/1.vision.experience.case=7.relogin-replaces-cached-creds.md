# case 7 — a re-login replaces the cached creds

**narrative (the human).** the human unlocked a profile as the wrong sso user; keyrack cached that
user's creds. keyrack's username check catches the mismatch, and the human re-authenticates as the right
user. the post-login refresh calls the op with `refresh: true`. it deletes the cache entry at once, then
queues for the key; under the hold it deletes again, exports, and writes the new value. a read caller
that arrives while the refresh waits finds no cache, so it queues too, and reads the right user's creds
once the refresh writes them — never the wrong user's, which would otherwise have lived until expiry.

**fail safe — loud, teaches the fix:** the refresh never reads the cache, and it deletes the entry before
it queues and again before it exports. so a pre-login value cannot survive a login, not even when the
refresh's own export fails; that failure names the profile and hints to re-run `rhx keyrack unlock`.

**the residue:** a read export already in flight from before the login may land its value before the
refresh takes the key (fulcrum F5).

```
given('[case7] a valid cached export, minted before a re-login')
  when('[t0] the post-login refresh runs with refresh: true')
    then('the aws cli ran, even though the cache was valid')
    then('the cache holds the new export, not the old')
  when('[t1] the refresh runs, and its export fails')
    then('it throws, with the profile named and a hint to re-run rhx keyrack unlock')
    then('no cache entry is left — neither the old nor a new one')
given('[case7] a refresh while another process holds the key')
  when('[t2] the refresh runs')
    then('it waits for the key, then exports anyway — it never takes the holder\'s value')
  when('[t3] a read caller arrives while the refresh waits')
    then('it finds no cache and queues for the key')
    then('it returns the refresh\'s post-login value, never the pre-login one')
```
