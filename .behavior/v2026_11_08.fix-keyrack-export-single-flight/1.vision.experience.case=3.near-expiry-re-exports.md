# case 3 — a value near its expiry re-exports, once

**narrative (the caller).** a long session asks for creds whose cached copy expires in 3 minutes. a
caller that took them would hold creds that die mid-task. keyrack treats a value within 15 minutes of
its expiry — or past it — as stale (the window botocore refreshes within, fulcrum F3): it takes the mutex, re-reads, exports, and overwrites the cache with the
new expiry.

the same holds for a burst. when 33 suites arrive together on a near-expiry cache, one takes the key and
re-exports; each waiter then takes the key in turn, re-reads, finds the new value valid, and returns with
no cli. a box at load 70 runs one python process, not 33 — so this is the wish's own scenario, and a
critipath.

```
given('[case3] a cached export 3 minutes from its expiry')
  when('[t0] one caller asks for the profile')
    then('the aws cli ran once')
    then('the result carries the new expiry, not the old')
    then('the cache file holds the new value')
given('[case3] a cached export 3 minutes from its expiry, and 33 callers')
  when('[t1] all 33 ask together')
    then('the aws cli ran once')
    then('all 33 results carry the new expiry')
```
