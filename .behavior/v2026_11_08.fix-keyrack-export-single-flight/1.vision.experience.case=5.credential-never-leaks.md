# case 5 — a credential never leaks

**narrative (the on-call).** an export returns output keyrack cannot parse, and the error lands in a ci
log. the on-call reads it: the error names the profile and the keys it found (`AWS_ACCESS_KEY_ID`, but no
`AWS_SECRET_ACCESS_KEY`) — never a value. on disk, the cache dir is `0700` and each file `0600`, so a peer
user on the box reads naught.

**fail safe — fast, loud, teaches the fix:** a parse fault throws loud, writes no cache, and carries key
names only. its hint names the next move: run `aws configure export-credentials --profile <profile>` by
hand to see what the cli emits for that profile, fix the profile's config, then retry.

```
given('[case5] an export whose output lacks the secret key')
  when('[t0] a caller asks for the profile')
    then('it throws a MalfunctionError')
    then('the error names the profile and the keys found, with a hint to run the export by hand')
    then('the error carries no credential value')
    then('no cache file was written')
given('[case5] an export that succeeds')
  when('[t1] a caller asks for the profile, and the cache is written')
    then('the dir mode is 0700 and the file mode 0600')
    then('no log line carries a credential value')
```
