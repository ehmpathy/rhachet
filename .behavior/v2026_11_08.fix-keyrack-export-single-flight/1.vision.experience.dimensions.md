# experience dimensions — aws export single-flight

## .axes

| axis | positions | why it is orthogonal |
|---|---|---|
| form | read · refresh (`refresh: true`) | the caller picks it; no box state implies it |
| identity | default config · override config (`AWS_CONFIG_FILE` or `AWS_SHARED_CREDENTIALS_FILE` set) | the profile, the two config paths (the env picks them) and both files' content, read on every call, warm reads too; an absent file reads as empty, an unreadable one fails loud (a ConstraintError with its path). so a config edit is a new identity (case 16). the profile name is data, never shell: any name, shell syntax included, reaches the cli as one literal word, so the name's content forks no cell. the cache axis then speaks of this identity's entry only |
| callers | 1 · N at once | how many processes arrive is set by the workload, not by the cache or the cli |
| cache | absent · valid (> 15 min left) · near expiry (≤ 15 min, or past it) · corrupt | what a prior run left on disk for this identity; no caller choice sets it |
| holder | none · live · dead (killed mid-hold) | whether another process holds the key, and whether it still lives |
| export result | ok · fails (stale session, cli fault) · incomplete (output lacks a key) · hangs | what the aws cli does when run; the cache and the lock do not reach it |
| cache write | ok · fails (dir not writable, disk full, rename fault) | what the disk does with the write; reached only after `export = ok` (collapse 11) |

## .collapses — each one stated, so a reader can check that no distinct cell was dropped

1. **read × valid → no lock, no export.** the read form returns a valid cache before it takes the key, so
   the holder and export axes do not reach it: one cell per caller count (case 2). a refresh in the queue
   does not break this: it deleted the entry before it queued (collapse 9)
2. **expired ≡ near expiry.** a value past its expiry and a value with ≤ 15 min left take the same path —
   take the key, re-read, export, overwrite. one position covers both
3. **corrupt ≡ absent.** a cache file that does not parse, lacks a key the creds need, or records another
   identity, is treated as no cache: the caller exports and overwrites it. it never throws on a bad file
4. **near expiry ≡ absent on the export path**, save that the stale file is the one overwritten. so
   `near expiry × {fails, incomplete, hangs}` is case 6, 5, or 9: the failed export writes naught, the
   stale file stays stale, and the next caller exports anew
5. **refresh × any cache ≡ refresh × absent.** the refresh form reads no cache and deletes the entry
   before it queues and again before it exports, so the cache axis does not reach it (case 7)
6. **identity does not fork the walk.** the cache file and the mutex key are both named by the identity,
   so a default-config caller and an override-config caller each walk the same cells over their own
   entry and their own key. an entry of the other identity is a different file, so it is never this
   caller's cache: case 8 is an override caller whose own cache is absent while the default config's is
   valid. the cross-identity read is a forbidden cell (catalog)
7. **holder = live, for one caller, is a wait of at most the lease, then the `holder = none` cell.** a live
   holder frees the key when its export ends, and its export ends within the 2 min hang guard. N callers
   behind a live holder are the queue of case 1 / 6 / 9
8. **holder = dead behaves as holder = none once the lease lapses**, after a wait of at most the 3 min
   lease — under the 5 min wait bound, so a dead holder alone never makes a caller pass its bound (case 4).
   this holds for each form and each export result
9. **the holder's form is not an axis.** a read holder and a refresh holder hold the same key the same
   way. what a refresh changes for others is the entry, and it deletes that before it queues — so a read
   caller behind a refresh holder is the `read × absent × live` cell, and reads the refresh's value
   (case 7 [t3]). the one residue is fulcrum F5
10. **refresh × N is N refreshes in turn.** each deletes, exports, and writes, or on any failure leaves no
    entry; the last success stands, and every value is post-login
11. **cache write is reached only after `export = ok`.** a failed export writes naught, so the write axis
    has one live cross: `export = ok × write = fails`. there the caller throws a ConstraintError whose
    hint names the cache path to make readable and writable and the disk's own error, carries no
    credential value, and removes its temp file; it never returns creds it could not cache in silence,
    since that would hide that the single flight had broken. the dir ensure, the read and the drop
    fault the same way, before any export; the unlock row shows `— fix: make <path> …` and exits 2.
    a wrong-kind entry (a file where the dir belongs, a dir where a file belongs) faults the same way,
    but its cure is a move: `— fix: move aside the entry at or above <path> …`, never a mode fix
12. **daemon liveness is no axis of the export.** `rhx keyrack unlock` findserts the daemon before it
    stores a grant, and the export never reads the daemon. its one cross with the callers axis is
    `N × no daemon alive`: one daemon spawns under a disk mutex keyed by its socket path, and every
    other caller reaches that daemon. one catalog row holds it

after the collapses, the distinct cells are the rows of `1.vision.experience.case=_.md` `.cells`; each
carries a verdict there.

## .actors — a view over the cells, not an axis

**the caller** (a process that needs one profile's creds — `rhx keyrack unlock`, a jest env, the daemon's
unlock path) · **the human** at a loaded box · **the on-call** who reads the logs after a fault.

each actor meets the same state cells; what differs is what it sees of them. so the catalog walks the
cells once and lists, per actor, the cells it meets (`.actors × feel`). no actor has a cell the others
lack: the daemon serves `keyrack get` from its store and never runs the export, so it meets no cell here.
