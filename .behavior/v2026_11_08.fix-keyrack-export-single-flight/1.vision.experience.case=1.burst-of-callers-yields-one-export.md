# case 1 — a burst of callers yields one export (the dense walk)

**narrative (the caller, then the human).** a jest run on a box at load 70 starts 33 suites, and each asks
keyrack for `ahbode.test.ehmpath` at once. the first to reach the disk mutex holds it and runs `aws
configure export-credentials`; it takes 12s on this box. the other 32 poll the mutex, quiet. the holder
writes the cache file and frees the key. each waiter takes the key in turn, re-reads the cache, finds it
valid, and returns at once — no cli. all 33 hold identical creds; the box ran one python process.

an hour later the cached creds are 3 minutes from expiry. the human's next `rhx keyrack unlock` takes the
mutex to re-export — and the human hits ctrl-c mid-export. that key now sits on disk with no process
behind it. the next jest suite to ask finds it held, waits out the lease, wins the key, exports, and
returns. no one deleted a lock file.

**boundaries crossed (6):** process ↔ process (the mutex, as a queue) · process ↔ aws cli · process ↔ disk
cache · the validity check before the lock and again inside it · the near-expiry limit · a killed
holder's lease.

```
given('[case1] a box where 33 callers ask for one profile, the cache absent')
  when('[t0] all 33 call genAwsProfileExport together')
    then('the aws cli ran once')
    then('all 33 results are identical')
    then('the cache file holds that result, mode 0600')
  when('[t1] later, the cached value is 3 minutes from its expiry, and a caller asks')
    then('the aws cli ran again, and the cache holds the new expiry')
  when('[t2] a re-export holder is SIGKILLed, and the next caller asks')
    then('it waits out the lease, exports, and returns')
```

the sharp critipaths inside this walk keep their own spotlights so each fail-safe stays legible:
near expiry → case 3, the killed holder → case 4.
