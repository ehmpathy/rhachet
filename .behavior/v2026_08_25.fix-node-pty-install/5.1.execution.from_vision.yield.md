## the cure

**two lines of `package.json`.** everything else serves acceptance #3 and #4.

```diff
  "optionalDependencies": {
-   "node-pty": "1.1.0"
+   "node-pty": "1.2.0-beta.15"
  },
  "pnpm": {
    "onlyBuiltDependencies": [
      "bun",
-     "node-pty"
    ]
  }
```

- the bump: upstream ships linux-x64 and linux-arm64 prebuilds from `1.2.0-beta.15`, so the
  install hook is a no-op and pnpm's build gate has no hook to block
- the deletion: `onlyBuiltDependencies` applies in the **root project's** manifest only, so our
  entry never helped a consumer — it only made our tree the one place immune to the defect. with
  it gone, our dev tree and ci behave as a consumer's does

one cure closes all three surfaces the vision named — `pnpm add -g`, `rhx upgrade`, and a
consumer's own `pnpm install` — because it makes the gate's outcome irrelevant rather than
negotiates with it.

### 🚨 the render had THREE owners, and the two defects that produced this one were opposite halves of that

the frames above are what a human reads. **who composes them** turned out to be three independent
answers to one question, and the third was wrong in a way the other two were not:

| renderer | glyph | sentence | hint | metadata blob |
|----------|-------|----------|------|---------------|
| `withCliOutputErrors` (the talk verbs) | ✅ | ✅ | ✅ | ❌ |
| `execUpgrade`'s `asUpgradeFailureMessage` | — | ✅ | inline | ❌ |
| `invoke.ts`'s top-level catch | in text | ✅ | ❌ | 🔴 ✅ |

two defects shipped on the **same line** of that third renderer, one after the other, and each was
the cure for the one before it:

1. a bare `.message` printed the **whole metadata blob** — and `asNpmInstallFailureError` puts the
   package manager's entire captured log in `metadata.output`, which the install had **already
   replayed**. so one sentence sat buried between two copies of thousands of bytes
2. the redact that fixed that — `.redact(['metadata'])` — **deleted every hint that lives only in
   `metadata.hint`**. `invokeKeyrack` alone throws a dozen. `rule.require.errors-name-the-fix`,
   inverted by its own cure, across 15+ call sites

⚠️ **both have ONE root, and to name it is what turned a patch into a repair:** two facts a human
needs sit in the same object as bytes they must not see. so neither *"print it"* nor *"strip it"* is
right — the answer is to read the two fields **by name**, which `asCliErrorJson` already did for the
machine channel.

`src/contract/cli/asCliErrorFrame.ts` is now the one owner. it is a **transformer, not a printer** —
it returns lines rather than writes them — so every row is unit-assertable with no captured stream,
and each call site keeps its own channel.

🚨 **the clamp holds the pair AS A PAIR, and that is the whole design.** dogfooded in both
directions:

| mutation | what reddened |
|---|---|
| blanket `.redact(['metadata'])` | exactly the 2 hint rows |
| bare `.message` | the blob row, + 3 more |

## the durable axes

the instances live in the review artifacts; these are the lessons that outlive them.

| axis | the lesson |
|---|---|
| 🚨 **a green test near a defect is not evidence of its absence** | it is often **the reason nobody looked** |
| 🚨 **an honestly disclosed debt is still a debt** | disclosure is not verification — a clamp called sound *by inspection* is a claim, and only a run can settle it |
| 🚨 **payload is not screen** | a return-value clamp cannot see a render; an assertion over a RELATION can hold while both renders are nonsense |
| a fact fixed at its call sites and left wrong in its docs is **not fixed** | a doc comment teaches the next reader; it is a call site too |
| a dead-end cure does not vanish when rewritten — **it relocates** | ask not *"is this cure correct?"* but *"on which hosts, and does the code know which host it is on?"* |
| the tell for an absent test is **not low coverage** | it is a value used as a premise in many places and asserted in none |
| the diff contradicts itself more often than it contradicts the world | when you know what you meant, prose that says otherwise reads as what you meant |
| a class recurs when you patch the **instance** | sweep the class, or meet it again |
| the **guards** can be the defect | a guard asserts a proposition; check which one before you relax it |
| a dogfood can correct your own written claim | run the mutation; do not reason about it |
| a guard scoped to the instance it was born from will pass while the class recurs beside it | and a token list is only as good as its members |
| a deliverable that logs its own revisions **is** the class it reports on | absorb the finds; delegate the trail |
| **a fix with no articulation is, to a reviewer, indistinguishable from a fix that never happened** | the contemplation loop is not paperwork after the work — it is the half that makes the work legible |
| 🚨 **a symptom names no cause, so a cure that fits one cause must READ the error first** | three lanes went dark for two reasons and were cured as one for 17 rounds — because the rule I applied opened *"…because its prompt exceeds the context window"* and had no row for any other cause |
| a hint printed by one failure reads as the error of another | the overflow's own `use --focus pull` is what made the pull lanes' `--focus pull` error invisible |
| **a true claim asserted for an unverified reason is still unverified** | I wrote *"the guard is not a driver lever"* into two `.taken` files before I ever checked `route.mutate.guard`. it holds — and that is luck, not diligence |
| 🚨 **…and the same defect recurred THIS round, where the luck ran out** | I asserted the exact `[case2b]` resnap diff in three artifacts with no run behind it. the real diff was three changes, not one. the conclusion held; **the evidence i offered for it was invented**, and a reviewer who checked it would rightly have distrusted the rest |
| 🚨 **a FAILED attempt measures a moment; it does not classify a lever** | one `keyrack unlock` timeout was carried up as a human gate for several rounds. a retry authenticated with no prompt — the daemon had not been spawned. ⚠️ **the error named a human in its own words** (*"human did not respond to browser sso prompt"*), and that is precisely why it persuaded me |
| **an escalation is INHERITED, so a wrong owner survives** | once *"this is human"* was in the blocker file, every later round read it as settled and re-relayed it. nobody downstream re-derives an owner — the check must happen at the moment of the claim |
| 🚨 **a cure can BE the next defect, and the pair shares one root** | a bare `.message` printed the metadata blob; the redact that fixed it deleted the hint. **same line, consecutive rounds.** two facts a human needs sat in the same object as bytes they must not see — so *"print it"* and *"strip it"* were both wrong, and only a read **by name** is right |
| 🚨 **a clamp for a pair of opposite defects must assert the PAIR** | a strip fails one row, a print fails the other — so no blunt rule passes both, and the clamp cannot be satisfied by any answer but the correct one. **one row of each would have let either cure through** |
| **the rule of three is a diagnosis, not merely a threshold** | the reviewer's read — *"the blocker is a symptom of the fragmentation"* — is what turned a name-by-name audit into an extraction. three renderers did not merely justify a shared owner; they **explained** why a defect kept landing on exactly one of them |

| 🚨 **a rewritten clamp inherits no dogfood** | the old assertion had been watched red; the one that replaced it had not. a clamp's teeth are a property of **that** assertion against **that** source, so a rewrite resets the proof to zero |

### the portable-cure sweep — the class, not the instance

`rule.forbid.host-specific-cures-in-hints` was authored inside this change, and a second live
instance of the class was found afterwards in `execNpmInstallGlobal`'s probe-unreadable notice.
two failures produced that, and both are corrected:

- **scope** — the guard was a const inside one test, so a kin surface was never checked
- **coverage** — the offending token matched **none** of the guard's four original members, so
  even in scope it would have stayed green

`HOST_SPECIFIC_SHELL_TOKENS` now has ONE owner (`src/.test/assets/hostSpecificShellTokens.ts`),
carries three more members, and is applied to the upgrade notice as well as the fallback error.
the notice names the **datum** (`the PATH environment variable`) rather than any shell incantation.

> ✅ **the sweep paid for itself on its first run:** the extended guard went RED on a *third*
> instance in the same notice, one line above the token it was added for — then green on the fix.
> a real defect as the dogfood, never a synthetic mutation.

the sweep's own adjacent find is now closed rather than merely recorded: `getPnpmPresence` ran
`which` on **every** platform, win32 included, where that binary does not exist — so the probe
returned a confident wrong `absent` there, indistinguishable from a host that genuinely lacks
pnpm.

🚨 **the cure deletes the question rather than answers it per host.** a per-family lookup word
(`where` on win32, `which` elsewhere) would fix the spelling and leave the shape wrong: a PATH
lookup answers *"is there a file named pnpm"* when the caller's question is *"can i run pnpm"*,
and the two diverge on any host with a corrupt shim or a dangling symlink — a lookup hands back a
confident `present` for a manager that cannot run. so `getPnpmPresence` runs `pnpm --version`,
which asks the caller's actual question and is spelled identically on darwin, linux and win32.
no platform seam exists to maintain, because no per-host branch is needed (`rule.prefer.simple`).
`getPnpmPresence.integration.test.ts` holds the flag against a real pnpm — the unit rows mock
`spawnSync`, so they clamp the arguments and can never clamp what those arguments do. the retry
stays: a wedged PATH mount hangs the direct form too.

⚠️ **the residue, stated plainly:** `--version` is the read-only form. `pnpm version` without the
dashes is a *different* command that bumps package.json and can tag — so the retry above, which
is safe only because the probe writes naught, would mutate the repo twice against that form. the
dashes are clamped in the unit row's argument assertion, and the reason is written beside it.
