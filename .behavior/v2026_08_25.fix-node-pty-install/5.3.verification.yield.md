### 🔴 defect 1 — the nonce was masked in the wrong order

`blackbox/cli/clone.acceptance.test.ts` read:

```ts
asSnapshotSafe(shapes.got.stdout).split(nonce).join('__NONCE__')
```

and the nonce is `` `json${getUuid()}` ``. this branch taught `asSnapshotSafe` to rewrite a uuid to
`__SERIAL__` — so by the time `.split(nonce)` ran, the text held `json__SERIAL__` and the raw nonce
could no longer match. the run-specific reply text then leaked straight into the snapshot.

the repair inverts the two: mask the nonce **first**, then hand the result to `asSnapshotSafe`.

```ts
asSnapshotSafe(shapes.got.stdout.split(nonce).join('__NONCE__'))
```

> ✅ **the strongest proof available: the stored snapshot matched byte-for-byte with NO resnap.**
> `--scope 'path://clone.acceptance'` → **120 passed, 0 failed**. the snapshot was correct all
> along; the order was the entire defect. had I resnapped instead, a live regression would have
> been written into the baseline and the suite would have gone green over it.

### 🚨 defect 2 — the new `hint` leaked the linked-role roster into three error-shape snapshots

failures 5 and 6 looked like ordinary drift. they were not. each of those tests carries its own
stated guarantee, verbatim from the file:

> *"the availableRoles list is version-fragile (it grows as packages add roles), so redact its
> contents to a stable token while the rest of the block stays deterministic"*

this branch's error `hint` **repeats that same roster in prose**. the extant redaction covers the
JSON array alone, so the roster re-entered the snapshot through the hint — and re-coupled an
error-**shape** clamp to the org's role **inventory**. a new role package anywhere would then redden
three tests that have no stake in the roster at all.

the repair extends the redaction to the hint:

```ts
.replace(/("hint":\s*"available roles: )[^"]*"/, '$1$AVAILABLE_ROLES"');
```

applied at 2 sites in `init.incremental.acceptance.test.ts` and 1 in `rhx.acceptance.test.ts`.

> ⚠️ **worth its own note.** the failure was a stale snapshot; the defect underneath it was a
> silent loss of determinism. a resnap would have accepted the roster as the new baseline and the
> guarantee that comment describes would have been gone with no test to say so.

## 🔴 one defect this gate found in a test, and repaired rather than deferred

`keyrack daemon [case11]` reddened on **two consecutive** full-tier runs with
`ENOENT: /tmp/keyrack-raced-<pid>.pid` at `daemon.integration.test.ts:1064`. a repeat is what stopped
it from a read as noise.

**the root cause is a budget inverted against the case's own premise:**

| budget | value |
|---|---|
| the handover poll | 50 × 100ms = **5000ms** |
| the predecessor's idle timeout | **4000ms** |

the poll was allowed to outrun the very window the case needs. under load the successor's spawn
exceeds 4000ms, so the predecessor idle-exits **mid-handover**; `unlinkOwnFiles` reads the pid file,
sees its own pid, correctly concludes it owns it, and deletes it. the test then read that file with
**no ENOENT guard** — though the production code 60 lines away guards the identical read:

```ts
// allow expected errors: ENOENT = already cleaned up, by us or by a successor
```

> ✅ **the production code was correct throughout.** the defect was entirely in the clamp.

the repair, all in `daemon.integration.test.ts`:

1. the idle window now **exceeds** the poll's own budget, so the overlap the case needs actually holds
2. the read is ENOENT-guarded, exactly as production guards it — an absence mid-handover is a retry
3. the overlap is now **asserted**, so a load-induced miss names the premise it broke rather than
   surfaces as an opaque read fault three lines earlier
4. the demand loop and the case timeout were raised together, to keep the predecessor's death inside
   the window

⚠️ **and the prune it was diagnosed with was retired as ritual.** across four runs the failure count
fell 10 → 3 → 1 → 1, and the largest single improvement came from the run with **no** prune. these
suites are already identity-hermetic — `withTempHome` overrides `$HOME`, `getHomeHash()` reads it at
call time, and the socket embeds that hash — so a shared `XDG_RUNTIME_DIR` is a shared *directory*,
never a shared *socket*. what they are not hermetic about is **wall-clock**, not state.
