## 🆕 .two defects the UNREDACTED payload exposed — both invisible while it was redacted

neither was in the plan. both surfaced only once the metadata reached a rendered surface, which
is the same mechanism as the doubled glyph: **a redacted render hides a second claim.**

### 1. the temp-dir root was never masked, and nobody could tell

`asSnapshotSafe` masks serials, socket paths, and iso stamps — but never the `genTempDir` root
(`/tmp/test-fns/<repo-dirname>/.temp/<stamp>.<slug>.<8hex>`). its two peer masks cannot reach it:
the home/Users/runner-work pattern is anchored elsewhere, and the iso-stamp mask demands COLONS
while test-fns writes dashes so the name is filesystem-safe.

⚠️ **it was harmless only by accident.** the path lived in metadata, and metadata was redacted, so
an unmasked volatile sat in the helper for as long as the redaction did. the repair that made the
fix visible is what made the gap visible too.

the mask is anchored on both literal segments and bounded by the 8-hex tail, so the RELATIVE path
survives — and that tail is the part a reader is owed, since it names which file the report is about.

### 2. a `cause` payload that ANNOUNCES a cause and shows none

`JSON.stringify` renders an `Error` as an empty object: `name`, `message`, and `stack` are all
non-enumerable, so the serializer sees no own keys. **19 throwers attach `cause: error`**, and
every one had its diagnosis erased at the last layer, on BOTH channels.

that is worse than an omission. an absent field reads as *there was none*; an empty one reads as
*the cause was empty* — a false claim, rendered with confidence.

**the fix is at `asCliErrorJson`, not at the 19 throwers.** the field NAME is the thrower call and
`cause` is semantically right; what breaks is the serialization, and `asCliErrorJson` is the one
layer that knows a value is about to be handed to `JSON.stringify` for someone to read.

⚠️ **and this is where it PARTS from the bulk rule.** `asCliErrorFrame` says bulk is bounded at its
source, because the render cannot tell a bulk field from a load-bearer — that is a judgment about
what a field MEANS. this is a TYPE check, which the render can always make. same file, opposite
owner, and the line between them is judgment-vs-type.

measured, on the corrupt-manifest row: the frame went from a bare sentence to the class name, the
exact `manifestPath`, and a `cause` of `class: SyntaxError` with the parser message that names the
line and column of the corruption.

⇒ the human now gets the exact file AND the exact byte. before, they got a sentence and a grep.

**clamped and dogfooded** — `asCliErrorJson.test.ts` `[case9]`, three rows. under a reverted

### the one-line fix I refused

⚠️ stamping `syscall: "bind"` would have closed it in one line and it is wrong. the predicate reads
node`s structured field precisely because it is *the emitter`s own declaration of which call failed*
— and the timeout`s premise is that no call declared a fault in either direction. to forge that
field corrupts the one field the predicate trusts, and now that metadata is UNREDACTED it would put
a false claim on a human`s screen.

so the mark is our own: `CLONE_SOCKET_BIND_TIMEOUT_MARK`, exported from `socket/constants.ts`,
stamped by the producer, read by the predicate. a shared const so a rename breaks both sides at
compile time; a property rather than a class because this predicate already documents that an
`instanceof` read is realm-dependent under jest; a second allowlist ENTRY rather than a wider read.

**clamped, three rows, dogfooded** — the mark branch disabled reddened exactly 1 of 11, the match
row, with both negative rows still green.
