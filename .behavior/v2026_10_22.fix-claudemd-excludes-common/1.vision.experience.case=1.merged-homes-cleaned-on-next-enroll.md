# case=1 — merged homes cleaned on the next enroll

## narrative — the enrollee's walk, then the reviewer's

camper and vlad each enrolled on their own branch; the merge kept both lines. vlad pulls main and
runs `claude` (an alias for `rhx enroll claude`). the enroll rewrites the repo actor's
`settings.of.repo.json`: both home literals go, one common line stays.

the next day, the teammate who reviews vlad's pr sees a two-line removal from the settings file,
once — and no line that names a person. every pr after that shows no settings churn at all.

## timeline

```
[t0] given  settings.of.repo.json holds claudeMdExcludes =
              ["/home/camper/.claude/CLAUDE.md", "/home/<user>/.claude/CLAUDE.md", "**/CLAUDE.local.md"]

[t4] when   a launch reads that file with no config dir (the case-4 probe shape)

[t7] then   the file bytes are unchanged (case 2)
```

`rhx init` re-derives the repo actor's file only where its `actor.json` sits on disk. a bare enroll
writes that manifest, and git ignores it, so a fresh clone holds none: on that box `rhx init` and
`rhx upgrade` leave a stale committed file as it is, and the first bare enroll cleans it. every box
that has enrolled once cleans it on `rhx init --hooks` too, and names each dropped entry beneath the
actor row (`claudeMdExcludes dropped <path>`).

proven through the cli: `blackbox/cli/enroll.acceptance.test.ts` `[case2f]` (enroll twice, bytes
compared) and `blackbox/cli/init.hooks.acceptance.test.ts` `[case9]` (init twice, stdout pinned).

clamp rows of the same test (seam W, W1=repo, W3=first): prior key absent · common only · one home
literal · literal + common · a hand-added entry — each yields exactly the common pair.

boundaries in one walk: two machines · a git merge · rhachet's writer · claude's matcher · the
actor's own door. it subsumes case 2's single boundary and shares case 4's matcher boundary.
