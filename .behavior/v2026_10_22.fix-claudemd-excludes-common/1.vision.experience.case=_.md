### home shapes, inside home × `--settings` (unit matrix rows of case 4)

`/home/x` · `/Users/x` · `/root` · deep (`/var/lib/x`, a temp HOME) · windows `C:/Users/x` →
excluded. a home whose name starts with `brain` → not excluded, argued below.

### the `brain*` home, argued

- frequency: it needs a POSIX account whose name starts with `brain` (`/home/brain`,
  `/home/brainy`) — picomatch's negated extglob is prefix-scoped — on a box that runs
  the actor's settings with no config dir. the second condition is the journey test's probe shape,
  not a path any enroll takes — every clone sets `CLAUDE_CONFIG_DIR`
- cost if hit: that one launch reads the human's home notes, the defect state of today on every box
- fail-safe: none at runtime, by choice. a second pattern
  (`**/!(actor.via.*)/brain/.claude/CLAUDE.md`) would close it but breaks the wish's "ONE common
  pattern" and couples the glob to the actor dir name. the unit matrix pins the row as "not
  excluded", so the gap is visible and a later fix is a clean one-line add (fulcrum F1)
