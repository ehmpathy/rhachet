# 1.vision — claudeMdExcludes without per-machine paths

## .the outcome world

the repo actor's `settings.of.repo.json` is committed. today rhachet writes one literal per enroll:

```json
"claudeMdExcludes": [ "/home/<user>/.claude/CLAUDE.md", "**/CLAUDE.local.md" ]
```

so every machine that enrolls rewrites the line to its own home, every pr carries a churn line, and
a merge of two branches unions two homes into git (`/home/camper/…`, `/home/<user>/…`).

after:

```json
"claudeMdExcludes": [ "**/!(brain)/.claude/CLAUDE.md", "**/CLAUDE.local.md" ]
```

one line, the same on every machine. an enroll on camper's box and an enroll on vlad's box write
byte-identical files; `git status` stays clean after `rhx enroll` on any box.

**aha:** the human runs `claude` on a fresh laptop, and the only diff in the repo is the work they
did — never a config line that names them.

## .before / after

| | before | after |
|---|---|---|
| home exclude | `/home/<user>/.claude/CLAUDE.md` — one per machine | `**/!(brain)/.claude/CLAUDE.md` — one, for all |
| a second machine enrolls | the line flips to its home; a merge unions both | no change |
| extant per-machine lines | stay until a human prunes them | dropped on the next enroll (the key is rewritten whole) |
| a regression that writes a machine name | lands silently in git | a test fails before review |

## .the proof — what claude code's `claudeMdExcludes` matches

measured against `@anthropic-ai/claude-code@2.1.308` (latest at 2026-10-22), via
`rhx claude.cli.probe` + `rhx claude.cli.strings --pattern claudeMdExcludes`:

1. **matcher = picomatch, `{ dot: true }`, against the absolute path** (`\` → `/`). the schema
   description names picomatch and absolute file paths; the code builds
   `picomatch(patterns, { dot: true })` and tests `path.replaceAll("\\","/")`
2. **`~` is not expanded.** the only rewrite (`cqo`) is for patterns that start with `/`: it adds the
   symlink-resolved twin of the literal prefix. so `~/.claude/CLAUDE.md` matches no real path — a
   silent no-op, ruled out
3. **a `**` prefix reaches outside the repo** — the path is absolute, so `**/x` matches
   `/home/v/x`. measured both ways below: the unit matrix (picomatch, claude's options) and the
   journey `[t3.0]` against the real cli — a temp HOME's `.claude/CLAUDE.md` sentinel is quoted
   with the excludes stripped and dropped under the written file
4. **it applies only to user, project, local memory** — the home `CLAUDE.md` is user memory when
   `CLAUDE_CONFIG_DIR` is unset, and project memory when an ancestor dir's `.claude/CLAUDE.md`.
   an enrolled clone sets `CLAUDE_CONFIG_DIR` and omits the project source, so for it the exclude
   is a second wall. it bites on a launch that reads the actor's settings without the config dir —
   e.g. `claude -p --settings <actor>/settings.of.repo.json`, the probe the journey test runs
5. **the user memory path is `<configDir>/CLAUDE.md`** — for a clone, `<actor>/brain/.claude/CLAUDE.md`,
   its OWN door. so `**/.claude/CLAUDE.md` would hide the clone's own boot. that is why the extant
   code wrote a literal

⇒ the common pattern must match `<any home>/.claude/CLAUDE.md` and must not match
`<actor>/brain/.claude/CLAUDE.md`. every actor door sits under a dir named `brain`
(`define.brain-dir-layout-is-one-for-every-actor`), so the extglob `**/!(brain)/.claude/CLAUDE.md`
parts them. the proof is clamped twice:

- a unit test, with the same picomatch options claude uses, over the matrix in
  `1.vision.experience.case=4.home-excluded-own-door-kept.md` (plus near-misses `brains/`, `xbrain/`)
- an acceptance test against a real `claude -p` (haiku): a temp HOME holds a sentinel in
  `.claude/CLAUDE.md`, `CLAUDE_CONFIG_DIR` unset, user source only, `--settings <file>`. without
  the pattern the brain quotes the sentinel; with it, it does not

## .mental model

*"rhachet tells claude: skip any `.claude/CLAUDE.md` that is not an actor's own door."* — the
human's notes never ride into a clone, and the line that says so never names the human.

analogy: a `.gitignore` entry `**/.DS_Store` versus `/Users/vlad/repo/.DS_Store`. the first is a
rule; the second is a fact about one laptop.

## .evaluation

- goals: one pattern ✅ · no machine name ✅ · old literals cleaned on next enroll ✅ (the key is
  rewritten whole, so cleanup is by construction) · a check that fails loud ✅
- pros: zero churn, zero leak, no migration step to run
- cons: the pattern is broader than "home" — it also excludes an ancestor's `.claude/CLAUDE.md`
  (e.g. `~/git/.claude/CLAUDE.md`). that is the same intent (no corpus but the actor's), so it is
  accepted
- cons: "any machine" has one known exception — a home dir whose name starts with `brain`
  (`/home/brain`, `/home/brainy`) is not excluded: picomatch's negated extglob is prefix-scoped, so
  `!(brain)` spares it as it spares every actor door (measured, unit matrix). it bites
  only on a `--settings` launch with no config dir (no enroll takes that path). accepted under the
  wish's "ONE pattern"; pinned in a test so it stays visible (`case=_.md`, fulcrum F1)
- pit of success: the test drives the one writer, so every path to the committed file is covered;
  and this repo's own committed file is scanned too, so a hand edit is caught in CI
