# 1.vision.experience.dimensions

the behavior has two seams, and each seam has its own axes. the split is the orthogonality claim:
**after the fix, the writer's output does not depend on the machine** — that independence is the
whole wish. so machine-shaped values live only on the matcher seam, and file-shaped values live
only on the writer seam.

## seam W — the writer (`genBrainCliConfigArtifact` → `settings.of.repo.json`)

| axis | positions (closed) | why orthogonal |
|---|---|---|
| W1 actor dir | repo actor (committed) · any other actor (hash, slug, derived — one code path, gitignored) | the caller picks the dir; the prior file content does not |
| W2 prior `claudeMdExcludes` | absent · common pattern only · home literal(s), any count · home literal(s) + common · a hand-added entry | the prior file is whatever git and humans left; the writer reads none of this key |

product: 2 × 5 = **10 cells**.

`a hand-added entry` is additive, not exclusive: it may sit beside any of the other four values.
each such mixed state (literal + hand, common + hand, …) takes the same verdict as the
hand-added cell — the whole-key rewrite drops every entry it did not author — so they are walked as
one row rather than four.

hidden-dimension check: a "run count" axis (first vs repeat enroll) was tried and dropped — it is
not orthogonal to W2. a repeat enroll is a write whose prior state is the post-fix state, i.e.
`W2 = common pattern only`; a "repeat" over a home literal is just W2 = home literal. so
idempotence is the cell `W2 = common only`, and the latent axis was W2 all along.

## seam M — the matcher (claude code reads the written excludes)

| axis | positions (closed) | why orthogonal |
|---|---|---|
| M1 where the `.claude/CLAUDE.md` lives | the human's home · an ancestor dir of the repo · `<repo>/.claude` (a link to the repo actor's dir) · an actor's own brain dir | a property of the file's path, independent of how claude starts |
| M2 launch | enrolled clone (`CLAUDE_CONFIG_DIR` = brain dir, user source only) · `--settings` with no config dir | how claude starts, independent of the file's path |

product: 4 × 2 = **8 cells**.

M2 bundles two toggles — where `CLAUDE_CONFIG_DIR` points, and which sources load. the two values
named are the two launches rhachet and its tests make. a third shape exists: the actor's settings
with `CLAUDE_CONFIG_DIR` set to some other dir. it is a boundary, out of this behavior: there User
memory is that other dir's `CLAUDE.md`, so the home exclude is moot, and the actor's boot is absent
whatever the excludes say. no exclude pattern can help or harm it, so it earns no cell.

the home's *shape* (`/home/x` · `/Users/x` · `/root` · deep · a home named `brain` · windows) is
a sub-axis of M1 = home. it changes only whether the glob matches, never which memory source loads
it, so it is walked as rows of one unit matrix inside the M1 = home cells, not as a product axis.

## seam G — the grove link in git (`settings.of.grove.json` → `<home>/.claude/settings.json`)

found in execution (fulcrum F5): a second committed artifact that names a home, in a link target
rather than a config value.

| axis | positions (closed) | why orthogonal |
|---|---|---|
| G1 the link in git's index | untracked · tracked (a prior release allowlisted it) | what git and history left; the sync reads it, never writes it back |
| G2 the box's grove | `~/.claude/settings.json` present · absent | a property of the box; decides whether the layout findsert relinks the arrow or drops it |

product: 2 × 2 = **4 cells**.

## invariants — not cells, overlays on the whole box

| invariant | kind |
|---|---|
| the repo actor's written file names no machine (home, user, host) | forbidden output, nurture |
| no actor file but `actor.via.repo=ambient` is committed | forbidden scope, nurture (`.gitignore`; a `git add -f` could break it) |

## the felt actors (narrative POV, not an axis)

the human who enrolls · the human who reviews the pr diff · the mechanic who edits the excludes
code · the clone whose corpus is at stake. CI is the writer and matcher on a `/home/runner` box —
a home-shape row — so it adds no cell.

every cell and invariant is verdicted in `1.vision.experience.case=_.md`.
