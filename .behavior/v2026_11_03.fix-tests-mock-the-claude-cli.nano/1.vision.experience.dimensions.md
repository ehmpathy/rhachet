# 1.vision.experience.dimensions

a tier runner runs one test tier; a suite author writes a suite in one. two axes decide what that
run touches.

| axis | closed values | what it varies |
|---|---|---|
| **tier** | integration · acceptance | the grain: a src suite that calls rhachet in-process, or a blackbox suite that drives the built cli or sdk |
| **brain** | mock repl · mock atom · real, gate shut · real, gate open · real, no gate | what answers the call (and, under mock, which kind), and whether a real one is let run — `no gate` is a real brain no live flag holds back, so it runs on every run of its tier |

## .why `flag` is not its own axis

the `BRAIN_LIVE_SCOPE` flag only moves a real brain: under a mock it is inert. as a third axis it
would duplicate every mock cell with no change, so it folds into **brain** as the gate state of a
real brain. the latent sub-dimension (the gate applies to real brains only) is now the axis itself.

## .why the two axes are orthogonal

- **tier** answers *where the brain is reached from*; **brain** answers *what is reached*. each
  tier can, in code, reach any brain value: a src suite can construct `genBrainRepl` (real) or
  `genMockedBrainRepl`; a blackbox suite can put the real claude or the stub cli on PATH
- so no value of one axis forecloses a value of the other by nature. the barred cells — the
  whole integration × real region, every gate state — are barred by nurture (a rule), and the
  catalog says which

## .the brain kind — repl or atom — rides inside the brain value

a brain is a **repl** (`ask` and `act`) or an **atom** (`ask` only). under **mock**, the two are
distinct experiences: `genMockedBrainRepl` and `genMockedBrainAtom` are separate fixtures, and
`caseAskable` routes `ask` to an atom first. so the mock value splits into **mock repl · mock atom**,
each verdicted and demoed in the catalog. under **real**, the kind does not change the experience
this wish governs (a real brain of either kind spends credit), so the real values stay unsplit.

## .why the credential is not its own axis

a real brain with the gate open meets a host that holds a credential, or one that does not. that
state matters only to the real, gate-open cells, and there it is a precondition with one outcome
each: present → the smoketest runs; absent → `ConstraintError` with the cure. case 3 walks both as
its happy and sharp halves. as an axis it would add four cells that can only read *mock: inert* or
*gate shut: inert*, so it stays a precondition of the brain value, named here.

## .why the actor is not its own axis

two actors meet this behavior: the **tier runner** (cicd or a human), who walks every cell, and the
**suite author**, who writes a new src suite. the author's whole walk sits in one cell
(integration × mock) and is either paved (the six suites show the form) or sharp (case 2: a told
output the schema refuses). the catalog itemizes the author's paved walk and demos the sharp one,
so the actor varies within a cell, not across the grid.

product: 2 × 5 = 10 cells, each verdicted in `1.vision.experience.case=_.md`.
