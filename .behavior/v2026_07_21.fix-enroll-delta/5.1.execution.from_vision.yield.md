## progress log

- root cause pinned to #418 (`ea89630`, v1.44.0): global `getPreprocessedRoleArgv` encodes lead-`-`
  tokens to `\u0000role` for commander's variadic init; enroll never decoded, so `-driver` reached
  the enroll parser as `\u0000driver` → treated as a bare role in replace mode → validate fail.

  assertion to match, rather than reintroduce a per-command guard.

  `git diff --stat main` shows zero change across `invokeRun.stdin.integration.test.ts`, `invokeRun.ts`,
  `.test/infra`, `domain.operations/run`. the error is a bun-binary fixture skill-discovery miss, not
  role parsing.

## convergence round 3 (i006 l3 re-review — the `-r` global collision)

on a fresh `--as arrived`, the judge tally showed `blockers exceed threshold (2 > 0)` — the
TWO fresh **l3** blockers (r10 enroll-impl-behavior-intent, r11 enroll-impl-arch-defects).
this corrects the earlier "l1 exhaustion wall" note: the judge counts the fresh l3 blockers,
NOT the exhausted-cached l1 set, so no human overrule was needed — the path was to converge
r10 + r11.

both l3 reviewers independently traced the SAME real regression that round 2's `-r` fix
introduced:

- **`-r` globally corrupts `act`/`ask`/`run` short flags** (r10 + r11 blocker, genuine):
  round 2 made `isRolesFlag` recognize `-r`, but the argv preprocessor runs on the GLOBAL
  argv before commander knows the command. `-r` is the `--role` alias on act/ask/run (not
  `--roles`), so a command-blind encode opened a bogus roles value-run and rewrote the next
  short flag (e.g. `-s`) to a `\u0000s` null byte — a break of `act -r <role> -s <skill>`.
  fixed at the root: the encode is now **command-scoped**.
  - new `getCommandFromArgv.ts` (+ test, 5 cases) — subcommand lookup, robust past a global
    `-c/--config <path>`.
  - `getPreprocessedRoleArgv` gates: encodes ONLY for the `--roles` delta commands
    (`init`/`enroll`/`upgrade`); every other command's argv passes through untouched.
  - clamps: `getPreprocessedRoleArgv.test.ts` case6/case7 (act/ask/run `-r … -s`/`-a`/`-i`
    stay intact; enroll `-r -driver` still encodes behind a global `-c`) + blackbox
    `act.acceptance.test.ts` case3 (`act -r any -s say-hello` reaches the same
    `no brains available` outcome as the long form — proof at the subprocess layer).
  - the rule brief now has a `.the -r short-alias trap` section (polysemy table + the
    command-scope rule + a new enforcement line) that closes the "durable record absent" gap.
- **A vs B**: r11 preferred option A (drop enroll's `-r` alias). i took **option B**
  (command-scoped encode) because A regresses enroll's PRIOR `-r, --roles` alias — a
  product-visible flag that predates the wish (vision doc verified enroll's signature). that
  removal is a wisher call; B fixes the bug with zero behavior change on any command. flagged
  A to the wisher as a future simplification.
- **held / parked (all l3 nitpicks)**: `invokeEnroll` operation decomposition, duplicate
  enroll test surfaces, `--help` passthrough, `upgrade --roles` multi-specifier acceptance —
  all previously-tracked, out of this wish's bound scope, flagged for the wisher.
