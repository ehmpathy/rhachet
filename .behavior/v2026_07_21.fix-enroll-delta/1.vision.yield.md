# 1.vision — fix enroll delta roles regression

## the wish, restated

`rhx enroll claude --roles -driver` should **drop the driver role** from the default
enrollment set (delta-subtract). instead it errors:

```
BadRequestError: role 'driver' not found, did you mean 'driver'?
  { "role": "\u0000driver", ... }
```

that self-contradicting "did you mean 'driver'?" (it IS driver) is the tell: a NUL
sentinel (`\u0000`) is glued to the front of the role name. this is a **regression** — it
worked a week ago. the wish asks us to (1) track down the release that broke it, (2) fix
the regression, (3) clamp it with acceptance + integration coverage so it can never
regress again.

---

## the outcome world

### day-in-the-life

a human tunes which roles a brain boots with, using the delta sigils:

```sh
rhx enroll claude --roles -driver             # all defaults, minus driver
rhx enroll claude --roles +architect          # all defaults, plus architect
rhx enroll claude --roles -driver,+architect  # minus driver, plus architect
rhx enroll claude --roles mechanic            # replace: ONLY mechanic
```

`-driver` reads like `git`'s own `-`: a subtraction. the brain boots with every linked
role except driver. no error, no NUL byte, no surprise.

### before / after

| | before (v1.44.0, broken) | after (fix) |
|---|---|---|
| `enroll --roles -driver` | 💥 `role '\u0000driver' not found` | ✓ boots defaults minus driver |
| `enroll --roles +architect` | ✓ (bare `+` survives) | ✓ (unchanged) |
| `enroll --roles mechanic` | ✓ replace | ✓ (unchanged) |
| `init --roles -reviewer` | ✓ (decodes sentinel) | ✓ (unchanged) |

only the **`enroll` + leading-`-`** path is broken; the fix restores it without touching
the `init` incremental path that #418 shipped.

### the "aha"

the value clicks the moment a human types `-driver` and the driver simply isn't there —
the sigil does exactly what the shell-native `-` implies. subtraction is honored, not
mangled.

## user experience

### usecases / goals

- **trim a noisy role** for a focused session (`-driver`) without re-listing every other role
- **add one role** on top of defaults (`+architect`)
- **compose** both in one call (`-driver,+architect`)
- **replace** wholesale with a bare list (`mechanic,ergonomist`)

### contract inputs & outputs

- **input**: `rhx enroll <brain> --roles <spec>` where `<spec>` is comma-separated tokens:
  - bare `role` → replace mode
  - `+role` → delta add
  - `-role` → delta subtract
  - mixing bare + sigil is an error ("in delta mode, all roles must be prefixed with + or -")
- **output**: a generated enrollment config (`settings.enroll.$hash.local.json`) whose
  SessionStart hooks contain exactly the computed role set, then the brain CLI is spawned
  against it.

### leverage example

```sh
$ rhx enroll claude --roles -driver
# → config authored with mechanic + ergonomist + ... (all linked roles EXCEPT driver)
# → claude spawns booted with that role set
```

### timeline

instant — the failure (and the fix) both occur at argv-parse time, before any spawn.

## evaluation

### how well it solves the goal

fully — it restores the documented contract (`invokeEnroll.ts:175`, `.note` on
`parseBrainCliEnrollmentSpec.ts:6`) that was silently broken by an unrelated feature.

### pros

- surgical: the enroll spec parser already handles `-driver` correctly (unit-tested at
  `parseBrainCliEnrollmentSpec.test.ts:55` case4). the fix is upstream of it.
- the `init` incremental feature (#418) keeps working unchanged.
- clamps close a real coverage gap (see "why it slipped").

### cons / tradeoffs

- the argv-preprocessing seam (`getPreprocessedRoleArgv`) is a global transform applied
  before command routing. any fix must respect that both `init` and `enroll` share
  `--roles` but interpret dash-led tokens differently. scoping the transform is the clean
  cut but means the preprocessor must become command-aware.

### edgecases / pit of success

- `--roles -driver,+architect` (mixed) — must survive as `-driver` + `+architect`
- `--roles -` (empty after sigil) — still errors cleanly ("cannot be empty")
- `enroll` vs `init` with identical `--roles -x` — must diverge correctly (enroll parses
  the dash natively; init decodes a sentinel)
- a real `-role` that collides with a brain passthrough flag — enroll strips `--roles` from
  passthrough (`filterOutRolesArg`, `invokeEnroll.ts:143`), so no leak downstream

## why it slipped (the coverage gap)

the repo's real acceptance layer is **`blackbox/cli/*.acceptance.test.ts`** — true
subprocess tests driven through the built binary via `invokeRhachetCliBinary`.

- the #418 author wrote **exhaustive** blackbox coverage for `init`'s incremental sigils:
  `blackbox/cli/init.incremental.acceptance.test.ts` has **21 cases** (e.g. `-architect`
  remove at case3, `+architect -reviewer` at case4, bare `-` at case9). that harness
  **does** exercise the full argv path, `invoke.ts:36`'s `getPreprocessedRoleArgv` and all.
- **but `enroll` got zero `blackbox/cli/` coverage.** a single mirrored enroll case
  (`enroll <brain> --roles -driver`) would have caught this regression the moment #418
  merged.
- the only enroll "acceptance" test, `src/contract/cli/invokeEnroll.acceptance.test.ts`, is
  a **mislabeled outlier**: it lives under `src/` (not `blackbox/cli/`), is
  `describe.skip(...)` (`:42`), drives commander **in-process** via
  `program.parseAsync([...], { from: 'user' })` (`:148,246`) — which **bypasses**
  `getPreprocessedRoleArgv` entirely — and gates on `ANTHROPIC_API_KEY` + a live `claude`
  spawn.

net: the harness that would have caught this existed and was used for `init`; `enroll` was
never wired into it.

## proposed contract for the fix

### root cause (verified)

- **introduced by**: PR #418 (`ea89630`, "feat(init): incremental --roles +role/-role
  syntax"), shipped in **v1.44.0** (2026-07-21). last good release: **v1.43.1**.
- **chain**:
  1. `invoke.ts:36` calls `getPreprocessedRoleArgv({ args })` on the **global argv, every
     command**.
  2. `getPreprocessedRoleArgv.ts:45-48` rewrites any `-role` token after `--roles` into
     `\u0000role` so commander's *variadic* `init --roles <roles...>` won't drop it.
  3. `init` decodes it back (`getDecodedRoleToken`, used in `invokeInit.ts`). **`enroll`
     never decodes** (`invokeEnroll.ts` has no such call).
  4. so `enroll --roles -driver` → `opts.roles = '\u0000driver'` →
     `parseBrainCliEnrollmentSpec` sees a token NOT starting with `-` → treats it as a bare
     role in **replace** mode → `validateRoleExists` fails →
     `role '\u0000driver' not found, did you mean 'driver'`.

### fix — root cause: unify `--roles` into one shared contract

**wisher decision (2026-07-21):** do not merely scope the sentinel hack to `init`. the true
root cause is **two commands with divergent `--roles` treatment** — `init` (variadic +
sentinel decode) vs `enroll` (single-string, no decode). the global encode was built for
init and silently corrupts enroll. the cut is to make `--roles` **uniform** across every
command that offers it.

**the uniform `--roles` contract:**

- **one grammar** — each token is `+role` (add), `-role` (remove), or bare `role` (replace).
- **two interchangeable forms, both always supported:**
  - space-separated: `--roles +architect -reviewer`
  - comma-separated: `--roles +architect,-reviewer`
  - (mixed allowed; both collapse to the same token list)
- **one shared parser** — a single transformer that every command calls to turn the raw
  token list into ops. merge the extant `parseBrainCliEnrollmentSpec` (enroll) and init's
  token classifier (`getClassifiedRoleTokens`) into **one** canonical parser, so the grammar
  lives in exactly one place.
- **uniform sentinel** — a variadic option still needs the argv encode to keep
  space-separated `-role` tokens past commander, so the global encode **stays** — but now
  **every** `--roles` consumer decodes through the shared parser. no command is left
  un-decoded, so the `\u0000` can never leak again. the asymmetry that caused the bug is
  deleted, not patched around. (mechanism detail — keep the global encode + shared decode,
  vs a commander `preSubcommand` hook that rewrites raw argv — is a **blueprint** call;
  the *contract* above is fixed.)
- **codify it** — a `.this`-scoped rule brief at `.agent/repo=.this/role=any/briefs/`
  (proposed `rule.require.roles-flag-dual-format.md`) states: *every `--roles` option in
  **this repo** MUST accept both the space- and comma-separated sigil forms, via the one
  shared parser.* scoped to this codebase's `--roles` + shared parser (not a generic
  cross-repo rule). this stops the contract from drift back into per-command divergence
  (the exact drift that produced this regression).

this supersedes the earlier "A vs B" framing: it **is** fix A (solve at cause), taken to its
end — one grammar, one parser, one uniform sentinel path, one brief to hold the line.

### clamp — thorough & exhaustive, per the uniform contract

the wisher wants **thorough and exhaustive** acceptance coverage. since the fix makes
`--roles` uniform, the tests verify the *contract* on **every** `--roles` consumer
(`init` **and** `enroll`), across **both** forms (space + comma), so no command can ever
drift again.

**layer 1 — unit: the shared parser + the argv sentinel.**
- exhaustive table-driven unit tests of the one shared parser: for **each** form (space and
  comma) × **each** sigil case — bare replace, `+add`, `-remove`, mixed `+a -b` / `+a,-b`,
  dedupe `+a +a`, conflict `+a -a`, empty `-` / `+`, whitespace — assert identical ops
  regardless of form.
- the argv sentinel round-trip: `-role` encodes then decodes back to `-role` for **every**
  `--roles` consumer (no command left un-decoded → `\u0000` can never survive to a role name).

**layer 2 — blackbox acceptance (subprocess, the contract proof).** true subprocess tests
via `invokeRhachetCliBinary`, mirrored on the extant 21-case
`blackbox/cli/init.incremental.acceptance.test.ts`:
- **extend** `init` coverage to add the **comma-separated** form for every case it already
  tests space-separated (so both forms are proven for init).
- **add** `blackbox/cli/enroll.acceptance.test.ts` covering the full matrix for enroll:
  `-driver` (the regression), `+architect`, `-driver,+architect`, `-driver +architect`,
  bare replace, dedupe, conflict, unknown role, empty sigil — in **both** forms. reuse
  `setupRoleFixtureRepo` / `isRoleLinked` from `blackbox/.test/infra/`. do **not** rely on
  the skipped in-process outlier `src/contract/cli/invokeEnroll.acceptance.test.ts` (retire
  or fold it).
   - **the enroll-specific wrinkle**: `init`'s terminal action links files (clean asserts);
     `enroll`'s terminal action **spawns the brain CLI** (`enrollBrainCli`,
     `invokeEnroll.ts:131`) after config generation, so the blackbox test must not let a live
     `claude` spawn run in CI. two coverable pre-spawn seams: (a) the **error path** — a bad
     spec throws at validate *before* spawn (assert exit≠0 + clean message; and exit==0 for a
     valid `-driver` up to the spawn boundary); (b) the **config artifact** — assert the
     authored `settings.enroll.$hash.local.json` role set. the blueprint picks the
     spawn-avoidance mechanism (stub brain, or assert-then-let-spawn-fail).

**layer 3 — the rule brief** (`.agent/repo=.this/role=any/briefs/`): the contract as a
durable rule, so future `--roles` consumers inherit "both forms, one shared parser" by
default and reviewers can cite it. this is both a deliverable and a regression clamp — it
makes the divergence that caused this bug a reviewable violation.

## what is awkward

- **one `--roles`, two grammars**: `init` uses a **variadic** `--roles <roles...>` (needs
  the sentinel smuggle); `enroll` uses a **single-string** `--roles <spec>` (parses dashes
  itself). a global argv transform can't serve both — it must know which command it's
  feeding. that's the friction the fix has to settle.
- **the sentinel leaks conceptually**: a NUL byte injected globally to work around one
  command's parser is a footgun for every other `--roles` consumer, present and future. the
  clean design would encode as late as possible (only for the variadic init parser), not on
  the shared global argv. fix A is the minimal step toward that; a follow-up could push the
  encode fully into the init command's own arg handling.
- **the skipped acceptance test** gave false comfort — it named `-driver` yet structurally
  could not catch this class of bug. that's the most uncomfortable part: coverage existed on
  paper, not in fact.
