# 1.vision.experience.case=5.upgrade-under-a-mod — sharp critipath (fails safe)

## .narrative

two weeks after vlad's mods, ehmpathy ships mechanic@1.40.0. that release rewrites
`rule.prefer.short-sentences.md` — a new caveat — and removes `rule.prefer.active-simple-tense.md`,
which vlad had also shadowed.

`rhx upgrade` relinks the role and re-materializes the modded view. without a reminder, vlad's
shadow would keep the newer original out of sight, and nobody would re-read it. his mod `boot.yml`
declares `of: ehmpathy/mechanic@1.39.5`, so the upgrade names the move and lists every mod to review;
each boot after it names the drift in the mod notice until the pin moves. a mod arms no stop hook
(F23 (b)).

the removed path needs no special state: the role no longer holds it, so vlad's file there is now a
file at an unheld path that no `say:` names — the same refusal as a typo (case 3). the upgrade names
it under `🧢 a mod no longer applies`, with its fix, and exits 2 once every other actor is rendered;
the boot of that role fails loud with the same fix; actors without the mechanic boot as usual.

**why critipath**: every mod outlives a release sooner or later. if this broke, mods would rot in
silence — the drift a per-clone copy causes, one grain up.

## .bdd `[tn]` timeline

```
given the mod boot.yml declares `of: ehmpathy/mechanic@1.39.5`
  and shadows of short-sentences and active-simple-tense

  when [t0] `rhx upgrade` lands mechanic@1.40.0, which changes short-sentences and removes active-simple-tense
    then the relink completes, and stdout names the modded role, 1.39.5 → 1.40.0, every mod listed,
         and the pin to set
    then stdout names the active-simple-tense mod under `a mod no longer applies`, with its fix; exit 2

  given a release that removes no modded path
  when [t0.1] `rhx upgrade` lands it
    then stdout names the drift alone; exit 0

  when [t1] a clone boots the mechanic
    then the boot fails loud, exit 2, and names the mod of the mechanic as refused:
         active-simple-tense is a file the role no longer holds — neither shadow nor addition

  when [t2] vlad folds the new caveat into his short-sentences shadow, deletes the active-simple-tense
       file, and runs `rhx init`
    then the boot passes, and its mod notice reads `@1.39.5 (installed 1.40.0)`

  when [t3] vlad sets `of: ehmpathy/mechanic@1.40.0`
    then the boot notice drops the drift

  given a mod boot.yml whose `of:` carries no `@version`
  when [t4] the role moves
    then no pester fires; the refusals still do

  and at every stop, in every state above
    then no stop carries a mod pester — a mod arms no stop hook
```
