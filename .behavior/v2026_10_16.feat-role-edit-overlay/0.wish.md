wish =

# wish: edit an extant role in place, via `.agent/repo=.edit/role=<role>/`

## .outcome

a repo can **modify a role it consumes, without a publish of that role's package**:

```
.agent/repo=.edit/role=mechanic/
  briefs/rule.require.foo.md          # OVERWRITES the mechanic brief of the same path
  briefs/rule.require.bar.md          # EXTENDS — a brief the mechanic role never had
```

the next boot of a clone with that role sees the edited role: the overwrite in place of the
original brief, the extension beside the role's own briefs, the rest of the role as published.

## .why

today a change to a role's briefs is a full roundtrip: edit the role repo, review, merge, release,
`rhx upgrade` in every consumer — before a single clone can try the change. so an experiment with a
role costs a release, and most experiments never get run.

with an edit dir, a supervisor or a human tries a change in one repo, watches clones under it for a
session or a week, and only then promotes what worked upstream. the roundtrip moves from *before*
the experiment to *after* it, and only for the edits that earned it.

## .what the vision must settle

- **match**: how an edit names the brief it overwrites — by its path relative to the role's
  `briefs/`, by filename, or another key. a typo must not silently turn an overwrite into an
  extension
- **scope**: briefs first. say whether skills, inits, hooks, `boot.yml`, and `keyrack.yml` can be
  overwritten or extended too, and which are out of scope for now
- **boot**: how an edited role interacts with its `boot.yml` say/ref split and its token budget — an
  extension a boot never loads edits naught
- **which role**: `role=<role>` names one role — say how a name that two linked repos share (e.g.
  `ehmpathy/mechanic` vs another `mechanic`) is disambiguated
- **visibility**: a clone, a reviewer, and a human can each see that a role is edited, and what the
  edit changed — never a silent divergence from the published role
- **lifecycle**: what an `rhx upgrade` does to an edit whose original brief changed or vanished
  upstream, and how an edit is promoted upstream or dropped once it lands

## .done when

- a repo with `.agent/repo=.edit/role=<role>/briefs/…` boots clones that load the edited role, proven
  by an acceptance test: an overwrite replaces, an extension adds, the rest stays untouched
- an edit that names a brief the role does not hold fails loud, or is declared an extension — by an
  explicit rule, never a guess
- the boot render and `rhx roles` (or its peer) show which roles are edited and how
