## .the short rows

### D4 — role identity

| value | verdict | why |
|---|---|---|
| `one` | demoed (cases 1–5, 7–9) | the common case |
| `many` | **forbidden** → **demoed** case 6 | a bare slug two linked repos share; refused with the `repo/role` forms |
| `none` | **forbidden** → **demoed** case 6 `[t0]`, `[t2]` | `of:` absent or unlinked; refused with the linked roles named |

### D5 — artifact kind

| kind | verdict | why |
|---|---|---|
| `brief` | in scope — demoed cases 1–5, 7, 8 | the wish's first scope |
| `skill` | in scope — demoed case 9 | the wisher's call (S1). it runs from the merged view |
| the mod's `boot.yml` | in scope — the plan | the role's schema plus `of: repo/role[@version]`; a `budget:` key is refused |
| `init` (hooks) | **forbidden** — refused loud | hooks come from the role package and write `settings.of.repo.json`; a mod there changes actor config |
| `keyrack.yml` | **forbidden** — refused loud | a credential manifest is a security surface |
| `readme` | **forbidden** — refused loud | no behavior changes |

### D6 — boot placement

| value | for a shadow | for an addition |
|---|---|---|
| `say` / `ref` | keeps the original's slot, unless the mod's boot.yml names it (read first) | the slot the mod's boot.yml names |
| `unplaced` | **impossible** unless the original was itself unplaced — then it renders where the original would, in `<also>` | **forbidden** — an addition no glob names is case 3 |

### D7 — clone time

| value | verdict | why |
|---|---|---|
| `new` | **demoed** cases 1, 2, 8 | enroll renders boot.md (`invokeEnroll.ts:483`), so it boots the mod |
| `live` | **itemized**, sharp alterpath — demoed in case 8 `[t0]`, `[t2]` | a live clone keeps the boot it read at session start; a re-enroll picks up the mod. render paths say so in stdout |

### D8 — same slug, other repo — does another linked repo (or `.this`) ship the modded role's slug

| state | verdict | why |
|---|---|---|
| `alone` | **demoed** — cases 1–5, 7–9 | the common case |
| `shared` | **demoed** case 10 (both boot apart, each as its own `repo/role`), case 6 `[t1]` (a mod lands on the one `of:` names; the other boots as published) | roles boot apart (S4). today a `boot.md` drops all but the first per slug (`asRoleRefsFirstSeenPerRole.ts:7-13`); this wish removes the drop |
| `shared`, both modded | **impossible** in v1 — case 6 `[t3]` | one mod dir per slug (`role=<slug>`), so the layout cannot hold two |

### D9 — version

| value | verdict | why |
|---|---|---|
| `equal` | **demoed** cases 1, 2 (silent) | naught moved |
| `differs` | **demoed** case 5 | `rhx upgrade` lists every mod and exits 0; each boot's notice names the drift; no stop carries it (F23 (b)) |
| `absent` | **itemized** — demoed in case 5 `[t3]` | no pester; the refusals still apply |
