## 2. ⭐ what sharpens the fix

my first read was *"the credential is simply unfilled."* that was incomplete, and the fuller
version matters:

**`AWS_PROFILE` is not declared for `env.test` at all.**

- `useKeyrack()` defaults to `env: 'test'`
- the root manifest declares `AWS_PROFILE` only under **`env.prep`**
- the mechanic manifest has it **commented out** under `env.test`

so these tests could **never** source AWS creds locally — even on a box whose AWS SSO is perfectly
configured. a fill alone would not fix it; the **declaration** has to come first.

⚠️ I did not make that edit myself. it changes what `keyrack unlock --env test` demands of every
consumer of this repo, and a newly-declared key that is not yet filled could turn the harness's
`keyrack: unlocked ehmpath/test` step into a new failure for others. that is a shared
credential-config decision, so it is yours.
