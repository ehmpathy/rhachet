## 7. the one blocker — foreman-owned, and precisely named

**15 integration tests fail on this host.** all 15 are `aws.params`:

- `setKeyrackAwsParamGithubApp.integration.test.ts`
- `vaultAdapterAwsParams.integration.test.ts`
- `delKeyrackAwsParam.integration.test.ts`
- `getOneKeyrackAwsParam.integration.test.ts`

### the cause, diagnosed and cited

the failure is **not** an assertion. it is:

```
TypeError: A dynamic import callback was invoked without --experimental-vm-modules
  at @aws-sdk/credential-provider-node/dist-cjs/index.js:121:29
```

`vaultAdapterAwsParams.integration.test.ts`'s own `.creds` note explains the mechanism exactly:

> the SSO session is re-vended THROUGH keyrack, then exported as STATIC env creds, so the AWS SDK
> uses the synchronous env provider (**an SSO profile makes the SDK lazily `import()`, which jest
> rejects**)

`useKeyrack()` sources `env: 'test'` in `lenient` mode; with no profile sourced it returns without
any export of static creds, so the SDK falls through to its dynamic-import SSO branch.

**keyrack itself names the absent credential:**

```
$ rhx aws.whoami --env test
🔐 keyrack
   └─ ehmpathy.test.AWS_PROFILE
      ├─ status: absent 🫧
      └─ tip: rhx keyrack set --key AWS_PROFILE --env test --vault aws.config
```

and `.agent/keyrack.yml` declares `AWS_PROFILE` under **`env.prep`** only, while `env.test`
(via `.agent/repo=.this/role=test/keyrack.yml`) holds just the three llm keys.

### ruled out as mine — three independent ways

1. **the stack holds no keyrack frame.** it is entirely inside `@aws-sdk/credential-provider-node`
2. **the failure precedes my code.** it fires at `beforeAll(() => useKeyrack())`, before any
   keyrack operation runs
3. **the one aws.params file I did touch is provably off that path.** my change to
   `getOneKeyrackAwsParamOrgProfile.ts` sits behind `if (org === '@all') return null;`, and those
   tests' own `.scope-note` states their keys are `@all` — so the changed line is never reached.
   its unit clamp (`getOneKeyrackAwsParamOrgProfile.test.ts`) passed in the green 1653

### CI is the authoritative gate, and it covers this

`useKeyrack` **skips in CI** (`if (process.env.CI) return`) because credentials arrive from an
attached role. CI's `test` workflow passes on main (`gh run list` → `test`, `success`, `6m45s`,
2026-08-22), which covers integration.

### the exact fix, for the foreman

```sh
rhx keyrack set --key AWS_PROFILE --env test --vault aws.config
```

| does my diff touch that path? | **no.** `git diff origin/main --name-only` holds no `clone`/`joker`/`realbrain`/`pty` file. every change is keyrack, `.behavior/`, `.agent/`, `pnpm-lock.yaml` |

### the root cause, read from the captured pty buffer

the harness already handles claude's one-time folder-trust menu
(`blackbox/.test/infra/enrollCloneHarness.ts`). it raced `/trust\?|Welcome/` and, on the trust arm,
sent a bare `\r` — because the menu **used to** pre-select `Yes, I trust this folder`.

the current claude build renders the menu with the **safe refusal pre-selected**:

```
⚠ This folder pre-approves 195 tool permissions in .claude/settings.json:
❯ No, exit
  Yes, I trust this folder
Enter to confirm · Esc to cancel
```

so the bare `\r` **confirmed the exit**. claude never booted, `Welcome` never printed, and the
next wait burned its full 120s — 27 times, with no clue in the message why.

⚠️ the failure mode is the expensive kind, and it is the same shape as this wish's own complaint:
the error names the symptom (`no /Welcome/`) and not one word about the cause.

### the repair

read **which** option carries the `❯` cursor rather than assume a pre-selection, then step onto the
trust option before the Enter:

```ts
await bg.waitForOutput({ pattern: /Yes,[^\r\n]*folder/, timeoutMs: 30000 });
const cursorSitsOnRefusal = /❯[^\r\n]*No,/.test(bg.getOutput());
if (cursorSitsOnRefusal) bg.write('\u001b[B'); // ↓ onto "Yes, I trust this folder"
bg.write('\r');
```

its properties, each checkable:

- **order-independent** — it reads the cursor, so it survives either option order. the prior code
  hard-assumed one, which is exactly what broke
- **additive** — if the trust option is already selected, no arrow is sent and the behavior is the
  prior behavior
- **waits for the option list first** — the `trust?` header prints **before** the options, so the
  cursor must not be read at the header match. a second short wait on the trust option's own line
  fixes the read point
- **spans the escapes** — the menu draws word-by-word with `[NNG` cursor moves, so the match is
  same-line (`[^\r\n]*`) rather than contiguous
