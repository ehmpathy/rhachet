# case=2 — role × deliver × happy

> **cell #3** — the clone opens; **every** brief is present, and the load is a cache read.
> this is the wish's central promise.

## .the narrative

the clone opens. Kai asks it a question whose answer lives **in the middle** of the corpus — a rule
from the learner role, roughly 120 KB into a 224 KB payload:

> *"what does `rule.always.reuse-pavement-before-improvise` say about grepsafe?"*

the clone answers with the brief's actual content: that `grepsafe` reports a lower bound rather
than a census, that a `/` in `--glob` matches no file and reports a clean zero, and that
dot-prefixed files are invisible to it.

**that answer is the acceptance test.** it is unanswerable from a 2,000-character preview. the
clone could only produce it if the byte at offset ~120,000 actually reached its context.

Kai checks the session's cache stats. the first session of the day was a cache **write**. this one
— same roles, same corpus, different worktree — is a cache **read**.

## .why this is a critipath

it is **the wish, stated as an observation**. every other case in the inventory exists to protect
or qualify this one.

and it is the case that distinguishes the *real* motive from the one #398 led with. the corpus was
never merely *expensive* to deliver — past 10,000 characters it was **not delivered at all**. the
clone held a pointer to a file it usually never read.

> **stated honestly: this is not an optimization. it is a repair.**

## .the bdd sketch

```
given [case2] a clone enrolled with a corpus larger than 10,000 characters

  when [t0] the session opens
  then    the corpus is present in the clone's context
  and     no part of it was replaced by a preview or a file pointer

  when [t1] the clone is asked to quote content from the MIDDLE of the corpus
  then    it reproduces that content
  and     it does not report the content as absent or unread

  when [t2] the corpus is inspected for placement
  then    it sits in the cached prefix, ahead of the conversation
  and     it precedes any per-session dynamic content

  when [t3] a SECOND session opens with the identical role set
  then    the corpus load registers as a cache read, not a cache write

  when [t4] a session opens with a DIFFERENT role set
  then    the corpus load registers as a cache write
  and     the prior role set's cache entry is undisturbed

  when [t5] the corpus is 224 KB (the measured mechanic role)
  then    every brief it names is present
  and     no truncation notice appears in context
```

## .the trap this case must not fall into

`[t1]` is the assertion that carries the weight, and it is the easy one to fake. a test that
asserts *"the artifact on disk contains the text"* proves the **render**, not the **delivery** —
and the render was never the broken half.

⇒ the assertion must reach through the transport into the clone's actual context. **the cheap
proof the wisher already named: launch with the corpus and ask the clone to quote from the middle
of it.**
