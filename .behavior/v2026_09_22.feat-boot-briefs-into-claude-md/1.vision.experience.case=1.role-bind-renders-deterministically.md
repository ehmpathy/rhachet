# case=1 — role × bind × happy

> **cell #1** — a human enrolls a clone; the role corpus renders to its transport, byte-deterministically.

## .the narrative

Kai opens a fresh worktree and enrolls a clone for the work ahead:

```
rhx enroll claude --roles mechanic,driver,learner
```

the command resolves the three roles from `.agent/`, orders them **published-first, local-last**,
renders their `say` corpus into one artifact, and launches the cli pointed at it.

```
🐢 radical!

🐚 enroll claude --roles mechanic,driver,learner
   ├─ roles: 3 (published 3, local 0)
   ├─ corpus
   │  ├─ tokens = 48,210  (o200k_base)
   │  └─ digest = sha256:4f1c9a2e…
   └─ launched
```

Kai's colleague Mira runs the identical command in a **different worktree of the same repo**, on a
**different machine**. her digest reads `sha256:4f1c9a2e…` — **the same eight bytes**.

that identity is the whole point. the corpus is a cache *prefix*; two prefixes that differ by one
byte are two cache entries. same roles ⇒ same bytes ⇒ one shared cache entry, and Mira's first
session is a cache **read**.

## .why this is a critipath

**every** other benefit rests on it. if the render is non-deterministic — a timestamp, a map
iteration order, an absolute path, a locale-dependent sort — then the cache fragments per machine
and per worktree, the savings evaporate, and **the defect is invisible**: the corpus is still
*correct*, merely never *shared*. a silent 20× cost regression with a green test suite.

this is also where `--exclude-dynamic-system-prompt-sections` earns its place. without it the
docs state the cache is *"effectively scoped to one machine and directory… that includes worktrees
of the same repository."* a byte-identical corpus in a per-worktree cache entry is determinism
achieved and then discarded one layer up.

## .the bdd sketch

```
given [case1] a repo with three linked roles: mechanic, driver, learner

  when [t0] a human enrolls a clone for those roles
  then    the corpus renders to the transport artifact
  and     the artifact holds every `say` brief of all three roles
  and     the emitted digest names the corpus content

  when [t1] the same three roles are named in a DIFFERENT input order
  then    the rendered bytes are identical
  and     the digest is unchanged

  when [t2] the same command runs from a different worktree of the same repo
  then    the rendered bytes are identical

  when [t3] the same command runs with a different $HOME, $PWD, and locale
  then    the rendered bytes are identical

  when [t4] the corpus is inspected for order
  then    every published role precedes every local (repo=.this) role
  and     a local role edit leaves the published prefix byte-identical

  when [t5] a role is added to the set
  then    the digest changes
  and     the published prefix up to the insertion point is byte-identical
```

## .the sharp edges this path must avoid

| hazard | the guard |
|---|---|
| a timestamp or build id in the artifact | forbid non-derived content; `[t1]`–`[t3]` catch it |
| map/glob iteration order | sort explicitly before render |
| an absolute path (gitroot, `$HOME`) inlined | labels are repo-relative — the peer branch already settled this |
| locale-dependent sort | byte sort, never locale collation |
