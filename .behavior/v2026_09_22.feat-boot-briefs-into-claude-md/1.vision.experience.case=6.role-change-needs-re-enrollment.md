# case=6 — role × change × sharp

> **cell #6** — a human adds a role mid-route and expects it live. the honest answer is
> "re-enroll". this is the **regeneration ceremony**, and it is the ergonomic price of a frozen prefix.

## .the narrative

Kai is deep in a route when the work turns architectural. the clone was enrolled with
`mechanic,driver,learner` — it lacks the architect briefs.

Kai links the role and expects it to take:

```
rhx roles link --repo ehmpathy --role architect
```

**it does not take** — and **for TWO reasons, not one:**

1. **`roles link` was never the command that changes an enrolled set.** it materializes a role's
   directory into `.agent/` — a filesystem act, per-`(repo, role)`. the enrolled set is changed by
   `rhx enroll claude --roles +architect`, which is the *addition* sigil of the `--roles` delta
   grammar (`rule.require.roles-flag-dual-format`; the delta commands are `init`, `enroll`,
   `upgrade` — **`roles link` is not among them**)
2. the session's corpus was rendered and **recorded at its first request**, and the cli reuses that
   record.

⇒ **and reason 1 makes this case SHARPER, never weaker.** `roles link` reports success, writes a
real symlink, and changes the live corpus not at all — so a human who reaches for it gets the
quiet failure below **even on a design where a mid-session set change WOULD take.** it is the
better demo of the two, because it fails at a layer no transport choice can rescue.

the failure mode to avoid is the **quiet** one: Kai asks an architecture question, the clone
answers from general knowledge rather than from the architect briefs, and the answer *looks
plausible*. the absence is invisible.

the sanctioned outcome — the drift is detected and named:

```
🐢 heads up — your role set has drifted from this session's corpus

   ├─ enrolled : mechanic, driver, learner   (sha256:4f1c9a2e…)
   ├─ linked   : mechanic, driver, learner, architect
   └─ drifted  : +architect

   the corpus is bound at enrollment and recorded for this session.

   fix — re-enroll to rebind:
     rhx enroll claude --roles mechanic,driver,learner,architect
```

### what the cell is now

| actor form | is `role × change × happy` still impossible? |
|---|---|
| **hash** — `rhx enroll`'s output, the fleet's default | ✅ **yes, by NATURE and for an unchanged reason.** a role change is a **different path**; this session's file is byte-unchanged forever, so no re-read can deliver new content |
| **slug** / **derived** | ⚠️ **open.** the path holds and the content is rewritten, so a re-read *would* deliver it — **if** a re-read happens, which is `[research]` row 1 |

⇒ **the cell's verdict survives on the fleet's default form and on that form alone.** it is no
longer a bar on the whole cell; it is a bar on the hash form, plus a measurement elsewhere.

🟡 **the record-once quote below is kept and demoted** — it is why the cell *was* sharp, and it is
no longer the mechanism:

> "Claude Code records the system prompt on a session's first request and reuses that record
> until the session is compacted."

## .why this is a critipath, though its happy path is forbidden

#398 named this in its own "what is awkward" and it remains true:

> "'i added a role, why isn't it loaded?' — because CLAUDE.md wasn't regenerated."

it is **frequent** (role sets change often mid-work), **costly** (a clone answers without briefs it
should have had), and **silent by default**. frequency × cost × silence is exactly the profile of
a critipath — and **the detection matters under either grade above**: on a hash actor because the
path cannot repair, and on a slug actor because a repair that lands at an unpredictable moment is
drift a human must still be able to see.

**the asymmetry this section once recorded as "a real argument for `.claude/rules/`" is the
argument that won.** it was ranked below a per-repo grain claim that was false; `CLAUDE_CONFIG_DIR`
removes the grain objection, so the re-read benefit lands at the actor grain. ⇒ `.fulcrums/…F1…`.

## .the bdd sketch

```
given [case6] a live session enrolled with a known role set

  when [t0] a role is linked that the session's corpus does not hold
  then    the live session's corpus is unchanged
  ⇒ asserted so the invariant is provable, not assumed

  when [t1] the drift is checked
  then    the enrolled set and the linked set are compared
  and     the difference is named explicitly
  and     the fix names the exact re-enroll command, with the full role set

  when [t2] the clone is asked a question the absent role's briefs would answer
  then    the drift signal has already been surfaced
  ⇒ the human must not learn of the gap from a wrong answer

  when [t3] the human re-enrolls with the new set
  then    the new corpus holds the added role
  and     the digest changes
  and     the published prefix ahead of the insertion point is byte-identical
  ⇒ a role addition must not invalidate the whole cache — only the suffix

  when [t4] a role is REMOVED from the linked set
  then    the same drift signal fires
  ⇒ drift is symmetric; a removal is as invisible as an addition

  when [t5] the linked set matches the enrolled set
  then    no drift signal fires
  ⇒ the signal must not cry wolf, or it will be tuned out
```

## .the open question

🟡 **where should the drift check fire?** candidates: at session start (cheap, but the drift
usually appears *after* start) · on each route stone (frequent, natural for a driver) · in the
`route.drive` stop hook (already runs, already prints).

⇒ recorded as fulcrum **F4**. the vision best-guesses the **stop hook**, since it already runs on
a cadence that matches when role sets actually change, and it already owns a human-visible surface.

## .F21 voided the drift check

the wisher ruled drift unreachable (**F21**): clones reference their actor's brain dir, and a
roleset change is a new actor, so there is no stale corpus to compare against. the drift
signal above, its record (F17) and its guard (F18) are not built; F4 is void.

what replaces it: `rhx roles link`, `rhx init` and `rhx upgrade` each re-render every active
actor's `boot.md` and print one census line per corpus written. the human who runs one of them
sees the corpus change.

🟡 **the residual risk.** the census reaches only the human who ran the command. a role that a
teammate or ci linked — then pulled into this checkout — re-renders nothing here, and gives no
signal to a human who never ran `rhx roles link` themselves. their live clones keep the prior
corpus until the next render, and no line names the gap. a `[t1]`-style check is the repair if
the gap bites; it is not built.
