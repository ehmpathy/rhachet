# 1.vision.yield — boot briefs into the brain dir

> **a brain dir holds `AGENTS.md` (`@boot.md`) and `boot.md` (the role corpus we render).**
> an enrolled clone reads its actor's brain dir, via `CLAUDE_CONFIG_DIR`. an unenrolled `claude`
> reads the repo's brain dir. `rhx enroll` writes the actor's; `rhx init` and `rhx upgrade` write the
> repo's and every active actor's. the role boot hooks are deleted; the adhoc boot hook stays.

seeds: S1–S10 · brief: `define.brain-dir-repo-vs-actor` · evidence: `1.vision.appendix=groundwork.md`

---

## .the shape

```
<repo>/.claude -> .agent/.actors/actor.via.slug=.default/brain/.claude   # symlink — every brain dir under .actors/

<repo>/.agent/.actors/actor.via.slug=.default/   # the repo's actor — reserved; the one tracked dir under .actors/
  brain/.claude/                             # the repo's brain dir — unenrolled `claude`
    CLAUDE.md -> AGENTS.md                   #   symlink — the core project door, ungated — tracked
    AGENTS.md                                #   @boot.md — tracked
    boot.md                                  #   the repo's default roles, rendered — gitignored
    .gitignore                               #   boot.md — findserted by `rhx init`
    settings.json                            #   hooks — the role boot hooks removed — tracked
    settings.enroll.$h.local.json            #   the enroll --settings artifact — + claudeMdExcludes — gitignored

<repo>/.agent/.actors/actor.via.hash=$h/     # <actorDir> — gitignored
  roles/enrollment.jsonl
  clones/serial=$uuid/
  brain/.claude/                             # the actor's brain dir = CLAUDE_CONFIG_DIR
    CLAUDE.md -> AGENTS.md                   #   symlink — the user-scope door, ungated
    AGENTS.md                                #   @boot.md
    boot.md                                  #   this actor's roles, rendered
    .credentials.json -> ~/.claude/.credentials.json
```

| command | writes |
|---|---|
| `rhx enroll` | the actor's brain dir |
| `rhx init` · `rhx upgrade` | the repo's brain dir **and** each active actor's brain dir |

- `boot.md` is regenerated on every `rhx init` and `rhx upgrade`, so it is never tracked. `AGENTS.md` is a one-line ref and `CLAUDE.md` a symlink to it; both are tracked.
- every brain dir holds the same three: `CLAUDE.md -> AGENTS.md`, `AGENTS.md`, `boot.md`.
- all brain configs sit in one place, `.agent/.actors/`. `<repo>/.claude` is a relative symlink to the default actor's brain dir; `rhx init` moves an extant real `.claude/` into it, then links it. rhachet owns the boot context, so an extant `AGENTS.md`, `CLAUDE.md` or `boot.md` there is dropped, never moved.
- `.agent/.actors/` stays self-ignored, and one dir is excluded from that: `actor.via.slug=.default`. `rhx init` findserts the negation into the repo `.gitignore` and into `.actors/.gitignore`.

## .why — p0 · 1d

```
claude-opus-5-5   costs ~50% less per token, and requires cli 2.1.280
cli ≥ 2.1.89      caps hook output at 10,000 chars, then a 2,000-char preview   [changelog]
the role boot     rides that hook today
⇒ the boot path holds the fleet on the old cli and the pricier model
```

role corpora, measured from one session's own `SessionStart` output:

| role | chars | × the cap |
|---|---|---|
| `ehmpathy/mechanic` | 229,835 | 23× |
| `bhrain/learner` | 95,520 | 9.6× |
| `bhrain/driver` | 72,902 | 7.3× |
| `ehmpathy/architect` | 66,758 | 6.7× |
| six more | 10k–53k | 1–5× |
| five more | <10k | under |

⇒ 10 of 15 breach the cap the moment the fleet upgrades. the whole repo default renders to
**787,547 bytes** — under the documented **4 MiB** instruction-file cap `[/docs/en/memory]`.

## .how the corpus reaches the model

| clone | route | citation |
|---|---|---|
| unenrolled `claude` | the core project load reads `<repo>/.claude/CLAUDE.md` (a symlink to `AGENTS.md`), engine-native and ungated | `/docs/en/memory` |
| enrolled clone | `CLAUDE_CONFIG_DIR` makes the actor's brain dir the user scope; its `CLAUDE.md` (a symlink to `AGENTS.md`) is the user-scope instruction file, engine-native and ungated | `/docs/en/claude-directory` · `/docs/en/memory` |
| both | `@` imports expand at launch, eagerly, relative to the file that holds them | `/docs/en/memory` |

- **one brain dir per clone.** an enrolled clone's cwd is the repo, so the project load also finds the
  repo's `CLAUDE.md`, and the `agents-md` walk its `AGENTS.md`. the enroll `--settings` artifact
  excludes both via `claudeMdExcludes`, which *"applies to the `AGENTS.md` files this plugin reads
  too"* `[mods/agents-md/README.md]`.
- **`CLAUDE.md -> AGENTS.md` in every brain dir.** `CLAUDE.md` is the one door the cli reads in both
  scopes without a gate; the `agents-md` walk sits behind a remote flag (`3.1.1` E3–E5). the symlink
  holds no content of its own, so `AGENTS.md` stays the file rhachet writes.
- **the human's own user-scope memory never loads.** the relocation is not enough — the cli still
  loads a literal `~/.claude/CLAUDE.md` — so `claudeMdExcludes` names it too (`3.1.1` E6).

- past the cap, the adhoc hook emits a manifest header first, so every brief path survives truncation.

## .freshness — clones reference the actor

| change | what happens |
|---|---|
| role **content** (`rhx upgrade`) | each active actor's `boot.md` re-renders in place. live clones take it at their next read; new clones at spawn |
| role **set** | a new hash ⇒ a new actor ⇒ a new brain dir. the prior clone keeps its roles, correctly |

- **active** = at least one clone still live — its reach state LIVE or DEAF, never DEAD. a DEAF
  clone's brain still runs and reads `boot.md` at its next compaction; a DEAD one reads naught.
- an actor skipped for no live clone is rendered at its next spawn: every spawn renders the actor's
  `boot.md` first.
- no drift record, guard, or signal. the reference is the mechanism.
- the corpus is byte-identical at one package version — sorted roles, sorted files, no stats, no
  timestamps. across an upgrade it may differ; that is the point of an upgrade.

## .guardrails

| sharp edge | guardrail |
|---|---|
| cli below the floor | `rhx enroll` refuses — exit 2, names the binary, its version, the floor **2.1.277**, the fix. no clone spawns |
| a fresh actor demands a login | `<actorDir>/brain/.claude/.credentials.json → ~/.claude/.credentials.json`, findserted. measured: an empty config dir → *"Not logged in"* |
| many worktrees of one repo | `--exclude-dynamic-system-prompt-sections` on every spawn — else the cache is scoped per worktree `[C-04]` |
| a rendered corpus lands in git | `rhx init` findserts `boot.md` into the default brain dir's `.gitignore` |
| a real `<repo>/.claude/` already there | `rhx init` drops its `AGENTS.md`, `CLAUDE.md` and `boot.md` — rhachet owns the boot context — and moves each other entry into the default brain dir, then links. stdout names each drop and move. another name in both → refuses, names each, moves none |
| an actor's config lands in git | `.agent/.actors/` stays ignored; only `actor.via.slug=.default` is negated |
| a render fails for one actor on upgrade | the rest proceed; each failure is named on stderr; exit 2 when every failure is the human's to fix (a slug no longer linked), else exit 1 |
| a role boot hook arrives twice | `rhx init` · `rhx upgrade` delete the role boot hooks from `.claude/settings.json`, scoped to our author tag and the `roles boot` command. `assertRegistryBootHooksDeclared` stops its demand for them |
| the run is unattended | every refusal above is an exit code, never a printed message alone |
