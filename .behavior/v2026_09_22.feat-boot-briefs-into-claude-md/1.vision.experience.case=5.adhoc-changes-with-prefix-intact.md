# case=5 — adhoc × deliver + adhoc × change, both happy

> **cells #11 and #13** — the stone's briefs reach the clone, and the route advances to a new
> brief set, **with the cached prefix untouched both times**.
>
> **this is the wisher's core question, demonstrated.**

## .the narrative

the driver is at stone `3.3.1.blueprint`. that stone's manifest names the blueprint practice
briefs — a set the vision stone never needed.

```
rhx roles boot --manifest .behavior/v2026_09_22.feat-boot-briefs-into-claude-md/boot.3.3.1.yml
```

the payload appends to the conversation. the clone has the blueprint briefs **now**, this turn.

the driver passes the stone. the route advances to `5.1.execution`, whose manifest names a
different set again. that payload appends too.

**at no point does the cached prefix move.** the role corpus sits in the cached prefix exactly
where it was at session start. the two adhoc payloads landed *after* it, in the conversation. a
cache read still hits on every turn.

Kai checks: three brief sets have now entered this session, and the session has paid for the role
corpus **once**.

## .why this works — and why it is a property, not a choice

> **the prompt cache is a PREFIX match.**

that single fact settles the whole question:

| the write | effect on cache |
|---|---|
| **append to the end of the conversation** | **cannot** disturb the prefix. by construction |
| change the system prompt (layer 1) | invalidates all that follows |
| change project context (layer 2) | invalidates all that follows |

⇒ an adhoc payload in the conversation is **safe by construction**, whatever transport the
blueprint picks for it. that is invariant 3 in the dimensions file.

### and the second reason FELL with F1's reversal (S12)

the argument read: even with cache set aside, **the system prompt is frozen at the session's first
request** — *"Claude Code records the system prompt on a session's first request and reuses that
record until the session is compacted"* — so an adhoc boot in layer 1 would be **inert**, not
merely expensive.

**S12 ruled a layer-2 transport, which is re-read from disk. that bar is gone.**

⇒ **the verdict holds and the redundancy does not.** row 1 of the table above — *an append cannot
disturb the prefix, by construction* — now carries this case alone. it is the stronger of the two
and it was never contingent on a transport, which is why the walk survives its own reversal.

⚠️ **and the re-read creates a hazard on the other side**: an adhoc boot written to a prefix file
mid-route is no longer inert — it may take at the next compaction, at a moment nobody chose. ⇒ the
adhoc corpus stays in layer 3 because it lands there at an **exact** moment, never because layer 2
cannot receive it.

> **so the split is forced by the mechanism, not chosen for tidiness.** today's hook already
> puts adhoc content in the correct layer. **its placement was never the defect — only its
> 10,000-character cap is.**

## .the bdd sketch

```
given [case5] a session with a role corpus already in the cached prefix

  when [t0] a route stone boots an adhoc manifest
  then    the manifest's briefs are present in the clone's context
  and     the cached prefix is byte-unchanged
  and     the next turn still registers a cache read

  when [t1] the clone is asked to quote from the adhoc payload
  then    it reproduces that content

  when [t2] the route advances and boots a DIFFERENT manifest
  then    the new briefs are present
  and     the prior manifest's content is not re-sent
  and     the cached prefix is still byte-unchanged

  when [t3] three manifests have booted across one session
  then    the role corpus has been paid for exactly once

  when [t4] an adhoc payload is placed in the SYSTEM PROMPT mid-session instead
  then    the change does not apply to the live session
  ⇒ the negative case that proves invariant 1 — inert, not merely costly

  when [t5] the adhoc manifest is byte-identical to the one already booted
  then    the boot is a no-op or is idempotent
  ⇒ a re-entered stone must not double the payload
```

## .the residual sharp edge

🟡 `[t5]` and cell **#16** are where this path still bites: at `/compact`, adhoc content added
earlier is *"summarized with the rest of the conversation"* — it **degrades rather than reloads**,
unlike the role corpus which re-applies intact.

**cell #16 is a CRITIPATH**, on the profile `frequent × costly × silent × no wired fallback`.
the argument is carried in full by the inventory.

⇒ so the residual is narrow, and it is a **selection**, never a grade:

| settled | still open |
|---|---|
| that a remedy is **owed** — #16 is `criti`, and a critipath owes a fail-safe | **which remedy** the blueprint picks |
| that the `matcher: compact` re-delivery **works** as one — demoed in `case=8` | whether the re-boot carries the **current stone's** manifest or the whole route's |
