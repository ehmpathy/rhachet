# case=3 — role × bind × sharp, both attendance positions

> **cells #2 and #17** — the cli is **below the version floor**. it must fail loud, never degrade
> silently — and **#17 asks the harder question: loud to WHOM?**

## .why this case exists at all

the wish's stated urgency is that the old boot path **pins us to an old `claude-cli`**. this
design does remove that pin — and **replaces it with a higher one**:

| capability | floor | whose requirement |
|---|---|---|
| **`AGENTS.md` support** | **2.1.277** | **this feature's transport** (S12) |
| `claude-opus-5-5` | **2.1.280** | **the MODEL's, never this feature's** |

🟡 **row 1 MOVED with F1's reversal**, and the case is unchanged by it. under S6 the transport
floors were 2.1.267 (record-once) and 2.1.275 (the dynamic boundary); S12 ruled
`<brainDir>/AGENTS.md`, whose floor is **2.1.277**. ⇒ ten patch versions higher, **same verdict**
— which is the evidence that this case was always about row 2.

⚠️ **and the floor is not clear on this machine today.** two installs are present; the one that
wins `PATH` is a pnpm shim at **2.1.87**, with **2.1.278** behind it. a naive spawn of bare
`claude` gets the version that clears **neither** floor.

**row 2 is why this case is a guardrail rather than a tax (S11).** the fleet needs 2.1.280 on
the *model's* account, and 2.1.280 clears the row above it. ⇒ **this feature pins no version
the fleet did not already need** — so what Rae meets below the floor is an **extant** block,
surfaced at the one moment she can act on it.

⚠️ **and row 3 is not a claim that the fleet gets to 2.1.280 on its own.** the cap at 2.1.280 is
what truncates the corpus, so **this feature is the blocker on that upgrade** — which is the p0
(S9), and the exact reason Rae's box still runs 2.1.87.

⇒ the wish asks to be *"free of the `claude-cli` version floor"*, and **that means free to move the
floor UP**, never free of a floor. this case is where the move lands on a human.

## .the narrative

Kai enrolls a clone on a box whose `claude` resolves to `2.1.87`.

the dangerous outcome is the **quiet** one: the corpus renders, the flag is accepted (the flag has
existed since well before the cache landed), the session opens, the briefs are present — and every
session is a cache **write**. it works. it is simply 20× more expensive than it reports, forever,
and no signal ever says so.

the sanctioned outcome instead:

```
🐢 bummer dude — your claude cli is too old for a cached boot

  why: AGENTS.md support landed in 2.1.277
       found 2.1.87 at /home/camper/.local/share/pnpm/claude

  fix: upgrade it —
    pnpm add -g @anthropic-ai/claude-code@latest

  heads up: a newer 2.1.278 sits at
    /home/camper/.local/share/fnm/aliases/default/bin/claude
    but the pnpm shim wins your PATH
```

## .why this is a critipath

**a silent degradation here is undetectable by construction.** the feature's entire value is a
cache hit, and a cache miss looks *exactly* like a cache hit from the inside — same briefs, same
answers, same green tests. only the bill differs.

⇒ this is the clearest case in the inventory for **fail fast, fail loud**: the one failure mode
that cannot be caught later must be caught at bind.

🟡 and the error must name **which binary and which path**, because the measured failure here is
not "no claude installed" — it is **two installs and the wrong one wins**. an error that says only
*"upgrade claude"* sends Kai to upgrade the 2.1.278 that was already fine.

## .the bdd sketch

```
given [case3] a machine whose resolved `claude` is below the required floor

  when [t0] a human enrolls a clone
  then    the bind refuses
  and     the error names the required version
  and     the error names the found version
  and     the error names the resolved PATH of the binary it found
  and     the error names the exact upgrade command

  when [t1] a SECOND, newer claude exists elsewhere on the machine
  then    the error also names that path and its version
  and     it states which one wins PATH

  when [t2] the resolved claude clears the floor
  then    the bind proceeds with no version notice

  when [t3] the transport is attempted anyway on an under-floor cli
  then    it is refused at bind
  and     it never degrades to an uncached load in silence

  when [t4] no claude is found at all
  then    the error distinguishes "absent" from "too old"
```

## .the UNATTENDED bind — cell #17

### .the narrative

Rae maintains the fleet. she does not enroll clones by hand — a ramp job does it, forty hosts at a
time, on a schedule.

she opens a PR that adds the `librarian` role to the fleet manifest. the ramp runs that night.

**at 02:14 the job enrolls host 12, whose `claude` is a pnpm shim at 2.1.87.** the floor check
fires exactly as designed. it prints the block from `[t0]` — the required version, the found
version, the resolved path, the upgrade command, and the note that a newer binary sits behind the
shim on the same box. **it is a perfect message.**

then the enroll exits `0`.

the job goes green. Rae's dashboard shows 40/40. the PR merges. nobody opens the log.

**for the next three weeks, host 12's clones run uncached.** they are not broken — they answer
normally, the briefs are present, the tests pass. they are simply ~20× more expensive than every
other host, forever, and **the one signal that said so scrolled past at 02:14 into a file no human
has a reason to open.**

Rae finds it in the cost review. it takes her an afternoon to work out which host, because the
spend is aggregated and every clone reports success.

> **the feel: a refusal that was never refused.** every word of the message was correct, and the
> outcome was identical to a message that had never been printed at all.

### .why the attended remedy evaporates

every `then` in the attended sketch above describes **text a human reads**. the wish is framed
around a **fleet**, and a fleet enrolls from CI or a provisioned host, where that text lands in a
log nobody opens.

> **an enroll that prints a perfect refusal and exits `0` has refused naught.** the pipeline
> goes green, the clone is provisioned degraded, and the fleet inherits the cost silently — which
> is the exact failure mode this case exists to kill, reintroduced one layer out.

⇒ **the refusal must be a FAILURE, not a message.** the text above is the attended presentation of
a machine-detectable event; it is not the event itself.

```
given [case3.u] an UNATTENDED enroll — CI, a provisioned host, a fleet sweep

  when  [t5] the resolved claude is below the floor
  then  the enroll exits NON-ZERO
  and   the exit code distinguishes "too old" (a constraint, exit 2)
        from "no claude found" (also a constraint) and from an internal fault (exit 1)
  ⇒ a caller that cannot read prose can still route the two cases differently

  when  [t6] the enroll runs in CI with the under-floor cli
  then  the build fails at the enroll step
  and   it does NOT proceed to spawn a degraded clone
  ⇒ the fail-fast bound: a refusal that lets the next step run is a warn

  when  [t7] N hosts are enrolled in one sweep and some clear the floor
  then  each host's verdict is individually detectable
  and   a partial success is not reported as a whole success
  ⇒ the fleet case. a sweep that summarizes is a sweep that hides

  when  [t8] the operator later reads the CI log
  then  the same human-readable block from [t0] is present
  ⇒ the attended presentation is ADDITIVE to the exit code, never a substitute for it
```

🟡 **the general result, which recurs at #18 and #21:** every sharp remedy in this design is a
printed message, and a printed message has no reader in a fleet. #17 is where that becomes a
concrete contract — an exit code with a distinguishable constraint value.

## .a hard refusal, never a warn-and-proceed — RULED (F2, S11)

the fork was whether an explicit opt-out is owed: a fleet mid-upgrade might prefer *"warn loudly
and proceed uncached"*, since an uncached boot is merely the status quo cost.

**two arguments close it, and they are independent.**

**1 — an unattended run cannot consent.** a warn in a clone's stdout is read by nobody (cell #17 is
the walked proof). so the opt-out's only safe form is an explicit flag a human typed, never an
inferred tolerance.

**2 — the population the opt-out would serve does not exist.** 2.1.280 is required for
`claude-opus-5-5` and clears both transport floors, so a host below the floor already cannot run
the model this work exists to unblock.

| the opt-out would serve | does that population exist? |
|---|---|
| a host that should stay below the floor | **no.** every host must reach 2.1.280 |
| a host mid-upgrade, briefly below it | ⚠️ yes — and the halt **names the upgrade command**, which is the fastest exit from that state, never an obstacle to it |

⇒ **the refusal turns away only hosts that are already broken for the fleet's purpose.** what Rae
sees at `[t3]` is not a new block; it is an extant block, reported at the one moment she can act.

🟡 argument 1 does not rest on argument 2 — it holds whether or not the opt-out had a constituency.
