## part A — Dev types `claude`, and the clone is a stranger wearing the repo's clothes

Dev has been on this repo for three weeks. the muscle memory is set: open the worktree, type
`claude`, hit enter. it has worked every day.

today it still works. the cli comes up. the banner renders. the cwd is right, the git branch is
right, the file tree is right. **every signal Dev has ever used to know a clone is healthy is
green.**

Dev asks it to add a domain operation — one the `mechanic` role has six briefs about.

the repo default landed, so the clone knows the house voice and the broad strokes. it writes a
`function` declaration anyway. positional arguments. a `try/catch` that swallows the error and
returns `null`. it is competent, plausible TypeScript that **half-matches** the repo — and it
violates four rules the `mechanic` role holds as blockers.

Dev frowns and says *"use the input-context pattern."* the clone says *"of course"* and does. it
is agreeable. it is also **a guess**, because it never read the role's briefs.

> **the corpus is not truncated here. it is PARTIAL — and partial is the harder case.** the
> repo anchor rides the ancestor walk, so it lands with no enrollment. the **actor's** corpus rides
> `CLAUDE_CONFIG_DIR`, which only rhachet sets. Dev did not go through rhachet, so the env var was
> never set, so the actor layer never arrived.
>
> ⚠️ **S13 made the loss smaller and the SIGNAL weaker.** an empty clone is generic; a
> repo-default clone sounds *almost right*, which is the read a human is least likely to question.

Dev, mildly annoyed, tries to hand the task to another clone:

```
$ rhx clone say --to @mechanic-1 'take this one'
🐈 belay that... no clone registered at @mechanic-1
```

**that** is the first real signal, and it arrives only because Dev happened to reach for a
feature that needs the registry. the clone's address and socket register **at enroll** — so a
bare clone is `dark` (unaddressable) and `deaf` (no socket), and it has been both for an hour.

Dev's feel: **not betrayed — puzzled, then embarrassed.** the failure never presented as a
failure. it presented as *"the clone is having an off day"*, which is the most expensive
diagnosis available, because it sends a human to argue with a model instead of to restart a
session.

**the sharp line: a clone that lacks its briefs does not act lost. it acts CONFIDENT.** a
truncated corpus at least leaves a 2,000-char stub a human might notice (#4). a **partial** corpus
leaves a clone that speaks the repo's voice with none of its role's rules — **closer to correct
than an absent one, and therefore harder to catch.**

### what the remedy would have been

```
$ claude
🐢 hold up, dude — this repo needs an enrolled clone

  why: briefs, addressing, and `rhx clone say` all bind at enroll
  fix: rhx enroll claude
```

**one refusal, one command, zero minutes lost.** the shim (proxy or refuse) and the `PreToolUse`
brick are the two levers that produce it, and both live in
`.dream/2026_09_22.enrollment-mandate-a-bare-claude-is-unenrolled.md`.

## part B — CI calls the binary, and there is no Dev to be puzzled

the nightly sweep runs a clone across 40 worktrees. the job was written before `rhx enroll`
existed and calls `claude -p` directly. it has never failed, so nobody has read its log.

tonight it does exactly what it did last night: 40 clones come up, each with **no briefs, no
address, no socket**, each exits 0, and the job reports green.

> **strictly worse than part A, and for a structural reason rather than a scale one.** part A
> had exactly one detection channel — *a human eventually notices the clone does not know its own
> rules*. **remove the human and that channel does not degrade; it disappears.** a fleet of 40
> unenrolled clones is indistinguishable, from the outside, from a fleet of 40 enrolled ones.

and the remedy sketched in part A **does not reach here**: a refusal printed to a log nobody
opens is not a refusal. the machine-detectable form is what part B demands —

- the shim `exec`s `rhx enroll claude`, so the CI job is **repaired rather than refused**
  (`PATH`-derived, so the job's own command line never changes), or
- the brick denies every tool and the job **fails the build**, loudly, with the fix in the deny
  reason

⇒ **this is the D4 finding in its purest form**: *"fail loudly" is meaningless with no listener*,
and it is why the enforcement design cannot stop at a good error message.

```
given [case9] a repo whose clones bind briefs, address, and socket at enroll
              and a human whose muscle memory types `claude`

  when  [t0] the bare binary launches
  then  the clone opens with the REPO DEFAULT corpus, no role briefs, no address, no socket
  and   every signal a human uses reports a healthy boot

  when  [t1] it is asked to write code the ROLE holds rules about
  then  it answers confidently from a repo-default base
  and   the human reads the answer as a quality problem, never a boot problem
  ⇒ the expensive misdiagnosis — a human argues with a model instead of a restart
  ⚠️ S13 narrowed the loss and WEAKENED this signal: a half-right clone reads as a bad day

  when  [t2] the human runs `rhx clone say --to <its address>`
  then  the address is not found
  ⇒ the first honest signal, and it is incidental: it needs a registry feature

  when  [t3] an UNATTENDED caller — a CI job, a provisioned host — calls the binary
  then  the clone comes up unenrolled and exits 0
  and   the build reports green
  ⇒ cell #26: [t0]'s one detection channel does not degrade, it disappears

  when  [t4] the enrollment mandate is in place          <- DEFERRED, not shipped here
  then  the launch is proxied to `rhx enroll claude`, or refused with the command
  and   the refusal is machine-detectable, never only printed
  ⇒ the fail-safe these cells owe, and the reason their verdict is `deferred`

  when  [t5] the repo also holds a project CLAUDE.md     <- NEW, from S13
  then  the default mode reads CLAUDE.md and SHADOWS the .claude/AGENTS.md anchor
  and   the override lives in user/--settings/managed scope, which a bare launch does not carry
  ⇒ the repo default vanishes too, and [t0] degrades back to a TOTAL loss, silently
  ⇒ the check rhx init owes: name the shadow at author time, never let it pass
```

**`[t4]` is the only step in this catalog that describes a behavior this round does NOT ship**,
and that is exactly why cells #25/#26 are verdicted **`deferred` rather than `demoed`**. a sharp

honest grade names the absence rather than the hazard walk. ⇒ `[t4]` is the target the deferred
behavior must satisfy, and the catalog's re-walk obligation is keyed to it.
