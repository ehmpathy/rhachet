# 3.3.1.blueprint.product.yield — boot briefs into the brain dir

---

# summary

each role's body is rendered into `boot.md`, the corpus of a brain dir, beside an `AGENTS.md` that holds `@boot.md`.

every brain dir lives under `.agent/.actors/`, one spot:

| brain dir | where | the cli reads it via | holds | in git |
|---|---|---|---|---|
| the repo's (the default) | `.agent/.actors/actor.via.slug=.default/brain/.claude`, and `<repo>/.claude` is a symlink to it | project scope — `<repo>/.claude/CLAUDE.md`, a core project door, engine-native and ungated, through the symlink | `settings.json` · `CLAUDE.md` → `AGENTS.md` · `AGENTS.md` · `boot.md` · `.gitignore` · the enroll artifacts | ✅ tracked — the one exclusion from `.actors/`'s self-ignore; `boot.md` and `*.local.json` ignored inside it |
| an actor's | `.agent/.actors/actor.via.hash=<h>/brain/.claude` | user scope — `CLAUDE_CONFIG_DIR` | `CLAUDE.md` → `AGENTS.md` · `AGENTS.md` · `boot.md` | ❌ ignored |

| command | renders into |
|---|---|
| `rhx enroll` | the actor's brain dir, then spawns with `CLAUDE_CONFIG_DIR` set to it |
| `rhx roles link` · `rhx init` · `rhx upgrade` | the default brain dir (and the `<repo>/.claude/AGENTS.md` symlink to it) and each active actor's brain dir — every hash actor; slug actors are not built yet (`.out of scope`). all three change the linked set or its content, so all three re-render: one `syncBootsForBrainDirs` at the tail of each command, after its links land (F26) |

**the default brain dir follows the linked set at once.** it is the one slug actor here, so a
link edits its roleset in place — no new actor, no re-enroll. every bare `claude` in the repo
reads it through `<repo>/.claude`: a new session holds the new role at spawn, a live one at its
next `/compact`. an enrolled hash actor is the opposite case — its roleset is its identity, so a
link never adds a role to it; `rhx enroll claude --roles +<role>` mints the actor that holds it.

the hook sync stops to write role boot hooks, so `init` and `upgrade` delete the extant ones.
⚠️ that hook also printed the per-session `<stats>` census; it is lost in full, and only a render
prints one now (F19, Q2). `assertRegistryBootHooksDeclared` is removed. an enroll below cli
**2.1.277** refuses.

vision cells #8 and #20 (a stale corpus at `/compact` or `--resume`, `case=10`) need no mechanism
here: F21 dissolved them — a clone references its actor's `boot.md`, and a new roleset is a new
actor. journey [t4] and [t6] prove the stale state unreachable.

three more vision cells take a disposition here, not a mechanism:

| cell | disposition |
|---|---|
| #25 · #26 `[t5]` — a project `CLAUDE.md` shadows the repo anchor (`case=9`) | dissolved by D7. the shadow is the `agents-md` walk, which a `CLAUDE.md`-family file switches off (E5); the repo corpus now enters through the core `.claude/CLAUDE.md` door, which loads beside a root `CLAUDE.md` and a `CLAUDE.local.md`. so the `rhx init` guard `case=9` asked for has no shadow to name. journey [t1.1] proves it |
| #6 — `rhx roles link` mid-session, the live clone lacks the role (`case=6`) | split by clone kind (S3, F26). **a bare `claude`** reads the default brain dir, and `roles link` re-renders it in place: a new session holds the role at spawn, a live one at its next `/compact` — journey [t1.3]. **an enrolled clone** reads its hash actor, whose roleset is its identity: correct for its roleset, and the fix is `rhx enroll claude --roles +<role>` (F21, F4). no drift notice either way — the drift apparatus is deleted |
