three properties fall out, each asserted rather than asserted-about:

- **the exit code tells a caller who must fix it** — 2 for a constraint the caller owns, 1 for a
  malfunction the system owns (`rule.require.exit-code-semantics`)
- **every failure names BOTH fixes**, never one — a human is never handed a single forced path
- **an absent credential is not treated as a refusal** — the pit-of-success reading: the clone
  spawns, and the human is told what is missing rather than blocked by it

**defaults match the common case** — ✅. the common case is *"boot my roles"*, and it is the
**default**, never an opt-in: no `--boot`, no `--corpus`, no corpus flag at all. the journey's
`[t1]` invocation does carry two flags — `rhx init --roles v --hooks` — and **neither is one**:

change. the clean proof is `[t1.3]`, a bare `rhx roles link` with *"no init after"* whose corpus
renders anyway. a human who types the shortest command that could work gets the corpus.

**convenient** — ✅. zero new flags. the common case is bare `rhx init` / bare `rhx enroll`; the
corpus rides along. not one step must be repeated per-actor either — a single `rhx init` re-renders
**every** live corpus at once, which journey `[t4]` asserts head-on: *"init re-renders every live
corpus"*.

**safe — the pit of success** — ✅, on two counts:

- the easy path is the correct path: a human who does nothing new gets a correct corpus
- the dangerous path is closed by construction. `claudeMdExcludes` keeps the cwd walk off the repo

**zero surprises** — ✅ with one honest note: the `__CHARS__` token in the snapshots is a test-side
mask, never what a human sees. a human sees a real integer.
