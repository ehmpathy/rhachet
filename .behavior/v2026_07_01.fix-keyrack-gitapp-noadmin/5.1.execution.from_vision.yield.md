### resolved (code changed)
- **verb renames** (r4.b1, r5.b1, r5.b2, r6.b1, r6.b2, r6.b3): domain operations now
  use the closed get/set/gen verb set —
  - `initKeyrackInfra` → `genKeyrackInfra` (findsert)
  - `setKeyrackInfraApp` → `genKeyrackInfraApp` (findsert; gen is the domain-op verb for
    findsert per get-set-gen — reconciles the two briefs that clashed on `findsert` vs `gen`)
  - `setGhRepoCreate` → `genGhRepo` (rewritten as a true findsert with effect return)
  - `setGhFileContent` → `upsertGhFileContent` (upsert = overwrite semantics)
- **grain separation** (r4.b3, r6.n1): the async-IIFE discovery inside
  `acquireForSet` moved into a new orchestrator `getKeyrackInfraCandidateApps`;
  the adapter now delegates (mandatory-infra gate + registry-first + admin fallback +
  auto-register all live in the orchestrator).
- **inline single-use type** (r7.b2): `GhOrgInstall` inlined into the `getGhOrgInstalls`
  return type.
- **cli output snapshot** (r8.b1, r9.b1): the inline tree format logic in the `infra init`
  action moved into a pure transformer `getKeyrackInfraInitReport`, covered by a 2-variant
  snapshot test (fresh-init + re-run). the action is now a thin narrative.
- **error friction** (r9.b2): broadened the cli global error handler from
  `BadRequestError` to `HelpfulError` (root-cause fix in `invoke.ts`) — every command now
  renders the friendly, hint-rich message + correct exit code instead of a raw stack
  trace; no per-action try-catch needed.
- **actionable error** (r9.b3): `getGhOrgInstalls` non-403 failures now carry a hint
  ("check `gh auth status`; may be rate-limited — try again").
- **exit-code semantics** (r2.n1, r2.n2): already satisfied by the global handler —
  `ConstraintError` (`code.exit = 2`) → exit 2; the broadened handler keeps this intact.

### kept, with justification (considered disagreement — for the reviewer/wisher)
- **`isGhForbiddenStderr` `is*` prefix** (r4.b2): `is*` is the sanctioned boolean-predicate
  transformer prefix (`rule.require.named-transformers`, e.g. `isEligibleForPremiumFeatures`).
  `getIsGhForbiddenStderr` would be less idiomatic and less readable. get/set/gen governs
  retrieve/mutate/findsert operations, not boolean predicates.
- **no DI for gh communicators** (r4.n1, r7.b1): the DI brief's stated benefit is
  a mock-based swap for unit tests, but the repo's grain-based test rule verifies
  communicators via **real integration tests** (5.3), and `rule.forbid.integration.mocks`
  forbids mocks. to inject a `gh` runner purely to enable mocks would contradict the
  stronger no-mocks strictness, and to thread it through 5 orchestrators + the adapter is
  speculative complexity (wet-over-dry). the communicators are the thinnest possible I/O
  boundary; their value is proven by real calls, not fakes.
- **stderr string match** (r6.n2): the `gh` CLI emits HTTP status as stderr text
  ("HTTP 403"); a match on that IS the status-code capture the note suggests. structured
  errors aren't available at the CLI boundary; a move to octokit is a larger architectural
  change out of scope. real integration tests (5.3) verify the member/transient split.

### deferred to 5.3.verification (chartered, no-mocks needs a real test org + creds)
- **gh integration tests** (r8.b2): each gh communicator + the set flow need real calls

### resolved (code changed)
- **transient-failure failhide** (r6.b1, r9.b3, r9.b4): `getGhFileContent` and
  `getGhRepoExists` previously treated *any* non-zero gh exit as "absent", so a network

  fails loud with a hint.
- **stack-trace preservation** (r6.n1): the broadened `HelpfulError` catch in `invoke.ts`

  handler — `genKeyrackInfra`/`genKeyrackInfraApp` throw `UnexpectedCodePathError`
  (a `HelpfulError`), now caught and rendered (message + stack + exit 1) instead of a raw
  uncaught trace.

### kept, with justification
- **`genKeyrackInfraApp` read-modify-write "race"** (r7.b1): the write passes the sha it
  read, so github's contents api rejects a concurrent stale-sha write with 409 → that
  writer fails loud (no lost update); the loser re-runs into the idempotent skip. the sha
  optimistic-lock IS the atomicity mechanism; documented as a `.note`.
- (carried) `is*` prefix, no-DI for communicators, stderr string match — unchanged from i8.

### deferred to 5.3.verification (unchanged)

  subprocess harness against a real github test org. the transformer-level output snapshot
  (`getKeyrackInfraInitReport`, 2 variants) is in place; the full contract acceptance suite
  is the verification stone's remit.

## resolution: dependency-injection + hermetic fakes (wisher-chosen)

the wisher chose to make 5.1 self-verified via **dependency injection**, not real creds
and not `jest.mock` (which the repo forbids for remote boundaries). this both closes the
test-coverage gap AND permanently clears the open DI blockers (r4.n1, r7.b1, r7.n1).

### the seam
- **new `infra/gh/runGh.ts`** — `GhRun` type + the sole real i/o boundary (`spawnSync gh`).
  every other `infra/gh` function is now a pure transform over an injected `GhRun`.
- **threaded `context: { ghRun }`** through all 5 gh communicators + all 5 infra
  orchestrators; the two composition roots (`mechAdapterGithubApp.acquireForSet`, the
  `keyrack infra init` cli action) inject the real `runGh`.
- **`runGh` is the one untested leaf** — a ~3-line passthrough; its real-`gh` integration
  test is the only remainder for 5.3.verification.

### hermetic coverage (no creds, no real github, no mocks — a stateful fake)
- **`src/.test/assets/genMockGhRun.ts`** — an in-memory github fake: models findsert repos,
  sha-guarded file writes (real 409 on stale sha), 404s, and org-install forbidden. a fake,
  not a stub — it enforces the same optimistic-lock github does.
- **new unit tests (56 in the infra subtree, 168 repo-wide, all green):**
  - communicators: `getGhRepoExists`, `getGhFileContent`, `upsertGhFileContent`,
    `genGhRepo`, `getGhOrgInstalls` — happy paths via the fake + transient-failure
    fail-loud via inline stubs.
  - orchestrators: `genKeyrackInfra` (fresh-create + idempotent re-run),
    `genKeyrackInfraApp` (register + findsert-skip), `getAllKeyrackInfraApps`,
    `getKeyrackInfraExists`, and `getKeyrackInfraCandidateApps` — all four vision discovery
    branches (not-reachable, registry-hit-no-admin-call, admin-fallback, member-403).

### what this closes
- r4.n1 / r7.b1 / r7.n1 (DI) — resolved: the raw boundary is injected.
- r8.b3 / r9.nitpick.2 (untested communicators + orchestrators) — resolved via the fake.
- r7.b2 / r7.b3 (concurrency "race") — now unit-proven: the sha-guard fake shows the loser
