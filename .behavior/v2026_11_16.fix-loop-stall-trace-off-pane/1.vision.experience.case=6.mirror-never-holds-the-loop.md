# experience case=6: the pane mirror never holds the daemon loop

cells 24–27 of `1.vision.experience.dimensions.md` (the pane mirror). sharp × critipath.

## .the narrative

a human runs a crew of clones in panes on one box. one pane sits in scrollback, or its terminal
is starved for cpu, so it drains late. the clone behind it keeps on: its brain-cli redraws, the
daemon mirrors each frame to the pane, and the daemon's loop still turns on time, so a `clone say`
to that clone is still served. when the clone exits, its last frames reach the pane in order
before the exit is reported, so the human sees how it ended. if the pane never drains, the exit
does not wait on it past a short bound. and if the enroll fails before the clone is ready, the
human's terminal is never switched; they see the thrown frame and their shell as it was.

## .bdd

```
given('an attended host whose pane reader is held still')
  when('[t0] the brain-cli redraws while the reader is still')
    then('the host loop still turns on time — the mirror never blocks it')
given('an attended host that flushes behind a still reader')
  when('[t1] it writes many chunks, flushes, and exits')
    then('every chunk reaches the pane, in order, the last before exit')
given('an attended host that flushes behind a frozen pane')
  when('[t2] the pane stays frozen past the flush bound')
    then('the flush settles at its bound — the frozen pane never holds the exit')
given('an enroll whose socket bind faults before ready')
  when('[t3] the enroll throws')
    then('the async mirror is never acquired — the tty is never switched')
```
