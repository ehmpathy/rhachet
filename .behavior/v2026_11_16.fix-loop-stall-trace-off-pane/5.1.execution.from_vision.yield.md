# execution: the clone daemon's trace lines live in its trace log, never in a pane

## .todos

- [x] a daemon sink that writes the trace log only — `src/domain.operations/clone/getOneCloneTraceSinkForDaemon.ts`
  - repo log → fallback per-day log under `CLONE_TRACE_FALLBACK_DIR` (per uid, under the os tmpdir) → dropped and counted
  - the next line the repo log takes is preceded by one gap line: count, cause, fallback path, loss
  - any error an os call returns (a string `code` and a `syscall`, `isCloneTraceHostFault`) falls back; only a code defect is thrown up loud. no allowlist: in the daemon a throw from the sink lands in a timer or an emitter and kills the clone, so no errno a host may return can reach that throw
  - the fallback dir is made owner-only (`0o700`)
  - every line is stamped with its iso time, the daemon pid, and the clone address (`clone=@:<short serial>`, from the pty host); a fallback line also names its repo and the repo log's fault code
  - the repo root is `stat`ed per line, so a removed worktree takes the fallback and is never recreated
- [x] the loop watch's liveness line goes through the same sink (`genCloneSocketServer`), stamped like the stall lines it vouches for
- [x] a wedged `clone say` hint names the daemon trace log and its fallback dir — `computeCloneUnreachableHint.ts`
- [x] every daemon part defaults to it, through one owner, `getOneCloneTraceSinkForDaemonAtCwd`
  - `genCloneSocketServer` — `options.trace` default; it threads `trace` into its `genCloneWriteQueue`
  - `genCloneWriteQueue` — `context.trace` default (was `input.traceToStderr`; moved to `context` like its peers, renamed since it must never carry stderr)
  - `genCloneScreenFeed` — `context.trace` default (same rename)
  - `genBrainCliPtyClone` — `context.trace` default; builds ONE instance and passes it to the screen feed and the socket server, so all three share one gap record
- [x] the stall line names its class: `clone daemon event loop stalled <N>ms (cpu <C>ms, loop active <A>ms)` — `genCloneLoopLagWatch.ts`
  - active ≈ drift, cpu ≈ drift → the daemon's own sync work
  - active ≈ drift, cpu ≪ drift → a blocked sync call
  - active ≪ drift → the host starved the loop
- [x] `getCloneTraceSink` (the tee to stderr) is now client-side only, and its docblock says it must never serve the daemon; stale `'inherit'` claims fixed in `getCloneTraceLogPath`, `writeCloneTraceLine`, and the liveness note in `genCloneSocketServer`
- [x] hot-path audit for sync calls on the daemon's loop (grep `Sync\(` over `src/domain.operations/clone`), each one that can hold the loop for a stall-scale span cured
  - bind and close: `unlinkSync`, `chmodSync` — once per lifetime, not a stall source
  - the trace sink's `mkdirSync` + `appendFileSync` — per trace line, which fires on a fault or a stall only; this change removes the tty write that used to ride beside it
  - 🔴 the mirror's `process.stdout.write` to the tty — per chunk, sync on linux. **measured**: behind a pane reader held still for 3000ms, the host loop ran 2783ms late. **cured** in `genPtyCloneHostFromProcess.ts`: a new host member `enterAsyncMirror` makes the stdout tty handle async once the ready gate passes and every other host wire is set, so a chunk the pane cannot take yet queues in order and the loop turns on; its release runs last in teardown, after the socket is closed and unlinked, and drains the queue before the clone's exit is reported, bounded at 2000ms so a frozen pane never holds the exit, then makes the handle sync again. an enroll that faults before ready never acquires it (F5 holds the memory tradeoff)

## .fulcrums settled in execution

- F1 (where a line goes when the log cannot be written) — built as best-guessed: fallback log, then a counted loss, named on recovery
- F2 (thread a daemon sink vs change the shared default) — both: each daemon part's default is the daemon sink, and the pty host threads one instance; the client tee is unchanged
- F3 (the stall class measure) — process cpu plus `eventLoopUtilization` loop active, both on the line, with the three-way read in the watch's docblock
- F4 (the worktree's declapract husky upgrade) — out of this change; not authored here, and not staged with this change's commit. its `rhachet-roles-ehmpathy` bump also moves three `rhx init` acceptance snapshots (case5); those are not this change's
- F5 (the async mirror trades a bounded heap for a live loop) — a frozen pane queues in memory; a sync write was the measured stall
