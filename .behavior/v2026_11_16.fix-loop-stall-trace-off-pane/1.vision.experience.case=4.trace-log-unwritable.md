# experience case=4: the trace log cannot be written

feel × care = sharp × critipath. the edge where "never the pane" meets "never a failhide".

## .narrative — the operator's pov

the repo's `.agent/.cache/` is read-only on this host (a bad mount, a disk full). the daemon
stalls. before, the stall line hit stderr (the pane) and then a second line,
`clone trace could not reach its durable log: EACCES …`, hit the pane too. now the pane stays clean
and both lines land in a fallback per-day log under the os tmpdir (fulcrum F1, best guess).

once the repo log takes a write again, its first line names the gap and where it went:

```
clone trace log was unwritable for 4 lines (EACCES); they are in /tmp/rhachet/clone-trace/daemon.2026-11-16.log
```

so the operator who reads the repo log meets the pointer in the place they already look, and needs
no docblock to find the fallback.

fails safe: the line is not lost, and not in the pane. if the fallback write ALSO fails, the line
is dropped and the drop is counted; the same recovery line then says
`… 4 lines lost, the fallback was unwritable too (ENOSPC)`, so a silent gap still names itself.

## .bdd sketch

```
given('[case4] a daemon sink whose repo log path is unwritable — on either host mode')
  when('[t0] a traced line (stall, liveness, or fault) is written')
    then('it lands in the fallback log, with a note that the repo log was unwritable and why')
    then('the host stderr receives zero bytes')
  when('[t0.1] the repo log becomes writable again, and the next line is traced')
    then('the repo log first names the gap: how many lines, the cause, and the fallback path')
  when('[t1] both the repo log and the fallback are unwritable, then the repo log recovers')
    then('the next good write names how many lines were lost')
    then('the host stderr receives zero bytes throughout')
  when('[t2] the sink throws a non-io error (a code defect)')
    then('it is thrown up loud, as getOneCloneTraceSinkToLog does today')
```
