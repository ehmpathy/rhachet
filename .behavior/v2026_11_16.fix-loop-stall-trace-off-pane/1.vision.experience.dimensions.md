# experience dimensions: daemon trace lines vs the pane

## .the input axes

each is orthogonal to the others: a value on one never fixes a value on another.

| dim | name | positions |
|---|---|---|
| H | host mode — where the daemon's stdio points | `attended` (stdout + stderr = the pane's tty) · `detached` (stderr = a pipe, unread after handoff) |
| L | traced line class — what the daemon traces while it serves | `stall` (loop-lag drift) · `liveness` (once per lifetime) · `fault` (socket server error, screen feed fault, write queue fault) |
| W | log state — which trace log can take a write | `writable` (the repo log) · `repo-unwritable` (perm, disk full, path fault; the fallback log takes it) · `both-unwritable` (the fallback fails too; the line is dropped and counted) |

## .what is NOT an axis, and why

- **the reader** (pane-human, pane-scrape, log-reader) is DERIVED: the sink decides who can meet a
  line. it appears below as an outcome column, never as an input
- **traced vs thrown** splits the space before these axes apply. an enroll fault (bind refused,
  pty refused) is THROWN to the enroller before the daemon serves; the thrown error's reader is
  fixed, so it is walked as its own small space below. a bind fault ALSO traces one line
  (`clone socket ready rejected with …`) as it throws: that line is a traced `fault`, so it lands
  by the L=fault rows (5, 6, 15 attended; 11, 12, 18 detached), W applies to it, and no pane meets
  it. a pty refusal throws before the sink exists and traces none
- **client probe faults** (`getCloneInputStateOrBlind`, `writeCloneSayDebugLog`) run in the
  `clone say` / `clone get` client processes, not the daemon. they are out of this behavior's
  scope (yield Q3), so they are no value on L

H × L × W = 2 × 3 × 3 = 18 cells. the contract makes H irrelevant to where a traced line goes; H
matters only to who COULD have met it before the cure (a pane exists on attended alone).

| 5 | attended | fault | writable | repo log | log-reader |

## .the walked product — thrown enroll faults

H × cause = 2 × 2 = 4 cells.

| # | H | cause | where it lands | who meets it |
|---|---|---|---|---|
| 19 | attended | socket bind refused | the enroller's terminal, as a qualified error with a hint; its `ready rejected` trace twin lands in the repo log (cell 5) | the human who ran the enroll; the log-reader, for the twin |
| 20 | attended | pty unavailable — the addon absent, the libc unsupported or unreadable, the device refused | same | same |
| 21 | detached | socket bind refused | the enroller's terminal, via the pre-handoff stderr forward (`genCloneEnrollDetached.ts:196`); its trace twin lands by cell 11 | same |
| 22 | detached | pty unavailable | same | same |

the pty causes share one cell: each is refused before the pty spawns, by one throw path, with one
frame per cause. the suite proves each frame (`enroll.reach` [case4]–[case7]); the trace-off-pane
invariant is the same for all, so one cell holds them.

## .the walked product — the pane mirror

the daemon-owned part of the stall: the mirror copies the brain-cli's screen to the pane, and a
sync tty write held the event loop behind a pane that did not drain. it is a third space, apart
from the trace sink: its bytes are the brain-cli's screen, which the pane is MEANT to show.

| dim | name | positions |
|---|---|---|
| R | pane reader state | `live` (drains as fast as it is fed) · `still` (drains late — a paused, scrolled, or starved terminal) · `frozen` (never drains) |
| M | mirror moment | `steady` (while the clone serves) · `exit` (the last frames, before exit is reported) |
| E | enroll outcome | `ready` (the mirror is acquired) · `failed before ready` (the enroll throws) |

H × R × M on a ready enroll, plus the failed enroll, plus the detached host:

| # | H | R | M / E | what the human sees | the daemon loop |
|---|---|---|---|---|---|
| 23 | attended | live | steady | every brain-cli byte, in order | on time |
| 24 | attended | still | steady | every byte, in order, once the reader drains | on time — the write never blocks it |
| 25 | attended | still | exit | every chunk, in order, the last before exit is reported | on time |
| 26 | attended | frozen | exit | what the pane took before it froze | the flush settles at its bound; exit is not held |
| 27 | attended | any | failed before ready | the thrown frame alone; the tty is never switched | n/a — the mirror is never acquired |
| 28 | attended | frozen | steady | naught new | on time; the bytes queue in memory (F5) |
| 29 | detached | — | — | no pane | no mirror to the tty |
