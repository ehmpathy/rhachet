## .the narrative

a human works in a tmux pane that a clone once opened, so the pane's env still carries
`RHACHET_CLONE_DEPTH=0` — or `1`, from a reviewer's shell. they type
`rhx enroll claude --roles mechanic`. today the enroll reads the inherited var and mints the clone
at depth 1 (or refuses it outright at depth 2). the human drives a route with it. at the first
guarded stone, `route.stone.set --as arrived` runs the guard's `rhx enroll claude -p '…'`. that
enroll reads depth 1 → child depth 2 → refused:

```
✋ ConstraintError: clone enroll depth budget spent
  depthRequested: 2
  depthMax: 1
```

the guard gets no verdict; the stone stalls. reproduced 2026-10-07 with
`RHACHET_CLONE_DEPTH=1 rhx enroll claude --roles -driver -p '…'`.

after, as ruled (S1): the enroll sees an interactive tty on stdin. a tty is a human at a keyboard;
a brain's tool shell never has one. so the clone is minted at depth 0, whatever depth var the pane
inherited, and its guard's reviewers are minted at depth 1 — allowed.

## 🔴 .amended by F13 — for the wisher

execution found that a clone can open a fresh pty (`tmux new-window`, `unbuffer`, a node-pty
spawn), so "a tty is a human" holds only where the caller cannot open one. the best-guess taken
(F13, candidate (i)) narrows the rule above: **a tty mints depth 0 only when its env holds no depth
var.** a tty that carries one reads that var + 1, as a no-tty spawn does.

the cost lands on this very case: a human in a pane that inherited `RHACHET_CLONE_DEPTH=0` now mints
the clone at depth 1, and its guard's reviewers are refused, which is the reported block. the
refusal hint sends them to a fresh terminal, where no var is inherited and the clone is top-level.
the wish's "never reset to 0 on the way down" argues for (i); S1 argues against it. one line reverts
it, and its clamps flip with it (F13 `.the best-guess on the hole`).
