# 1.vision.experience.dimensions

## .the dimensions

the experience space of "who may spawn a clone" factors into three orthogonal axes. the outcome
of each cell is derived from its coordinates, so it is a column of the inventory, not an axis.

### D1 — the caller's place in the chain (what the caller's env and stdin say)

the rule, per the ehmpathy/rhachet#577 vision: **a leaf may not spawn; every other caller may.**
depth is a fact: **an enroll at a tty with no parseable depth var is top-level; every other spawn
is caller depth + 1**, where a no-tty caller with no var or an unparseable var counts as depth 0.
a tty with a var reads that var + 1, because a clone can open a fresh pty (F13).

| value | signal | who | today a spawn reads as | after the fix |
|---|---|---|---|---|
| `tty-clean` | stdin is a tty, no `RHACHET_CLONE_DEPTH` | a human at a plain terminal or pane — the wisher's daily path (Q7a, measured) | depth 0 | enroll → depth 0 · repl → brain at depth 1, a leaf |
| `tty-inherited` | stdin is a tty, `RHACHET_CLONE_DEPTH` set | a human at a pane split from inside a clone, or a fresh pty a clone opened | the inherited depth + 1; refused at var 1 🔴 | the inherited depth + 1 at both doors, never refused |
| `notty-unmarked` | no tty, no var | the tool shell of a raw `claude` opened in a clean pane; a cron job | depth 0 🔴 | depth 1 |
| `raw-claude-inherited` | no tty, var set by the pane | the tool shell of a raw `claude` opened in an inherited pane | the inherited depth + 1 🔴 (refused at var 1) | the inherited depth + 1, never refused |
| `depth0` | no tty, `RHACHET_CLONE_DEPTH=0` | an enrolled top-level clone's tool shell (its guard, its own Bash) | enroll → depth 1 · repl → brain carries depth 0 🔴 | depth 1 at both doors |
| `depth1 (work)` | no tty, `RHACHET_CLONE_DEPTH=1`, no leaf mark | a worker a depth-0 clone enrolled in session mode | depth 2 → enroll refused 🔴, repl allowed unmarked | depth 2 at both doors — **allowed** (#577) |
| `leaf` | `RHACHET_CLONE_LEAF` set, any depth, any tty | a `-p` reviewer, a repl brain, or a shell or job one started | refused only where its depth read ≥ 1 🔴 | **refused** at both doors |
| `smudged` | no tty, var set but not a non-negative integer | a corrupted env | depth 0 🔴 | depth 1 |

the set is closed: a caller that carries the leaf mark is `leaf`, whatever else holds. all others
split as before: a tty is `tty-clean` or `tty-inherited` by whether the var is set; no tty is split
by the var: absent (`notty-unmarked`), set by a pane (`raw-claude-inherited`), a non-negative
integer (`depth0`, `depth1 (work)` — a depth ≥ 2 reads as `depth1 (work)` does, allowed), or not
an integer (`smudged`).

🟡 `raw-claude-inherited` differs from `depth0` only in the depth it records: depth refuses no one.

### D2 — the spawn path

| value | entry | spawns a brain process? | budget checked today? |
|---|---|---|---|
| `enroll.watch` | `rhx enroll claude` (attended) | yes, pty or plain | ✅ |
| `enroll.async` | `rhx enroll claude --async` (detached host re-exec) | yes | ✅ (env replayed whole) |
| `enroll.await` | `rhx enroll claude -p '…'` (the guard peer-review shape) | yes | ✅ |
| `repl` | any call that hands a repl brain its `ask`/`act`: `genContextBrain` → `brain.repl.ask/act` (e.g. `rhx review --brain claude/code`), and the actor ops `actorAsk`/`actorAct` behind `rhx ask`, `rhx act` and `clone.ask/act` | yes — the supplier spawns `claude` via claude-agent-sdk with `process.env` | 🔴 **no** |
| `atom` | `genContextBrain` → `brain.atom.ask` | no — one api request, no tools, no process | n/a |

### D3 — concurrency within one caller process

| value | what |
|---|---|
| `solo` | one spawn in flight from the caller process |
| `concurrent` | two or more spawns in flight from one caller process (e.g. `rhx review` runs rubrics in parallel) |

this axis matters only where the fix touches shared state. enroll spawns build each child's env
as its own object, so concurrent enrolls never share a scope. the repl door scopes the caller's
`process.env` (F2), which every concurrent call shares. so the caller depth is held by the scope,
and a call that returns first must not restore the env while another is still mid-spawn.

## .the walked product

8 × 5 × 2 = 80 cells. every cell is verdicted in `1.vision.experience.case=_.md` — the solo
plane row by row, the concurrent plane as a matrix.

## .why these three and no more

- **brain kind** (claude vs another cli) is folded in on one premise: its shell tool hands its
  commands no tty. measured for claude only. a CLI whose shell tool allocates a pty would read its
  depth-1 clone as a tty caller and mint depth 0 on enroll — Q10 measures each before the seam
  relies on it.
- **slug reuse** (`--as @:x` on a live clone) spawns no brain. the leaf check runs before the
  reuse check, so a leaf caller is refused even a reuse. that order is kept: it is the stricter
  read, and no cell needs it relaxed.
- **a `!rhx enroll` typed into a clone session** has no tty, so it reads as that clone's own
  call — one value with the brain's own call, one verdict. the wisher settled this (S1): no tty
  is one level down.
- **a human pipe into `rhx enroll`** (`echo … | rhx enroll`) has no tty, so it is
  `notty-unmarked` — depth 1, a work clone. no separate value: same signal, same verdict. this
  holds for the sanctioned `--reason @stdin` channel too.
- **the roleset** is no axis: the ambient actor carries `reviewer`, so a role read would mark
  every everyday `claude` a leaf. only the door marks a leaf (F23).
