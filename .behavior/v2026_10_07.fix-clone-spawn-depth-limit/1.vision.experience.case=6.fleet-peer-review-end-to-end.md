# case=6 — a fleet peer review, end to end

**cells walked:** tty-clean × enroll.watch → depth0 × enroll.watch → depth1 (work) × enroll.await →
leaf × repl → refused
**feel × care:** 😊 for the driver and its worker, 🗡️ for the reviewer · 🔴 critipath — the densest
walk, and the one that stalled the fleet

## .the narrative

a human, at a fresh terminal, runs `rhx enroll claude --roles mechanic,driver` and asks it to drive
a route. the driver enrolls a storefront worker in session mode to drive one stone. the worker
arrives at `5.1.execution`. its guard runs
`rhx enroll claude --roles reviewer,behaver,architect,mechanic -p '<review the diff>'`.

**the two blocks this walk answers:**
- a reviewer could run `rhx review`, which walked the repl door unchecked and started one brain
  per rubric, so the guard's `-p` stalled
- on main, the worker at depth 1 can enroll no reviewer at all, so its stones stall — the
  storefronts and gads L10 gate

**the walk:**

1. the human's enroll sees a tty with no depth var → the driver is depth 0 (case=4)
2. the driver's session enroll has no tty → the worker is depth 1, no leaf mark
3. the worker's guard runs `-p` → admitted (#577) → the reviewer is depth 2, a leaf (case=1)
4. the reviewer runs `rhx review`. the repl seam reads the leaf mark → refused, before the
   supplier is called (case=2):
   ```
   ✋ ConstraintError: a reviewer clone may not spawn
     via:  a repl brain (`rhx review`, `rhachet ask`, `rhachet act`)
   ```
5. the reviewer reads one line, reviews the diff itself, prints its verdict
6. the guard's `-p` returns inside one brain's time. the worker reads the verdict and moves on

four boundaries in one walk — human/clone (the tty read), a work enroll, a reviewer enroll (the
leaf mark), repl (the check) — every work spawn is allowed, and the refusal lands only at the leaf.
