# handoff: rhachet split layout leaves a plain claude session without the ambient settings

## .what

on rhachet's split layout, a claude session that rhachet did not spawn — a plain `claude` at the
repo root, no enroll — loads none of the repo actor's allows or hooks. the ambient roles reach
only an enrolled brain.

the expected fix: rhachet links the repo actor's `settings.local.json` to `settings.of.repo.json`,
so a plain session loads the ambient settings through claude's local layer.

## .owner

rhachet (`ehmpathy/rhachet`), the layout op `setBrainDirSettingsLayout`. nheuron holds a
hand-made stopgap link (see `.stopgap`).

## .why it happens

the split layout of the repo actor brain dir (`<repo>/.claude` links to it), as rhachet 1.49.2
builds it:

```
settings.of.repo.json                        a real file: the repo's allows + hooks
settings.json -> settings.of.grove.json -> ~/.claude/settings.json
(no settings.local.json)
```

each launch loads a different set:

| launch | claude loads | gets the ambient settings? |
|--------|--------------|----------------------------|
| enrolled (`rhx enroll`) | `--setting-sources user --settings <brain dir>/settings.of.repo.json` | yes, via `--settings` |
| plain `claude` at repo root | user `~/.claude/settings.json` + project `<repo>/.claude/settings.json` (→ home) + local `<repo>/.claude/settings.local.json` | **no** — project leads to home, local is absent |

`--settings` is the only door to `settings.of.repo.json`, and only rhachet's spawn opens it
(`domain.operations/enroll/asBrainCliSpawnArgs.js`).

## .evidence

- `setBrainDirSettingsLayout.js` findserts `settings.of.repo.json` and the two grove arrows; no
  line names `settings.local.json`
- `setRepoActorBrainDir.js` re-includes `!/settings.local.json` in the brain dir `.gitignore`,
  so git would track one — yet no op creates it
- nheuron's permission hooks (`permissions.layers.operations.sh`) already read the split layout
  as `settings.of.repo.json` + the user file, for a plain session too (no `$CLAUDE_CONFIG_DIR`,
  config dir = `<repo>/.claude`). without the link, the hooks judge against an allowlist that
  claude never loaded

## .the fix

in `setBrainDirSettingsLayout`, for the **repo actor's** brain dir only, findsert one more arrow:

```
settings.local.json -> settings.of.repo.json   (relative)
```

then a plain session loads: user (home) + project (→ home, deduped) + local (→ repo), which is
exactly the set an enrolled brain loads, and exactly the set the hooks read.

scope it to the repo actor. a clone's brain dir is never a cwd, so claude never resolves its local
layer, and an arrow there would be dead weight.

## .caveats to settle

- **"always allow" writes** — claude saves a session's "always allow" grant to the local layer.
  through the arrow, that grant lands in the tracked `settings.of.repo.json`, and so in a commit.
  rhachet must decide: accept it (the grant is the repo's), or have a role init re-derive the
  allowlist and drop strays (the mechanic init already rewrites the allowlist with a backup)
- **a real file in the way** — a repo that kept a real `settings.local.json` from the old layout
  holds human grants. replace it as the grove arrows replace a real file, or merge its allows into
  `settings.of.repo.json` first. a silent replace drops them
- **no grove** — the arrow targets `settings.of.repo.json`, which is always findserted, so a box
  with no home settings needs no special case

## .stopgap

nheuron holds the arrow by hand, made via:

```sh
rhx symlink --at .agent/.actors/actor.via.repo=ambient/brain/.claude/settings.local.json \
            --to .agent/.actors/actor.via.repo=ambient/brain/.claude/settings.of.repo.json \
            --mode relative --idem findsert
```

rhachet 1.49.2 does not touch `settings.local.json`, so the arrow survives `rhx upgrade` and
`rhx init --hooks`. delete it once rhachet ships the arrow, or leave it: a findsert would meet it
in place.

## .validation

1. in a repo on the split layout, run `rhx upgrade`
2. confirm `.claude/settings.local.json` is a link to `settings.of.repo.json`
3. start a plain `claude` at the repo root, with no `$CLAUDE_CONFIG_DIR`
4. confirm a repo-only allow runs with no prompt, and a repo-only hook fires (e.g. the mechanic
   SessionStart permissions notice)

## .related gap — the PermissionRequest hook

rhachet's role hooks have no PermissionRequest event, so nheuron registers
`permissionrequest.decide-permissions.sh` by hand in `settings.of.repo.json`. the migration from
the old layout dropped that entry (restored by hand). rhachet keeps it through `rhx init --hooks`,
but a fresh layout never writes it, and other repos that use the mechanic role never get it. a
`hooks.onBrain.onPermission` (or similar) role hook type would close the gap.

## .priority

medium — an enrolled brain works; only a plain session loses the ambient roles' allows and hooks.
the hooks then nudge toward an allowlist that claude does not hold, so the human sees prompts the
repo meant to pre-approve.
