# fix(init): link settings.local.json to the repo settings so a plain claude loads the ambient roles

## .what

on the split layout, a plain `claude` at the repo root loaded none of the repo actor's allows or hooks: `settings.json` led to the grove, and no `settings.local.json` existed. now every actor brain dir holds:

```
settings.local.json  -> settings.of.repo.json           # the repo outranks the grove, for a plain claude too
settings.json        -> settings.of.grove.json -> .home/.claude/settings.json -> ~/.claude/settings.json
```

- a real `settings.local.json` (or `settings.json`) is replaced by the arrow and the replace is reported, never merged or kept aside (`inventory.of=requirements.case=7`, `case=10`)
- tracked settings carry no machine path: the grove arrow goes through an untracked `.home` mirror, and `trackedBrainDirSettingsArePortable.integration.test.ts` fails on any absolute arrow or home path in tracked settings
- `claudeMdExcludes` keep the home `CLAUDE.md` and `CLAUDE.local.md` out of a repo session (`case=11`)
- `rhx init --roles …` and `rhx upgrade` land the layout before the role inits run (`case=8`)

route: `.behavior/v2026_10_15.fix-split-layout-local-settings-arrow/`. proofs: `5.3.verification.yield.md`.

### F11 — the home `CLAUDE.md` exclude covers four home roots, not every home

portable globs cover `/home/<u>`, `/Users/<u>`, `/root`, `/github/home`. a custom home (e.g. `/srv/<u>`) would load its `~/.claude/CLAUDE.md` in the repo with no notice. the exact `$HOME` path would close that, but it would put a machine path into the tracked `settings.of.repo.json`, which S6 forbids. so S5 ("always exclude the home CLAUDE.md") and S6 collide only on a home outside the covered roots. a third way, not built: write the absolute path to an untracked file the clone also reads.

→ accept the four roots, or build the untracked-file third way?
