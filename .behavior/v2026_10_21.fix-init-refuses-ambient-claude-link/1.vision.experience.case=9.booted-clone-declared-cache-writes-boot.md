# case 9 — a booted clone with the declared cache writes boot.md and releases its lock (happy × criti)

## .narrative

i am a booted clone. my SessionStart hook runs the tree's own rhx (`./node_modules/.bin/rhx`), so
`simple-on-disk-cache` resolves to the copy rhachet declares (`1.8.1`, with `version()`). the boot
write takes the repo mutex, writes boot.md, and releases the lock. i never see the mutex at all.

the new cache guard (case 5) sits on this same path. this case is what proves it is silent when the
cache is right: a guard that refused the declared copy would break every boot.

## .timeline

```
given('[case9] a mutex cache with version() — the declared simple-on-disk-cache')
  when('[t0] withRepoMutex runs a section')
    then('the cache guard passes, silent')
    then('the section runs once, and its result returns')
    then('the lock is released; a second section can take it')
  when('[t1] two sections race on one lock key')
    then('they run one after the other, never at once')
```

[t0] and [t1] without the guard are extant in `src/infra/lock/withRepoMutex.integration.test.ts`.
the guard's silence on the declared copy is the new assertion this pr owes there.

## .fail-safe

happy path; its fail-safe is case 5.
