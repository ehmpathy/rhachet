# 5.3.verification — handoff v1 to the foreman

## .the ask

```sh
rhx keyrack unlock --owner ehmpath --env test
```

at a terminal with a browser: the `ehmpathy.test.AWS_PROFILE` key needs an aws sso login, which only a
human can complete. once it lands, the driver resumes on its own; no other ask.

## .what is blocked

every test tier that `rhx git.repo.test` gates on keyrack — integration and acceptance — refuses to
start:

```
✋ keyrack unlock
   └─ aws sso login timed out
      ├─ status: blocked 🚫
      │  └─ human did not respond to browser sso prompt
      ├─ robot: halt and escalate
```

## .what was tried

1. a scoped acceptance run (`--scope 'path://blackbox/cli/init.preflight'`) — refused, as above
2. a scoped integration run (the four openai suites, for the F14 revert) — refused, as above
3. `rhx keyrack status --owner ehmpath --env test` — the daemon lists `AWS_PROFILE` with 37m left, yet
   the unlock the test tool runs finds no prior sso session (`✗ clear, no prior session`) and asks for a
   browser login; the daemon entry is a stale cache, not a live session
4. a retry of (1) — refused identically, so the timeout is not transient
5. no workaround: keyrack forbids one (`do not find workarounds · do not skip credentials`), and an
   unlocked subset would be a credential bypass the stone forbids

## .why it is foreman-only

an aws sso device login opens a browser and needs the human's identity provider. no driver lever
completes it.
