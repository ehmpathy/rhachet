# 1.vision — init boots any tree, or refuses before it writes

> **a fresh tree boots a crew — on a laptop, on the cloud grove, and in a director tree whose link lands
> on its own repo actor brain dir (the acceleration layout). where `rhx init` cannot finish, it stops before any role init, or it
> leaves the settings true to the roles it did link, and it names the one fix.**

scope: the wish (a director tree's `.claude` refused · a mutex fault in the same function · global rhx
skew) plus `ehmpathy/rhachet#657` (a fresh cloud tree cannot boot a crew). one pr, `closes #657`
(seed S1).

---

## .the outcome world

### before

a commander opens a fresh rhachet tree on the cloud grove. `pnpm install` runs `prepare:rhachet`, i.e.
`rhachet init --keys --hooks --roles mechanic behaver driver …`. mechanic is first:

```
📚 link role repo=ehmpathy/role=mechanic
🔧 init claude config for mechanic role...
cp: cannot create regular file '.claude/settings.<ts>.bak.json': Permission denied
❌ init.claude.permissions.sh failed at line 99
❌ init.claude.sh failed at line 39
```

the install fails. then `rhx enroll claude --as @:mechanic` refuses:

```
a clone would load hooks from roles it is not enrolled in
   (driver · behaver · learner · dispatcher)
```

no rerun converges. no fresh tree boots on cloud, and the commander p0 waits behind it.

on a laptop, a director tree meets a different wall in the same function:

```
✋ ConstraintError: <repo>/.claude is a symlink to another place
```

and a peer tree dies one line later, on that function's mutex:

```
💥 MalfunctionError: withSimpleMutex: the cache backend faulted while it read the lock version on acquire
```

three trees, three walls, one step of init — and no message names its cause.

### after

the same fresh cloud tree boots:

```
📚 link role repo=ehmpathy/role=mechanic
🔐 mechanic permissions configured successfully!
   .claude/settings.of.repo.json
…
✨ hooks
   └─ synced
```

`rhx enroll claude --as @:mechanic` bakes a clone. the crew boots, and the grove's
`~/.claude/settings.json` is neither read for a backup nor replaced.

where the brain dir cannot be written, init stops at the door — before any role links or inits:

```
✋ ConstraintError: the repo actor brain dir is not writable
   ├─ path = .agent/.actors/actor.via.repo=ambient/brain/.claude
   ├─ probe = settings.of.repo.json (EACCES)
   └─ hint = grant write to this dir, then rerun `rhx init --roles …`. no role init ran
```

where one role's init fails part way, init still syncs the hooks to the roles it did link, then fails
loud:

```
💥 MalfunctionError: init command failed for repo=ehmpathy/role=mechanic (exit code 1)
   ├─ linked = mechanic
   ├─ not linked = behaver · driver · … (13)
   ├─ hooks = synced to the linked roles; none of the 13 remain in settings.of.repo.json
   └─ hint = fix the cause above, then rerun the same `rhx init --roles …`
```

enroll then meets no hook of a role it lacks, and the rerun converges.

where the mutex cache is the wrong copy, the fault names the copy:

```
💥 MalfunctionError: the repo mutex cache lacks version()
   ├─ module = /…/node_modules/.pnpm/simple-on-disk-cache@1.7.10/…/index.js
   ├─ version = 1.7.10, wanted >= 1.8.1
   └─ hint = this rhx resolved a foreign simple-on-disk-cache; run the tree's own rhx (npx rhx)
```

### the aha

> **init either boots the crew, or it stops and leaves a tree a rerun can fix.** no one hand-cleans a
> settings file, and no one reads a stack to learn which file was at fault.

## .the causes — what each wall is

| # | wall | cause | verdict |
|---|---|---|---|
| 1 | cloud: mechanic init `cp … Permission denied` | **proven** by a hermetic repro. at `rhachet-roles-ehmpathy@1.39.3` (main's pin), `init.claude.sh:35` copies `.claude/settings.json` — a link to the grove's `~/.claude/settings.json` — to `.claude/settings.<second>.bak.json`; `cp` copies the source mode, so a read-only grove file yields a read-only backup. `init.claude.permissions.sh:99` then copies to the **same name** in the same second → EACCES; the parent trap reports line 39. with the grove file at 0644 the run passes — and its `mv` (`:102`) then replaces the `settings.json` grove arrow with a real file. `1.39.4` still faults; `1.39.5` cures it (no `cp` in `init.claude.sh`, writes `settings.of.repo.json` by name, never through the link) | cure = pin `rhachet-roles-ehmpathy` to `>= 1.39.5`; `1.39.7` is already staged in this tree |
| 2 | cloud: enroll refuses on driver/behaver/learner/dispatcher hooks | the run need not have written those hooks: the repo actor's `settings.of.repo.json` is **tracked** on main (`git ls-tree origin/main .agent/.actors`), and main's copy already holds driver, behaver, learner and dispatcher hooks, so a fresh clone carries them before any init. the director's report reads them as written by the run; either way the tree reaches one state, and the cure is the same. a role links just before its init runs (`getRolesLinkedFromFound.ts:31-34`); the mechanic init threw (`execRoleInits.ts:91-92`), init aborted before the hook sync (`invokeInit.ts:218-227`), so only mechanic was linked while the file still held the hooks of four roles with hooks. enroll's guard refuses exactly that (`assertCloneSettingsLayersHoldOnlyEnrolledRoles.ts:59-69`) | inferred from code; consistent with the four names reported. clamp below (case=11) |
| 3 | no preflight | the layout step before the inits catches every classed fault and returns `null` (`setRepoActorBrainDirLayout.ts:63-72`); the role inits run anyway, and no step probes write access | clamp below (case=10) |
| 4 | director tree: `<repo>/.claude is a symlink to another place` | **unproven.** the acceleration tree's chain, read by its director (seed S2), is a relative link inside the tree over real dirs — the layout init already accepts (case 6). its route holds no record of the refusal, so the tree that refused is unknown | no fix for an unseen layout. the refusal stays, and prints both realpaths, so the next refusal diagnoses itself (case 4) |
| 5 | mutex: `the cache backend faulted while it read the lock version` | acceleration proved the fault comes from a `simple-on-disk-cache` with no `version()` (1.7.10). rhachet declares `1.8.1` in `dependencies`, and 1.8.1 returns `version` as an own property, so the `{ ...cache, set }` spread at `withRepoMutex.ts:157` keeps it. how 1.7.10 reached the import is open: 1.7.10 sits in this tree (`with-simple-mutex@0.1.1 → with-simple-cache@0.17.0 → 1.7.10`, and `rhachet-roles-ehmpathy@1.39.7`), and the global rhx shim adds pnpm's global hoist to `NODE_PATH` | rhachet side: a guard in `withRepoMutex` that refuses a cache with no `version()` and names the resolved copy. the path hunt stays with acceleration |
| 6 | global rhx skew | the global `rhx` on this box is `1.50.1` (`~/.local/share/pnpm/rhx`), not the pin. `prepare:rhachet` runs `rhachet` from `node_modules/.bin` (the pin). this repo's hooks run `./node_modules/.bin/rhx` (the pin). a tree whose hooks or human call bare `rhx` runs the global | named. whether to refuse a global rhx that differs from the pin is a behavior change → the commander |

## .mental model

- **to a friend:** *"init used to half-boot a tree and jam it. now it boots the crew, or stops at the
  door, or tidies up to what it did manage, and tells you the one fix."*
- **analogy:** a preflight before takeoff — and if a door fails mid-taxi, the plane rolls back to the
  gate rather than sit on the runway.

| a user says | we say |
|---|---|
| `.claude` | the repo actor's brain dir, reached by the `<repo>/.claude` link |
| "init broke halfway" | a role init failed part way |
| "leftover hooks" | hooks of roles not linked, in `settings.of.repo.json` |
| "the wrong rhx" | a global rhx that differs from the tree's pin |

## .evaluation

| goal | met by |
|---|---|
| a fresh tree boots a crew on cloud | the pin bump (cause 1) + case 3 (cause 2): even where a role init fails, enroll no longer meets a stranger's hook |
| a `.claude` init cannot write fails loud before any hook | case 2 |
| a part-way init leaves no hooks of roles not enrolled | case 3 |
| the director tree's link is accepted, or its layout named | case 6 (a link that lands here is accepted — the acceleration layout, S2) + case 4 (one that does not is refused, both realpaths named). the tree that refused is unknown, so cause 4 ships its diagnosis only |
| the mutex fault named | case 5 — rhachet's half; the path hunt stays with acceleration |
| which rhx each step runs | cause 6 |

**pros:** each clamp is a gate at one step, testable in a temp repo. no new command, no flag.

**cons:** case 3 changes what a failed init leaves behind: today it leaves the file as found; after, it
rewrites the hooks to the linked set. a hand-added hook authored by a role not linked would go — the
same loss a normal `rhx init --hooks` already causes.

**edgecases:**
- an init run without `--hooks` → case 3 touches no hook (init never syncs hooks without it). the enroll
  refusal there still names `rhx init --hooks` as its cure
- the failed role itself is linked (it links before its init). it counts as linked, so its hooks sync
- case 2 probes write by a create-and-remove of a probe file in the dir, plus an open-for-append of
  `settings.of.repo.json`; a probe that cannot clean up fails as a malfunction

## .what is awkward?

- **the director's case 2 clamp does not, by itself, cure the measured cloud run.** the brain dir there
  was writable (the init wrote its temp file in it); the fault was a backup copied from a read-only
  grove file. case 2 would pass that tree. the run is cured by the pin bump plus case 3. named so no one
  reads case 2 as the cloud fix
- **the director's first clause, read literally, already mostly holds.** in a brain dir init cannot
  write, the end-of-run hook sync could not write either, so "fails loud before any hook lands" is
  near-true today. what case 2 adds is the stronger form: the refusal comes before any role links or
  runs, so no role is left half-done and the fault is not deferred to the boot sync
- **a tracked `settings.of.repo.json` is the root of cause 2.** every fresh clone arrives with hooks for
  roles it has not linked. case 3 repairs the failure path; a fresh clone before any init still refuses
  at enroll, by design, with the `rhx init --hooks` hint
- **cause 4 is unproven, and stays so.** the acceleration tree, read at last, has the layout init
  already accepts (case 6), and no record of the refusal survives. the wish's first fault therefore has
  no tree to reproduce it in. this pr ships only the diagnosis for it — both realpaths in the refusal —
  so the next tree that meets it names its own cause (seed S2)
