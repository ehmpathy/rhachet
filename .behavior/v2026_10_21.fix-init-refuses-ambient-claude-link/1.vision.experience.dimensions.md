# 1.vision.experience.dimensions

## .actors — axis 0, by command path

| actor | command path | orthogonal because |
|---|---|---|
| **commander** | install + enroll: `pnpm install` → `prepare:rhachet` → `rhx init --hooks --roles …`, then `rhx enroll claude` | the actor picks which command reaches the gates; every tree state on axes A–I can sit under any of the three |
| **director** | init / upgrade by hand: `rhx init` or `rhx upgrade` | same |
| **booted clone** | a SessionStart hook: `rhx upgrade` / a boot.md write under the repo mutex | same |

the tree kind — fresh, or a director tree whose link another run laid — lives on axis D alone.

## .axes

| axis | positions | the gate it decides | orthogonal because |
|---|---|---|---|
| **A. host** | laptop · cloud grove | none directly — only through G2 | A correlates with G2 in practice (a cloud grove usually ships a read-only grove file) but does not fix it: `cloud × writable` and `laptop × read-only` are both valid, and the catalog walks them as G2 cells |
| **B. brain dir write access** | writable · not writable | the preflight write probe (new) | a filesystem fact, free of the link, the cache and the roles. a brain dir that is absent is not a third position: the layout step `mkdir`s it first (deferred on failure), so the probe always meets one of the two |
| **C. role inits** | none fail · some fail | the failure path of the role loop | a role init fails for its own reasons (G is one of them), free of B once the probe passed. under stop-at-first-failure (today, F5) "some" is exactly one |
| **D. `.claude` link** | absent · lands here, relative (direct or via another path) · lands here, absolute · a real dir · a file · a dangle · aims elsewhere | the preflight link check (F6), then `setRepoBrainDirSymlink` | laid by a prior run; free of write access and of which cache loads. "lands here" means its realpath is the repo actor brain dir; the seven positions are mutually exclusive |
| **E. lock cache** | declared copy (has `version()`) · foreign copy (no `version()`) | `withRepoMutex`, at every caller | E is an outcome of F × H, not a free choice — so its cells are walked through F × H below |
| **F. rhx** | the tree's pin · a global that differs | which rhachet code runs | the binary on `PATH` is chosen by the caller |
| **H. how `simple-on-disk-cache` is found** | rhachet's own dependency · a hoisted or `NODE_PATH` copy (e.g. 1.7.10 via `with-simple-cache`, or pnpm's global hoist that the global rhx shim adds) | which copy `withRepoMutex`'s dynamic `import` loads | a property of the install layout and env, free of which rhx binary the caller typed |
| **G1. roles-ehmpathy pin** | `<= 1.39.4` (main is `1.39.3`; `1.39.4` still faults) · `>= 1.39.5` (this pr) | whether the mechanic init copies through the grove link | a dependency pin |
| **G2. grove settings file** | writable (0644) · read-only (0444) | live only at G1 `<= 1.39.4` | a host fact |
| **G3. time between the two old backups** | same second · across a second boundary | live only at G1 `<= 1.39.4` × G2 read-only | a race inside one peer init |
| **I. concurrency** | alone · two inits at once · an enroll mid-init · a boot write mid-init | which writer or reader meets which state of `settings.of.repo.json` | the clock between processes, free of every tree state |

### I — what serializes what

`withRepoMutex` keys each lock on a path. measured in code:
- the link: `.repo-brain-dir-link` (`setRepoBrainDirSymlink.ts:89`)
- the hook sync's write: the brain dir's `settings.of.repo.json` (`syncHooksForLinkedRoles.ts:329` →
  `withBrainDirSettingsShield.ts:48`)
- enroll's guard **reads** `settings.of.repo.json` with no lock (`assertCloneSettingsLayersHoldOnlyEnrolledRoles.ts:81`)

so two inits serialize their writes; an enroll mid-init reads whichever state the file holds (see the
catalog's I rows).

## .order of the gates — one walk

```
F (which rhx) · H (which cache copy)
 → layout step: mkdir the brain dir · the link set · the settings findsert, under their locks
      — a classed fault here is DEFERRED (setRepoActorBrainDirLayout.ts:63-72), never thrown
 → preflight (new): B write probe (case 2) · D link check (case 4, F6)   — refuses before any role links
 → C role loop (link, then init, per role)
      ├─ some fail → hook sync to the linked roles (only with --hooks), then fail loud (case 3).
      │              the boot sync is skipped, as today: init aborts at the failed role
      └─ none fail → boot sync: re-runs the layout step — a deferred E fault surfaces HERE (case 5)
                   → hook sync (only with --hooks)
 → enroll
```

a walk stops at the first gate that refuses, so a cell with two refusals takes the earlier gate's
experience. under F6 the only fault still deferred past the role loop is E; a C failure skips the boot
sync, so a deferred E fault waits for the rerun.
