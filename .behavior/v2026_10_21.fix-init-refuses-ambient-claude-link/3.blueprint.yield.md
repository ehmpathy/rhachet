## .codepath tree

### P1 — the write probe (case 2)

```
assertRepoActorBrainDirWritable({ repoActorBrainDir })
  ├─ write   <brainDir>/.rhachet.write-probe.<pid>      flag 'wx'
  ├─ unlink  the same
  ├─ EACCES | EPERM | EROFS → ConstraintError '<brain dir> is not writable'
  │    { path, owner = stat.uid, mode = stat.mode octal, hint = 'grant write to <path>, then rerun `rhx init`' }
  └─ any other errno → rethrow (failfast; never read as "not writable")
```

- runs only under `--roles` (the role inits are what write there)
- the probe touches `<brainDir>` itself, which each role init writes through `<repo>/.claude`
  (cause 1)

### P2 — the link check (case 4, F6; case 6 kept)

```
assertRepoBrainDirSymlinkLandsHere({ repoPath, repoActorBrainDir })
  ├─ lstat <repo>/.claude
  │  ├─ absent | real dir | the legacy link → return (the layout step owns these)
  │  ├─ a file → ConstraintError (extant text, moved here)
  │  └─ a symlink
  │     ├─ realpath(link) === realpath(brainDir) → return          (case 6: relative, absolute, via a hop)
  │     └─ else → ConstraintError '<repo>/.claude is a symlink to another place'
  │          { path, aimed = readlink, realpathFound (or 'dangles'), realpathWanted, hint }
setRepoBrainDirSymlinkWithinLock → calls the same check at its refusal site, so one text, one rule
```

- read-only and lock-free: a read of one link never races a write it would refuse
- the preflight runs it after the layout step, so a link the layout step could not fix (deferred) is
  refused here, before any role writes through it (F6)

### P3 — the part-way init (case 3, F1, F2, F5)

```
invokeInit
  └─ role loop throws (absolute or incremental)
     ├─ if --hooks: syncHooksForLinkedRoles({ brains })      prunes to the roles linked on disk
     └─ rethrow asRolesPartWayFaultError({ error, specifiers, linked = read from .agent/repo=* })
          ConstraintError | MalfunctionError, by the cause's own class
          { failed = repo=…/role=…, linked = [...], notLinked = [...], hint = 'fix the failed init, then rerun the same command' }
```

- F5: the loop still stops at the first failed role (extant)
- F1: the failed role keeps its link, so its hooks stay
- F2: no `--hooks` → no sync, as today; the error still names the sets
- the sync's own faults print beside the role fault; the exit stays non-zero

### P4 — the foreign cache (case 5)

```
getOneRepoMutexCache
  └─ after createCache: assertRepoMutexCacheFit({ cache })
       typeof cache.version !== 'function'
         → MalfunctionError 'the lock cache lacks version(): a foreign simple-on-disk-cache copy'
              { cachePath = the module lookup of 'simple-on-disk-cache/package.json',
                cacheVersion, wanted = '>= 1.8.1', rhx = getOneRhxProvenance(), hint }
```

- thrown before any acquire, so no half-taken lock is left (case 5's fail-safe)
- init's layout step defers it (extant); its boot sync surfaces it, exit 1 (case 5 [t1])

### P5 — which rhx runs (case 7, F3)

```
getOneRhxProvenance({ repoPath })
  → { running: { path = realpath of this rhachet's package root, version },
      pinned:  { path = <repo>/node_modules/rhachet, version } | null }
invokeInit header: when running.path ≠ pinned.path and the versions differ
  → one notice row '🐚 rhx <running.version> runs; this repo pins <pinned.version>' (never a refusal, F3)
```
