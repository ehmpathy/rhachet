# case 2 — a clone gets its own roles over the grove, from its own actor dir only (e3, e8)

## narrative

vlad keeps `model: opus` and a deny on `Agent` in `~/.claude/settings.json`. he enrolls a peer with specific
roles, `--roles -driver`, to ask it a question. the peer runs on opus, cannot spawn `Agent`, and never sees a
route.drive stop hook. every config it reads comes from its own hash actor's dir; the repo actor's dir is
never opened for config. when the peer's roles set a model of their own, that model wins over the box's.

## timeline

```

  and a repo whose ambient roles include mechanic and driver

  then it holds mechanic hooks, zero driver hooks, the repo's permissions, and claudeMdExcludes

  and the config sources are `user` only — the cwd's project and local files are never read
  and --settings names its own settings.repo.json
when [t3] the repo settings set model=sonnet and the grove sets model=opus
  then the clone runs on sonnet — the repo outranks the grove
when [t4] the repo actor's brain dir is listed
  then no settings.enroll.<hash>.local.json was written there
```
