# case 6 — mira switches her clone's model, and her box stays whole (e14, sharp, fail-safe spotlight)

## narrative

mira is mid-task in a clone and wants a faster model, so she runs `/model sonnet`. claude saves that to its
user layer, which in every actor is the arrow to her grove. either the save follows the arrow — and her box
now defaults to sonnet everywhere, which is what `/model` on her box has always meant — or claude replaces
the arrow with a real file, and that one actor quietly stops to follow her grove.

she does not have to know which. the next time she runs `rhx init`, the log says it plainly: the actor's
`settings.json` had forked from the grove, the forked copy is kept aside by name, and the arrow is back. her
`/model sonnet` is still in the kept file if she wants it; if she wants sonnet box-wide, the log names
`~/.claude/settings.json` as the place for it. `ls -l` shows every actor's `settings.json` points at the
grove again.

(which of the two saves claude makes is verified in the execution stone; the outcome mira sees after the next
init is the same either way.)

## timeline

```
given mira's clone of an actor with the one layout
when [t0] mira runs `/model sonnet` in the clone
  then her clone runs on sonnet for the rest of the session
when [t1] mira runs `rhx init`
  then each actor's settings.json is the arrow to settings.grove.json
  and if an actor's settings.json had been replaced by a real file, the log names that actor, the real file
      is kept aside as settings.forked.<iso>.json (byte-identical), and the log names
      ~/.claude/settings.json as the place for a box-wide change
when [t2] mira runs `rhx init` again
  then no fork is reported — idempotent
```

fail-safe: loud (a log line names the actor and the kept file), teaches the fix (the log names where a
box-wide change belongs), and drops no data silently (the fork is kept aside, byte-identical).
