## 1. settings.{repo,grove}.json are the sources; claude's fixed names are symlinks

> ⚠️ the two-tree layout in this section was the first draft. **appendix A supersedes it** — one layout,
> every actor. the musts below still hold, read with the appendix's names.

today a clone's config blends. `rhx init` writes an actor brain dir's `settings.json` with EVERY linked
role's hooks (`syncHooksForLinkedRoles.ts`), and a clone spawns with `CLAUDE_CONFIG_DIR=<actor brain dir>`
and `--setting-sources user,local`. so the role-filtered `--settings` file
(`settings.enroll.<hash>.local.json`) is likely merged with an unfiltered all-roles user layer. and the
human's box defaults (`~/.claude/settings.json`) never reach a clone at all.

i want two named sources, and the names the claude cli requires become symlinks to them:

```
repo brain dir  (<repo>/.claude -> .agent/.actors/actor.via.slug=.default/brain/.claude/)
  settings.repo.json                              # REAL: all repo roles' hooks + permissions (tracked)
  settings.json        -> settings.repo.json      # project layer, for a bare `claude`
  settings.local.json                             # the human's own (gitignored), untouched

actor brain dir (<actorDir>/brain/.claude/)
  settings.grove.json  -> ~/.claude/settings.json # the grove's (box's) own defaults
  settings.json        -> settings.grove.json     # user layer, via CLAUDE_CONFIG_DIR
  settings.repo.json                              # REAL: filtered to this actor's roles; passed as --settings
```

musts:

- 🔴 the hook writer (`writeClaudeCodeSettings`, `config.dao.ts`) writes `settings.repo.json` by name,
  atomically — never `settings.json`. a `fs.writeFile` through a `settings.json` symlink would follow the
  arrow
- the per-actor hook sync writes the actor's `settings.repo.json` filtered to THAT actor's roles
  (`getSettingsForRoles`), never all roles
- enroll writes `<actorDir>/brain/.claude/settings.repo.json` in place of the repo-level
  `settings.enroll.<hash>.local.json` — it derives from `{ brain, roles }`, so it is the actor's
  (`rule.forbid.per-clone-config`)
- enroll findserts the grove symlinks beside the credential symlink; an absent `~/.claude/settings.json`
  leaves no broken link behind
- a real `settings.json` migrates to `settings.repo.json` + a symlink
- extant actor dirs: an all-roles real `settings.json` becomes the symlink; stale
  `settings.enroll.*.local.json` files are pruned

## A. one brain dir layout, every actor

there is ONE brain dir layout, and every actor dir has it. there is no "repo brain dir" as a second kind:
it is the **repo actor's** dir (see C), and `<repo>/.claude` is only a symlink into it. no file lives in
`<repo>/.claude`, and none can.

```
.agent/.actors/<any actor>/brain/.claude/
  CLAUDE.md            -> AGENTS.md
  AGENTS.md                                       # @boot.md
  boot.md                                         # REAL: that actor's roles, rendered
  settings.repo.json                              # REAL: that actor's roles' hooks + permissions
  settings.grove.json  -> ~/.claude/settings.json # the grove (the box)
  settings.json        -> settings.grove.json     # claude's fixed name → our clear name
```

claude's fixed name (`settings.json`) points at our clear name (`grove`), which points at the source of
truth. `settings.repo.json` is passed to claude by its clear name.

### every reader is a clone

folks alias `claude` → `rhx enroll claude`, so every reader of a brain dir is an enrolled clone. a clone
spawns with `CLAUDE_CONFIG_DIR=<its actor dir>/brain/.claude` and the `user` config source only, plus
`--settings <its actor dir>/brain/.claude/settings.repo.json`.

🔴 **requirement: the repo outranks the grove.** on a key both set, the repo's value wins.

| slot | file | rank |
|---|---|---|
| `--settings` | `settings.repo.json` | high — the repo wins |
| user | `settings.json` → `settings.grove.json` → `~/.claude/settings.json` | low — the grove fills every key the repo leaves unset |

settled by docs + probe, 2026-09-27:
- claude ranks managed > `--settings` > project local > shared project > user; **no layer ranks below user**
  (https://code.claude.com/docs/en/settings)
- `CLAUDE_CONFIG_DIR` relocates the user layer
- **`--settings` does not stack.** a second `--settings` replaces the first whole: `{model:haiku}` then
  `{env:{…}}` ran on the default model, not haiku. so the grove cannot ride a first `--settings` under the
  repo — it rides the user layer, and the file claude calls `settings.json` is the grove

what follows:
- brain settings live ONLY in actor dirs, and each clone reads exactly ONE actor dir — its own
- a clone drops the `local` and `project` config sources: claude looks both up from the cwd (the repo), which
  would reach the repo actor's dir. measured: a clone today reads the repo actor's `settings.local.json`
  through its cwd — claude logged that it dropped 14 of its `permissions.allow` entries as untrusted
- `settings.local.json` is not part of the layout — no clone reads it. a human's own file there is left alone
- where claude's own writes land: `/model` or `/config` in a clone → `settings.json` → the grove (box-wide).
  where a clone saves an "always allow" with no local source → to probe
- the brain dir's `.gitignore` findsert: `settings.grove.json` (a home path), `boot.md`, `*.forked.*.json`
- 🔴 **requirement: trust inherits from the repo actor.** claude records workspace trust per config dir
  (`<actor>/brain/.claude/.claude.json` → `projects[<repo path>].hasTrustDialogAccepted`). measured: a fresh
  hash actor did not inherit it, so claude dropped the repo's allow rules as untrusted. when the repo actor
  trusts the repo, every other actor and every clone trusts it too — carried at enroll beside the first-run
  state (`findsertBrainFirstRunState`), never a prompt the human answers twice. when the repo actor does not
  trust it, no other actor is trusted on its behalf
  - ⚠️ **amended by the wisher, 2026-09-28:** *"the blanket grant stays"* — every enroll grants trust
    outright, to every actor, which subsumes "inherit from the repo actor"; the enroll is the consent.
    recorded where it was asked: `5.1.execution.from_vision.yield.md` section D. transcribed here by
    the driver (2026-10-05) so the requirement reads as shipped; the wisher may revert this note
- enforced by `define.brain-dir-layout-is-one-for-every-actor` + `rule.forbid.brain-dir-layout-divergence`

## B. actors vs roles — the fulcrum

an actor = `{ brain, roles }`. the confusion came from one word, "default", on both halves. each half gets
its own words, and they never borrow from each other:

| axis | terms | answers |
|---|---|---|
| **roles** | **ambient** · **specific** | which roles? |
| **actors** | **repo** · **hash** · **slug** | which identity holds them? |

- **ambient roles** = the roles a clone is enrolled with when not otherwise specified. **specific** = named,
  by `--roles` or in `actors.yml`
- the actor names follow the on-disk namespace: `actor.via.repo`, `actor.via.hash`, `actor.via.slug`
- 🔴 **invariant: the ambient roles live in the repo actor, and only there.** a bare `rhx enroll claude`
  grabs the ambient roles, so it lands in the repo actor — that is the definition. a hash actor holds
  specific roles only; a slug actor holds specific roles declared in `actors.yml`
- folks alias `claude` → `rhx enroll claude`, so an everyday `claude` is an ambient enroll into the repo actor
- "default" leaves the vocabulary. glossary: `domain.terms/term=ambient`

## C. `actor.via.slug=.default` → `actor.via.repo=ambient` — the seed

the structure says it too.

- `.agent/.actors/.gitignore` ignores `.default` again, and re-includes `actor.via.repo=ambient` instead
- the repo `.gitignore` negation line follows (`ACTORS_GITIGNORE_LINE`)
- symbols shed "default": `DEFAULT_ACTOR_DIR_NAME`, `getDefaultActorOndiskDir`, `syncDefaultBrainDir`,
  `findsertDefaultActorGitignoreExclusion`, `asDefaultBrainDirOutcome`, `defaultBrainDir(Rel)`, and the
  enroll path's `rolesDefault` → `rolesAmbient`
- 🔴 **a bare enroll lands in `actor.via.repo=ambient` — structurally, impossible to fail, clamped.**
  measured 2026-09-27: three bare enrolls each spawned under `actor.via.hash=bb10e9fb`, a hash twin of the
  ambient roles. the fix is not a branch on "were `--roles` passed?" — a branch can be bypassed. it is:
  - **one derivation.** a single pure transformer maps a resolved roleset to its actor: the ambient roleset
    → the repo actor; any other roleset → its hash actor. every enroll and clone path goes through it; no
    caller computes an actor dir by hand
  - **identity by roleset.** the route follows from the roles, not the flags — a bare enroll, and a
    `--roles` list whose resolved set equals the ambient roles, both land in the repo actor
  - **a clamp.** the hash-actor derivation refuses the ambient roleset outright (a malfunction, fail loud),
    so no path — present or future — can mint a hash twin of the repo actor
  - **a test clamps the clamp.** bare enroll → `actor.via.repo=ambient`, and a direct call that hands the
    ambient roleset to the hash derivation throws
  - extant hash twins of the ambient roles (e.g. `actor.via.hash=bb10e9fb`) are orphans after the fix —
    their live clones finish, and prune reaps them once DEAD
- extant repos migrate: the tracked `.default` dir moves to `actor.via.repo=ambient`, `<repo>/.claude` is
  repointed (today `setRepoBrainDirSymlink` refuses a symlink aimed elsewhere — it must accept the legacy
  target), and the legacy gitignore negation is dropped
