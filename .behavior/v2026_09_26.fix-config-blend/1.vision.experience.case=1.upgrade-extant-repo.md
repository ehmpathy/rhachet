# case 1 — upgrade an extant repo with a live `-driver` peer (e0, densest)

## narrative

vlad's repo predates this change. its repo actor is `actor.via.slug=.default`, tracked, with a real
`settings.json` that holds every role's hooks and a few permissions he added by hand. his `claude` alias has
put every everyday clone into a hash twin of the ambient roles. last week he enrolled a peer with specific
roles (`--roles -driver`); its hash actor holds a real all-roles `settings.json` from `rhx init`, and a
`settings.enroll.<hash>.local.json` from that enroll still sits in the repo actor's dir. his
`~/.claude/settings.json` pins `model: opus`, and he trusted the repo long ago.

he runs `rhx upgrade`. the repo actor becomes `actor.via.repo=ambient`, every actor gets the one layout, and
every boot re-renders. he opens `claude`: it lands in the repo actor, on opus, trusted, with the rhachet intro
on top. he respawns the peer: its own roles only, zero driver hooks, no trust prompt.

## timeline

```
given a repo actor at .agent/.actors/actor.via.slug=.default, tracked, with a real settings.json
  (all roles' hooks + hand-added permissions), trusted
  and a hash actor for specific roles (-driver) with a real all-roles settings.json and a live clone
  and a settings.enroll.<hash>.local.json in the repo actor's brain dir
  and ~/.claude/settings.json with model=opus
when [t0] `rhx upgrade` runs
  then the repo actor's dir is now .agent/.actors/actor.via.repo=ambient
  and .agent/.actors/.gitignore re-includes actor.via.repo=ambient/ and no longer re-includes .default
  and <repo>/.claude is a symlink to .agent/.actors/actor.via.repo=ambient/brain/.claude
when [t1] the repo actor's brain dir is listed
  then settings.repo.json holds the prior content — the ambient roles' hooks and the hand-added permissions
  and settings.grove.json -> ~/.claude/settings.json
  and settings.json -> settings.grove.json
when [t2] the hash actor's brain dir is listed
  then it holds the same six names and arrows as the repo actor's
  and its settings.repo.json holds the -driver roleset's hooks and zero driver hooks
when [t3] the repo actor's brain dir is listed for enroll artifacts
  then the peer's settings.enroll.<hash>.local.json is still there — the live peer was spawned with
       --settings on that path
when [t3.1] the peer exits and `rhx init` runs again
  then that stale enroll file is pruned
when [t4] vlad runs `claude` (→ `rhx enroll claude`)
  then the clone lands in actor.via.repo=ambient, never a hash actor
  and it runs on model=opus from the grove, unless the repo settings set a model — the repo outranks
  and it raises no trust prompt — the repo actor trusts the repo
  and its boot.md opens with the rhachet intro
when [t5] the peer is respawned
  then it reads its own actor dir only — `user` source + --settings on its own settings.repo.json
  and it raises no trust prompt — trust was carried from the repo actor
when [t6] `rhx upgrade` runs again
  then every file above is unchanged — idempotent
```
