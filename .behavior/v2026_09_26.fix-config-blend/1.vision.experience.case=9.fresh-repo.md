# case 9 — a fresh repo: first `rhx init`, first `claude` (e1)

## narrative

juno clones a repo that has never met rhachet. she adds the roles, runs `rhx init`, and types `claude` — her
alias for `rhx enroll claude`. there is no legacy dir to rename and no old file to move aside: the repo actor
is born as `actor.via.repo=ambient` with the one layout, and her first clone lands in it. her box already has a
`~/.claude/settings.json` with her model and her deny rules, and the clone runs on them — shadowed where her
roles set a key of their own. she trusts the repo at the first prompt, once; every clone after that, of any
actor, is trusted.

## timeline

```
given a repo with no .agent/.actors dir and no <repo>/.claude
  and ~/.claude/settings.json with model=opus
when [t0] juno runs `rhx init` with roles linked
  then .agent/.actors/actor.via.repo=ambient/brain/.claude holds the one layout:
       boot.md, AGENTS.md, CLAUDE.md -> AGENTS.md, settings.repo.json (the ambient roles' hooks),
       settings.grove.json -> ~/.claude/settings.json, settings.json -> settings.grove.json
  and <repo>/.claude is a symlink into it
  and .agent/.actors/.gitignore re-includes actor.via.repo=ambient/ only
when [t1] juno runs `claude` (→ `rhx enroll claude`)
  then the clone lands in actor.via.repo=ambient
  and it runs on opus, from the grove
  and claude asks her to trust the repo — the repo actor has no grant yet
when [t2] she accepts, exits, and runs `claude --roles -driver`
  then a hash actor is born with the one layout, trusted — carried from the repo actor
  and it raises no second trust prompt
```
