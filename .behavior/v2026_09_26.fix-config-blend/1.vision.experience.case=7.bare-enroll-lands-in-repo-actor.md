# case 7 — a bare enroll lands in the repo actor, and no path can miss (e17, sharp, clamp spotlight)

## narrative

vlad types `claude` fifty times a day; his alias runs `rhx enroll claude`. every one of those clones must land
in `actor.via.repo=ambient` — the one home of the ambient roles — so they share its config and its trust.
today they land in a hash twin (`actor.via.hash=bb10e9fb`), measured.

the fix is structural, so no future code path can reopen it: one derivation maps a resolved roleset to its
actor, and the hash derivation refuses the ambient roleset outright. a contributor who adds a new enroll path
and computes an actor dir by hand hits the clamp in the first test run, with a message that names the fix.

## timeline

```
given a repo whose ambient roles are [mechanic, driver, ergonomist]
when [t0] `rhx enroll claude` runs (bare)
  then the clone lands in .agent/.actors/actor.via.repo=ambient
  and no actor.via.hash=* dir is created
when [t1] `rhx enroll claude --roles mechanic,driver,ergonomist` runs (resolves equal to the ambient roles)
  then the clone lands in actor.via.repo=ambient — identity by roleset, not by flags
when [t2] `rhx enroll claude --roles -driver` runs
  then the clone lands in actor.via.hash=<hash of [mechanic, ergonomist]>
when [t3] code hands the ambient roleset straight to the hash-actor derivation
  then it throws a MalfunctionError: the ambient roles belong to the repo actor; route through the one
       derivation
when [t4] a new role is linked, so the ambient roles grow
  then the next bare enroll still lands in actor.via.repo=ambient — the repo actor's roles follow the
       ambient roles by reference, never a snapshot
```

fail-safe: the clamp is fast (throws at the boundary), loud (a MalfunctionError, never a silent twin), and
teaches the fix (names the one derivation to route through).
