# case 10 — a bare enroll meets a repo still at the legacy actor dir (e21)

## narrative

kai pulls the rhachet upgrade into a repo whose tracked repo actor still sits at its legacy name,
`actor.via.slug=.default`, with a real `settings.json` inside. before he runs `rhx init`, he types `claude`
— his alias for `rhx enroll claude`. were enroll to mint `actor.via.repo=ambient` first, the legacy move
would skip forever (a current dir already exists) and strand the tracked config. so enroll moves the legacy
dir to its current name before it makes any actor dir, and repoints `<repo>/.claude` at it, so the link
never dangles. kai's clone lands in the repo actor with the config the repo already tracked. the move
prints no row of its own: kai's screen reads as any bare enroll's.

## timeline

```
given a repo with .agent/.actors/actor.via.slug=.default/brain/.claude (a real settings.json, keep.json)
  and <repo>/.claude -> .agent/.actors/actor.via.slug=.default/brain/.claude
  and no `rhx init` since the upgrade
when [t0] kai runs `claude` (→ `rhx enroll claude`, bare)
  then .agent/.actors/actor.via.repo=ambient holds the legacy dir's content (keep.json carried)
  and no actor.via.slug=.default dir remains
  and <repo>/.claude -> .agent/.actors/actor.via.repo=ambient/brain/.claude, and reads through
  and the clone lands in the repo actor
  and the enroll report reads as any bare enroll's — the move adds no row
when [t1] kai later runs `rhx init`
  then the legacy move is a no-op — the dir already sits at its current name
```
