# case 4 — a ci box with no `~/.claude/settings.json` (e4, sharp, fail-safe spotlight)

## narrative

rook maintains the ci runners. a fresh runner has never run claude by hand, so it has no
`~/.claude/settings.json`. rook's pipeline runs `rhx enroll claude --roles -driver -p "…"`. the enroll
succeeds, the clone runs on its repo settings alone, and the job log carries one clear line: the grove file
is absent, so box defaults did not apply, and here is the path to create if they should. rook does not
chase a broken symlink or a mystery config, because there is none.

later rook bakes a `~/.claude/settings.json` into the runner image. the next `rhx init` links it into every
actor, and the next clone runs on it.

## timeline

```
given a box where ~/.claude/settings.json does not exist
when [t0] rook's pipeline runs `rhx enroll claude --roles -driver -p "…"`
  then enroll exits 0 and the clone runs
  and the actor's settings.grove.json and settings.json do not exist
  and settings.repo.json does, and --settings names it
  and the job log names ~/.claude/settings.json as absent, and says box defaults did not apply
when [t1] rook bakes ~/.claude/settings.json into the image and `rhx init` runs
  then every actor now holds settings.grove.json -> it, and settings.json -> settings.grove.json

given a box where ~/.claude/settings.json does not exist
  and a hash actor holds a legacy real all-roles settings.json
when [t2] rook's pipeline runs `rhx enroll claude --roles -driver` for that actor
  then the legacy settings.json is removed — rook's clone gets only its own roles' hooks, grove or no grove
```

⚠️ the rule allows this one layout gap: every actor lacks the two grove names (`settings.grove.json`,
`settings.json`) together, on this box. no actor has a file another lacks.

fail-safe: fast (no wait), loud (a log line names the absent grove), teaches the fix (the log names the path
`~/.claude/settings.json`).
