# case=5 — SessionStart stdout lands in context

`seat × {SessionStart, UserPromptSubmit} × any × one-emits` · happy · critipath

## .narrative

a seat boots. today four SessionStart hooks print to stdout: the mechanic's permission notice, the
behaver's bound-behavior boot, the driver's `route.drive`, and others. claude adds each to context.
this very route reached its driver that way.

after: one SessionStart entry. the dispatcher captures each rule's stdout and writes them in
manifest order. the context the seat boots with holds the same text, in the same order. a rule's
`🪨 run solid skill …` stdout header (`invokeRun.ts:71-75`) still opens an `rhx-skill` rule's
part, so the seat's boot reads as it did.

then the human types a prompt. UserPromptSubmit fires one rule today, the mechanic's
`userpromptsubmit.git-pull-watch.sh`, which prints held pr-watch alerts to stdout; claude adds them
to the turn's context. through the dispatcher the same text lands, and the event answers inside
claude's 30 s UserPromptSubmit default.

## .[tn] sketch

```
given('an actor whose roles declare four SessionStart rules')
  when('[t0] each rule runs alone on a SessionStart payload (today)')
    then('stdouts O1..O4')
  when('[t1] the dispatcher runs the event')
    then('exit 0')
    then('stdout === O1 + O2 + O3 + O4, in manifest order')
    then('the behaver boot rule (an rhx-init rule) part opens with `💪 init role repo=bhuild/role=behaver/init=…`, as today')
    then('zero rhx execs')
given('an actor whose roles declare one UserPromptSubmit rule')
  when('[t2] the rule runs alone on a UserPromptSubmit payload (today)')
    then('stdout U')
  when('[t3] the dispatcher runs the event')
    then('exit 0; stdout === U')
    then('the dispatcher hook's timeout fits under claude's 30s UserPromptSubmit default')
```
