# case=9 — one seat session, end to end

`seat × {SessionStart, PreToolUse, Stop} × {rhx-skill, rhx-init, shell, foreign} × {one-emits, all-allow, one-blocks, many-block, json}` · happy + sharp · critipath · **the densest walk**

## .narrative

a seat boots on a branch with a bound route, works one stone, and tries to stop. one walk crosses
every merge boundary the dispatcher owns:

- it boots — four SessionStart rules print the route (`route.drive --when hook.onBoot`), the
  behavior boot (an `rhx-init` rule, `💪 init role` frame), the permission notice, and the pr-watch
  notice; one dispatcher, the same context as today
- it runs `pwd` — ten PreToolUse rules fit, all allow; one process, no rhx boot
- it runs `ls src/` — the permission check refuses; the bytes match today
- it retries `ls src/` unchanged — the permission check answers with the `ask` json, beside three
  `rhx` headers on stdout; claude still parses one json and asks the human
- it reads a sealed `.stone` — `route.mutate.guard` refuses, wrapped in the `🪨 run solid skill …
  ✋ blocked by constraints` frame, with no rhx boot
- it writes `cat x 2>/dev/null > /tmp/y` — three rules refuse; all three refusals, in manifest order
- it stops — `route.drive --when hook.onStop` refuses with the stone; the two foreign Stop rules
  (`rhachet roles cost …`, `node -e …`) still run; the stop is refused, as today

the boundaries that interact: the `ask` json beside the `rhx` stdout headers (`case=8`), and the
Stop event's mix of an `rhx-skill` refusal with two foreign rules.
