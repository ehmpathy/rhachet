# case=3 — many rules block one call

`seat × PreToolUse × any × many-block` · sharp · critipath

## .narrative

a seat writes `cat foo.txt 2>/dev/null > /tmp/out`. three rules object: the permission check (`cat`
unpaved), stderr-redirect, and tmp-writes. today claude runs all three in parallel and shows three
`hook error` blocks, one per command label.

after: the dispatcher runs every fit rule — it never stops at the first refusal, since today the
seat learns all three fixes from one call, and a first-stop would cost it two more round trips. it
writes each blocker's stderr in **registry order** (the order of the rules in the manifest, which is
the order `rhx init` wrote them in today), one after another, and exits 2. claude shows one `hook
error` block whose body holds all three refusals.

## .[tn] sketch

```
given('a payload three rules refuse')
  when('[t0] piped to each rule alone')
    then('three exit 2s: S1, S2, S3')
  when('[t1] piped to the dispatcher')
    then('exit 2')
    then('stderr === S1 + S2 + S3, in manifest order')
    then('a rule that allowed adds no bytes')
  when('[t2] piped again — the order is stable')
    then('stderr is identical to t1, though the rules ran in parallel')
```
