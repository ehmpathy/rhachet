# case=8 — a json decision survives the merge

`seat × PreToolUse × shell × one-emits (json)` · sharp · critipath

## .narrative

a seat retries an unpaved command. `pretooluse.check-permissions.sh` writes a json decision to
stdout — `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask",…}}` — and
exits 0, so claude asks the human rather than block.

today that json is the whole stdout of its own process. in one dispatcher it would sit beside the
`🪨 run solid skill …` headers the three `rhx` rules print to stdout on every call
(`invokeRun.ts:71-75`). concatenated, claude no longer parses a json, the `ask` is lost, and the
call runs with no prompt. a silent gate opened.

so the merge treats stdout by kind:

- if no rule's stdout is a json object → plain text, concatenated in manifest order (as `case=5`)
- if exactly one rule's stdout is a json object → that json is the dispatcher's stdout. on
  PreToolUse and Stop, plain stdout from the other rules is transcript-only today, so it drops
- itemized, not live: a json beside plain text on SessionStart / UserPromptSubmit (fold the text
  into `additionalContext`), and two rules that each emit json (claude's rule: first deny wins).
  no rule does either today — the four SessionStart rules print plain text, and the only json
  emitter on a synced event is `check-permissions.sh` on PreToolUse

## .[tn] sketch

```
given('a retry payload that check-permissions answers with an ask json')
  when('[t0] piped to check-permissions.sh alone')
    then('exit 0, stdout = J (a json object)')
  when('[t1] piped to the dispatcher, with the three rhx rules also fit')
    then('exit 0')
    then('stdout parses as json')
    then('stdout deep-equals J')
given('a Stop where one rule emits json and another prints plain text')
  when('[t0] dispatched')
    then('stdout parses as json and deep-equals the json rule's stdout')
```
