## .what the dispatcher guarantees

each line is a property that holds, with the test that pins it. the review trail that surfaced each
lives in `.reviews/peer/*.taken.by_self.*.md`.

### verdicts

- a rule that exits 0 or 2 before the watchdog reaps it keeps its own verdict; only a rule the watchdog's TERM killed reads as timed out, 124 (`[t23]`, `[t27]`)
- a crash beside a block rides after the blockers' stderr (`[t2b]`); beside a json decision or plain context, it rides as the json `systemMessage` (`[t3]`)
- json decisions rank deny > ask > allow (`[t10]`), the PermissionRequest `behavior` shape included (`[t22]`)
- a refusal exits per event: 1 on UserPromptSubmit and on a Stop already held once, 2 elsewhere (F20, `[t7b]`)
- a blocked call ends with one `🪝 hooks.dispatch <Event> blocked by <rule path>` line per blocker, after every rule's own bytes, so the refuser is named though claude labels only the dispatcher (F3)

### fail closed

- an absent manifest, a manifest version or row it cannot read, a row with more fields than v1, and an unresolved merge conflict each refuse with a `✋ ConstraintError` that names `npx rhx init --hooks` (`[t4]`, `[t7]`, `[t13]`, `[t15]`, `[t21]`, `[t21b]`)
- enroll refuses a dispatcher whose manifest is absent (`enroll` [case2e][t4])
- a silent crash and an invalid regex are named (`[t9]`, `[t11]`)

### process hygiene

- per-call files are private, created under noclobber with the pid plus a random part, and removed on any exit by the dispatcher alone (`BASHPID == $$`); a dir it cannot write refuses (`[t14]`, `[t19]`, `[t20]`, `[t27]`)
- a timed-out rule gets TERM, then KILL two seconds later, by its own pid only (F13, `[t12]`); bash's job notice for it never reaches stderr (`[t12]`)
- a rule whose file reads `$$` runs as `bash <path>`; bash < 5 runs every rule that way (`[t4b]`)
- the watchdog costs one subshell and one `sleep` exec, of 57 execs per Bash call

### the sync

- the manifest lands whole before the settings name the dispatcher (`syncRoleHooksIntoTarget` integration); dispatchers upsert before the role hooks leave, through one predicate (`isHookReplacedByDispatch`), so a faulted sync never leaves a clone that runs each rule twice
- each sync rederives every rule's file fields, so a moved file or a flipped shebang reaches the row
- a matcher bash would read otherwise than claude, a path or event the shell would split, and a field that holds a row breaker each refuse at sync, snapped with their fixes
- the timeout unit is seconds on both sides, as the published claude adapter writes it; timeouts carry no default, and a 0 refuses
- a brain adapter that refuses the dispatcher write reports per role × brain (`upgrade` [case17])
- the report names the shape: `N rules → M dispatchers`, each event's rule count, the role hooks that moved, the manifest path
- a hand-added hook stays in the settings, untouched, and never enters the manifest (`init.hooks` [case9])

### one source each

- one manifest fields const, one manifest path function, one hook identity (`BrainHook.unique`), one author parser, one enrolled-role narrow, one exact-list matcher pattern; the bash copies of each are held by parity tests
- a run flag in any form commander reads (`--role=x`, `-rx`) marks the parse uncertain, so the command runs as declared

### what a human reads

- `RHACHET_HOOKS_DISPATCH_TRACE` writes one line per rule, each with the dispatcher's pid (`[t25]`, `[t26]`)
- a label line above each manifest row; a readme section with the replay command and `RHACHET_HOOKS_DISPATCH_SOURCE=0`
- `[t5]`, `[t5b]`, `[t6b]` snap what lands in context
