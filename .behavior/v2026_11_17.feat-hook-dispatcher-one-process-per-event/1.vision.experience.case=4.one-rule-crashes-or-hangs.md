# case=4 — one rule crashes or hangs

`seat × any B × {shell, rhx-skill} × {one-crashes, one-hangs}` and `seat × F=fleet` · sharp · critipath (all)

## .narrative

today each rule is its own process, so one rule's failure cannot touch another's. the dispatcher
must keep that wall, or one bad rule in one role silently disarms every other role's guard.

**crash.** a rule exits 1 (say `jq` is absent). the other rules still run and still decide. if
another rule blocks, the result is exit 2 with every blocker's stderr, as `case=3`. if none blocks,
the dispatcher writes the crashed rule's stderr and exits with its code — claude treats that as a
non-block error, exactly as it treated the lone crashed hook before. (the mechanic's rules already
trap their own crash into exit 2 and fail closed; that is their bytes, and it holds.)

per event, a lone crash keeps the effect it has today: on PreToolUse and Stop the call or the stop
proceeds; on SessionStart and UserPromptSubmit every other rule's stdout still lands in context, so
one broken boot rule does not blank the seat's boot.

**hang.** a rule runs past its timeout. the dispatcher kills that rule's subshell tree, reports
`💥 MalfunctionError: <rule> timed out after <n>s` on stderr, and treats it as a crash. the event
answers within the budget, so one slow rule cannot eat a fast one's verdict.

why a hang is a critipath, not an alterpath: today claude kills one hung hook at its own timeout
and the other nine still decide. if the dispatcher's own claude timeout fired first, claude would
kill the dispatcher, and **every** rule's verdict for that call would be lost at once — every gate
open, with no trace. so the dispatcher's claude timeout is set above its slowest rule's timeout plus
a margin, and each rule is killed at its own timeout from inside.

**fleet.** the hang is not a corner on the shared laptop. at load ~100 on 12 cores, a rule that
takes 200 ms solo can take seconds, and a 5 s rule timeout can fire on an innocent rule. today
claude kills that one hook and the other nine still decide. under the dispatcher the same holds:
the slowed rule is killed at its own 5 s, reported as a crash, and the other rules' verdicts land —
so a refusal from a fast rule still blocks. the seat meets the same verdicts it would meet today at
the same load, and never the loss of every verdict at once.

## .[tn] sketch

```
given('a manifest with a rule that exits 1 and a rule that blocks')
  when('[t0] the payload is dispatched')
    then('exit 2; stderr holds the blocker, then the crash, in manifest order')
given('a manifest with a rule that exits 1 and rules that allow')
  when('[t0] the payload is dispatched')
    then('exit 1; stderr === the crashed rule's stderr')
given('a SessionStart manifest with a rule that exits 1 and three that print context')
  when('[t0] the event is dispatched')
    then('stdout holds the three rules' context, in manifest order; stderr holds the crash')
given('a manifest with a rule that sleeps past its timeout')
  when('[t0] the payload is dispatched')
    then('the dispatcher returns within timeout + a small margin')
    then('stderr names the rule and the timeout')
    then('no orphan of the hung rule outlives the dispatcher')
    then('the other rules' verdicts still land: a blocker still blocks')
given('[fleet] a box under cpu contention, where one fit rule now runs past its 5s timeout and another rule blocks')
  when('[t0] PreToolUse is dispatched')
    then('the slowed rule is killed at its own timeout and reported')
    then('the blocker's stderr still lands; exit 2')
    then('the dispatcher answers before its own claude timeout')
given('a synced manifest whose slowest rule has timeout T')
  then('the dispatcher hook's timeout in settings is greater than T plus a margin')
```
