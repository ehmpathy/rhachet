# case=3: an extant actor keeps its settings

## .narrative

a maintainer has leaned on one actor for a month. its clones boot with the driver's route reminder,
run without a permission prompt on the paved commands, pick up the env their skills read, and never
see a stray `CLAUDE.md` from a peer actor. the maintainer upgrades rhachet and enrolls the actor again.

what they notice is what does not change: the boot reminder still fires, the paved commands still
run unprompted, the skills still find their env, no stray brief leaks in. the one difference shows
up later, when the clone commits — no trailer. under the hood the file gained one key,
`attribution`, and every other key kept its value.

## .timeline (sketch)

```
given an actor whose settings.of.repo.json holds hooks, permissions, env, and no attribution key
  and given the repo actor's source file is unchanged since that actor's last enroll
  when [t0] the actor is enrolled again
    then [t0] attribution is { "commit": "", "pr": "" }
    then [t0] hooks, permissions, env, and every other key equal their prior values
    then [t0] the new clone's boot hooks fire, its paved commands run unprompted, as before
    then [t0] the new clone's first commit carries no Co-Authored-By: Claude trailer
  when [t1] the actor is enrolled a third time
    then [t1] the file is byte-identical to its state after [t0]
```

this is clamp 2 of the wish. [t1] covers the idempotent re-enroll (inventory case=7).
