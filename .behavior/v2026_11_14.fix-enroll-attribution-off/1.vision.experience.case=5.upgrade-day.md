# case=5: upgrade day (the densest walk)

## .narrative

a human bumps rhachet in a repo that has used it for months. the repo actor's
`settings.of.repo.json` is tracked in git and full of hooks and allows. their
`~/.claude/settings.json` is stock, so claude's own default would add the trailer. they type
`claude` and ask for a fix, a commit, and a PR.

the enroll rewrites the repo actor's file: one key appears, `attribution`. the clone boots with it
at the `--settings` rank, outranks the grove, and never hears the attribution reminder. the commit
and the PR are clean. afterward, `git diff` on the repo actor's file shows exactly one added key —
no hook, allow, or exclude moved. the human's own `~/.claude/settings.json` is untouched, so their
bare, unenrolled claude elsewhere behaves as before.

boundaries crossed in one walk: an extant actor file (case=3), the repo actor (case=1), a grove that
disagrees (case=4), a git-tracked config, and the commit + PR output itself.

## .timeline (sketch)

```
given a repo whose repo actor settings.of.repo.json holds hooks + allows, tracked in git
  and given ~/.claude/settings.json is silent on attribution (claude default = add the trailer)
  when [t0] the human upgrades rhachet and runs `claude`
    then [t0] the repo actor's settings.of.repo.json gains "attribution": { "commit": "", "pr": "" }
    then [t0] `git diff` on that file shows that one key and no other change
    then [t0] ~/.claude/settings.json is byte-identical to its prior state
  when [t1] the clone commits and opens a PR
    then [t1] no attribution reminder reached the clone
    then [t1] the commit has no Co-Authored-By: Claude trailer; the PR body has no Claude footer
```
