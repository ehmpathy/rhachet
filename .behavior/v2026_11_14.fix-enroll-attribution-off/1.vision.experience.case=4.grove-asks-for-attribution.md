# case=4: the grove asks for attribution

## .narrative

a human's `~/.claude/settings.json` sets `"attribution": { "commit": "Co-Authored-By: …" }` for their
own unenrolled sessions (a stock grove, silent on attribution, is the upgrade-day walk in case=5). the clone reads that file at the user rank, through the
`settings.json → settings.of.grove.json → ~/.claude/settings.json` arrows. the actor's
`settings.of.repo.json` arrives at the `--settings` rank, which outranks user, so its empty strings
win. the clone writes no trailer. the human's own file is never opened for write: their bare,
unenrolled `claude` sessions keep whatever they chose.

## .timeline (sketch)

```
given ~/.claude/settings.json sets attribution.commit to a Claude trailer
  when [t0] a clone is enrolled
    then [t0] ~/.claude/settings.json is byte-identical to its prior state
    then [t0] the actor's settings.of.repo.json sets attribution.commit and .pr to ""
    then [t0] the merged attribution the clone resolves is empty (--settings outranks user)
```

## .why it fails safe, and why it stays silent

- **safe by construction**: the outrank is claude's own precedence, so no rhachet code must win a
  race against the grove, and no grove value can reopen the reminder
- **silent on purpose**: the human has naught to fix — the clone already behaves as the fleet rule
  asks, and their own sessions keep their choice. a notice here would be a line they cannot act on
  (enroll treats the settings write as a precondition, not a receipt)
- **loud where it can break**: if the actor's `settings.of.repo.json` cannot be written (a symlink or
  a dir at that name), the extant writer and layout findsert already refuse before the spawn, so no
  clone boots without the key — verdicted as inventory case=16 (and a malformed file as case=15)
