# 1.vision.experience.dimensions

> the axes an enrolled clone's attribution experience varies on, and the walked product.

## .dimensions

| # | dimension | positions |
|---|---|---|
| D1 | actor form | `repo` (an everyday `claude`, the repo actor) · `hash` (`rhx enroll claude --roles …`) · `slug/derived` (`actors.yml`, `--as @<slug>`, a delta actor) |
| D2 | actor `settings.of.repo.json` before | `absent` (first enroll) · `extant, no attribution key` · `extant, attribution off` (re-enroll) · `extant, attribution true` (claude's default trailer, asked for) · `extant, attribution custom text` (a hand-authored string) · `extant, malformed json` (a hand edit broke it) · `unwritable` (a symlink or a dir at that name) |
| D3 | grove (`~/.claude/settings.json`) | `absent` · `silent on attribution` (claude's default applies) · `sets attribution text, or includeCoAuthoredBy: true` |
| D4 | write path | `enroll, attended` · `enroll --async / unattended` (detached host; how a cron seat or a peer is stood up) · `rhx init` (hook sync's actor pass) |
| D5 | clone life | `fresh spawn` · `live clone, spawned before the fix` · `none` (no clone spawns — `rhx init`, or an enroll that fails fast before its spawn) |

## .why these and no others

- the whole defect lives in ONE merge: claude resolves `attribution` across its settings sources;
  the clone has exactly two (`--settings` → the actor's `settings.of.repo.json`; user → the grove).
  D2 and D3 are those two sources; D1 picks which actor file; D4 picks which writer path; D5 picks
  when claude reads it
- **actor kind (human vs system) is not its own axis**: a cron seat or a supervisor's peer is a
  `hash` or `slug/derived` actor stood up via `enroll --async / unattended` (D4). its experience is
  that D1 × D4 cell; no other code path serves it
- **git-tracked is not its own axis**: `.gitignore` ignores `.agent/.actors/*` and re-includes only
  `actor.via.repo=ambient/` (lines 7, 25). so tracked ⟺ D1 = `repo`; a separate axis would only
  repeat D1
- the brain cli version is not an axis: the object form `{ "commit": "", "pr": "" }` is honored by
  every claude version that knows `attribution` (the first such version is a `[research]` item in
  the yield)

## .the walked product

3 × 7 × 3 × 3 × 3 = 567 raw cells. most are invalid or dominated, so the effective set is small:

- D5 = `none` pairs with D4 = `rhx init`, or with an enroll whose D2 is `malformed json` or
  `unwritable` (it fails fast before the spawn); D5 = `live` pairs only with an enroll that found a
  prior clone
- D1 × D4 collapse to one writer: every enroll path and the init pass call
  `setActorSettingsRepoWithinLock` (`invokeEnroll.ts:628`; `setActorSettingsDerived.ts:41`, which
  init's pass runs for every actor, the repo actor included — `syncHooksForLinkedRoles.ts:233-236`)
- D3 never changes the clone's resolved attribution, since `--settings` outranks user; it changes
  only whether the human's file must stay untouched, which is one experience (case=4)

the distinct experiences that survive — 15 cells, each verdicted, plus one scope line — are in
`1.vision.experience.case=_.md`. none was lost in the collapse: each collapsed axis value maps to a
row that names it.
