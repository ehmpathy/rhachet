wish =

# wish: rhachet init never writes outside the repo, and every hook sync error prints

task: ehmpathy/rhachet#661

## .the defect

`pnpm install` runs `prepare` → `rhachet init`, which exits 1 with no error shown. the last line is
`🧢 apply hooks to enrolled actors… ├─ <actor hash>`, then `ELIFECYCLE exit code 1`.

two causes, both in `syncHooksForLinkedRoles`:

1. errors vanish: the `💥 N hook sync error(s)` summary prints before the actor loop, so errors the
   loop pushes are never shown, yet `invokeInit` still exits 1 on them. a silent exit 1.
2. it writes outside the repo: an actor's `brain/.claude/settings.json` can be a symlink chain that
   ends at the human's `~/.claude/settings.json`. the sync follows it and writes hooks into the
   human's global settings. where the human keeps that file read-only (0444), the write fails with
   EACCES, once per role.

## .the outcome

- every hook sync error prints, with its actor, role, and path, before init exits non-zero
- init never writes through a symlink whose target resolves outside the repo. for such a target it
  skips the write with a named warn, or writes the repo-scoped settings file instead
- an actor whose settings.json links to a read-only file outside the repo: init exits 0 with a
  visible warn, and the human's file is untouched

## .the proof

a clamp test that is red without the fix and green with it: an actor whose settings.json links to a
0444 file outside a temp repo. init leaves that file byte-identical and prints the warn.

## .why now

dev-env-setup #167 (approved by the commander) releases only after this ships into prod and #167
is upgraded onto it.
