# case=6 — the grove still holds hooks an old build wrote

**feel × care** = sharp × alterpath · cell: g.polluted × b.inside × r.{file,absent} × a.enrolled × f.none × k.solo × c.init

## .narrative

mia (case=2) ran `pnpm install` on the old build for weeks. her `~/.claude/settings.json` now
holds this repo's role hooks, each tagged with an `author` of `repo=…/role=…`. she upgrades rhachet
and reruns. the new init never touches her home file — as the wish asks — so those hooks stay, and
every claude session on her box, in any repo, still fires them at low rank.

the fix is hers to make, since only she may edit her home file. what rhachet owes her is to say so.

## .fail-safe (proposed — see the yield's open questions)

- loud: init reads the grove (a read, never a write) and, where it finds a hook whose `author` is
  one of this repo's linked roles, prints a `⚠️` block that names the file and the count
- teaches: the hint names the file and says to remove the `author: repo=…` entries by hand
- never writes: the file stays byte-identical, by the wish's own rule
