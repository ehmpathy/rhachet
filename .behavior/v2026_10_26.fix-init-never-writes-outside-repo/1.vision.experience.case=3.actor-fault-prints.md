# case=3 — a fault inside the repo prints before the exit

**feel × care** = sharp × critipath · cell: g.readonly × b.inside × r.{file,absent} × a.enrolled × f.fs × k.solo × c.init (and c.upgrade at [t1])

## .narrative

an actor dir in jo's repo is read-only after a bad `chown`. `pnpm install` runs init. jo sees:

```
🧢 apply hooks to enrolled actors...
   ├─ ✗ hash=7dcf1989: ✋ ConstraintError: actor settings could not be written (EACCES)
   │  ├─ roles = driver, learner, behaver, dispatcher, mechanic
   │  ├─ path = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude
   │  └─ hint = restore write access to that dir, then rerun `rhx init --hooks`
   └─ repo=ambient

⚠️ left a read-only file outside the repo untouched
   ├─ path = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude/settings.json
   ├─ lands at = /home/jo/.claude/settings.json (read-only)
   └─ rhachet never writes outside the repo; the actor's hooks live in its settings.of.repo.json

💥 MalfunctionError: 1 hook sync error — role hooks may be uninstalled
```

then `ELIFECYCLE exit code 1`. jo reads the hint, fixes the mode, reruns, and it passes. the next
week jo runs `rhx upgrade` on a box with the same fault and meets the same row and header.

under the old build, jo saw only the actor hash and the exit code. on main today jo sees the row
with the raw `Error: EACCES …` and its path, but no roles and no hint — the wrap closes that gap.

## .fail-safe

- fast: the fault is caught at the actor's boundary — the first write into its brain dir fails,
  the temp + rename leaves no partial file, and the wrap happens right there in the actor pass,
  before the next actor starts. (and the sweep then continues, so every other actor still syncs)
- loud: the row names the actor, its roles, the errno and the path
- teaches: the hint names the dir and the rerun command

## .bdd sketch

```

    then it exits 1

    then beneath it, `roles = …` lists the actor's roles, `path = …` names the dir, `hint = …` names the fix
    then the read-only note prints, once
    then the `💥 MalfunctionError: 1 hook sync error` header prints AFTER that row
    then <home>/.claude/settings.json is byte-identical
  [t1] when jo runs `rhx upgrade` on the same scene
    then it exits non-zero, with the same row and header
```
