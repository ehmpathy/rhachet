# case=5 — an old brain adapter's write by name stays in the repo

**feel × care** = happy × critipath · cell: g.readonly × b.inside × r.{file,absent} × a.repo-legacy × f.none × k.solo × c.init

🔴 **this is the cell #661 reports.** the reporter's repo pins `rhachet-brains-anthropic@0.4.3`,
whose hooks dao writes `.claude/settings.json` by name with `fs.writeFile`, so it follows the grove
arrow to home. an adapter that writes `settings.of.repo.json` never followed the arrow, so cells
with a current adapter never reproduced the defect on the old build. found at verification:
acceptance case10 (0444 home) and case11 (writable home), red on rhachet 1.48.0 and 1.49.1

## .narrative

lee maintains a repo that still pins `rhachet-brains-anthropic` 0.4.x, whose hook adapter writes
`<repo>/.claude/settings.json` by name — and in the layout that name is the arrow to lee's 0444
home file. lee runs `pnpm install`. the hooks land, init exits 0, and lee's home file is the same
bytes it was. lee never learns there was a shield in between; the only line that touches home is
the read-only note from case=1.

(beneath lee's walk: the shield swaps the arrow for a real copy, lets the old adapter write it,
folds the hooks into `settings.of.repo.json`, and relinks the arrow.)
