# 1.vision.experience.dimensions

the axes along which one brain dir's turn in `rhx init --hooks` (or `rhx upgrade`) varies.

| # | dimension | positions |
|---|---|---|
| G | the grove state this brain dir's `settings.json` reaches | `g.writable` (arrow → a writable home file, clean) · `g.polluted` (arrow → a writable home file that already holds this repo's role hooks, written by a pre-v1.49.2 build) · `g.readonly` (arrow → a 0444 home file) · `g.absent` (arrow → an absent home file) · `g.legacy` (a real `settings.json` in the brain dir, from before the layout) |
| B | where the brain dir really sits | `b.inside` the repo · `b.outside` (it, or a parent under the repo, is a symlink out) |
| R | what sits at the brain dir's `settings.of.repo.json` name | `r.file` (a real file) · `r.absent` · `r.arrow` (a symlink, to anywhere) |
| A | which actor, and so which writers run | `a.repo-current` (the repo actor; root sync by a current adapter, then the derivation) · `a.repo-legacy` (the repo actor; root sync by an adapter that writes `settings.json` by name, under the shield) · `a.enrolled` (a hash, slug or derived actor; the derivation only) |
| F | a fault inside the repo | `f.none` · `f.fs` (EACCES / EPERM / EROFS on a repo path) · `f.defect` (a code bug, e.g. a TypeError) |
| K | concurrency | `k.solo` · `k.peer-init` (a second `rhx` writes the same brain dir) · `k.peer-swap` (a peer repoints the brain dir link between the guard's probe and the write) |
| C | the caller | `c.init` · `c.upgrade` |

## .why these

- G is the wish's scene (a link to a home file) and its silent twin (writable), its aftermath
  (polluted), and the two shapes an older box may hold (absent, legacy)
- B is the one shape in which a write can still leave the repo on main — every write lands by name
  inside the brain dir, so only the dir can point out
- R is the one file the derivation writes, and the one name in a brain dir that could itself be
  an arrow out while the dir sits inside
- A carries the one writer core does not own (a legacy adapter), which runs only for the repo actor
- F is the error-print half of the wish
- K surfaces the race the guard's probe-then-write leaves, and the peer write the mutexes cover
- C: both callers run the same two brain-dir phases (`execUpgrade.ts:362`
  `syncAndReportBrainDirBoots`, `:390` `syncHooksForLinkedRoles`)

## .orthogonality

- G was once two axes (the chain end, the home mode); one implied the other, so they are merged.
  each G position is now one box state, and every G × B × R × A × F × K × C combination can exist
- R is independent of the rest: what sits at `settings.of.repo.json` is set by whoever last
  touched that one name in the brain dir (a human, a role init, a prior run). it implies no grove
  state (G concerns `settings.json`, a different name), no dir placement (B), no actor kind (A), and
  no fault or race
- `g.polluted` was once a separate "box history" axis with one live cell; it is a G position now
- A: a legacy adapter writes only in the root sync, which only the repo actor gets, so it is a
  position of A, never a separate writer axis that would make `enrolled × legacy` impossible

## .scoped out, with why

- **who runs it** (a human at a terminal vs a ci job with no human): the output and exit code are
  identical; only the reader differs. a ci log holds the same `⚠️` and `💥` lines. so it varies no
  experience the product does not already hold, and is not an axis
