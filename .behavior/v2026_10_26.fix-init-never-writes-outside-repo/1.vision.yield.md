# 1.vision — rhachet init never writes outside the repo, and every hook sync error prints

## .the outcome world

### a day in the life

a human keeps `~/.claude/settings.json` at 0444, so no tool may edit their box-wide claude config
behind their back. they clone a repo and run `pnpm install`. `prepare` runs `rhachet init --hooks`.

```
🧢 apply hooks to enrolled actors...
   ├─ hash=7dcf1989: +3
   └─ repo=ambient

⚠️ left a read-only file outside the repo untouched
   ├─ path = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude/settings.json
   ├─ lands at = /home/kai/.claude/settings.json (read-only)
   └─ rhachet never writes outside the repo; the actor's hooks live in its settings.of.repo.json

✨ hooks
   └─ no changes needed
```

exit 0. `~/.claude/settings.json` holds the same bytes it held before. the warn the wish asks for
prints once per run per outside target (every actor's arrow reaches the one grove, so it prints
once, not once per actor or per role). it reports a fact the human cares about — the file they
locked was reached and left alone — not a fault.

a second day, a broken one: an actor dir is read-only after a bad `chown`. init cannot write it.

```
🧢 apply hooks to enrolled actors...
   ├─ ✗ hash=7dcf1989: ✋ ConstraintError: actor settings could not be written (EACCES)
   │  ├─ roles = driver, learner, behaver, dispatcher, mechanic
   │  ├─ path = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude
   │  └─ hint = restore write access to that dir, then rerun `rhx init --hooks`
   └─ repo=ambient

💥 MalfunctionError: 1 hook sync error — role hooks may be uninstalled
```

exit 1, and the reason sits on screen above the exit: which actor, which roles, which path, which
fix.

🟡 on main today the row reads `✗ hash=7dcf1989: Error: EACCES: permission denied, open '<abs path>'`
with no hint beneath it: `asErrorHintOrNull` reads a hint only off a `HelpfulError`, and a raw fs
error is not one. the row prints — so the fault is not silent — but the fix is not named. the
wrap above is owed (see .the contract).

### before / after

| | before (rhachet as installed in the report, pre-v1.49.2) | after |
|---|---|---|
| where actor hooks land | `brain/.claude/settings.json` by name, which follows the grove arrow into `~/.claude/settings.json` | the actor's own `settings.of.repo.json`, inside the repo |
| a read-only home settings file | EACCES once per role, init exits 1 | untouched, one `⚠️` note, init exits 0 |
| a writable home settings file | silently gains the repo's hooks, box-wide | untouched |
| an actor-pass fault | pushed to `errors`, never printed; `ELIFECYCLE exit code 1` alone | its row, its roles, its path, its hint, then the one `💥` header |
| a write whose real target sits outside the repo | follows the arrow | refused at the writer, with a named `⚠️` warn; the outside file is untouched |

### the aha

the 0444 file was never the defect. it was the alarm. a human with a writable home settings file
had the same write land silently, box-wide, in every claude session they run. the fix is not
"handle EACCES"; it is "the write never aimed there".

## .the contract

### the write guard

one rule, checked once per brain dir, before init writes into it:

> **before init writes into a brain dir, compute that dir's realpath. a brain dir whose realpath
> sits outside the repo is not written at all: init skips it and emits a named warn.**

- **why the dir, not each file**: every write init makes into a brain dir (the boot render's
  `boot.md`, the layout findsert's arrows and `{}` seed, `settings.of.repo.json`) lands by name
  inside it, and each by temp + rename, which replaces whatever sits at the name and never follows
  it. so the dir is the one part that can leave the repo, and one check per dir covers every
  writer — including a writer added later
- **where it runs**: inside the brain-dir writers' shared entry points, so no phase can skip it.
  init reaches a brain dir through three phases, and each calls one of these:

  | phase | entry it reaches | the writes beneath it |
  |---|---|---|
  | the pre-init layout (`setRepoActorBrainDirLayoutBeforeInits`, before role inits) | `setBrainDirSettingsLayout` | arrows, the `{}` seed |
  | the boot render (`syncAndReportBrainDirBoots`) | `setBrainDirBoot` (→ `setBrainDirPointerFiles`), `setBrainDirSettingsLayout` | `boot.md`, `AGENTS.md`, arrows, seed |
  | the hook sync (`syncHooksForLinkedRoles`) | `withBrainDirSettingsShield`, `setActorSettingsDerived` (→ `setBrainDirSettingsLayout`, `writeClaudeCodeSettings`) | the shield copy and fold, `settings.of.repo.json` |

  so the guard sits at four entries — `setBrainDirSettingsLayout`, `setBrainDirBoot`,
  `withBrainDirSettingsShield`, `writeClaudeCodeSettings` — one helper, and any phase added later
  that reaches a brain dir passes through one of them. a skip at an inner entry still surfaces to
  the phase as a named warn, never a silent no-op
- **both sides are realpaths**: the brain dir's realpath is compared against the repo root's
  realpath (`context.gitroot`), never the raw path — a repo that itself sits under a symlinked
  parent (`/home` → `/mnt/home`) would otherwise read every brain dir as outside
- **the warn** is `⚠️`, never `✋` or `💥`: the human's box is in a shape rhachet must not
  touch, and naught is broken for the repo. it names the path, where it lands, and the fix:

```
⚠️ skipped a write outside the repo
   ├─ path = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude
   ├─ lands at = /home/human/dotfiles/claude
   └─ hint = point that dir back inside the repo, then rerun `rhx init --hooks`
```

- **a skip is not an error**: it is not pushed to `errors`, so it does not set exit 1. the wish
  asks for exit 0 with a visible warn

### the read-only note

> **when a brain dir's `settings.json` arrow reaches a read-only file outside the repo, init prints
> one `⚠️` note per distinct target per run, and writes naught there.**

- the wish's proof names this warn, so it is owed even though no write aims at the file: it tells
  the human the file they locked was reached and left alone
- read-only only, per the wish: a writable grove (case=2) is untouched with no line, since a line
  on every healthy run would teach the human to skim `⚠️`
- it is a probe (`lstat` + `realpath` + an access check), never an open for write; it is not an
  error and does not set the exit code

### the error print

> **every entry in `syncHooksForLinkedRoles`' returned `errors` has printed a row before the
> function returns.** the one `💥` header follows the last row.

on main this already holds by construction (the header prints after the actor loop,
`syncHooksForLinkedRoles.ts:262–266`). the vision adds the clamp that keeps it: a test that fails
if any pushed error lacks a printed row.

### the actor fault wrap

> **an fs fault in the actor pass is wrapped in a `ConstraintError` that carries the actor, its
> roles, the path, the errno, and a hint; the raw error rides as its `cause`.**

- the wrap applies to the errnos a human fixes on their own box (EACCES, EPERM, EROFS); other
  errnos keep their raw class, so a malfunction is not relabelled as a caller fault
- the row prints `roles = …`, `path = …` and `hint = …` as subbranches beneath it. the extant
  `hint: …` render in `asEnrolledActorsHookSyncLines` is repaired to `hint = …` on the way
  through (`rule.forbid.colons-in-stdout`)
- **the roles**: the wish asks each error to name its role. on main one derivation writes one file
  for all the actor's roles, so one fault is shared by them all. the row names every role of the
  actor once, in one subbranch — never one row per role, which would repeat one fault N times, the
  noise the report described ("once per role")

## .mental model

how a human would say it: *"rhachet only writes inside the repo. if a path in the repo points out of
it, rhachet tells you and leaves it alone."*

the analogy: a house-sitter who waters the plants inside your house. if a hose runs out the window
to the neighbour's garden, they do not follow it — they leave a note on the counter.

| a human says | we say |
|---|---|
| my global claude settings | the grove, `~/.claude/settings.json` |
| the actor's settings | the actor's `settings.of.repo.json` |
| a link out of the repo | a write target whose realpath sits outside the repo |
| it failed and said naught | a fault pushed to `errors` with no printed row |

## .evaluation

**goals**

| goal | met by |
|---|---|
| every hook sync error prints, with actor, role and path | the row per fault (already on main) + a clamp that holds it + the actor fault wrap (roles, path, hint) |
| init never writes through a link out of the repo | the core writers already aim inside; the guard makes it a checked invariant |
| a 0444 grove: exit 0, visible warn, file untouched | exit 0 and untouched hold on main; the read-only note supplies the warn |
| a clamp red without the fix, green with it | case=1 against the pre-#600 build; case=4 against main without the guard — fulcrum F2 |

**pros**: the guard closes the class, not the instance — a future writer, a role init, or an old
adapter that aims out of the repo meets it. the human's box is untouched whether or not they chose
0444.

**cons**: a realpath per write (cheap, a handful of files per init). a human who DID mean a brain
dir to live outside the repo (a dotfiles symlink) now gets a skip; the warn names the fix.

**edgecases and the pit of success**

| edge | outcome |
|---|---|
| `settings.json` → grove → absent home file | untouched; no write aims there |
| `settings.of.repo.json` itself is an arrow out of the repo | the layout findsert refuses a symlink at that name (`define.brain-dir-layout-is-one-for-every-actor`: "refuses a symlink or a dir at that name"), so init fails loud before any write; the outside file is untouched. verdicted in `case=_` slice 2 (checked in code: `setBrainDirSettingsLayout.ts`, `statRepo && !statRepo.isFile()` → `ConstraintError`) |
| `brain/.claude` dir is an arrow out of the repo | the guard skips, warns (case=4) |
| `<repo>/.claude` → the repo actor dir | inside the repo; writes proceed |
| a worktree, whose repo actor dir sits inside the worktree | inside the repo; the bound is `context.gitroot`, never the main checkout |
| a code defect (a TypeError) in the actor pass | still throws loud; not a fault row (`isCodeDefectError`) |

  (temp + rename). the report came from a pre-v1.49.2 install: `ahbode/app-storefronts-web`
  pins `"rhachet": "1.48.0"` (its `package.json` on `origin/main`, read via `rhx git.repo.get`),
  and the report's row `├─ 7dcf1989` is the old bare-hash render, where main renders
  `hash=7dcf1989`. 🟡 that main passes the scene is read from code, not yet run; case=1's clamp
  is the measurement
- **[answered]** so does "upgrade rhachet" alone fix the report? — for the reported path, yes by
  the code. the wish still owes the clamp (the proof), the class-wide guard (case=4), and the hint
- **[answered]** does main print the `💥` header before the actor loop? — no. it prints once,
  after every phase (`syncHooksForLinkedRoles.ts:262–266`); actor faults render as rows via
  `asEnrolledActorsHookSyncLines`
- **[answered]** the wish asks a 0444-grove init to "print the warn", though on main naught aims at
  the grove. — the warn is kept: the wish states it as part of its proof, and a vision may not
  narrow a stated requirement (`rule.forbid.dropped-behavioral-requirements`). it is shaped as a
  note on a fact — the locked file was reached and left alone — once per target (F1, conceded)

  all its roles. — kept: the row prints every role of the actor once, in one subbranch
- **[wisher]** "red without the fix": the fix that closed the reported path already shipped. best

## .what is awkward

- **the fix already shipped.** #600 closed most of the wish's mechanism. this behavior's weight is
  the clamp and the guard — proof and a class-wide invariant — not a repair. a reviewer who reads
  the diff will find little production code changed, and that is correct
- **"red without the fix" fights the timeline.** a clamp written today against main is green on
  its first run. the red half needs the old build (F2)
- **the warn the wish names has no write to report** in the 0444-grove case. it is kept, as a note
  on what was left alone rather than an alarm; a human who reads it every install may come to skim
  it
- **the guard's realpath is a probe, then a write.** a peer that repoints a link between the two
  could slip past it. verdicted in the inventory as an accepted risk (`case=_` slice 7): the
  threat is a misconfigured box, not an adversary
