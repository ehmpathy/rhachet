# case=5 · relock wins

the sharp critipath with security weight. a renew must never resurrect a key a human relocked.

## .narrative

a renew starts: it reads the camp grant and begins the silent proof, which takes a few seconds.
meanwhile the human runs `rhx keyrack relock`. the store drops the grant. then the silent proof
returns "live". if the renew now wrote its grant back, the human's relock would be undone in
silence, with credentials still live: a surprise with security weight
(`daemonKeyStore.ts:121-124` already argues that a token which outlives an explicit relock is
unacceptable).

so the renew writes back only if the grant it read is still the one in the store. a relock
removed it, so the renew drops its result. the key stays locked.

## .fail-safe

- **safe by construction** — the write-back is conditional on the grant it read; a relocked key
  has no grant to match.
- **no record to clean** — a relock also clears the daemon's renew record for that key, so no later
  tick picks it up.

## .timeline

```
given('[case1] an sso grant mid-renew')
  when('[t0] a relock lands before the silent proof returns')
    then('the renew does not write the grant back')
    then('keyrack get reads the key as locked')
  when('[t1] the next renew tick runs')
    then('no renew fires for the relocked key')
```
