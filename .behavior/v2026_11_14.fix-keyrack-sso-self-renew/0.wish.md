# wish: keyrack renews an aws sso key before it expires, from the live sso session

## outcome

a key the keyrack daemon holds via aws sso (for example ahbode.camp.AWS_PROFILE) stays live past its role session expiry with no hand unlock, for as long as the human's sso portal session is live. every consumer of the key keeps its access across the expiry; the live one is grove 0901's tunnel, whose reconnect needs the camp creds.

## evidence

- 11-09, midday: `rhx keyrack status --owner ehmpath` read ahbode.camp.AWS_PROFILE as expires in 20m.
- `rhx keyrack unlock --owner ehmpath --env camp` then renewed it silently from the live sso session (expires in 55m), with no browser. so the silent path exists; no one fires it before expiry.
- 0901 went dark overnight 11-08 to 11-09 and came back only by a hand camp unlock.
- when the sso portal session itself has lapsed, the unlock waits ~45s on a browser prompt and fails (exit 2). a renew must never hang there on each interval; it names the lapse once, where `keyrack status` shows it.

## done

- the daemon renews each sso key before expiry, silent path only; `keyrack status` shows the renew and any lapse
- a test clamps it: red without the renew, green with it
- proven live: ahbode.camp.AWS_PROFILE passes two expiries with no hand unlock
