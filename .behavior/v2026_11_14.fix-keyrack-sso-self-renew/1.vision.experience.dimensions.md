# 1.vision.experience.dimensions

the experience space of "the daemon renews an sso grant before it expires", factored into
orthogonal dimensions. each axis is a closed set.

## .the dimensions

| dimension | positions | why it varies the experience |
|---|---|---|
| **actor** | consumer (a process that runs `keyrack get`, e.g. 0901's tunnel) · human (`keyrack status`, `unlock`, `relock`) · bot (a clone that reads `status` and runs the printed fix) | the consumer only feels access kept or lost; the human feels the record of it; the bot acts on the record, so a fix it cannot finish must say so |
| **portal session** | live · lapsed | the one fact the silent path depends on |
| **grant at the tick** | outside the renew window · inside it · past expiry (daemon slept) | decides whether a renew fires, and whether a gap was felt |
| **unlock cap** | ahead · reached · absent (the unlock sent none) | the human's own bound on the key's life (fulcrum F1); absent means renew was never opted in |
| **fault** | none · transient (a blip a later tick clears) · persistent (an unclassified error that holds for a full window, 10 ticks) | separates a lapse from a blip, and a blip from a stall |
| **concurrency** | none · a consumer `get` mid-renew · a hand `unlock` mid-renew · a `relock` mid-renew | a renew writes the store; one read and two human verbs touch it too |
| **renew record** | active · marked (`lapsed` or `halted`) | a marked key takes no more renews and is named in status (fulcrum F5) |
| **mech** | EPHEMERAL_VIA_AWS_SSO · any other | only sso has a silent path |
| **build** | cli and daemon match · new cli, older daemon · older cli, new daemon | one long-lived daemon serves every repo on the host, so the cli that unlocks and the daemon that renews can differ |
| **fault locus** | the portal · the daemon's own env · the renew code | decides the cure: a fresh session, a respawn, or a fix to the code |
| **rack** | the default rack · a named owner rack (`--owner`) | each owner has its own daemon, so a printed fix must name the rack it cures |

🟡 `build` and `fault locus` were found at execution, past the vision. `build ≠ match` collapses every other axis (c17, c18); `fault locus` splits only c14 (c19, c20). a hang (c21) and an expiry that does not advance (c22) are fault positions the execution named.

## .the walked product

the full product is 2 × 2 × 3 × 3 × 3 × 4 × 2 × 2 = 1728 cells. most collapse:

- **mech = other** collapses every other axis to one forbidden cell (c12): the renew selects on `source.mech`.
- **cap = absent** collapses every other axis to one cell (c15): the key was never opted into renew, so it behaves as today.
- **cap = reached** collapses portal, grant, fault, concurrency, record: no renew fires, so they cannot vary the outcome (c8).
- **record = marked** collapses portal, fault, grant: no renew fires on a marked key. only the human verbs vary it: an `unlock` replaces the mark (c11), a `relock` clears it (c6 tail).
- **portal = lapsed** collapses fault and grant: the silent proof answers `{ valid: false }` whatever the grant's state; a transient blip amid a lapse is retried, then lands on lapse (c4 → c5). inside the window the consumer keeps access until expiry; past expiry (a sleep through both the expiry and the portal's end) the consumer already felt the gap, and the first tick after wake marks the key lapsed. the human sees the same `lapsed` branch either way.
- **grant = outside window** collapses portal, fault, concurrency: no renew fires (c10).
- **concurrency** collapses under every cell where no renew is in flight (outside window, cap reached or absent, record marked): with no write in flight there is no race. where a renew is in flight:
  - a consumer `get` inside the window reads either the old grant or the new one, both live; a stale-but-valid read is harmless, so it collapses to its row's outcome (c16)
  - a consumer `get` past expiry reads locked until the write-back lands: the store already purged the old grant. that is the tail of the gap the sleep opened, a few seconds longer, and it self-heals on the write-back; it collapses into c3
  - a hand `unlock` or a `relock` is decided by the conditional write-back alone, whatever the portal or fault: the renew writes only if the grant it read is still stored (c6, c7)
- **fault** under portal live collapses `grant = inside window` and `grant = past expiry` into one rule, since the fault count, not the grant's state, decides the outcome:
  - transient → retried next tick; the next success renews (c9). past expiry, that renew ends the gap one tick later than a clean wake
  - persistent → retried each tick; after 10 consecutive failures the key is marked `halted` (c14). inside the window that lands at about the grant's expiry; past expiry it still grants 10 tries, so a blip at wake never halts a key
- **actor** splits each distinct cell into what the consumer feels and what the human sees; the inventory carries both in one row.

the distinct cells that remain are inventoried in `1.vision.experience.case=_.md`.
