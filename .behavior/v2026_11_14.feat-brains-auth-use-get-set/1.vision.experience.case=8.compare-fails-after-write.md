# case=8 — the compare fails, or would

feel = sharp · care = critipath · cell = `use × any × after ≠ target` (forbidden as success)

## .narrative

the human swaps the grove to b@. an env var such as `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`
outranks the stored login, so no swap of the grove file would reach a clone that inherits this env.
the command reads only the env to know this, so it refuses first: before any read, mint or write,
with the key to unset. the fix is the caller's env, so it is a constraint (exit 2).

where the write lands but the read back names some other account, even the same email in another
org, the command never reports success on the write's exit code. it fails loud and names what
landed instead. where the read back gets no answer at all, it says the use landed but is
unverified: a claim of "did not land" would be as false as a claim of success.

## .[tn]

```
given the grove on a@, and an env credential that outranks the stored login
  when [t0] `rhx brains auth use --account b@example.com --scope grove`
    then exit 2 with `✋ ConstraintError: use did not land`
    then stderr shows `target = b@`, the outranker it found, and `unset <key> where clones spawn`
    then the grove file still holds a@, b@ stays parked, and naught is minted
    then the success line is never printed

given the grove on a@, and a read back that names an account other than b@
  when [t0b] `rhx brains auth use --account b@example.com --scope grove`
    then exit 1 with `💥 MalfunctionError: use did not land`
    then stderr shows `target` and `after` by email and org, e.g. `b@ in org-b` vs `b@ in org-other`

given the grove on a@, and a read back the provider does not answer
  when [t0c] `rhx brains auth use --account b@example.com --scope grove`
    then exit 1 with `💥 MalfunctionError: use landed, but its read-back could not be verified`
    then the grove holds b@ and a@ is stowed; a retry reports `unchanged` once verified

given the grove on a@, and a live clone that rewrites `.credentials.json` while b@ is minted
  when [t1] `rhx brains auth use --account b@example.com --scope grove`
    then the compare-and-swap sees the file changed and aborts before install
    then b@'s rotated refresh token is refiled to b@'s keyrack slot, so b@ stays usable
    then exit 1 with `💥 MalfunctionError: grove login changed mid-swap`; the hint says retry
    then the grove file is whatever the clone wrote; no token is lost
```
