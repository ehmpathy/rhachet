# case=5 — an absent or dead credential

feel = sharp · care = critipath · cells = `get|use × any × absent|dead`

## .narrative

the human types `rhx brains auth use --account c@example.com --scope grove`, but c@ was never set.
the command refuses before it touches the grove, lists the accounts it does hold, and names
`rhx brains auth set` as the way to add c@. later, b@'s seat lapses; `get` still renders a@'s row
and marks b@ `dead`, with the same fix named.

## .[tn]

```
given stored accounts a@ (fresh) and b@ (dead: refresh revoked)
  when [t0] `rhx brains auth use --account c@example.com --scope grove`
    then exit 2 with `✋ ConstraintError: no stored credential for c@example.com`
    then stderr lists a@, b@ and the hint `rhx brains auth set --brain claude`
    then the grove is untouched (before = after)
  when [t1] `rhx brains auth use --account b@example.com --scope grove`
    then exit 2; the hint names `rhx brains auth set` to re-login b@; the grove is untouched
  when [t2] `rhx brains auth get`
    then a@'s row renders in full; b@'s row reads `dead` with the same hint; exit 0

given the grove's access token has expired, so the signed-in account cannot be proven without a refresh
  when [t3] `rhx brains auth use --account a@example.com --scope grove`
    then exit 2 with `✋ ConstraintError: the grove's signed-in account is unverified`
    then stderr names the name `.claude.json` claims, and says why it is not trusted
    then the hint names how to prove it (any claude session on the box refreshes the login)
    then naught is minted, written, or stowed
```
