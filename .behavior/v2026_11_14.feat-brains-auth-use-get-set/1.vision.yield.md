# 1.vision: rhx brains auth set | get | use

## the outcome world

### before

- usage lives outside rhachet: a human runs dev-env-setup `brains.auth.usage` to see which paid
  claude account has headroom before its reset
- a swap is a hand oauth handshake per grove (`rhx git.grove.auth`, or `/login` in a session)
- an account whose week resets tomorrow with 60% unspent just lapses, because no one looked

### after

- `rhx brains auth set` — log an account in once, in an isolated browser login; its refresh token
  lands in the keyrack, filed by the account's email. never on stdout, never in git
- `rhx brains auth get` — per stored account: the session and week windows, each with its used
  share, its reset, and the saved resets (reset grants) left
- `rhx brains auth use --account <email> --scope grove|tree|clone` — point a scope at that account,
  proven by a before/after compare of (email, orgId) read back from the scope

### a day in the life

at dawn the human runs `rhx brains auth get`:

```
🧠 brains auth get --brain claude
   ├─ a@example.com  ← signed in (grove)
   │  ├─ session  █████████░  92% used · resets in 2h41m
   │  ├─ week     █████████░  91% used · resets in 6h
   │  └─ saved resets = 1
   └─ b@example.com
      ├─ session  ██░░░░░░░░  18% used · resets in 4h10m
      ├─ week     ██░░░░░░░░  18% used · resets in 4d
      └─ saved resets = 0
```

a@ is spent; b@ has a week left. the human runs `rhx brains auth use --account b@example.com
--scope grove`:

```
🧠 brains auth use --account b@example.com --scope grove
   ├─ before = a@example.com (org 4f1c…)
   ├─ after  = b@example.com (org 9e02…)
   ├─ a@example.com stowed in the keyrack
   └─ live sessions on a@ until their next login read
      ├─ @:driver
      └─ @:reviewer
```

every new clone on the box now spends b@. no browser opened.

### the aha

the read and the swap share one noun, the account, and every write is proven by a read. so the
#575 pool rotation is a loop with no human: `get --output json`, sort by soonest reset, `use` the
first account with headroom.

## the contract, sketched

| verb | flags | writes | proof |
|---|---|---|---|
| `set` | `--brain claude` (default) · `--owner` | keyrack key `BRAINS_AUTH__OF__CLAUDE_CODE_OAUTH_TOKEN` at reach = the account email | `/api/oauth/profile` names the email; stdout shows email + orgId, never the token |
| `get` | `--account <email>\|@all` (default `@all`) · `--output tree\|json` | the rotated refresh token, back to its keyrack slot | per-window values match `brains.auth.usage` |
| `use` | `--account <email>` (required) · `--scope grove\|tree\|clone` (required) · `--clone @:<slug>` when `--scope clone` | grove: `~/.claude/.credentials.json` under `withBrainAuthWriteLock`; the prior account stowed into its slot, last | `before` and `after` read back from the scope; exit 0 only when `after = target` |

- exit codes: 0 landed · 1 our fault (rotation not stored, compare failed) · 2 the caller's to fix
  (absent or dead account, no human for `set`, bad flag)
- the per-brain knowledge (endpoints, client id, credential file shape) lives in a brain auth
  adapter keyed off the brain command table, so `brains auth` reads "through the BrainCli" and a
  second brain can plug in later

## mental model

- to a friend: "a keychain for my claude seats. it shows which seat still has juice before it
  resets, and hands that seat to the whole box, one repo, or one clone"
- analogy: a dual-sim phone. `get` is the data meter per sim; `use` picks which sim the calls go out
  on; a call already in progress stays on its sim until you hang up
- their words vs ours: *seat / account / login / swap* vs *credential / set / use at a scope*. the
  cli speaks *account* in output and takes the email as the address

## evaluation

### against the done-when

| done when | how the vision meets it |
|---|---|
| `get` shows the same windows as `brains.auth.usage` | case=2 `[t0]` asserts parity per account |
| `use` proven by before/after (email, orgId) | case=3, case=4 read `after` back from the scope; case=8 fails loud when it differs |
| `set` keeps the credential in the keyrack, never printed or committed | case=1 asserts no token on stdout and none under the repo |
| tested against two real subscriptions | a@ and b@ through every demo; owed at verification as a real-account test |

### pros

- one noun, three verbs; #575 composes on `get` + `use` with no browser
- every write is proven by a read, so a silent no-op cannot pass as success
- grove scope reuses what exists: the shared login, its write lock, the env-outranks check
- the keyrack reach axis already files one key per claude account

### cons

- the usage endpoint is undocumented, and its pinned user agent drifts; `get` has no fallback
- each read rotates the stored token, so a dropped write strands an account (case=9)
- a live session keeps its old account until its next login read; a swap is not instant everywhere
- a live session can still refresh the old account's token after `use` stows it, which would strand
  that account (case=7); the stow must wait for, or warn about, live sessions
- clone and tree scopes have no mechanism today and cut against the one-login design (#571)

### pit of success

- `use` refuses before any write when the account is absent or dead (case=5)
- `use` refuses success when the read back disagrees, and names the outranker (case=8)
- `set` refuses at once without a human rather than hang on a browser (case=6)
- `get` renders every readable row even when one row is dead (case=5 `[t2]`)
- `get` never refreshes the signed-in session's token (case=9)
- `use` with no `--scope` refuses and lists the three, rather than guess a blast radius

- a3. **[answered]** grove = the box (`~/.claude`); tree = a repo on it; clone = one clone of an actor — verified
- a4. **[research]** (r3) a live clone moves to the new account at its next read of the shared login — this repo
  says clones read and refresh that file and recover on a refill with no respawn
  (`invokeEnroll.ts:560-564`, `assertBrainAuthNotDead.ts:33`); dev-env-setup says open sessions
  keep the old token until restart. **the two disagree; owes a probe** (case=7)
- a5. **[wisher]** (q2) "saved resets" = the reset grants the plan banks (`cedar_ember.grants`) — best guess, F4
- a6. **[research]** (r4) `/api/oauth/profile` returns an org id beside the email, so the compare the done-when names
  (email, orgId) has both halves. **unverified**: the research saw the email read, not the org read,
  and no code here reads an org field. fallback: `~/.claude.json` `.oauthAccount` for the grove.
  owes a probe at blueprint, since requirement case=11 rests on it
- a7. **[research]** (r5) one email names one account. **may be false**: one email can sit in a personal plan and a team
  org at once. if so, a slot keyed by email alone lets a second `set` overwrite the first. guard:
  `set` reads (email, orgId) from the profile and refuses to overwrite a slot whose stored orgId
  differs, and names the clash; the address widens to email + org only if the probe finds it real
- a8. **[wisher]** (q5) the keyrack the tokens live in. prior art files them under owner `ehmpath`, env `prep`, org

  human's own seats may belong in the human's keyrack instead. asked (q5)

## groundwork

### external research

- `POST https://platform.claude.com/v1/oauth/token` (`grant_type=refresh_token`, claude-code client
  id, `anthropic-beta: oauth-2025-04-20`): returns a short-lived access token and a NEW refresh
  token that kills the old one. source: uladkasach/dev-env-setup
  `src/grove.provision/2.shell/2.7.aliases/brains.auth.sh`
- `GET https://api.anthropic.com/api/oauth/usage?cedar_ember=1&at_wall=1`: `five_hour` and
  `seven_day` as `{ utilization, resets_at }` (null = the plan has no such limit), plus
  `cedar_ember.grants[]` for saved resets. undocumented; the user agent `claude-cli/<v> (external,
  cli)` is load-bearing; a `claude setup-token` token is rejected here. source: same file and its
  `briefs/creds/hazard.claude-*.md`
- `GET https://api.anthropic.com/api/oauth/profile`: the email and org of a token. source: same
- the #324 spike (ehmpathy/rhachet, open, unmerged) never read real windows; its capacity read was
  a placeholder, and its setup-token finding is overturned by the above. re-derived, not reused

- no domain object for an account, a usage window, or a reset grant yet

## what is awkward

- *scope* names three grains, and two of them (clone, tree) fight the one-login design. grove is
  natural; the other two are the open fulcrum (q1, F1)
- `get` writes. a read that rotates a token is a surprise to anyone who expects `get` to be pure;
  the output and the help must say so, and the pool must not poll faster than every 5 minutes
- the "signed-in" account is not in the keyrack while it is active (its token lives in the grove
  file), so `get` reads it a different way than the rest
- `set` can never run without a human, so the pool can only rotate among accounts a human set
- fulcrums → `.fulcrums/inventory.of=fulcrums._.md`
