# case=10 — the pool rotates with no human

feel = happy · care = critipath · cells = `pool × get → pick → use grove` (the densest walk)

status = each step this PR owns is built and proven against an injected provider: the json read
(`getAllBrainAuthUsage.integration [case1]`), the grove swap and its json
(`setBrainAuthAccountInUseAtGrove.integration`, `asBrainAuthUseJson.test`), the `unchanged` retry
(`[case2]`), and the lapsed-grove refusal (`[case7]`). the pick and the hourly loop are #575's. the
proof on real seats is owed with F6.

## .narrative

it is 3am. the #575 pool loop wakes on its hourly tick. it runs `rhx brains auth get --output json`,
sees a@'s week `capped` at 100% with its reset in 40m, b@ at 30% with its reset in 2d, and c@ at
10% with its reset in 5d. a@ resets soonest, but it is capped, so the loop picks b@: the soonest
reset that still has headroom. it runs `rhx brains auth use --account b@example.com --scope grove`. the
read-back says `after = b@`. the loop logs the swap and sleeps. at dawn the human finds the box on
b@, a@ fresh after its reset, and no clone idled on a capped account overnight.

no human was present at any step, so every slip must fail loud to the loop's log and leave every
account usable.

## .[tn]

```
given a@ (week capped at 100%, resets 40m), b@ (30%, resets 2d), c@ (10%, resets 5d); grove on a@; no tty
  when [t0] `rhx brains auth get --output json`
    then json lists each account with `session` and `week` as { usedShare, resetsAt } and savedResets
    then each stored refresh token was rotated and written back (case=9)
  when [t1] the loop picks the soonest reset with headroom (b@) and runs
       `rhx brains auth use --account b@example.com --scope grove --output json`
    then json holds { before: a@, after: b@, landed: true }
    then exit 0 only because after = target
  when [t2] the same tick runs again 5 minutes later
    then `use` reports `unchanged` (already on b@); no token is minted, no write

given the same pool, and an idle box: no claude session has run for over an hour, so the grove's
access token has lapsed
  when [t3] the tick runs `get`, then `use`
    then `get` shows the signed-in row `unverified`, with no windows; the stored rows still read
    then `use` refuses, exit 2, `the grove's signed-in account is unverified`; naught is minted
    then the loop cannot clear this alone: any claude session renews the login (F19, for the
         commander: whether a lapsed signed-in token may ever be refreshed)
```
