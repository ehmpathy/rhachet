# 5.3.verification — handoff v1, to the foreman

two walls stand. each needs a key or a call only the foreman holds. all else in 5.3 is green
(`5.3.verification.yield.md`).

## wall 1 — F6: the two-real-seat proof

### .what is owed

the wish's done-when: `use` proven landed by a before/after (email, orgId) compare, and every verb
tested against at least two real claude subscriptions (`inventory.of=requirements.case=27`,
`case=28`).

### .what was tried

| approach | result | why it does not close the wall |
|---|---|---|
| integration over an injected provider context (`genMockedContextBrainAuthAccount`) | 107 brain/auth integration tests green: set, get, use at grove, the compare, the stow, the abort refile, drift, the outranker | it proves our code against our model of the provider, never against the provider |
| acceptance through a real pty (`[case9]` t0–t3), no seat | every refusal leg of `set` walked and snapped | the positive legs need a real login in a real browser |
| acceptance on an empty home, a lapsed home, an outranker env | `get`, `use` refusal and unverified legs snapped | the positive `get` row and a landed `use` need a held account |
| this box's own claude accounts | not run, on purpose | a `get` rotates every parked token, and a `use` rewrites the grove login a human works in. one bad run strands a seat. forbidden by the director |
| a loopback-only provider seam (F6 `.two cheaper steps`) | not built | it adds an env seam to prod code; whether that seam is worth its risk is the commander's call |
| `get --account <signed-in>` alone | not run | it spends no seat, but still reads a real account on this box; waits on the commander's word |

### .why it is a foreman key

the seats are accounts. only a human can own them, log them in through a browser, and name which
two may be spent on tests. no code path, credential, or clone can stand in for that.

### .the ask

1. name two claude seats set aside for tests (F6 option A)
2. file each, at a real terminal, into the test keyrack:
   ```sh
   rhx keyrack unlock --owner ehmpath --env test
   rhx brains auth set --brain claude --owner ehmpath
   ```
3. then the driver adds and runs the positive real-seat legs: `get` reads both rows with the same
   windows as `brains.auth.usage`, and `use --scope grove` swaps a → b → a with each compare named

## wall 2 — F1: `use` at clone and tree scope

### .what is owed

the wish names three scopes; `use --scope clone|tree` refuses today with exit 2, a hint that names F1
(acceptance `[case3][t1]`, snapped).

### .what was tried

the mechanism (pin an account per clone or repo, inject a minted token at spawn as
`CLAUDE_CODE_OAUTH_TOKEN`) is designed in F1 and the code is shaped for it
(`setBrainAuthAccountInUseAtGrove` takes the scope as a suffix, `…AtClone` / `…AtTree` slot in
beside it). it is not built, because it trades the one shared login model (#571).

### .why it is a foreman key

only the wisher may trade the one-login model or narrow the stated scopes
(`rule.forbid.dropped-behavioral-requirements`). a driver who builds it, or drops it, decides for
the wisher.

### .the ask

rule F1: build clone and tree scope by spawn-time injection, or narrow this behavior to grove scope
by an amendment of `inventory.of=requirements.case=28`.
