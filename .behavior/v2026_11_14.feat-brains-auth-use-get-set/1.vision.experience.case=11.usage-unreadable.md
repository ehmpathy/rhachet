# case=11 — usage is unreadable

feel = sharp · care = critipath · cell = `get × any × unreadable`

## .narrative

the human runs `rhx brains auth get` on a train with patchy wifi. the endpoint answers for a@ but
times out for b@. the table renders a@ in full and marks b@ `unreadable · server or network`,
which says it is not the human's fault and a retry may help. on another day the endpoint returns
429 for every account; the rows say `rate-limited`, and the exit code tells the pool loop to back
off rather than treat the accounts as dead.

## .[tn]

```
given stored accounts a@ and b@
  when [t0] the usage endpoint answers for a@ and times out for b@
    then a@'s row renders in full; b@'s row reads `unreadable · server or network`
    then exit 0, since at least one account was read
  when [t1] the usage endpoint returns 429 for every account
    then each row reads `rate-limited`; no row reads `dead`
    then exit 1 (not the caller's to fix); the hint says to wait, not to re-`set`
  when [t2] the refresh returns 401 for b@
    then b@'s row reads `dead` (case=5), and only b@'s
```
