# case=9 — a read rotates the stored token

feel = sharp · care = critipath · cells = `get × any × each read` · `get × signed-in account` (forbidden)

## .narrative

the human runs `rhx brains auth get` every half hour all day. each read of b@ trades the stored
refresh token for an access token and a new refresh token; the old one dies at once. rhachet writes
the new one to the keyrack before it reads usage, so b@ stays readable. a@ is the account the
human's own claude session is signed in on; rhachet never refreshes a@'s live token, so that
session never sees a 401. if the keyrack write fails, the command fails loud and names the account
at risk, rather than report usage for an account it just stranded.

## .[tn]

```
given b@ stored in the keyrack, and the grove signed in on a@
  when [t0] `rhx brains auth get`
    then b@'s refresh token in the keyrack differs from before, and still refreshes
    then a@'s live `.credentials.json` refresh token is byte-identical to before
    then a@'s row is read with the live access token, marked `← signed in`
  when [t1] the keyrack write of b@'s new token fails
    then exit 1 with `💥 MalfunctionError: rotated token not stored`, named for b@
    then the new token is never printed; the hint names how to recover b@ (`rhx brains auth set`)
```
