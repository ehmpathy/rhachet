# case=2 — get the usage table

feel = happy · care = critipath · cells = `get × any × fresh|stale × headroom|capped`

## .narrative

the human runs `rhx brains auth get`. for each stored account they see the session window and the
week window: the used share, the reset time, and how many saved resets are left. account a@'s
access token had expired overnight; rhachet refreshed it silently and the row reads like the
others. c@'s week is full: its row reads `capped` beside its reset, so the human sees at a glance
that c@ is unusable until then, not merely low. a@ is 92% spent and resets in 6h; b@ is 18% and
resets in 4d.

## .[tn]

```
given three stored accounts: a@ (stale access token, live refresh), b@ (fresh), c@ (week at 100%)
  when [t0] `rhx brains auth get`
    then one branch per account, each with session + week windows
    then each window shows used share, reset time; each account shows saved resets left
    then c@'s week reads `capped · resets in …`, distinct from a high used share
    then a@'s row is read after a silent refresh; no prompt, no warn
    then the values match what dev-env-setup `brains.auth.usage` shows for the same accounts
  when [t1] `rhx brains auth get --output json`
    then the same data as json, with `capped: true` on c@'s week, for the #575 pool loop
```
