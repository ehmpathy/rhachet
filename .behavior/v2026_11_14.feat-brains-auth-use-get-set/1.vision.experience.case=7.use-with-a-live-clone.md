# case=7 — use while a session in the scope is live

feel = sharp · care = critipath · cell = `use × any × live-reader`

## .narrative

two clones are mid-session in the box when the human swaps the grove to b@. each live clone still
holds a@'s access token in memory, and moves to b@ the next time it reads the shared login (when
that access token expires, or on a 401). the swap kills no one.

the sharp edge: `use` cannot reach into a live session's memory, so it cannot stop a live clone
from a refresh of a@ with the refresh token it still holds. that refresh would rotate the copy
`use` just stowed for a@, and strand a@. so `use` says so, loudly: it names each live clone, names
a@ as at risk until they move, and names the fix — if `rhx brains auth get` later reads a@ as
`dead`, run `rhx brains auth set` for a@.

## .[tn]

```
given the grove on a@, and two live clones in it
  when [t0] `rhx brains auth use --account b@example.com --scope grove`
    then before/after shows a@ → b@ for the grove file
    then a branch lists each live clone as `on a@ until its next login read`
    then a warn line names a@ as at risk while those clones live, and the fix `rhx brains auth set` for a@
    then no live clone is killed or restarted by the swap
  when [t1] a live clone's access token expires and it re-reads the login
    then it reports b@ as its account
  when [t2] a live clone refreshed a@ from memory before it re-read, and `rhx brains auth get` runs
    then a@'s row reads `dead`, with the fix `rhx brains auth set` (case=5); no other row is touched
```

## .note

how a live session reacts is unprobed: dev-env-setup says open sessions keep the old token until
restart; this repo's `assertBrainAuthNotDead.ts` hint says live clones recover on a refill with no
respawn. a probe at blueprint settles it (r3). if the probe shows a live clone re-reads the file
before it refreshes, the risk in `[t0]` drops away and the warn can go.
