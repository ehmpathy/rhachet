# 1.vision.experience.dimensions

the axes the wish varies over. each is a small closed set; each is orthogonal to the rest — a value
on one never implies a value on another.

| # | dimension | values | why orthogonal |
|---|---|---|---|
| D1 | **actor** | `author` (writes a test, so chooses its backend and venue) · `dev` (runs a tier on a local box) · `ci` (the per-pr gate) | who meets a run says naught about what it proves, what backs it, or where it lives |
| D2 | **subject** — what the run is for | `mech` (prove rhachet's own mechanism: enroll argv, pty, socket, say/get, history link, boot, settings) · `contract` (prove rhachet against the real claude: a real tui submits our bytes, a real claude loads our memory files, a real sdk boots) · `measure` (learn how the real claude behaves — its render, its queue — so the mock can imitate it) | a property of the run, not of who runs it or what backs it. `measure` surfaced from the walk: `screen-dogfood` emits measured grids to a research artifact, a purpose neither `mech` nor `contract` names |
| D3 | **brain** — what answers the spawn | `mock.cli` (the mock claude cli on PATH — imitates claude's surface: tui, transcript, print) · `mock.repl` (a mocked `BrainRepl` at the rhachet seam — imitates the supplier's contract, not claude's) · `real.haiku` · `real.default` (any non-haiku model) | a choice the run makes; any subject *can* pick any backend — whether the pick teaches aught is the verdict, not the axis |
| D4 | **creds** | `valid` · `dead` (claude-code has cleared the login on disk — revoked, or a refresh the server rejected; rhachet's dead-login gate refuses it, `assertBrainAuthNotDead.ts:20-35`) · `absent` | a property of the host |
| D5 | **claude surface** | `stable` · `changed` (a claude-code release moved a surface rhachet reads — a transcript field, a tui ack, a render) | a property of upstream and time. it reaches every backend that sits on claude's surface: on `mock.cli`, `changed` means the mock has drifted; on a real backend, the real cli now differs from what rhachet expects. `mock.repl` sits on the supplier's contract instead, so D5 does not reach it (collapse 3) |
| D6 | **venue** — where the run lives | `jest` (a suite in a jest tier, run per pr) · `byhand` (a skill a human or clone runs on demand) | a choice of home, independent of what the run proves or what backs it |
| D7 | **session** | `own` (the run boots its own brain) · `shared` (the run is one turn in a session that several clamps share) | a choice of cost, independent of the subject |
| D8 | **turn** | `lands` (the brain takes the turn and answers within the bound) · `wedges` (a real brain stalls — a slow model, a modal, a dropped submit) | an event of the run, independent of every choice above. with D7 `shared`, a wedge can starve the turns after it — the pair that surfaces the cascade |
| D9 | **claude bin** | `ok` (a `claude` at or above `BRAIN_CLI_VERSION_FLOOR` on PATH) · `short` (absent, or below the floor) | a property of the host, apart from creds: `getRealClaudeOrThrow` checks the two separately (`enrollCloneHarness.ts:339-371`) |
| D10 | **host reads** — which host inputs a smoketest consumes | `creds + bin` (the tui clamps, the memory load) · `bin only` (the dead-login smoketest: it plants its own login in an isolated home, then runs the host's `claude`) · `creds only` (the sdk door: it runs its own bundled cli on the host's login) | a property of each smoketest, apart from the host's state: two hosts with the same creds and bin pass and fail different smoketests by what each reads |

**`fit`** — a shorthand the inventory uses for D4 and D9 under D10: a host input is `fit` for a
smoketest when it is `valid` / `ok`, or when the smoketest does not read it. so creds `absent` are
fit for the dead-login smoketest, and a `short` bin is fit for the sdk door.

## .the product

3 × 3 × 4 × 3 × 2 × 2 × 2 × 2 × 2 × 3 = **10368 cells**.

## .the collapses — each stated once, so no cell is folded by a silent rule

1. **D1 (actor) never changes a verdict.** it changes who meets a cell and when: `author` meets
   the choice of D3 / D6 / D7 at write time; `dev` and `ci` meet the run at run time. each row's
   actors column names who meets that cell in the normal flow. an actor a row omits meets the cell
   only by a step into another actor's seat — an author who runs a suite is, for that run, a dev —
   and then meets the same verdict
2. **D7 (session) and D8 (turn) apply only to `contract × real.haiku × jest × creds fit × bin
   fit`.** a forbidden cell is forbidden in any session; a `byhand` skill runs alone, and a wedge
   there is a byhand retry; with a read input unfit, no turn runs. on a mock: `wedges` is
   impossible (a mock answers by construction, it does not stall); `shared` is attemptable and
   pointless, since a mock boots in a blink — itemized as row #26. off those cells, D7 and D8 each
   have one value and are not walked
3. **D4, D5, D9 do not move a mock cell, save D5 on `mock.cli`.** a mock never reads creds and never
   runs the real bin — that indifference is the value. `mock.repl` imitates the supplier's
   `BrainRepl` contract, which a claude release does not touch; that seam is the supplier's, and
   the sdk-door smoketest watches it. `mock.cli` imitates claude's surface, so D5 is walked for it
4. **D2 × D3 × D6 decides most verdicts.** within a forbidden `D2 × D3 × D6` triple, every value of
   the other axes is forbidden for the same reason; the inventory gives such a triple one row
5. **with D5 `changed`, the alarm verdict holds in every D7 × D8 cell.** the first red is the seam
   that moved — in a shared session, a moved surface that stalls a turn *is* that turn's wedge, and
   per the cascade invariant (cell #10) the clamps after it report "not reached", so the one red
   still names the seam
6. **D10 (host reads) applies only to `contract × real.haiku × jest`,** and only through `fit`: it
   decides which D4 / D9 values are fit for a given smoketest. a mock reads no host input, a
   forbidden cell is forbidden whatever it reads, and a byhand skill reads both. so D10 appears in
   the inventory as the `fit` test on rows #7–#11 and as the read-input condition on #12–#14

the walked cells, with verdicts, live in [`1.vision.experience.case=_.md`](./1.vision.experience.case=_.md).
