# 1.vision — tests run on a mock claude cli; only the smoketests call anthropic, on haiku

> **the wish:** every non-essential anthropic api test in rhachet runs on a mock of the claude cli;
> only the essential smoketest acceptance tests call the api, on haiku.

## .the outcome world

### before

rhachet tests reach a real `claude` from three places:

| where | what | example |
|---|---|---|
| blackbox reach probes | a real claude tui under our pty, real `say` / `get` | 6 `blackbox/cli/clone*.realbrain.acceptance.test.ts` suites (`clone`, `joker`, `saybulk-probe`, `modalprobe`, `transcript-lag`, `screen-dogfood`) + 6 real enrolls and a set of `claude -p` sentinel asks in `brain-dir-boot.journey.acceptance.test.ts` |
| blackbox print + sdk | a real `claude -p`; a real sdk door | `enroll.shared-brain-auth.acceptance.test.ts` (5 `--model haiku -p` calls on fake expired creds — no inference, but a real call to anthropic's oauth refresh), `sdk/replDoorRealSupplier.realnode.acceptance.test.ts` (a live haiku `.ask` through the agent sdk) |
| src integration | `genBrainRepl({ slug: 'claude/code/haiku' })` from `rhachet-brains-anthropic` — the real claude agent sdk, real tokens | `actorAsk`, `actorAct`, `invokeAct`, `genActor.brain.case{Askable,Collocated,Published}` `.integration.test.ts` — each asserts pass-through only (a string or object comes back) |

each of those spends tokens and tens of seconds per run, flakes on model latency, and fails on any
host without an anthropic login — even when the subject of the test is rhachet's own mechanism
(the pty, the socket, argv passthrough, the transcript link) and claude is only the party on the
far end of the wire.

the repo already holds the cure for one slice: a rich stub brain
(`src/.test/assets/stubBrainCli.cjs`), put on PATH as `claude` by `setupRichStubBrainPath`
(`blackbox/.test/infra/enrollCloneHarness.ts:75`). the clone reach acceptance suites use it. the
cure was never made the default, never widened to the print and sdk modes, and never fenced, so
new suites copied the realbrain neighbours.

### after

- **one mock claude cli** — the extant stub, grown to cover each mode rhachet drives through a
  `claude` on PATH: the interactive tui (pty, paste, submit, the ready banner the real harness waits
  on, transcript jsonl in the claude transcript dir) and print mode (`-p`). it accepts the flags
  rhachet passes (`--model`, `--tools`, `--append-system-prompt`, `--output-format`), which the stub
  refuses today, and still refuses what the real cli refuses
  (`rule.require.a-stub-refuses-what-its-subject-refuses`)
- **a mocked repl for the sdk path.** the agent sdk spawns its own bundled cli, never the `claude` on
  PATH, so the src integration suites that only assert pass-through take a mocked `BrainRepl` at the
  rhachet seam (`genMockedBrainRepl` exists) instead of `genBrainRepl` from the supplier
- **the mock is the default.** the shared harness and the integration setup hand it out unasked.
  a mech test never has to opt in
- **the integration tier stops to demand an anthropic key.** today
  `jest.integration.globalSetup.ts:25` sources keyrack `env.test`, which lists `ANTHROPIC_API_KEY`
  (`.agent/repo=.this/role=test/keyrack.yml:6`), and fails fast without it. once no integration
  suite reaches anthropic, that demand is a lie the tier tells — so the key leaves the integration
  tier's demand, and stays only where a smoketest reads it. `OPENAI_API_KEY` and `XAI_API_KEY` are
  out of this wish's scope and stay as they are
- **a small, named smoketest set** reaches the real api, each on `--model haiku`, in the default
  acceptance gate. one smoketest per seam the mock cannot prove (see below)
- **a fence.** a real-claude spawn from a suite outside the smoketest set is refused, loud; a
  smoketest on the mock is refused, loud

### the aha

the anthropic key stops to be a precondition to test rhachet. it is a precondition only to test
claude. a clone on a fresh box runs every tier it touches, green, for zero tokens — and the few
tests that do spend tokens are the ones whose failure means "claude changed", which is exactly
what we pay them to tell us.

### the smoketest set (proposed — fulcrum F1)

one smoketest per seam where the real claude is the subject. the realbrain suites each pin a
real-tui behavior rhachet's design rests on — each docblock says which, and most say what broke
when it went unpinned — so every one of those clamps survives. what changes is that they stop to
each boot their own claude: the tui clamps fold into **one shared real-haiku session** that walks
each seam in turn (one boot, shared via `useBeforeAll`, as `rule.allow.acceptance-spawns-real-brain-cli`
already prescribes).

| seam | the clamp, kept real | today |
|---|---|---|
| a real tui submits a dispatched `say` across turns; its transcript reads back via `get` | multi-turn reach | `clone.joker` (subsumes the 1-turn `clone.realbrain`) |
| a bulk paste commits only with a length-scaled submit delay | bulk say | `clone.saybulk-probe` — "goes red if the bulk path regresses to a fixed-tiny submit delay" |
| a real claude writes the user turn at **submit**, even while queued — so a transcript rise cannot part `enqueued` from `released` | queued say | `clone.transcript-lag` — a two-way clamp; red if a future cli defers the write |
| a real render does not trip the modal classifier; a multi-line paste lands as one turn | screen read | `clone.modalprobe`, `clone.screen-dogfood` [the clamp cases] |
| a real claude loads the memory files we lay down (CLAUDE.md → boot.md, `--setting-sources user`, `claudeMdExcludes`) | memory load | `brain-dir-boot.journey`, cut to its cheapest proof per layer (`claude -p` sentinel asks where a tui is not the subject) |
| a real claude-code clears a dead login where rhachet expects it to | dead login | `enroll.shared-brain-auth` (keep 1 of 5; spends no tokens) |
| the real sdk door boots its bundled cli and answers | sdk door | `sdk/replDoorRealSupplier.realnode.acceptance` |

the first four rows share one session; the last three keep their own spawn, since each needs a
different home, auth, or entry point.

all else moves to a mock:

| today | after |
|---|---|
| 6 separate realbrain boots | 1 shared session (above) |
| the rhachet behavior each tui clamp guards (verdict trees, `enqueued` vs `released`, `withheld`) | mock cli modes that imitate the measured quirk. 🔴 the stub's `busy` mode drifts from real claude **today**: it holds the message "with no transcript write" (`stubBrainCli.cjs:248`), the very premise `transcript-lag` refuted. the mock must follow the measurement before it carries the mech suites |
| `screen-dogfood`'s research half (it emits measured grids to a research artifact) | a byhand skill, the shape `claude.cli.secstore.trial` takes (case 5) — a followup, caught as a dream, not built here |
| `brain-dir-boot` tui enrolls whose subject is not the tui | the `-p` asks |
| `shared-brain-auth` 4 of 5 cases (rhachet's refusal + adopt paths) | mock cli |
| `actorAsk`, `actorAct`, `invokeAct`, `genActor.brain.*` (pass-through) | mocked `BrainRepl` |

## .mental model

- **to a friend:** "the tests talk to a fake claude now. a few talk to the real one, on the cheap
  model — one shared session plus three one-offs — and those exist to tell us when claude itself
  changed."
- **analogy:** a flight simulator and a check ride. pilots log most hours in the sim — cheap, safe,
  repeatable. a short check ride in the real aircraft proves the sim still matches the plane. if
  the check ride fails while the sim passes, the sim is what gets fixed.
- **terms:** a human says "fake claude" or "real claude". we say **mock claude cli** (the
  backend), **smoketest** (a real-claude acceptance test, on haiku), **mech** vs **contract**
  (what a test proves). `stub brain` is the extant name in code and stays: a rename across a dozen
  suites buys no behavior and the wish does not ask for one. in prose, "mock claude cli" and the
  code's `STUB_BRAIN` name the same artifact.

## .evaluation

| goal | how this meets it |
|---|---|
| non-essential tests on a mock | the mock is the default backend; the fence refuses real claude outside the smoketest set |
| essential tests on the real api | the smoketest set, one per contract seam, stays in the default acceptance gate |
| on haiku | the smoketest entry point pins `--model haiku`, as `enrollRealClaudeAndWaitReach` already does |

**pros** — tokens per pr drop to a handful of haiku turns · the tiers run green on a box with no
creds · mech tests stop to flake on model latency · the drift alarm gets sharper, since a red
smoketest beside a green mock suite names the cause.

**cons** — the mock is a second implementation of claude's surface and needs upkeep on each
claude-code bump, and it has drifted once already (`busy`) · the shared smoketest session couples
its clamps: one wedged turn can fail the turns after it · a smoketest set cut too small would let a
real-tui regression through, which is why every extant clamp is kept.

**edge cases and the pit of success**

| edge | the contract |
|---|---|
| a smoketest on a host with no creds | fails loud, exit 2, names the unlock — never skips, never falls back to the mock |
| an author copies a realbrain neighbour | the fence refuses the real spawn and names the mock entry point |
| claude-code changes a surface | the smoketest on that seam goes red and points at the mock |
| a real `claude` sits first on PATH | the harness puts the mock first; the real one is reached only through the smoketest entry point (`RHACHET_REAL_CLAUDE_BIN` / floor check already exist) |
| the sdk spawns its own bundled claude, not the one on PATH | a PATH mock cannot reach it; sdk pass-through suites take a mocked `BrainRepl`, and the one sdk smoketest stays real (F3) |
| a mock enroll meets the dead-login gate (`assertBrainAuthNotDead`) | the mock harness sets a fake env token, as the shared-brain-auth suite already does with fake creds |

## .open questions & assumptions

**assumptions**

- A1: "anthropic api test" means any test that reaches a real claude — tui, print mode, or sdk —
  not only a raw http call to `api.anthropic.com`
- A2: the extant stub brain is the right seed for the mock, not a new artifact
- A3: a blackbox suite that drives rhachet's cli against the mock keeps its `.acceptance.test.ts`
  name, since its subject is rhachet's contract and the real claude contract is held by the
  smoketests. this reads `rule.forbid.faked-or-quarantined-acceptance` as "the claude contract must
  have a real test in the default gate", not "no acceptance test may touch a mock" (F2, Q3)

**the questions, triaged**

| # | question | tag | answer, or who / how |

## .groundwork

### external research

- the claude agent sdk spawn seam: `rhachet-brains-anthropic@0.4.3`
  `dist/domain.operations/repls/genBrainRepl.js:182-194` calls the sdk `query()` with
  `{ systemPrompt, model, allowed/disallowedTools, outputFormat }` — no `pathToClaudeCodeExecutable`,
  no `env`. so the sdk spawns its own bundled cli; a `claude` on PATH never reaches it
- claude-code's tui surface: the real harness waits on
  `CLAUDE_IS_READY = /Welcome|Usage[^\r\n]*Billing|manual[^\r\n]*mode[^\r\n]*on/`
  (`enrollCloneHarness.ts:557`) and drives the trust menus (`:579-627`); the stub prints neither.
  the stub's transcript shape (`{type, message:{content:[{type:'text',text}]}}` under
  `$CLAUDE_CONFIG_DIR/projects/<cwd-slug>/`) matches what `get` reads today; its fidelity against
  claude-code 2.1.292 (the ci pin) is to be checked in the blueprint

### internal research

- the stub: `src/.test/assets/stubBrainCli.cjs`; shim on PATH: `setupRichStubBrainPath`
  (`blackbox/.test/infra/enrollCloneHarness.ts:75-86`) — a bash shim named `claude` that execs the
  stub under node. it emulates `--version` (`2.1.277`, override `RHACHET_STUB_BRAIN_VERSION`), `-p`
  (`got:<prompt>`), an interactive box with `poke <n>` → `ack:<n>`, a claude-shaped transcript, and
  screen modes via `RHACHET_STUB_MODE` (`default`, `dirty`, `modal`, `nobox`, `busy`,
  `bufferedhold`). its argv allowlist (L54-81) refuses `--model`. used today by 10 blackbox suites
  (`enroll.reach`, `enroll-to-reach.journey`, `clone`, `clone.lifecycle`, `clone.prune`,
  `clone.say.delivered`, `clone.say.withheld`, `actor`, `init.delta-live`, `enroll`) and 2 src
  integration suites (`genBrainCliPtyClone`, `genCloneOndisk`, via `command: process.execPath`)
- production spawn: the command name is hardcoded `claude` (`getSupportedBrainCommand.ts:40-43`) and
  resolved through PATH by the version probe (`assertBrainCliVersionFloor.ts:108-118`) and the pty
  spawn (`genBrainCliPtyClone.ts:147`). PATH is the one blackbox seam; the domain-level `command`
  input is the integration seam
- the dead-login gate: `assertBrainAuthNotDead.ts:20-35` — a mock enroll must clear it; it refuses only a login claude-code has cleared, and an env credential bypasses it (L26)
- ci: only the acceptance job installs claude-code (`.github/workflows/.test.yml:321-322`, pinned
  2.1.292); the integration job needs `ANTHROPIC_API_KEY` from keyrack only for the sdk suites —
  after this wish, it needs none
- the real gate: `getRealClaudeOrThrow` (`enrollCloneHarness.ts:339`) — floor check
  (`BRAIN_CLI_VERSION_FLOOR`), auth check (`~/.claude/.credentials.json`, `ANTHROPIC_API_KEY`,
  `CLAUDE_CODE_OAUTH_TOKEN`), override `RHACHET_REAL_CLAUDE_BIN`; fails with `ConstraintError`
- real-claude callers: grep of `getRealClaudeOrThrow|enrollRealClaudeAndWaitReach` over the repo
  (the 6 realbrain suites + `brain-dir-boot.journey`); `enroll.shared-brain-auth` and
  `replDoorRealSupplier.realnode.acceptance` reach real claude by their own paths (a cached pinned
  bin on PATH; the sdk)
- sdk callers: grep of `rhachet-brains-anthropic` over `src/**/*.test.ts`, each file read for a
  real `.ask` / `.act`: 6 suites reach the api. `genContextBrain.integration.test.ts` only lists the
  anthropic atoms and asks hand-written mocks — no api call
- `genActor.brain.caseAskable` also reaches real xai (`XAI_API_KEY`); out of this wish's scope,
  which names anthropic only
- rules this must honor: `rule.require.test-claude-cli-against-haiku`,
  `rule.allow.acceptance-spawns-real-brain-cli`, `rule.forbid.faked-or-quarantined-acceptance`,
  `rule.forbid.integration.mocks` (a mock in integration needs an inline `.mock / .why / .real`
  note — the `.real` is the smoketest)
- requirement registered: `inventory.of=requirements.case=10.tests-mock-the-claude-cli.md` (owed)

## .what is awkward?

- **the rules pull two ways.** `rule.forbid.faked-or-quarantined-acceptance` was written to stop
  exactly the move this wish asks for, after a stub let a real `say` bug ship (2026-08-12). the
  answer here is that the smoketests keep that bug class caught — but the smoketest set is now the
  only guard against a repeat, so its size is the decisive call (F1)
- **the tui quirks are the hardest to mock.** the realbrain clamps exist because the real tui did
  surprise us (modals, paste bursts, a transcript write at submit). a mock that imitates each quirk
  has to learn each new quirk by hand, and its `busy` mode already learned one wrong. so each quirk
  lives twice: as a real clamp in the shared session, and as a mock mode for the mech suites
- **`stub` vs `mock`.** the code says stub; the wish says mock; `rule.forbid.integration.mocks`
  reads "mock" as a jest module mock. a real child process that imitates claude is closer to a
  fake than either. the code name stays (see mental model); the two words in prose name one artifact
