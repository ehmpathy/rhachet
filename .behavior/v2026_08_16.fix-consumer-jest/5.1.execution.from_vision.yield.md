## note — jest tension resolved (design fork, Option A)

lazy import() alone broke rhachet's OWN keyrack crypto jest tests (they run REAL crypto, unlike
the brain load-sites which fake the load). jest refuses import() without --experimental-vm-modules.
resolution: `importEsmOrRequire` picks its branch by a DETERMINISTIC runtime flag —
`process.env.JEST_WORKER_ID !== undefined` selects require() under jest, else import() in real-node.
it never matches on an import error's message text (the fragile approach reviewer r7 blocked), and
the require() branch never fires at module-eval or in real-node. keeps the suite green AND fixes
#468 (module-eval carries no static require). purist alt (a move of crypto tests to real-node
acceptance) is a clean follow-up.
