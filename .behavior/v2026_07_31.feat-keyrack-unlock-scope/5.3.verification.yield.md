stray line there is a live hazard no stderr snapshot can see.

## 1h — the rebase round, and the one regression a blanket resnap would have buried (2026-08-10, last)

the branch was rebased onto main. the suite came back with **29 acceptance failures across 12
suites**, and the attractive move — `--resnap` the wall and move on — is precisely the move that
would have shipped a silent behavior loss.

### the discipline, stated before the resnap ran

a rebase mixes two failure kinds that are **visually identical** in a jest diff:

| kind | what happened | correct action |
|------|---------------|----------------|
| branch-stale | main moved; the snapshot predates it | resnap |
| regression | main's change silently degraded this branch | fix the code |

`--resnap` "fixes" both, and the second then ships green with no signal. so every one of the 29
was classified **before** a snapshot was written. the rule this round produced is now durable at
[`rule.forbid.blanket-resnap-after-rebase`](../../.agent/repo=.this/role=any/briefs/rule.forbid.blanket-resnap-after-rebase.md).

### the classification — 28 stale, 1 regression

each row answers *"did MY side change, or did THEIRS?"* via `git diff origin/main -- <file>` and
`git show origin/main:<file>`. no row is inferred.

| # | class | whose change | evidence | files |
|---|-------|--------------|----------|-------|
| a | `🐢 bummer dude... / 🐚 <cmd>` → `🔐 <cmd>` on every blocked tree | **main's** — `getKeyrackBlockedReport` reroot | `git show origin/main:…getKeyrackBlockedReport.ts` already emits `🔐` | session, set, fill, reach.envvar, source.reach, sdk source |
| b | `🗑️ keyrack del` → `🔐 keyrack del` on the success render | **main's** — same palette rule, applied to `del` | main's own del snapshot carries `🔐` | del |
| c | `--vault` help gains `aws.config, aws.params, github.secrets` | **main's** — three new vaults | the vault enum on main | reach.help, validation |
| d | `[keyrack-daemon] spawned background daemon` line dropped | **mine** — `asPtySnapshotSafe` is net-new on this branch | whole-block add, no `-` context lines | fill |
| e | `BadRequestError` → `✋ ConstraintError` + raw dump → blocked tree | **mine** — the §1e error-word round | `origin/main` snapshot still reads `BadRequestError` | validation, vault.awsParams |
| **f** | **a blocked refusal moved from stderr to stdout, and its glyph from `✋` to `💥`** | **a REGRESSION** | see below | reach.envvar |

⚠️ **class (d) needed its own check rather than a classification.** `startKeyrackDaemon.ts` is
**byte-identical to main**, so the line's disappearance was no code change on either side — which
made it look like a timing artifact, and a timing artifact baked into a snapshot is a CI flake. it
is not: every fill snapshot routes through `asPtySnapshotSafe`, which drops the notice
unconditionally, so the removal is deterministic. the scrubber's own comment had already reasoned

### ⛔ class (f) — the regression, and why no other check would have caught it

main added a **per-key fault isolation** to `unlockKeyrackKeys`: it catches a `ConstraintError`
per key, renders it as an `errored 💥` row, and carries the batch on. the vault-posture refusal
(`assertKeyrackReachAddressable`) sat **inside** that try, so it was swept in. two contract legs
broke at once:

| leg | owed | what it became |
|-----|------|----------------|
| glyph | `✋ blocked` | `💥` — which `rule.require.keyrack-emoji-palette` reserves for a **MalfunctionError**, so a caller-fixable refusal read *"we broke"* |
| stream | stderr | stdout — the channel `keyrack source` **evals as shell** |

**the exit code stayed 2 throughout.** `asKeyrackUnlockExitCode` returns 2 for an all-`ConstraintError`
batch either way, so the one check most likely to catch a downgrade did not. the message text was
**byte-identical** on both sides. only the stream and the glyph moved — which is exactly the tell
the new rule names: *a diff where content only MOVED is where a silent contract loss hides.*

**the fix honors main's contract rather than fights it.** main's own catch-block comment scopes the
isolation to *"the LIVE, OPERATIONAL faults a vault adapter raises."* a vault-posture refusal is
**static** — decided by the `(vault, reach)` pair with no i/o at all — so it belongs **above** the
try, beside the write-only-vault check already there. the assert was hoisted, not the catch widened.

three notes carried in the code, because each is a reason a reader would otherwise re-derive:

- there is never a batch to isolate on this path anyway — `--reach` requires `--key` (q2), so a
  reach-ask is always ONE key; isolation of a single-key ask protects no peer and only degrades the render
- it now fires before `identity.getOne()`, so an impossible reach is refused up front rather than
  after an ssh-key unlock the caller did not need (`rule.prefer.prevent-over-correct`)
- the adapter-level guards stay, as defense in depth — the sdk reaches an adapter directly, with no
  unlock loop above it to hoist a check into

### the clamp, and it bites

a snapshot pair reports this drift as one anonymous diff, so a refreshed snapshot alone would have
been a **blocker** under `rule.require.clamp-edge-cases`. an assertion that names the invariant was
added instead:

```ts
then('the refusal is on stderr, and stdout stays a result-only stream', () => {
  expect(result.stderr).toContain('✋ blocked:');
  expect(result.stdout.trim()).toEqual('');
  // the malfunction glyph must never mark a caller-fixable refusal
  expect(result.stdout + result.stderr).not.toContain('💥');
});
```

**dogfooded:** with the assert left inside the try, all three expectations go red — stderr empty,
stdout non-empty, `💥` present. with it hoisted, all three pass. the clamp reports **why**, not
merely *that*.

⚠️ and the resnapped `keyrack.reach.envvar` snapshot is itself corroboration: the blocked tree is
captured under the **`stderr`** key. were the regression live, that snapshot would be empty and the
content would sit under `stdout`.

### the nitpick, and why it was taken rather than banked

`enroll-verif-snapshot-blemishes` (l3) found a **doubled blank line** before `🔐 keyrack del` in four

|------|--------|

### ⛔ the scoped resnap was TOO NARROW, and the independent run is what caught it

the first full run after the nitpick fix came back **2 failed** — `keyrack.aws-params.githubApp
[case3]` and `keyrack.vault.githubSecrets [case3]`, each a `- Snapshot - 1 / + Received + 0`: the one
blank line, in two suites I had not resnapped.

**the mistake was in how the scope was derived.** I scoped the resnap to the reviewer's list —
`keyrack.del` and `keyrack.vault.awsParams` — but that list was of **blemish occurrences the reviewer
happened to find**, not of **every snapshot that embeds the del render**. those are different sets,
and the second is the one a resnap must cover. derived properly, it is four files:

```
rg "🔐 keyrack del" blackbox/ -l
→ keyrack.del…snap   keyrack.vault.awsParams…snap   keyrack.vault.githubSecrets…snap   keyrack.aws-params.githubApp…snap
```

I had two of the four. worse, the miss was **foreseeable from a comment I had already read**:
`asKeyrackDelReport.test.ts`'s own header names *"the destroyed end-to-end path … acceptance-snapshotted
in keyrack.aws-params.githubApp.acceptance.test [case3]"*. the map existed; I did not consult it.

> **the rule this yields:** scope a resnap by the RENDER'S CONSUMERS, derived from a grep for the
> rendered text — never by the list of occurrences a reviewer reported, and never by filename
> resemblance. a reviewer reports what it found; a resnap owes what exists.

⚠️ **note which half of the discipline caught this.** §1h's rule guards against a resnap that is too
**broad** — one that buries a regression. this is the opposite defect, a resnap too **narrow**, and no
amount of classification would have found it. what found it was step 5 of that same rule: the
**re-run without `--resnap`**. that step is not a formality; it is the only check that sees a snapshot
the resnap never visited.

**and the semantic clamps held throughout**, which is why this was a snapshot refresh rather than a
behavior investigation: in the same suite, `then: the CLI echoes that the SSM secret was destroyed
(never a bare "removed")` **passed**. an assertion that names the invariant survives a byte change to
the render; only the snapshot pair went red. that is `rule.require.clamp-edge-cases`, paid back.
