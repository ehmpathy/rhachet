# vision: a labeled input-box rule reads as a rule

## the outcome world

a foreman enrolls a driver with an agent name (`mechanic`). claude code draws that name into the
input box's top rule. the foreman runs `rhx clone say @:driver --what 'status?'`, and the say lands.
`rhx clone get --what buffer` shows the one-row box, not the transcript above it.

| | before | after |
|---|---|---|
| a labeled top rule, box at the foot | `withheld` / `focus-unrecognized`, hint says tear the clone down | `released` — the box reads `input` / `clear` |
| a labeled top rule, plain rules higher on screen | `withheld` / `input-region-dirty`, the transcript read as the box, hint offers `--force` | `released` — the band pairs the labeled rule with the bottom rule |
| a real modal | `modal` | `modal`, unchanged |
| a prose row with a `─` in it | no rule | no rule, unchanged |

the aha: the clone was never deaf. the classifier could not see the box's top rule.

## the contract

a **rule row**, on the trimmed row, is a run of ≥20 `─` glyphs, then at most one label and a
`─` tail:

```
/^─{20,}(?:\s+[^─\s][^─]*\s+─+)?$/
```

- `─────────────────────────────` → rule (as before)
- `────────────────────────────── mechanic ─` → rule (new)
- `── note ──` → no rule (a lead run under 20)
- `● a reply that says ── here` → no rule (no lead run)
- `────────────────────── a ─ b ─` → no rule (two label groups. one label only)

the half-width guard stays on the lead run, as the issue proposes.

## mental model

"the clone shows its name on the box border, and say could not find the border." a human sees a
box with a title. the code must see it too.

## evaluation

- pros: one regex, a single owner for both locators, so both faces are cured at once
- cons: a transcript row shaped `──…── word ─` would now read as a rule. the band takes the LAST
  pair at the foot, so a stray rule higher up does not move the box. the risk is small
- pit of success: the lead run is ≥20 glyphs and only one label is allowed, so prose and short
  dividers stay out

## open questions & assumptions

- [answered] does a label on the bottom rule break the band? it closes no box: only a bare rule
  closes one, so a labeled row beneath the box (a status line) can never pair into a false `clear`.
  a labeled bottom is unmeasured, so it fails closed (the say is withheld)
- [answered] does a wider label pad break the match? no — the regex takes `\s+` each side
- [answered] does the cure reach the queue walk too? yes — `computeCloneInputContent.ts:57` calls
  the same `isRuleRow`. code
- [answered] which screen produced face 2? the issue prescribes two plain rules above; its capture
  fits one. both are clamped (case 2a, 2b), so the question needs no wisher
- [answered] can a label hold a `─`? unmeasured; if it does, the row reads no rule and the say is
  withheld (fail closed). no research owed now
- [answered, wisher] does the hint copy ride this fix? no — F1 ruled A; ehmpathy/rhachet#736

## what is awkward?

the regex is a shape whitelist of one measured label form. a label with an embedded `─` would fail
closed (no rule → `unrecognized`), which is the safe direction. so would a narrow pty whose long
agent name leaves a lead run under 20 glyphs — unmeasured, and the same guard the old code held.
