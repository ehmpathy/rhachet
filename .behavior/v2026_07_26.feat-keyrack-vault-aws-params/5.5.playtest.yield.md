# 5.5.playtest — keyrack `aws.params` vault (byhand foreman verification)

> this is the byhand quality-assurance walk for the `aws.params` keyrack vault. every step is
> copy-pasteable, states its expected output, gives a pass/fail line, and cites the acceptance
> test that locks the same behavior. the CLI-surface steps (help, validation, the error gates)
> run with NO AWS account. the live-roundtrip steps (set → unlock → get) need a real AWS
> identity + a real SSM SecureString; those are marked **[needs AWS]**.

---

## prerequisites

- a build of this worktree: `npm run build` (so `npx rhx keyrack …` runs THIS code — see
  `.agent/repo=.this/role=any/briefs/howto.test-local-rhachet.md`; confirm with
  `npx rhx keyrack set --help | grep aws.params`).
- **[needs AWS]** an AWS identity for the live steps:
  - `--org @all` (grove path): an EC2 instance role reachable over IMDS, OR
  - a specific org: a completed AWS SSO session, e.g. `rhx keyrack unlock --owner ehmpath --env test`.
- **[needs AWS]** `AWS_REGION` exported (e.g. `export AWS_REGION=us-east-1`) — region is NOT
  ambient at unlock; it is captured at set into `meta.region`.
- **[needs AWS]** the out-of-band IAM/KMS grants on the identity:
  - reference/read: `ssm:GetParameter` + `kms:Decrypt`
  - github-app persist: those PLUS `ssm:PutParameter` + `kms:Encrypt` (all four — set writes then
    roundtrip-reads).

## sandbox

- all byhand file ops (temp HOME, temp repo, pem files) target `@gitroot/.temp/` only. never
  write to the repo root or a real `~/.rhachet`. each live step below pins `HOME` into `.temp/`.
- set up once:
  ```sh
  mkdir -p .temp/playtest && export PLAY_HOME="$PWD/.temp/playtest"
  HOME="$PLAY_HOME" npx rhx keyrack init --owner mechanic
  ```
  the init seeds the host manifest into the sandbox HOME. without it, the very first `set` below
  fails loud with `host manifest not found. run: rhx keyrack init --owner mechanic` — the init line
  clears that precondition once for every set/unlock/get step that pins `HOME="$PLAY_HOME"`.

## happy paths

### h1 — `aws.params` is a known vault + the help names its prerequisites
```sh
npx rhx keyrack set --help
```
- **expected:** the `--vault` list includes `aws.params`; a dedicated `aws.params` block names the
  `AWS_REGION` prerequisite, the mandatory `--owner`, and the per-mech out-of-band IAM/KMS grants
  (`ssm:GetParameter`+`kms:Decrypt` for reference; plus `ssm:PutParameter`+`kms:Encrypt` for
  github-app).
- ✓ **pass if:** the help text shows the `aws.params` block with the region + IAM/KMS lines.
- ✗ **fail if:** `aws.params` is absent from the vault list, or the prerequisites are unnamed.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case2].

### h2 — a reference set autocomputes the SSM path + advises existence is unverified
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key ANTHROPIC_API_KEY --vault aws.params \
  --mech PERMANENT_VIA_REFERENCE --owner mechanic --env prod --org ehmpathy
```
- **expected:** the set is accepted; stdout echoes the computed path
  `/keyrack/infra/vault/aws.params/v1/mechanic/ehmpathy/prod/ANTHROPIC_API_KEY`, writes NO value,
  and appends the advisory that existence is not verified until the first unlock.
- ✓ **pass if:** the computed `v1/…` path is echoed AND the "existence not verified" advisory is shown.
- ✗ **fail if:** a path is typed by you, a value is written, or the advisory is absent.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case4].

### h3 — **[needs AWS]** unlock then get a reference key (identity IS the unlock)
> first place a real SSM SecureString at the path from h2 (or use your own `--exid`):
```sh
aws ssm put-parameter --type SecureString --region "$AWS_REGION" \
  --name /keyrack/infra/vault/aws.params/v1/mechanic/ehmpathy/prod/ANTHROPIC_API_KEY \
  --value 'sk-ant-playtest-value'
HOME="$PLAY_HOME" npx rhx keyrack unlock --env prod --org ehmpathy
HOME="$PLAY_HOME" npx rhx keyrack get --key ANTHROPIC_API_KEY --env prod --org ehmpathy --value
```
- **expected:** `unlock` prints NO human prompt (the ambient identity is the unlock); `get`
  returns the decrypted SecureString value.
- ✓ **pass if:** no prompt on unlock AND the exact secret value is served on get.
- ✗ **fail if:** unlock prompts for input, or get returns empty / a stale value / an error.
- **acceptance:** `blackbox/cli/keyrack.aws-params.journey.acceptance.test.ts` [case1][t2][t3];
  SDK read parity `blackbox/sdk/keyrack.aws-params.acceptance.test.ts`.

### h4 — get before unlock reads locked, and names the unlock fix
```sh
HOME="$PLAY_HOME" npx rhx keyrack get --key ANTHROPIC_API_KEY --env prod --org ehmpathy
```
(run in a fresh shell, before any unlock)
- **expected:** the key reads as locked, and the output names the `keyrack unlock` command to run.
- ✓ **pass if:** status is locked AND the unlock command is named as the fix.
- ✗ **fail if:** a bare failure with no fix, or a value is served without an unlock.
- **acceptance:** `blackbox/cli/keyrack.aws-params.journey.acceptance.test.ts` [case1][t1].

### h5 — **[needs AWS]** github-app set persists the blob into SSM (guided)
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key EHMPATHY_SEATURTLE_GITHUB_TOKEN --vault aws.params \
  --mech EPHEMERAL_VIA_GITHUB_APP --owner mechanic --env prod --org ehmpathy
```
- **expected:** a `🔐 keyrack set … via EPHEMERAL_VIA_GITHUB_APP` header, then the guided
  app-selection + pem prompts; on completion the blob is persisted into SSM at the computed path
  and confirmed. the blob value is NEVER echoed back.
- ✓ **pass if:** the guided tree renders under the 🔐 header AND the persist is confirmed AND no
  secret blob appears in stdout.
- ✗ **fail if:** the blob value is printed, or the persist is unconfirmed.
- **acceptance:** `blackbox/cli/keyrack.aws-params.githubApp.acceptance.test.ts` [case1][t0][t1].

### h5b — **[needs AWS]** unlock a github-app key mints a short-lived token (not the master key)
```sh
HOME="$PLAY_HOME" npx rhx keyrack unlock --env prod --org ehmpathy
HOME="$PLAY_HOME" npx rhx keyrack get --key EHMPATHY_SEATURTLE_GITHUB_TOKEN --env prod --org ehmpathy --value
```
- **expected:** unlock reads the persisted app blob from SSM and mints a ~1h github installation
  token; get serves that short-lived token, NEVER the app master private key. (this is vision u2 /
  criteria uc6.)
- ✓ **pass if:** a short-lived installation token is served AND the master private key never appears.
- ✗ **fail if:** the app master key is served, or no token is minted.
- **acceptance:** `setKeyrackAwsParamGithubApp.integration.test.ts` (the mint is proven at the
  integration grain; a CLI-subprocess mint is out of acceptance scope — there is no headless github
  mint injection point).

### h6 — the mechanism prompt appears when `--mech` is omitted (interactive)
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key SOME_KEY --vault aws.params \
  --owner mechanic --env prod --org ehmpathy
```
(answer the prompt with the reference option)
- **expected:** keyrack asks "which mechanism?" and lists BOTH aws.params mechs with plain
  descriptions; your pick is what registers.
- ✓ **pass if:** both mechs are listed with descriptions AND the chosen mech registers.
- ✗ **fail if:** no prompt appears, or a silent default mech is chosen.
- **acceptance:** `blackbox/cli/keyrack.aws-params.githubApp.acceptance.test.ts` [case4].

### h7 — **[needs AWS]** `--org @all` machine-wide roundtrip with NO repo manifest
```sh
cd "$PLAY_HOME" && HOME="$PLAY_HOME" npx rhx keyrack set --key GROVE_KEY --vault aws.params \
  --mech PERMANENT_VIA_REFERENCE --owner mechanic --env prod --org @all
HOME="$PLAY_HOME" npx rhx keyrack unlock --env prod --org @all
HOME="$PLAY_HOME" npx rhx keyrack get --key GROVE_KEY --env prod --org @all --json
```
(run from a directory with NO `.agent/keyrack.yml`)
- **expected:** the set is accepted with no repo manifest present; the computed SSM name carries
  the legalized machine-wide `_all_` segment (no raw `@`); unlock + get serve the machine-wide value.
- ✓ **pass if:** the name shows `_all_`, the set works with no repo manifest, and get serves the value.
- ✗ **fail if:** it demands a repo manifest, or the name carries a raw `@`, or resolves to a repo org.
- **acceptance:** `blackbox/cli/keyrack.aws-params.orgScope.acceptance.test.ts` [case1].

### h8 — `--org @all` ignores a present repo manifest org
```sh
# in a repo whose .agent/keyrack.yml declares org: testorg
npx rhx keyrack set --key GROVE_KEY --vault aws.params --mech PERMANENT_VIA_REFERENCE \
  --owner mechanic --env prod --org @all
```
- **expected:** the computed name carries `_all_`, and IGNORES the manifest org (`testorg`).
- ✓ **pass if:** the name is machine-wide `_all_`, not `testorg`.
- ✗ **fail if:** the manifest org leaks into the machine-wide name.
- **acceptance:** `blackbox/cli/keyrack.aws-params.orgScope.acceptance.test.ts` [case2].

## edgey paths

### e1 — set fails loud when `AWS_REGION` is absent
```sh
env -u AWS_REGION -u AWS_DEFAULT_REGION HOME="$PLAY_HOME" npx rhx keyrack set \
  --key K --vault aws.params --mech PERMANENT_VIA_REFERENCE --owner mechanic --env prod --org ehmpathy
```
- **expected:** non-zero exit; the error states region is required and names the fix (`set AWS_REGION`).
- ✓ **pass if:** it fails loud and names the region fix. ✗ **fail if:** it registers region-less.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case7].

### e2 — set fails loud when `--owner` is omitted
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params \
  --mech PERMANENT_VIA_REFERENCE --env prod --org ehmpathy
```
- **expected:** non-zero exit; the error names `--owner` as the mandatory fix.
- ✓ **pass if:** it fails loud and names `--owner`. ✗ **fail if:** it registers with a skipped owner.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case9].

### e3 — set with no `--mech` on a non-terminal stdin never hangs
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params \
  --owner mechanic --env prod --org ehmpathy < /dev/null
```
- **expected:** it does NOT block on the interactive prompt; it fails loud and names
  `--mech <PERMANENT_VIA_REFERENCE|EPHEMERAL_VIA_GITHUB_APP>` as the fix.
- ✓ **pass if:** no hang; the `--mech` fix is named. ✗ **fail if:** it blocks to await a tty answer.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case3].

### e4 — an unsupported `--mech` is rejected (the vault is still accepted)
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params \
  --mech PERMANENT_VIA_REPLICA --owner mechanic --env prod --org ehmpathy
```
(`PERMANENT_VIA_REPLICA` is a REAL mech — valid enum — that aws.params does not support, so this
exercises the vault's `mechs.supported` rejection, not a bare invalid-enum parse error)
- **expected:** non-zero exit; NO "invalid --vault" error (the vault is valid); the mech is what
  fails, and the supported mechs are named.
- ✓ **pass if:** the vault is accepted and the mech is rejected with the supported set named.
- ✗ **fail if:** it errors on the vault, or silently accepts the bad mech.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case1].

### e5 — **[needs AWS]** unlock exits NON-ZERO when an aws.params key faults (G5 automation contract)
```sh
# reuse the h2 key; run with NO resolvable AWS identity (unset the ambient creds)
env -u AWS_PROFILE -u AWS_ACCESS_KEY_ID -u AWS_SECRET_ACCESS_KEY \
  HOME="$PLAY_HOME" npx rhx keyrack unlock --env prod --org ehmpathy ; echo "exit=$?"
```
- **expected:** the faulted key is surfaced distinctly (an `errored` omission, never silently
  dropped); the process exits NON-ZERO — so a chained `unlock && start-app` does not run credential-less.
- ✓ **pass if:** the errored key is shown AND `exit=` is non-zero.
- ✗ **fail if:** exit is 0 with an absent credential, or the fault aborts the whole batch.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case5].

### e6 — a specific-org key with no `AWS_PROFILE` declared fails loud (no silent IMDS fallback)
```sh
# in a repo with org: testorg but NO AWS_PROFILE declared for testorg
npx rhx keyrack unlock --env prod --org testorg
```
- **expected:** unlock fails loud, names the org `AWS_PROFILE` as the fix, and NEVER falls back to
  IMDS or an ambient SSO session for a tree-scoped key.
- ✓ **pass if:** it fails loud and names the org `AWS_PROFILE`. ✗ **fail if:** it silently uses IMDS.
- **acceptance:** `blackbox/cli/keyrack.aws-params.orgScope.acceptance.test.ts` [case3][t1].

### e7 — **[needs AWS]** github-app set fails loud on an unreadable pem path
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params \
  --mech EPHEMERAL_VIA_GITHUB_APP --owner mechanic --env prod --org ehmpathy
# at the pem prompt, give a path that does not exist
```
- **expected:** non-zero exit; the guided output states the unreadable-pem failure; NO secret blob
  is echoed; NO manifest entry is registered for the failed set.
- ✓ **pass if:** it fails loud on the pem issue AND leaves no manifest entry.
- ✗ **fail if:** it registers a partial entry, or echoes a blob.
- **acceptance:** `blackbox/cli/keyrack.aws-params.githubApp.acceptance.test.ts` [case2].

### e8 — re-set a reference key at a new `--exid` echoes the re-point (no residual)
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params --mech PERMANENT_VIA_REFERENCE \
  --owner mechanic --env prod --org ehmpathy --exid /a
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params --mech PERMANENT_VIA_REFERENCE \
  --owner mechanic --env prod --org ehmpathy --exid /b
```
- **expected:** the re-set is accepted; stdout echoes `re-pointed: was /a → now /b`; a reference
  re-point strands NO owned secret, so there is NO residual-secret note.
- ✓ **pass if:** the was→now echo shows AND no residual note appears.
- ✗ **fail if:** the pointer moves silently, or a residual note appears for a reference key.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case8].

### e9 — **[needs AWS]** del of a github-app key destroys the SSM secret + says so
```sh
# after h5 persisted a github-app key, delete it
HOME="$PLAY_HOME" npx rhx keyrack del --key EHMPATHY_SEATURTLE_GITHUB_TOKEN --env prod --org ehmpathy
```
- **expected:** the CLI echoes that the SSM secret was destroyed (NOT a bare "removed"); the key
  leaves the manifest.
- ✓ **pass if:** the destroyed-secret line is shown AND the key is gone from `keyrack list`.
- ✗ **fail if:** it prints a bare "removed" while a live SSM secret was destroyed.
- **acceptance:** `blackbox/cli/keyrack.aws-params.githubApp.acceptance.test.ts` [case3].

### e10 — del of a reference key reports a plain removal (no destroy)
```sh
HOME="$PLAY_HOME" npx rhx keyrack del --key ANTHROPIC_API_KEY --env prod --org ehmpathy
```
- **expected:** a plain removal (keyrack wrote no value → destroys no remote secret); the key
  leaves the manifest; the operator-owned param is untouched.
- ✓ **pass if:** a plain "removed" AND the key is gone from the list.
- ✗ **fail if:** it claims to destroy a secret for a reference key.
- **acceptance:** `blackbox/cli/keyrack.vault.awsParams.acceptance.test.ts` [case6].

### e11 — a malformed explicit `--exid` is rejected before any SSM call
```sh
HOME="$PLAY_HOME" npx rhx keyrack set --key K --vault aws.params --mech PERMANENT_VIA_REFERENCE \
  --owner mechanic --env prod --org ehmpathy --exid 'not a legal name'
```
(no AWS needed — the name is validated at the boundary, before any region resolution or SSM call)
- **expected:** non-zero exit; the error states the value is not a legal SSM parameter name (a space
  is illegal); NO SSM call is attempted; no manifest entry is registered.
- ✓ **pass if:** it fails loud on the illegal name AND leaves no manifest entry.
- ✗ **fail if:** it registers the bad name, or the failure is a raw SDK `ValidationException` from AWS.
- **acceptance:** `src/domain.operations/keyrack/adapters/vaults/aws.params/isKeyrackAwsParamName.test.ts`
  (c32 — the boundary type-check that the CLI set path calls via `.assure`; a CLI subprocess induces
  the same rejection with no AWS, since validation precedes any SSM call).

walk does not step it.

## pass/fail criteria (overall)

- ✓ **pass if:** every h-step and e-step above matches its expected output and pass line, with the
  live **[needs AWS]** steps run against a real AWS identity + SSM SecureString.
- ✗ **fail if:** any step deviates — an absent prompt, a swallowed error, a leaked secret value, a
  silent IMDS fallback, an exit-0-on-fault, or a hang on non-terminal stdin.

## coverage note

every step above cites the acceptance test that locks the same behavior; the automated suites
run green in CI (`blackbox/cli/keyrack.vault.awsParams`, `…orgScope`, `…githubApp`,
`…journey`, `blackbox/sdk/keyrack.aws-params`). the live **[needs AWS]** roundtrip is also
covered at the integration grain (`vaultAdapterAwsParams.integration.test.ts`,
`getOneKeyrackAwsParam.integration.test.ts`, `setKeyrackAwsParamGithubApp.integration.test.ts`)
against a real SSM stand-in. this playtest is the human-hands confirmation on top of that.
