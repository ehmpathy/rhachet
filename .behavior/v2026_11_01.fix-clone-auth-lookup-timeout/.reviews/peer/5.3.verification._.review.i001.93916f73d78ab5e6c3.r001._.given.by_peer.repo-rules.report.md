# blocker.1: stdout tree leaves use `:` as a label/detail separator (`cause:`, `fix:`)

**rule**: .agent/repo=.this/role=any/briefs/rule.forbid.colons-in-stdout.md

**locations**:
- src/domain.operations/clone/cli/asCloneInputSurfaceText.ts:57
- src/domain.operations/clone/cli/asCloneInputSurfaceText.ts:58

`asCloneInputSurfaceText` renders the human treestruct for `rhx clone get --what buffer|queue` to **stdout**, and its probe-blind branch puts a colon between a label and its detail on two leaves:

```
   ├─ cause: <reason>
   └─ fix: <remedy>
```

this repo's stdout grammar makes the tree the separator: a label never runs on into its detail. the `fix:` leaf is a line this PR edits (the remedy now indexes `PROBE_BLIND_REMEDY` instead of a ternary cascade), so it is in scope directly; the `cause:` leaf sits in the same restructured block. both should read as `├─ cause <value>` / `└─ fix <value>`, or carry the detail as a subbranch.

note the rest of the new render code in this PR is careful about this (every new trace line in `genCloneSocketServer.ts` uses an em dash), so these two leaves are the outliers.

**snippet**:
```ts
    return [
      `😶 ${address} — the ${what} could not be read`,
      `   ├─ cause: ${reply.reason}`,
      `   └─ fix: ${PROBE_BLIND_REMEDY[reply.reason]}`,
    ].join('\n');
```
