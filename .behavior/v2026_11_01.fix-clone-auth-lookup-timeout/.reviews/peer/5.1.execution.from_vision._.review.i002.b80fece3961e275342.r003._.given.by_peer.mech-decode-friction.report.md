# blocker.1: decode-friction pipelines inline in the new genSlowSsOnPath helper

**rule**: .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/readable.narrative/rule.forbid.inline-decode-friction.md

**locations**:
- src/.test/assets/genSlowSsOnPath.ts:22-24
- src/.test/assets/genSlowSsOnPath.ts:25-27

The new `genSlowSsOnPath` asset (added whole in this PR, every line is new) inlines two pipelines that require mental simulation to understand what they produce:

1. `(pathBefore ?? '').split(delimiter).filter((dir) => dir !== '')` (lines 22-24) — split-and-filter that yields the non-empty PATH segments; a reader must simulate the empty-entry drop.
2. `dirsSearched.map((dir) => join(dir, 'ss')).find((candidate) => existsSync(candidate))` (lines 25-27) — a map-then-find that resolves the first existing `ss` binary on PATH; you have to trace each dir to `dir/ss` and then to the first that exists.

The rule explicitly lists `filter/map/sort` pipelines as decode-friction (`rule.forbid.inline-decode-friction`, mirrored by `rule.require.named-transformers`). Both of these should be extracted to named helpers, e.g. `asPathDirs({ path })` returning the non-empty segments and `findFirstExistingOnPath({ dirs, name })` returning the first existing candidate (or null), so the helper body reads as `const dirs = asPathDirs({ path: pathBefore }); const ssReal = findFirstExistingOnPath({ dirs, name: 'ss' });`.

Note the grain caveat: this is a `.test/assets` fixture rather than a domain.operations orchestrator, so the strictest reading of the rule may not bind it — but the same decode-friction test applies, and the two spots are cheap to name. If kept inline intentionally as test scaffolding, treat this as the lowest-priority instance; the map/find is the clearer offender.

**snippet**:
```ts
const dirsSearched = (pathBefore ?? '')
  .split(delimiter)
  .filter((dir) => dir !== '');
const ssReal = dirsSearched
  .map((dir) => join(dir, 'ss'))
  .find((candidate) => existsSync(candidate));
```
