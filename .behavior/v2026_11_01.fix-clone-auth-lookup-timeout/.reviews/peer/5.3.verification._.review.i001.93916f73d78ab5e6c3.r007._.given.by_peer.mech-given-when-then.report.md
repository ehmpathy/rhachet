# nitpick.1: unit test uses bare `test()` instead of the given/when/then frame

**rule**: .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.test/frames.behavior/rule.require.given-when-then.md

**locations**:
- src/domain.operations/clone/socket/computeCloneAuthGateAction.test.ts:39

`computeCloneAuthGateAction.test.ts` structures its rows with `describe()` + `test()` and never uses the `test-fns` `given()/when()/then()` hierarchy that the rule prescribes for test suites (`.how`: use `describe()` to group, `given()` for the setup scenario, `when()` for the act, `then()` for the outcome).

The rule requires this frame for integration tests and expects it for unit tests; this file is a unit test, so this is a nitpick rather than a blocker. Each table row is a scenario (`given`) whose read of `computeCloneAuthGateAction` is the act (`when`) and whose equality is the outcome (`then`) — the same content, expressed in the required frame, e.g. `given(thisCase.description, () => { when('[t0] the action is computed', () => { then(`it returns ${thisCase.expect}`, () => { ... }) }) })`.

**snippet**:
```ts
describe('computeCloneAuthGateAction', () => {
  TEST_CASES.map((thisCase) =>
    test(thisCase.description, () => {
      expect(computeCloneAuthGateAction(thisCase.given)).toEqual(
        thisCase.expect,
      );
    }),
  );
});
```

# nitpick.2: every case in isCallerSameUser.test.ts uses bare `test()` instead of given/when/then

**locations**:

- src/domain.operations/clone/socket/isCallerSameUser.test.ts:32
- src/domain.operations/clone/socket/isCallerSameUser.test.ts:48

`isCallerSameUser.test.ts` holds all four of its cases in `test()` blocks under a lone `describe()`, with no `given()/when()/then()` from `test-fns` anywhere in the file. The rule asks that test suites use `describe()` for grouping and the `given()/when()/then()` frame for the scenario (`given`), the act (`when`), and the outcome (`then`) — the sibling unit file `asSocketPeerPidFromSsPeerLine.test.ts` in this same change follows exactly that shape, so this file is the outlier.

Since this is a unit test (`.test.ts`) rather than an integration test, the rule treats the frame as expected rather than required, hence a nitpick. Each of the four cases maps cleanly onto the frame (given: a socket + injected `getPeerCred`/`getOwnUid`; when: the same-user check is awaited; then: the boolean or the thrown fault).

**snippet**:
```ts
describe('isCallerSameUser', () => {
  // an unconnected socket; the injected peer read never touches it
  const socket = new Socket();
  const genPeer = (uid: number) => async () => ({ pid: 4242, uid, gid: uid });

  test('a peer with our uid is the same user', async () => {
    const same = await isCallerSameUser(
      { socket },
      { getPeerCred: genPeer(1000), getOwnUid: () => 1000 },
    );
    expect(same).toEqual(true);
  });
```
