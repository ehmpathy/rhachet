`asCloneInputSurfaceText.test.ts` (edited here, plus its new snapshot) locks the `clone get --what buffer/queue` surface render for EVERY probe-blind reason the reply can carry: `feed-not-live`, `feed-faulted`, `peer-probe-blind`, `socket-gone`, and the newly introduced `probe-unanswered` (the loaded-box degrade this PR adds), each rendering a distinct `could not be read / cause / fix` tree. `[case.loaded-box]` in particular locks `probe-unanswered → "wait for it to calm, never a re-enroll"` for a get, and the reworked modal/unrecognized format (see `blackbox/cli/__snapshots__/clone.say.withheld.acceptance.test.ts.snap`) locks the nested cause/fix tree for a screen that is on a modal or unrecognized.

but the catalog's `.get (a direct clone get)` table holds only four coarse cells — `fast → state read`, `≥5s → clone get read timed out { replyMs: 5000 }`, `throws-fast → auth-denied`, `other → forbidden` — and NONE of them match what a caller actually reads. a get on a dead socket renders `could not be read / socket-gone / enroll fresh`, not `auth-denied`; a get on a not-live or faulted feed renders `could not be read / feed-not-live|feed-faulted`, not `read timed out`; a get behind a slow gate renders `could not be read / probe-unanswered / wait for it to calm` — the exact new experience this PR introduces. the `read timed out` cell is the input-state `clone get` throwing, a DIFFERENT read from the graceful `--what buffer` surface; so the surface-get blind outcomes are a real experience the contract does not hold.

per the evolution rule (`discovered at verification — itemize; demo if critipath`), the `.get` table should gain cells/rows for the surface-get blind verdicts (by reason: feed-not-live, feed-faulted, peer-probe-blind, socket-gone, probe-unanswered, plus the modal/unrecognized focus states), each with feel × care and its genuine fix line. a human reading the buffer on a loaded box has a workable fallback (wait and retry, or read the transcript), so this is an alterpath left un-itemized — a nitpick, not a blocker. the wrapper's `probe-unanswered` is cited under the `probe-observe` row (`getCloneInputStateOrBlind [case4]`), but that row is about the say's own poll probes, not the `clone get` command a human runs, so it does not cover the command-level render locked here. confirm the care once itemized; if a get-surface read is judged critipath, the demo escalation follows.
