**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.friction-hazards.md

**locations**:
- src/infra/socket/getSocketPeerCred.ts:29

The added docblock states: 'a fault of the exec itself (killed at the bound, `ss` absent) rejects with node's own `Command failed` error, which the clone gate folds into a deny (a named reason for it: ehmpathy/rhachet#683)'.

That is an admitted friction hazard on a user-facing path: when the `ss` lookup is killed at the bound or `ss` is absent, the human gets an auth deny whose reason is a raw node error string (it embeds the shell command and stderr) with no named reachCause and no hint. The naming work is deferred to rhachet#683, so at merge the deny carries no actionable fix — exactly the false-deny class (#678) this PR set out to cure for a same-user say on a loaded box. The rule requires error messages to say what went wrong AND how to fix it, and requires every blocked state to be snapped.

Either wrap the exec fault in a named error (e.g. reachCause 'lookup-timeout' / 'ss-absent' with a hint) so the clone gate denies with a named reason, or snap/assert the deny message the human actually sees for this path — a raw `Command failed: ss -xp | grep ...` is not clear enough.

**snippet**:
```ts
 * .note = linux-specific (needs /proc + ss). a guarded break (no fd, not a socket, no pid in
 *   the `ss` table, a peer gone before its /proc read) is a MalfunctionError; a bound that is
 *   not a positive number is the caller's to fix, a ConstraintError. a fault of the
 *   exec itself (killed at the bound, `ss` absent) rejects with node's own `Command failed`
 *   error, which the clone gate folds into a deny (a named reason for it: ehmpathy/rhachet#683)
```
