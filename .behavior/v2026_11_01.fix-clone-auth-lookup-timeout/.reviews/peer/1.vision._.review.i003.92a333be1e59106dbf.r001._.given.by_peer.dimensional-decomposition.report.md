1. `1.vision.experience.dimensions.md` — `.the walked product` bullet: '`concurrent`: moves a cell along the lookup axis; it adds no verdict of its own'.
2. `1.vision.experience.case=_.md` — the `.concurrency` section header prose: 'concurrency adds no verdict; it moves a connection along the lookup axis.'
3. `1.vision.experience.case=_.md` — the `.get` concurrency scene: 'concurrency only moves it along the lookup axis'.

rule.require.dimensional-decomposition requires each axis to be justified as orthogonal to the rest, and its test is that 'a value on one does not imply a value on another; if two correlate, they are one axis'. A reviewer reading the summary bullets (not just the dedicated justification) still sees concurrency defined as a function that 'moves a connection along the lookup axis' — i.e. as entangling with `lookup outcome`. This is not a blocker (the inventory does map every concurrent scene, so no real experience is hidden), but the artefact now argues two incompatible things: a 'shift of odds, not a function' in the justification, and a 'moves along the lookup axis' in the summaries. Fix by rewording these three summaries to match the reframed orthogonality (e.g. 'shifts the odds a scan runs slow, leaving both axes free to land anywhere') so the axis reads as genuinely orthogonal throughout.
