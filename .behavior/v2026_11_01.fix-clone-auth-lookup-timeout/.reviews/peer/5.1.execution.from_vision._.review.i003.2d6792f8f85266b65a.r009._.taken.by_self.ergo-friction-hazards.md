## blocker.1 — the positional parse misreads a path with whitespace · [REPAIR]

correct, and worse than a docblock claim: measured, it was a fail-open. `asSocketPeerPidFromSsPeerLine`
now reads the peer inode from the RIGHT of each line, never by column:

```ts
const SS_LINE_TAIL =
  /^.*\s(?<peerInode>-?\d+)(?:\s+users:\(\((?<tuple>.*)\)\))?\s*$/;
```

```ts
    // the peer's line, and only the peer's, holds our inode as its last inode
    const tail = line.match(SS_LINE_TAIL)?.groups;
    if (!tail?.peerInode || !targets.has(tail.peerInode)) continue;

    // the process tuple on this line is the peer's; absent → not visible to us → null
    const pid = tail.tuple?.match(/\bpid=(?<pid>\d+)/)?.groups?.pid;
```

ss prints the peer inode last before the tuple; the greedy `^.*` makes the rightmost viable split win,
so whitespace, digits, or a fake `users:((` inside an address sit to its left and cannot pose as it.
the pid is read from the matched tuple only, never from anywhere on the line.

the false docblock note is replaced:

```ts
 * .note = the peer inode is read from the right of the line (SS_LINE_TAIL), never by column
 *   position: a socket path may hold whitespace, and a positional read then lands on our own
 *   line and returns the reader's pid
```

four new rows in `asSocketPeerPidFromSsPeerLine.test.ts`: one-space path → 9191; two-space path →
9191; two-space path with only our line → null; a foreign peer whose bound path is
`users:(("x",pid=1,fd=1))` → null.

the clamp bites. with the positional parse put back: `tests: 9 passed, 4 failed` — one space
`Received: null` (the false deny), two spaces `Received: 8080` (the reader's pid), spoof
`Received: 1` (a spoofed pid; the old parse took the first `pid=` on the line)
(`.log/role=mechanic/skill=git.repo.test/what=unit/2026-11-01T21-21-35Z.stderr.log`). restored:
`tests: 13 passed, 0 failed`. socket integration `tests: 125 passed, 0 failed`
(`.log/role=mechanic/skill=git.repo.test/what=integration/2026-11-01T21-24-35Z.stdout.log`).
