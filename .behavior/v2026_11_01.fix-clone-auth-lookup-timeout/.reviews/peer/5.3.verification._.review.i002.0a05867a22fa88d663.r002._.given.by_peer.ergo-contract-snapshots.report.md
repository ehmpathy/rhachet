# blocker.1: live `clone say` success snapshot still carves out the tail that carries the new loaded-box copy

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.verification/rule.require.contract-snapshot-exhaustiveness.md

**locations**:
- blackbox/cli/clone.say.slowbox.realbrain.acceptance.test.ts:126
- blackbox/cli/__snapshots__/clone.say.slowbox.realbrain.acceptance.test.ts.snap:3

The new real-brain CLI acceptance case for a loaded box snapshots only the masked HEAD of `clone say` stdout. The tail is deliberately discarded by `asCloneSayHeadSnapshotSafe`, even though the tail is exactly where this PR's new user-facing copy lives: `└─ 🟡 screen probe unanswered (a loaded box) — verified by transcript; no action needed`. The rule forbids this carve-out: non-deterministic fields must be MASKED and the live output snapped, not omitted. The tail is deterministic for this scenario (the 7s fake `ss` forces the probe-unanswered degrade), so the test should mask the address/serial/volatile bits and snapshot the FULL stdout, including the degrade leaf. The current assertions only use `toContain('screen probe unanswered (a loaded box)')` and `toContain('verified by transcript')`, which permits drift in the rest of the rendered line and hides the exact CLI contract from the snapshot. The failure-path slowbox test already snapshots full stderr; the success-path live test should do the same for full stdout.

**snippet**:
```ts
      then('the LIVE say head renders as snapped (masked vibecheck)', () => {
        expect(asCloneSayHeadSnapshotSafe({ stdout: said.stdout })).toMatchSnapshot();
      });
```
