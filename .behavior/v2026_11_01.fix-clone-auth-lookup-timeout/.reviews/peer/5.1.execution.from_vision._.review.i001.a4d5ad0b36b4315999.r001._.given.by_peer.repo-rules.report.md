# nitpick.1: the slow-`ss` clamp relies on a process-wide `process.env.PATH` mutation rather than an injected env

**rule**: .agent/repo=.this/role=any/briefs/rule.forbid.ambient-creds-in-real-service-tests.md

**locations**:
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1424
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1425
- src/infra/socket/getSocketPeerCred.ts:68

`[case19]` de-authorizes/redirects the child by mutating the ambient `process.env.PATH` inside `useBeforeAll`, then relies on the operation under test inheriting it. the PR then had to change PROD code (`env: process.env` in `getSocketPeerCred`) purely so the test's ambient value reaches the shell — which is the smell the rule names: the credential/environment travels ambiently, and the operation has no injection seam.

the hazard is muted here because a failed override degrades to a red test (`elapsedMs >= 9_000` fails), so it fails loud rather than succeeding. still, the structural cure the rule prescribes is an explicit `env` that travels WITH the call: thread an `env`/`path` through `genCloneSocketServer`'s options into the gate's exec (or accept it on `getSocketPeerCred`), and drive it from the scene. that removes the process-wide mutation, the restore-on-teardown ordering risk (if `useBeforeAll` throws before `pathBefore` is set, the unguarded `afterAll` reads `scene.pathBefore` and masks the named `ConstraintError` with a TypeError), and the prod change made for a test's benefit.

**snippet**:
```ts
      const pathBefore = process.env.PATH;
      process.env.PATH = [binDir, pathBefore ?? ''].join(delimiter);
```
