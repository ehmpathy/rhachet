# blocker.1: `genSocketPairSameProcess` awaits listen/connect success only — a socket fault hangs the helper or crashes the worker via an unhandled 'error'

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/infra/socket/getSocketPeerCred.integration.test.ts:20
- src/infra/socket/getSocketPeerCred.integration.test.ts:24
- src/infra/socket/getSocketPeerCred.integration.test.ts:25
- src/infra/socket/getSocketPeerCred.integration.test.ts:26

The new fixture helper stands up a unix socket pair but registers NO error listeners on either the `server` or the `client`, and it settles on SUCCESS alone:
- `await new Promise<void>((done) => server.listen(path, () => done()))` — if `listen` faults (EMFILE/ENFILE, an unsupported abstract-namespace host, EADDRINUSE on a reused `\0` path), node emits `'error'` on the `Server`; with no `'error'` listener that is an uncaught exception, and the promise's `done` never runs so it stays pending forever (a hang until jest's timeout).
- `const client = connect(path)` — if the connect faults, node emits `'error'` on the `client` socket; no listener → uncaught exception, and `serverSideAccepted` (waiting on `'connection'`, which never fires) hangs.

This is the exact defect the sibling `genCloneSocketServer` guard was written to retire: an earlier shape 'awaited the bind's SUCCESS alone' and under a fault 'the await never settled: a LOUD uncaught crash became a SILENT hang' (`rule.forbid.failhide`). The whole `getSocketPeerCred.integration.test.ts` suite and `[case2]`'s PATH swap depend on this helper resolving; on a fault they hang rather than fail by name.

Fix: mirror the established pattern — settle on success OR fault (attach `server.once('error', ...)` / `client.once('error', ...)` that reject the awaited promise), and destroy the half-built pair on a fault so cleanup is symmetric.

**snippet**:
```ts
  const server: Server = createServer();
  const serverSideAccepted = new Promise<Socket>((done) =>
    server.once('connection', done),
  );
  const path = `\0rhachet-peer-cred-test-${getUuid()}`;
  await new Promise<void>((done) => server.listen(path, () => done()));
  const client = connect(path);
  const serverSide = await serverSideAccepted;
```

# nitpick.1: `context.lookupTimeoutMs` default covers an absent context but not an absent field — a partial context yields `timeout: undefined` = unbounded lookup

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/infra/socket/getSocketPeerCred.ts:38
- src/infra/socket/getSocketPeerCred.ts:76

The destructuring default on `context` only applies when the WHOLE context argument is omitted. A caller that passes a partial context — `getSocketPeerCred({ socket }, {} as any)`, or `{ lookupTimeoutMs: undefined }` slipping through a JS caller or a cast — gives `context.lookupTimeoutMs === undefined`, which is forwarded as `timeout: undefined` to `execAsync`. Node treats an absent `timeout` as NO bound, so the `ss` scan runs unbounded — the exact hazard this PR exists to retire, silently reintroduced through an unexpected default. The type requires the field, so this needs misuse to reach, but the default is documented as the safety net ('prod callers take the default') and a partial object defeats it.

Fix: resolve the value explicitly with a nullish fallback (`const timeoutMs = context.lookupTimeoutMs ?? SOCKET_PEER_CRED_LOOKUP_TIMEOUT_MS`) so an undefined field still lands on the bound rather than disabling it.

**snippet**:
```ts
  context: { lookupTimeoutMs: number } = {
    lookupTimeoutMs: SOCKET_PEER_CRED_LOOKUP_TIMEOUT_MS,
  },
```

# nitpick.2: `genSlowSsOnPath` is a shared fixture that can find a PRIOR fake `ss` and recurse if called while a swap is already active

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/.test/assets/genSlowSsOnPath.ts:25
- src/.test/assets/genSlowSsOnPath.ts:27

The fixture finds `ssReal` by scanning the CURRENT `process.env.PATH` for the first `ss`. It is placed in `src/.test/assets/` precisely so multiple suites can call it. If a second call happens while a first swap is still active (nested scenes, a scene whose teardown has not run, or a future case that calls it while another is mid-flight), `dirsSearched` lists the earlier fake `binDir` first and `ssReal` resolves to that FAKE — the new shim then `exec`s the old shim, so the real lookup sleeps `delaySeconds` twice (or stacks), producing a wall-clock/monotonic surprise in the dependent gate test rather than the single documented delay.

Fix: resolve and memoize the real `ss` from the ORIGINAL PATH captured once (or strip any known fake bins / resolve via an absolute pristine PATH) so a repeated call can never resolve to a previously-installed shim.

**snippet**:
```ts
  const ssReal = dirsSearched
    .map((dir) => join(dir, 'ss'))
    .find((candidate) => existsSync(candidate));
```

# nitpick.3: `[binDir, pathBefore ?? ''].join(delimiter)` leaves an empty PATH segment (the current directory) when PATH was unset

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/.test/assets/genSlowSsOnPath.ts:47

When `process.env.PATH` was originally unset, `pathBefore ?? ''` contributes an empty entry, so the swapped PATH becomes `binDir:` — a trailing empty segment. POSIX shells interpret an empty PATH element as the CURRENT WORKING DIRECTORY, so the shell that runs `ss -xp | grep …` now also searches CWD for every command. That widens the lookup's search surface and is a subtle environment hazard at exactly the seam this fixture exists to make deterministic. The restore path was made symmetric for the unset case (delete), but the SET path is not.

Fix: build the PATH with only non-empty segments (`[binDir, ...(pathBefore ? [pathBefore] : [])].join(delimiter)`), so an unset original yields just `binDir` and no CWD entry.

**snippet**:
```ts
  process.env.PATH = [binDir, pathBefore ?? ''].join(delimiter);
```
