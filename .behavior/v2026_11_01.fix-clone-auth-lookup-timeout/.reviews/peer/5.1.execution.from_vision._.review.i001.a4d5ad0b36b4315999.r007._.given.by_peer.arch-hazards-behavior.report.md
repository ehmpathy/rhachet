# blocker.1: `[case19]` PATH swap restore is not exception-safe — a setup failure leaks the fake slow-`ss` onto the worker PATH

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1425
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1427
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1429

`[case19]` mutates process-global state (`process.env.PATH`) to prepend a fake `ss` that sleeps 9s, then restores it in `afterAll`. The restore is NOT exception-safe:

- `process.env.PATH` is set at line 1425, and the very next statement that can throw is `await genServerWithCapture()` at line 1427 (a bind fault, a setup error, etc.).
- If that await throws, `useBeforeAll`'s scene resolves to a failed lazy ref; the `afterAll` at line 1429 then evaluates `scene.pathBefore`, which re-throws the captured setup error, so `process.env.PATH = scene.pathBefore` NEVER runs and `scene.close()` never runs.
- Result: the fake 9s `ss` stays at the front of the worker's PATH for every subsequent test file the worker runs, silently turning every auth-gated `ss` lookup in those suites into a 9s stall (potential false wedges / timeouts). This is a hidden side effect + order-dependence hazard that survives the test that introduced it.

This is precisely the defect class the sibling `[case16]` guards against: it uses optional chaining (`scene?.unclaimed?.close()`) with the comment that an unguarded teardown would replace a named error with a cleanup crash and mask the real verdict (`rule.forbid.failhide`). `[case19]` lacks that same guard.

Fix: make the restore exception-safe — e.g. capture `pathBefore` in an outer variable and restore via try/finally, or wrap the `afterAll` in optional chaining + a guaranteed restore (`process.env.PATH = scene?.pathBefore`), and set PATH only after the failable bind has succeeded (or restore in the setup's own finally).

**snippet**:
```ts
      const pathBefore = process.env.PATH;
      process.env.PATH = [binDir, pathBefore ?? ''].join(delimiter);

      return { ...(await genServerWithCapture()), pathBefore };
    });
    afterAll(async () => {
      process.env.PATH = scene.pathBefore;
      await scene.close();
    });
```

# nitpick.1: `[case19]` restore of a previously-undefined PATH coerces to the literal string "undefined"

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1430

`pathBefore` is read as `process.env.PATH` (which can be `undefined`) and later restored with `process.env.PATH = scene.pathBefore`. In Node, assigning `undefined` to `process.env.X` does not delete the var — it coerces to the string `"undefined"`. So on a host where `PATH` was originally unset, the restore writes `PATH="undefined"`, corrupting the environment for the rest of the worker rather than restoring the prior state. Guard the restore (e.g. `if (pathBefore === undefined) delete process.env.PATH; else process.env.PATH = pathBefore;`) so the mutation is symmetric with how it was applied.

**snippet**:
```ts
      process.env.PATH = scene.pathBefore;
```

# nitpick.2: fake `ss` script interpolates `${ssReal}` unquoted — a PATH entry with spaces breaks the shim

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.behavior-hazards.md

**locations**:
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts:1418

The generated shim is `#!/bin/sh\nsleep ...\nexec ${ssReal} "$@"\n`. `${ssReal}` is the absolute path discovered by scanning PATH. It is interpolated into the script unquoted, so if a PATH directory (or the checkout/worktree dir name) contains a space, `exec /some path/ss` is word-split and fails — the shim exits with an error instead of exec'ing the real `ss`, and the test reds for a reason unrelated to the property it holds. Quote the interpolated path (`exec "${ssReal}" "$@"`), and consider rejecting/skipping when `ssReal` contains whitespace.

**snippet**:
```ts
      writeFileSync(
        join(binDir, 'ss'),
        `#!/bin/sh\nsleep ${SS_DELAY_SECONDS}\nexec ${ssReal} "$@"\n`,
        { mode: 0o755 },
      );
```
