# blocker.2: the `auth-denied` error snapshot is carved to its first paragraph — the structured metadata is never snapped

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.verification/rule.require.contract-snapshot-exhaustiveness.md

**locations**:
- src/domain.operations/clone/socket/genCloneSocketServer.integration.test.ts
- src/domain.operations/clone/socket/__snapshots__/genCloneSocketServer.integration.test.ts.snap

the deny journey's assertion snaps `outcome.error.message.split('\n\n')[0]`, i.e. only the human prose line, deliberately dropping the metadata block that carries the structured cause (`reason`, `serial`, `slug`, socket path). the reason given ('the metadata below it holds a per-run socket path') is exactly the case the masking guidance covers: a volatile field must be MASKED to a stable placeholder (`<path>` / `<serial>`) and the live output snapped in full — never carved out. by cutting at the first blank line the snapshot leaves the entire structured error frame (which a machine consumer of `--output json` reads) unsupervised, so drift in the metadata shape ships silently. the repo already has `asSnapshotSafe`/`anonymize` masking used elsewhere (e.g. the slowbox acceptance snapshot), so the mask is available here and the carve-out is avoidable.

**snippet**:
```ts
expect(outcome.error.message.split('\n\n')[0]).toMatchSnapshot();
```
