# blocker.1: peer-line parser misreads a whitespace-bearing socket path — a legitimate owner can be false-denied, and a 2-space path reopens the auth bypass; docblock claims 'never a misread' and no test covers it

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.friction-hazards.md

**locations**:
- src/infra/socket/asSocketPeerPidFromSsPeerLine.ts:15
- src/infra/socket/asSocketPeerPidFromSsPeerLine.ts:28
- src/infra/socket/asSocketPeerPidFromSsPeerLine.ts:32

the new `asSocketPeerPidFromSsPeerLine` reads inodes by fixed whitespace columns (`tokens[5]` = local, `tokens[7]` = peer) and its docblock claims `.note = columns are read by position ... an address that holds whitespace shifts them, which matches no line and yields null — a deny, never a misread`. that claim is not true — the shift can misread our OWN line as the peer line and return the READER's own pid.

worked reproduction (`ss -xp` prints `<netid> <state> <recv-q> <send-q> <local addr> <local inode> <peer addr> <peer inode> users:(...)`):
- socket path with one space (e.g. checkout at `/Users/me/My Projects/x.sock`): both our line and the peer line shift by 1, so `tokens[7]` lands on `*`/a path part for both, nothing matches our inode, and the call returns `null` → the gate DENIES the real owner as `auth-denied`. that is the exact false-deny class ehmpathy/rhachet#678 is about, now reintroduced for space-bearing paths, and no test covers it (the unit fixtures use `/run/clone.sock` and `@name`, both space-free).
- socket path with TWO spaces (splits into three whitespace tokens): our own line becomes `[4]=a [5]=b [6]=c.sock [7]=<our inode> ... [10]=pid=<our pid>`. `peerInode = tokens[7]` now equals our inode, `localInode = tokens[5]` does not, so the guard passes and it returns OUR pid -> `isCallerSameUser` compares the reader's uid to itself and passes ANY caller. that is the same auth bypass this PR set out to close.

whether this bites in prod depends on `getCloneSocketPath` — if the clone socket always lives under a space-free path (e.g. a hashed `$XDG_RUNTIME_DIR`/`os.tmpdir()` name), the bypass is unreachable and only the docblock claim needs correcting. but the parser is documented as safe for any address and is not: a space-bearing clone path (a repo checked out under a directory with spaces) either false-denies or fail-opens. the fix should either (a) assert/ensure the clone path is whitespace-free and correct the 'never a misread' claim, or (b) parse robustly (e.g. from the right: the `users:(...)` tuple and the peer-end markers are unambiguous, or match the inode with a boundary regex rather than fixed positions). add a unit + a guard test for a whitespace-bearing address so the fail-closed/fail-open behavior is proven rather than asserted.

**snippet**:
```ts
    const tokens = line.trim().split(/\s+/);
    const localInode = tokens[5];
    const peerInode = tokens[7];

    // the peer's line holds our inode in its PEER column, and its own inode in the local one
    if (!peerInode || !targets.has(peerInode)) continue;
    if (localInode && targets.has(localInode)) continue;
```
