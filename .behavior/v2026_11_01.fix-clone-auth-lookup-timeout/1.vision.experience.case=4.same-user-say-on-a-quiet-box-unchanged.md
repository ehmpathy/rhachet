# case=4 — a same-user say on a quiet box is unchanged

feel = happy · care = critipath

## .narrative

most days the box is quiet and `ss -xp` returns in tens of ms. the human runs
`rhx clone say @:reviewer --what 'review the diff'`.

1. the cli's baseline probe connects; its gate scans in ms (or in a few seconds on a busier box —
   any scan under the baseline's 5s reply window walks the same), passes, and the probe reads the
   screen as `capable`
2. the dispatch connects; its gate passes in ms; the server writes `queued`, then `delivered`
3. the observe probes each pass their gate in ms and read the screen; the transcript rises
4. the cli prints `😶🎙️ said to @:reviewer` (`computeCloneSayReport.ts:189`) — no degrade note

later the human runs `rhx clone get @:reviewer`; its one connection passes the gate in ms and
returns the input state.

a raised bound changes naught a fast lookup touches: the bound is an upper limit a fast scan never
nears. this case is here so the fix is held to that — no new latency, no new line, no new frame
on the path every say takes.
