# 1.vision.experience.case=_ — inventory

axes: caller uid × connection kind × lookup outcome × concurrency (see
`1.vision.experience.dimensions.md`). 168 cells; groups that share one verdict for one reason are
rows of their own, each with its why. `solo` is assumed in the first three tables; the
concurrency table walks how `concurrent` moves a cell.

## .concurrency — how `concurrent` moves a cell

concurrency adds no verdict; it shifts the odds of where a connection lands on the lookup axis,
never the verdict a lookup cell earns. so each `concurrent` cell takes the verdict of the lookup
cell it lands in.

| scene | effect on the lookup | lands in | verdict |
|---|---|---|---|
| one say, its own probes in flight (baseline, then one per ~1.25s) | each probe adds a scan; on a slow box they pile up (~T / 1.25 at once) and slow the dispatch's own scan | `slow-short`, or past 30s → `slow-long` | itemized — the say's own load can push itself from case=1 into case=3. priced in the vision's cons; cure is F6's dream |
| many callers' says at once, same uid | each dispatch gates alone; frames chain per connection; the write queue orders the writes (extant `genCloneSocketServer.integration.test.ts` case3) | each its own lookup cell | itemized — unchanged order semantics; each say gets case=1/3/4's verdict for its own scan time |
| a `clone get` amid concurrent says or gets | its scan contends like any other; its 5s reply bound is unchanged | `fast` → state read; ≥ 5s → `read timed out` | itemized — `get` folds identically: concurrency only shifts where it lands on the lookup axis, and its verdict per lookup cell is the `.get` table's, unchanged by this behavior |
| a foreign-uid caller amid same-uid says | its gate denies; the others pass | its own cell | **forbidden** for the foreign one; the others unaffected |
| a quiet box, solo | — | `fast` | case=4 |

## .throws-fast for a same-uid caller — why alterpath

`same × throws-fast` is a false deny with no fallback, so its cost is high; its frequency for a
LIVE same-uid caller is near zero, so its care stays alterpath:

- *no fd* — node renamed `_handle`; the guard at `getSocketPeerCred.ts:44-47` fails loud on the
  first say after such an upgrade, caught by the extant socket-server integration tests
- *not a socket* — a unix socket accept always yields a socket fd; unreachable in practice
- *no pid in `ss`* — the peer exited before the scan read it, so no live caller is harmed; or the
  caller is unattributable (its own row above, F13)
- *`ss` absent* (no iproute2) — every say fails the same way, now by name
  (`` `ss` (iproute2) is absent ``, `getSocketPeerCred [case5]`), never read as an invisible peer

the label on that deny (`auth-denied`, with its run-as-another-user hint) is still false for a
same-uid caller; the cure is the `auth-lookup-fault` dream (F4), out of this wish's scope.

## .overflow for a same-uid caller — why alterpath

`same × overflow` is a false deny with no fallback for the caller (they cannot shrink the host's
socket table), so its cost is high. its frequency is near zero: the read buffer is 64 MiB, which
holds ~400k unix sockets at ~150 bytes a line, two orders past the ~7k where node's 1 MiB default
broke. its cure differs from every other lookup outcome — a larger buffer, never a longer wait —
which is why the fault is named apart from `killed` and from a generic failure
(`getSocketPeerCred [case6]`). the label on the deny is the same false `auth-denied` as
throws-fast; the cure for the label is #683.

## .forbidden — the rejection invariant

no cell with `uid = other` ever reaches a pass, on any connection kind, at any concurrency. the
bound change moves only WHEN a verdict lands, never WHICH verdict a given peer earns.

## .boundary density

the densest walk is `same × slow-short` through one `clone say` cli call: it crosses the probe
reply bound (degrades to blind), the old lookup bound (5s), the old gate bound (8s), and lands
inside the new lookup and gate bounds — four boundaries, one walk. case=1 centers on it.
