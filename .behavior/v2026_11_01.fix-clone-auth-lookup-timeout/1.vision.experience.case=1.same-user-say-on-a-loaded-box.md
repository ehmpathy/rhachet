# case=1 — a same-user say on a loaded box is delivered

feel = happy · care = critipath

## .narrative

the human's box runs a test tier and three brains. `ss -xp` takes 9s. they run
`rhx clone say @:reviewer --what 'review the diff'`.

1. the cli opens a baseline probe. its gate starts a 9s `ss` scan; the probe's 5s reply bound
   fires first, and the probe degrades to blind as `probe-unanswered`
   (`getCloneInputStateOrBlind`). the say continues
2. the cli dispatches the say on a fresh connection. its gate starts another `ss` scan, waits the
   9s (inside the 60s lookup bound, inside the 65s gate bound), reads the peer uid as the human's
   own, and passes. before the fix, the 5s exec kill threw here and the say was denied
3. the server writes `queued`, then `delivered`. the observe probes go blind the same way as the
   baseline, so the cli verifies the say by transcript and prints

   ```
   😶🎙️ said to @:reviewer
      └─ 🟡 screen probe unanswered (a loaded box) — verified by transcript; no action needed
   ```

the human sees the message landed, a few seconds later than usual, with an honest note that names
the loaded box. no false deny, and no re-enroll advice a slow box cannot use.

if the brain is busy and the transcript does not rise in the bound, the say ends `unreadable
probe-unanswered`, exit 1, and the hint forbids a blind re-send (the message was delivered) and
says to wait for the load to ease.

proven through the cli: `blackbox/cli/clone.say.slowbox.realbrain.acceptance.test.ts [case1]` — a
real enroll, a real claude, the real gate and a 7s `ss`; it snaps the tree above. with the lookup
bound put back to 5s, [case1] goes red: the say is refused. the busy `unreadable` failure needs a
brain held with no transcript rise, so it is proven at the integration grain with a stub brain:
`blackbox/cli/clone.say.slowbox.integration.test.ts [case2]`.
