# case 9 — capacity-read-is-throttled · cron · sharp · alterpath

**narrative**

the capacity read is a one-token probe whose rate-limit headers anthropic does not document. one
hour it returns no `anthropic-ratelimit-unified-*` headers, or a 429. the rotate does not stall the
fleet on that: it keeps each member's last read, marks it stale with its age, and picks on it.
a clone's own status line feeds the same cache for free each time it gets a response, so a busy
member rarely goes stale at all.

alterpath: a stale read still yields a sound pick most hours, and the next hour's read repairs it.

**bdd `[tn]` timeline**

```
given alice's last read is 50m old, and this hour's probe returns no rate-limit headers
  when [t0] the 15-minute rotate runs
    then alice's read is kept, shown as `read = 1h50m ago (stale)`, and the pick runs on it
    and  the rotate log names the probe failure; it does not exit nonzero for it
given every member's read is older than 6h (a stale cutoff)
  when [t1] a clone spawns
    then the pick still runs, and the enroll output warns `capacity unread for 6h+`
given the usage reader minted a new access token for alice, and crashed before it wrote the rotated
      refresh token back to keyrack (vision §3: one holder, write-back before use)
  when [t2] the next read for alice tries the refresh token keyrack holds
    then the mint is refused (the token was single-use), and alice's usage credential is marked `locked out`
    and  alice's capacity read falls back to her clones' status-line `rate_limits` and her last read, marked stale
    and  alice stays drawable: the setup-token a clone bills with is a separate credential, unharmed
    and  the board names the one fix: re-capture alice's usage credential at her reach, a human act at a tty
  when [t3] two processes on one box try to read alice at once
    then the second waits on the reader's per-reach lock and reuses the first's result; it never mints
```

the lockout does not return the oauth paste the wish forbids: no clone waits on it, and the pool keeps
rotation on the status line meanwhile. what the human loses is a fresh read of one member's week until
the re-capture.
