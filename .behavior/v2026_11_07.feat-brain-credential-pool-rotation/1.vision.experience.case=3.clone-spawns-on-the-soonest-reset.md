# case 3 — clone-spawns-on-the-soonest-reset · operator · clone · happy · critipath

**narrative**

the operator runs `rhx enroll claude --as @:feat` on the grove and reads one line back: which account
the new clone bills. behind that line, the pool ranked its members — alice's 5-hour window is 70% used
and resets in 40m; bob's is 20% used and resets in 4h20m. both have headroom, so the pick took
**alice**: her unspent 30% vanishes in 40m unless a clone spends it, while bob's headroom keeps.

the clone itself meets no prompt and no paste. it wakes with its own credential file — alice's token,
written into its own secure-storage dir before the brain-cli starts — and its first request bills
alice. no env token rides along, so the file stays the one source the clone reads and a later rotate
can reach it (case 4).

critipath: this is the spawn every clone on a pooled actor takes.

**bdd `[tn]` timeline**

```
given pool 'default' = [alice (70%, resets in 40m), bob (20%, resets in 4h20m)], read 15m ago
  when [t0] the operator runs `rhx enroll claude --as @:feat`
    then @:feat spawns with its own credential file = alice's token, in its own secure-storage dir
    and  CLAUDE_CODE_OAUTH_TOKEN / ANTHROPIC_API_KEY / ANTHROPIC_AUTH_TOKEN are cleared from its env
         (each outranks the file, and an env value is frozen for the life of the process)
    and  the enroll output shows `├─ brain account = alice@ahbode.com (pool default, 5h 70%, resets in 40m)`
  when [t1] @:feat sends its first request
    then it bills alice; no sign-in prompt appears on its screen
  when [t2] another clone spawns 5m later
    then it also draws alice — the pick is a read, and alice still resets soonest
given a pool member with no open window (resets_at null — idle)
  when [t3] a clone spawns
    then the idle member ranks after every member with a window that closes; its capacity keeps
given alice = 5h 70% (resets in 40m) but 7d 98% (resets in 2d); bob = 5h 20% (4h20m), 7d 30% (5d)
  when [t4] a clone spawns
    then alice's tight window is her week (98% is nearer its cap than 70%), so she ranks by her 2d reset
    and  the clone draws bob, whose tight window (5h, 20%) resets in 4h20m — sooner than 2d
    and  the enroll output names the tight window: `bob@ahbode.com (pool default, 5h 20%, resets in 4h20m)`
    so   no clone draws an account that caps on its week minutes later
```

alice's last 2% of week is not lost to this rank: she is still drawn once every member whose tight
window resets sooner is capped, or when no other member remains.
