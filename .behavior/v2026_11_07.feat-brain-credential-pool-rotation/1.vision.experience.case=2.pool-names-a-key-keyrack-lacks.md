# case 2 — pool-names-a-key-keyrack-lacks · operator · clone · sharp · critipath

**narrative**

the operator adds `carol@ahbode.com` to the pool but forgets to fill her token on the grove. the
next spawn must not quietly drop carol, and must not fall through to the shared login: either would
hide a pool that is smaller than declared. it refuses at the boundary, names the member, and prints
the exact `keyrack set` at carol's reach — not keyrack's generic tip, which on a rack that holds
alice's token would point at `unlock --reach alice` (`asKeyrackOmittedKeyTip.ts:137-138`).

a member that is held but locked is first re-unlocked headless by the pool's own read (vision §1).
only when that unlock itself fails — no robot prikey on this box, or one that does not open the
vault — does the clone meet the refusal: the same shape, a different fix, the `keyrack unlock` for
the robot owner.

critipath: a pool that silently shrinks is the defect this whole wish exists to prevent.

```
✋ ConstraintError: pool 'default' names a credential keyrack does not hold
   ├─ member = carol@ahbode.com
   ├─ key = CLAUDE_CODE_OAUTH_TOKEN
   └─ fix — mint it at a laptop, then fill it here
      ├─ claude setup-token
      └─ rhx keyrack set --owner ehmpath --key CLAUDE_CODE_OAUTH_TOKEN --env all --org @all \
            --reach carol@ahbode.com --mech PERMANENT_VIA_REPLICA
```

**bdd `[tn]` timeline**

```
given pool 'default' = [alice, bob, carol], and keyrack holds only alice and bob
  when [t0] a clone spawns via `rhx enroll claude`
    then the spawn is refused before the brain-cli starts (exit 2, no partial clone)
    and  the error names carol and the `keyrack set … --reach carol@ahbode.com` that fills her
  when [t1] the operator runs that `keyrack set`, then `rhx enroll claude` again
    then the clone spawns on a pool of three
given the grove's keyrack holds all three, locked, with the robot prikey present
  when [t2] a clone spawns
    then the pool's read re-unlocks headless and the clone spawns; no human is asked
given the same, but no robot prikey on the box opens the vault
  when [t3] a clone spawns
    then the refusal names `rhx keyrack unlock --owner ehmpath --env all`, not `set`
```
