# case 6 — swap-lands-on-no-new-account · clone host · sharp · critipath

**narrative**

the host rewrites `@:feat`'s credential file with bob's token. the rewrite exits 0. but the clone
keeps alice: perhaps the claude-code build in use no longer re-reads on mtime, or the write landed in
a file the clone does not read. a host that trusted the exit code would log "moved to bob", and the
clone would idle on alice's cap while the board says it is fine — the exact no-op swap
`term=auth.swap` warns of.

so the move is not reported until the compare passes. the compare fails: after = alice. the host
reports the move as failed, loud, names the clone and both accounts, and falls back to the one
sure lever: a restart of the clone on bob, with its session resumed (a wake). a second failure
there is a malfunction a human must see.

who feels it: the clone host acts, but the operator lives it — they read the board, and a board
that says `@:feat → bob` while `@:feat` idles on alice is a lie they act on.

critipath: a silent no-op swap is the failure that reads as success.

```
💥 MalfunctionError: swap for @:feat did not land
   ├─ target = bob@ahbode.com
   ├─ after  = alice@ahbode.com (unchanged)
   ├─ cause  = the clone did not re-read its credential file
   └─ fallback = restart @:feat on bob with its session resumed
```

**bdd `[tn]` timeline**

```
given clone @:feat on alice, and a credential rewrite to bob that exits 0
  when [t0] the verify compare reads after = alice
    then the move is reported failed, never as moved; the board does not show bob
  when [t1] the host falls back to a restart of @:feat on bob, with its session resumed
    then the compare reads after = bob, and the move is reported landed (via restart)
  when [t2] the restart also leaves alice
    then the rotate exits 1 and names the clone; no further attempt loops on it
    and  @:feat is marked `stuck` on the board, so the next tick skips it rather than retry
    and  the error names the human's next move:
```

```
💥 MalfunctionError: @:feat stayed on alice@ahbode.com after a rewrite and a restart
   ├─ target = bob@ahbode.com
   ├─ claude-code = <version the clone ran>
   └─ fix
      ├─ check bob's token alone: rhx brains pool status --pool default --fresh
      ├─ if bob reads held, the build ignores the credential file — pin the last claude-code build
      │  that rotated (Q4), then re-enroll: rhx enroll claude --as @:feat --brain-reach bob@ahbode.com
      └─ if bob reads dead, refill him (case 7) and re-enroll the same way
```
