# case 10 — choose-a-pool-or-account-per-clone · operator · happy · critipath

**narrative**

the commander wants a red-team clone billed to carol's account only, and a review clone kept off the
default pool's heavy accounts. both are a choice made at the clone, not at the box or the actor:

- `--brain-pool redteam` draws the clone from a named set; the automatic pick still ranks within it
- `--brain-reach carol@ahbode.com` pins the clone to one account; the pick is skipped
- no flag → the actor's default pool, the automatic pick

a pinned clone is still rotated by nobody but its operator: when carol caps, the host does not move a
pinned clone to bob (that would bill an account the operator excluded). it says so instead.

critipath: S4 makes per-clone choice the answer to #575's open question; with no flag there is no
way to keep one clone's work on one subscription.

**bdd `[tn]` timeline** (sketch flags)

```
given pools default = [alice, bob] and redteam = [carol]
  when [t0] `rhx enroll claude --as @:red --brain-pool redteam`
    then @:red draws carol, the only member of redteam
  when [t1] `rhx enroll claude --as @:rev --brain-reach bob@ahbode.com`
    then @:rev draws bob, pinned; the enroll output says `brain account = bob (pinned)`
  when [t2] bob caps while @:rev is live
    then the host does not move @:rev; it reports `@:rev pinned to bob, capped, resets in 2h10m`
  when [t3] `rhx enroll claude --brain-reach dave@ahbode.com` and dave is in no pool
    then the spawn is refused before any brain starts: `dave@ahbode.com is in no pool`, with the fix —
         add dave under a pool in `.agent/brain.pools.yml`, fill his token at `--reach dave@ahbode.com`
         (case 1), then enroll again. a reach outside every pool is never drawn
  when [t4] @:rev has exited, and `rhx clone wake @:rev --brain-pool default` revives it (sketch)
    then it revives with its session resumed, unpinned, and rotates with the default pool
    and  on a LIVE @:rev, wake returns the clone as it is — a live re-point has no verb (vision Q12)
  when [t5] `rhx enroll claude --brain-pool redtem` and no pool has that name
    then the spawn is refused before any brain starts, and the error lists the pools the file
         declares (`default`, `redteam`) — a typo never falls back to the default pool in silence
  when [t6] `rhx enroll claude --brain-pool redteam --brain-reach bob@ahbode.com`
    then the spawn is refused: bob is not a member of redteam. a pin inside a pool must name a member
```
