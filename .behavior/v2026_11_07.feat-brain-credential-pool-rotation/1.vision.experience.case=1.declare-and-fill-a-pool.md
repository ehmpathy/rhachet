# case 1 — declare-and-fill-a-pool · operator · happy · critipath

**narrative**

the operator runs two claude max accounts, `alice@ahbode.com` and `bob@ahbode.com`, and a new grove
for the fleet. once, at a laptop, they mint a one-year token per account with `claude setup-token`
(a browser sign-in per account, the last human step there will be). then, over ssh to the grove,
they run `keyrack set` once per account and paste the token at its hidden prompt — under the robot
owner, at the account's email as the reach. the human is at the grove's tty for that one act, and at
no point after it. then they commit one pool file
that names the two emails. from here on, no clone on that grove asks a human to sign in.

this is a critipath: with no declare-and-fill there is no pool, and the grove falls back to today's
single shared login, which caps and waits on a human paste.

**bdd `[tn]` timeline** (sketch commands — not committed flags)

```
given a grove with keyrack init'd under --owner ehmpath, and two claude accounts
  when [t0] the operator, at a laptop, runs `claude setup-token` once per account
    then each run prints a one-year token (sk-ant-oat01-…); naught is stored
  when [t1] over ssh on the grove, per account, the operator runs
           `rhx keyrack set --owner ehmpath --key CLAUDE_CODE_OAUTH_TOKEN \
              --env all --org @all --reach alice@ahbode.com --mech PERMANENT_VIA_REPLICA`
           and pastes the token at its hidden prompt (D6 = grove, a human at its tty)
    then keyrack holds one CLAUDE_CODE_OAUTH_TOKEN per reach; the secret is never echoed
    and  the fill labels the member once by the account its credential reports (vision §5), so a
         token pasted at the wrong reach is refused here, before any clone draws it
  when [t2] the operator commits `.agent/brain.pools.yml`:
           brain: claude
           key: CLAUDE_CODE_OAUTH_TOKEN
           pools:
             default: [alice@ahbode.com, bob@ahbode.com]
    then the file names reaches only — no token lives in it (S1)
  when [t3] the operator runs `rhx brains pool status`
    then both members show `held`, with their capacity (case 8)
```
