# 1.vision.experience.dimensions

the axes the pool experience varies over. each is a small closed set; each is orthogonal to the
others (a value on one implies no value on another).

| # | dimension | values | why it is its own axis |
|---|---|---|---|
| D1 | **actor** | `operator` (a human who declares the pool and fills keyrack) · `clone` (a brain-cli process that draws a credential) · `cron` (the hourly pick on a box, no human present) | each meets the pool at a different moment, and only `operator` can type a secret |
| D2 | **goal** | `declare` (name the pool) · `fill` (put a token in keyrack) · `read` (see capacity) · `pick` (choose an account for a spawn) · `rotate` (move a live clone off a capped account) · `verify` (prove the account changed) | the six verbs of the done-when clauses (S2); the same actor with two goals is two experiences |
| D3 | **pool state** | `headroom` (≥1 member uncapped) · `all-capped` · `idle` (a member with no open window: `resets_at` null) | decides what the pick may return; `idle` is a distinct value because it reads as "no data", not as "capped" |
| D4 | **credential state** | `held` (keyrack has it, unlockable) · `absent` (pool names a key keyrack lacks) · `locked` (keyrack has it, no unlock on this box) · `dead` (expired or revoked: 401) | the four answers a `keyrack.get` + first call can give; each one is a different repair |
| D5 | **capacity read** | `fresh` (read within the hour) · `stale` · `unreadable` (probe throttled, header absent) | the probe is undocumented upstream, so its failure is a real path, not a hypothetical |
| D6 | **box** | `laptop` (a human at the keyboard) · `grove` (headless, no human) | the wish's whole point: a grove must never wait on a human paste |
| D7 | **time** | `first` · `repeat` (the same pick again) · `concurrent` (two clones spawn at once) | surfaces the idempotency and race cells a happy-path list skips |

## .the walk

the full product is 3 × 6 × 3 × 4 × 3 × 2 × 3 = 3888 tuples. most collapse, because a goal fixes
its actor and pins the other axes it ignores:

| goal | actor it fixes | axes that vary for it | cells |
|---|---|---|---|
| declare | operator | D4 (each member's state), D6 | 8 |
| fill | operator | D4 {absent → held}, D6 | 2 |
| read | operator, cron | D3, D5 | 18 |
| pick | clone (at spawn), cron | D3, D4, D5, D6, D7 | the dense row; walked in full in the inventory |
| rotate | cron | D3, D4, D7 | 36 |
| verify | cron, clone | D4 {held, dead}, outcome {landed, no-op} | 8 |

the inventory (`1.vision.experience.case=_.md`) walks each row and verdicts every cell.

## .the hidden dimension the walk surfaced

`rotate × clone` fixes a value the free-list missed: a **live clone's env is frozen at spawn**
(`asBrainCliSpawnEnv.ts:61-74`), so an env token (option O5) cannot move a live clone. but
claude-code re-reads its credential file when the file's mtime moves (option O7, cited in
`.behavior/v2026_09_29.fix-shared-brain-credential-blanking/refs/inventory.of=options.case=O7-per-actor-credential-file.md`).
so `pick` writes a credential at spawn and `rotate` rewrites it on a live clone — two mechanisms,
which makes **D8 = clone liveness** {`not-yet-spawned`, `live`} latent under D2. a restart of the
clone (a wake) is the fallback when a rewrite does not land (case 6).
