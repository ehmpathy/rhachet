# case 8 — see-the-pool-capacity · operator · happy · critipath

**narrative**

the operator wants to know where the fleet stands before a big run. one command shows every member:
its state, its 5-hour and weekly windows, when each resets, how old the read is, and which member
the next spawn would draw. an idle member reads `idle`, never `0%` with a fake reset. a stale read
says how stale.

critipath: S2 names "capacity per credential is read and shown"; without it, every pick is a black
box and a dead member hides.

```
🐙 brains pool status --pool default
   ├─ alice@ahbode.com
   │  ├─ state = held
   │  ├─ 5h = 70%  resets in 40m
   │  ├─ 7d = 41%  resets in 3d
   │  └─ read = 4m ago
   ├─ bob@ahbode.com
   │  ├─ state = held
   │  ├─ 5h = idle
   │  ├─ 7d = 12%  resets in 5d
   │  └─ read = 4m ago
   └─ next pick = alice@ahbode.com (resets soonest with headroom)
```

**bdd `[tn]` timeline**

```
given pool 'default' with alice (a live window) and bob (idle)
  when [t0] the operator runs `rhx brains pool status`
    then each member shows state, 5h and 7d use + reset, and the age of its read
    and  bob's 5h shows `idle`, not a percentage
    and  the last line names the member the next spawn would draw
  when [t1] the operator runs it again within the hour
    then the cached read is shown with its age; no probe is spent (the probe is throttled upstream)
  when [t2] the operator runs `rhx brains pool status --fresh`
    then each member is probed once, and the ages reset
```
