# case 8 — see-the-pool-capacity · operator · happy · critipath

**narrative**

the operator wants to know where the fleet stands before a big run. one command shows every member:
its state, its 5-hour and weekly windows, when each resets, how old the read is, and which member
the next spawn would draw. an idle member reads `idle`, never `0%` with a fake reset. a stale read
says how stale.

critipath: S2 names "capacity per credential is read and shown"; without it, every pick is a black
box and a dead member hides.

```
🐙 brains pool status --pool default
   ├─ alice@ahbode.com
   │  ├─ state = held
   │  ├─ 5h = 70%  resets in 40m
   │  ├─ 7d = 41%  resets in 3d
   │  └─ read = 4m ago
   ├─ bob@ahbode.com
   │  ├─ state = held
   │  ├─ 5h = idle
   │  ├─ 7d = 12%  resets in 5d
   │  └─ read = 1h50m ago (stale — probe throttled, case 9)
   ├─ erin@ahbode.com
   │  ├─ state = locked (the headless unlock failed)
   │  └─ fix = rhx keyrack unlock --owner ehmpath --env all (case 2)
   ├─ carol@ahbode.com
   │  ├─ state = dead (401 since 2026-10-02)
   │  └─ fix = re-mint with `claude setup-token`, refill at --reach carol@ahbode.com (case 7)
   ├─ dave@ahbode.com
   │  ├─ state = absent (keyrack holds no token at this reach)
   │  └─ fix = rhx keyrack set … --reach dave@ahbode.com (case 2)
   └─ next pick = alice@ahbode.com (resets soonest with headroom)
```

**bdd `[tn]` timeline**

```
given pool 'default' with alice (a live window) and bob (idle)
  when [t0] the operator runs `rhx brains pool status`
    then each member shows state, 5h and 7d use + reset, and the age of its read
    and  bob's 5h shows `idle`, not a percentage
    and  bob's stale read shows its age and why, never a fresh-looked number
    and  the last line names the member the next spawn would draw
  when [t1] the operator runs it again before the next tick
    then the logged read is shown with its age; no probe is spent (the probe is throttled upstream)
  when [t2] the operator runs `rhx brains pool status --fresh`
    then each member is probed once, and the ages reset
given a member that is dead, a member keyrack lacks, and a member whose unlock fails
  when [t3] the operator runs `rhx brains pool status`
    then each shows its state and its fix on its own branch; none is hidden, none is drawn
given every member is capped
  when [t4] the operator runs `rhx brains pool status`
    then the last line reads `next pick = none — next headroom in 1h (alice)`, the same words case 5 logs
given a member cooled by a provider 429 (case 4 t6)
  when [t5] the operator runs `rhx brains pool status`
    then that member shows `state = cooled until <Retry-After lapse>`, its windows beside it, and it is not the next pick
given a member whose 7d window is nearer its cap than its 5h window
  when [t6] the operator runs `rhx brains pool status`
    then its tight window is marked (`7d = 98%  resets in 2d  ← tight`), so the rank reads plain
```
