# wish: no `rhachet-test-*` dir survives the test run that made it

## .source of record

**`ehmpathy/rhachet#488`** — read it FIRST and in full. it is the authoritative spec: it carries
the census, the repeated call-site shapes, and the four costs. this wish bounds the scope and
adds prior art the issue does not carry.

## .what

a full test run leaves **zero** new `/tmp/rhachet-test-*` dirs behind.

the guarantee must hold for a run that **fails**, a run that is **scoped** to a subset, and a run
**interrupted** part way — not only for a clean full pass.

## .why

measured on one dev machine, 2026-08-30: **12,901** `rhachet-test-*` dirs against 2,484 of all
else — so ~84% of `/tmp` is abandoned rhachet fixtures.

the costs the issue names, in the order they bite:

1. a large `/tmp` blocks boot for minutes on a LUKS system — `systemd-tmpfiles-setup.service`
   walks it
2. tools degrade — a ripgrep over `/tmp` blew a 20s timeout purely on directory count
3. inodes are held and never returned
4. a daily `find -mtime +3 -delete` sweep cannot keep up; fixtures are remade faster than a daily
   pass clears them

## .acceptance

- a full test run leaves zero new `rhachet-test-*` dirs — measured by a count before and after
- the guarantee survives a **failed** test, a **`--scope`d** run, and an interrupt
- a regression clamp that **bites**: red before the fix, green after
  (`rule.require.clamp-edge-cases`)
- a parallel run of the same suite does **not** reap a peer run's live dirs

## .prior art — this exact defect was solved once, in `nheuron`, and its lesson is cited

verified 2026-08-30 by direct read, not recalled:

`.agent/repo=.this/role=any/skills/work/work.harness.ts:62` declares `genTempDir({ slug })`,
which allocates **and** registers into a module-level `DIRS_TEMP`, paired with a sweep called
from an `afterAll`. that is the shape #488 proposes, already in production.

two hazards it solved that a naive form does not, both worth your attention:

- **never sweep by a bare prefix glob.** the harness sweeps only what *this process* made, so a
  parallel run of the same suite cannot reap its peer's live dirs. its own note:
  > *it sweeps only what this process made — never a bare prefix glob, so a parallel run of the
  > same suite cannot reap its peer's dirs.*
- **a reaper must skip both this run's own dirs and a peer's live ones** — `work.harness.ts:715`
  skips dirs in `DIRS_TEMP` (the `afterAll` owns them) and dirs named in a live process's argv.

and the lesson that *forced* the structural form, from `term=partial-audit`:

> a per-case sweep read its dir list **as of the moment it ran**, so dirs registered later
> survived every run — and under `--scope` its whole subject set went unswept with no verdict
> rendered at all. measured cost: **1,786 orphan dirs accrued under a green clamp.**
>
> the cure was structural rather than a sharper check: move the guarantee to a teardown that
> **neither order nor scope can step around**, and make it FAIL LOUD.

that is why `.acceptance` demands the scoped and interrupted cases explicitly. a fix that only
holds for a clean full pass reproduces the exact defect that precedent already paid for.
