# 1.vision — no test temp dir survives the run that made it

## the outcome world

### day-in-the-life

a mechanic runs `rhx git.repo.test --what acceptance --mode apply`. the suite makes ~432 temp
dirs across 95 files. it passes. both `/tmp` and the one contained dir under it hold exactly what
they held before.

then a scoped run. then a failed test. then a ctrl-c at 40%. same result each time: the dirs go.

when a fixture is worth a look, `TEST_FNS_KEEP=1` holds it.

### before / after

| | before | after |
|---|---|---|
| a full acceptance run | +432 dirs, forever | +0 |
| a failed test | dir survives | dir pruned |
| a `--scope`d run | dirs survive | dirs pruned |
| a ctrl-c | dir survives | dir pruned |
| a parallel peer run | — | peer's live dirs untouched |
| a deliberate hold | impossible | `TEST_FNS_KEEP=1` |
| call sites edited, any lane | — | **zero** |
| repos that inherit the fix | 1 | **every test-fns consumer** |

### the aha

**safe by default, never safe by expense.** the reclaim is not a step a caller performs — it is a
property of what they allocated. so no lesser act reaches the unsafe outcome, and the guarantee
cannot decay.

the leak this fixes is a decayed guarantee: *"OS handles cleanup"* delegated safety to a party that
would not do it. a design that leaves the reclaim as a separable step repeats that defect. folks
skip a separable step — not from carelessness, but because the step they came for is the other one.

three properties make the guarantee structural:

| the pit | how you fall in |
|---|---|
| `genTempDir` is the only allocator | every lane routes through it, so 432 call sites never learn the guarantee exists — `useBeforeAll` gives them no teardown slot anyway |
| the **name** carries the ownership | a run id in the dir name's own slot, so a `readdir` filter is peer-safe; no list to keep, none to lose |
| the teardown has no bypass | the `globalTeardown` is config, not a test — it runs once per run under a scope or a failure, and a signal runs the same teardown via the composed `globalSetup` |

## the scope choice — the fix lands in `test-fns`, not here

### why upstream

the defect is **`genTempDir`'s**. it allocates and never reclaims; its only reclaim is a 7-day age
gate that fires on a *later* call from the same repo (research 4). every caller of test-fns
inherits that. rhachet is where we **measured** it, not where it lives.

`ehmpathy/test-fns` is ours — not a third party we must route around. so a local wrapper is a
bridge over a hole we own: build it, then delete it, while every peer repo keeps its leak.
`rule.require.solve-at-cause` names this directly.

### the alternative, and the evidence that closed it

the alternative was a local wrapper (`genTestTempDir`) plus a rhachet-owned prune. probe 1 and
probe 2 (below) close it on evidence, not taste.

what those probes settle is the **boundary of what a library can own**:

| could test-fns do it invisibly, with no consumer config? | verdict |
|---|---|
| register `process.on('exit')` at first allocation | ⛔ **no** — jest kills its workers; the hook never fires (probe 1) |
| mint a per-worker id into `process.env`, prune in-worker | ⛔ **no** — jest hands each test file a fresh env copy (probe 2) |
| mint before the fork, prune from a framework hook | ✅ **yes** — but the hook must be declared in jest config |

so a library **cannot** attach a teardown jest will not run. upstream-first does not mean
zero-config; it means the config is paid **once per repo** instead of once per call site.

### what each side owns

| side | deliverable |
|---|---|
| **test-fns** | mint the run id in a `globalSetup`; stamp it in the dir name's run slot; reclaim by it in a `globalTeardown`; `TEST_FNS_KEEP`; a **configurable** age gate, defaulted to 24h |
| **rhachet** | declare the two config keys × 3 jest configs; run the same teardown on a signal; migrate every lane off its hand-rolls; the lint rule; the clamps |

### the sequence risk, and why it is not a bet

if the upstream publish stalls, rhachet keeps its leak. that is the only argument the local bridge
ever had.

the wisher's answer: **no bridge.** the director prioritizes test-fns and signals when rhachet may
bump. until then rhachet does the work the bump does not gate (handoff §what rhachet does).

sameness still bounds the cost of a later change of mind: the upstream code and a bridge would be
identical in shape — mint before the fork, stamp the name, reclaim by stamp at teardown — so a
bridge, if ever wanted, is a change of import path, not of design.

## user experience

### usecases

| who | goal | how it shows up |
|---|---|---|
| mechanic | run the suite, keep `/tmp` clean | automatic |
| mechanic | inspect a failed fixture | `TEST_FNS_KEEP=1` |
| mechanic (parallel) | two scoped suites at once | neither prunes the other's dirs |
| author of a new test | make a temp dir | `genTempDir` — one call; the lint rule refuses a hand-roll |
| a peer repo | the same guarantee | bump test-fns, declare two config keys |

### the contract

call sites are unchanged, in every lane and every repo:

```ts
// blackbox/cli/roles.boot.acceptance.test.ts — UNCHANGED
const repo = useBeforeAll(async () => genTestTempRepo({ fixture: 'with-briefs' }));
```

**prunable is not a choice — it is what a temp dir IS.** so allocation is the only act, and the
local wrapper disappears with it:

```ts
// blackbox/.test/infra/genTestTempRepo.ts
const repoPath = genTempDirPhysical({   // genTempDir, deref'd to its physical path
  slug: `rhachet-test${suffix}`,
  clone: fixturePath,
  git: { commits: { init: false, fixture: false } },
});                                      // allocated ⇒ stamped ⇒ reclaimed
```

rhachet's whole wire-up is two keys per jest config:

```ts
// jest.acceptance.config.ts
globalSetup: './jest.acceptance.globalSetup.ts',   // composes test-fns/autoprune.setup.jest + the interrupt reclaim
globalTeardown: 'test-fns/autoprune.teardown.jest', // reclaims every dir this run stamped
```

### what test-fns does behind those two keys

**the run id is minted before the workers exist.** probe 2 proves it cannot be minted inside one —
a worker gets a fresh env copy per test file, so a worker-local mint is erased between files. so
`test-fns/autoprune.setup.jest` runs once, in the jest main process, before the pool, and puts a
fresh run id on the main env.

probe 3 proves the handoff: `JEST_WORKER_ID` is injected at fork and reaches every test file's env,
nine files deep in one worker. whatever sits on the main env at fork time arrives the same way.

**the name carries the ownership, so there is no list to keep.** `genTempDir` names each dir
`{timestamp}.{run}.{slug}.{8hex}` inside one contained dir — the run id in a slot of its own, read
back by a parse rather than a loose text test, so a slug can never pose as a run.

**the teardown is config, so no test can skip it.** `test-fns/autoprune.teardown.jest` runs once,
in the main process, after every test file — under a failure and under a `--scope` alike — and
removes exactly the dirs that carry this run's id. with `TEST_FNS_KEEP=1` it keeps them and says
where they sit.

a peer run's dirs carry a different run id, so they are invisible to this reclaim. peer-safety is a
property of the name, not of a check that could be wrong.

**the disk is the state, so there is no state to lose.** two hazards that would each empty an
in-memory list are closed: jest's module registry resets per test file, and a worker can die
mid-file — its dirs carry the run id, so the main process's teardown still claims them. neither
can rename a directory.

**the interrupt path calls the same teardown.** jest never reaches its `globalTeardown` when a run
is signaled, so each composed rhachet `globalSetup` calls `setTempDirReclaimOnInterrupt`, which on
SIGINT or SIGTERM runs that same test-fns teardown, then exits 128 + signal.

a whole-run `kill -9` is **not** closed by this: no handler runs at all, so its dirs stay with a
dead run id until the 24h age gate (see cons).

### timeline

```
globalSetup mints the run id ──► fork spreads it ──► genTempDir stamps each dir
                                                             │
                   globalTeardown reclaims by run id ◄───────┤
                                                             │
                   ctrl-c ──► the same teardown, on signal ◄─┘
```

allocation IS the claim; every exit path reads the same disk state.

## mental model

> the temp dir is a library book. the desk stamps your card number in it when you take it — so
> when you leave, it collects every book with your stamp. you never remember to return one.

**the stamp goes on at checkout, so the reader carries no duty.** a call site that never sees the
allocation is never asked to see the reclaim. and the desk reads the stamps, never a shelf list —
so it collects yours and leaves the next reader's alone.

| we say | a human says |
|---|---|
| prunable by default | "cleanup rides along with the thing it cleans" |
| ownership in the name | "only prune your own mess" |
| structural teardown | "there's no way to skip it" |

the anti-model is a **class prune** — walk the dir and delete by what the name looks like, rather
than by what you know you made. it fails two different ways, and the wish forbids both:

| class prune | the failure |
|---|---|
| **ungated** — delete every `{prefix}*` | takes a live peer's dir. a class prefix cannot tell whose it is |
| **age-gated** — delete every `{prefix}*` older than N | cannot keep up. `find -mtime +3` is this, and 432 dirs per run outrun any N |

we do not hunt for what looks abandoned. we close what we opened.

### the backstop covers most of what we cannot close

"we close what we opened" has a converse: **a dir whose opener never returns is unclaimable.** no
future run shares its session, so no future prune of ours takes it. three cases land here — and the
backstop reaches only two:

| unclaimable | cleared by | when |
|---|---|---|
| `TEST_FNS_KEEP=1` | the age gate | the first run in this scope past the gate window |
| `kill -9` | the age gate | the same |
| a **deleted** worktree | ⛔ no mechanism today | test-fns#66 — see research 8 |

**this is not a reversal of the anti-model.** the age gate is safe *as a backstop* precisely
because it is age-gated and self-scoped — it cannot reach a live peer's fresh dirs. what it cannot
do is keep up as the *primary* mechanism. so: the session claims the 99% and keeps pace; the age
gate claims the residue that has no claimant at all.

**the gate must stay, and must be configurable.** `TEST_FNS_KEEP=1` depends on it — without the gate, a
deliberate hold is a permanent leak. and 7 days is far longer than a fixture's useful life, so the
default drops well below it while the value stays overridable for a genuinely long-lived fixture.

the third row needs a fix one level above our reach, so it is dispatched (research 8).

## evaluation

| acceptance criterion | served by |
|---|---|
| zero new dirs after a run | the run id in the name + the `globalTeardown` |
| survives a **failed** test | the `globalTeardown` runs after a failure too |
| survives a **`--scope`d** run | the `globalTeardown` is config, not a test; a scope only picks fewer files |
| survives an **interrupt** | a SIGINT/SIGTERM handler in the composed `globalSetup` runs the same test-fns teardown before exit; it reads the disk, so it needs no live state |
| peer run untouched | the filter is this run's id, never the class prefix |
| a clamp that bites | two clamps, one per deliverable — below |

**two deliverables, so two clamps** (awkward #5). each must go red with its own fix reverted:

| clamp | what it counts | goes red when |
|---|---|---|
| **the prune** | the probe dirs of one case's slug, at the derived root, after a nested run | the hooks are removed — **or** the run id splits per worker, which is the subtler direction (awkward #1) |
| **the lint rule** | a fixture that hand-rolls `mkdtemp` | the rule is removed |

### pros

- **every test-fns consumer inherits it** — one fix, not one per repo
- **zero call-site churn** — small diff, cheap review
- **no in-memory state to lose** — the disk is the record, so a split module instance or a dead
  worker cannot erase a directory name (a whole-run `kill -9` is a separate case — see cons)
- **peer-safe by construction**, not by a check that could be wrong
- **the local wrapper never exists**, so it never has to be deleted

### cons

- **an upstream publish is on the critical path** — bounded by sameness, not by hope (§the scope choice)
- **a `kill -9`'d run leaks until the age gate fires** — its dirs carry a dead run id, so no later
  run's reclaim claims them. the one case where the backstop is the whole guarantee.
- **two config keys per repo** — a library cannot do better; jest kills the workers that would
  otherwise self-reclaim (probe 1)
- **the prune is best-effort per path** — one un-removable path must not abort the rest

### edgecases

| edgecase | how the shape holds |
|---|---|
| two suites in parallel | each filters on its own run id |
| a test removes its own dir | `rm(force: true)` — absent path is a no-op |
| a path is un-removable | prune continues, then **fails loud** with the residue named |
| a fixture throws mid-provision | the name exists from `mkdir`, so a partial dir is already owned |
| a new test file appears | inherits the prune with no action |
| someone hand-rolls `mkdtemp` | the lint rule refuses it |
| a consumer omits the two config keys | no prune, and the age gate is their only reclaim — same as today, never worse |

### the four probes — run, and each one moved the design

each probe wrote to an in-repo log from inside `rhx git.repo.test --what unit`.

#### probe 1 — a process-exit hook never fires in a jest worker ⛔

a test file registered `exit`, `beforeExit`, and `SIGTERM` handlers, then logged from `afterAll`:

```
TEST_A     pid=1556141 isRealProcess=true
AFTERALL_A pid=1556141 listeners=1
```

the handler sat on the **real** process and was **still registered** at teardown. no `EXIT_A`, no
`BEFOREEXIT_A`, no `SIGTERM_A`, and no error-fallback file. jest kills its workers rather than let
them exit.

**what it settles:** a library cannot own the teardown invisibly. whatever test-fns registers from
inside a test file never runs. the reclaim must hang off a framework hook the framework itself calls.

#### probe 2 — `process.env` writes do not survive between test files in a worker ⛔

14 files, 6 workers, each file mint-once-if-absent into `process.env`. worker 4 ran **nine**:

```
worker=4 pid=1585559 session=Syvtxvf minted=true
worker=4 pid=1585559 session=Sou8fn9 minted=true
…nine lines, one pid, nine ids, every one minted=true
```

jest hands each test file a fresh copy of env, so a worker-local mint is erased between files.

**what it settles:** the session id cannot be minted per worker. it must exist **before** the
workers do — which is what a `globalSetup` is for.

#### probe 3 — the fork spreads the main env ✅ (this is R5)

the same log's `worker=` column *is* `JEST_WORKER_ID` — injected by jest-worker at fork time via
`env: { ...process.env, JEST_WORKER_ID }`. it reached every test file's env copy, nine files deep
in worker 4.

that is link 3 of the mint chain, observed rather than inferred. links 1 and 2 are read in source
(§the mint chain). **R5 holds.**

#### probe 4 — `genTempDir` serves lane A, isolation intact ✅ (this is R2)

the "zero call-site edits" claim rests on `genTempDir({ git: true })` yielding what
`genTestTempRepo` needs. one call, five reads:

```
RETURNED          {repo}/.temp/genTempDir.symlink/{timestamp}.probe-r2.65d656d9
PHYSICAL          /tmp/test-fns/rhachet.beav.fix-test-tempdir-leak/.temp/{timestamp}…65d656d9
RETURNED_IN_REPO  true          ← the handle is an in-repo path
PHYSICAL_IN_REPO  false         ← the bytes are not
GIT_SEES_SELF     true          ← git rev-parse --show-toplevel yields the temp dir
LOOKUP_VIA_SYMLINK   ABSENT     ← node cannot reach this repo's node_modules
LOOKUP_VIA_PHYSICAL  ABSENT
```

three things this settles for lane A:

1. **git-root detection holds.** a `git rev-parse` from the returned handle names the temp dir
   itself, never rhachet — so the fixture is self-rooted, which is what every acceptance test
   assumes.
2. **module isolation holds through the handle.** the critical one: lane A spawns the rhachet CLI
   with `cwd = repoPath`, so an escape into this repo's `node_modules` would break every blackbox
   test. node walks **realpaths**, so the lookup lands in `/tmp/test-fns/…` and finds no
   `node_modules` above it. `ABSENT` from both the handle and the physical path.
3. **lane A needs no `realpathSync`.** the handle behaves like the physical dir for both git and
   node, so `genTestTempRepo` can return `genTempDir(...)` unchanged. the deref stays a lane-D
   concern only (test-fns#65).

**and it confirms awkward #7 empirically.** `PHYSICAL` is keyed on the **worktree** name
(`rhachet.beav.fix-test-tempdir-leak`), not the repo — exactly the path test-fns#66 will move. a
clamp hardcoded to either literal is now measured, not merely predicted.

### R1 — `process.ppid` cannot be the session id ⛔

two throwaway probe files printed `pid`/`ppid`:

| run | files | pid(s) | ppid | jest mode |
|---|---|---|---|---|
| A | 2 | 1127513, 1127498 | **1127361** (shared) | forked |
| B | 1 | 1135996 | 1135993 | **in-band** |
| C | 1 (repeat of B) | 1142227 | 1142224 | in-band |

**`process.ppid` means two things.** in run A it is the jest main. in runs B and C — one test file,
so jest never forked — `pid` and `ppid` are *adjacent*, so ppid is the **npm/sh wrapper**, a process
that is not jest at all.

that instability is not hypothetical: a `--scope`d run that matches one file takes the in-band path,
and a scoped run is a first-class case in the wish's `.acceptance`.

**the collision it admits.** in-band ppid is "whatever spawned jest". via `npm run` that is a fresh
wrapper per invocation (B ≠ C, confirmed). but a human who runs `npx jest -c … --testPathPatterns foo`
straight from an interactive shell gets **their shell's pid** — stable across runs. two concurrent
scoped runs from one shell would share a session, and each would prune the other's live dirs. that
is precisely what the wish forbids.

so the session cannot be inferred from process topology. it must be **minted**.

### the mint chain, read in source

a `globalSetup` writes one id into `process.env`. three links carry it to every worker, each
verified in this repo's installed jest 30.2.0:

| # | link | evidence |
|---|---|---|
| 1 | `globalSetup` runs **in the jest main process**, awaited — so its `process.env` write lands on the main env | `@jest/core` `runGlobalHook`: `requireAndTranspileModule(...)` then `await globalModule(globalConfig, projectConfig)` |
| 2 | it runs **before** the worker pool exists | `runJest`: `globalSetup` at the `jest/globalSetup:start` mark, `createTestScheduler` strictly after |
| 3 | each worker is forked with a **copy of the main env** | `jest-worker`: `env: { ...process.env, JEST_WORKER_ID: … }` — and probe 3 observes it arrive |

so: main mints → pool built after → fork spreads main's env. the in-band case needs no link at all
— with no fork, the workers *are* the main process.

**the honest bound.** links 1 and 2 are an **implementation** contract, not a documented one.
jest's public docs are silent on env propagation, and they carry a nearby caution that reads the
other way — *"any global variables defined through `globalSetup` can only be read in
`globalTeardown`"*. that caution is about `globalThis`, **not** `process.env`, and the three links
above are why. but a future jest could change link 3 with no note.

so the execution stone should **clamp** the mint chain rather than trust it — a defect there is
silent (awkward #1).

## groundwork

### external research

**none — no third-party research was needed.** the one external artifact is `ehmpathy/rhachet#488`,
read in full.

this says naught about the **delivery** dependency: the fix lands in `ehmpathy/test-fns`, which is
ours, so it is a sequence to manage rather than a third party to research (§the scope choice,
awkward #6).

### internal research

**1. the census.** `genTestTempRepo` (`blackbox/.test/infra/genTestTempRepo.ts:79`) is called
**432 times across 95 test files** — not the issue's "~55 call sites", which came from a
`rhachet-test-` string search that misses every caller who reaches the string through the fixture.

**2. the root cause is a written-down false premise.** `genTestTempRepo.ts:59-63`:

> ```
> *   - OS handles cleanup (no manual teardown needed)
> ```

its non-repo twin `genTestTempDirNonRepo.ts:15` repeats it verbatim. linux does not clear `/tmp` on
any schedule that keeps up. both comments must be corrected as part of the fix.

**3. `genTempDir` can serve every lane, out-of-repo cases included.**
`genEphemeralTempDir.ts:36-43` runs `initGitRepo({ dir: tempDir })` against the **physical** dir at
`/tmp/test-fns/{repo}/.temp/{name}`. so `git: true` yields a self-rooted git repo physically outside
this repo — what `genTestTempRepo` needs.

for a cwd that must be **not any** git repo, `genIsolatedTempInfra.ts:52,73-76` makes
`genTempDir.symlink` a **directory-level** symlink onto `pathPhysical`, so a `realpathSync` of the
returned handle reaches the physical dir, outside any repo. lane D wraps that as
`realpathSync(genTempDir({…}))` — or drops it once test-fns#65 lands.

**4. `genTempDir` gives containment and an age gate, not a teardown.** it still writes under `/tmp`
— `genIsolatedTempInfra.ts:42` hard-requires `/tmp`. but into **one** contained dir,
`/tmp/test-fns/{repo}/.temp/`, one entry per dir, named `{timestamp}.{slug}.{8-hex}`.

so a migration with no teardown splits the wish's four costs in half:

| cost | migration alone |
|---|---|
| #1 boot walk, #2 ripgrep timeout | ✅ fixed — `/tmp`'s **top level** stops growth |
| #3 inodes, #4 age gate outpaced | ✗ entries still accrue **inside** |

the age gate has three properties that bound what it can promise (`genTempDir.ts:107` →
`pruneStale.ts`):

- **caller-triggered, never scheduled** — it runs inside `genTempDir`, so a dir is reclaimed only
  when a *later* `genTempDir` call happens. no timer, no daemon
- **self-scoped** — it is passed `tempInfra.pathPhysical`, so it scans only the contained dir of
  the repo that called it. it never reaches a peer worktree's (research 8)
- **7 days, and age is read from the dir name** — `computeStaleDirs` parses the timestamp prefix,
  and **preserves** any dir whose name does not parse

the public contract (`dist/contract/index.d.ts`) exports only `genTempDir` and `isTempDir` — no
teardown a consumer can call. and a 7-day gate is the exact shape the wish criticizes in
`find -mtime +3`. so containment serves the `.why`, never the `.acceptance` — which is why the
teardown, not merely the migration, is the deliverable.

**5. no `globalSetup` or `globalTeardown` exists; `setupFilesAfterEnv` does.** all three configs
(`jest.unit.config.ts:48`, `jest.integration.config.ts:52`, `jest.acceptance.config.ts:43`) declare
`setupFilesAfterEnv`, and `jest.acceptance.env.ts:54` already uses the slot to source keyrack creds.
no config sets `resetModules`. `jest.acceptance.config.ts:46` sets `maxWorkers: '50%'` —
multi-process, which is why a class-prefix prune would be dangerous and a session filter is not.

the absent `globalSetup` is a deliverable: probe 2 shows the session cannot be minted in a worker,
so all three configs gain the hook — pointed at test-fns' module, never a local one.

**6. `rhx clone prune` is this design, already shipped on a different noun.** it prunes an actor's
finished DEAD clones so `.agent/.actors/` does not grow unbounded, and `term=prune` documents it.
it solved every hazard this behavior faces:

| `clone prune` | this design |
|---|---|
| never prunes a clone whose pid it cannot verify | never prunes a dir whose session is not ours |
| plan by default; `--mode apply` commits | prune by default; `TEST_FNS_KEEP=1` suppresses |
| one failed removal does not abort the batch — prunes the rest, then fails loud with the serials it could not prune, never a silent partial | one un-removable path does not abort — prunes the rest, then fails loud with the residue named |

so the upstream implementation should **cite `clone prune` and follow it**, rather than re-derive
the shape. two instances of one safe-by-default prune, not two unrelated prunes.

**7. the vocabulary is settled — this behavior coins no new term.**

| word | verdict |
|---|---|
| `prune` | canonical for "remove what has gone stale". forbidden synonyms: `sweep`, `reap`, `cleanup`, `gc`, `purge`, `vacuum` |
| `keep` | already declared — `ClonePruneDecision = 'prune' \| 'keep'` (`computeClonePruneDecision.ts:30`), so `--keep` conforms |
| `session` | test-fns' word to choose, since the operation lands there. locally it names one jest invocation's mint |
| `run` | deliberately **not** itemized — `rule.require.domain-term-itemization` names it in its own exclusion list as generic english |

**8. each worktree gets its own contained dir, and a dead one never self-clears.**
`computeIsolatedTempBasePath.ts:15` takes `path.basename(gitRoot)`, so a worktree at
`…/_worktrees/rhachet.beav.fix-test-tempdir-leak` writes to
`/tmp/test-fns/rhachet.beav.fix-test-tempdir-leak/.temp/` — not the main checkout's
`/tmp/test-fns/rhachet/.temp/`.

two consequences, one good and one bad:

**a prune never reaches another branch's dirs.** peer-safety holds across worktrees for free, one
level above the session. our session does not depend on this — two parallel runs in the *same*
worktree were always possible — so it is a bonus, never a load-bearing layer.

**a deleted worktree's dirs live forever.** the age gate is caller-triggered and self-scoped
(research 4), so it reclaims `/tmp/test-fns/{X}/.temp/` only when a later `genTempDir` runs *from
worktree X*. delete X and no such call can ever happen — its whole tree, at any age, is orphaned.
no future run of ours claims it either, since its sessions are dead.

**the cause is that the scope key is wrong, and it is fixable upstream.** a worktree is not a
separate repo — its `.git` is a pointer file (`gitdir: …/rhachet/.git/worktrees/{name}`), so the
main checkout is always derivable via `git rev-parse --git-common-dir`. key the contained dir
**there** and every worktree of `rhachet` shares `/tmp/test-fns/rhachet/.temp/`, where a deleted
worktree's stale entries are reclaimed by the next run from any peer. the extant age gate then
reaches them unchanged — no **cross-scope walk** is needed to hunt an orphan, because there is no
orphan left to hunt.

that is [test-fns#66](https://github.com/ehmpathy/test-fns/issues/66), together with the shortened
gate. it costs the free cross-worktree isolation above — an acceptable trade, since our session
already carries peer-safety and must anyway.

**this is a dispatched hole, never a scoped-out one.** a worktree deleted *after* this fix lands
still orphans its dirs, so it is new litter rather than the historical litter the wish excludes.
bounded at ~1 dir per branch, so it does not gate this behavior.

## what is awkward

**1. ⚠️ the session carries the whole design.** it must be one value: **the same across this run's
jest workers**, and **different from a concurrent run's**. both directions can fail, and they fail
differently:

| wrong direction | what happens |
|---|---|
| session differs per worker | each worker prunes only its own slice — dirs survive under a green suite. the `1,786 orphan dirs under a green clamp` precedent in a new costume. |
| session collides across runs | we take a peer's live dirs. the wish forbids this outright. |

`process.ppid` cannot serve (R1). the mint chain can (probe 3 + links 1–2), but links 1 and 2 rest
on jest's implementation rather than its docs. so this row is the design's residual risk, and the
clamp must bite on it.

**a corollary:** jest reuses a worker **process** across files while it resets the module registry
per file. so a `process.on('SIGINT')` at module scope would re-register per file and trip node's
max-listener warn. the handler must be idempotent per process, guarded on `process` itself rather
than in module scope.

**2. the interrupt criterion earns the least and risks the most.** a full run leaks ≥432 dirs; an
interrupted run leaks the few live at that instant — well under 1% of the 12,901. yet the signal
handler is the most fragile piece: it races jest's own handler, it must be sync-only `rmSync`, and
its forced `process.exit` could mask a real failure code.

it stays — an explicit criterion, and cheap. but it is built **last**, behind the teardown path,
and must not destabilize the 99%.

**3. `TEST_FNS_KEEP=1` fights the whole point.** the value is that dirs vanish, which is exactly wrong the one
time a mechanic wants to open a failed fixture. the hatch resolves it, at the cost of a flag that
must not be left on in CI.

**4. the clamp reads outside the repo boundary.** `rule.forbid.reads-outside-the-repo` states
"there is none" of exceptions, and "if a genuine need arises, **ask** rather than read". the ask
was made and granted, so the literal `/tmp` count is authorized. **resolved:** the rule now names
the carve-out in `.the one exception`, bounded to a count at a derived path.

**5. the fix and the rule are two deliverables.** the code fix stops today's leak; only the lint rule
stops the next one. both are in scope, and they have different review surfaces — the rule needs its
own examples and enforcement point.

**6. the deliverable now spans two repos.** the clamp that proves the fix lives here; the code it
clamps lives upstream. so this behavior cannot go green until a test-fns version ships — and the
execution stone must pin the version it bumps to, or the clamp measures whatever was installed.

**7. ⚠️ the clamp measures a path that upstream is about to move.** today the contained dir is keyed
on the **worktree** name (research 8), so this branch writes to
`/tmp/test-fns/rhachet.beav.fix-test-tempdir-leak/.temp/`. test-fns#66 re-keys it to the git
**common** dir, so it becomes `/tmp/test-fns/rhachet/.temp/`.

a clamp that hardcodes either literal counts **0 before and 0 after** once the other one is live —
green, and blind. that is the `1,786 orphan dirs under a green clamp` precedent a third time.

so the clamp must **derive** the path from the same operation the allocator uses — ideally a
contained-path export from test-fns, which also retires lane D's `realpathSync` (#65). a derived
path makes #64 and #66 safe to land in either order; a hardcoded one makes their order decide
whether the clamp works, and stays silent when it does not.

probe 4 measured this rather than predicted it: the physical dir came back as
`/tmp/test-fns/**rhachet.beav.fix-test-tempdir-leak**/.temp/` — the worktree name, live today.

**8. a second peer-safety defect exists today, and the fix cures it incidentally.**
`src/.test/infra/withTempHome.ts:20` builds a **deterministic** path
(`/tmp/rhachet-test/{name}`), and its `setup()` runs `rmSync` before `mkdirSync`. all 8 call sites
pass distinct names, so no two files collide *within* a run — but two concurrent runs share the
path, and the second **deletes the first's live temp home mid-test**.

that is the wish's peer-safety criterion failing now, by a different mechanism than the leak. found
by the lane-B census.

**resolved by deletion, not by a clamp.** `withTempHome` is a second temp-dir allocator — a
synonymous codepath beside `genTempDir`. the wisher's call: eliminate it. its 8 callers move to
`genTempDir`, the file is removed, and the lint rule refuses its return. with no deterministic-path
allocator left, there is no code for a refactor to regress.
