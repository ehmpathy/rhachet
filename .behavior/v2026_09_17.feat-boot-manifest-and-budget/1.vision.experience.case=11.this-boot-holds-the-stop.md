# case=11 — a `.this` boot over its budget holds the stop

**cell `H7`** — gate `onStop` × ownership `.this` (the repo's own `.agent/repo=.this` roles). **sharp ×
critipath.**

🔴 **reinstated by `S18`, which narrows `S14`.** `S14` struck the `onStop` gate as a repo-wide roster
that fired on every spec at every session close. `S18` keeps that strike for the roster, and brings
the gate back for one population: the repo's own `.this` roles, whose boot no other gate sees and
whose files the session author can always write.

---

## .the narrative

a repo keeps its own briefs under `.agent/repo=.this/role=any`. nobody declared a budget for them, so
the boot grows a brief at a time and no one notices.

`rhx init --hooks` findserts two things: `budget.tokens: 5_000` in that role's `boot.yml`, and an
`onStop` hook that runs `roles cost --all --when hook.onStop`. while the boot fits, the hook is
**silent** — a session closes as it always did.

then a brief grows the boot past its cap. the next session's stop is **held**:

```
🧢 roles cost --all --when hook.onStop
├─ ✋ ConstraintError: 1 boot spec over budget
│  └─ .agent/repo=.this/role=any/boot.yml (29,264 / 5,000 tokens)
├─ some resources must go — you choose which
└─ fix — four strategies, cheapest first
```

the author is present, the named file is a regular file in their own tree, and the remedy is one
edit away.

## .the bdd sketch

```
given [case1] a repo whose own role has a payload and no budget
  when [t0] init --hooks
    then boot.yml now declares a 5_000 token budget
    then hooks.yml declares the onStop budget hook
  when [t1] the onStop hook fires while the boot fits its budget
    then exits 0, and is silent
  when [t2] a brief grows the boot past its budget, then the hook fires
    then exits 2, so the stop is held
    then stderr names the spec over budget and the remedies
  when [t3] init --hooks runs again
    then findserts naught new

given [case2] a repo whose own role already declares a budget
  when [t0] init --hooks
    then boot.yml is left exactly as its owner wrote it
  when [t1] the onStop hook fires against the owner budget
    then exits 2, measured against the owner budget

given [case3] a caller that names no declared hook event
  then --when hook.bogus is refused, and --when without --all is refused
```

proven at `blackbox/cli/init.hooks.boot-guard.acceptance.test.ts`, every case above, with snapshots.
