## .the narrative

Bea boots the mechanic role. its boot.yml declares no `budget`, because it was written before
budgets existed.

**the boot renders, and exits 0.** no halt, no warn on stderr. one line of `<stats>` differs from
yesterday:

```
  └── tokens ≈ 56818 / unlimited budget ($0.17 at $3/mil)
```

she can tell at a glance that this role runs uncapped — and that a cap is one line of boot.yml away.

⇒ that is the requirement: **no refusal, and no silence.** there are **15** extant boot specs in this repo's `.agent/`
(`rhx globsafe --pattern '.agent/repo=*/role=*/boot.yml'`), and none declares a budget — a default
cap, of any value, would halt every one of them on the first session after release.

🟡 **the basis for "none declares a budget" is logical rather than a census**, and it is stated that
way deliberately: `budget` is a key **this wish introduces**, so no extant spec has a reason to
carry it and no extant code reads it. spot-verified by a full `Read` of
`repo=bhrain/role=driver/boot.yml` and a grep over the 2 non-symlinked specs. ⚠️ **a census of all
15 was NOT performed** — 13 are symlinks into `node_modules`, which defeats a cheap count.

### 🔴 the aha, inverted — the value here is the ABSENCE of an experience

every other demo shows what the human sees. this one shows what the human **must not** see.

| if a default cap existed | what ships |
|---|---|
| default = generous (say 50k) | a cap nobody chose, which silently becomes the norm, and which the ~46% payload would have passed anyway. it caps naught and implies it caps |
| default = tight (say 5k) | every extant role halts at once. the release is a breakage |
| default = absent | ✅ opt-in. an author who wants a cap declares one |

⇒ **the cap is a declaration, never a policy.** this is also what keeps the feature adoptable: a
role takes a budget when its author is ready to pick the number.

## 🔴 .the hole this cell leaves open, deliberately

`[t2]` is worth a second read. a manifest with no budget is an **uncapped custom payload** —
exactly what the wish calls *"the extant defect with a nicer syntax"*.

requirement 4 says it must render. so the wish is internally consistent only because **both
halves land together**: the manifest opens the path, and the budget makes the path cappable.

⇒ this is the mechanical reason the wish refuses a two-pr split. `[t2]` is the cell that would
ship alone.

🟡 **it does not follow that a manifest must be forced to declare a budget.** to require one on
`--manifest` but not on a role would be a second dialect, and requirement 1 forbids that. the
honest answer is that a manifest *may* be uncapped, and whatever generates manifests
(the dispatched consumer halves) should emit one with a budget by default.

⇒ raised as fulcrum **F9** — whether `--manifest` should *warn* when no budget is declared. `S11`
cut the warn; `S19` settled the callout in-band instead — one `<stats>` line, on both sources, and
naught on stderr.

## .the regression gate

this cell's proof is **the extant snapshots, resnapped once** — each moves by the one suffix alone:

| artifact | what it pins |
|---|---|
| `blackbox/cli/__snapshots__/roles.boot.bootyaml.acceptance.test.ts.snap` | the `<stats>`, `<brief.say>`, `<brief.ref>`, `<also>` blocks for 6 cases |
| `blackbox/cli/roles.boot.acceptance.test.ts` | boot with no boot.yml |
| `blackbox/cli/roles.boot.published.acceptance.test.ts` | boot from published packages |
| `roles.boot.performance.*.acceptance.test.ts` | 🔴 the boot latency budget — see below |

🔴 **the performance assertions are why this cell guards the LAZY LOAD, not the counter.** the
tokenizer's cost decomposes into **~1,800ms of one-time encoder construction** and **~46ms of
encode** for a 44,666-char payload (measured via `rhx perf.test`, over a 174ms floor).

⇒ so what these tests forbid is a tokenizer constructed on **every** boot. they do **not** forbid a
real tokenizer — encode sits inside the assertion with room to spare.

🔴 **that is exactly what requirement 4 delivers: the tokenizer loads only when a `budget` is
declared.** this cell's boots declare none, so they construct no encoder, and the assertion is
untouched.

⚠️ **the trap these numbers set: *"a real tokenizer costs ~1.66s"* names encoder CONSTRUCTION and
calls it tokenization** — a real measurement of the wrong operation, and one that reads as evidence
because it carries digits. ⇒ `F1`, and the new assertion this cell owes is item `1′` there: **a
budgeted boot is a new path, and it owes its own latency bound.**

## 🔴 .this cell is F12's CONSTRAINT

`F12` measures the gated quantity at **36.5%** of what the boot emits, and its guess is to gate the
full rendered payload. 🔴 **this cell is what forbids that correction from applying globally.**

`[t0]` pins the uncapped `<stats>` line:

```
then <stats> calls it out as budgetless
  - tokens ≈ 56818 / unlimited budget ($0.17 at $3/mil)
```

⇒ that number **is** `chars / 4`, and `chars` is the quantity F12 corrects. a global fix would
construct the tokenizer on every boot — ~1.8s on every unbudgeted session — to sharpen a number no
gate reads.

| F12's shape | what happens here |
|---|---|
| correct `chars` **globally** | 🔴 every unbudgeted boot pays the encoder construction. the perf shield breached |
| correct it **only when a `budget` is declared** | ✅ this cell keeps the `≈` estimate; `case=1`'s receipt and `case=2`'s halt get the honest number |

⇒ **so F12's "show the corrected number only when a budget is declared" is not a preference — it is
the only shape this cell permits.** `S19` changed this cell's render, and left that constraint whole:
the `≈` marks the unbudgeted number an estimate.

🟡 **and it is a good property of the walk that this cell predates F12.** it pinned the constraint
before anyone knew the constraint would be needed.
