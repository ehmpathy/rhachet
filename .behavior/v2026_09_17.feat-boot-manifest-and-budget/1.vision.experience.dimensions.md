# 1.vision.experience.dimensions

the axes the boot-manifest-and-budget experience varies over, and the product walked.

⇒ the verdicted cells live in `1.vision.experience.case=_.md`. the demos live in
`1.vision.experience.case=N.$slug.md`.

---

## .the primary grid — the boot that renders

### axis A — payload source (2)

**where the spec that shapes the payload comes from.**

| value | sense |
|---|---|
| `role-default` | `rhachet roles boot --role X` — reads `.agent/repo=$r/role=$X/boot.yml` |
| `custom-manifest` | `rhachet roles boot --manifest <path>` — reads the named file |

orthogonal to the rest: the source decides *which file is read*, never what is in it.

### axis B — spec state (3)

**whether the spec can be read at all.**

| value | sense |
|---|---|
| `valid` | the file is present and parses |
| `absent` | the file is not there |
| `malformed` | the file is there and does not parse (bad yaml, or bad schema) |

### axis C — budget (3)

| value | sense |
|---|---|
| `undeclared` | no `budget` key — the spec names no cap |
| `declared-under` | a cap is named, and the resident payload fits it |
| `declared-over` | a cap is named, and the resident payload exceeds it |

🟡 **C folds two concepts on purpose.** *declaration* and *comparison* look like two axes and are
not orthogonal — you cannot be over a cap you never declared. the method says to merge a
correlated pair, so C is one axis of three values rather than two axes with four void cells.

### the product

**A × B × C = 2 × 3 × 3 = 18 cells.** walked in the inventory.

## 🔴 .the latent axis the grid surfaced — selection

the `role-default` × `valid` row forced a question no free-list would have asked.

a role's boot.yml may be in **subject mode**, and `--subject a,b` boots a *subset* of it
(`bootRoleResources.ts:84-101`). so the resident payload of one spec is **not one number** — it
varies by which subjects were asked for.

> **a budget of what?** the spec as a whole, or the payload this invocation actually renders?

| value | sense |
|---|---|
| `all` | no `--subject` — the always section plus every subject |
| `subject-scoped` | `--subject a,b` — the always section plus the named subjects |

⇒ this is a **domain discovery from the grid**, not a detail. the two readings differ by a large
factor on a subject-mode role, so a budget that measures the wrong one is a budget that refuses a
boot it should pass. it is raised as fulcrum **F2** and demoed as an alterpath.

⇒ it composes with A: a **custom manifest** may itself be subject mode, so `--manifest` and
`--subject` must either compose or refuse each other explicitly.

### 🔴 .the selection axis, CROSSED — a latent axis owes the same walk as a declared one

🔴 **a latent axis feels DISCOVERED rather than DECLARED, so the pull is to give it a demo instead
of a walk** — the discovery is the hard part, and it reads as the finish line.

⇒ the cell such a shortcut omits is `subject-scoped × undeclared`, which is **the actual current
experience for the one subject-mode spec today**. so the axis is crossed against the primary axes it
varies over, exactly as a declared axis would be.

**crossed with C** (spec state pinned to `valid`, source `role-default`):

| cell | budget | verdict | where, or why |
|---|---|---|---|
| **L** | `declared-under` | **demoed** | `case=6` `[t0]` — 6,000 against an 8,000 cap passes, with a receipt |
| **L′** | `declared-over` | **demoed** | `case=6` `[t1]`/`[t2]` — the halt names the per-subject cost, so a subject can be cut |
| 🔴 **L″** | `undeclared` | **itemized** | **today's state for the one subject-mode spec** — it renders the subset uncapped. the property is requirement 4's, and `case=5` already demos it for the `all` selection; **selection does not change it**, since an absent `budget` key is not consulted at any selection. low freq, low cost ⇒ a deliberate skip |

**3 = 2 demoed + 1 itemized + 0 forbidden.** ✅ reconciles.

**crossed with B** — `subject-scoped × {absent, malformed} × {undeclared, declared-under,
declared-over}` is **6 cells, every one impossible by nature**: **a selection is a choice among
sections a spec declares**, so no spec — or no parseable one — ⇒ no sections to select from. that
is why B is pinned to `valid` above rather than omitted.

🟡 **4 of the 6 are impossible on two independent grounds** (no sections to select, *and* no spec ⇒
no budget); **2 — the `undeclared` pair — are impossible for the selection reason alone**, and those
two are the only cells this axis adds to the impossible set by its own argument. ⇒ the 6 are tabled
as `Li1`–`Li6` in `1.vision.experience.case=_.md`, which is where the walked matrix lives.

⚠️ **the count is 6, never 4.** a tally of the doubly-impossible rectangle alone loses the two
`undeclared` cells the selection argument contributes on its own — which is why the matrix lives in
the inventory, where a cell that no argument claims is visible as a gap.

**crossed with A** — `custom-manifest × subject-scoped` is **itemized**, and the inventory carries
that row: `F2`'s compose-or-refuse fork is unsettled, so the fulcrum owns the decision and a demo
would assert one branch of it. 🟡 **that is why `case=3` carries no subject-compose `then`** — see
the note in that file.

## 🔴 .axis G — OWNERSHIP, the axis wish requirement 8 makes decisive

| value | sense |
|---|---|
| `ours` | the spec is writable by this repo — `repo=.this/**`, or any `--manifest` path inside it |
| 🔴 `foreign` | the spec's realpath leaves the repo — a symlink into a version-pinned store |

**a latent axis, exactly as `selection` is** — implicit in every cell until requirement 8 makes it
decisive. ⇒ and `rule.require.experience-catalog-evolution` is explicit that a new experience found
at any later stage evolves the contract **before that stage passes**, so it is walked here rather
than merely noted.

### crossed with C — the budget axis, which is the only one it changes

| # | ownership | budget | verdict | why |
|---|---|---|---|---|
| **G1** | `ours` | `declared-over` | **demoed** | `case=2`. requirement 2, unchanged — the halt fires |
| 🔴 **G2** | `foreign` | `declared-over` | 🔴 **itemized** | requirement 2's **first exception**: not gated. every remedy would name an unwritable file |
| **G3** | `ours` | `declared-under` | **demoed** | `case=1` / `case=3` |
| **G4** | `foreign` | `declared-under` | **itemized** | renders; the gate is moot below the cap, so it is indistinguishable from G3 at the surface |
| **G5** | `ours` | `undeclared` | **demoed** | `case=5`. requirement 4 |
| **G6** | `foreign` | `undeclared` | **demoed** | `case=5` covers it — **13 of the 15 extant specs ARE this cell**, and `case=5` boots them |

**6 cells = 4 demoed + 2 itemized + 0 forbidden + 0 impossible.** ✅ reconciles.

🔴 **G2 is the cell requirement 8 creates, and it is an alterpath rather than a critipath** — so it
is itemized, not demoed, and the verdict is argued rather than assumed:

| the care test | the answer |
|---|---|
| how often does it arise? | 🔴 **never today.** `budget` is a key this wish introduces, so no extant spec declares one. it arises only when a third party ships a cap |
| what does it cost when it does? | a boot renders that a stricter read would have halted. no data loss, no wrong output |

⇒ **freq ≈ 0 × cost = low ⇒ alter** (`define.experience._.axis=care.path=criti-vs-alter`). an
itemized alterpath owes no `case=N` demo, and its absence is a nitpick rather than a blocker
(`rule.require.experience-coverage`).

🟡 **G4 alone is itemized on indistinguishability.** a foreign spec *under* its cap renders
byte-identically to an owned one, so the ownership check has no observable effect and a demo would
assert a difference that does not exist.

🔴 **G6 is DEMOED.** it is indistinguishable too — and `case=5` already renders it, so the demo
exists regardless. ⇒ **indistinguishability decides whether a NEW demo is owed; it never un-demos a
cell an extant demo covers.** the inventory's `.the ownership cross` carries the same correction.

### 🔴 what axis G costs the walk

**it does NOT multiply into A × B × C.** ownership is a property of the *spec's provenance*, and A
already splits on source (`role-default` vs `custom-manifest`) while B splits on its content. so
G × A × B × C would be `2 × 18 = 36` cells of which the 18 new ones differ from their twins **only
in the `declared-over` row** — which is G2, already tabled.

⇒ the primary walk stays **18**, and axis G is carried as its own 6-cell cross against C, in the
same place and for the same reason the `selection` family is: **a latent axis gets a walk, never a
demo.**

## 🔴 .axis H — the GATE

> 🔴 **NARROWED 2026-09-23 by `S14`: the axis has TWO positions, not three.** the `onStop` position
> was struck with the hook itself — *a human may sweep; a hook may not*. the struck rows below keep
> their ordinals (`H3`, `H4`) so no citation of this table breaks
> (`rule.forbid.itemization-without-coordinates`).

| value | sense | sees |
|---|---|---|
| `introspect` | `rhachet repo introspect`, at `build:complete`, pre-publish | **only** `src/domain.roles/*/boot.yml` inside a `rhachet-roles-*` package |
| ~~`onStop`~~ | 🔴 **STRUCK** — the hook is cut (`S14`) | — |
| `boot` | `rhachet roles boot` / `onBoot` | whatever spec that boot names |

🔴 **what replaced the struck gate is a COMMAND, never a gate**: `roles cost --all` sweeps every
spec in the repo and **reports**, at a human's invocation. it is not a position on this axis,
because it refuses naught — `boot` gates, `cost` reports (`S13`, `S16`).

**the third latent axis, and the one with the most structural consequence.** every prior cell
assumed a single gate — `F4` spent 96% confidence on *which line of the render path*, a question
that presupposed the render path was the only gate.

⇒ **axis H is what refuted it.** the gate is not a position; it is a *population filter*, and no one
gate sees the whole population.

🔴 **and `S14` then refuted axis H's own first answer.** the walk concluded *"no one gate sees the
whole population, therefore add gates until they do"* — and the third gate it added fired
**unprompted**, on a question no session had posed. ⇒ **a population a gate cannot see is not
automatically a population that owes a gate.** the residue is served by a command a human types,
which is a different instrument entirely.

### 🔴 crossed with G — the ownership axis, because the RUNG is the product of the two

the rung is computed, never constant (requirement 8 × requirement 9). so the cross is `H × G`, and
the `declared-over` row of C is the only one where a gate is observable at all:

| # | gate | ownership | rung | verdict | why |
|---|---|---|---|---|---|
| **H1** | `introspect` | `ours` | 🔴 **halt** | 🔴 **demoed** — `case=8` | the author's `npm run build` refuses, pre-publish. the remedies are all writes they can make |
| **H2** | `introspect` | `foreign` | — | 🔴 **IMPOSSIBLE** | git cannot track a symlink into `node_modules`, and introspect reads only git-tracked source. **the cell cannot be constructed** |
| ~~**H3**~~ | ~~`onStop`~~ | ~~`ours`~~ | — | 🔴 **STRUCK** — `S14` | ~~demoed by `case=9`~~; the demo is deleted with the gate. **the payload that motivated this wish is still covered** — by `roles cost`, which its author types |
| ~~**H4**~~ | ~~`onStop`~~ | ~~`foreign`~~ | — | 🔴 **STRUCK** — `S14` | it was already *"indistinguishable in effect from H6"*, which is the tell a first read passed over |
| **H5** | `boot` | `ours` | 🔴 **halt** | **demoed** — `case=2` | the halt demo, and now the **only** halt on a spec a boot names |
| **H6** | `boot` | `foreign` | 🟡 **warn** | **itemized** — `G2` | the cell requirement 8 creates. already walked as `G2`, and its alterpath verdict is argued there |

🔴 **4 live cells = 2 demoed + 1 itemized + 1 impossible + 0 forbidden**, plus **2 struck**. ✅
reconciles.

🔴 **H2 is the walk's first genuinely IMPOSSIBLE cell**, and that is worth more than a verdict: it
is the *reason* gate 1 can halt unconditionally. the boot gate needs the `lstat` to decide its rung;
introspect needs no check at all, because the population it reads is writable by construction.

⇒ so the honest statement of requirement 8's reach: **the symlink test is owed at the boot gate, and
is dead code at introspect.** a builder who writes it into both has written one branch that cannot
fire (the same defect the owner-axis remedy branch had, per requirement 3).

### .what axis H costs the walk

**it does not multiply into A × B × C either.** a gate is observable only where a budget is both
declared and exceeded — `C = declared-over` — so the 2 other C values collapse H entirely:

| C value | does the gate matter? |
|---|---|
| `undeclared` | 🔴 **no.** requirement 4 — no counter runs, so no gate exists to differ |
| `declared-under` | 🔴 **no.** the gate passes at every H value, byte-identically |
| `declared-over` | ✅ **yes** — and that is the 6-cell cross above |

⇒ the primary walk stays **18**, and axis H is carried as its own `H × G` cross, for the same
reason `selection` and `ownership` are: **a latent axis gets a walk, never a full multiply.**

🟡 **and H subsumes G rather than sits beside it.** `G1`/`G2` are `H5`/`H6` — the same two cells
read before the gate axis existed. the `G` cross is kept because its `declared-under` and
`undeclared` rows (`G3`–`G6`) are real and H's collapse table above does not cover them.

## 🔴 .axis J — the SURFACE, and the premise axes G and H both held fixed

> 🔴 **ADDED 2026-09-24, at `5.1.execution` i020**, by `enroll-impl-behavior-intent` blocker.2.

| value | sense |
|---|---|
| `gate` | a command that **refuses** — `roles boot`, `repo introspect`. axes G and H walk this value, and only this value |
| 🔴 `report` | a command that **renders** — `roles cost --all`. it refuses naught (`S13`) |

🔴 **axes G and H each hold `surface = gate` fixed, and neither declares it.** every verdict they
reach is scoped to a moment the reader did not choose, in a render that carries one spec. the sweep
inverts both: the reader typed for it, and it carries every spec side by side.

⇒ that inversion is what makes `G4`'s verdict non-transferable. *"a foreign spec under its cap
renders byte-identically, so ownership is unobservable"* is true of a **single-spec** render and
false of a roster, where the tag is all that parts a row the reader can act on from one they cannot.

### crossed with G — the ownership axis, because that is what the surface reveals or hides

| J value | ownership observable? | what a reader can act on |
|---|---|---|
| `gate` | 🟡 **only via the rung** — a halt means ours, a warn means foreign | the one spec in front of them |
| 🔴 `report` | ✅ **on every row**, cap or no cap | 🔴 **the subset that is theirs** — and it must be legible, or the roster misleads |

⇒ cells `J1` (ours) and `J2` (foreign), both **demoed** at `case=10`. the two are graded as a pair
because the tag is legible only by contrast.

### .what axis J costs the walk

**it does not multiply into A × B × C, for a sharper reason than G or H.** `report` is not a state
the boot can be in at all — it is a **different command**. so a product of it with the boot's own
axes would name cells no invocation can reach.

| J value | what it grades |
|---|---|
| `gate` | the boot's refusal — already walked by A × B × C, G, and H |
| `report` | the sweep's render — a surface with its own reader, its own population, and no refusal |

⇒ the primary walk stays **18**, and axis J is carried as its own 2-cell `J × G` cross. 🟡 **it
crosses G alone** — the sweep renders every C value in one roster, so C does not partition it.

## .the secondary grid — the argument that is refused

axis B grades the *content* of a spec. it cannot grade the *argument* that named it, and that is
where the rejection invariants live. a second, smaller walk:

### axis D — the `--manifest` value (5)

| value | sense |
|---|---|
| `inside-repo` | a path within the repo |
| `outside-repo` | a path that escapes the repo (`../../etc/hosts`) |
| `absent-value` | the flag was the last token, no path follows |
| `with-role` | `--manifest` and `--role` both named |
| 🔴 `with-if-present` | `--manifest` and `--if-present` both named |

🟡 **`with-if-present` reads almost identically to the `with-role` row one line above it**, which is
exactly how a cell goes absent from the inventory: a demo asserts the refusal in a `then` and states
that the inventory carries it, and nobody re-reads the inventory. ⇒ 🔴 **a claim that a record
exists is not a record.**

### axis E — the `budget.tokens` value (5)

| value | sense |
|---|---|
| `positive-int` | `5_000` — the sane case |
| `zero` | `0` |
| `negative` | `-5` |
| `non-numeric` | `"5k"`, `true`, `null` |
| 🔴 `fractional` | `5000.5` — **added at `5.1.execution` i027** |

🔴 **`fractional` is the only value here that clears both of the other refusals' bars** — it is
numeric, and it is positive. so `.int()` alone refuses it, and a schema loosened to `.positive()`
would keep every row above green while this one reddens. ⚠️ **it is also the least typo-like of the
four**: `5000.5` reads as a deliberate figure, which makes it the value a later edit is likeliest
to round rather than refuse.

### 🔴 axis K — the section KEY, in a subject-mode spec (3)

> **added at `5.1.execution` i026**, under `rule.require.experience-catalog-evolution`.

| value | sense |
|---|---|
| `always` | the unconditional section |
| `subject.<coordinate>` | a scoped section |
| 🔴 `mistyped-prefix` | `subjct.repo` — a near-miss on the `subject.` prefix |

🔴 **the `subject.` prefix is the one place a spec's payload is routed by a STRING MATCH rather than
a schema key**, so a near-miss is accepted by the catchall and then discarded by the filter —
a whole briefs/skills section that boots for no one, in silence. that is a value on the section-key
axis, and neither D nor E reaches a section name.

🟡 it is the twin of cell `F` one axis over: **`F` swallows a MODIFIER** (`budget` parsed as a
subject section), **`K3` swallows a PAYLOAD**.

⇒ **D × E × K is not walked as a product** — they are independent refusals, each graded on its own,
so the product says only *"the first refusal fires"* in every cell but one.

**the basis, derived from the three axis tables above rather than copied:** axis D declares **5**
values, axis E declares **5**, axis K declares **3**, so the product is `5 × 5 × 3 = 75` cells.
exactly one is not a refusal — `inside-repo × positive-int × a valid section key`, the demoed
cross — so **74 of 75 carry the same degenerate verdict.**

⇒ the inventory verdicts each value once instead, as a rejection invariant: **4 on axis D + 4 on
axis E + 1 on axis K = 9.** ✅ reconciles against the inventory's own count.

🔴 **the arithmetic above recomputes from the three axis tables rather than quote a digit.** a copied
total goes stale the moment a value joins either axis, and it goes stale **silently** — the table
two lines up is correct, the sentence below it is not, and neither contradicts the other on its own
page (`rule.require.a-cue-is-not-a-claim`). stated as a basis, a new value visibly breaks the sum.

## .what the axes deliberately do NOT include

| omitted | why |
|---|---|
| **concurrency** | a boot is a read-only render with no shared mutable state, so first-vs-concurrent-vs-retried yields one identical experience |
| **the consumer halves** | what a *route* or a *behavior* does with a manifest is dispatched elsewhere (`rhachet-roles-bhrain#510`, `rhachet-roles-bhuild#392`). the wish forbids their construction here, so their experiences are out of this space |
| 🔴 **output shape, ON `roles boot`** | `roles boot` has **no output-shape flag** — `invokeRolesBoot.ts:12-71` declares `--repo`, `--role`, `--if-present`, `--subject` and no more. so `tree` vs `json` is not an axis with a closed value set; it is a capability that does not exist. ⇒ 🟡 **the trap is a hedged `then`** — a demo that asserts *"if a `--format json` path exists, it must …"* reads as coverage and is a cell with no axis behind it. the omission is a **verdict** here rather than a gap there |

> 🔴 **the output-shape row is SCOPED to `roles boot`, and it read as unscoped.** added at
> `5.3.verification` i003, after a reviewer found `roles cost --top`, `calc.tokens --against`, and
> `calc.tokens --format json` exercised by the verification tier with no cell behind them.
>
> ⚠️ **the row's claim is still true as written** — it is a fact about one command's flag set. what
> it cannot carry is the **report** surfaces this behavior also ships, because every axis in this
> file grades the **gate** (`S13`: *"`boot` gates; `cost` reports"*), and a gate axis has no
> position for a flag that only shapes a rendered readout.
>
> ⇒ those parameters are walked as **axis R** in `1.vision.experience.case=_.md`. all six values are
> `alter` — each has a fallback a caller reaches without help — so they are **itemized** rather than
> demoed, and two of them are rejection invariants.
>
> 🟡 **the lesson is narrower than "walk more axes":** a verdict that names its subject (*"`roles
> boot` has no output-shape flag"*) reads as a verdict about the **feature** once the feature grows
> a second command. the scope was correct at authorship and misleads by growth alone.

### 🔴 .the axis that was WRONGLY omitted — actor

⚠️ **the argument that omits an actor axis here is:** *"one actor reaches every cell … there is no
second role with different permissions, so an actor axis would be a column of one."*

🔴 **it conflates ACTOR with PERMISSION ROLE, and the method forbids the conflation.**
`howto.experience.enumerate` move 1 is *"list the actors and their goals"* — an actor is anyone
whose **lived encounter** differs, never anyone whose **permissions** differ. the canonical
`define.experience._.demo.surf-school` splits surfer from admin because they **come for different
goals**, not because they hold different grants.

⇒ and this vision carries its own counter-example: **`case=7` `[t5]` demos Ana the reviewer**, who
holds permissions identical to Bo the author and has a wholly different encounter — *she never set
out to check cost, and the diff tells her anyway.* a column of one cannot contain two rows.

### .the actor axis, as it actually stands

| actor | the goal they came for | their encounter |
|---|---|---|
| **the author** (Bo) | *"boot the docs my route needs, and know what it costs"* | the whole A × B × C product. every demo `case=1..7` |
| **the reviewer** (Ana) | *"review the behavior"* — she did **not** come for the cost | one boundary: a `budget.tokens` delta on a diff line. `case=7` `[t5]` |
| **the brain** | *"receive my briefs"* | 🔴 **two cells, and one is itemized rather than demoed** — see below |

### .the actor × feel grid — the method's premier tactic

🔴 **every cell carries one of the four verdicts — `demoed` · `itemized` · `forbidden` ·
`impossible` — in the same vocabulary the A × B × C grid uses.** a reasoned skip is not a fifth
verdict; a deliberate non-demo of a real experience **is** `itemized`, by definition.

| actor | happy | sharp |
|---|---|---|
| **author** | **demoed** — a payload renders, headroom is legible (`case=1`, `case=3`, `case=5`, `case=7` `[t0]`/`[t1]`) | **demoed** — over budget (`case=2`) · an unreachable manifest (`case=4`) · the recovery (`case=7` `[t3]`) — **criti**, and each proves it fails safe |
| **reviewer** | 🟡 **itemized** — two real happy encounters exist: a `boot.yml` **added** with a budget (she sees a cost bound declared), and a `say` entry **demoted** to `ref` (she sees a payload shrink). both rest on the identical property `[t5]` already demos — *a budget line on a diff is legible to a reader who did not come for it* — so a separate demo would restate it. **the skip is a SUBSUMPTION, never an absence** | **demoed** — the **raise** is legible without intent (`case=7` `[t5]`) — **alter**: the diff is the mitigation, and a missed raise is caught at the next boot's `used / budget` line |
| **brain** | **itemized** — the payload arrives and the session has its briefs. **this is `case=1`/`case=3` seen from the other side of one event**, so a second demo would restate one already-demoed event from the brain's side of it | 🔴 **itemized** — see the row below |

**6 actor cells = 3 demoed + 3 itemized + 0 forbidden + 0 impossible.** ✅ reconciles, cell by cell.

🔴 **the two happy skips carry a verdict LABEL, never a prose reason alone.** *"skip / subsumption"*
and `itemized` are the same decision, and only one of them lets a reviewer reconcile this grid as a
walked matrix the way the A × B × C grid reconciles. ⇒ **right substance in the wrong vocabulary is
not checkable**, and the vocabulary is what a reviewer grades.

### 🔴 .the brain's sharp cell — itemized, with its scope boundary stated aloud

⚠️ *"the halt has one audience"* is a false premise. **it has two**, because requirement 2 says
**no payload is emitted at all** — so one event splits:

| who | what they get | verdict |
|---|---|---|
| the **human** | a loud halt: budget, payload, overage, and 🔴 **four strategies — catalogization · condensation · reference · elimination**, which name **that** some resources must go and never **which** (`F13`) | **demoed** — `case=2`, and it fails safe |
| the **brain** | 🔴 **no briefs** | **itemized** — the seam is in scope, the handler is not |

⇒ **what is in scope here:** that `roles boot` makes its refusal legible to a *machine* caller —
`ConstraintError`, exit **2**, the halt on **stderr**, and naught on stdout. that is the seam this
wish owns, and `case=2` asserts it.

⇒ **what is NOT in scope:** what a `SessionStart` hook *does* with exit 2. a hook that swallows it
starts a session whose briefs are silently absent — which is the exact shape of the incident that
motivated this wish, and it is `rhachet-roles-bhrain#510` / `rhachet-roles-bhuild#392`, both
dispatched. the wish forbids their construction here.

🟡 **so the obligation this wish carries is narrow and real:** the exit code and the stream must
give a machine caller enough to fail loud on
(`define.invariant.empty-render-names-its-cause` — an empty answer must name its cause). the
consumer's duty to *act* on it is theirs.

### .what the corrected axis does NOT change

this behavior still has **no authorization dimension** — that part of the old argument holds, and
it is why every sharp cell is a *legibility* problem rather than a *permission* one. the defect was
to reason from that true fact to "therefore one actor".
