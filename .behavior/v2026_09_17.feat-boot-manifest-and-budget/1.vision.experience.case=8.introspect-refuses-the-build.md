# case=8 — `repo introspect` refuses the build

**cell `H1`** — gate `introspect` × ownership `ours`. **sharp × critipath.**

🔴 **the first of requirement 9's TWO gates** — narrowed from three by `S14`, which struck the
`onStop` hook. the budget hooks into the operation every role package **already runs** in its build
flow, as a fifth `assertRegistry*` guard.

## .the narrative

Ann maintains `rhachet-roles-ehmpathy`. the mechanic role is dense — it is the most-booted role in
the org, and it declares `budget.tokens: 60_000` precisely because of that.

she adds two briefs to `say`. good briefs. she runs the build.

```
$ npm run build

> build:clean
> build:compile:tsc
> build:complete:dist
> build:complete:repo
  npx rhachet repo introspect

🔭 load getRoleRegistry from rhachet-roles-ehmpathy...

🧢 repo introspect — src/domain.roles/mechanic/boot.yml
   ├─ ✋ over budget
   │  ├─ budget   = 60,000 tokens   (declared in boot.yml)
   │  ├─ payload  = 64,310 tokens   (full emitted payload, o200k_base)
   │  └─ over by  =  4,310 tokens   (107% of budget)
   │
   ├─ some resources must go — you choose which
   │
   └─ fix — four strategies, cheapest first
      ├─ catalogize    replace a set of briefs with one catalog that indexes them
      ├─ condense      author an x.md.min beside x.md
      ├─ reference     move a say entry to ref, in boot.yml
      └─ eliminate     delete what does not earn its boot
                       ⇒ or raise budget.tokens deliberately — it lands on the diff

npm ERR! code 2
```

Ann condenses one of the two — authors an `.md.min` beside it — and the build passes. **the cap was
enforced before a single consumer ever saw the payload.**

### 🔴 the aha — the halt lands where the author can actually act

this is the gate that makes the vision's own aha-line literally true. *"the trim happened at
authorship, in the author's own hands, in under a minute"* — here that is a plain description:

| | |
|---|---|
| the spec the halt names | `src/domain.roles/mechanic/boot.yml` — 🔴 **git-tracked, in Ann's own tree** |
| who is present | Ann. it is her `npm run build` |
| what a halt costs | a build retry. no session blocked, no consumer affected |
| when it fires | **once**, before `prepublish` — so the over-budget payload **cannot ship at all** |

⇒ compare gate 3, where the same halt would land on a consumer, on a file that is a symlink into a
version-pinned pnpm store, with remedies that each name a write they cannot make. **the halt is
identical; only the writability of the named file differs — and that difference is the whole
argument.**

## .the bdd sketch

```
given [case8] a role package whose boot payload exceeds its declared budget
  # src/domain.roles/mechanic/boot.yml declares budget.tokens: 60_000
  # the spec is a GIT-TRACKED REGULAR FILE — ours by construction (H2 is impossible)
  # the FULL EMITTED payload measures 64_310 real tokens (requirement 7)

  when [t0] the author runs the build
    $ npm run build      # → build:complete:repo → npx rhachet repo introspect

    then it exits 2                                  # ConstraintError
      # the same error class as its four peer guards — no new failure shape
    then rhachet.repo.yml is NOT written
      # the manifest is the build artifact; an over-budget role must not
      #   produce one, or the cap ships unenforced
    then the halt names the ROLE and its spec path
      # a package may declare many roles; the author must know which
    then the halt names the arithmetic
      - budget, payload, and the overage, each as a number
    then 🔴 it names NO individual resource
      # F13 — that some must go, never which
    then it names the four strategies, IN ORDER
      - catalogize · condense · reference · eliminate
    then 🔴 NO symlink check is performed
      # cell H2 is IMPOSSIBLE: git cannot track a symlink into node_modules,
      #   and introspect reads only git-tracked source. so the rung here is
      #   ALWAYS halt, and an lstat at this gate is a branch that cannot fire
    then the guard ran AFTER its four peers
      # assertRegistrySkillsExecutable, …BootHooksDeclared, …HooksNoNpx,
      #   …HasNoOrphanBriefs — a budget breach is the least urgent of the five,
      #   so it must not mask a broken skill or an orphan brief

  when [t1] the author condenses one brief to .md.min, then re-builds
    then it exits 0
    then rhachet.repo.yml is written
    then no boot.yml change was needed
      # the renderer already prefers .md.min — strategy 2 costs no spec edit

  when [t2] a role in the SAME package declares no budget
    then that role is not gated                      # requirement 4, per-role
    then the package still builds if every budgeted role passes
```

## 🔴 .why the guard runs FIFTH, and why that is not arbitrary

the four extant guards at `invokeRepoIntrospect.ts:82-92` are ordered by severity, and a budget
breach is the mildest of the five:

| # | guard | what it catches | severity |
|---|---|---|---|
| 1 | `assertRegistrySkillsExecutable` | a skill that cannot run | 🔴 the package is broken |
| 2 | `assertRegistryBootHooksDeclared` | bootable content with no hook | 🔴 the content never loads |
| 3 | `assertRegistryHooksNoNpx` | an `npx` hook — a latency footgun | a real perf defect |
| 4 | `assertRegistryHasNoOrphanBriefs` | a `.md.min` with no source | a stale brief ships |
| 🔴 **5** | **`assertRegistryWithinBudget`** | a payload over its own declared cap | **the content works; it costs too much** |

⇒ **a budget breach must not mask a broken skill.** if the budget guard ran first, an author with
both defects would fix the cap, re-build, and only then learn their skill is not executable — two
build cycles where one would do.

🟡 and the position is cheap to get right precisely because the family exists. **the order is the
only design decision this guard carries**; the error class, the invocation, and the `.why`
convention it all inherits.

## .why sharp × critipath

| axis | verdict | why |
|---|---|---|
| **feel** | **sharp** | the build fails. exit 2, `npm ERR!` |
| **care** | 🔴 **criti** | **freq: every publish of every role package that adopts a budget.** cost if absent: an over-budget payload **ships**, and every consumer pays it on every session — with no writable file to fix it (the `F10` hazard, at full scale) |

⇒ this is the gate that makes requirement 8's warn rung tolerable. **a consumer-side warn is only
acceptable because gate 1 stopped the payload before it ever reached them.** without gate 1, a warn
at gate 3 would be the whole enforcement, and it would enforce naught.
