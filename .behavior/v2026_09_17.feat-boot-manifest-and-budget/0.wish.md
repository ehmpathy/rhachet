# wish: a boot renders from a declared manifest, and is refused when it exceeds a declared budget

## .the outcome

**`rhachet roles boot` takes `--manifest <path>`, and every `boot.yml` may declare
`budget.tokens`.** a boot whose resident payload exceeds its budget **halts**, names the overage,
and names the remedies. a boot within budget renders exactly as it does today.

```yaml
budget:
  tokens: 5_000
always:
  briefs:
    say:            # resident in context, every session
      - briefs/core.md
    ref:            # path-only, fetched on demand
      - briefs/reference.md
```

## 🔴 .why the two land TOGETHER, and not as two PRs

they are one mechanism — the boot renderer — and each is defective alone:

| alone | what ships |
|---|---|
| `--manifest` with no budget | 🔴 a first-class path to an **uncapped** custom payload. that is the extant defect with a nicer syntax |
| `budget.tokens` with no manifest | a cap that reaches role defaults alone, while the payload that measured ~46% has no path at all |

⇒ `ehmpathy/rhachet#537`'s own acceptance already says it: *"over-budget on a custom manifest halts
exactly like a role boot (companion task)."* **a manifest that lands first is a hole that must then
be closed; a budget that lands first caps the wrong set.**

## 🔴 .why — a bespoke hook is the only path, and a hook has no contract to hold it

**measured: a bound-behavior boot consumed ~46% of a session's context at startup, before a single
turn.** it was a hand-written `SessionStart` hook that injected a whole doc set — wish, vision,
criteria, blueprint yields. it was removed by hand, so the capability it served is **absent rather
than repaired**.

⇒ the defect is not that hook's payload. **it is that a bespoke hook was the only way to get one.**
so every route-scoped boot re-derives the same mechanism, each one unbudgeted by construction, and
each one grows without a cap — because a `say` set grows in silence and nobody re-reads a hook.

🔴 **the cheapest moment to cap a payload is the moment somebody authors one.** a declared budget
puts the trim in front of the author, at review time, as a reviewable choice. a hook offers no such
moment.

## .what must be true of the answer

| # | requirement | why |
|---|---|---|
| 1 | `--manifest <path>` renders any `boot.yml`, at **schema parity** with a role default | `always.briefs.say`, `always.briefs.ref`, and `budget` all honored. a partial parity is a second dialect |
| 2 | 🔴 over-budget is a **loud hard stop**, never a warn | a silent pass is the extant state. the author must make the trim, or the raise, a conscious act |
| 3 | the halt **names the remedies** | move `say` → `ref` · point `say` at a `.min` variant · raise the declared budget deliberately. an error that states a symptom alone is a blocker (`rule.require.errors-name-the-fix`) |
| 4 | a boot.yml with **no** `budget` is never refused, and its `<stats>` calls it out: `tokens ≈ N / unlimited budget` | the cap is opt-in per manifest. a default cap would break every extant role boot at once — but a budgetless spec is visible as one (`S19`, which reverses `S11`) |
| 5 | an absent or malformed manifest path **fails loud** — the path, and what was expected | |
| 6 | both stdouts are **snapshotted**: the clean pass and the over-budget halt | the halt is a human surface, and a surface with no snapshot drifts unreviewed |
| 🔴 **7** | the counter is **accurate** — real tokens, over the **full emitted payload** | added 2026-09-18. the vision measured the extant counter at **3.29x understated**; see the amendment |
| 🔴 **8** | the gate applies to specs **this repo can write**; a foreign spec is not gated | added 2026-09-18. 13 of 15 extant specs are symlinks into a version-pinned store, so every halt remedy would name an unwritable file |

## 🔴 .amendment — 2026-09-18, mid-vision

**added by the wisher at the `1.vision` approval gate**, after the vision's measurements came back.
recorded here because the requirement set lives in this file. the verbatim exchanges are the route's
seeds **S3** and **S4**; below is the claim each settles.

### requirement 7 — the counter is accurate

the open question below asks *"what counts a token"* and offers three options. **the wisher refused
the tradeoff rather than pick a side of it: the counter must be accurate.**

⇒ so `chars ÷ 4`, and any corrected divisor over it, are both out. the measurement that forced it:

| quantity | value |
|---|---|
| what the boot **reports** | `chars = 16,427` → `tokens ≈ 4,107` |
| what the boot **emits** | 44,666 chars |
| **real tokens** (`o200k_base`) | 🔴 **13,494** |
| understated by | 🔴 **3.29x** |

🔴 **and there is no tokenizer to blame.** `tokens ≈ chars / 4` is a heuristic, and the error is two
independent defects that compound — both of them downward:

| # | the defect | factor |
|---|---|---|
| 1 | a **scope** error — the heuristic is applied to 16,427 of 44,666 emitted chars. every `ref` line, the whole `<also>` block, and all XML chrome are never summed | **2.72x** |
| 2 | the **divisor** — this payload's true density is **3.31** chars/token, not 4.0 | **1.21x** |

`2.72 × 1.21 = 3.29` ✅.

🟡 **the perf objection the open question raises is answered by requirement 4, not by a tradeoff.**
an unbudgeted boot needs no counter, so the tokenizer loads **lazily on a declared `budget`** — the
extant `under 250ms` assertion covers unbudgeted boots and stays untouched, and a budgeted boot is a
new path that owes a new assertion.

### requirement 8 — our own specs only

`F10` found that a halt on a third-party spec names, in all three remedies, a file the halted party
cannot write. **the wisher narrowed the gate rather than widen the remedies.**

⇒ requirement 2 therefore carries its **first exception**: a foreign spec's `budget` does not halt a
consumer. *"is this spec ours?"* becomes a contract question the mechanism must answer — the
candidate is a realpath escape check, the same boundary `cpsafe`/`rmsafe`/`teesafe` already hold.

🟡 **this also refuses a capability:** the owner-aware alternative needed an override flag, which is
adjacent to the two consumer halves this wish forbids.

## 🔴 .the open question we could not settle from outside — WHAT COUNTS A TOKEN

🔴 **settled 2026-09-18 by requirement 7 above — read this section for its argument, never for its
verdict.** it is kept because the way it poses the tradeoff is what the measurement refuted.

requirement 2 makes a number **load-bearing**: it now refuses a boot. so the counter's accuracy
stops to be cosmetic.

⚠️ **the extant boot stat is a flat `chars ÷ 4`**, at a flat `$3/mil`:

```
quant
  ├── files  = 255
  ├── chars  = 227271
  └── tokens ≈ 56818 ($0.17 at $3/mil)
```

227271 ÷ 56818 = **4.0000**. that divisor has never been checked against a real tokenizer, and our
briefs are unusually dense in `🔴 ⚠️ ├─ └─ │` — glyphs that tokenize far worse than 4 chars each.

⇒ **so an estimate that is merely indicative today becomes a gate tomorrow.** settle it and say
which you chose:

| the counter | the tradeoff |
|---|---|
| keep `chars ÷ 4` | zero deps, and it refuses a boot on a number nobody has verified |
| a real tokenizer | accurate per model, and it adds a dependency to the boot path |
| `chars ÷ 4` **plus a measured correction** for our actual corpus | cheap, and the correction needs a one-time measurement stated in the yield |

**whichever you take, state the error bar.** a budget of `5_000` against a counter that is 30% low
is a budget of 6,500 that reads as 5,000.

## .what is NOT wanted

- 🔴 **a warn instead of a halt.** a warn is what the extant hook already effectively does — the
  cost is visible to nobody and the payload grows anyway
- **a default budget applied to boots that declare none.** requirement 4 is the bound
- **a second renderer** for the manifest path. it consumes the extant render, or the two drift and
  the budget holds only one of them
- **the CONSUMER halves.** what a *route* does with a manifest is `rhachet-roles-bhrain#510`; what a
  *behavior* chooses to boot is `rhachet-roles-bhuild#392`. both are dispatched, both wait on this.
  **do not build either here**

## ⚠️ .what this budget actually caps — say it plainly in the yield

it caps **context occupancy** — the ~46% figure — reliably, because a cached token occupies context
exactly as an uncached one does.

🟡 **it caps CASH only while the prompt cache misses.** a boot payload is the single most
cache-friendly object in the system: byte-identical, at token 0, on every session. so once a
provider's prompt cache hits, a boot's token count **overstates its dollars**, and it overstates it
worst for the payload this budget governs.

⇒ that is not a reason to change the unit — tokens are the right unit for a context cap. it is a
reason to **name the unit honestly** where the budget is documented, so a later reader does not read
`budget.tokens` as a dollar cap it was never built to be.

a gate the author meets at authorship.
