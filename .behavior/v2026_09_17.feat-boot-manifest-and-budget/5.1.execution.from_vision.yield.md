## 1. ✅ `budget` in the boot schema, and the catchall swallow

**the blocker the vision found, confirmed on both halves and closed.**

| what | where |
|---|---|
| `schemaBootBudget` — `z.number().int().positive()` | `src/domain.objects/RoleBootSpec.ts` |
| `BootBudget` — the resolved shape; `null` means none declared | same |
| `budget` declared in BOTH mode schemas | same |
| `budget` excluded from mode detection, and refused with no payload to cap | `computeBootMode.ts` |
| `assertNoNestedBudget` — the one forbidden cell | `parseRoleBootYaml.ts` |
| `resolveBootBudget` | same |

### 🔴 why `z.number().int().positive()` is the whole malformed-input story

one refinement refuses all four rejection invariants on axis E at once: `0` (not positive), `-1`
(not positive), `5000.5` (not int), `"5000"` (not a number). no hand-rolled guard, no four branches.

### 🔴 the catchall fix is one line, and the mechanism is the reason

```ts
export const schemaRoleBootSpecSubjected = z
  .object({
    always: schemaSubjectSection.optional(),
    budget: schemaBootBudget.optional(),   // ← this line
  })
  .catchall(schemaSubjectSection);
```

**a zod catchall applies only to keys the object shape does not name.** so an unnamed `budget` was
parsed AS a subject section — its `tokens` key dropped by the non-strict object, the section
validated as empty, then discarded by the `subject.` prefix filter. ⇒ **to name it in the shape is
the entire fix**, and the `.note` in the file records the mechanism so nobody re-derives it.

### the clamp, proven to bite

per `rule.require.clamp-edge-cases` — *"a clamp you have not seen fail is a guess."*

| step | result |
|---|---|
| land the fix | **36 green** |
| revert ONLY the `budget:` line from the subject schema | 🔴 **1 red — `[case9][t0]` "the budget is resolved, never swallowed by the catchall"**, and only that one |
| restore | **36 green** |

⇒ the clamp exercises the defect rather than merely sits beside it.

### 🟡 `budget` is REQUIRED on the resolved interface, never optional

`RoleBootSpecSimplified.budget: BootBudget | null` — not `budget?:`. per
`rule.forbid.undefined-attributes`, an optional field is invisible at compile time, so an author
must consciously supply `null`. the cost was 21 test constructors, swept with `sedreplace`.

### ⚠️ what `budget.tokens` caps — context, never cash

the wish asks the yield to say it plainly, so here it is:

- **it caps context occupancy, always.** a cached token fills the context window exactly as an
  uncached one does
- **it caps cash only while the prompt cache misses.** a boot payload is byte-identical at token 0 on
  every session, so it is the most cache-friendly object in the system. once the cache hits, the
  token count **overstates** the dollars, and it overstates them most for the payload this budget
  governs

⇒ tokens stay the unit, because a context cap is what the budget is for. the same statement lives
where the budget is declared, in the `schemaBootBudget` docblock (`RoleBootSpec.ts:33-36`), so a
reader of the schema never takes `budget.tokens` for a dollar cap.

## 2. ✅ the accurate token counter

**requirement 7: real tokens, over the full emitted payload.** the extant heuristic understated this
repo's own boot by **3.29x** via two defects that compound — scope 2.72x × divisor 1.21x. both
repaired.

### the divisor — a shared, memoized encoder

`src/domain.operations/brainCost/getOneBrainTokenEncoder.ts`

🔴 **this is a fix at source, not a new counter.** `calcBrainTokens.ts:15` constructed the encoder
**inside the function body**, and construction is ~1,800ms and input-invariant. so:

| caller | before | after |
|---|---|---|
| `calcBrainOutputCost` | calls `calcBrainTokens` **4×** in one function ⇒ ~7.2s of construction | **one** construction, process-wide |
| the budget gate | would have paid ~1.8s per count | shares the same encoder |

the public sdk contract is unchanged — verified by `calcBrainTokens.acceptance.test.ts`, **3 green**
against `dist`.

### the scope — the payload assembled to a buffer

`bootRoleResources.ts` no longer streams the body through ~40 `console.log` calls as it builds it.
it assembles `linesBody`, then emits `[...stats, ...body, ...stats]` in one call.

⇒ two properties fall out, and the wish needs both:

1. **the full payload is countable before a byte is emitted** — which is requirement 2's *"spend
   naught"*, and the 2.72x scope fix: every ref line, the whole `<also>` block, and all xml chrome
   are now in the measured string
2. **byte-identity is preserved** — requirement 4

### 🔴 the `process.stdout.write` misstep, and what it taught

I first flushed with `process.stdout.write(payload + '\n')`. **10 integration tests went red with
`Received string: ""`** — the harness captures `console.log`, so the write bypassed every assertion.

⇒ `console.log(payload)` appends exactly one `\n` and does no format substitution on a single arg,
so it is **byte-identical on the wire** and keeps the harness intact. **the write bought naught and
broke a contract 10 tests depend on.** the `.note` in the file now says so, so the next author does
not re-reach for it.

🟡 **and the 10 failures were a clamp at work by accident** — they proved the tests observe the emit
mechanism. they are partial-match assertions though, so the **byte-identity oracle is the pinned
acceptance snapshot**, which passed: **63 passed, 0 failed**, both perf suites (`under 250ms`)
among them.

### the counter, and why it is lazy

`src/domain.operations/boot/calcBootPayloadTokens.ts`

🔴 **the laziness carries weight rather than ceremony**, and the measurement says why:

| fact | consequence |
|---|---|
| `roles boot` runs from a **bun** binary whose perf suites assert `under 250ms` | an eager import puts ~2MB of rank tables on every boot's critical path |
| js-tiktoken is **NOT** otherwise in that binary's eval graph | ⇒ the import would be **new** cost, not shared cost |
| an unbudgeted boot never calls the counter | ⇒ requirement 4's boots pay naught |

🔴 **`roles cost` uses `Math.ceil(chars / 4)` too** (`getRoleFileCosts.ts:81`) — which is how I know
the tokenizer is absent from that binary. **see the find below: that is a live seam.**

### 🔴 the clamp found a clamp with no teeth

the revert step did its job twice over:

| the assertion | under the reverted heuristic |
|---|---|
| tokens is a real count, not a char-derived estimate | 🔴 red ✅ |
| the estimate UNDERCOUNTS this payload | 🔴 red ✅ |
| the count is the real bpe count, pinned | 🔴 red ✅ |
| ~~the true density is below **4.0**~~ | 🟡 **GREEN — a false clamp** |

**`chars / ceil(chars / 4)` is ~3.97** — just under 4.0, an artifact of the ceil. so a `< 4.0`
assertion passes under the very heuristic it means to refute.

⇒ tightened to `< 3.8`, and **all four now bite**. the fix carries the measurement in a comment,
since *"a clamp that passes with the defect present proves only that it does not exercise the
defect."*

🟡 **I would not have found it by a read of the test.** it reads as a correct claim about density —
and it is. it is just not a claim that discriminates.

## 4 + 5. ✅ the budget gate, its halt render, and the computed rung

three operations, each with one job:

| operation | what it decides |
|---|---|
| `isBootSpecForeign` | ownership — one `lstat`, bounded to `.agent/repo=$slug/role=$name/` |
| `asBootBudgetReadout` | the human surface — the `🧢`/`✋` tree, and the ladder of loss |
| `assertBootWithinBudget` | the gate — count, render, warn or throw |

### 🔴 the halt renders in TWO parts, and the reason is the error frame

`withCliOutputErrors` already renders a `HelpfulError` as `${glyph} ${class}: ${message}` plus JSON
metadata. so two rejected alternatives:

| rejected | why |
|---|---|
| the tree AS the error `message` | the frame prefixes `✋ ConstraintError:` onto the first line — a glyph collision inside the author's own render |
| the tree in the error **metadata** | JSON-escaped, so the tree is unreadable exactly where it teaches |

⇒ **taken: emit the tree via `console.error`, THEN throw a terse `ConstraintError`.** the tree
teaches top-down; the frame supplies the greppable class and exit code 2.

### the rung is computed, and the short-circuit is requirement 4

```ts
rung: budget && isBootSpecForeign({ pathToSpec: source.pathToSpec, cwd }) ? 'warn' : 'halt',
```

the `budget &&` keeps an unbudgeted boot free of the syscall — requirement 4 is the blast-radius
shield **and** the perf shield, and this is the second place that pays off.

### 🔴 the clamp found a real defect in the ownership check

`lstatSync` **throws** on an absent path, and an absent `boot.yml` is a *legitimate* role fallback
(say-all). so the first wiring took 7 role-boot tests red with `ENOENT`.

```ts
const stat = lstatSync(input.pathToSpec, { throwIfNoEntry: false });
if (!stat) return false;   // an absent spec is not foreign
```

🟡 **`throwIfNoEntry: false` rather than an `existsSync` guard** — one syscall instead of two, and no
race between them.

### the clamp, proven to bite

| step | result |
|---|---|
| land the gate | **8 green** in the budget suite, **33 green** across all three boot suites |
| revert ONLY the gate call | 🔴 **6 red, 2 green** — and the 2 that stay green are exactly the two pass-through cases, which is the correct partition |
| restore | **33 green** |

then requirement 4's oracle: `npm run build`, acceptance `path://roles.boot` → **63 passed, 0
failed**, both perf suites (`under 250ms`) among them. ⇒ the lazy load holds: an unbudgeted boot
never loads the tokenizer.

### what the readout asserts, and what it FORBIDS

the four strategies are asserted **as an order**, not a set — the ladder of loss is cheapest-first
by cost **to the reader**, and a list sorted any other way inverts the pit of success.

🔴 subject mode earns a fifth, `narrow`, and it **HEADS** the ladder rather than joins its end. it
is the one remedy that touches no document at all — the author asks for less of a spec that stays
entirely intact — so by the ladder's own sort key it is the cheapest rung there is. the vision
settled it explicitly (`1.vision.experience.case=6` `[t2]`: *"the halt lists FIVE strategies, with
`narrow` first"*), and `asBootBudgetReadout.ts` prepends it.

🔴 **and one assertion is negative on purpose:**

```ts
expect(readout).not.toContain('0.wish.md');
expect(readout).not.toContain('1.vision.yield.md');
expect(readout).toContain('you choose which');
```

`F13` was struck by the wisher — the gate sees a resource's **cost** and not its **value**. the
negative assertion is what stops a future builder from re-adding the breakdown as a kindness.

## 7. ✅ gate 1 — the refusal that fires where the author can WRITE the file

**requirement 9's first gate, and the one that makes the vision's aha-line literally true.**

### 🔴 the extraction is the whole point, and `F17` is why

`bootRoleResources` both **assembled** and **emitted**. gate 1 must assemble WITHOUT emitting, so it
needed one of three things: a mode flag on the renderer, a second assembly path, or an extraction.

- a **flag** — a `'emit' | 'measure'` parameter is a flag-on-a-function, and the plan-vs-apply
  vocabulary it reaches for is governed here by a rule of its own
- a **second path** — 🔴 **this is exactly the seam `F17` had just recorded for `roles cost`**: two
  code paths that compute one quantity, which then disagree. to build it deliberately, one task
  after writing down why it is a defect, would be the `F13` failure in a new coat
- ⇒ **extraction.** one assembly, three measurers, one emitter

⇒ so `genOneBootPayload` returns the **body** separate from the stats block, and the stats block as a
closure the caller invokes with the gate's own count. that split is `F15` made structural: the thing
that is measured and the thing that reports the measurement cannot be the same string.

### 🔴 the label is part of the payload, so gate 1 computes the CONSUMER's label

a resource line reads `<brief.say path="…">`, and that path is bytes the tokenizer counts. at gate 3
the prefix is `.agent/repo=$slugRepo/role=$slugRole/`. so gate 1 derives **the same prefix** — from
`registry.slug` + `role.slug`, which it holds — rather than the package-local path it is standing in.

⇒ a gate that labelled by its own vantage would measure a payload no boot ever renders. the two
slugs are load-bearing, and the clamp asserts them.

### 🔴 the layout refusal — a second mechanism, argued rather than assumed

the gate derives the whole source from `dirname(boot.uri)`, which holds because role packages are
**flat** (verified against `getMechanicRole.ts`: `readme`, `boot`, `briefs.dirs`, `skills.dirs` all
under one `${__dirname}`). a role whose briefs sat elsewhere would be scanned **short** here and
rendered in full by a consumer.

⇒ the choice was to **generalize the scan** or to **refuse the layout**. refusal was taken:

| | generalize | 🔴 refuse |
|---|---|---|
| what it costs | `dirBriefs`/`dirSkills` become arrays, through the whole renderer | one predicate |
| what it risks | a wider change to the one path requirement 4 pins byte-for-byte | a loud error on a set that is **empty today** |

🟡 it fires **only for a role that declares a budget**, and `budget` is a key this behavior
introduces — so the set it can break today is empty by construction. a split-layout role keeps
working exactly as it does now, right up until the day it opts into a cap.

## 8. 🔴 the repo-wide sweep — a REPORT a human types, never a gate that fires

> 🔴 **this section was `gate 2 — the budget check on hook.onStop`. the gate is CUT (`S14`), and
> the sweep beneath it SURVIVES as a command.** *a human may sweep; a hook may not.*

| what | where |
|---|---|
| `assertRepoBootSpecsWithinBudget` — the repo sweep | `src/domain.operations/boot/assertRepoBootSpecsWithinBudget.ts` |
| `getOneBootSourceForSpecPath` — a source from any spec path | `src/domain.operations/boot/getOneBootSourceForSpecPath.ts` |
| `roles cost --all` — the cli surface a **human** types | `src/contract/cli/invokeRolesCost.ts` |
| the fast-path route — `boot\|cost` | `bin/run` |

### 🔴 why the sweep is a report and the gate is not

`repo introspect` refuses to run outside a `rhachet-roles-*` package
(`invokeRepoIntrospect.ts:55-59`, a hard `ConstraintError`), so it is **structurally blind** to a
repo-local role and to a route-scoped `--manifest` — and the second of those is the ~46% payload
this whole wish exists to fix.

**that blindness is a measurement and it is correct.** what does not follow from it is a gate:

| the instrument | who invokes it | what it does about an over-budget spec |
|---|---|---|
| a **gate** at `hook.onStop` | 🔴 **nobody.** it fires at every session's close | refuses, on a question that session never posed |
| 🔴 **`roles cost --all`** | a human, deliberately | **reports** — a row per spec, `⚠️` on each over |

⇒ **`boot` gates; `cost` reports**, and a report that refuses is not a report (`S13`). the roster is
not noise once a human typed the command — it is the answer to the question they asked (`S14`, `S16`).

### 🔴 the `dot:` defect — the sweep found only the population it was NOT for

every spec the sweep exists for sits under a **dot dir** — `.agent/`, `.behavior/`, `.route/` — and
fast-glob skips those by default. so the first sweep found a role package's
`src/domain.roles/*/boot.yml` and no other.

```ts
dot: true,
followSymbolicLinks: true,   // a linked spec IS a symlink (13 of 15 here)
```

🟡 **`followSymbolicLinks` and requirement 8 do not fight**, and the reason is a property of
fast-glob worth a note: it yields the path it **matched**, never the realpath. so the sweep discovers
a foreign spec (a spec it cannot see cannot even mark) while the downstream `lstat` still sees the
link rather than its target.

⇒ measured live: **2 passed / 7 failed** without `dot: true`, **9 passed** with it.

### 🔴 what the struck gate cost, and what it taught

it was built end to end — a framework-authored `onStop` hook, its own sync kernel, five clamps — and
deleted five days later. **two of the round's sharpest lessons came out of code that no longer
exists**, and both outlive it:

| the lesson | where it now lives |
|---|---|
| a `serialize()` staleness key made the sync **delete its own hook** on the second run; the extant `computeHookDiff` was immune by construction | `F19` — `rule.always.reuse-pavement-before-improvise` |
| an idempotency assertion passed **vacuously** — two EMPTY reads compare equal — until a positive control proved the first write happened at all | `rule.forbid.failhide`, in its quietest form |
