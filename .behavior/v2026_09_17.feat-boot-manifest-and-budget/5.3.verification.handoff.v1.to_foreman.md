## ✅ .item 1 — `age` was absent. CLOSED.

the human installed it. the two suites that had failed on a dependency assertion:

```
$ rhx git.repo.test --what integration \
    --scope 'path://sshPrikeyToAgeIdentity' --scope 'path://keyrack/recipient' --mode apply

```

### 🔴 what the close revealed — a suite guard hides its own blast radius

**21 passed, where the failed run reported 6** (`5 passed, 1 failed`). the assertion fires at
**suite** scope, so **16 tests were never reached**. they did not fail. they did not run.

⇒ *"1 failed"* understated the damage by **16**, and no read of the failure report would have
revealed it. only the count after the repair does.

### what was tried, in order

| # | approach | outcome |
|---|---|---|
| 1 | `sudo apt-get install -y age` — **cicd's exact command**, `.test.yml:209` | 🔴 `a terminal is required to read the password`. the agent shell has no tty |
| 2 | the **npm** package named `age` | 🔴 **a name collision.** an unrelated *"Abstract Gameification Engine"* (`rodw/age`) with **no `bin` at all** |
| 3 | **entool it** — `.agent/repo=.this/role=any/skills/install.age.sh` | ✅ built. plan-first, idempotent, byte-matched to `.test.yml:209`, **18 acceptance tests + 4 snapshots** |
| 4 | hand the one command up | ✅ **taken**, and the human ran it |

🟡 **the skill is kept, not discarded.** it makes the next absent-`age` host a one-command repair
rather than a re-diagnosis, and it is the artifact that survives this stone.

### 🔴 a defect in my own repair, found by the human

the skill's first refusal probed with `sudo -n true` and refused the human **in their own terminal**.
`-n` asks *"can sudo run with NO password?"* — never *"can sudo GET one?"*. the guard is now a
**disjunction** (passwordless **or** a tty exists).

⇒ recorded as the **third** incident of `rule.forbid.mechanism-inferred-from-outcome`, under its new
**probe variant**: *a probe warrants naught wider than the question it asks.*

## 🟡 .item 2 — `clone say` exits 2 for a dispatch that landed. DOWNGRADED.

```
$ rhx git.repo.test --what acceptance --against local --env test \
    --scope 'path://clone.acceptance' --mode apply
   ├─ stats
   │  ├─ suites: 1 files
   │  ├─ tests: 120 passed, 0 failed, 0 skipped
   │  └─ time: 88s
EXIT=0
```

⚠️ **this is NOT a repair, and it must not be read as one.** the dream diagnoses a **settle-window
race** — load-dependent by construction. so a green on a single suite, alone, on an unloaded host is
**exactly what a live race produces**. it is consistent with the defect's absence and with its
presence, and discriminates neither.

### why the repair is not mine to make

the SAFE/CLEAN test grades **both halves against the fix**, never against scope:

| question | answer |
|---|---|
| is it **SAFE**? | 🔴 **no.** the repair changes *when `clone say` may exit* on a socket dispatch path this diff cannot exercise and its tests cannot cover |
| is it **CLEAN**? | no. it ripples into the documented consumer contract (*"exit 2 ⇒ retry"*) and every caller that branches on 2 |

⇒ **unsafe is a harder stop than unclean.** and the cheap alternative — relax the assertion — is
forbidden outright (`rule.forbid.failhide`). **the test was left intact.**

### severity — corrected, and unchanged by the isolation green

an early draft called the trigger *"bounded to co-scheduled runs."* **withdrawn** — it rested on an
inference the dream's own refutation table calls *"consistent with a flake and proves none."*

🔴 it reads **trigger unknown, possibly live**, and **the green above neither raises nor lowers that
grade** — which is precisely why it is reported as a downgrade of the *ask* rather than of the
*defect*.

### the act that closes it

**a wisher rules on `F45`** — direct the repair now, or accept the deferral. stated fairly at 96%.

### 🔴 the mechanism — the SECOND incident of one rule in this stone

`rule.forbid.mechanism-inferred-from-outcome`. the first was `sudo -n true` read as *"sudo is

⇒ recorded as the rule's **fourth** incident, with a corollary: *a rendered status is never evidence
