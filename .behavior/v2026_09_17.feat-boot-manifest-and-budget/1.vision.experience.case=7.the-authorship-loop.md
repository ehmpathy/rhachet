# case=7 — the authorship loop (the DENSE journey)

**cells 11 → 12 → 11, plus the reviewer seam** · feel **happy → sharp → happy** · care **critipath**

🔴 **this is the densest experience the wish implies, and it is the one to center.** six boundaries
in one realistic session, across two actors.

⇒ the focused demos (`case=1..6`) cross **one** boundary each — 🟡 **`case=6` excepted: it demos two
cells (`L` under, `L′` over) and so crosses the under→over limit inside subject mode** — and *"a
vision of only sterile single-boundary demos is thin"*
(`define.experience._.metric=boundary-density`). sharper still: **the yield's `a day in the life`
section narrates this exact loop, so without this file the vision would promise a journey no case
demonstrates** — precisely the *"prose promises; it does not demonstrate"* failure
`define.experience` names.

## .the narrative

Bo wants a route-scoped boot for the behavior he drives. he writes the manifest in one session.

**he starts small.** the wish and the vision, resident; naught else.

```
  └── tokens ≈ 3120 / 5000 budget   (62% used)
```

it renders. he gets on with the work.

**an hour later he wants the fulcrum inventory in context too.** he adds it to `say`.

```
  └── tokens ≈ 4890 / 5000 budget   (98% used)
```

🟡 **this is the moment the whole design earns its keep, and it is quiet.** Bo was not stopped. he
was *told* — 98% — and he now knows the next add is the one that breaks. he would not have known
that from a boot that speaks only when it refuses.

**then he adds the six experience demos.** the boot refuses:

```
🧢 roles boot --manifest .behavior/v2026_09_17.feat-boot-manifest-and-budget/boot.yml
   ├─ ✋ over budget
   │  ├─ budget   = 5,000 tokens   (declared in boot.yml)
   │  ├─ payload  = 7,240 tokens   (full emitted payload, o200k_base)
   │  └─ over by  = 2,240 tokens   (145% of budget)
   │
   ├─ some resources must go — you choose which
   │
   └─ fix — four strategies, cheapest first
      ├─ catalogize    replace a set with one catalog that indexes it
      ├─ condense      author an x.md.min beside x.md
      ├─ reference     move a say entry to ref  (it stays addressable, costs its path line)
      └─ eliminate     delete what does not earn its boot
                       ⇒ or raise budget.tokens deliberately — it lands on the diff
```

Bo reads the ladder and knows what to do. **the halt names no file, and it does not have to** — Bo
wrote every one of these and knows which carry the argument. he moves the demos from `say` to `ref`
(strategy 3), because a demo is consulted once and a rule fires every turn. re-boots:

```
  └── tokens ≈ 4930 / 5000 budget   (99% used)
```

✅ it passes. **and the payload is not diminished** — every demo is still there, one `Read` away.

### 🔴 the felt friction the dense walk exposed, and the sterile demos did not

Bo glances at the whole `<stats>` block after the move and frowns:

```
quant
  ├── files = 9          ← unchanged
  │   ├── briefs = 9
  │   │   ├── say = 3    ← was 9
  │   │   └── ref = 6    ← was 0
  ├── chars = 19720
  └── tokens ≈ 4930 / 5000 budget   (99% used)
```

**`files = 9` did not move.** for a second he thinks the edit did not take — because the headline
number is the one that stayed still. it is the *nested* `say`/`ref` split that changed.

⇒ this is real, and it follows from the extant code: `relevantFiles`
(`bootRoleResources.ts:105-113`) counts **say and ref together**, while `totalChars`
(`:127-146`) counts **say only**. so the remedy the halt recommends is the one remedy whose effect
is **invisible in the top line of the very block that reports it.**

🟡 **no focused demo could surface this — `case=6`'s two cells included.** `case=1` and `case=3`
each render one payload once, and `case=6`'s pair varies on **selection**, never on a say→ref move.
the defect lives in the *difference between two consecutive boots*. that is the value of density,
demonstrated on itself.

**the fix it implies** — a nitpick, not a blocker: when a budget is declared, the `<stats>` block
should make the say/ref split legible at the level the remedy acts on. the cheapest form is to name
the delta on the line the author already reads. filed against **F6**, which owns the within-budget
`<stats>` shape.

### the temptation, and the second actor

Bo could have taken the third remedy. suppose he had — `budget: 5_000` → `8_000`, one line, boot
passes, work continues.

**Ana opens the PR the next day.** she does not look for the budget; she reviews the behavior. but
the diff says:

```diff
 budget:
-  tokens: 5_000
+  tokens: 8_000
```

and she asks the one question that matters: *"what did we add that needed 3,000 more?"*

⇒ 🔴 **this is the wish's social claim, demonstrated rather than asserted.** the yield's `cons`
section says the raise-the-budget remedy *"is mitigated socially (it is a reviewable line in a
diff), not mechanically."* `[t5]` is what makes that claim checkable: **the mitigation is real
only if the raise is legible to a second actor who never went looking for it.** a one-line diff on
a declared integer is about as legible as a change gets.

## .the bdd sketch

```
given [case7] a route dir with a boot.yml that declares budget.tokens = 5_000
  # .behavior/v2026_09_17.feat-boot-manifest-and-budget/boot.yml
  #   budget: { tokens: 5_000 }
  #   always: { briefs: { say: ['0.wish.md', '1.vision.yield.md'] } }

  when [t0] Bo boots the manifest
    $ rhachet roles boot --manifest .behavior/v2026_09_17.../boot.yml

    then it exits 0
    then the two say briefs render resident
    then <stats> names          tokens ≈ 3120 / 5000 budget   (62% used)

  when [t1] Bo adds the fulcrum inventory to say, and re-boots
    then it exits 0                                        # under, still
    then <stats> names          tokens ≈ 4890 / 5000 budget   (98% used)
    # the steer boundary: the actor learns the next add is the one that breaks,
    # WITHOUT a halt. no other cell can assert this, because it needs two boots.
    #
    # 🔴 .proven = `roles.boot.budget.acceptance.test.ts` [case8], as a PAIR with
    #   [case7] there. [case7] grades one boot's BAND; [case8] grades the DELTA
    #   between two, which no snapshot of either boot can see.
    #   ⇒ the assertion is RELATIONAL (`after > before`), never the two literals
    #     above — a pinned pair would redden on a render change and be resnapped.
    #   ⇒ teeth: pin the render to a constant `80` and [case7]'s three behavioral
    #     assertions ALL stay green (80 sits inside its 75..100 band); only its
    #     snapshot reddens, and a snapshot is what a resnap washes away. [case8]'s
    #     climb reddens on BEHAVIOR: `Expected: > 80 · Received: 80`.

  when [t2] Bo adds the six experience demos to say, and re-boots
    then it exits 2                                        # ConstraintError
    then NO payload is emitted at all                      # requirement 2 = "spend naught"
    then stderr names budget, payload, and overage
    then 🔴 stderr names NO individual resource
      # F13. the halt says that some resources must go, and never which.
      # ⇒ a NEGATIVE assertion on purpose — it forbids the block, so a builder
      #   cannot re-add it as a kindness.
      # 🔴 and THIS case is the demo of why. the six briefs Bo moves at [t3]
      #   LEAVE the heaviest list, so a cost-sorted halt would name three
      #   SMALLER files while occupancy ROSE (F12). advice sorted by cost
      #   walks a staircase, downward.
    then stderr names the four strategies, IN ORDER
      - catalogize · condense · reference · eliminate
      # a ladder of loss: 1-2 cost the reader naught, 3 costs a dereference,
      #   4 costs the document. the order is the pit of success.
    then stderr offers the deliberate budget raise, AFTER the four

  when [t3] Bo picks a strategy HIMSELF — reference: moves those six from say to ref — and re-boots
    # 🔴 the halt named no file, so the choice is Bo's. he picks the six demos
    #   because a demo is consulted once and a rule fires every turn — a VALUE
    #   judgment the gate could not have made for him.
    then it exits 0                                        # the recovery boundary
    then <stats> names          tokens ≈ 4930 / 5000 budget   (99% used)
    then all six demos are still addressable as <brief.ref path="..."/>
    # 🔴 the density find — assert the part that misleads, explicitly.
    #    ⚠️ the comparison target is the SPEC's file set, never [t2]'s <stats>:
    #    [t2] halted and emitted no payload, so it rendered no <stats> to
    #    compare against. the spec at [t2] and the spec at [t3] name the same
    #    9 resources; only the say/ref split moved.
    then <stats> files count equals the file count of [t2]'s SPEC   # 9, say + ref together
    then <stats> briefs.say fell 9 -> 3 and briefs.ref rose 0 -> 6
    # ⇒ so the headline `files` line does not move while the payload fell by
    #   six briefs, and the author's first read is "the edit did not take".
    #
    # 🔴 .proven = `roles.boot.budget.acceptance.test.ts` [case9] — and it is the
    #   ONLY test that walks [t2]->[t3] end to end: a real halt, a real
    #   writeFileSync between two real subprocess calls, an identical reboot,
    #   and an assertion that the act the remedy NAMED is the act that cleared
    #   it. the spec is byte-identical across the pair but for the say/ref move.
    #   ⇒ it carries a NEGATIVE assertion too — the six were REPLACED, never
    #     duplicated — backed by `getAllBootSayResources.ts:88`.
    #
    # 🟡 this citation was ABSENT until i006, and the absence is the sharper
    #   record. [case7] and [case8] were cited for the whole loop, and neither
    #   ever breaches: [case7] grades one boot's band, [case8] grades a climb
    #   whose two boots are BOTH under budget. ⇒ a reviewer who walked the
    #   declared chain would have found the loop unproven and been WRONG, which
    #   is worse than an honest gap because it reads as a real defect.

  when [t4] Bo instead raises the budget to 8_000 (the alternative history)
    then it exits 0
    then the raise is the only line changed in the spec

  when [t5] Ana reviews the diff that [t4] produced
    then the diff shows `- tokens: 5_000` / `+ tokens: 8_000`
    then the cost change is legible to an actor who never set out to check cost
    # the seam boundary: this is the ONLY assertion that grades the wish's
    # social-mitigation claim. a second actor, with no such intent, still sees it.
```

🟡 **note what the two forms each caught, per `define.experience`'s no-transliteration rule.** the
narrative caught the **felt** surprise — the unmoved `files = 9`. the `[tn]` caught the **logical**
one — that `[t5]`'s assertion has no owner among the six focused demos, so the yield's social
claim was, until now, untested by any artifact.
