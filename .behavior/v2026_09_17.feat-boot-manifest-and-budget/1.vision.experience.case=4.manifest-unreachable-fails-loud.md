## 🔴 .the asymmetry the grid surfaced

**the same axis value — `absent` — has opposite verdicts by source.**

| source | spec `absent` | verdict |
|---|---|---|
| `role-default` | no boot.yml in the role dir | **legitimate.** say-all is the documented fallback (`bootRoleResources.ts:76-81` → `null` config) |
| `custom-manifest` | the named path is not there | 🔴 **a loud failure.** the caller named a specific file; its absence is never a default |

⇒ a free-list would have written one "absent spec" case and picked one behavior. **the grid forced
both, and they must not share a code path.** this is the single most valuable result of the walk.

🟡 and it is a real hazard, not a hypothetical: the extant `--if-present` flag exists precisely to
soften an absent *role dir*. if `--manifest` inherits that softness, a typo'd path boots silently
empty — a failure that reads as success.

⇒ **so `--if-present` must NOT apply to `--manifest`**, or must be refused beside it. it is axis
D's `with-if-present` value in `1.vision.experience.case=_.md` — a rejection invariant, and it is
asserted at `[t6]` below.

🔴 **a claim that a record exists is not a record** — the citation above names a row a reader can
open, so the invariant is checkable rather than asserted.

### ⚠️ the extant code leans AGAINST this, so it is argued rather than derived

`ifPresent` gates **two** things today, and the absent `boot.yml` is **neither** of them:

| line | what `ifPresent` gates |
|---|---|
| **41-49** | an absent **role DIRECTORY** → returns silently instead of a throw |
| **116-124** | an **empty payload** → returns silently instead of the `⚠️` warn |
| **76-81** | 🔴 an absent **`boot.yml`** → `: null`, **unconditionally**. `ifPresent` is not consulted |

🔴 **a manifest path IS the spec, so its closest extant analogue is line 41-49** — the absent role
dir — and that case *is* softened today. ⇒ the asymmetry above is real, but it does not by itself
settle the flag: an honest reader can say *"a manifest is like a role dir, so soften it."*

**the argument that settles it is about the flag's PURPOSE, not a symmetry:**

> `--if-present` exists because a caller boots a **set** of roles, some of which may not be linked
> in this repo — it means *"boot whichever of these are here."* a `--manifest` names **one** path
> the caller chose deliberately. there is no set to be tolerant across, so tolerance here converts
> a typo into an empty boot rather than an error.

⇒ and note what that implies for `[t6]` below: the right behavior is to **refuse the combination**
outright rather than silently ignore the flag — a caller who typed both has a mistaken model, and
`rule.require.errors-name-the-fix` says to correct it loudly.

## .the bdd sketch

```
given [case4] a --manifest path that cannot be read

  when [t0] the path does not exist
    $ rhachet roles boot --manifest .behavior/typo/boot.yml

    then it exits 2                            # ConstraintError — the caller must fix it
    then no payload is emitted
    then the halt names the path as asked-for AND as expanded
    then the halt offers the nearest extant match, when one is close
    then the halt names the alternative:  --repo/--role

  when [t1] the file exists and holds invalid yaml
    then it exits 2
    then the halt names the path, the parse error, and the expected shape

  when [t2] the file exists and parses but fails the schema
    then it exits 2
    then the halt names which key was wrong        # reuses parseRoleBootYaml's errors

  when [t3] --manifest is the last token, with no path after it
    then it exits 2
    then the halt names the absent value, never reads the next flag as a path

  when [t4] --manifest names a path outside the repo
    then it exits 2                            # a rejection invariant
    then the halt names the repo boundary

  when [t5] --manifest and --role are both named
    then it exits 2                            # two specs, no precedence
    then the halt names which flag to drop

  when [t6] --manifest is named beside --if-present
    then it exits 2                            # an absent manifest is never "not present"
```
