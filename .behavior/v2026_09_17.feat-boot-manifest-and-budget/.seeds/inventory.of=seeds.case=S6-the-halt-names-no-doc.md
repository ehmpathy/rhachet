# seed S6 — the halt says THAT some docs must go, never WHICH

**caught 2026-09-18, at the `1.vision` approval gate.** it struck a feature the vision had invented
and then treated as settled.

---

## .said

> it shouldn't say which docs to omit. it should just say omit some. and it should recommend
> catalogization, condensation, reference, and elimination as good strategies to guide fix on
> budget exceeded

and, quoted back at the vision's own mental-model line:

> *"…tokens it's allowed to spend on them. if you go over, it refuses and tells you which doc to
> demote."*

---

## .settled

**the halt names four strategies, in order, and no individual resource.**

```
   some resources must go — you choose which

   fix — four strategies, cheapest first
     ├─ catalogize   replace a set with one catalog that indexes it
     ├─ condense     author an x.md.min beside x.md
     ├─ reference    move a say entry to ref  (it stays addressable, costs its path line)
     └─ eliminate    delete what does not earn its boot
                     ⇒ or raise the declared budget, deliberately — it lands on the diff
```

## 🔴 .why — the gate knows COST; only the author knows VALUE

| the halt asserts | what it must know to be right |
|---|---|
| **that** some resources must go | the payload's **cost** — which the gate measures exactly |
| 🔴 **which** resources must go | that resource's **value** — 🔴 **which the gate cannot see at all** |

⇒ **a 2,021-token brief may be the one document the whole role rests on, and a 300-token one may be
dead weight.** to sort by cost is to advise by the one quantity that is uncorrelated with the
decision.

🔴 **and the vision had already measured the symptom, three rounds before it named the cause.**
`F13`'s own notes observed that a trim of the top brief *leaves* the heaviest list — so the next
halt names three **smaller** files while occupancy may have risen. **I filed that as a caveat and
kept the feature.** it was the refutation: **advice sorted by cost walks a staircase, downward.**

## 🔴 .the four strategies are a LADDER OF LOSS, and the order is the pit of success

| # | strategy | what survives | what it costs the reader |
|---|---|---|---|
| 1 | **catalogize** | 🔴 **all of it**, restructured — one catalog indexes a set | naught, if the catalog is good |
| 2 | **condense** | **all of it**, compressed — an `x.md.min` beside `x.md` | naught — the renderer already prefers `.min` |
| 3 | **reference** | the doc, **not resident** | one dereference |
| 4 | **eliminate** | 🔴 **none of it** | the document |

⇒ an author who reads top-down reaches for a **lossless** remedy before a lossy one. a list sorted
any other way invites the cheapest-to-*type* remedy rather than the cheapest-to-*read*.

🟡 **two of the four were already in the wish's three remedies** (`condense` ↔ *point say at a
.min*, `reference` ↔ *move say to ref*). the wisher **added** `catalogize` and `eliminate`, and
**dropped** the per-file targets — so the remedy set grew while the advice narrowed.
