# case=1 — a role boot that fits its declared budget

**cell 2** — `role-default` × `valid` × `declared-under` · feel **happy** · care **critipath**

---

## .the narrative

Bea opens a session on the mechanic role. she has no thought to spare for tokens — her mind is on
the bug she came for.

the boot renders, as it always has. one line is new: the `<stats>` block now says what the payload
was allowed to cost, beside what it did cost.

> `tokens ≈ 4,210 / 5,000 budget`

she reads it in half a second and moves on. **that half second is the whole product for this
cell** — the cap is not a gate she must clear, it is a receipt she can glance at.

three months later a teammate adds two `say` briefs to that role. the number climbs to 4,890. Bea
never notices, because there is naught to notice — it still fits. the next add is the one that
halts (`case=2`), and by then the budget has already done its job: it made the headroom
**visible while there was still room left**.

⇒ the value of this cell is that it is **dull**. a cap that only ever speaks when it refuses is a
cap nobody can steer by.

## 🔴 .and under F12, the dullness is the HAZARD

this cell's virtue is that Bea trusts the receipt without thought. the narrative says so outright:
*"she has no thought to spare for tokens"*, *"she reads it in half a second and moves on."*

🔴 **that is precisely what makes a wrong number dangerous here.** `F12` measures the gated quantity
at **36.5%** of what the boot emits, so the receipt reads `84% used` while occupancy may be over
200% of the cap.

| the cell | what F12 does to it |
|---|---|
| `case=2` — the halt | a **remedy overstates its effect**. an irritation, and the author is at least engaged |
| 🔴 **`case=1` — the receipt** | **a false reassurance, read by an actor whose attention is elsewhere.** no halt fires, no attention is drawn, and the number is believed on sight |

⇒ **a halt that misleads gets argued with. a receipt that misleads gets trusted.** so the
within-budget cell is the one where the wrong quantity does its quietest damage, and it is graded
**happy × critipath** — the combination that gets the least scrutiny.

🟡 **the cell's design is not at fault, and no change is owed here.** the `used / budget` line is
right (`F6`) and steerability is a real virtue. what it requires is that the number be honest ⇒
**`F12` is this cell's precondition too, and the argument for `F12` is stronger for it:** the case
for a correct numerator does not rest on the halt alone.

## .the bdd sketch

```
given [case1] a role whose boot.yml declares a budget its payload fits
  # .agent/repo=ehmpathy/role=mechanic/boot.yml
  #   budget:
  #     tokens: 5_000
  #   always:
  #     briefs:
  #       say:  ['briefs/core.md']
  #       ref:  ['briefs/deep/**/*.md']

  when [t0] the role is booted
    $ rhachet roles boot --repo ehmpathy --role mechanic

    then it exits 0
    then it renders the payload exactly as it does today
      - <readme path="..."> ... </readme>
      - <brief.say path="briefs/core.md"> ... </brief.say>
      - <brief.ref path="briefs/deep/x.md"/>
    then the <stats> block names the budget beside the cost
      - tokens ≈ 4210 / 5000 budget   (84% used)
    then no warn and no halt is emitted
```

### 🟡 .why this sketch carries no `--format json` step

**no output-shape flag exists.** `invokeRolesBoot.ts:12-71` declares `--repo`, `--role`,
`--if-present`, and `--subject`, and no more.

⇒ 🔴 **a bdd `then` is an assertion, so a hedged one is a defect either way**: if the shape existed
it would be an un-walked cell on an undeclared axis; since it does not, such a step asserts an
undefined capability. **a hedge — *"(if a json shape exists)"* — is the tell**, and output shape is
named in the dimensions' omissions table, so its absence is a verdict rather than a gap.

🟡 a case file that posits a path with no cell and no verdict breaks the walk's completeness claim,
which rests on the product of the declared axes.

## 🟡 .the design question this cell raises

**how loud should a within-budget boot be about its budget?**

| option | cost |
|---|---|
| say naught unless over | the author cannot see the headroom shrink. the cap becomes a surprise |
| always name `used / budget` | one extra line per boot, forever |
| name a percentage only past a threshold (e.g. 80%) | a third state to explain, and a second number to tune |

⇒ **best-guess: always name `used / budget`.** it costs one line and it is the only option where
the headroom is visible *before* it runs out. raised as fulcrum **F6**.

🔴 the line itself must be inside `<stats>`, never above it — the `<stats>` block is already
snapshotted by `roles.boot.bootyaml.acceptance.test.ts`, so a line outside it would land in the
payload a brain reads as context.
