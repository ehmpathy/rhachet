# case=2 — an over-budget boot halts, and names the remedies

**cells 3 + 12** — `either source` × `valid` × `declared-over` · feel **sharp** · care **critipath**

🔴 the densest cell in the grid. the whole wish turns on it.

---

## .the narrative

Bev adds a brief to the behaver role. it is a good brief — dense, worked, 1,900 tokens. she adds
it to `say` because that is what `say` is for.

she opens a session. **the boot refuses.**

```
🧢 roles boot --repo bhuild --role behaver
   ├─ ✋ over budget
   │  ├─ budget   = 5,000 tokens   (declared in boot.yml)
   │  ├─ payload  = 6,340 tokens   (full emitted payload, o200k_base)
   │  └─ over by  = 1,340 tokens   (127% of budget)
   │
   ├─ some resources must go — you choose which
   │
   └─ fix — four strategies, cheapest first
      ├─ catalogize    replace a set of briefs with one catalog that indexes them
      │                (the set stays reachable; only the index is resident)
      ├─ condense      author briefs/x.md.min beside briefs/x.md
      │                (the renderer already prefers .md.min — no boot.yml change)
      ├─ reference     move a say to ref, in boot.yml
      │                (a ref costs one path, never its body)
      └─ eliminate     delete a brief that does not earn its boot
                       ⇒ or raise budget.tokens deliberately, if the cost is warranted
```

Bev knows which of her briefs carry weight — the halt does not, and does not guess. she reads the
ladder, recalls that `howto.write.skills-stdout` has a `.md.min` beside it already, condenses, and
the boot passes. **elapsed: under a minute.**

### 🔴 why the halt names no file — the tool knows COST, the author knows VALUE

the feature a halt reaches for is *the 3 heaviest say resources, in order*. it is forbidden
(`F13`), on two arguments — and the second is the one that settles it:

| | |
|---|---|
| the loop | a trim of the top brief **leaves** the heaviest list, so the next halt names three smaller files. an author who follows the advice literally walks a staircase, downward |
| 🔴 **the claim** | to name a file asserts knowledge of that file's **value**. a 2,021-token brief may be the one document the whole role rests on; a 300-token one may be dead weight. **the gate can see only cost** |

⇒ so the halt names **that** some must go, plus **how** — and the four strategies are a ladder of
loss (`catalogize` and `condense` cost the reader naught; `reference` costs a dereference;
`eliminate` costs the document), which is why they print in that order.

### 🔴 the aha — the trim happened at authorship, in front of a reviewer

the counterfactual is the whole argument. with no budget, Bev's brief lands, the boot grows by
1,900 tokens, and **nobody learns of it** — not Bev, not the reviewer, not the twenty sessions
that pay for it daily. the payload that measured ~46% of a context window got there exactly this
way: one good brief at a time, each one locally correct.

⇒ the halt converts an invisible, permanent cost into a **one-minute, reviewable choice**. and
the choice is on the diff — *"raised budget 5,000 → 6,500"* is a line a reviewer can argue with.

## .the bdd sketch

```
given [case2] a role whose payload exceeds its declared budget
  # boot.yml declares budget.tokens: 5_000
  # the FULL EMITTED payload measures 6_340 real tokens (requirement 7)

  when [t0] the role is booted
    $ rhachet roles boot --repo bhuild --role behaver

    then it exits 2                                  # ConstraintError — the author must fix it
    then NO payload is emitted
      - no <readme>, no <brief.say>, no <brief.ref>, no <stats>
    then the halt names the arithmetic
      - budget, payload, and the overage, each as a number
    then 🔴 the payload figure is the FULL EMITTED payload, in REAL tokens
      # requirement 7. NOT the say-only char sum, and NOT chars ÷ 4 —
      #   the extant counter measured 3.29x understated (a 2.72x scope
      #   error × a 1.21x divisor error). a say-only gate is the shape
      #   requirement 7 exists to eliminate, so it is pinned here rather
      #   than left to a builder's read of "payload".
    then 🔴 the halt names NO individual resource
      # F13. to name a file asserts knowledge of that file's VALUE, and the
      #   gate can see only its COST. the halt says that some resources must
      #   go, and never which.
      # ⇒ this `then` is a NEGATIVE assertion on purpose — it forbids the
      #   per-resource block, so a builder cannot re-add it as a kindness.
    then the halt names the four strategies, IN ORDER
      - catalogize   (a set → one catalog that indexes it)
      - condense     (author an x.md.min beside x.md)
      - reference    (move a say to ref)
      - eliminate    (delete it)
      # the ORDER is asserted because it is a ladder of loss: 1-2 cost the
      #   reader naught, 3 costs a dereference, 4 costs the document. an
      #   author who reads top-down reaches the cheapest remedy first.
    then the halt offers the deliberate budget raise, AFTER the four
      # the wish's third remedy. it stays, but it is not one of the four —
      #   the four shrink the payload; a raise accepts it.
    then stderr carries the message; stdout stays empty

  when [t1] the author moves one say to ref, then re-boots
    then it exits 0
    then the payload renders
    then <stats> reports the cost under the budget

  when [t2] the author instead raises budget.tokens to 6_500, then re-boots
    then it exits 0                                  # a deliberate raise is honored
```

## 🔴 .why NO payload may be emitted

the strongest temptation is to render the payload *and* warn. it must not.

- a boot's output **is** the context injection. to emit it is to pay its cost
- so a render-plus-warn has already spent the tokens the budget exists to refuse — the cap
  becomes a label on a bill that was paid anyway
- ⇒ **requirement 2 is not merely "be loud". it is "spend naught".** the check must sit *before*
  the first `console.log`, which in `bootRoleResources.ts` means before line 189 (`printStats()`)

🟡 this is a real constraint on where the check goes, and it is cheap to satisfy: the char count
is already computed at lines 127-146, *before* any output. the budget gate slots in at line 147.

---

## 🟡 .why exit 2, not exit 1

`ConstraintError` (exit 2) means *the caller must fix it*; `MalfunctionError` (exit 1) means *the
tool is broken* (`rule.require.exit-code-semantics`). an over-budget payload is a declared cap
at work as designed, so the author is the party who acts. **exit 2.**

⇒ a `SessionStart` hook that treats any non-zero as a crash would report this as a tool failure.
the wish does not cover hook behavior, so it is itemized as a downstream concern for
`rhachet-roles-bhuild#392`.

---

## 🔴 .the counter's accuracy is load-bearing HERE — and requirement 7 settles it

this cell is where a counter's error bar stops to be cosmetic. a counter that **undercounts** lets
an over-budget payload render — the exact silent pass this cell exists to prevent.

**settled 2026-09-18 by wish requirement 7: the counter is a real tokenizer over the full emitted
payload.** the measurement that forced it, on this repo's own `repo=.this/role=any` boot:

| quantity | value |
|---|---|
| what the boot **reported** | `chars = 16,427` → `tokens ≈ 4,107` |
| what the boot **emitted** | 44,666 chars |
| **real tokens** (`o200k_base`) | 🔴 **13,494** |
| understated by | 🔴 **3.29x** |

two independent defects, both downward, and they compound: a **scope** error of `2.72x` (the
heuristic is applied to 16,427 of 44,666 emitted chars) × a **divisor** error of `1.21x` (the true
density is 3.31 chars/token, not 4.0). `2.72 × 1.21 = 3.29`.

⇒ so the halt above renders **real tokens over the whole emitted payload**, and a `budget: 5_000`
means 5,000 real tokens. the tokenizer loads **lazily on a declared `budget`**, so an unbudgeted
boot — which needs no counter at all — never pays for it (requirement 4). the residual is narrow
and disclosed: the count is exact for one encoder, approximate across model families. fulcrum
**F1**.

## 🔴 .the FIRST remedy is partly illusory under the extant counter

measured. *"move a `say` entry to `ref`"* does two things:

| effect | on the gated number | on actual context occupancy |
|---|---|---|
| the file's content leaves `totalChars` (`bootRoleResources.ts:126-146`) | 🔴 **a large drop** | — |
| a `<brief.ref path="…"/>` line is added to the payload | **no change — it is uncounted** | 🔴 **a real increase** |

⇒ **the remedy converts counted payload into UNCOUNTED payload.** the gated number falls far more
than the occupancy does, so the author reads a bigger win than they got.

```
$ npx rhachet roles boot --repo .this --role any | head -13   →   chars = 16427
$ npx rhachet roles boot --repo .this --role any | wc -c      →   44982
```

🔴 **the gate sees 36.5% of what the boot emits** — every ref line, the whole `<also>` block, and
all XML chrome are emitted and uncounted. so this cell's own headline remedy is the one that most
exploits the gap. ⇒ fulcrum **F12**.

### ✅ .and requirement 7 closes it

requirement 7 gates the **full emitted payload**, so the ref line a demoted brief leaves behind is
counted:

| effect | under the extant counter | 🔴 under requirement 7 |
|---|---|---|
| the brief's body leaves `say` | a large drop in the gated number | a large drop — **and it is real** |
| a `<brief.ref path="…"/>` line is added | uncounted ⇒ a free win | **counted** ⇒ the small true cost of a ref |

⇒ **the remedy stops to be illusory, and becomes merely favourable** — which is what it always
should have been. the halt above therefore renders a payload figure an author can act on without
a correction factor, and the `[t1]` `then` ("the payload renders … under the budget") is true of
occupancy rather than of a proxy for it.

## 🔴 .every strategy assumes the halted party OWNS the spec

each of the four — catalogize, condense, reference, eliminate — plus the deliberate raise, needs a
**write** the halt's named spec path points at: `reference` and the raise edit the `boot.yml`
itself; `catalogize`, `condense`, and `eliminate` edit the resources it names. that holds for
`repo=.this`, and it does not hold for most specs in this repo:

```
rhx globsafe --pattern '.agent/repo=*/role=*/boot.yml'   → 15 files, 2 of them ours
```

the other 13 are symlinks into a **version-pinned pnpm store**, so an edit there is wiped by the
next `pnpm install`.

⇒ **a halt whose every remedy names a file the halted party cannot write is a halt with no
remedy** — the product-level form of `rule.always.raise-a-blocker-a-taken-cannot-close`
(**OWED ≠ PERMITTED**). requirement 4 defers the whole blast radius today, since none of the 15
declares a `budget` yet, so the risk is **forward**: it arrives by a third-party release.

### 🔴 .the resolution — narrow the GATE, not the remedies

wish requirement 8 gates **our own specs only**, rather than widen the remedies per owner:

| | gate every source | 🔴 **gate our own only** |
|---|---|---|
| a foreign over-cap spec | halts, with owner-specific remedies | **does not halt** |
| what it needs | an **override flag** — a new capability | **no new capability** |

⇒ **so the four strategies above are correct as written, unconditionally**, because the only party
they are ever shown to is a party that can write the files. the owner axis does not vary the
strategy list; it is the **gate condition itself** (walked as axis `G`, cells `G1`–`G6`).

🟡 **and requirement 3's remedy function collapses by one axis: it is `(mode)`, never
`(mode, owner)`.** `case=6` is the one cell that still varies it — a subject-scoped spec earns a
**fifth** strategy, *narrow the `--subject`*. a builder who branches on owner would build a branch
that cannot fire.
