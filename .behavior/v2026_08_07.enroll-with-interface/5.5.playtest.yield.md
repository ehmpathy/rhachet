# 5.5.playtest — enroll with interface

> a step-by-step byhand quality-assurance checklist for the foreman. walk each step, compare the
> actual output to the stated expectation, and mark pass/fail. every step cites the acceptance test
> that proves it, so a green suite and a green byhand walk agree.

> **scope.** this behavior delivers the **frame** (actor/clone on disk) + the **talk** surface
> (`list` / `say` / `get` / `whoami`) + the reach-state lifecycle (`LIVE` / `DEAF` / `DEAD`) and its
> cleanup verb (`prune`). the **bake** lifecycle (`make` / `fork` / `wake`) and the `actors.yml` slug
> namespace are the `rhx clone` dream — **out of scope**, so no step exercises them.

---

## prerequisites

- the repo is built: run `npm run build` once (the byhand steps invoke the compiled `bin/run` via
  `npx rhx`, per `howto.test-local-rhachet` — the `link:.` self-link makes `npx rhx` your local build).
- the repo is **linked**: it carries a `.agent/` directory. this worktree already is. a fresh sandbox
  repo is linked with `rhx roles link` (see the unlinked edge path below for the fail-loud when it is not).
- for the **real-brain** steps (enroll → say → get a live reply), a real authenticated `claude` on
  PATH. these are the credential-gated steps; the rest are deterministic and need no brain.
- the whole automated proof: `rhx git.repo.test --what acceptance --against local --env test --scope enroll --mode apply` (110 files) and `--scope clone` / `--scope actor`.

## sandbox

- **every file create/write/delete in a byhand step targets `@gitroot/.temp/`.** never enroll, link,
  or write outside it — an enroll in the repo root leaves real actor dirs under `.agent/.actors/`.
- the reach-surface reads that inspect THIS worktree (`clone list`, `actor list`, `clone --help`) are
  read-only and safe to run from the repo root — they mutate naught.

### sandbox setup (make the linked repo the enroll steps assume)

every `enroll` step below runs INSIDE a linked sandbox repo. stand one up once, before step 1:

1. `rhx mkdirsafe --path .temp/playtest` — make the sandbox dir.
2. `cd .temp/playtest` — the enroll/list/say/get steps run from HERE (so the actor dirs land in the
   sandbox, never the repo root). all `npx rhx …` below assume this cwd unless a step says otherwise.
3. `git init` — rhachet needs a git root to anchor `.agent/`.
4. `npx rhx roles link --roles mechanic,architect` (or your role set) — this creates the `.agent/`
   directory that marks the repo LINKED. confirm: `.agent/` now exists.
5. for the **unlinked** edge steps (E1), use a SECOND bare dir with a `git init` but NO `roles link`,
   so `.agent/` is absent.

when done, remove the sandbox: `rhx rmsafe -r .temp/playtest`.

### two terminals — enroll OCCUPIES its terminal

`rhx enroll` opens an interactive claude that INHERITS the terminal and stays in the foreground until
you exit it (Ctrl-D). so:

- keep **terminal A** for the enroll (the live brain sits here).
- open **terminal B**, `cd .temp/playtest` (same sandbox cwd — the reach verbs look up clones against
  THIS repo's `.agent/.actors/`), and run the `clone list` / `say` / `get` verbs there while the brain
  in terminal A stays live.
- to run several enrolls (steps 2, 12, E9), either exit each brain (Ctrl-D) before the next, or use a
  fresh terminal per enroll — each still `cd`'d into the sandbox.

### which steps need a live brain

- 🧠 **live-brain steps** (need an authenticated interactive claude): 1, 2, 3, 6, 7, 8, 9, 12, 13, E5, E9,
  E10, E13, E14, E16.
- ⚙️ **deterministic steps** (fail-loud or read-only — NO brain needed): 4, 5, 10, 11, E1, E2, E3, E4, E6,
  E7, E8, E11, E12, E15, E17, E18, E19, E20, E21. a foreman with no claude auth can still walk every ⚙️
  step. (E10 and 13 spawn a real brain to exercise the DEAF→DEAD lifecycle, so they carry the 🧠 mark; the
  prune SURFACE itself — E20, E21 — is deterministic.)

## placeholder convention (substitute before you paste)

the commands below carry angle-bracket placeholders. replace each with a concrete value first:

- `<nonce>` / `<n>` — any short unique token YOU pick, e.g. `k7q2`. it lets you prove the exact message
  you said is the one that reads back (an `ack:k7q2`).
- `<serial>` — a full clone serial. copy it from a `clone list` row (`serial=<full>`) or from the
  `@:<serial>` the bare enroll printed on spawn.
- `<hash>` / `<hash-prefix>` — an actor hash (or its first few chars). copy it from an `actor list` row
  (`@<hash>…`). derive it BEFORE the step that needs it.
- a brain "exits" when you close its terminal (Ctrl-D at the claude prompt, or close the tab). the
  clone then reads DEAD on the next `clone list`.

## happy paths

### 1. enroll opens the brain and leaves an addressable clone (the invisible hot path)

- **action:** in a linked sandbox repo, run `npx rhx enroll claude --roles mechanic`.
- **expected:** claude opens in the terminal and inherits it, exactly as before. invisibly, a clone
  record lands on disk under `.agent/.actors/actor.via.hash=<hash>/clones/serial=<serial>/`, and the
  bare-enroll breadcrumb prints the human's own `@:<serial>` reach address to stderr.
- **cite:** `enroll.acceptance` case2b (bare enroll keeps the default roleset, success snapshot);
  `enroll.reach.acceptance` case1 (the bare-enroll breadcrumb names how to reach the own clone).

### 2. the default brain resolves from three input forms

- **action:** run each of `npx rhx enroll` (no brain), `npx rhx enroll --brain claude`, and
  `npx rhx enroll claude` (positional).
- **expected:** all three enroll the same brain. the bare form falls back to the repo default; the flag
  and positional are aliases.
- **cite:** `enroll.acceptance` case2b (bare → default roleset); the brain-conflict guard in case10 t2
  proves the flag+positional agreement rule from the other side.

### 3. name the clone with `--as`, then reach it by BOTH slug and serial

- **action:** in terminal A run `npx rhx enroll claude --as @:driver` (leave the brain live). in
  terminal B (cd'd into the sandbox) run `npx rhx clone say @:driver --what "poke <nonce>"` and
  `npx rhx clone get @:driver`. repeat the say/get by the printed `@:<serial>`.
- **expected:** the clone carries `driver` as a stable handle. both `@:driver` and `@:<serial>` address
  the SAME clone. the `get` output carries the TRANSFORMED ack (`ack:<nonce>`); the say reached the brain
  (an echo alone would not prove dispatch).
- **cite:** `clone.acceptance` case1 t1 (say by slug → get the transformed ack), t2 (say by serial →
  same ack); `enroll-to-reach.journey.acceptance` case1 t1 (the core round-trip by slug).

### 4. the actor identity is anonymous (roleset-derived), never a slug actor

- **action:** after the `--as @:driver` enroll, run `npx rhx actor list`.
- **expected:** the actor appears as an ANONYMOUS hash actor `@<hash>…` with its brain + roles — never a
  slug actor. the `driver` name lives on the CLONE, not the actor (the two-grain split).
- **cite:** `clone.acceptance` case1 t0 (on-disk actor is a HASH actor, never a slug actor);
  `enroll-to-reach.journey.acceptance` case1 t0 (anonymous hash actor).

### 5. enumerate actors and clones

- **action:** run `npx rhx actor list`, then `npx rhx clone list`.
- **expected (verbatim shape):** `actor list` renders `🎭 actors` with one row per enrolled hash actor,
  e.g. `├─ @8169357…  brain=claude  roles=behaver,ergonomist,mechanic,reviewer`. `clone list` renders
  `🎭 clones`, groups clones under their actor header, and each clone row shows
  `@:<serial>  serial=<full>  state=<LIVE|DEAF|DEAD>  since=<ISO>`, closed by a legend
  `legend: LIVE = say + get · DEAF = get only, cannot hear a say · DEAD = finished/gone`. when any row is
  DEAD, a `tip: reap DEAD clones with \`rhx clone prune [--older-than <dur>]\`` line follows the legend.
- **the three reach-states (say-ability ladder):** `LIVE` = a socket answers, so `say` lands and `get`
  observes. `DEAF` = a socketless clone (a `--no-socket` / non-capable / headless spawn) whose process is
  still ALIVE — it cannot hear a `say` (refused), but `get` still observes its transcript; DEAF is
  TRANSIENT. `DEAD` = finished/gone (a socket clone whose brain exited, OR a socketless clone whose process
  exited) — a fresh `say` cannot land, but `get` reads whatever transcript remains.
- **cite:** `actor.acceptance` case2 (populated-actor format snapshot); `clone.acceptance` case1 t0
  (clone appears LIVE by slug + abbreviated serial), case4 t0 (empty clone-list format);
  `clone.prune.acceptance` case1 t0 (a live `DEAF` + `LIVE` list format locked), t1 (the `DEAF`→`DEAD`
  transition list format).

### 6. dispatch a message into a live clone (say)

- **action:** with a live named clone, run `npx rhx clone say @:driver --what "wrap up and commit"`.
  also pipe a payload: `echo "a longer motive" | npx rhx clone say @:driver --what @stdin`.
- **expected:** the message is delivered to the brain as if typed; the say reports delivered (exit 0).
  the `@stdin` form captures the piped text. a LONG message lands too — the whole message is written in one
  bulk pty write, then a length-scaled submit delay commits it, so a large `say` is fast (not a slow
  char-at-a-time type) yet still PROVEN delivered.
- **note — one known limit:** a message with an embedded newline submits early at the first `\n`, so the CLI
  fails loud on a multi-line `say` and names the newline cause rather than send a truncated first line. use
  a single-line message (or `@stdin` for a payload).
- **cite:** `clone.acceptance` case1 t1 (say → delivered, exit 0), t6 (`--what @stdin` round-trip);
  `clone.saybulk-probe.realbrain.acceptance` (a real brain receives + submits a short AND a ~3728-char
  message — the bulk-write path proven against a live brain).

### 7. observe a clone's output (get — a directioned conversation)

- **action:** run `npx rhx clone get @:driver`, then `npx rhx clone get @:driver --tail 1`, then
  `npx rhx clone get @:driver --tail all`, then `npx rhx clone get @:driver --format raw`.
- **expected:** the DEFAULT render (`--format blocks`) is a directioned conversation — each turn shows a
  `← say` header (an inbound dispatch / human turn) or a `→ reply` header (an outbound clone reply) over its
  body, with a break between turns, so a reader tells the two directions apart. `--format raw` keeps the
  pipe-clean verbatim REPLY stream a comms relay forwards (no headers, no inbound turns). `--tail 1` returns
  a whole reply (never an empty tool-result line); `--tail all` reads unbounded (no fewer messages than
  `--tail 1`).
- **note — get reads HISTORY, not the live socket:** `get` observes the brain-cli's own transcript, so it
  succeeds on ANY clone that has history — LIVE **or** DEAF **or** DEAD (a past session's last reply still
  reads back). this is the deliberate split from `say`, which needs a LIVE socket: `say` to a DEAF or DEAD
  clone fails loud (a DEAF clone: `✋ … cannot hear a say …`), while `get` on that same clone still returns
  its recorded output — DEAF is observe-only, not silent.
- **cite:** `clone.acceptance` case1 t11 (human-tree get carries an ack line — the directioned blocks),
  t7 (`--tail 1` bounded machine shape), t9 (`--tail all` unbounded); `enroll.reach.acceptance` case3 t1
  (`get` still observes a DEAF clone — observe-only); the directioned in/out render is
  `asCloneConversationText` (`--format blocks` default, `--format raw` verbatim).

### 8. the end-to-end reach round-trip (the mandated critipath)

- **action:** `npx rhx enroll claude --as @:pilot`, then `npx rhx clone say @:pilot --what "poke <n>"`,
  then `npx rhx clone get @:pilot`. repeat by `@:<serial>`. then inspect the on-disk actor.
- **expected:** the get reflects the said message landed and was acted on, by BOTH address forms; the
  on-disk actor stays anonymous (`actor.via.hash=…`) while the clone wears the `@:pilot` handle.
- **cite:** `enroll-to-reach.journey.acceptance` case1 t0–t1 (the full journey clamp); `clone.acceptance`
  case1 t0–t2 (the reach round-trip by slug + serial, the two-grain split).

### 9. self-identification from within a clone (whoami)

- **action:** from a shell spawned AS an enrolled clone, run `npx rhx clone whoami` and
  `npx rhx clone whoami --output json`.
- **expected:** whoami returns THIS clone's own serial, slug (if any), and reach-state. the json also
  carries the clone's own `actorHash`, so the clone can pass it to `clone list @<actor>` to enumerate
  its SIBLING clones (the self-management motive).
- **cite:** `clone.acceptance` case1 t3 (whoami names this clone by slug + serial), t5 (whoami json
  carries serial + slug + actorHash).

### 10. machine consumption — `--output json` on every talk verb

- **action:** run each of `npx rhx clone list --output json`, `npx rhx actor list --output json`,
  `npx rhx clone say @:driver --what x --output json`, `npx rhx clone get @:driver --output json`.
- **expected:** each emits machine-parseable JSON (no tree glyphs, no stray lines). the json carries the
  same information the human tree shows, in a stable machine shape.
- **cite:** `clone.acceptance` case1 t7 (say/get json), case4 t0 (empty list json);
  `actor.acceptance` case2 t1 (one-actor json shape), case1 t1 (empty-actors json).

### 11. the headless machine handoff — `enroll --output json`

- **action:** a supervisor spawns `npx rhx enroll claude --as @:worker --output json` non-interactively.
- **expected:** stdout carries a single-line, parseable handoff with the clone's serial + reachability,
  so the supervisor reads the address to `say`/`get` with no second command and no race. (the handoff is
  compact single-line BY DESIGN — enroll keeps the child's stdout stream open, so a supervisor reads the
  handoff off the live stream by a single-line marker.)
- **cite:** `enroll.reach.acceptance` case2 (the machine handoff shape is locked); `clone.acceptance`
  case3 (a second live-slug enroll `--output json` reports `outcome=reused` for the same clone).

### 12. config stays in sync across clones and re-links (init)

- **action:** enroll an actor twice with the same roleset (two clones — exit each brain before the next,
  or a terminal each), then re-run `npx rhx roles link --roles mechanic,architect` (the same link that
  applies hooks/config).
- **expected:** both clones reference the ONE shared `actor.via.hash=<hash>/brain/.claude/settings.json`
  — no per-clone copy. the config applies to the repo root AND every enrolled actor dir, so configs never
  drift.
- **cite:** `init.hooks.acceptance` case7 (the per-actor apply — config reaches each actor dir AND the
  repo root, tree stdout locked, t0). the "same-roleset → same actor dir" half is the `genEnrollmentHash`
  determinism property, clamped at the integration grain (`findsertActorEnrolled` / the hash-content
  invariant), not a distinct blackbox case.

### 13. reap dead clones — the `clone prune` lifecycle (DEAF → DEAD → reaped)

- **action:** enroll a socketed clone to keep (`npx rhx enroll claude --as @:keeper`, leave it live) AND a
  socketless one to reap (`npx rhx enroll claude --as @:goner --no-socket`). while both live, run
  `npx rhx clone list` — the keeper reads `state=LIVE`, the goner `state=DEAF`. now exit the goner's brain
  (Ctrl-D), re-run `npx rhx clone list` — the goner flips to `state=DEAD`. then preview the reap with
  `npx rhx clone prune` (plan is the default — no clone is removed), and commit it with
  `npx rhx clone prune --mode apply`.
- **expected:** the plan lists ONLY the dead goner and names the apply follow-up (`--mode apply`); the LIVE
  keeper is NEVER in the plan, and the DEAF goner (while still alive) is never in the plan either — prune is
  safe-by-default. after `--mode apply` the goner is gone from `clone list` while the keeper survives LIVE.
  a machine reads the same via `--output json` (`{mode, count, clones}`).
- **note — plan is the default (safe):** a bare `npx rhx clone prune` only PREVIEWS; it removes no clone
  until `--mode apply`. `prune` never touches a LIVE or a DEAF (still-active) clone — only finished/gone
  ones.
- **cite:** `clone.prune.acceptance` "reach-state lifecycle" case1 t0 (keeper LIVE + goner DEAF), t1
  (goner DEAF→DEAD on exit), t2 (plan names only the dead goner, never the LIVE keeper), t3 (apply reaps
  the goner, keeper survives LIVE); `clone.prune.acceptance` case1 t0 (plan default previews two DEAD, omits
  the DEAF watcher), case2 t0 (apply reaps DEAD, keeps DEAF).

## edgey paths

### E1. unlinked repo — fail loud with the fix

- **action:** in a repo with NO `.agent/`, run `npx rhx enroll claude --roles mechanic`, then
  `npx rhx clone list`, then `npx rhx actor list`.
- **expected:** enroll fails loud: "no .agent/ found … run `rhachet roles link` first". the list verbs
  do NOT crash — they show the DISTINCT not-linked state + the link fix (never the linked-but-empty enroll
  state).
- **cite:** `enroll.acceptance` case8 (no `.agent/` errors + snapshot); `clone.acceptance` case5 (unlinked
  → not-linked state, distinct from empty); `actor.acceptance` case4 (unlinked, not-linked state).

### E2. linked-but-empty repo — a distinct fail-loud

- **action:** in a linked repo with an empty `.agent/` (no roles), run `npx rhx enroll claude --roles mechanic`.
- **expected:** fails loud: "no roles found in .agent/ … run `rhachet roles link` first" — a message
  distinct from the never-linked one.
- **cite:** `enroll.acceptance` case9 (empty `.agent/` errors that no roles were found).

### E3. bad `--as` — three fail-loud shapes

- **action:** run `npx rhx enroll claude --as @:11111111-1111-1111-1111-111111111111` (a uuid shape),
  then `npx rhx enroll claude --as @:BAD/slug`, then `npx rhx enroll claude --as driver` (no `@:` marker).
- **expected:** each is rejected PRE-SPAWN with the fix named: a uuid-shaped handle "reads as a serial —
  unreachable" (use a non-uuid handle); an unsafe charset names the safe set; a marker-less value gets a
  did-you-mean `--as @:driver`.
- **cite:** `enroll.acceptance` case10 t4 (uuid-shaped `--as` rejected), t4b (unsafe charset), t4c
  (dropped `@:` sigil).

### E4. brain conflict — names both values

- **action:** run `npx rhx enroll claude --brain codex`.
- **expected:** fails loud, shows BOTH brain values in conflict, before any spawn. under `--output json`
  the failure is a parseable structured error (not human prose), non-zero exit.
- **cite:** `enroll.acceptance` case10 t2 (conflict fails loud, both values), t5 (a failed-enroll
  `--output json` → structured error).

### E5. say to a dead clone — never silently drop

- **action:** enroll a clone (note its `@:<serial>`), close the brain's terminal (Ctrl-D) so it exits,
  confirm it reads DEAD via `npx rhx clone list`, then run `npx rhx clone say @:<serial> --what hi`.
- **expected:** the command fails loud and names the reach failure (never drops the message). under
  `--output json` it emits a parseable ConstraintError (no tree glyphs), non-zero exit.
- **cite:** `clone.acceptance` case2 t0 (dead-clone say fails loud + snapshot), t1 (dead-clone say
  `--output json` parseable error).

### E6. get / say to an unknown address — fail loud

- **action:** run `npx rhx clone get @:nonexistent-serial` and `npx rhx clone say @:nope --what hi`.
- **expected (verbatim):** `get` prints `✋ no clone answers to '@:nonexistent-serial'` then
  `└─ list clones with \`rhx clone list\``, exit 2. `say` fails the same way for `@:nope`. never a
  deceptive empty output.
- **cite:** `clone.acceptance` case1 t4 (say to an unknown address, names the fix), t10 (unknown-address
  as machine json).

### E7. whoami outside a clone — fail loud

- **action:** run `npx rhx clone whoami` from a plain shell (NOT inside an enrolled clone).
- **expected (verbatim):** `✋ not run inside an enrolled clone` then
  `└─ whoami works from within a clone spawned by \`rhx enroll\``, exit 2. never a fabricated
  self-identity.
- **cite:** `clone.acceptance` case1 t5b (whoami OUTSIDE a clone fails loud).

### E8. the address-grain slip — recover on the `@:` form

- **action:** try to reach a clone by the ACTOR form `@driver` (wrong grain), then recover with `@:driver`.
- **expected:** the actor form names the fix (use the `@:` clone form); the same message by the `@:` form
  delivers.
- **cite:** `enroll-to-reach.journey.acceptance` case1 t2 (grain error names the fix, then recovery
  delivers).

### E9. concurrent clones of one actor — independent channels

- **action:** enroll the same actor twice (two live clones), address each by its own serial.
- **expected:** each has its own reachable channel and history, no shared-state clobber.
- **cite:** `enroll-to-reach.journey.acceptance` (multi-timestep flow); `clone.acceptance` case1 (per-serial
  reach). the reach-by-serial round-trip proves the per-clone socket.

### E10. the `--no-socket` / non-capable fallback — never hard-fail (DEAF, not dead)

- **action:** run `npx rhx enroll claude --as @:plain --no-socket`, then (terminal B) `npx rhx clone list`,
  `npx rhx clone say @:plain --what hi`, and `npx rhx clone get @:plain`.
- **expected:** the brain still opens normally; while alive the clone appears `state=DEAF` (no socket stood
  up — observe-only). a `say` to it fails loud and names the DEAF cause + fix (`✋ … cannot hear a say …`),
  but a `get` STILL observes its transcript — DEAF is observe-only, not dead. an absent pty addon or a
  non-capable brain degrades to the same plain-spawn, with a one-line notice, never a hard fail. once you
  exit the brain the clone flips DEAF → DEAD (see step 13).
- **cite:** `enroll.reach.acceptance` case3 t0 (`--no-socket` → DEAF, list format + json `reachState=DEAF`
  locked), t1 (`say` to a DEAF clone refused loud with the DEAF cause; `get` still observes it).

### E11. hash-prefix reach on an actor scope

- **action:** first run `npx rhx actor list` and copy an actor's hash. run
  `npx rhx clone list @<first-4-chars>` (a unique prefix). to see the ambiguous case, use a prefix short
  enough to match two actors (e.g. the first 1–2 chars when two hashes share them).
- **expected:** a unique prefix resolves and lists only that actor's clones (git-style short reach). an
  ambiguous prefix fails loud, names the candidate actors, and asks for a longer prefix.
- **cite:** `clone.acceptance` case4 t1 (`clone list @<unknown-actor>` names the fix); the
  `getOneActorEnrolledByRef` unique-prefix + ambiguous classifier (unit-clamped; the blackbox two-actor
  snapshot rides the acceptance backlog — see the blueprint ledger).

### E12. machine-caller advisory mode-gate (get)

- **action:** this needs a clone whose only linked episode is a vanished transcript — a state hard to
  stage byhand, so lean on the cited automated clamp for the mechanism; to reproduce byhand, delete the
  target of a `history/*.jsonl` symlink under the clone dir, then run
  `npx rhx clone get @:<serial> --output json`, then the same as `--output` tree.
- **expected:** under json the fact is a STRUCTURED field (`exidsUnreadable`), no advisory prose on
  stderr; under tree a human DOES get the `⚠` advisory on stderr.
- **cite:** `clone.get-advisory.acceptance` case1 t0 (json → structured field, no stderr prose), t1
  (tree → human `⚠`).

### E14. `--reason` records the audit "why" 🧠

- **action:** run `npx rhx enroll claude --reason "nightly cron refresh"`, then inspect the actor's
  `roles/enrollment.jsonl`. also try `echo "a piped motive" | npx rhx enroll claude --reason @stdin`, and
  a bare `npx rhx enroll claude` with no `--reason`.
- **expected:** the supplied reason is recorded in the audit line (`"reason":"nightly cron refresh"`); the
  `@stdin` form captures the piped, trimmed motive; the bare enroll records `"reason":null` (a truthful
  audit, never a fabricated motive).
- **cite:** `enroll.acceptance` "rhx enroll --reason" case1 (plain reason recorded + full audit-line
  snapshot), case2 (`@stdin` motive), case3 (bare enroll → null).

### E15. `--as` global slug collision — a DIFFERENT actor is refused ⚙️

- **action:** enroll actor A with `--as @:foreman` (default roleset). then, from a DIFFERENT roleset
  (e.g. `-r -driver`), run `npx rhx enroll claude -r -driver --as @:foreman`.
- **expected:** the second actor is refused PRE-SPAWN — the slug is globally claimed:
  `slug "foreman" is already claimed by a different actor`, with the two-way fix. this is distinct from
  the bad-`--as`-shape rejections (E3): here the shape is valid, but the NAME is taken by another actor.
- **cite:** `enroll.acceptance` "rhx enroll --as slug collision" case1 (a different-roleset actor is
  refused, collision error snapshot).

### E16. idempotent live-slug reuse — a cron retry does NOT duplicate 🧠

- **action:** enroll `npx rhx enroll claude --as @:driver` (leave it live). in terminal B, enroll the
  SAME slug again: `npx rhx enroll claude --as @:driver --output json`.
- **expected:** the second enroll REUSES the still-live clone — the json handoff reports
  `"outcome":"reused"` for the SAME serial (no second brain spawned). without `--output json`, a human
  sees `♻ reused the live clone that already answers to @:driver`. this is the create-vs-findsert boundary
  a retrying cron leans on.
- **cite:** `clone.acceptance` case3 t0 (a second live-slug enroll `--output json` → `outcome=reused`, same
  serial, snapshot).

### E17. `get --tail <bad>` — the tail-bound guard ⚙️

- **action:** run `npx rhx clone get @:driver --tail notanumber` (or `--tail -1`).
- **expected:** exits non-zero (a caller fault) and names the valid forms (a positive integer, or `all`).
  the boundary between a valid `--tail N` / `--tail all` and an invalid value is explicit, not a silent
  misread.
- **cite:** `clone.acceptance` case1 t8 (`get --tail <bad>` exits non-zero, names the valid forms, snapshot).

### E18. the empty-but-linked boundary — zero actors, zero clones ⚙️

- **action:** in a freshly linked sandbox (no enroll yet), run `npx rhx actor list` and `npx rhx clone list`.
- **expected:** neither crashes. `actor list` shows an empty state that names the get-started move
  (`rhx enroll`); `clone list` shows an empty clone list. this is the zero-boundary, distinct from the
  unlinked state (E1) — linked but not yet enrolled.
- **cite:** `actor.acceptance` case1 (empty repo names the get-started move + snapshot);
  `clone.acceptance` case4 t0 (empty clone-list format + snapshot).

### E19. `say --what @stdin` with NO pipe — an isTTY hint, never a silent hang ⚙️

- **action:** run `npx rhx clone say @:driver --what @stdin` in an interactive terminal WITHOUT piping
  anything (do not `echo … |` it). the same hazard applies to `enroll --reason @stdin`.
- **expected:** rather than block forever on a stdin that will never close, the command emits a hint that
  stdin is a TTY and shows the piped form (`echo "msg" | … --what @stdin`). a foreman is never left
  staring at a frozen prompt with no clue why.
- **cite:** the isTTY-stdin hint (blueprint ledger — `--what @stdin` / `--reason @stdin` interactive-hang
  guard, integration-backed); the piped-happy-path is `clone.acceptance` case1 t6 (`--what @stdin` with a
  pipe delivers).

### E20. `clone prune --older-than` — the age gate + a bad value fail loud ⚙️

- **action:** run `npx rhx clone prune --older-than 1h` (a fresh dead clone under an hour is held back),
  then run a bad value `npx rhx clone prune --older-than soon`.
- **expected:** the age gate holds back a clone that has been dead LESS than the given duration — a plan
  that names `no dead clones to prune` (a truthful empty, not a silent reap). a bad `--older-than` value
  exits non-zero and names the valid shape: `✋ invalid --older-than "soon"` →
  `use <N><unit> where unit is s|m|h|d, e.g. --older-than 1h`. under `--output json` the failure is a
  parseable ConstraintError (no tree glyphs), non-zero exit.
- **cite:** `clone.prune.acceptance` case3 t0 (a fresh dead clone below the `--older-than 1h` gate → empty
  plan + json count 0), t1 (a bad `--older-than` fails loud, names `s|m|h|d`), t1b (the same as a machine
  `--output json` ConstraintError).

### E21. `clone prune` resilience — a mid-batch failure never fails silent ⚙️

- **action:** this needs a clone whose on-disk `history/` is corrupt (a file where a dir is expected) so its
  reap throws mid-batch — a state hard to stage byhand, so lean on the cited automated clamp; the mechanism
  is that `prune --mode apply` reaps every healthy DEAD clone it can, THEN fails loud for the one it could
  not.
- **expected:** the batch does NOT abort on the first failure — the healthy peers are still reaped — and the
  run exits 1 (a MalfunctionError) naming the count it could not reap + the fix, never a false all-clear.
  under `--output json` it is a parseable `MalfunctionError`.
- **cite:** `clone.prune.acceptance` case4 t0 (a mid-batch reap failure reaps the healthy peer, then fails
  loud + snapshot), case4b t0 (the machine `--output json` MalfunctionError).

### E13. the real-brain integration (credential-gated)

- **action:** with a real authenticated claude on PATH, enroll → `say` a real prompt with a sentinel +
  nonce → `get` the reply.
- **expected:** the say is accepted (exit 0); the real brain's reply carries the sentinel + nonce — the
  socket dispatched a real message to a real brain and the reply read back.
- **cite:** `clone.realbrain.acceptance` case1 t0 (a real prompt dispatched, then observed; the reply
  carries the sentinel + nonce). fail-loud when the credential is absent, never a silent skip.

## vision coverage — behaviors verified by automation only (not byhand-reproducible)

a few vision/criteria behaviors resist a clean byhand walk (they need a race, a peer socket, or a second
host). none is a silent gap — each is clamped by an automated test or is an explicitly-deferred acceptance
snapshot on the blueprint ledger. a foreman confirms these via the cited suite, not by hand:

- **shell-escalation safety (vision edge; criteria uc.10).** a `say` that carries content beyond a plain
  input message must touch ONLY the brain's input channel, never the wider terminal. proven by the
  server-side content gate `isSafeCloneDispatchInput` (allows SGR color for the comms relay, rejects
  cursor/screen CSI + OSC + paste-terminator forgery) — unit-clamped.
- **concurrent single-writer dispatch (vision edge; criteria uc.6).** two senders to one live clone are
  serialized whole, never interleaved into corruption. proven by `genCloneWriteQueue` (single-writer
  serial queue + two-phase ack) — integration-clamped.
- **caller-auth (vision safety premise).** only a same-user caller may reach a clone's socket; a
  cross-user peer is blocked. proven by `isCallerSameUser` (SO_PEERCRED uid) — integration-clamped.
- **mid-run SIGWINCH resize (vision edge).** the brain re-flows on a terminal resize. proven at the
  faked-pty integration grain (`genBrainCliPtyClone` case3, dogfooded); the real-spawn acceptance resize
  is a deferred snapshot (blueprint ledger).
- **cross-host `say`/`get` fail-loud (vision edge).** a clone spawned on host A, reached from host B,
  fails loud rather than trust a foreign pid. proven at the pure-classifier grain
  (`computeCloneUnreachableHint` DEAD-cross-host branch); the reach-invoker acceptance assertion is
  deferred (blueprint ledger).
- **soft accrual WARN (criteria uc.11 add.7).** a bare enroll past a live-clone threshold still succeeds
  and emits a one-line accrual advisory (+ a structured json field). proven by `computeCloneAccrualWarn`
  (unit) + the json-field clamp; the multi-live-socket end-to-end acceptance is deferred (blueprint ledger).
- **SIGKILL-orphan cost field (criteria uc.11 add.4, 2nd scenario).** STAGED + wisher-gated —
  `computeCloneOrphanVerdict` is built + unit-tested but not wired into the list view (needs a `/proc`
  start-time probe + a spawn-path change reserved for the wisher; blueprint ledger row 11). explicitly
  out of v1 byhand scope.
