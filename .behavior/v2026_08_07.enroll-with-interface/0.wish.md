## amendment (2026-08-07) — enroll spawns clones, only; actors are declared only in actors.yml

the wish above (line 120) said `rhx enroll -driver --alias foreman` would **create an actor** called
'foreman' into `actors.yml`. on reflection this conflates two grains. the corrected model:

- **`rhx enroll` is HASH-ONLY — it never involves `actors.yml`, never a slug actor.** it derives an
  **anonymous** actor id from `genEnrollmentHash({brain, roles})` and spawns a live clone under
  `actor.via.hash=$hash`. that is the point of the split: enroll only ever writes the hash namespace.
- **`rhx clone` is the `actors.yml`-aware surface.** the slug namespace (`actor.via.slug=$slug`,
  addressed `@<slug>`) belongs to clone: it discovers a declared `slug:` entry and clones it. an actor
  is declared ONLY in `.agent/repo=.this/actors.yml`; **no cli flag mints an actor** — enroll derives
  its hash actor from the roleset, clone reads its slug actor from the manifest.
- **the clone is named with `--as @:<slug>`** — the one assignment flag on either command. it always
  takes the clone address form (`@:` prefix mandatory). there is no `--slug` flag anywhere.

so the original `--alias foreman → writes an actor to actors.yml` intent is **deferred to the
`rhx clone` / `actors.yml` dream** (`.dream/2026_08_07.clone-actor-from-actors-yml.dream.md`) — that is
where an actor gets declared/authored, addressed `@foreman`. this behavior delivers the frame + the
clone ipc + the reach surface; enroll here just spawns an anonymous clone to reach.

the address notation is now formalized (see
`.agent/repo=.this/role=any/briefs/define.address-sigils.md`):

- `@<slug>` ≡ `actor://<slug>` — an **actor** (the bare, unmarked `@`; distilisys-native)
- `@:<serial>` ≡ `clone://<serial>` — a **clone** (the `:`-marked grain)

the two-namespace point from the wish still holds, now split by **command**: `actor.via.hash=$hash`
(enroll's anonymous domain) vs `actor.via.slug=$slug` (clone's declared domain, from `actors.yml`) — and
the fully-qualified slug rule too (`actor.via.slug=ehmpathy.mechanic` external, `actor.via.slug=.this.redteamer`
native). only the "enroll creates the actor" mechanism is corrected: enroll clones anonymously into the
hash namespace; `rhx clone` reads `actors.yml` for the slug namespace.
