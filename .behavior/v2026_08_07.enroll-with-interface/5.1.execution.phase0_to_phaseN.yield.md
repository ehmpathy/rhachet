### decisions this phase — wet-over-dry
- **`getSocketPeerCred` built FRESH in infra/socket/, daemon NOT repointed.** the keyrack daemon has
  its own `getSocketPeerPid` (pid-only, a same-login-session gate); the clone needs uid too (a
  same-user threat model). a repoint of the daemon onto a widened shared reader would touch its
  live, 64-test suite for no clone benefit — two copies is acceptable wet, DRY earned on a third.
- **the daemon socket cores NOT lifted.** the clone server's needs diverge (write queue, content

  genuinely different servers. the clone server is its own communicator.
- **async write queue (setImmediate per tick).** a synchronous drain empties the queue before depth
  can build, so the depth cap would be dead code (untestable). a per-tick drain lets a synchronous
  burst build real depth, so the cap is meaningful and the .test.ts proves an overflow NACK.
