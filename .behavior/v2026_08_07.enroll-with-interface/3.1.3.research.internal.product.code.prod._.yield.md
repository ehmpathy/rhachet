## 1. enroll CLI entry — **[EXTEND]**

**file:** `src/contract/cli/invokeEnroll.ts`

the brain is a **required positional** today:

> **[1]** (lines 208-209)
> ```
> .command('enroll <brain>')
> .description('enroll a brain CLI with customized roles')
> ```

passthrough args are computed by stripping the brain token **by value match**:

> **[2]** (lines 29-34)
> ```
> // find brain position (should be first non-flag arg)
> const brainIdx = argsAfterEnroll.findIndex((arg) => arg === input.brain);
> if (brainIdx === -1) return argsAfterEnroll;
> // return everything after the brain arg
> return argsAfterEnroll.slice(brainIdx + 1);
> ```

`--roles` is a **required option**, tokenized by a shared parser:

> **[3]** (lines 211-214)
> ```
> .requiredOption(
>   '-r, --roles <spec>',
>   'roles to enroll — a single spec (e.g. mechanic, +architect, -driver). ...',
> )
> ```
> **[4]** (lines 140-144)
> ```
> const tokens = getRoleDeltaTokens({ raw: [rolesSpec] });
> const spec = parseBrainCliEnrollmentSpec({ tokens });
> ```

**verdict [EXTEND].** relation to the wish: usecase.3 widens the brain input to **three forms** (absent
→ default, `--brain <brain>`, positional). so:
- the positional `<brain>` becomes **optional** (`enroll [brain]`) — extends **[1]**.
- a `--brain` option is **added**; a conflict between flag+positional must fail loud (matrix 1).
- `getRawArgsAfterEnroll` must strip the **derived** brain whether it arrived positionally, by flag,
  or was defaulted (absent → strip no token) — extends **[2]**.
- a new `--as @:<slug>` option is **added** next to `--roles`, and must not collide with the delta
  tokenizer **[4]** (usecase.2).

## 3. config gen + `genEnrollmentHash` — **[REUSE]** the hash, **[EXTEND]** the write-path

**file:** `src/domain.operations/enroll/genBrainCliConfigArtifact.ts`

the enrollment identity is already a content hash of `{brain, roles}`:

> **[7]** (lines 71-79)
> ```
> const genEnrollmentHash = (input: {
>   enrollment: BrainCliEnrollmentManifest;
> }): string => {
>   const data = JSON.stringify({
>     brain: input.enrollment.brain,
>     roles: input.enrollment.roles.sort(),
>   });
>   return createHash('sha256').update(data).digest('hex').slice(0, 8);
> };
> ```

the config is written under `.claude/`, keyed by that hash:

> **[8]** (lines 90-95)
> ```
> const settingsDir = path.join(input.repoPath, '.claude');
> const hash = genEnrollmentHash({ enrollment: input.enrollment });
> const settingsPath = path.join(
>   settingsDir,
>   `settings.enroll.${hash}.local.json`,
> );
> ```

**verdict [REUSE] the hash, [EXTEND] the write-path.** this is the single most load-bearing reuse:
`genEnrollmentHash` **is** the anonymous actor identity (matrix 3, usecase.4). same `{brain, roles}` →
same 8-char hash → same `actor.via.hash=$hash/`; a different roleset → a different hash → a distinct
actor — exactly the idempotency the criteria demand, already implemented. **[EXTEND]:** the config now
also lives under (or is referenced from) `actor.via.hash=$hash/brain/.claude/settings.json` as the one
shared config all clones reference (usecase.9), rather than a flat `.claude/settings.enroll.$hash…`.

## 7. brain continuity — `genBrainSeries` + `exid` — **[REUSE]**

**file:** `src/domain.operations/brainContinuation/genBrainSeries.ts`

the series is built **in memory** and carries an `exid` handle — no transcript is persisted here:

> **[13]** (lines 13-29)
> ```
> export const genBrainSeries = async (input: {
>   on: { series: Pick<BrainSeries, 'episodes'> | null };
>   with: { episode: BrainEpisode; exid: string | null };
> }): Promise<BrainSeries> => {
>   const priorEpisodes = input.on.series?.episodes ?? [];
>   const episodes = [...priorEpisodes, input.with.episode];
>   const hash = await computeBrainSeriesHash({ episodes });
>   return new BrainSeries({ hash, exid: input.with.exid, episodes });
> };
> ```
> **[14]** `computeBrainSeriesHash` (lines 15-16)
> ```
> const content = input.episodes.map((e) => e.hash).join('\n');
> return asHashSha256(content);
> ```

**verdict [REUSE].** this confirms the vision's key premise (assumption #3, external topic-2): rhachet
holds the **`exid` handle**, not the transcript. so "revive a serial" = delegate to the brain-cli's
native `--resume <exid>`. the clone's `history/` **symlinks** to the brain-cli's own `<exid>.jsonl`
transcripts (external topic-2 [10], topic-1 transcript-location) — zero-copy, consistent with this
in-memory series model. `exid: string | null` **[13]** matches "a brain that writes no transcript has
an empty history/". the multi-episode `BrainSeries` **[13]** grounds the "exid = latest episode session
id" mapping.

## net — reuse-heavy, one net-new frame

the behavior is **reuse-dominant**: the identity hash **[7]**, the default-brain rule **[12]**, the
`exid`-handle continuity model **[13]**, the `Actor` term **[10]**, and the brain-command seam **[15]**
all pre-exist and align with the wish. the **extensions** are surgical — widen the brain input **[1][2]**,
route the spawn through a pty while retaining the direct spawn as fallback **[5]**, key the config under
the actor dir **[8]**, add clone/exid-record steps to the orchestrator **[9]**, per-brain capability on
the seam **[15]**, per-actor config application **[16]**. the only **net-new** surface is the
`.agent/.actors/` frame + the `Clone` object (item 10) and the `say`/`get` talk verbs. **no pattern is a
full [REPLACE]** — even the direct spawn survives as the fallback path, so no extant behavior regresses.
