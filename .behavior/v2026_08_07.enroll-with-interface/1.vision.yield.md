# 1.vision — enroll with interface

> illustrate the world implied by [`0.wish.md`](./0.wish.md): every `rhx enroll` becomes a
> **managed, addressable actor** — recorded on disk under `.agent/.actors/`, streamed through an
> invisible socket so crons/comms can observe and dispatch into it later.

---

## the outcome world

### day-in-the-life

a human runs the same command they run today:

```bash
rhx enroll claude --roles mechanic
```

no visible change — claude opens, inherits their terminal, they work as usual. **but
invisibly**, rhachet no longer spawns claude directly. it spawns claude *through* a managed
pty it sits in the middle of — which stands up a **socket** for dispatch — and it leaves a durable record:

```
.agent/.actors/
  actor.via.hash=9c1e…/              # what `rhx enroll` writes — ANONYMOUS (hash namespace);
                                     #   hash = genEnrollmentHash({brain, roles}); never consults actors.yml
    brain/
      .claude/
        settings.json                # the actor's config (roles→hooks, auth, claude.md) —
                                     #   ALL clones share it, so they stay in sync long-term
    roles/
      enrollment.yml                 # append-only role history: which roles, when, why
    clones/
      slug=driver -> serial=7f3a…/   # symlink: slug → serial (RefByUnique → RefByPrimary) — fast forward lookup
      serial=7f3a…/                  # a clone — keyed by its serial (RefByPrimary); only the SESSION differs
        identity.json                # { serial, slug } — formalizes the map; the serial→slug reverse lookup
        socket                       # unix domain socket — dispatch INTO the clone (the `say` verb);
                                     #   its liveness IS the clone's liveness (connectable = LIVE, else DEAD)
        history/                     # symlinks to the brain-cli's OWN transcripts —
                                     #   one link per episode: <exid>.jsonl in ~/.claude/projects/<cwd-slug>/
                                     #   (zero-copy; `get` reads these; the exid for wake lives in the link name)
                                     # — no status.json: the socket is the state; a streamed stdout mirror is a future todo
  actor.via.slug=foreman/            # what `rhx clone @foreman` writes — DECLARED in actors.yml (slug namespace)
    …                                #   same shape; the slug namespace is clone's domain, never enroll's
```

**two namespaces identify an actor — split by which command wrote it:**

- `actor.via.hash=$hash/` — **`rhx enroll`'s domain.** every enroll is anonymous: it derives the id
  from `genEnrollmentHash({brain, roles})` and **never consults `actors.yml`**. an ad-hoc roleset is
  all enroll knows — it spawns a clone under a hash actor, full stop.
- `actor.via.slug=$slug/` — **`rhx clone`'s domain.** clone is the **actors.yml-aware** surface: it
  discovers a declared `@<slug>` actor (a `slug:` entry in `.agent/repo=.this/actors.yml`) and spawns
  a clone of it. enroll never produces a slug actor; only clone does.

```bash
rhx enroll claude -r -driver         # anonymous → clone under actor.via.hash=9c1e…   (never actors.yml)
rhx clone  @foreman                  # declared in actors.yml → clone under actor.via.slug=foreman
```

so the whole slug / `actors.yml` surface belongs to **`rhx clone`** (the reach/lifecycle surface,
largely the clone dream); **`rhx enroll` stays hash-only by design** — that split is the point. neither
command *mints* an actor by a flag: enroll derives the hash actor from its roleset, clone reads the slug
actor from the manifest.

`actors.yml` records the declared roleset for a slug as concrete roles (or a base **peer actor**
`@<slug>` with deltas). the repo's default role-set is an **enroll-time** concept — actor scope is
repo-agnostic and cannot reference it — so a `-driver` composed against the repo default is resolved
to concrete roles at persist time (e.g. `foreman: [ehmpathy/mechanic, ehmpathy/architect]`).

a **role-derived** slug (one not given a custom name) is **always fully-qualified** — it mirrors the
`.agent/repo=*/role=*` layout: an external role → `actor.via.slug=ehmpathy.mechanic`, a native
`.this` role → `actor.via.slug=.this.redteamer`. here `.this` is the **native repo**, i.e. the
`.this` of `.agent/repo=.this/` — so `.this.redteamer` is the `redteamer` declared in this repo's
own `.agent/repo=.this/actors.yml`. fully-qualified slugs keep the namespace unambiguous across
suppliers (the same disambiguation the `rhx clone actor://ehmpathy/mechanic` form gives).

later — a **different** process (a cron, a comms webhook, a `rhx` subcommand) — can reach that
same active claude, with no hand on the human's keyboard:

```bash
rhx clone list
# actor.via.hash=9c1e…                                                 # anonymous — enrolled without --as
#   └─ @:7f3a…  brain=claude  roles=mechanic  state=LIVE  since=2m ago   # no slug yet → reach by serial

rhx clone say @:7f3a… --what "wrap up and commit what you have"
rhx clone get @:7f3a… --tail 40

# had the human baked it `--as @:driver`, list + reach would also carry the slug —
# and @:<slug> / @:<serial> both address the SAME clone:
# actor.via.hash=9c1e…
#   └─ @:driver  (serial 7f3a…)  brain=claude  roles=mechanic  state=LIVE
# rhx clone say @:driver --what "…"    # by slug   ┐ same clone
# rhx clone say @:7f3a…  --what "…"    # by serial ┘
```

### before / after

| | before (today) | after (this wish) |
|---|---|---|
| enroll spawns | `spawn(claude, …, { stdio: 'inherit' })` — direct, opaque | spawn **through** a managed pty rhachet owns |
| record of enrollment | none — vanishes on exit | `.agent/.actors/actor.via.hash=$hash/` on disk, uuid'd clones |
| reach an active brain | only the human at the keyboard | any process, via the clone's socket (observe + dispatch) |
| parallel runs | untracked, indistinguishable | each is a `clone` with its own `serial`, history, socket |
| revive / fork a session | not modeled | enabled by this frame; the `rhx clone wake`/`fork` lifecycle is delivered by the clone dream |
| terminal-control risk for crons/comms | full-terminal control (kitty ipc, tmux) | scoped to **one brain-cli** — small blast radius |
| `rhx init` scope | root `.claude/` only | root `.claude/` **and** each `actor=*/brain/.claude/` |

### the "aha" moment

the value clicks when someone wires the **first cron or comms handler**:

> "wait — i don't need a kitty-ipc or tmux-control setup to talk to an active claude. it's
> just a file path with a socket. i `rhx clone say` and it lands. and it can only touch
> *that brain*, not my whole terminal."

the actor frame turns an ephemeral spawn into a **thing with an address** — and an address is what
every downstream usecase (crons, comms, self-management) was missing.

## user experience

### usecases & goals

- **enroll as always** — the human's mental model of `rhx enroll` is unchanged; the socket is
  invisible. (goal: zero added friction on the hot path.)
- **observe a clone** — read what an active brain is doing without stealing its terminal. (crons,
  dashboards, "is it stuck?")
- **dispatch to a clone** — inject a message into an active brain programmatically. (comms: a slack
  reply becomes a message to the clone; crons: "nudge every idle clone at 5pm".)
- **enumerate actors & clones** — discover who is enrolled and which clones are live/dead/revivable.
- **revive / fork** `[clone dream]` — reopen a serial's terminal, or branch a new serial from a root;
  the `rhx clone wake`/`fork` lifecycle is the clone dream's, built on this frame's `exid` record.
- **self-management** — a clone can enumerate and message its sibling clones through the same
  scoped socket, instead of full-terminal control.

### contract inputs & outputs (proposed — testdriven below)

**the (unchanged-looking) enroll surface**

```bash
rhx enroll [<brain> | --brain <brain>] [--roles <spec>] [--as @:<slug>] [passthrough…]
```

- **brain input — three forms, one sense:**
  1. omit it entirely — `rhx enroll` — falls back to the repo's **default brain**
  2. `--brain <brain>` — the explicit flag form (new)
  3. `<brain>` — the positional form (extant, unchanged)

  all three derive the same `{brain}`; the flag and positional are aliases, and the absence of both
  is the default. when both are given, they must agree, else the surface fails loud (a `--brain claude`
  next to a positional `codex` names the conflict, per `rule.require.errors-name-the-fix`).
- **enroll spawns a CLONE under an ANONYMOUS actor, always.** enroll is **hash-only**: it derives the
  actor id from `genEnrollmentHash({brain, roles})` and **never consults `actors.yml`**. it mints no
  slug actor — the slug / `actors.yml` surface belongs to `rhx clone`, not enroll. (a declared `@<slug>`
  actor is reached via `rhx clone @<slug>`, the clone dream's surface.)
  - `--as @:<slug>` (optional) — names *the clone* (the `@:` clone grain, prescribed in address form —
    the mandate, see `define.address-sigils.md`), a stable handle to `say`/`get`/`wake` later. omit it
    and the clone gets a fresh auto-serial. there is **no `--slug` flag** — `--as` names the clone, and
    an actor is never assigned by a flag.
- all else passes through to the brain, exactly as today.
- **effect:** finds (or creates) the anonymous hash actor its `{brain, roles}` derive under
  `.agent/.actors/actor.via.hash=…/` (brain config + roles log), spawns a new `clone` under it with a
  fresh `serial` (or the `--as` handle), and streams the brain through the socket — visibly to the
  human, addressably to machines.

**the actor + clone surface (new)**

this behavior delivers the **reach** surface — the commands that prove the socket that enrollment stands
up. the clone to reach comes from `rhx enroll` (which creates the clone + its socket in this
behavior); these commands observe and dispatch into it:

```bash
rhx actor list                              # actors on disk (the identities)
rhx clone list [@<slug>]                   # clones (all, or scoped to one actor), with state (LIVE|DEAD|…)
rhx clone say @:<slug|serial> --what <m>    # dispatch a message into a live clone
rhx clone get @:<slug|serial> [--tail N]    # observe the clone's recent output
```

**address sigils.** `@<slug>` addresses an actor (shorthand for `actor://<slug>`), `@:<serial>` a
clone (shorthand for `clone://<serial>`). markedness encodes the grain — `@` is the unmarked actor (the
durable recipe), `@:` the marked clone (one of the many an actor spawns) — and the shared `@` root
encodes descent (`@:bob` comes from `@mechanic`). both are shell-safe unquoted (a bare `#` opens
a shell comment, so the clone sigil is `@:`, not `#`). `@<slug>` is character-identical to distilisys's
`@<name>` actor address — a superset, since distilisys has no clone grain. full rationale:
`.agent/repo=.this/role=any/briefs/define.address-sigils.md`.

the `say | get` pair is the whole socket contract at the cli: **say** dispatches into the clone's
input channel, **get** observes its output stream, and **list** finds the serial to address. `get`
(not `read`) is the canonical retrieval verb per `rule.require.get-set-gen-verbs` — `read` is a
forbidden synonym. together they make the socket **end-to-end testable and experienceable**: enroll a
clone, `say` into it, `get` its output — an acceptance test proves the dispatch landed and the stream
reads back.

**out of scope — the clone lifecycle (`make | fork | wake`).** the commands that *create* clones
outside an interactive enroll — `make` a fresh clone from a declared actor, `fork` an extant clone,
`wake` a dead serial — belong to the `rhx clone` dream
(`.dream/2026_08_07.clone-actor-from-actors-yml.dream.md`), where they build on this frame and the
`actors.yml` manifest. they are the actor-declaration/fork lifecycle (open-question #7), a separate
lift; this behavior needs none of them to prove the socket, because `enroll` already creates the clone to
reach. the dream carries the full grammar and its ergonomic surface, all **out of scope here**:

- **`gen <make|fork|wake> <uri> [--as @:<slug>]`** — the canonical create/reopen verb (`gen` implicit).
- **the sigil shorthand** — a bare source URI takes its scheme's default mechanism: a bare
  `rhx clone @<slug>` **makes** a fresh clone of the actor; a bare `rhx clone @:<serial>` **forks** it
  (a new lineage). both **create** by default; `--as @:<slug>` flips either to **findsert** (idempotent
  by the slug). to reopen an extant clone rather than fork it, reach for the explicit **wake** verb —
  `rhx clone wake @:<serial>` — findsert by construction.
- **`+role` / `-role` deltas** — on a `make` they yield a **derived actor**; on a `fork` the new clone
  inherits the source's history, then gains the delta (see the max-boundary critipath, edge-case table).
- **`--say <m>`** — dispatch an initial message on spawn (bake + `say` in one). the `say` verb itself is
  in scope here; the *on-spawn* combination rides with the lifecycle.

outputs follow the extant treestruct stdout style (`rule.require.treestruct-output`) and fail loud
with errors that name the fix (`rule.require.errors-name-the-fix`) — e.g. "no live clone for serial
7f3a…; re-enroll to spawn a fresh clone" (once the clone dream ships, the fix names `rhx clone wake`).

### a timeline

```
t0  human: rhx enroll claude --roles mechanic
      └─ findsert actor.via.hash=9c1e (anonymous; brain/.claude/settings.json, roles/enrollment.jsonl += mechanic)
      └─ spawn clone serial=7f3a through the socket; status=LIVE; human sees claude, works
t1  cron (5pm):  rhx clone list  → sees serial=7f3a LIVE, idle 20m
t2  cron:        rhx clone say clone://7f3a --what "commit WIP before EOD"
      └─ the socket injects the message; claude receives it as if typed; acts
t3  human closes claude → status=DEAD, history/ retained
t4  next day:    rhx clone wake clone://7f3a  [CLONE DREAM] → delegates to the brain-cli's native
                 resume (claude --resume <exid>) keyed by the exid this behavior's frame recorded —
                 rhachet stores no transcript itself, only the exid handle. t0–t3 are THIS behavior
                 (enroll + list + say/get); t4 is the clone dream, unlocked by the exid the frame keeps
```

## mental model

### how a user describes it to a friend

> "rhachet used to just launch claude and forget about it. now every launch is an **actor** with a
> little mailbox on disk. i can list them, read what they're doing, and drop a message in — a cron
> or a slack bot can too — without hijacking my terminal. and if one dies i can revive it."

### analogies / metaphors

- **phone line** (the wish's instinct) — the socket is how you *reach* a clone; you "open a line" and
  "leave a message". strong for comms; risks over-specializing (see fulcrum below).
- **process + pid, but for a brain** — `actor` is the identity, `clone/serial` is a running instance
  with a handle, the socket is its stdin/stdout you can tap.
- **tmux/screen session, scoped** — same "attach to a running thing" power, but limited to one
  brain-cli instead of a whole shell — the safety win the wish calls out.

### their terms vs our terms

| they say | we say | why |
|---|---|---|
| "the claude i launched" | **actor** (identity) + **clone** (live instance) | one identity, many concurrent runs |
| "the session id" | **serial** | a clone's primary ref (`RefByPrimary`); its `--as` slug is a unique ref |
| "its history" | **series → episodes → exchanges** | extant brain-continuity vocab (already in code) |
| "phone / mailbox / socket" | **socket** | the clone's dispatch channel; `say` writes it, its liveness = the clone's |
| "launch it" | **enroll** (unchanged) | the enrollment is what creates the actor/clone |

## evaluation

### how well it solves the goals

- **the frame** (goal 1): `.agent/.actors/{brain,roles,clones}` gives every enrollment a durable,
  addressable identity — the missing substrate for crons/comms/self-management. ✔ directly delivered.
- **the clone socket** (goal 2): streaming through a managed pty yields observe + dispatch with a
  **per-brain** risk surface instead of full-terminal control. ✔ directly delivered, and it is the
  concrete safety improvement over kitty/tmux full-terminal control the wish motivates.

### pros

- **invisible on the hot path** — the human's enroll experience is unchanged; adoption cost ≈ 0.
- **small blast radius** — machine control is scoped to one brain-cli, not the terminal.
- **composable substrate** — the actor frame is reused by *other* todos that need identifiable actors
  (the wish says so explicitly), not just this socket.
- **reuses extant vocab & objects** — `Actor`, `sdk.actors.ts`, `BrainSeries/Episode/Exchange`
  already present; this extends rather than invents.

### cons / costs

- **a pty dependency** — "stream through invisibly" almost certainly needs a pseudo-terminal
  (e.g. `node-pty`), a native module today **absent** from the repo. new build/portability surface.
- **liveness is socket-derived, not tracked** — no LIVE→DEAD state machine, no stale-serial reap: a
  clone's socket IS its liveness (connectable = LIVE, absent/refused = DEAD). findsert the clone dir,
  leave the socket, let a dead socket speak for itself. this **collapses the old lifecycle-tracking
  cost** — an orphan-socket unlink is the only residue (a `list` marks DEAD; a re-enroll may clean up).
- **`.agent/` write volume is small** — a clone is a socket + `history/` symlinks (zero-copy); no stdout
  mirror is persisted (observe reads the brain-cli's own transcript). gitignore the host-scoped socket;
  no prune discipline needed for a streamed log, because there is none. (a streamed mirror is a
  **future todo**, not this behavior.)
- **passthrough fidelity** — the socket wrapper must not corrupt tty behavior (colors, resize, raw-mode
  prompts) the human relies on today.

### the paramount priority — exhaustive critipath coverage

above every feature above, the **single most important deliverable of this behavior is comprehensive,
exhaustive coverage of the critical paths — both happy and edge — proven by real tests, no gaps.** the
behavior earns its keep only if every critipath is covered; a shipped feature with an uncovered path
is a latent defect (behaver `philosophy.verification-strictness` — zero tolerance, no gaps).

**the happy critipaths — each covered end-to-end:**
- enroll → findsert `actor=<slug>/` (brain config + roles log) → spawn a clone through the socket →
  `status=LIVE`, the human sees the brain and works (the invisible hot path, unchanged)
- `rhx clone list` → the live clone appears with its state + serial
- `rhx clone say @:<serial>` → the message lands on the brain's input channel and is processed
- `rhx clone get @:<serial>` → the brain's recent output reads back
- `rhx actor list` → the enrolled actors appear
- **the named-handle reach** — enroll with `--as @:<slug>`, then `say` / `get` the clone by both its
  `@:<slug>` handle and its `@:<serial>`; both address the same clone (the `@:bert` experience, scoped
  to reach — the bake half is enroll's)
- `rhx init` re-link → applies to root AND every `actor=*/brain/.claude/` (no config drift)

**the edge critipaths — the table below enumerates them, each covered:** absent `.agent/`, dead-serial
`say`, concurrent clones of one actor, orphaned sockets, absent pty addon, shell-escalation attempts,
concurrent dispatch, cross-machine checkout, brains without pty/resume support, mid-run resize. none
may be a silent gap — each has a declared, tested behavior.

the acceptance bar: an assertion (and, for user-faced output, a snapshot) on every happy critipath and
every edge critipath. the socket is not "delivered" until `say` + `get` are proven against a **real**
enrolled clone (blackbox acceptance), never a mock.

**mandated worked-example critipaths — exercise AND clamp.** the concrete experiences in
`.agent/repo=.this/role=user/briefs/actors/inventory.of=experience._.md` (and the `@:bert` reach in
`howto.use.clones.md`) are not illustration only — each is a **mandated acceptance-test critipath**: an
acceptance test must exercise it against a real enrolled clone and **clamp** it — a regression test that
goes red the moment the path breaks (`rule.require.clamp-edge-cases`). scope splits by primitive:

- **in this behavior (clamp here):** the reach flow — enroll `--as @:<slug>` → `say @:<slug|serial>` →
  `get @:<slug|serial>`, by both the `--as` slug (a `RefByUnique`) and the serial (a `RefByPrimary`).
  this is the
  [`name the clone on enroll`](../../.agent/repo=.this/role=user/briefs/actors/inventory.of=experience.case=4.named-clone-on-enroll.md)
  inventory case in full: its primitives (enroll `--as`, `say`, `get`) all land here, and it also proves
  the **two-grain split** — the clone earns the `@:` handle while the actor stays `actor.via.hash`
  (assert the on-disk record is a hash actor, never a slug actor). the `@:bert` experience minus the bake
  (enroll does the bake).
- **in the `rhx clone` dream (clamp there):** the **redteam fan-out** — `make` / `fork` with `--say`
  and `+role` deltas, plus inter-clone observation. it needs the lifecycle verbs (out of scope here), so
  it is mandated as the dream's **steel-test critipath** (the max-boundary fan-out) and clamped at its
  build.

as the inventory grows, each experience it records inherits this mandate: added to the inventory ⇒ owed
an acceptance critipath + clamp in whichever behavior owns its primitives.

### edge cases & pit-of-success

| edge case | how the contract keeps users safe |
|---|---|
| enroll with no `.agent/` | keep today's fail-loud: "run `rhachet roles link` first" |
| `say` to a dead serial | error names the fix: "re-enroll to spawn a fresh clone" (never silently drop; `wake` names the fix once the clone dream ships) |
| two clones, same actor, concurrent | distinct serials, distinct sockets — no shared-state clobber |
| socket orphaned after crash | `clone list` marks DEAD via **socket liveness** (a socket that refuses a connection = a dead clone); an orphan-socket unlink happens on next enroll — no pid state to reap |
| pty native module absent / fails to load | fall back to today's plain `stdio: 'inherit'` spawn (no socket) with a loud one-line notice, so enroll never hard-fails on a missing addon |
| a cron/comms handler tries to escalate to shell control | the socket exposes ONLY the brain-cli's message-input + output-stream — it is not a raw tty passthrough. `clone say` lands on the brain's input channel, never arbitrary terminal/escape control. this scoped-to-one-brain contract is the whole safety premise over kitty/tmux full-terminal control |
| two crons dispatch to one clone at once | **single-writer discipline** on the socket (a dispatch queue / lock) serializes writes so interleaved bytes never corrupt the brain's input; reads may be multi-subscriber |
| the repo is checked out on two machines / worktrees | `clones/` is **host-scoped** runtime (sockets, pids) — always gitignored; `status.json` records the host so a cross-machine read fails loud instead of trusting a foreign pid. only the actor identity (`brain/`, `roles/`) is potentially shareable |
| the brain-cli has no pty / resume / dispatch support | the socket is a **per-brain adapter**, not a universal mechanism — a brain without the capability falls back to the plain `stdio: 'inherit'` spawn (no socket), same as the missing-addon case |
| human's terminal resizes mid-run | pty forwards SIGWINCH so the brain re-flows (fidelity requirement) |
| `rhx init` re-link | applies to root **and** every `actor=*/brain/.claude/` so configs never drift |
| serial vs series confusion | keep `serial` = the clone's id; `series` = its continuity — document how they relate |
| add a role (e.g. `achiever`) to an actor | every clone **references** the one shared `actor=$slug/brain/.claude/settings.json` — one source of truth, no per-clone copy. new clones inherit at spawn; live clones inherit on respawn (claude reads `--settings` at launch, so a mid-session hot-reload is not assumed). clones stay in sync by design |
| anonymous enroll — `rhx enroll claude -r -driver` (ad-hoc roleset, not in `actors.yml`) | still works: the actor id **is** the `genEnrollmentHash({brain, roles})`. same roles → same hash → same anonymous actor → clones share config; `-driver` vs `-mechanic` → different hash → different actor → no clobber. a `slug:` entry in `actors.yml` just gives that same identity a friendly `@<slug>` name |
| **clone an actor with a role-delta — `rhx clone actor://builder -driver`** (the max-boundary critipath) | a **derived actor** `actor.via.slug=builder._.delta=$hash`, NOT a frozen snapshot: it references `builder` + stores the `-driver` delta, and its effective config = builder's config with `-driver` applied, re-derived at spawn (via `genBrainCliConfigArtifact`). so it **still inherits builder's updates** — add `achiever` to builder and every derived clone gets `builder.roles + achiever − driver` at next spawn. `$hash = genEnrollmentHash(delta)` is deterministic, so the derived actor is reusable and its clones stay in sync. this is the one identity form carried by **both** slug + hash. the `actor://` *command* is the clone dream; the frame *represents* the derived actor here. see `define.actor-clone-hierarchy.md` → "derived actors" |

## open questions & assumptions

### assumptions made

1. **"managed subshell streamed invisibly" ⇒ a pty in the middle.** to both mirror to the human and
   expose a socket, rhachet must sit between the tty and the brain — a pseudo-terminal is the standard
   mechanism. (external research below.)
2. **the two namespaces split by command.** `rhx enroll` is **hash-only**: any enroll (incl. bare
   `rhx enroll claude`) derives its id via `genEnrollmentHash({brain, roles})` and lands in the **hash**
   namespace `actor.via.hash=$hash/` — it never consults `actors.yml`. the **slug** namespace
   `actor.via.slug=$slug/` is `rhx clone`'s domain: clone reads a declared `slug:` entry from
   `actors.yml`. (supersedes the wish's earlier `.brains/` / `actor=$uuid` drafts.)
3. **`serial=$uuid`** is a clone's stable id. rhachet does **not** persist the transcript — `genBrainSeries`
   builds the series in memory and carries only an `exid` (external session id). so "revive a serial"
   means *delegate to the brain-cli's native resume* (`claude --resume <exid>`) via the `exid` the clone
   recorded; "fork" ≈ start a new serial seeded from a root's `exid`. the `serial` is rhachet's handle;
   the `exid` is the brain-cli's. note a clone's history is a `BrainSeries` of **many** episodes (bridged
   by compaction), each a distinct brain-cli session — so `exid` = the clone's **latest** episode session
   id (the resume target), not one flat id for the whole life.
4. **the socket is per-clone**, not per-actor — because parallel clones each need their own live
   stream/history (the wish states this directly).
5. **the `Actor` filesystem record and the `Actor` sdk object are the same concept** at two grains

## what is awkward?

1. **the pty native dependency vs the repo's bun/tsx dispatch.** the "invisible stream" almost
   certainly needs a native pseudo-terminal module, and this repo goes out of its way to keep the hot
   path fast (`bin.dispatcher.pattern`) and portable (hermetic acceptance harness). a native addon is
   the single biggest friction point — it may fight the bun-compile path. **the load-bearing risk.**
2. **"phone" over-specializes the frame.** the socket serves crons *and* comms *and* self-management; a
   comms-flavored term ("phone") narrows a general capability. the neutral word **socket** was chosen
   for exactly this reason, even though "phone" is the most evocative.
3. **serial ≈ series** — two near-identical words for a clone's id vs its continuity. easy to conflate
   in code and docs; the distinction is real but the collision is a papercut.
4. **two grains of "actor"** — the on-disk identity and the in-memory sdk `Actor` share a name. correct
   (they are the same concept), but readers may expect them to be the same *object*; they are the same
   *concept* at two layers.
5. **invisible-but-recorded is a subtle contract.** the human sees "no change", yet a lot now happens
   on disk (clones, history, sockets). the gap between the visible experience and the on-disk reality
   must be documented, or the `.agent/.actors/` tree will surprise people.
6. **scope tension between "the frame" and "the socket".** the wish asks for both in one behavior. the
   frame alone is clean; the socket alone needs the frame. bundling is correct, but the pty work could
   dominate the budget — hence the "which verbs this round" fulcrum above.

## amendment (2026-08-13) — the reach-state lifecycle sharpened + three ergonomic follow-ons

a dogfood round on the shipped socket surfaced four durable requirements. they refine the reach model
and the talk surface; recorded here so the spec, not a task list, is the authoritative home.

### A. DEAF is transient — a socketless clone flips to DEAD once its process finishes

the shipped tri-state read a socketless clone as **DEAF forever** (reach-state was keyed only on the
spawn-time `socketEligible=false` fact). the wisher corrected this (2026-08-13): *"obviously mute
clones should be marked dead once they're done"*. (the state was also renamed MUTE→DEAF that day —
mute names can't-SPEAK, but a socketless clone still produces output; the true property is
can't-HEAR = DEAF; the wisher: *"and yeah obvi use DEAF"*.) the sharpened model:

| state | means | `say` | `get` |
|-------|-------|-------|-------|
| **LIVE** | socket-eligible AND its socket answers | ✅ lands | ✅ observes |
| **DEAF** | never had a socket AND **its process is still alive** — can't hear you, but active | ❌ refused | ✅ observe-only |
| **DEAD** | **finished / gone** — a socket clone whose socket is gone, OR a socketless clone whose process has **exited** | ❌ refused | ✅ if a transcript remains |

so DEAF now means *"active but cannot hear you"*, and DEAD means *"finished / gone"* for **every**
clone, not only socket clones. reach-state becomes a function of three facts:
`{ socket-eligibility, socket-liveness, process-liveness }`. the process-liveness probe is the recorded
`hostPid` checked on its own host (with a pid-reuse guard via the `/proc` start-time — the same
mechanism `prune` needs, and the ledger-row-11 `/proc` capture is thereby pulled **in scope**). a
cross-host socketless clone whose pid cannot be probed from here reads DEAD conservatively.

### B. `rhx clone prune` — the lifecycle-cleanup surface

crons + headless enrolls accrue socketless clones that pile up. `rhx clone prune [@<actor>]
[--older-than <dur>] [--mode plan|apply] [--output tree|json]` removes the DEAD ones (which now include
finished DEAF clones, per A) — the clone dir, identity, socket file, and the `.slugs`/`.serials`/`.exids`
index entries. **plan-by-default** (safe preview); **never prunes a LIVE clone**; never prunes a
cross-host clone on a host that cannot verify its pid. this is the extant `del*` deferred
cleanup-family (was "the `rhx clone` dream"), now pulled into scope because A gives it a sound
"truly gone" signal.

### C. `rhx clone say` — faster dispatch that still delivers (say-bulk) — RESOLVED (bulk-write WON)

> update 2026-08-13: an earlier draft of this §C (and the blueprint's amendment §C) recorded a
> **negative** result — that a booted claude-cli discards a one-shot burst, so `say` must type one char
> at a time. that conclusion was a **misdiagnosis** and is now **superseded**. see
> `lesson.clone-say-bulk-write-works` (the corrected experiment) and `5.1.execution` §C.

the original worry: a booted claude-cli seemed to **discard a one-shot burst** of pty-injected input, so
a long message (`$(cat task.md)`) would be slow to type char-at-a-time. a corrected live experiment
(real haiku, 2026-08-13) **disproved that worry**: claude ACCEPTS a bulk write of the WHOLE message in
ONE pty write — the earlier "burst rejected" read confused a *content-rejection* with the true cause,
which was the submit `\r` that raced the paste-commit. the shipped design:

- **write the whole message in ONE pty write** (`asCloneDispatchFrame` = the raw content, NO
  bracketed-paste wrapper — claude renders the markers literally), then
- **wait a length-scaled submit delay** (`computeCloneSubmitDelay`: floor 50ms, 0.3ms/char, cap 2000ms —
  a larger paste takes longer to commit), then
- **submit with a separate `\r`** in its own later pty read, so the Enter lands after claude commits the
  paste (never an empty-line submit).

this is ~30x faster for a long `say` and proven against a real haiku (short AND ~3728-char, 4/4
acceptance). the fixed char-at-a-time cadence (`CLONE_TYPE_CHAR_DELAY_MS`) is **retired**. the delivery
invariant still holds: a `say` is PROVEN to leave the input buffer (transcript self-verify), never a
false `delivered`; the wedged-window scale stays correct.

**one known limitation (flagged):** a message with an embedded `\n` submits early at the first newline —
a multi-line `say` needs a per-brain soft-newline translation (a live-probe follow-up), so the CLI fails
loud on a multi-line message and names the newline cause rather than submit a truncated first line.

### D. `rhx clone get` — a directioned, block-separated conversation (better-get)

`get` today drops the inbound half (every `type:'user'` transcript record) and flattens the rest to bare
assistant text with no turn breaks. the requirement: turn the observe stream into a **directioned
message stream** — `CloneMessage { dir: 'in' | 'out'; text }` (in = a say / human turn, out = a clone
reply) — and render it legibly (`← say` / `→ reply` blocks with a break between turns). a machine reads
`dir` as a field; a `--format raw` keeps the verbatim-forwardable path the comms relay needs. full spec:
`dispatch/task.teach-clone-get-directioned-render.md`.

### the coverage bar (unchanged, restated for these four)

each requirement is owed exhaustive critipath coverage — happy AND edge — proven by real tests with
**thorough snapshots**, no gaps (behaver `philosophy.verification-strictness`). the mandated clamps:
the DEAF→DEAD transition (DEAF while alive → DEAD after exit, both snapshotted); a prune plan+apply
round-trip (a finished clone gone from `list`); a real-claude long-message `say` measurably faster than
today; a `get` directioned render (a `← say` block + a `→ reply` block, snapshot paired with a
functional assert).
