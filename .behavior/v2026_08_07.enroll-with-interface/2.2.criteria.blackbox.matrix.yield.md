# 2.2.criteria.blackbox.matrix — enroll with interface

> distills [`2.1.criteria.blackbox.yield.md`](./2.1.criteria.blackbox.yield.md) into coverage matrices.
> one matrix per related usecase set. each table labels **ind** (independent — the inputs/conditions
> that vary) vs **dep** (dependent — the observable outcomes). gaps and decomposition signals are
> flagged inline.

---

## matrix 1 — brain input derivation (usecase.3)

> how the `{brain}` is derived from the three input surfaces, and what a conflict yields.

| ind: positional brain | ind: `--brain` flag | ind: repo default | dep: brain enrolled | dep: error |
|-----------------------|---------------------|-------------------|---------------------|------------|
| absent                | absent              | present           | the default brain   | none       |
| absent                | `<brain>`           | (any)             | `<brain>`           | none       |
| `<brain>`             | absent              | (any)             | `<brain>`           | none       |
| `<brain>`             | `<brain>` (agree)   | (any)             | `<brain>`           | none       |
| `<brainA>`            | `<brainB>` (differ) | (any)             | none                | fail loud — names both values in conflict |
| absent                | absent              | absent            | none                | fail loud — no brain given, no default (⚠ gap-check below) |

- **gap flagged:** the last row (no positional, no flag, no repo default) is not stated explicitly in
  2.1. the vision assumes a repo default always exists (`genActor` "first brain in allowlist"). **owed
  a criterion** — either declare the default is guaranteed, or add a fail-loud for the no-default case.
- ind count = 3 (brain surfaces + default), all one concern (brain derivation) → no decomposition needed.

## matrix 3 — actor identity by roleset (usecase.4)

> enroll is identity-by-roleset. the actor record an enroll lands on is a pure function of {brain, roles}.

| ind: brain | ind: roleset | ind: prior enroll of same {brain,roleset} | dep: actor record | dep: actor kind | dep: config shared |
|------------|--------------|-------------------------------------------|-------------------|-----------------|--------------------|
| B          | R            | none                                      | new actor         | anonymous       | (sole clone)       |
| B          | R            | present                                   | the SAME actor    | anonymous       | yes — shared       |
| B          | R2 (≠ R)     | (any of R)                                | a DISTINCT actor  | anonymous       | no — separate      |
| B          | R (ad-hoc, undeclared) | none                          | new actor         | anonymous       | (sole clone)       |

- every row → **anonymous** actor kind; **no** row yields a named/slug actor. this is the two-namespace
  invariant proven by absence: enroll never produces a slug actor.
- ind count = 3 (brain, roleset, prior-state) → clean; prior-state is the idempotency axis, not a
  separate concern.

## matrix 4 — talk operations by address form and clone state (usecase.5, 6, 7)

> the core reach surface — the central matrix. ind = {operation, address form, clone state}.

| ind: operation | ind: address form | ind: clone state | dep: outcome | dep: error |
|----------------|-------------------|------------------|--------------|------------|
| `clone list`   | (n/a — enumerate) | live             | clone shown with serial, brain, roles, state=LIVE | none |
| `clone list`   | (n/a)             | dead             | clone shown with state=DEAD | none |
| `clone list`   | (n/a — scoped `@<actor>`) | mixed    | only that actor`s clones listed | none |
| `actor list`   | (n/a)             | (any)            | each enrolled actor shown | none |
| `clone say`    | `@:<serial>`      | live             | message delivered + brain acts | none |
| `clone say`    | `@:<slug>`        | live             | message delivered to same clone | none |
| `clone say`    | `@:<serial|slug>` | dead             | — | fail loud — names the fix (re-enroll / wake) |
| `clone say`    | `@:<serial>`      | unknown (no clone)| — | fail loud — names the fix |
| `clone get`    | `@:<serial>`      | live/dead w/ output | recent output returned | none |
| `clone get`    | `@:<serial> --tail N` | has output   | last N lines returned | none |
| `clone get`    | `@:<slug>`        | has output       | same output as by serial | none |
| `clone get`    | `@:<serial>`      | unknown (no clone)| — | fail loud — names the fix |

- **symmetry check — slug ≡ serial:** every `say`/`get` row that works by serial has a slug twin that
  works identically. no gap; the interchangeability is the invariant.
- **symmetry check — dead vs unknown:** both `say`-to-dead and `say`/`get`-to-unknown fail loud and
  name a fix; neither silently drops. no gap.
- ind count = 3, but the three are tightly coupled to one concern (reach). borderline on the
  decomposition threshold (4+ triggers it) → **stays one behavior**; see note below.

## matrix 5 — the reach round-trip by address form (usecase.8)

> the mandated named-handle critipath: enroll `--as` → say → get, proven by both address forms plus the
> two-grain assertion.

| ind: address form used | ind: assertion target | dep: outcome |
|------------------------|-----------------------|--------------|
| `@:<slug>`             | say lands, get reflects it | round-trip succeeds by slug |
| `@:<serial>`           | say lands, get reflects it | round-trip succeeds identically by serial |
| (either)               | on-disk actor kind    | actor is anonymous; clone wears the `@:<slug>` handle |

- this matrix is the **acceptance-critipath clamp** (per `rule.require.clamp-edge-cases`): each row is a
  mandated real-clone test. no gap — it composes matrices 2, 4 into one end-to-end proof.

## matrix 7 — pit-of-success under adverse conditions (usecase.10)

> each edge condition maps to one declared, safe, observable behavior. ind = the adverse condition;
> dep = the safe outcome.

| ind: adverse condition | dep: enroll/talk behavior | dep: safety property held |
|------------------------|---------------------------|---------------------------|
| host cannot route a managed stream | enroll falls back to a direct open, one-line notice, no hard-fail | graceful degradation |
| brain-cli has no observe/dispatch capability | brain opens; list marks it not-reachable-for-talk | per-brain capability, not a universal promise |
| a `say` attempts terminal-control escalation | only the brain`s message-input is affected | scoped-to-one-brain blast radius |
| repo checked out on a second machine/worktree | cross-host `say`/`get` fails loud vs a foreign run | no silent wrong-target |
| two concurrent clones of one actor | each has its own channel + history, no clobber | parallel independence |
| two concurrent `say`s to one clone | messages delivered whole, one-at-a-time | no interleave corruption |
| terminal resized mid-run | brain re-flows to new size, no visible degradation | invisible-stream fidelity |

- **decomposition signal — WATCH:** usecase.10 bundles 7 distinct adverse conditions. they share one
  dependent theme (pit-of-success), so they are NOT 7 independent dimensions of one matrix — each is a
  standalone 1-condition→1-outcome row. this is acceptable as a **catalog**, not an exploded product.
  no decomposition forced, but flagged: if any single condition grows its own sub-dimensions (e.g. the
  fallback gains modes), split it into its own matrix.

## coverage summary

| usecase | matrix | ind dims | gaps flagged |
|---------|--------|----------|--------------|
| 1, 2 (enroll + `--as`) | matrix 2 | 2 | none |
| 3 (brain input) | matrix 1 | 3 | ⚠ no-default fail-loud case owed |
| 4 (actor identity) | matrix 3 | 3 | none |
| 5, 6, 7 (talk: list/say/get) | matrix 4 | 3 | none |
| 8 (reach round-trip) | matrix 5 | 2 | none (clamp critipath) |
| 9 (config sync) | matrix 6 | 2 | none |
| 10 (pit-of-success) | matrix 7 | 1 (catalog) | none — watch-flag on fallback growth |

**decomposition verdict:** no matrix exceeds 3 independent dimensions; none explodes. the behavior`s
scope (frame + talk) holds as one coherent boundary. the **bake** lifecycle was correctly kept out of
scope — to fold it in would have added a 4th dimension (create-vs-fork-vs-wake) to matrix 4 and tripped
the decomposition signal.

**the one owed criterion:** matrix 1`s no-positional/no-flag/no-default row — either guarantee the repo
default brain always exists, or declare a fail-loud. carry this to the blueprint.
