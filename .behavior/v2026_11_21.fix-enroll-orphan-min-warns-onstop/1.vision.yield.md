# 1.vision — a content defect never refuses a clone birth

## .the solution

a boot-time **content check** judges the bytes of a role's own files: its briefs, its skills, its `boot.yml`. today three such checks throw inside the render that `rhx enroll` must finish before a clone exists. after this work, each one **sets the defect aside, renders the rest, and warns**. the warn lands at birth as a 🟡 line, and at the stop through the sweep the budget gate already rides (`roles cost --all --when hook.onStop`).

| check | today | after |
|---|---|---|
| orphan `.md.min` (no `.md` beside it) | `ConstraintError`, enroll exits 2 | orphan skipped (it was never in the plan), 🟡 at birth, stop holds |
| a brief holds the cache-boundary literal | `ConstraintError`, enroll exits 2 | that line rendered defanged, 🟡 at birth, stop holds |
| a role's `boot.yml` will not parse | `ConstraintError`, enroll exits 2 | that role rendered refs-only, 🟡 at birth, stop holds |

### .why it works

- **the orphan refusal protects no content.** `getRoleBriefRefs` builds `refs` from `.md` files alone (`src/domain.operations/role/briefs/getRoleBriefRefs.ts:25-29`). an orphan `.md.min` never reaches the plan. so a boot with the throw removed is byte-identical to a boot after the fix "delete the orphan". the refusal blocks birth and buys naught
- **the boundary guarantee survives.** a defanged line holds zero copies of the literal. so the corpus count check (`asBootCorpusWithCacheBoundary.ts:43-51`) still proves exactly one boundary. the silent mis-split the strict refusal feared cannot occur
- **refs-only keeps every file addressable.** every brief and skill of a role with a broken spec stays listed by path. no curated `say` is inflated to say-all, so the budget cannot blow up (`getOneRoleBootSpecFromRef.ts:14-17` forbids that downgrade, and refs-only respects it)
- **the stop already exists, and it is armed by the same hands.** the sweep is armed by a `.this` budget or a mod (`getAllRepoThisRolesWithHooks.ts:18-35`). the content check rides inside it as a third check, never as a third arm (`rule.forbid.framework-owned-hooks`). the memo fingerprint already hashes every file under each `.this` role dir (`getOneRepoThisBootFingerprint.ts:78-97`), so an orphan edit misses the memo and reruns the sweep
- **the content check walks role dirs, not specs.** the budget check finds specs by `.agent/repo=.this/role=*/boot.yml` (`getOneRepoThisBootFingerprint.ts:18`), so a `.this` role with no `boot.yml` is absent from it. the content check walks every `.agent/repo=.this/role=*` dir, the fingerprint's own reach, so a role with no spec is still checked

```
(clone works; the session stops)

   │  ├─ orphan .md.min  .agent/repo=.this/role=any/briefs/rule.foo.md.min
   │  └─ orphan .md.min  .agent/repo=.this/role=any/briefs/rule.bar.md.min
   │
   └─ fix — a .md.min is derived from its .md
      ├─ restore  put the absent .md back beside it
      └─ delete   remove the orphan .md.min           # exit 2, the stop holds
```

### .the rule that stops the class

a new brief, `.agent/repo=.this/role=any/briefs/rule.forbid.content-checks-that-halt-enroll.md`, states: no boot-time check whose verdict rests on a role's own file content may halt a clone birth. such a check sets the defect aside, renders the rest, and warns at birth and at the stop. it names the seam (content vs identity, below) and the test.

### .the clamp

a blackbox acceptance test over `rhx enroll`, one `given` per content check, each on a fixture repo that holds that defect in a `.this` role:

- `then` enroll exits 0 and `boot.md` exists
- `then` stderr names the defect on a 🟡 line
- `then` `roles cost --all --when hook.onStop` exits 2 and names the defect

a fourth `given` holds a defect in a **linked** role: enroll births; the stop does not hold (not this repo's to fix).

each content check reports a `RoleContentDefect` of one declared `kind` (`orphan-min` · `boundary-literal` · `spec-unparsed`), and the render returns them beside its body, never throws them. the test's fixtures are a record typed `{ [K in RoleContentDefect['kind']]: Fixture }`. a new kind added with no fixture is a type error, so a new content check cannot land unclamped. a check that throws rather than report a kind is the rule's to catch in review.

proof it bites: revert the warn arm of one check → its `given` goes red (exit 2, no `boot.md`); restore → green.

## .the seam — content vs identity

| class | judges | on a defect | checks |
|---|---|---|---|
| **content** | the bytes of a role's own files | set aside, render the rest, warn | orphan `.md.min` · boundary literal · unparseable `boot.yml` |
| **identity** | WHICH clone is born | halt — a render would birth a different actor than asked | role not linked · focus names an absent subject (`assertRoleFocusDeclared`, U1) · stale or native-targeted mod view (F8, F14, F18) |
| **malfunction** | the render itself | halt | `assertBootMdDelivered` · a vanished file mid-read |

the test that sorts a check: *"if the render proceeds, is the clone still the actor the caller asked for?"* yes → content, so it warns. no → identity, so it halts.

## .the outcome world

**before.** a supplier ships a role with two orphan `.md.min` briefs, or a human renames a `.md` and forgets its twin. the next `rhx enroll claude` exits 2. no clone exists, so no clone can delete two files. the human must find the defect, fix it by hand, and retry. every robot in the repo is down until then.

**after.** enroll births the clone. the birth line shows two 🟡 rows. the clone works. at its first stop the sweep holds and names both paths with the fix. the clone deletes them, and the next stop is silent.

**the aha.** the clone that the defect would have refused is the very worker that repairs it.

## .mental model

- to a friend: *"a typo in a brief no longer keeps a robot asleep. it wakes, and it must fix the typo before it can stop."*
- analogy: a car starts with the check-engine light on. it does not refuse the ignition.
- their words vs ours: "broken brief", "leftover min file" ↔ ours: orphan `.md.min`, content defect. the 🟡 line says both: `orphan .md.min` plus the plain fix.

## .evaluation

**goals.** every wish item lands: no refusal (all three content checks), a warn at the stop (third check in the sweep), a rule (the new brief), a clamp (acceptance per check, its fixtures typed exhaustive over the defect kinds).

**pros**
- a clone always boots, so a repo never goes dark on a content typo
- the boot is no worse than after the obvious fix (orphan: identical bytes)
- one sweep, one memo, one hook. no new framework hook

**cons**
- a defect can now live until a stop. a session that never stops never sees the hold; the birth line is its only cue
- refs-only for a broken `boot.yml` changes what a clone reads. it is degraded, not identical
- a linked-role defect never holds the stop. it shows at birth, in the `roles cost --all` roster, and as a JSON warn at the stop that holds naught

**edgecases**
- **unarmed repo** (no `.this` budget, no mod): there is no stop hook, so the 🟡 birth line is the only warn. the content check does not arm the hook itself (fulcrum F6)
- **`roles boot` and `roles cost`**: `genBootPayload` sets a content defect aside the same way, so the sweep can cost a spec that holds one and a hand-run roster marks it 🟡 rather than refuse. `roles boot` keeps its budget halt (`bootRoleResources.ts:80`); it is no clone birth
- **`rhx init`, `rhx upgrade`, declared actors**: each renders boot corpora through `setBrainDirBoot` too (`setRepoActorBrainDir.ts:94`, `syncActiveActorBrainDirs.ts:116`, `setDeclaredActorsOndisk.ts:223`). today an orphan halts them as well, so the remedy path (`rhx upgrade` to a fixed release) is itself refused. the fix lives in `getOneRoleBootContent`, so all of them stop to halt at once, and each prints the same 🟡 receipt
- **memo**: a verdict is clean only with zero specs over budget AND zero owned content defects, and only a clean one is memoized. `MEMO_VERSION` bumps to `v2`, so a clean verdict from before this check cannot mask a defect
- **a defect in a `.this` role and a budget breach together**: the stop prints both readouts and holds once, as the budget and mod readouts already do (`invokeRolesCost.ts:108-114`)

## .open questions & assumptions

- **[wisher] which roles held the two orphans that refused?** no record in this repo names them (`.log`, clone transcripts: 0 hits outside this session). if a linked role, case 2 is the incident and the stop will not hold for it (F2). the rework to hold for linked defects too is one filter
- **[wisher] should a broken `boot.yml` render refs-only, or stay a halt?** (F5) a broken spec has no faithful render, so only the wisher can weigh a degraded clone against no clone
- **[answered] is the 🟡 birth row in scope, beyond "warns at onStop"?** (F3) yes. a set-aside with no notice is a failhide, and at least 53 of 61 org repos arm no stop, so the stop alone would reach few. the row is an actionable receipt, the kind `invokeEnroll.ts:757-761` already prints
- **[answered] do identity checks stay halts?** (F1) yes. the wish's motive is "a clone that cannot be born cannot repair the defect". an identity defect (focus, mod, an unlinked role) is fixed at the call, by its caller, who can always re-run with a fixed focus or roleset. a content defect needs a file edit that the would-be clone is the one to make
- **[answered] does claude code surface a stop hook's exit-0 output?** plain stdout and stderr on exit 0: no. exit 2 blocks the stop and feeds stderr to the model. a JSON reply on exit 0 with `systemMessage` or `additionalContext` surfaces without a hold (https://code.claude.com/docs/en/hooks.md#exit-code-output). so an owned defect holds (exit 2), as budget does. a linked defect, which this repo cannot edit, can warn at the stop through that JSON reply, never a hold. this sharpens F2 and stays inside the wish's "warns"; criteria pins which JSON field reaches the model

## .groundwork

### .external research

- claude code stop hook semantics — https://code.claude.com/docs/en/hooks.md#exit-code-output. checked: exit 2 holds the stop and feeds stderr to the model; plain exit-0 output reaches no one; a JSON exit-0 reply with `systemMessage` / `additionalContext` surfaces and holds naught. the owned hold and the linked warn both rest on this

### .internal research

- refusal sites: `assertZeroOrphanMinifiedBriefs` at `getOneRoleBootContent.ts:107` (enroll's render, via `setBrainDirBoot.ts:42`, called at `invokeEnroll.ts:720`) and at `genBootPayload.ts:234` (`roles boot`, `roles cost`, the sweep's costs). a third caller: `assertRegistryHasNoOrphanBriefs` in `repo introspect` (`invokeRepoIntrospect.ts:94`). that one is a publish-time check, not a boot-time one, and it stays a refusal
- boundary check: `assertRoleBootsFreeOfCacheBoundary.ts:14-29`, called at `asBootCorpusWithCacheBoundary.ts:27`
- spec parse: `parseRoleBootYaml.ts:29` via `getOneRoleBootSpecFromRef.ts:31`
- the precedent: enroll's render (`setBrainDirBoot` → `getOneRoleBootContent`) never calls `assertBootWithinBudget`, so a clone birth never halts on budget; the stop does (`invokeRolesCost.ts:96-135`). `roles boot` (`bootRoleResources.ts:80`) and publish (`assertRegistryWithinBudget.ts:111`) do halt on budget; that halt stays, since neither is a clone birth
- the stop today is blind to an orphan, and the orphan blinds it to budget: the sweep costs each `.this` spec through `genBootPayload` (`getAllRepoBootSpecCosts.ts:73`). the orphan throw there is caught per spec (`:107-118`), printed as an "unreadable" notice to stderr, and the spec is dropped. with naught else over, the stop exits 0, so claude code shows no one the notice. the dropped spec's budget goes unchecked, and the verdict `over: []` is memoized as clean (`genOneRepoThisBootBudgetVerdict.ts:52-53`). after the fix the spec is costed again, and the explicit content check holds the stop
- stop arms and memo: `getAllRepoThisRolesWithHooks.ts`, `genOneRepoThisBootBudgetVerdict.ts`, `getOneRepoThisBootFingerprint.ts:18,78-97`
- stop readout shape to match: `__snapshots__/asBootSweepOverBudgetReadout.test.ts.snap` (`🧢` header, `✋ ConstraintError:` class row, paths as children, a `fix` branch)
- birth receipt placement: a clean render says naught (`invokeEnroll.ts:715-717`); every enroll receipt goes to stderr before the spawn, since stdout is the brain-cli's (`invokeEnroll.ts:757-761`). the 🟡 row is one more such receipt; it prints only when a defect was set aside, so it is actionable, never census noise
- vocab: "orphan .md.min", "set aside", "the sweep", "arm"

## .what is awkward

- the warn reaches a clone only at a stop. that is the right moment for a hold, and a late one for a cue. the birth line closes most of the gap
- "warn" at the stop is a hold (exit 2), as the budget's is. the wish says "warns, never blocks a clone birth"; the hold blocks a stop, not a birth. it reads stronger than "warn"
- refs-only is a judgment call. a broken spec has no faithful render, so any fallback is a guess
