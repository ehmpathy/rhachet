# case=8 — `rhx upgrade` is the remedy, and it renders past the defect

## .narrative

a consumer repo links `rhachet-roles-ehmpathy@1.17.15`, which shipped an orphan `.md.min` in its mechanic role. the supplier publishes `1.17.16` with the `.md` restored. today the consumer's `rhx upgrade` reinstalls, then re-renders every actor's `boot.md` through `setBrainDirBoot`. if the render meets the old orphan first (or any orphan still in the tree), it halts, and the upgrade that would fix it reports failure. after this work the render sets any orphan aside. the upgrade completes and prints the receipt only if a defect remains. on `1.17.16` none remains, so it prints naught, and the next `rhx enroll` births clean.

## .timeline

```
given a consumer repo on rhachet-roles-ehmpathy@1.17.15, whose mechanic role holds an orphan .md.min
  and @1.17.16 restores the absent .md

when [t0] `rhx upgrade` while the tree still holds the orphan (e.g. a stale link)
  then the re-render of each actor's boot.md completes; exit 0
  then stderr shows the 🟡 receipt with the orphan, owner repo=ehmpathy, and its levers

when [t1] `rhx upgrade` lands @1.17.16
  then the re-render meets no defect; no 🟡 receipt; exit 0

when [t2] `rhx enroll claude`
  then exit 0; the clone is born; no 🟡 receipt
```
