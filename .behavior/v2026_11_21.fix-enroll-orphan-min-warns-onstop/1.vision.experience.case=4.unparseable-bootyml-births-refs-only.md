# case=4 — an unparseable boot.yml births the role refs-only

## .narrative

a human edits `.agent/repo=.this/role=user/boot.yml` and leaves a bad indent. today enroll exits 2 on the parse. after this work the render cannot trust the spec, so it renders that role refs-only: its readme said, every brief and skill listed by path. no file is inflated to say-all, so the budget holds. other roles render as their specs say. the 🟡 row names the spec and the parse fault. the stop holds until the spec parses.

## .timeline

```
given `.agent/repo=.this/role=user/boot.yml` fails to parse
  and the sweep is armed

when [t0] `rhx enroll claude`
  then exit 0; the clone is born
  then role=user renders refs-only: every brief and skill as a ref, none said
  then every other role renders per its own spec
  then stderr shows the 🟡 row: `boot.yml will not parse  .agent/repo=.this/role=user/boot.yml` + the parse message

when [t1] the clone's session stops
  then the sweep exits 2 and names the spec, with the parse message as the fix cue
```
