## .deviations from the vision

- `roles boot` (session-boot) skips an orphan but prints no receipt: its payload renderer also feeds every cost sweep, so a receipt there would repeat per spec. an unparseable spec still refuses `roles boot`, since the publish gate reads the same payload (F16)
- each scan sets an identity refusal aside per role (a mod that names a native role); the boot names it, never the stop or the roster (F9)
- a `.this` spec that will not parse arms the stop sweep even in a repo that declares no budget, since its budget is unknown, not absent (F17, reversed); vision row 3 drew such a repo as unarmed
- a linked row names its owner by the path's `repo=<slug>` and the report's `--into <owner>/rhachet-roles-<slug>`, with no `owner:` label; the github org is no fact a link records, so it stays `<owner>` (F26)
- the content hold, like the budget hold, does not read `stop_hook_active`: a clone that will not repair is held on each stop (F25)
