# case=2 — a linked orphan births the clone and names its owner

## .narrative

a supplier publishes `rhachet-roles-ehmpathy` with an orphan `.md.min` in the mechanic role. a consumer upgrades and runs `rhx enroll claude`. today that exits 2 and no robot in the repo can start. after this work the clone is born; the 🟡 row names the orphan and its owner, `repo=ehmpathy`, with the levers this repo holds: upgrade, mod the brief via `.agent/repo=.mods`, or report it upstream. the stop does not hold. the defect is the supplier's, and a hold on every stop for a file this repo does not own would be noise.

## .timeline

```
given a linked role `.agent/repo=ehmpathy/role=mechanic` with an orphan `.md.min`
  and the consumer's sweep is armed

when [t0] `rhx enroll claude`
  then exit 0; the clone is born
  then stderr shows the 🟡 row with the path and `owner: repo=ehmpathy`
  then the row lists the levers, each a command or a path to write:
       ├─ upgrade  `rhx upgrade` (a newer release may hold the .md)
       ├─ mod      add `.agent/repo=.mods/role=mechanic/briefs/<name>.md` (supplies the absent source)
       └─ report   `rhx radio.task.push --via gh.issues --into ehmpathy/rhachet-roles-ehmpathy --title "orphan .md.min: <name>" --description @stdin`

when [t1] the clone's session stops
  then the sweep exits 0; the stop is not held
  then a JSON reply names the linked orphan and its owner, a warn that holds naught

when [t2] a human runs `rhx roles cost --all`
  then the mechanic role's row carries a 🟡 mark; exit 0
```
