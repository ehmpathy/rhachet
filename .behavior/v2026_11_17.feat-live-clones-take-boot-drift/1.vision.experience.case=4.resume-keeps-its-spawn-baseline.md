# case=4 · a resumed session keeps the baseline its first spawn recorded

sharp · critipath. cells: before · any · resumed · any · under/over.

## .narrative

`@:reviewer` was spawned on `sha256=a1`, then died. the boot moved to `sha256=c3`. the enroller resumes
its session (`rhx enroll claude --resume <session>`). the brain cli ignores the `--system-prompt-file`
of a resumed session and sends the system prompt the session first recorded, measured 2026-11-03
(`rhx boot.resume.probe`). so the clone's real baseline is still `a1`, not `c3`.

the spawn ref is why this holds. the resume spawn finds the clone record whose history holds that
session, carries its `boot.spawned.ref` into the new record, and names `--add-dir boots/sha256=a1`,
whose `CLAUDE.md` already holds the drift `a1 → c3`. without the ref, the resume would hash today's
boot as its baseline, compute an empty delta, and the clone would silently miss every edit since it
first spawned.

## .timeline

```
given('[case4] @:reviewer, spawned on sha256=a1, now dead; the actor boot.md now at sha256=c3')
  when('[t0] rhx enroll claude --resume <its session id>')
    then('the new clone record holds boot.spawned.ref = sha256=a1, carried from the prior record')
    then('the argv names --add-dir <actor>/boots/sha256=a1')
  when('[t1] the resumed clone sends its first request')
    then('its memory holds the drift a1 → c3')
  when('[t2] no clone record holds that session (resumed by hand, or pruned)')
    then('the baseline is the current boot and the delta is empty: the drift before the resume is missed, as under #713, never faked')
    then('the enroll tree says so in one branch: "boot drift baseline = the current boot; no clone record holds this session, so edits before the resume are absent — respawn fresh to take the whole boot"')
```
