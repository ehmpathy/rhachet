# case=3 · a clone spawned after the edit starts clean

happy · critipath. cells: clone · after · * · * · * · none · one/shared · loads · *.

## .narrative

the enroller needs a second reviewer after the editor's fix. they bake `@:reviewer2` and say the
first task. it answers with the fixed rule, at once, with no note about drift: there is none. it never
learned an old rule, so it has naught to unlearn. its first reply comes as fast as the reviewers that
came before it, because its boot is the same bytes they share, read from cache. a third reviewer
spawned a minute later is as fast again, and the enroller never thinks about boots at all.

## .timeline

```
given('[case3] the actor boot.md at revision sha256=b2; boots/sha256=a1/ held by an older clone')
  when('[t0] rhx enroll claude --as @:reviewer2 --roles -driver --async')
    then('boots/sha256=b2/boot.md holds the bytes of the actor boot.md')
    then('boots/sha256=b2/CLAUDE.md is empty')
    then('clones/serial=<u>/boot.spawned.ref holds sha256=b2')
    then('the argv carries --add-dir <actor>/boots/sha256=b2 just before --system-prompt-file')
    then('the env carries CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1, and no CLAUDE_CODE_DISABLE_CLAUDE_MDS')
  when('[t1] the clone sends its first request')
    then('the boot mark appears once in the system block and zero times in the messages')
    then('the cache write is a few thousand tokens, not the boot size — the boot reads from cache')
  when('[t2] a second clone spawns on the same revision')
    then('boots/sha256=b2/ is reused as is; no second copy of the boot is written')
```
