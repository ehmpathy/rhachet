# 1.vision.experience.dimensions

the experience space of "a live clone takes boot drift". the actor seat A plus eleven dimensions
D1–D11 (D6 and D7 collapse, below, so nine are walked); the product is walked in
`1.vision.experience.case=_.md`, where each row names the cells it covers.

## .dimensions

| # | dimension | positions |
|---|---|---|
| A | the actor's seat | `clone` (the brain in a live session) · `enroller` (the human or supervisor that spawned it and talks to it) · `editor` (the human who edits a brief and renders) · `inspector` (a process with no clone serial that runs `clone boot drift --of @:<x>` against another clone) · `bystander` (a process with no clone serial that runs the drift command or hook for itself) |
| D1 | when the clone spawned, relative to the edit | `before` · `after` · `legacy` (before this layout: no spawn ref) |
| D2 | what the edit did to the boot | `changed` (a block's text) · `added` · `removed` · `moved` (say ↔ ref) · `outside` (bytes changed outside any `path=` block) · `noop` (render, no byte change) |
| D3 | the clone's lifecycle relative to the render | `live-at-render` · `dead-at-render` · `resumed-after` (a `--resume` once the boot has moved) |
| D4 | how the clone meets its memory next | `compact` (manual, or `/compact` via `clone say`) · `autocompact` · `none-yet` · `n/a` |
| D5 | the drift's size | `none` · `under` the threshold · `over` the threshold · `over-cap` (past the 2000 line carry cap: the drift is a stub with no block) · `n/a` |
| D6 | the actor form | `hash` · `slug` · `derived` · `repo` |
| D7 | the spawn mode | `pty` (interactive / `--async`) · `print` (`-p`, one turn) |
| D8 | multiplicity and time | `one` (one clone on a revision, one render) · `shared` (many clones on one revision) · `stacked` (many renders before one compaction) · `raced` (a render between the spawn's hash and the brain cli's read) |
| D9 | the drift door | `loads` (the add-dir memory is read at compaction) · `fails` (it is not: an undocumented door, or a brain cli that drops the key) |
| D10 | the drift hook | `declared` (a role the clone carries declares it) · `absent` |
| D11 | the drift state on disk | `whole` · `revision-absent` (a `boot.spawned.ref` names a `boots/sha256=<h>/` that is gone) · `unreadable` (a delta or ref the process cannot read) · `revision-stale` (a delta that reads cleanly but was computed against an older current boot) |

## .implications — the axes are not all free

| implication | why |
|---|---|
| D1 `after` ⟹ D5 `none` | a clone spawned on the current boot has no drift |
| D1 `legacy` ⟹ D5 `n/a`, D9 `n/a`, D11 `n/a` | no spawn ref, no add-dir: no drift is computed, loaded, or stored |
| D2 `noop` ⟹ D5 `none` | an unchanged render yields the same hash and an empty delta |
| D2 in-block or `outside` ⟹ D5 ≠ `none` | a byte change always yields a non-empty delta; so D5 `none` occurs only with D2 `noop` or D1 `after` |
| D2 `moved` ≡ `removed` + `added` | the block key carries its tag (`brief.say` vs `brief.ref`) |
| D2 `outside` ⟹ D5 by the residual's size | the residual section counts toward the threshold like any block: a one-line wrapper change sits `under` and loads quietly; a large one sits `over` and nudges |
| D3 `resumed-after` ⟹ D1 `before` | a resume once the boot has moved means the clone first spawned on an older boot |
| D3 `resumed-after` ⟹ D5, D9 `n/a` | a resume records no spawn ref and gets no `--add-dir`: it takes no drift, and is marked `resumed` so every reader says so (the carry-over is the F7 dream) |
| D5 `over-cap` ⟹ D9 `n/a` | the stub carries no block, so a compaction takes naught; respawn is the one cure |
| D3 `dead-at-render`, never resumed ⟹ D4 `n/a` | a dead clone meets no memory |
| D7 `print` ⟹ D4 `n/a` | one turn, no compaction |
| D11 ≠ `whole` ⟹ D9 `n/a` for that clone | a fault surfaces before any load; it is the fault's own experience (cases 21, 28) |
| A `bystander` ⟹ D1–D5 `n/a` | it runs the command for itself and has no spawn to drift from |
| A `inspector` takes the target clone's D1–D5, D8–D11 | `--of @:<x>` reads that clone's coordinates, and shows them |
| A `enroller` takes the target clone's D1–D5, D8–D11 | the enroller acts on one clone it spawned (asks it, compacts it, resumes it), so it meets that clone's coordinates |
| A `editor` reads D2–D5, D8 and D11 | the editor's own edit (D2), which clones are live or dead (D3), when each takes it (D4), the size (D5), the reach (D8), and any revision the render marks `✗` (D11) — never a clone's memory itself |

## .what collapses

- **D6 collapses.** every form has an actor dir with a `boot.md` that the render rewrites in place; the
  mechanism keys on the actor dir and the spawn hash, never the form. a hash actor's role change is a
  NEW actor, not drift (forbidden row)
- **D2 `changed` · `added` · `removed` · `moved` collapse to one experience for the clone.** the delta
  is a pure function of `(spawn boot, current boot)`; the edit kind shapes only the delta's sections.
  `outside` does not collapse: it renders a different section, whose cure is a respawn
- **D4 `compact` · `autocompact` collapse.** the docs say the automatic pass works as `/compact` does

## .the walked product

raw: A (5) × D1 (3) × D2 (6) × D3 (3) × D4 (4) × D5 (4) × D7 (2) × D8 (4) × D9 (2) × D10 (2) × D11 (4),
most of it fixed by the implications above. the clone's seat with D11 `whole`, after the implications
and collapses, splits by D1 (D4 counted as 2: compacts, not yet):

| D1 | the reachable product | cells |
|---|---|---|
| `before` | D2 (2: in-block, outside) × D3 (3) × D4 (2) × D5 (2: under, over) × D8 (4) × D9 (2) × D10 (2) | 384 |
| `after` | D5 `none`; D2 moot; D3 (2: `resumed-after` needs `before`) × D4 (2) × D8 (4) × D9 (2) × D10 (2) | 64 |
| `legacy` | D5, D9, D11 `n/a`; D2 moot; D3 (3) × D4 (2) × D8 (4) × D10 (2) | 48 |

at most 496 cells: an upper bound, since `dead-at-render` with no resume fixes D4 `n/a` and trims
further. D11's three fault positions add one slice (they pre-empt D9; cases 21 and 28), and the other four seats add one
slice each, by the seat implications above. the inventory groups them by the
outcome the actor lives; each row states the cells it covers, so a reader can check that a cell is
covered rather than trust it.
