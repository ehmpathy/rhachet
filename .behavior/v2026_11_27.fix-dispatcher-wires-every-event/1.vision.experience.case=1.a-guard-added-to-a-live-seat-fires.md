# case=1 — a guard added to a live seat fires on its next call

`seat × PreToolUse × C=after × D=named-by-new-row-only` · sharp · critipath

## .narrative

a seat has driven a route for an hour. its settings hold one PreToolUse wire. a role author ships
`pretooluse.forbid-nested-agents.sh`, an `onTool` hook with `filter.what: 'Agent'`. the human runs
`rhx upgrade`; the manifest gains the row.

today the seat's wire reads `Write|Edit|Read|Bash|NotebookEdit|Grep|Glob|EnterPlanMode|WebFetch`.
`Agent` is not in it, so claude never starts the dispatcher on an `Agent` call. the guard sits in
the manifest and never runs. the seat spawns a nested agent; naught stops it. the cure today: a
settings rewrite the file watcher must catch, or a respawn.

after, the wire reads `*`. the seat's next `Agent` call starts the dispatcher, which reads the
manifest as it does on every call, finds the new row, and runs it. the guard refuses the call. no
settings byte moved.

## .[tn] sketch

```
given('a seat whose settings were written with no Agent row in the manifest')
  when('[t0] the settings are read')
    then('PreToolUse holds one dispatcher entry, matcher `*`')
  when('[t1] an Agent row is appended to the manifest, settings untouched, then an Agent payload is dispatched')
    then('the Agent row runs; its block reaches stderr; exit 2')
  when('[t2] the sync runs again')
    then('the settings file is byte-equal to [t0]: same matcher, same timeout')
```
