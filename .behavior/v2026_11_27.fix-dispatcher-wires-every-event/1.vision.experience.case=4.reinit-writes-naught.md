# case=4 — a re-init writes one `*` wire per event, never two, and never moves for a new row

`human × rhx init × E=whole` · happy · critipath

## .narrative

the human runs `rhx init` twice in a row. the second run reports `hooks` with no change, as today:
each wire it would write is already there, the same in command, matcher, and timeout
(`setHookDispatchersViaAdapter.ts:117-121`).

then a role upgrade adds a PreToolUse row for a new tool, and the human runs `rhx init` once more.
the manifest is rewritten. the settings are not: the wire's matcher is `*` and its timeout sits at
the floor, so naught about the wire derives from the new row. the swap report still names the new
rule count per event, so the human sees what landed.

## .[tn] sketch

```
given('a repo synced to the whole shape')
  when('[t0] rhx init runs again')
    then('the settings are byte-equal; each mapped event holds exactly one dispatcher entry')
  when('[t1] the settings are read')
    then('SessionStart, PreToolUse, UserPromptSubmit, Stop: one entry each, matcher `*`')
  when('[t2] a row for a new tool lands in the manifest and rhx init runs')
    then('the manifest gains the row; the settings are byte-equal to [t0]')
    then('the swap report names the new rule count for PreToolUse')
```
