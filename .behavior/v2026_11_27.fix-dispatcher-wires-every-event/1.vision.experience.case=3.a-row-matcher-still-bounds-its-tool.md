# case=3 — a row's own matcher still bounds which tool runs it

`seat × PreToolUse × D ∈ {named, unnamed} × F=some` · happy / sharp · critipath

## .narrative

a human hears the wire is now `*` and worries: will every guard now run on every tool? will a `Read`
pay for the `Bash` permission check, or worse, be refused by it?

they watch a seat work. it reads a file: the `Bash` guard stays quiet, as it always did on a `Read`.
it updates its todo list: naught happens at all — no output, no delay they can feel. then it runs
`rm -rf /tmp/x` in Bash: the `Bash` guard fires and refuses, exactly as before.

each guard still answers only to the tools its own row names. what changed is only that claude now
asks the dispatcher on every tool, so a guard added tomorrow for a new tool is already in reach.

## .the mechanism, for the reader who asks

the dispatcher reads each row's matcher by claude's own grammar (`hooks.dispatch.sh:215-237`) and runs
only the rows that fit. a tool no row names runs naught and exits 0.

the cost of that empty start, measured with `rhx hooks.dispatch.cost --tool Agent --runs 7`: 200 ms
cpu per call against a 90 ms harness floor, so ~110 ms; one bash process, 8 MB rss. a `Bash` call,
which every union already wired, costs ~800 ms. `--what verdicts`: exit 0 both shapes, stdout
byte-equal.

## .[tn] sketch

```
given('a manifest with a Bash row that blocks, and settings with a `*` PreToolUse wire')
  when('[t0] a TodoWrite payload is dispatched')
    then('exit 0; stdout and stderr empty')
  when('[t1] a Read payload is dispatched')
    then('the Bash row does not run; exit 0')
  when('[t2] a Bash payload is dispatched')
    then('the Bash row runs and blocks; exit 2')
```
