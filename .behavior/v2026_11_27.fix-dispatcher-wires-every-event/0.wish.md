# wish: the hook dispatcher wires every claude event whole

## .outcome
at each init and enroll, rhachet writes one dispatcher wire per claude hook event with the matcher `*`, never the union of the matchers its manifest rows hold today. a hook row added to the manifest after a seat starts then fires for any tool, on any event, with no new settings write and no respawn. the manifest stays the one place that decides which hook runs on which tool.

## .why
today a seat's settings carry the union of the row matchers present at its init. a row added later (an Agent guard, a SubagentStop check, a UserPromptSubmit check) for a tool or event absent from that union never fires in a seat already up: the guard runs dark, and the only cure is a hand settings edit or a respawn.

## .done means
- after init or enroll, each claude hook event in the settings holds one dispatcher entry whose matcher is `*`
- a manifest row added after the settings write, for a tool absent before, fires on its next event with no settings write
- the dispatcher still filters by the manifest, so a row's own matcher still bounds which tool runs it
- a re-init is idempotent: one `*` entry per event, never doubled
- a test per case, red without the change, green with it
- a pr opened and green on `--watch`; no merge, no release

## .bounds
- this tree grows beside the open declapract upgrade of ehmpathy/rhachet: it touches only `src/**` and its tests; no package.json, lockfile, config, practs, or `.agent/` edits
- no merge, no `--apply`: the commander reviews the pr


## the shape of the vision and the pr body

this section rides every dispatch; the sprout adds it to the wish.

- the solution is the body. the vision artifact and the pr body lead with what this work builds and why it works
- each ends with a short `## pushback footnote`, placed last: one line per prior decision this work pushes back on
  - the line names the decision, where it was made (a path, a pr, or a brief), and the stat or read that overturns it
  - e.g. `- <the decision> — <where it was made> — overturned by <the stat or read>`
- no prior decision pushed back on → no footnote at all. never an empty section, never a "none" line
- a pushback with no stat or read behind it is no pushback: keep the prior decision, or go get the read

the commander: "the focus should be on the solution" · "the pushback callout should just be a footnote" · "to show proof of thought" · "id rather have the better solution though when its grounded in stats"
