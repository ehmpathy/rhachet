# 1.vision — the hook dispatcher wires every claude event whole

## .what this builds

the settings stop to mirror the manifest. at each init and enroll, rhachet writes exactly one
dispatcher wire per mapped claude event — SessionStart, PreToolUse, UserPromptSubmit, Stop — each
with matcher `*` and a timeout that no row moves. the manifest alone decides which rule runs on
which tool, because the dispatcher already reads it fresh on every call and checks each row's own
matcher (`bin/hooks.dispatch.sh:215-237`).

one transformer changes: `asHookDispatchersOfRules`. today it lists the events the rows hold and
joins their matchers into a union. after, it lists the four mapped events, wires each at `*`, and
sets the timeout to `max(rows' max, 60) + 5`. both writers — the repo sync
(`setHookDispatchersViaAdapter`) and the clone derive (`setActorHookDispatchManifestDerived` →
`asSettingsWithHookDispatchers`) — read it, so both gain the shape.

one guard lands beside it. the wire count now keys on the manifest's presence, not its row count:
the repo sync (`setHookDispatchersForTarget`) reads an absent manifest as zero rules, and zero rules
would now wire four events at a file that does not exist. so the sync wires only where a manifest
exists, as the clone derive already does (case=9).

## .why it works

two halves, each on its own events:

- **the matcher** bites on PreToolUse (tool name) and SessionStart (source). claude ignores a
  matcher on Stop and UserPromptSubmit
- **the presence** bites on every event: a wire is written whether or not a row names the event, so
  an event no row held is no longer absent from the settings (F3)

and four guarantees hold under both:

- **a new row needs no settings write.** matcher `*` and a timeout floor at the live max leave
  naught in the wire derived from the rows, so `isSameBody` holds and the sync writes naught to
  settings (`setHookDispatchersViaAdapter.ts:117-121`)
- **the manifest still bounds each rule.** a `Bash` row never runs on `Read`: the dispatcher skips
  each row whose matcher does not fit
- **an empty start is cheap and silent.** measured, `rhx hooks.dispatch.cost --tool Agent --runs 7`:
  one bash process, 8 MB rss, ~110 ms cpu (200 ms against a 90 ms harness floor). `--what verdicts`:
  exit 0, stdout byte-equal to no hook. a `Bash` call, which the union already wires, costs ~800 ms
- **no rule ever runs twice.** the sync drops every rhachet dispatcher hook before it writes the new
  ones (`isHookReplacedByDispatch`), so a union-shaped entry leaves whole on upgrade

## .the outcome world

**before.** a role ships an `Agent` guard. `rhx upgrade` writes it to each manifest and re-derives
every enrolled actor's settings with `Agent` in the union (`syncHooksForLinkedRoles.ts:326`). a seat
already up sees the guard only if claude re-reads its settings file mid-session; the manifest, by
contrast, is read on every dispatch. where the re-read does not land, the guard runs dark until a
respawn — the gap the wish reports.

**after.** the same upgrade rewrites the manifest and leaves every settings file as it was. each
seat's next `Agent` call starts the dispatcher, which reads the new row and runs it. one file
decides; every seat agrees on the next event.

**the aha.** the settings are wire, not policy. once the wire covers every tool, policy lives in one
place, and a seat cannot be out of date about it.

## .mental model

a friend would say: *"the hook settings just plug every event into the dispatcher; the manifest is
the switchboard."* the analogy is a house wired with an outlet in every room: what you plug in is
your choice later, and no electrician comes back to add an outlet.

| a human says | we say |
|---|---|
| "the hook didn't fire" | the row sat outside the wire's matcher |
| "plug it in" | wire the event |
| "the hook list" | the manifest |

## .evaluation

**goals.** every `.done means` line maps to a case: `*` per event (case=4 [t1]), a later row fires
(case=1, case=2), the manifest still bounds (case=3), idempotent (case=4), red-then-green per case
(each `[tn]` is a test sketch).

**pros.** one transformer changes; both writers inherit it. the defect class closes: no future row,
tool, or roleset narrow can leave a wire short. the settings churn less.

**cons.** each tool call no row names now starts one bash process (~110 ms cpu). each human prompt
starts one on a repo with no `onTalk` rows. a row whose timeout exceeds 60 s still moves the wire.
the ~110 ms is cpu on one box, median of 7; wall time under fleet load, and the share of a seat's
calls that go to a tool no row names, are unmeasured. the verification stone owes both reads.

**edge cases and their pit of success.**
- no manifest → no wire, by an explicit guard; without it, a dispatcher named at an absent manifest
  would fail closed on every call (F4, case=9)
- a manifest with zero rows → four quiet wires; the first row added is live at once (F3)
- a hand-added hook in the old union entry → kept under its own matcher, never folded or dropped
- a corrupt manifest → the dispatcher refuses on every event now, not only on the union's tools;
  louder, and still names `npx rhx init --hooks`

## .groundwork

### external research
- claude hooks reference, https://code.claude.com/docs/en/hooks (read 2026-11-27):
  - `"*"`, `""`, or omitted matcher → fires on every occurrence of the event
  - Stop and UserPromptSubmit have no matcher support; a matcher there is ignored. SubagentStop
    filters on agent type
  - default command-hook timeout: 600 s; 30 s on UserPromptSubmit
  - edits to hooks in settings files are normally picked up by a file watcher — so a settings write
    can reach a live seat, but only the seat whose file was written

## .what is awkward

- a tool call no row names now pays a bash start for naught. small and measured, but it is cost
  spent on the chance a row arrives
- the timeout floor is a number picked from today's max, not from a law. a 90 s rule tomorrow moves
  the wire again
- the floor lifts UserPromptSubmit's wire from 20 s to 65 s. a hung rule is still killed at its own
  timeout by the dispatcher, so a human waits no longer; only a hung dispatcher itself would hold a
  prompt 65 s, not 20 s
- "every event" reads wider than it is: four of claude's events, not all of them. the name of the
  wish and the shape of the fix disagree until a new `BrainHookEvent` lands
