# execution: brain auth context — get-or-unlock creds

## what was built

the brain creds path is now **get-or-unlock**: get each keyrack key; if a key is `locked`,
auto-unlock just that key (narrowly) and re-get. fail only when truly stuck.

## wisher decisions honored (2026-07-05)

- `absent`/`blocked` → `ConstraintError` ✋ (not malfunction)
- `MalfunctionError` 💥 reserved for locked→unlock-failed / no identity
- interactivity → delegated to keyrack's extant unlock (no special policy)
- daemon spawn on cache miss → acceptable

### contested findings (held, with rationale)

- **`process.cwd()` scope leak (r11 #1)** — held. this is the entry-composition tier (like the sdk
  `keyrack.get`); the brain always runs inside the repo. a gitroot injection would be unrequested
  surface. re-open if a non-repo caller appears.
- **`MalfunctionError.wrap` discarded result (r11 #5)** — held. the host-manifest load is a
  side-effect identity check; the re-get reads the authoritative daemon state, so a discard of the
  return is deliberate solve-at-cause, not a hidden failure.
- **`owner: string | null` (r11 #6)** — held. matches the extant keyrack context signatures; the
  brain always passes a string. a narrow to `string` would diverge from the peer ops.
- **getter-mode `BadRequestError` (r11 #7)** — held (out of scope). the getter-mode path is
  pre-change and unrelated to the keyrack contract this behavior shifts.
- **`keys.map(String)` (r11 #8)** — held. `(keyof TKeys)[]` widens to `string[]`; the map is a safe
  identity over strings, no root type gap.
- **no snapshot in `genKeyrackKeySecrets` test (r11 #10)** — held. the return is live credentials;
  a snapshot would commit a secret. the error-shape snapshot lives in the consumer test instead.

## peer-review fixes round 2 (r11 i4 — judge approved, but prose had fresh findings)

- [x] **B1 — getter-mode failhide** (`getSdkCredsFromBrainSupplies.ts`): the getter `try/catch`
      rewrapped *every* error (even an intentional `ConstraintError`/`MalfunctionError` the getter
      threw) as generic `BadRequestError`. now re-throws known `HelpfulError` subclasses as-is and
      only wraps unknown errors — no failhide.
- [x] **B3 — `owner: string` tighten**: the sole caller already guards `!owner`, so the null could
      not reach here in practice and only polluted error metadata. tightened the boundary to
      `owner: string` (leaf ops still accept `string | null`, so the pass-through is safe).
- [x] **N3 — named identity assert**: extracted the throwaway `daoKeyrackHostManifest.get` into
      `assertKeyrackUnlockIdentityAvailable` (a communicator) so the discarded-result intent reads
      as narrative instead of an opaque wrapped get.

### r11 i4 findings held (with rationale)

- **B2 — grain/DI (self-built context)**: held. entry-composition tier (as the sdk `keyrack.get`);
  the brain always runs inside the repo. lift-to-caller is a larger restructure beyond this wish.
- **N1 — "dead" inner status guard**: held. it is the discriminated-union narrow TypeScript
  requires to read `attempt.grant.key.secret`; removal breaks the type-check. not dead code.
- **N2 — `gen` verb**: held. `get` is forbidden here (unlock is a real side-effect); `gen`=findsert
  (get-or-create-granted-state) is the correct verb.
- **N4 — repeated `!` on Map lookup**: held. the maps are built from the same `keys` array, so the
  lookups are safe; a one-file `getOrThrow` helper would be premature abstraction (wet-over-dry).
- **r10 #5 — identity-fail → MalfunctionError untested**: held. a test needs a corrupted host
  manifest / bad prikey (destructive to the host); the path is now a named, isolable communicator.
