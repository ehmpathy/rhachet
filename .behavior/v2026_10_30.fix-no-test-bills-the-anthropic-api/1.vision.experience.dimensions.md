# 1.vision.experience.dimensions

> the experience space of "a caller reaches a brain", factored into orthogonal axes.

## .the dimensions

| dim | axis | positions |
|---|---|---|
| A | **who calls the brain** | `crew-test` (a seat runs `rhx git.repo.test` on a box) · `ci-test` (a github runner, after `keyrack firewall`) · `human-test` (a human runs a suite at a shell) · `seat` (a crew seat's own session, and the claude children it spawns: `rhx review` lanes, peer clones) |
| B | **how the call reaches the brain** | `cli` (spawns claude code: `claude -p`, `rhx enroll`, a `genBrainRepl` via claude-agent-sdk) · `api` (calls `@anthropic-ai/sdk` direct: `genBrainAtom`) |
| C | **which credential the brain would use** | `oauth` (a live `CLAUDE_CODE_OAUTH_TOKEN`) · `oauth-dead` (the token is present but expired or revoked) · `both` (oauth and `ANTHROPIC_API_KEY`) · `key` (only `ANTHROPIC_API_KEY`) · `login` (no env credential; a `/login` in the shared store) · `login-dead` (no env credential; the shared `/login` was cleared by a dead refresh) · `none` (no credential at all) |
| D | **load** | `solo` (one run on the subscription at a time) · `concurrent` (ci shards and crew boxes on one subscription at once) |

## .why these four are orthogonal — and the one place they are not

- **A decides where the env comes from, and whether a jest clamp sees it.** a crew test's env
  comes from `keyrack.source` in jest `globalSetup`, a ci test's from `keyrack firewall --into
  github.actions`, a human test's from the shell. all three run under jest, so the globalSetup
  clamp reaches them. a seat's env also comes from the shell, but a seat runs under no jest: no
  clamp reaches it. that is what parts `human-test` from `seat`
- **B decides which credentials can work at all.** claude code takes any of them, and ranks the
  api key above the oauth token and `/login` (`-p` always uses the key when present). the api sdk
  takes only an api key
- **C is the state the cure changes.** `oauth` and `oauth-dead` are split because a present token
  is not a live one; `login` and `none` are split because a seat's `/login` sits outside the env
  and authenticates, where `none` authenticates naught; `login-dead` is split from `none` because
  enroll refuses it with its own hint, which must not steer to the api key either
- **D decides whether the subscription's rate limit is in play.** ci runs integration and
  acceptance shards at once, and crews run beside them, all on one plan

🟡 **B and C correlate on purpose:** B=`api` admits only C ∈ {`key`, `both`}. an api sdk call
with C ∈ {`oauth`, `oauth-dead`, `login`, `login-dead`, `none`} cannot authenticate. those cells are verdicted
`impossible`, not left out.

## .tier — a sub-axis of one path only

tier (unit · integration · acceptance) changes one experience: WHERE an absent token stops the run.
integration sources keys in `strict` mode and stops at globalSetup (`sourceAllKeysIntoEnv.ts:174`);
acceptance sources in `lenient` mode (`jest.acceptance.globalSetup.ts:32`) and stops before the first
spawn. every other cell is the same on both tiers, and a unit test reaches no brain
(`rule.forbid.unit.remote-boundaries`). so tier is walked inside the absent-token cells 8–9, not
as a fifth axis.

## .the walked product

4 × 2 × 6 × 2 = 96 cells. the fold:
- B=`api` × C is the same for every A and D → one row per C group
- D matters wherever the subscription carries the call: B=`cli` × C ∈ {`oauth`, `login`}, for
  every A. crew-test and ci-test get their own rows (4, 4b: the load is theirs); human-test and
  seat share one row (4c: they meet the same refusal, made by the ci load)
- everywhere else D=`concurrent` behaves as `solo`, for one of two reasons: the call is not on
  the subscription (B=`api`; C ∈ {`key`, `both`} bills the api, which the clamp or the notice
  covers at any load), or no call is made (C ∈ {`none`, `oauth-dead`} is refused before or at the
  first request, at any load)

every cell is verdicted in `1.vision.experience.case=_.md`.
