# 1.vision — no fleet test or seat bills the anthropic api

> 🟡 **superseded in part by the commander's rescope (S5, 2026-10-31).** the rows on `CLAUDE_CODE_OAUTH_TOKEN`, the jest `globalSetup` clamp, the pre-spawn token check, the one org secret, and the five repos beyond rhachet no longer govern. what governs: rhachet only, on the api key, in three live-brain tiers — see `5.1.execution.from_vision.yield.md`. the enroll api-billed notice (case=5 [t1]), the repl bound and the seat hints still hold.

## .the outcome world

### before
every crew and ci test run sources `ANTHROPIC_API_KEY` into its env (`keyrack.source` in jest
`globalSetup`; `keyrack firewall --into github.actions` on ci). every suite that reaches a brain
spawns claude code — `claude -p`, `rhx enroll`, or `genBrainRepl` via claude-agent-sdk. claude code
ranks the api key ABOVE `CLAUDE_CODE_OAUTH_TOKEN` and the `/login` subscription, and in `-p` mode
uses the key whenever present. so each run bills the api. the only visible sign is a banner no one
reads: on #649's ci screen the clone shows `Haiku 4.5 · API Usage Billing`, then
`Credit balance too low · Add funds` (run 40993392834, acceptance shard 1/5). how much of the $100
went to tests, seats, or else is the measurement's job, not this vision's claim. the integration
repl suites on the same run fail with a bare `Exceeded timeout of 180000 ms` and no credit text in
the log (27 such rows, shards 1–3): the repl path hides whatever error it met behind a hang. that
the cause is the same credit error is inferred, not read; execution runs one repl suite on the
oauth token to prove it.

### after
the test env holds `CLAUDE_CODE_OAUTH_TOKEN` and no `ANTHROPIC_API_KEY`. claude code bills the
subscription. a key that creeps back into a test env stops the run before the first spawn, with a
ConstraintError that names it. an absent oauth token fails in seconds with the fill command,
never a 180s timeout. ci needs one org secret, set once a year.

### the aha
the hypothesis holds, and it is sharper than "the key is in the env": **the oauth token alone
would fix none of it.** claude code takes the api key first. the cure is the key's ABSENCE, so the
clamp asserts absence, not presence.

### a day in the life
a seat runs `rhx git.repo.test --what integration --scope actorAsk --mode apply`. green. the api
console shows no request. a week later a reviewer re-adds the key to a manifest "to fix auth";
the next run fails at globalSetup with the key named, and the pr never merges.

## .the exception — tests that keep the key

a suite whose SUBJECT is a direct-sdk atom (`genBrainAtom`, `new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY })`)
cannot run on an oauth token: the api sdk takes only an api key. it keeps the key, named with this
proof, and stays red until the api is funded (fulcrum F2). it sources the key inside the suite,
never in globalSetup, and spawns no claude — so the globalSetup clamp stays whole, and no env that
spawns claude ever holds the key (inventory cells 15–16). in rhachet there are none. six
integration suites import `genBrainRepl` (claude-agent-sdk): `actorAct`, `actorAsk`, `invokeAct`,
`genActor.brain.{casePublished,caseCollocated,caseAskable}`. `genContextBrain.integration` lists
`getBrainAtomsByAnthropic()` in a registry but calls only mocked brains. the acceptance suites
reach claude through a cli spawn. the members across the fleet are listed in execution.

## .mental model

- a human says: *"tests were on the company card instead of the subscription. now they use the
  subscription, and they refuse to start if the card is in the wallet."*
- the analogy: two payment cards; the terminal always picks the card over the membership. you do
  not add a membership card — you take the card out of the wallet
- our terms: api key, oauth token, precedence, clamp. their terms: card, subscription, "why does
  it charge the card"

## .evaluation

| goal | how |
|---|---|
| no test bills the api | key leaves env.test; the globalSetup clamp refuses it wherever it came from |
| tests that need claude code still run real claude code | yes — the same spawns, a different credential |
| the human act is one command | one org secret (`gh secret set --org ehmpathy`) |

- pros: a cure at source (the manifest), a clamp at the moment of harm, no prod behavior change
- cons: the subscription now carries ci load — rate limits are a new failure mode; an atom suite stays red
- edge cases
  - a human shell exports the key → `process.env` holds it at globalSetup, so the clamp names it and the hint says `unset ANTHROPIC_API_KEY`
  - a repo whose suites spawn no claude (to read per repo in execution) → the key leaves env.test, and no oauth token is declared there
  - the oauth token expires (one year) → integration's strict `keyrack.source` fails fast with the fill command; acceptance's lenient source does not, so its suites check the token before the spawn
  - `--bare` claude does not read `CLAUDE_CODE_OAUTH_TOKEN` → the spawns pass no `--bare` today (`asBrainCliSpawnEnv.ts:35` names why); a spawn that adds it would lose the token, so the oauth journey run in execution is what would catch it
