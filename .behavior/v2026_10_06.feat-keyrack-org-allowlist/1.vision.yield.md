# 1.vision — a keyrack manifest declares an org allowlist

## .the outcome world

### before

a repo whose fleet spans two orgs reads one of them and goes dark on the other:

```
rhx git.grove.wake grove-aether-v20260921
  🔐 ahbode.camp.AWS_PROFILE  ·  status: absent 🫧

rhx keyrack get --owner ehmpath --org aether --env camp --key AWS_PROFILE
  ✋ ConstraintError: --org 'aether' does not match manifest org 'ahbode'
```

the credential sits in the rack under `aether.camp.AWS_PROFILE` the whole time. each lever left — swap `org:`, `set` a copy under the wrong org, refile under `@all` — puts a second org into a slot built for one (wish §why the three workarounds).

🟡 **one door does exist today, and it is the wrong shape.** `get --org @all --key aether.camp.AWS_PROFILE` bypasses the manifest gate on purpose — the documented cross-org read (`getOneKeyrackGrantByKey.ts:53-66`). but it is half a door, and an unguarded one:

- **read-only.** with a manifest loaded, `unlock` builds every repo slug from the one `org` and then filters (`getAllKeyrackSlugsForUnlock.ts:160-195`): `--org @all` keeps machine-wide slugs only, `--org aether` misses. so from this repo an aether key can be read only if another repo already unlocked it
- **no wall.** `@all` waives the gate for every org, so a typo or a foreign org reads through as readily as a member
- **not on the route.** the grove skills ask with a bare key; a switch to full slugs under `@all` would make each skill spell the org twice and skip the firewall to do it

⇒ the allowlist is not the first door; it is the first door with a wall around it and a lock a member can turn.

### after

```yaml
# .agent/keyrack.yml
org:
  - ahbode      # the default — what @this and a bare read mean
  - aether      # a member; reachable with --org aether
```

```sh
rhx keyrack get --owner ehmpath --env camp --key AWS_PROFILE --value
# → ahbode.camp.AWS_PROFILE — as before, byte for byte

rhx keyrack get --owner ehmpath --org "$GROVE_ORG" --env camp --key AWS_PROFILE --value
# GROVE_ORG=aether → aether.camp.AWS_PROFILE
```

### a day in the life

at dawn a human runs `rhx keyrack unlock --owner ehmpath --env camp` exactly as yesterday: one org, the default, no new prompt. later a cron runs `rhx git.grove.wake grove-aether-…`; the grove record carries `org: aether`, the skill passes `--org "$GROVE_ORG"`, and the aether box wakes with aether's profile. a typo in a third record — `--org aethr` — fails loud at exit 2 and the message lists the two members, so the fix is one glance away.

### the aha

the manifest already was the place a repo says *"these credentials are mine to read"*. the allowlist lets it say that about two orgs without a lie about either — `org[0]` keeps every extant read where it was, and the second seat is opened only by name.

## .mental model

**to a friend:** *"the keyrack file used to name the one org whose secrets this repo may touch. now it can name a guest list. the first name is the host — that's who you get unless you ask. ask for anyone else on the list and you get them; ask for someone not on it and the door says no and reads you the list."*

| the human says | we say |
|---|---|
| "which org does this repo use" | `org[0]`, the default |
| "can this repo also see aether" | is `aether` a member of the allowlist |
| "switch to aether for this read" | `--org aether`, a selector on a keyed verb |
| "the guest list" | the org allowlist |

🟡 the term `allowlist` is the wish's own; the yaml key stays `org:` (singular) so a one-org file reads exactly as it did.

## .evaluation

### against the goals

| goal (wish) | met by |
|---|---|
| scalar or sequence parse | case=1, case=6 |
| `@this` and a bare read = `org[0]`, every extant call unchanged | case=1, F4 |
| `--org <member>` permitted | case=2, case=3, case=4 |
| non-member refused, message names the allowlist | case=5, F5 |
| extends decision | case=7, F1 — decided against the union, for the wisher |
| the grove consumer unblocked | case=2 — one flag, no raw `aws --profile` |

### pros

- additive: a scalar manifest and every bare call that succeeds today succeed byte-for-byte as today; only the non-member refusal text moves (F5, a con below)
- one door, named: a second org is opened only where a caller writes its name
- the refusal teaches the door (*add it to `org:`*) rather than the swap that silently repoints six slugs
- no new identity scheme: aws.params identity is already keyed by the slug org (`asKeyrackAwsParamIdentity.ts`), so a member composes with no change

### cons

- `--org` on a sweep gains a third sense (re-slug under a member, F2) beside "filter" and `@all`
- the manifest's yaml shape and the domain object differ on purpose (F4), a seam a reader must learn
- the extant refusal snapshot changes for scalar repos too (F5)

### edgecases held in the pit of success

| edge | the contract |
|---|---|
| empty list, duplicate member, `@this`/`@all` as a member | refused at parse, before any vault or prompt (case=6) |
| a full slug of a non-member (`aethr.camp.X`) | the same refusal as the flag, `givenBy: slug` (case=5) |
| a member asked on a verb that takes no `--org` (`fill`, `relock`, `firewall`) | unchanged: `fill` refuses `--org`; a member is filed via `set --org` (F3) |
| an extended role manifest whose `org:` differs | ignored as today; its keys are reachable under every root member (case=7) |
| `is-optional-if-has` / `reaches` on a member sweep | specs carry across the re-slug, so a member sweep honors them (case=4) |
| `--org ""` — a grove record with a blank org field | ⚠️ keyrack reads an empty flag as omitted (`asKeyrackSelectorOrg`: `if (!input.org)`), so it reads `org[0]` with no error — the wish's own silent wrong-org. this behavior leaves the cast as is (an empty flag is an extant, shared meaning); the grove pass-through owes a refusal of a blank record org before it calls keyrack. named in assumptions so the consumer half inherits it |

### the questions only the wisher can close

- **[wisher] the extant `@all` door.** the wish reads *"a wall with no legal door"*; the `@all` full-slug read is a door, read-only and unguarded (see §before). the vision assumes the wisher weighed it and wants a guarded door instead — one line of confirmation, since it is the cheapest alternative a reviewer will raise
- **[wisher] a member sweep over keys the member does not hold.** the wish itself measures that 3 of `dev-env-setup`'s 6 declared slugs exist in both orgs — so the other 3 do not exist under `aether`. a member sweep re-slugs every declared name (F2), so `unlock --org aether --env camp` would report those 3 absent. best guess: report them, as any absent key is reported today — the truth, and the sweep's extant rule. the alternative (sweep only what the member holds) hides a gap. the grove consumer needs only the keyed read and keyed unlock, which this question does not touch

### the questions answered here, not left open

- **[answered] should keyrack refuse `--org ""`?** no. an empty flag means omitted on every verb (`asKeyrackSelectorOrg`, `asKeyrackFilterOrg`: `if (!input.org)`); to change it here reshapes a shared contract for one consumer. the grove half refuses a blank record org itself (assumptions)
- **[answered] an explicit `default:` key instead of position?** no. the wish asks for the bare list, and a `default:` key would state one fact in two places. the position hazard is named in §awkward and clamped by case=3
- **[answered] does a member need an aws.params change?** no. the identity is keyed by the slug org (`asKeyrackAwsParamIdentity.ts:33-44`)

### assumptions

- every member of the allowlist is declared in the same repo file; no per-env allowlist (`env.prep` may not narrow it)
- the order of the list is significant only at position 0
- `keyrack init --org x` (`invokeKeyrack.ts:169`) still creates a scalar manifest; a second member is added by an edit of the yaml. a multi-org `init` was not asked for, and the file is the one place the list is declared
- the grove record's org field and the `git.grove.*` pass-through ship in their own repo; this behavior delivers only the keyrack half. that half must refuse a blank record org itself, since `--org ""` reads as omitted
- **one declared key set serves every member.** `env.camp` lists key NAMES once; a member read or sweep re-slugs those names under the member (case=4). so a key only aether holds must be declared in the shared section, and then the default org's sweep asks for it too. the wish's read — the same `AWS_PROFILE` name in both orgs — fits; a member sweep over a key the member lacks is an open **[wisher]** question above, and the wish's own repo already holds such keys. not asked for, so no per-key org pin (out of scope, case=_)
- the #518 silence (`absent 🫧` on a wrong-org read) stays out of scope (wish §the boundary); with the allowlist, a member read no longer hits it, and a non-member read already refuses loud

### external research owed

**[research]** none — the wish touches no external api or service (see groundwork). the research stone owes only internal reads the blueprint will need: the order in which `getAllKeyrackSlugsForUnlock` filters and guards (case=4 `[t4]`), and each `.org` read site's exact line at that time.

## .groundwork

### external research

none — no external dependencies. the change is internal to keyrack's manifest parse and org guards.

### internal research

**the refusal, single-owned** — `src/domain.operations/keyrack/asKeyrackOrgMismatchRefusal.ts`: render `--org 'x' does not match manifest org 'y'` (or `slug org`), `code: 'ORG_MISMATCH'`, hint `use an org under 'y', or pass --org @all`. snapshot: `blackbox/cli/keyrack.org-mismatch.acceptance.test.ts` cases 1–3.

**the four guards that compare against one org** — each becomes `orgs.includes(x)`:

| site | today |

**org comparisons that are NOT manifest reads** — checked so they are not mistaken for sites to move:

**extends** — `hydrate/hydrateKeyrackRepoManifest.ts`: extended keys merge last-wins (:351), `asKeysWithOrg` re-slugs them to the root org (:361), root keys win; the doc reads *"org is taken from root manifest only"*. brief `define.root-org-inheritance.md` names the boundary (*"org1 keys never leak to org2"*). → F1.

**sweeps and specs** — `getAllKeyrackSlugsForEnv.ts` enumerates `manifest.keys`, all under one org. `decideIsKeyStrictlyRequired.ts:33` reads `manifest.keys[attempt.slug]` by full slug, so a member sweep must carry the specs across the re-slug or lose `is-optional-if-has` / `reaches`. → case=4.

**aws.params identity** — `asKeyrackAwsParamIdentity.ts`, `getOneKeyrackAwsParamIdentity.ts`: the profile is looked up by `${slugOrg}.${env}.AWS_PROFILE` in the host manifest, so a member composes with no change. brief `rule.require.org-scope-grain-hardcut.md` holds: a member is a tree-grain org, never the grove.

## .what is awkward

- **`--org` has three senses.** keyed: pick the slug's org. sweep: filter, or — for a non-default member — re-slug (F2). `@all`: the grove. each is defensible; together they are a lot for one flag. the refusal and `--help` must carry the distinction.
- **position is semantics.** `org[0]` is the default by place, not by label. a reorder of the list silently repoints every bare read — the very hazard the wish names for a swap of `org:`. a `default:` key would be explicit, but the wish asks for the bare list; held as-is, and the manifest doc must say *"the first is the default"* loudly.
- **the yaml and the object differ.** `org:` in the file, `org` + `orgs` in memory (F4). honest about two facts, but a reader who greps `org` sees both.
- **one key list, many orgs.** the allowlist widens the org axis and leaves the key axis single: every member answers to the same declared names. right for the wish's fleet, and a seam the first disjoint-keyed fleet will find.
- **specs are keyed by full slug.** a member sweep must rebuild the slug→spec map under the member, a seam that exists only because the map was built for one org.
- **the snapshot moves for every repo.** a scalar repo's refusal reads differently after this ships (F5); right for consistency, uncomfortable for a change billed as additive.
- **extends against the wish.** F1 refuses the union the wish leans toward. grounded in an extant security boundary, but it is the call most likely to come back.
