# case=5 — a nonmember org is refused, and the refusal names the list 🔴 criti

**cell** — B=`nonmember` × D=`keyed.read`, `keyed.mutate`, `sweep` · C=`flag`, `slug` · A=`scalar` × `member`

## .narrative

a typo: `--org aethr`. the gate refuses, as it does today — but the refusal now names the whole
list, and the fix, so the human does not go and flip `org:` to make the error stop:

```
✋ ConstraintError: --org 'aethr' is not on this manifest's org allowlist

   ├─ orgGiven: aethr
   ├─ orgsOfManifest: ahbode, aether
   └─ hint: use one of 'ahbode', 'aether'; or add 'aethr' to org: in .agent/keyrack.yml; or, for a key that belongs to no org, pass --org @all
```

in a repo still on `org: ahbode` (scalar), `--org aether` gets the same render with a one-member
list. the hint now teaches the door — append a seat — instead of the trap (swap the one seat).

the order is deliberate: the members come first, so a typo (`aethr`) meets its correct spell
(`aether`) before the line that would widen the list. and `@all` is qualified, not offered bare —
the wish names a refile under `@all` as a defect for an org-owned key (an aws profile belongs to
exactly one org), so a bare `or pass --org @all` would teach that defect. see F7.

a cron that hits this reads exit 2 and stops. no fallback, no retry under another org.

## .why criti

the guard is the security boundary between orgs (`define.root-org-inheritance` — "org1 keys never
leak to org2"). the allowlist widens the gate; this case proves it still has a wall.
