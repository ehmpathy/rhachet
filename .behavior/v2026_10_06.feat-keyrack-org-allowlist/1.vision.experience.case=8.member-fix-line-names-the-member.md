# case=8 — a member key that is locked or absent: the fix line names the member 🔴 criti

**cell** — B=`member` × D=`keyed.read` × G=`asked` (locked) or `none` · F=`skill`, `human`

## .narrative

the grove cron wakes before anyone has unlocked aether today:

```sh
rhx keyrack get --owner ehmpath --org aether --env camp --key AWS_PROFILE --value
```

the gate admits `aether`. the key `aether.camp.AWS_PROFILE` exists but is locked. the refusal prints its fix line — and today that line omits the org:

```
credential 'aether.camp.AWS_PROFILE' is locked. unlock it first.
   fix: rhx keyrack unlock --owner ehmpath --env camp --key AWS_PROFILE
```

a human copies it. it unlocks `ahbode.camp.AWS_PROFILE`, because a bare `--key` slugs under the default. the next `get --org aether` is locked again. the human has been handed a loop.

the fix line is built at `getKeyrackKeyGrant.ts:129`: it spells `--org` only for `@all`, on the stated premise that *"a real org is already what `set` defaults to from the manifest"*. the allowlist breaks that premise for every member that is not `org[0]`.

so the vision: **the fix line spells `--org <slugOrg>` whenever the slug's org is not the default.** a default-org fix line stays byte-identical — it is carried in 8 snapshot files (`getKeyrackKeyGrant.ts:159-160`).

```
credential 'aether.camp.AWS_PROFILE' is locked. unlock it first.
   fix: rhx keyrack unlock --owner ehmpath --env camp --key AWS_PROFILE --org aether
```

the `absent` arm (:164) has the same gap and the same repair: `rhx keyrack set … --key AWS_PROFILE --env camp --org aether --vault <vault>`, so a human files the member's key under the member, never a second copy under `ahbode` — the exact defect the wish's workaround table names.


## .why criti

a cron cannot act on a hint, but the human who reads its log can — and a fix line that lands on a different key than the one asked for is worse than no fix line (`getKeyrackKeyGrant.ts:125`, its own words). a grove fleet meets this the first day after the allowlist ships.

## .the same premise, on the sweep side

a member sweep (case=4) prints tips built the same way, each with no `--org`:

- `cli/asKeyrackErroredKeyTip.ts:52` — `retry: rhx keyrack unlock --env …`
- `asKeyrackOmittedKeyTip.ts:111` — `rhx keyrack unlock --key … --env … --reach …`
- `fill/fillKeyrackKeys.ts:409` — the `✓ rhx keyrack unlock --key …` line (fill is `org[0]`-only per F3, so this one stays as-is)

the rule is one rule: **any fix line for a slug outside the default org spells that org.** the first two follow it; the third is out of reach by F3.

## .the owner

the same rule has a second segment: a printed command names the rack it was asked on. a robot sweep runs as its own owner:

```sh
rhx keyrack unlock --env prep --org aether --owner mechanic
```

a declared key held under no member is omitted, and its tip must carry `--owner mechanic` — a tip without it writes to the default owner's rack, a human's, and the key stays absent where the robot asked for it.

```
rhx keyrack set --owner mechanic --key UNHELD_KEY --env prep --org aether --vault <vault>
```

```ts
given('[case3] a declared key held under no member', () => {
  when('[t2] unlock --env prep --org aether --owner mechanic, a member sweep', () => {
    then('the omitted tip carries `--owner mechanic` and `--org aether`', ...);
  });
});
```

the keyed fix line (`getKeyrackKeyGrant`) already echoed `--owner`; the sweep tips are where it was absent.

## .the seam it exposes

`getKeyrackKeyGrant` does not read the repo manifest today, so it cannot know which org is the default. either the default org threads into its context, or the fix line spells `--org` for every real org and the 8 snapshots move. the vision leans to the first (the common path stays byte-identical); a clean rework either way.
