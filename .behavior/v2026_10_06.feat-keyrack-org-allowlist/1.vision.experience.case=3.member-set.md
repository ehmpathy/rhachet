# case=3 — a human files a member org's key 🟢 criti

**cell** — B=`member` × D=`keyed.mutate` · F=`human`

## .narrative

a new aether camp account goes live. vlad stands in `dev-env-setup` and runs:

```sh
rhx keyrack set --owner ehmpath --org aether --env camp --key AWS_PROFILE
```

today that is refused, so he would `cd` into some aether repo to file it (issue #496), or file it
under `ahbode` and break the push token. now `aether` is a member: the value lands at
`aether.camp.AWS_PROFILE` on the host manifest. the repo manifest already declares `AWS_PROFILE`
under `env.camp`, so `.agent/keyrack.yml` is left as-is — and the list is untouched.

`del --org aether` is the mirror: it removes `aether.camp.AWS_PROFILE` and no `ahbode.*` row.

## .every writer of the file

three paths rewrite an extant `.agent/keyrack.yml`, each by parse → stringify: `set`'s key findsert (`daoKeyrackRepoManifest/index.ts:164`), `del`'s key removal (`:228`), and `rhx init --roles`. (`:64` creates a fresh file and writes a scalar `org`, as today.) `[t1]`, `[t2]`, `[t3]` each assert the list survives its writer.

`rhx init --roles` merges role keyracks into `extends:` (`initKeyrackRepoManifest.ts:93-96`) via parse → stringify, and reports `org: (parsed.org as string)` (:87, :101). the parse keeps the array and its order, so the file survives — but the order IS the default (`org[0]`), so the vision states it as a clamp, not an accident. a rewrite that sorted the list, as it sorts `extends` (:75), would repoint every bare read in the repo with no error.

## .why criti

a read of a member org has naught to read until a member's key is filed. and `set` is the one verb
that WRITES the manifest — `findsertKeyToEnv` (`daoKeyrackRepoManifest/index.ts:131`) refuses today
unless `org` is a string, so a list would break every `set` in that repo. this case clamps both.
