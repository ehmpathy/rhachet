🔴 **the second column names the COVERAGE call (demoed/itemized), and the third names what a caller
RECEIVES** — the word `say` returns. the two are distinct: a cell's coverage state is not the verdict
it yields, and the two rows that return a false green (`enqueued`/`buffered` on a fused turn) need the
third column to be visible at all.

🔴 **the falsehood is not detectable by the verdict that reports it.** `getCloneSubmittedCount` counts
occurrences of our needle **within** a turn, so a fused turn `<their fragment><our message>` contains it
and the count rises exactly as a clean dispatch would. ⇒ **`define.invariant.clone-say-delivery`'s third
foreclosed mode — never a false `delivered` — is reachable through this flag**, and through no other
path once invariant 4 carries its `focus` conjunct.

⇒ the requirement, the `Q22` measurement it rests on, and the fallback if the clear proves impossible:
the yield's `.--force APPENDS`.

🔴 **the four cells above assume `focus: 'input'`, and the flag does NOT re-open them under a modal.**
a prompt over a half-typed region is an ordinary state — a human types, a tool call fires, the prompt
lands on top — so `modal` and `input-dirty` co-occur, and the D2 axis resolved only the `mid-turn` pair.
⇒ the pre-check tests **`focus` before `input`**, so under a modal the refusal raised is
`modal-holds-focus`, which this flag does not name and therefore cannot override. **a flag may never
override a reason it does not name** — otherwise invariant 2 is defeated through invariant 1's opt-out.

🟡 **`--force` is the densest ALTERPATH in the box** (the pre-check boundary · the override

narrative with the refusal removed. the cells above carry the record instead.

## .the invariants the closed cells declare

1. **a say never writes onto unsubmitted content it did not author — unless the caller passes
   `--force`** (`input-dirty` row). the default refuses; `force` is the documented opt-out,
   and its help text must state what it destroys rather than merely what it overrides. ⇒ the row is
   **gated**, never forbidden.
   🔴 **and the word *overwrites* is not yet true of the mechanism**: the extant write **appends**, so
   a forced dispatch delivers `<their text><our message>` as one turn and the needle count rises on it
   ⇒ **`released`, exit 0, falsely**. the opt-out must either deliver our message **unfused** or report
   that it could not — whether a multi-row region can be cleared at all is ⇒ **Q22**
2. **a say never writes while a modal holds focus** (`modal` row) — the strictest of the set: a `\r`
   into a permission prompt is an approval, so this one has **no `force` opt-out** at all.
   🔴 **and it is void wherever the gate read is STALE.** the probe is a client-side read taken before
   enqueue; `genCloneWriteQueue` serializes the **write** and admits up to 128 dispatches in between
   (`socket/constants.ts:93`), so a prompt raised by a queued message ahead of ours is invisible to our
   read and our `\r` answers it. ⇒ **the read a refusal rests on must be current at the moment of the
   write** — the yield's `.genCloneWriteQueue serializes the WRITE`.
   🔴 **and that holds when the region is ALSO dirty**, which is an ordinary co-occurrence the D2 axis
   never resolved: both conditions are refusal-worthy at once, and `--force` overrides only
   `input-region-dirty`. ⇒ the pre-check tests **`focus` before `input`**, or invariant 1's opt-out
   becomes a modal bypass and this invariant is defeated through a flag that never named it.
   🟡 an intent with no mechanism is what `rule.require.safe-by-default` exists to catch — the easy
   implementation (test the flag's own field first) is the unsafe one.
   🔴 the same refusal covers `focus: 'unrecognized'`, because the write test is a **whitelist**
   (`focus === 'input'`) rather than a modal blacklist — so a screen we never modelled refuses by
   construction and names what the probe actually saw
3. **a say never writes to a clone that is not LIVE** (`not-live` row) — extant, unchanged
4. 🔴 **a say reports `enqueued` only when `focus` reads `input` *and* the input REGION is CLEAR *and*
   the screen's needle count ROSE** — a **triple**, and each conjunct closes a hole the one before it
   leaves. a clear region alone is not enough, because the `modal` race consumes the paste and leaves
   the region clear too. 🔴 **and the pair is not enough either**: `countOnScreen` ranges over the
   whole rendered screen, so a prompt that ECHOES what it receives (unmeasured — **Q21**) satisfies
   both halves on the very race the pair was added for. `focus` was read at the pre-check and consumed
   nowhere in the verify, though the post-bound probe is the one read that can see a modal which
   arrived after a clean pre-check.
5. 🔴 **`enqueued` promises the brain HOLDS the message, never that it will DELIVER it.** the turn it
   waits behind can be aborted (a ctrl-C, a crash, a `clone prune`), and the brain's queue dies with
   the process. so `brain-queued` is a **waypoint** with two exits, and the verdict's documentation
   must state the bound — a caller that needs at-least-once delivery verifies later, and `say` must
   not be made to outlive an unbounded turn to hide it (case=1 t4). ⇒ surfaced by case=7 t2
6. 🔴 **every needle test is a RISE against a pre-write count, never a presence** — a daemon's nudge
   text is a constant, so a prior tick's echo sits on screen and satisfies a presence test on a
   dispatch that was dropped. ⇒ a lost message reported `enqueued`, exit 0, with the one caller who
   would retry told not to. the repo's transcript verify already compares before against after and
   states why (`getCloneSubmittedCount.ts:15-17`); the probe owes that same shape on the screen and
   the input region both.
7. 🔴 **the input is a REGION — every rendered row it occupies — never one row.** `asCloneDispatchFrame`
   maps each interior `\n` to `CLONE_SOFT_NEWLINE`, so a multi-line message lands as ONE input across
   several rows. a row-scoped read makes `buffered` **unreachable** for that class (the needle spans
   the row break, so every row counts 0) and — worse — reads a human's half-finished multi-line entry as
   `clear` on its empty last row, so the say pastes on top: **invariant 1's clobber guarantee, defeated
   for a supported input class.** ⇒ the screen needle also differs from the transcript needle: the
   transcript renders a newline as the two chars `\n`, the screen as a row break, so the two forms are
   not interchangeable.

8. 🔴 **the six verdicts are ORDERED, and `absent` is the RESIDUAL — *no verdict above held*.** their
   conditions are not mutually exclusive: a dispatched message renders on screen, so `released` and
   `enqueued` both hold on the normal success path; and invariant 4's `focus` conjunct then opens a state
   (focus `modal` · region clear · screen risen · transcript flat) that **no** count test names. ⇒ a set
   declared a partition and evaluated as one returns two verdicts for one state and none for another,
   which is `rule.forbid.failhide` one level up: an unnamed state is an unspecified behavior.
   **`released` outranks `enqueued`** because a transcript rise is the stronger observation — it says the
   brain dispatched the message, where a screen rise says only that the text is visible. and the
   residual fails loud with a *do re-send* rule, which is the safe action where we cannot say what took
   the paste.

9. 🔴 **the clone graph is bounded by DEPTH, and a self-address is a capability rather than a cycle**
   (E1's `depth-1` row · D5's `self` cell). one bound and one clamp, not two bounds:
   - **no unbounded depth** — a clone at depth 1 may not enroll a peer, which would sit at depth 2. the
     refusal reads `RHACHET_CLONE_DEPTH` and precedes every spawn, so provably no state changed. ⇒ the
     harm is unbounded fan-out: each level costs a brain-cli process plus a pty, unbounded
     (`asCloneEnrollDepth`)
   - **a self-say LANDS, with ONE knob clamped** — `--await release` lowers to `enqueue`, with a notice
     on stderr, because `released` needs an empty queue and the caller's own queue cannot drain until
     this very say returns. every other knob behaves as it does for a peer (`isCloneSayToSelf`)

   🔴 **the depth refusal precedes the effect, and that is the conjunct that makes its half checkable.**
   a bound enforced after the spawn is not a bound — it is a report. ⇒ a caller that receives it has
   caused no state change, so the safe action is to say to an extant peer, never to retry the enroll.

   ⚠️ **this invariant once read *"both of its bounds refuse before any effect"*, and it forbade a
   self-say outright on a claimed deadlock.** the deadlock was false: the brain writes each user turn to
   the jsonl at submit time, client-side, so the transcript rise never waited on a brain turn
   (`getCloneSubmittedCount.ts:12-14`). measured 2026-09-20 — a real clone said to its own address and
   got `delivered: true` / `verdict: enqueued` / `probe: capable`.
   ⇒ `define.invariant.clone-say-to-self-is-await-clamped-never-refused` carries the full record, and
   `define.invariant.clone-say-has-a-peer-target` is retired.

   ⇒ demoed by [case=8](./1.vision.experience.case=8.the-clone-graph-bounds-its-depth-never-its-own-address.md).

10. 🔴 **attendance is a MODE, never a REACH** (E2's two values). whether a human watches a clone is
    independent of whether a peer can be heard: attendance is a **mode** (is a tty present?), reach is
    a **channel** (does a socket answer?). so a `detached` enroll produces a clone that is REACHABLE —
    `socketEligible: true` — and a contract that made a tty a precondition of reach conflated the two.

    🔴 **the conflation is invisible to a human tester, which is why it survived.** a human at a
    terminal always has a tty, so a contract that read `socketEligible: false` for a no-tty enroll
    never fired for the one actor who could report it. it fired only for a daemon, a CI step, and a
    clone — none of which can file a defect.

    🔴 **and it is the loop directive's own precondition.** *"spawn a peer clone and say to them
    reliably"* is issued by a clone, whose enrolls are detached by construction — so this invariant is
    what makes the goal reachable at all, whatever the say path returns.

    ⇒ the durable statement is `define.invariant.clone-attendance-is-a-mode-never-a-reach`; demoed by
    [case=9](./1.vision.experience.case=9.a-detached-enroll-is-reachable.md).

### 🔴 .three of the ten rest on an UNMEASURED premise

an invariant is the **strongest** assertion this catalog makes, and `rule.require.experience-catalog-evolution`
says the criteria stage seeds its bdd from here. ⇒ an invariant whose premise is unmeasured becomes an
**acceptance assertion** with no note that it may not be testable at all.

| # | the premise it rests on | if the premise fails |
|---|---|---|
| **1** | **Q7** — the input region is locatable on the rendered screen | the clobber guarantee is **unenforceable**; there is no region to read |
| **2** | **Q8** — a modal is distinguishable from an input line | the strictest invariant in the set has **no detector**, so a `\r` can still answer a prompt |
| **4** | **Q6** — claude-code renders a queued message on screen at all | `countOnScreen` never rises ⇒ the conjunct never holds ⇒ **`enqueued` is unreachable** and a landed message reports `absent`, exit 1 |
| 🔴 **4**, a second premise | **Q21** — a permission prompt does **not** echo what it receives | the region-clear + screen-rise pair returns `enqueued` on a message a prompt ate. ⇒ the `focus: 'input'` conjunct is what makes 4 safe **whichever way Q21 falls**, so the invariant does not rest on the measurement |

⇒ invariants **3 · 5 · 6 · 7 · 8 · 9 · 10** do not appear above, and that is the point of the table: 3 is
extant behavior, and 5 · 6 · 7 · 8 are **derived** — from an aborted turn's semantics, from a repeated
needle, from `asCloneDispatchFrame`'s soft-newline, and from the six conditions read against each other.
each holds whatever a capture returns.

🔴 **9 and 10 are the two that rest on no TUI premise at all**, and the reason is structural: both are
settled **before any screen is read**. 9 reads an address and an env var; 10 reads a socket's answer. so
claude-code's render — the source of every premise in the table above — cannot reach either one. ⇒ that
is what makes them the two invariants a capture can neither confirm nor refute, and it is why they were
provable at the unit grain the round they were found.

🔴 **8 holds whichever way Q6 and Q21 fall, and that is what earns it the closed set beside its own
premises.** a `no` to Q6 makes `enqueued` unreachable and a `yes` to Q21 makes the pair unsafe — and in
both worlds the rows are still evaluated in order and `absent` is still what a caller receives when no
row above it holds. ⇒ a rule about the ORDER ranges over the **set**, so a premise that moves one
row's reachability cannot move it.

🔴 **invariant 4 rests on TWO research-gated premises — Q6 and Q21 — and a premise can hide in a DEMO
as easily as in an invariant.** Q21 lives inside case=6's t2 as the flat clause *"our needle is
nowhere"*, where a demo's declared status as a *sketch* makes it read as harmless.

🔴 **an invariant's form is flat assertion**, so it carries no hedge, and a hedge-scoped sweep cannot
reach it: the whole set reads as equally settled unless each premise is enumerated as a question. so
Q6 and Q21 are enumerated as questions, not asserted as settled.

🟡 **the repair is a dependency note, not a downgrade.** all three still belong in the closed set: each
states what the design **guarantees**, and each premise is testimony-grade rather than unknown — Q6 in
particular is the **wisher's own first-person report**. what was absent is the line that says a
`[research]` answer could move them.
