# 1.vision — give `clone say` a read channel

⇒ wish: `0.wish.md` → `ehmpathy/rhachet#527`

## .the root

the surface: *"`say` intermittently throws `MalfunctionError` against a live clone."* five whys down:

| why | answer |
|---|---|
| the say failed | the transcript verify timed out |
| the verify timed out | no new turn appeared within 15s |
| no turn appeared | the brain held the message behind its active turn |
| the hold read as a failure | `say` has ONE word for "not in the transcript", and that word is *"the brain never took it"* |
| it has one word | a bounded wait cannot part `not yet` from `never` — the transcript is the only surface `say` reads |

⇒ **the socket confirms TRANSMISSION, never RECEIPT.** the clone socket is not write-only — it
replies with an ack (`genCloneSocketServer.ts:112`). but that ack means *the bytes reached the pty*
(`delivered`, `sayClone.ts:21`), never *the brain took the message as a turn*. so `say` has no **read
of state** — no way to ask *"where is my message now?"* — and it infers receipt from the transcript,
which lags.

that one gap produces three defects:

- **the primary** — a message the brain queued reports `MalfunctionError`, a false failure
- **the secondary** — a say pastes over a human's half-typed input and submits both as one turn
- **the discovered** — a say answers a permission prompt: its `\r` approves a tool call no human approved

⇒ so this wish is not a timeout fix. it is a **read channel** — one that reports where a dispatched
message sits, so `say` states a fact instead of a guess.

## .the input triple

a message dispatched to a clone passes through three states, in order:

```
buffered  →  enqueued  →  released
```

| state | where the message sits | how it got there |
|---|---|---|
| **buffered** | the input buffer — where stdin goes, the box at the screen's foot | written, not yet submitted |
| **enqueued** | the queue above the box | submitted while the repl was at work; waits here until released |
| **released** | out of the queue, in the repl | the brain took it |

the transitions:

- if the repl is free at submit, a message passes through `enqueued` fast — `buffered → released` in one motion
- the queue releases in **subsets** — a message can leave at a different rate than its neighbours, so `released` is per-message, never per-queue
- the input buffer is shared with the human, so it may be **dirty** — it holds content nobody dispatched

⇒ this triple is the design's spine. `clone get` reads it; `clone say` reports which state it reached.
its durable brief is `.agent/repo=.this/role=any/briefs/define.brain-cli-input-states.md`.

## .the design

### the read is `clone get`

`say` leverages `get` under the hood — no new socket verb. `get` reads the clone's input state; `say`
observes state through it and reports which the message reached.

- **`clone get`** reports whether the screen carries **buffered** or **enqueued** input
- **`clone say`** reports **buffered**, **enqueued**, or **released** — plus the orthogonal refusals below
- **`clone say --await enqueue`** / **`--await release`** polls `get` until the message reaches the
  target state, or the poll timeout halts it

⇒ the target state is the caller's knob. the 15s bound is no longer the decider — it is a poll timeout,
with a floor set by the screen's render latency (⇒ Q11), never by the turn the message waits behind.

### what `say` returns

`say` returns exactly one verdict — a state of the triple, or a refusal orthogonal to it.

| verdict | exit | channel | when |
|---|---|---|---|
| `released` | 0 | stdout | the brain took it — transcript count rose (`😶🎙️ said to @:x`, unchanged) |
| `enqueued` | 0 | stdout | focus `input` **and** input region clear **and** screen count rose |
| `buffered` | 1 | stderr | our text sits in the input region — `countInInput` rose |
| `withheld` | 2 | stderr | the pre-check refused — a dirty input region, or a modal holds focus |
| `absent` | 1 | stderr | the residual — no verdict above held |
| `unreadable` | 1 | stderr | the bound elapsed against a probe-blind peer |

the six are evaluated in that order, first match wins, and `absent` is the residual. `released` outranks
`enqueued` because a transcript rise is the stronger observation.

⇒ **`enqueued` promises the brain HOLDS the message, never that it will DELIVER it.** the turn it waits
behind can be aborted — a ctrl-C, a crash, a `clone prune` — and the brain's queue dies with the process.
so a caller told not to re-send an `enqueued` must know that bound.

⇒ **every condition is a RISE, never a presence.** a daemon repeats one text, so a prior tick's echo
sits on screen; only a pre-write baseline compared against a post-bound read parts "the old echo" from
"the old echo plus ours" (the count rationale is `getCloneSubmittedCount.ts:15-17`).

⇒ **every field is a REGION, never a row.** `asCloneDispatchFrame` maps interior newlines to soft-newlines,
so a multi-line message occupies several rendered rows. a row-scoped read makes `buffered` unreachable and
reintroduces the clobber defect on a human's multi-line entry.

### the read channel

`get` returns a classification, never screen content:

```
← { focus: 'input' | 'modal' | 'unrecognized',
    input: 'clear' | 'dirty', countInInput, countOnScreen }
```

- **the reply carries a classification, not bytes** — the brain's screen holds the human's work; a verb
  that returned it would widen the socket into a session oracle (⇒ F02, F03)
- **`focus` is a whitelist** — the write proceeds only on `focus: 'input'`. `modal` and `unrecognized`
  both refuse, so a fourth value added later refuses by construction (safe by default)
- **the pre-check tests `focus` before `input`** — so `--force` overrides only a `input-region-dirty`
  refusal, never a modal one. a modal has no force path at all
- **the counts are counts** — `say` probes twice per dispatch and compares, per the rise rule above

### the machine channel

the say payload is additive — the verdict lands beside the extant boolean, so no caller breaks:

```
{ delivered, verdict, reason, probe, serial, slug }
```

- `delivered` keeps its extant sense and place
- `verdict` is the discriminator a retry policy reads
- `reason` is a **closed slug set** — a caller branches on it for the safe action (a `withheld` from a
  dirty region may be forced; a `withheld` from a modal may never be)
- `probe` is `'capable' | 'unsupported'` — it states the strength of the verdict, always present
- on the four refusal verdicts (stderr channel), the trio rides the thrown error's `metadata`, which
  `asCliErrorJson` projects verbatim — so a retry policy reads it on both channels

⇒ each coined verdict word (`released`, `enqueued`, `buffered`, `withheld`) owes a `domain.terms/` cluster
at execution; `absent` and `unreadable` are adopted and owe only a `.refs` extension.

### the model read

`clone get` / `whoami` report the brain **model**, and the model changes mid-run via `/model`. two split
by channel:

| the model at… | source | reliability |
|---|---|---|
| **spawn** | the harness knows the brain it enrolled — stamp it into the clone identity record | reliable, stale after `/model` |
| **now** | the transcript or screen — the read channel this wish builds | a `[research]` item |

⇒ `ANTHROPIC_MODEL` cannot carry the current model: it sets the launch default only, and `/model`
overrides it without write-back. so the current model rides `clone get`, same instrument as A1.

### where the screen comes from

a headless terminal (`@xterm/headless`) fed off the child's output holds a live rendered screen:

- **the feed attaches before the socket accepts** (V6) — else a probe reads an unfed screen and returns
  a false `absent`. `readScreen` reports `feed-not-live` rather than an empty screen (V7)
- **the terminal is constructed at the pty's geometry and re-flowed on every resize** (V14) — a clone
  takes the geometry of the human who enrolls it and may be resized mid-run, so a fixed-size emulator
  reads the wrong rows and reintroduces the clobber and modal defects
- **the feed listener is fault-isolated** (V16) — node-pty's emitter dispatches with no `try`, and the
  feed sits ahead of the human's mirror, so a throw there would suppress the human's own output
- **`readScreen` is a required injected field** (V18), reached like node-pty — a projected type, a lazy
  load, an injected seam (V19) — so no eager import lands in a bun fast path and every construction site
  decides what screen it models

### the write path holds

- **the gate read must be current at the write** — the queue serializes the write, not the box walk, so
  a probe taken before enqueue may be stale by up to 128 dispatches. the honest satisfier is a
  server-side pre-check at dequeue
- **every dequeue exit acks and releases the drain latch on the fault path** (V15) — else a rejected
  write leaves the clone alive, healthy on the reach channel, and permanently deaf to `say`

## .the retry contract

the wish's loudest benefit is that a daemon's retry policy becomes writable. the policy is a three-way
split, not the two-way one the surface suggests:

| verdict | re-send? | why |
|---|---|---|
| `released` · `enqueued` | no | the brain has it (bounded, for `enqueued`, by the abort note above) |
| `withheld` | yes | the pre-check refused, so NO pty write happened (`delivered: false`) — a re-send cannot duplicate |
| `buffered` · `unreadable` · `absent` | verify later, never re-send blind | `buffered`: our text is in the region (a re-send appends and wedges) · `unreadable`: we do not know where it went · `absent`: the bytes WERE delivered (`delivered: true`) and a modal may have eaten them (case=6 t3), so no rise is provably held |

## .the mental model

a **postal delivery scan**. `delivered` today means *the bag left the van*. the verdicts are the states a
courier already tells apart: `released` (delivered) · `enqueued` (held at depot) · `withheld` (recipient
unavailable) · `buffered` / `absent` (undeliverable). nobody finds it strange that a parcel at a depot is
not a lost parcel.

the wisher's words, adopted verbatim: `enqueued` (their *"queued … shows in the queued messages region"*),
`buffered` (their *"in the live input line, uncommitted"*), `absent` (their *"neither … holds the
message"*). `released` is the repo's extant success sense (`getCloneSubmitLanded`).

## .what is awkward

- **the central claim is untested.** A1 is testimony; if a brain-cli writes a queued message to the
  transcript at submit time rather than at dispatch time, the diagnosis is wrong. only the dogfood reduces
  this — no design does.
- **we screen-scrape another product's TUI** — but the brain-cli is pinned to a specific version, so
  the rendered shape is stable and the scrape reads a surface that does not move. when the pin lifts, the
  version diffs eject into the adapter pattern already begun (`BrainHooksAdapter`,
  `KeyrackHostVaultAdapter` are its peers) — so a new brain-cli version is a bounded, one-adapter cost,
  never a rewrite.
- **the mechanism is heavier than the symptom.** the report is a wrong error message; the proposal is a
  terminal emulator in the daemon. the weight is justified by the root and the two other defects it closes.
- **`enqueued` is the right word and its wire twin is taken** (F01). the alternative is an overloaded term
  in a contract, which `rule.forbid.domain-term-ambiguity` blocks outright.
- **case=6 outranks the wish's own primary ask** — a safety defect found while we design a fix for a
  log-noise defect. surfaced as a scope question (F07), not absorbed.
- **one concept, two channels, two shapes.** the verdict is written once as a payload field and once into
  error metadata; a consumer reads it from one place or the other by the answer it got. every alternative
  breaks the stdout/stderr split that guarantee rests on.
