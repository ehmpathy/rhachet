# case=6 — a say never answers a permission prompt on a human's behalf

`unattended × modal × (refused, or `absent` on the race) × probe-capable` · **feel** sharp ·
**care** critipath (freq: a brain mid-tool-call is routinely parked on a prompt · cost: a tool call
approved by no human)

⇒ the cell this walk discovered; the issue does not name it. **rank 3= by boundary-density**
(2 boundaries: the modal focus gate at t1, the pre-check/write race at t2) — and the **highest-cost
cell in the box**, which is what earns it the deepest scrutiny.

🟡 **this cell is NOT ranked 1 by boundary density.** its bdd crosses one mechanism, not five
boundaries — so density does not carry the rank; the **cost** argument does, on its own terms below.
`define.experience._.metric=boundary-density` is explicit that the two levers are separate.

## .why it outranks every other cell on COST

every other failure in the box costs a **message**. this one costs an **approval**:

- a brain-cli parked on `Do you want to proceed? (y/n)` receives keystrokes at the **prompt**, not
  at the input line
- our paste goes to the prompt, and then `say` writes its own `\r`
- **that `\r` is the answer.** it accepts whichever option has focus
- so a reminder daemon, with no human in the loop, can approve a tool call — and today `say` would
  report `delivered` and exit 0, because a prompt that dismisses also ends the turn and the
  transcript then moves on

⇒ the delivery defect and the safety defect share one cause (`say` writes blind), so one read
closes both. that is why this cell belongs to this wish rather than a separate one.

## .the narrative — the human's pov

i left my driver clone to run a long chain and walked away. it hit a prompt: *"write to
`~/.ssh/config`? (y/n)"*. i intended to read that carefully when i got back.

**today** the reminder daemon fires while i am gone. its paste lands in the prompt and its `\r`
answers it. i come back to a completed chain and no record that a machine, not me, made that call.
the say's log says `delivered`.

**post-fix** the daemon probes, sees a modal holds focus, and refuses. i come back to the prompt
still open, exactly as i left it, and the daemon's log says it withheld and why.

## .how it fails safe — fast · loud · teaches the fix

| property | how |
|---|---|
| **fast** | refused at the probe, before the content write. the `\r` — the dangerous byte — is never written |
| **loud** | exit 2 on the refusal, exit 1 on the race. never a `delivered` on a message a prompt ate |
| **teaches the fix** | names what would have happened (*"a say would answer it, so it was withheld"*) rather than only that it refused |

## 🔴 .no `force` opt-out, deliberately

case=2's refusal has `--force`, because its worst outcome is bounded — a human's sentence.
this refusal has no opt-out, because its worst outcome is **not bounded by the conversation**: an
approved write, an approved delete, an approved network call.

⇒ `rule.require.safe-by-default`'s ladder says make it **impossible**, not merely hard, when the
wrong action's cost is unbounded. so the modal refusal is a constraint, never a default.

## 🟡 .the race is why the verify needs BOTH reads

t2 is the residual the pre-check cannot close — a probe and a write cannot be one atomic act across
a socket. so the post-bound verify must be able to say `absent`, which it can do only if it tests
**two** facts: the input line's count did not rise, **and** the screen's did not either.

⇒ a verify that read the input line alone would call t2 `enqueued` — a green lie on a message a
permission prompt consumed. that is the whole argument for the conjunct in case=1's fail-safe, and
this cell is its proof.

### 🔴 .and TWO reads are not enough either — the conjunct does not part what it claims to

`countOnScreen` is defined over the **whole rendered screen**, and a permission prompt is on that
screen. ⇒ if the prompt **echoes** what it receives (unmeasured — **Q21**), t2 renders input `clear`
**and** a risen screen count, so the conjunct returns **`enqueued`, exit 0**: the precise green lie
this cell exists to prevent, produced by the cure this cell cites.

🔴 **the probe reply already carries the discriminator and the verdict table discarded it.** `focus`
was read at the **pre-check** and consumed nowhere in the verify — though t2's whole premise is a
modal that arrives *after* a clean pre-check, so the post-bound probe is the one read that can see
it. ⇒ **`enqueued` now requires `focus: 'input'`** (the yield's `.the input triple`), which makes
this cell safe whichever way Q21 falls.

### 🔴 .and BOTH facts must be RISES, or this cell's own fail-safe is holed

the conjunct was drafted over presence booleans, and a presence test breaks t3 on the actor most
likely to reach it — a daemon whose nudge text is a constant:

| the screen at t3 | a PRESENCE test says | a RISE test says |
|---|---|---|
| an earlier tick's echo, and this paste eaten | needle on screen ⇒ **`enqueued`, exit 0** 🔴 | count unchanged ⇒ `absent`, exit 1 ✅ |
| clean screen, and this paste eaten | needle absent ⇒ `absent`, exit 1 ✅ | count unchanged ⇒ `absent`, exit 1 ✅ |

⇒ **so the presence form holds only for a first-ever dispatch, and a permission prompt is exactly
what a daemon on a fixed nudge runs into.** a cell whose declared job is to fail loud would have
failed silent, from its second tick onward, forever. ⇒ `case=_` invariant 6.
