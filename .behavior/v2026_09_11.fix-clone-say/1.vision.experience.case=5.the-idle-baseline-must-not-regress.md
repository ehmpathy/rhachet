`operator × idle-clean × became-a-turn × probe-capable` · **feel** happy · **care** critipath

## .the narrative — the operator's pov

i run `rhx clone say @:beav-1 --what "drive on"` at an idle clone, which is what i do a dozen times
a day.

i get, byte for byte, what i got before the fix:

```
😶🎙️ said to @:beav-1
```

no new line, no notice, no extra latency i can feel. the probe before the write and the verdict
after it are both invisible on the happy path, because on the happy path there is no ambiguity to
report.

that is the whole experience, and it is the point: **a fix for the sharp cells must be free on the
common one.**

## .the bdd timeline

```
  and      stdout tree = `😶🎙️ said to @:beav-1`   ← unchanged, byte for byte
  and      stdout json = { delivered: true, verdict: 'released', reason: null,

  and      🔴 `reason: null` AND `probe: 'capable'` are rendered, never omitted — the contract
           declares SIX keys, and this demo owns the snapshot cost claim, so a short render here

  and      exit code = 0
  and      the added latency is ONE probe round-trip on a unix socket (sub-millisecond)
```

## .the three regression guards this case asserts

1. **the tree render is unchanged.** `😶🎙️ said to <addr>` keeps its exact bytes, so every extant
   snapshot in `blackbox/cli/__snapshots__/clone.*.snap` passes untouched. a changed happy-path
   render would be a visual blemish charged to every reader for a fix none of them needed.
2. **the json is additive.** `delivered: true` keeps its sense and its place; `verdict`, `reason`,
   and `probe` are **three** new keys beside it. an extant caller that reads `data.delivered` is
   unaffected.
   ⇒ so the one json say snapshot (`clone.acceptance.test.ts.snap:111-118`) re-snaps by **three**
   lines, which is the figure the yield states and this demo must render, or the cost claim and its
   own demo disagree.
   🔴 **this demo is the one owner of the count** — three keys: `verdict`, `reason`, `probe` — and
   every other passage cites it rather than restates it (`rule.require.a-cue-is-not-a-claim`: a count
   is a claim).
3. **the second probe never fires on the happy path.** the post-bound probe runs only when the
   transcript poll elapses — so the common path pays one pre-check round-trip, never two.

## 🟡 .the one honest cost

the pre-check probe is a new round-trip on **every** say, the happy path included. it is a unix-socket
request against a local daemon that answers from memory, so the cost is sub-millisecond against a
verify that already polls on a 250ms tick — but it is not zero, and it is paid by the most frequent
call.

⇒ the trade is stated rather than hidden: one sub-millisecond read, on every say, buys the case=2
guarantee that no say ever writes over a human's words. that guarantee is unobtainable any other
way, because a write cannot be un-done once the `\r` has fired.
