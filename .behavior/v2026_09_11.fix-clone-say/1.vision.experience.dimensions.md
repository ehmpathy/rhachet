# 1.vision.experience.dimensions

the orthogonal axes the `clone say` experience varies over, and the product they generate.

⇒ method: `howto.experience.decompose`. the inventory that verdicts every cell is
`1.vision.experience.case=_.md`.

## .the axes

### D1 — actor · who dispatches the say

| value | who |
|---|---|
| `unattended` | a daemon or cron with no human at the keyboard — RouteReminder's `sayToClone.ts`, a comms relay. reads `--output json` |
| `operator` | a human at a second terminal who invokes `rhx clone say` by hand. reads the tree render |

orthogonal because the say's fate does not depend on who sent it — only on what the target
holds. the axis changes what a **failure costs** and which **render** is read, never the mechanics.

### D2 — target state · what the clone holds when the say lands

| value | the clone's screen |
|---|---|
| `idle-clean` | no active turn, input region empty |
| `mid-turn` | an active turn in flight (a tool chain, a streamed reply), input region empty |
| `input-dirty` | input region holds unsubmitted content — a human mid-type, or a prior stuck paste |
| `modal` | a permission prompt or dialog holds focus — the input region is not what receives keystrokes |
| `not-live` | the brain-cli has exited, or the clone is on another host |

closed: keystrokes go to the input region, or to a modal, or nowhere (not-live); the region is empty
or it is not; a turn is active or it is not. `mid-turn` + `input-dirty` co-occur — resolved below.

### 🔴 that closure rests on an UNVERIFIED model of claude-code's focus, and it is the axis's weakest claim

the second and third clauses are **derivations** — *empty or not*, *active or not* are binary by
construction. the **first** is not: *"keystrokes go to the input region, or to a modal, or nowhere"* is
a claim about a TUI we do not own, and it is asserted flatly.

⇒ **a third focus target would break it**, and plausible candidates exist: a scrollback pager, an
in-app search, a mode in which the input is disabled. ⇒ **Q19**, enumerated in the yield.

🔴 **and D4's own note above understates itself by one axis.** it says D4 is *"the ONE axis whose value
SET a blueprint choice can change"* — true, and **D2's set can change for a strictly worse reason**: a
blueprint choice is ours, and claude-code's focus model is **nobody's here**. so D2 carries the same
open-set risk with none of the control.

🔴 **the consequence would be a SAFETY one if the probe reply's `focus` enum had no escape value.** a
two-value enum `focus: 'input' | 'modal'` forces a screen in an unmodelled focus state into one of
the two — and the two are not alike:

| classified as | what a say then does |
|---|---|
| `'input'` | 🔴 **writes**, then `\r`. keystrokes land wherever that mode actually sends them — the exact case=6 harm, with no modal on screen to have warned us |
| `'modal'` | refuses, exit 2. a **recoverable** false refusal |

⇒ a **rule of conduct** — *a screen the classifier does not recognize is `modal`, never `input`* —
would be wrong two ways: a convention is enforced by nobody, and it would make the **report** lie,
since `modal-holds-focus` would then assert a prompt the probe never saw. that collides with the rule
this vision already carries — *every slug names an OBSERVATION, never a guess at a cause*, the rule
that forbids `modal-raced-the-write`.

⇒ so the third state is carried **in the enum** rather than behind a convention —
`focus: 'input' | 'modal' | 'unrecognized'`, with the write gated on a **whitelist**
(`focus === 'input'`), so a fourth value added later refuses by construction. 🟡 that is
`rule.require.safe-by-default` moved out of a convention and into a type — the same argument the
verdict set already makes for `absent` vs `unreadable`: **the refusal to assert is the safe branch.**
⇒ the contract is the yield's `.focus is a THREE-value enum`.

🟡 **Q19 is unchanged by the repair, and its hazard MOVED.** the enum no longer forces a misclassified
write, so what is left is a **report** hazard and an **axis** one: a third focus target adds a **D2
value**, and the product, the inventory, and the invariants are each computed over D2.

🔴 **`region`, never `line` — every rendered row the input occupies.** `asCloneDispatchFrame` maps
each interior `\n` to a soft-newline, so a multi-line message lands as ONE input across several rows.
a row-scoped read of `input-dirty` classifies a human's half-finished multi-line entry as clean on its
empty last row — the clobber this axis exists to prevent (`case=_` invariant 7).

🔴 **`modal` is the value this walk discovered, and it is a SAFETY value rather than a delivery
one.** a brain-cli mid-tool-call is routinely parked on a permission prompt. our paste then goes to
the **prompt**, not the input line, and our `\r` **answers it** — so a say can approve a tool call
no human approved. the message is also lost, but that is the lesser half.

🟡 **`input-dirty` subsumes the mid-turn-and-dirty case.** dirtiness is what governs the
pre-check, and it governs it identically whether or not a turn is also active. so the two are
one value, not a fifth: the axis is *what must the say decide before it writes*.

### 🔴 the axis resolves ONE co-occurrence pair and there are TWO

the closure line above names `mid-turn` + `input-dirty` and says *"resolved below"*. it says not one
word about **`modal` + `input-dirty`**, which co-occur for the same ordinary reason — a human types, a
tool call fires, the prompt appears on top — and which carry a consequence the first pair does not.

⇒ the probe reply carries `focus` and `input` in **one** message, so at the pre-check **both** can be
refusal-worthy at the same instant. and their `--force` semantics are **opposite**:

| the pre-check tests | what a `--force` caller gets |
|---|---|
| `input` first ⇒ `withheld` · `input-region-dirty` | 🔴 the flag applies, the write proceeds, and the `\r` **answers the prompt** — the path **F06** forbids outright, reached through a flag that was never about modals |
| `focus` first ⇒ `withheld` · `modal-holds-focus` | ✅ refused. the flag never applies, because the refusal it overrides was never raised |

⇒ **`modal` outranks `input-dirty` on this axis**, and the yield states it normatively: *the pre-check
tests `focus` BEFORE `input`, and `--force` overrides only a refusal whose reason is
`input-region-dirty`.* 🟡 F06's intent was never in doubt — what was absent is the **mechanism** that
makes it true where both conditions hold, and the easy implementation (test the flag's own field
first) is the unsafe one.

🟡 **an axis that settles one overlap reads as an axis that looked for overlaps** — so a genuine
co-occurrence pair is easy to miss: the axis that removes the overlap masks the search for it.

### D3 — fate · where the message ends up

| value | position |
|---|---|
| `became-a-turn` | in the transcript — the brain dispatched it |
| `brain-queued` | held by the brain-cli behind the active turn; on screen above the input region |
| `uncommitted` | still in the live input region, our own text, no `\r` took |
| `absent` | nowhere — neither screen nor transcript |

orthogonal to D2 because a paste can drop at an **idle** target (the `\r` races the commit —
`define.invariant.clone-say-delivery`'s raced-submit) and a busy target can still submit
promptly if its turn ends inside the window. the correlation is strong, never total — and the
impossible cells are what the walk is for.

### D4 — peer capability · can the daemon answer a state read

| value | the clone daemon |
|---|---|
| `probe-capable` | spawned by a rhachet that serves the new read verb |
| `probe-blind` | spawned by an older rhachet — answers `rejected: request is not a say { message }` |
| 🔴 `feed-not-live` | 🔴 **CONTINGENT** — serves the verb, and its **screen feed** is not yet live. reachable only under a **reporting** satisfier of V6; a **structural** satisfier deletes the state outright |

orthogonal, and **not** an implementation detail: a clone daemon outlives the `rhx` binary that
spawned it. every human who upgrades mid-session hits `probe-blind` exactly once, with a live
clone they do not want to re-enroll. today's dispatch path is `probe-blind` by definition.

🔴 **D4 is the ONE axis whose value SET a blueprint choice can change.** its third value is the
enroll window V6 governs: `readScreen` can report `feed-not-live`, which renders `unreadable` with a
**retry** remedy where `probe-blind`'s is **re-enroll** — a different cause and a different fix, which
is the test every other value on this axis meets.

⇒ the yield marks that contingency on **V7's row**, on the **closed slug set**, and on `case=_`'s
**cause table** — each of them a value this axis GENERATES — and never here, on the axis that
generates them. **a contingency propagated downward and never upward leaves the one artifact whose
job is to declare the space with a closed set it does not have.**

🟡 the product below is computed at the **two settled values**. a reporting satisfier adds 40 product
cells that collapse to **one** experience, exactly as `probe-blind`'s 40 do (`case=_`) — so the count
moves and the coverage verdict does not, which is why the arithmetic keeps one owner rather than a
fork (`rule.require.a-cue-is-not-a-claim`).

### D5 — dispatch relation · whose address the say names

| value | the target |
|---|---|
| `peer` | another clone, or the human's session — a dispatch that crosses a process boundary |
| `self` | the caller's OWN address — a clone whose `@:serial` names the process it executes in |

orthogonal to D1 because the RELATION is independent of who dispatches: a daemon can name its own
address, and so can an operator who mistypes a serial. and orthogonal to D2 because the relation is
settled from the **address** alone, before any screen is read — which is what lets the `self` value
clamp one knob ahead of every mechanic the other axes describe.

🔴 **the axis was absent, and its absence is the shape `rule.require.experience-catalog-evolution`
names: a real experience the contract did not hold.** the drive found `self` at the execution stage
(`isCloneSayToSelf`, `clone.acceptance.test.ts` [t3b]) and it is a genuine cell, not a variant of an
extant one.

🔴 **a self-say LANDS, and it is a key capability rather than a hazard.** it is how a clone nudges its
own next turn (a self-driven loop) and how it hands itself a client-level slash command (`/model`,
`/compact`). exactly one knob is clamped: `--await release` lowers to `enqueue`, because `released`
needs an empty queue and the caller's own queue cannot drain until this very say returns — the
`clone say` process IS a tool call the brain is mid-way through. every other mechanic on every other
axis behaves identically to a peer say.

⚠️ **this cell once read *"refused at the address grain, exit 2, before any pty write"*, on a claimed
deadlock, and the deadlock was false.** the transcript rise never waited on a brain turn — the brain
writes each user turn to the jsonl at submit time, client-side
(`getCloneSubmittedCount.ts:12-14`). measured 2026-09-20: a real clone said to its own address and
got `delivered: true` / `verdict: enqueued` / `probe: capable`, with the payload landed as a turn.
⇒ the full record is `define.invariant.clone-say-to-self-is-await-clamped-never-refused`.

## .the product

```
D1 actor (2) × D2 target (5) × D3 fate (4) × D4 peer (2) × D5 relation (2)  =  160 cells
```

🟡 **D5 collapses the box rather than multiplies it, exactly as `probe-blind` does on D4** — and for a
different reason than that peer, so the two are not one rule. `probe-blind` collapses because the read
channel answers no question, so every mechanic below it is unobservable. `self` collapses because every
mechanic below it behaves **identically to a peer**: the clamp touches one knob (the await target),
and no D2 target, D3 fate, or D4 peer value changes under it. so all 80 of its cells are ONE
experience — *can a clone nudge itself?* — which is why it earns one demo and not a matrix.

⚠️ **the collapse once rested on the refusal** (*"`self` refuses at the address"*), which was retired.
the count is unchanged and its ground is not: a refusal collapses a box by making it unreachable, and
an identity collapses it by making it redundant. ⇒ the arithmetic held for a reason that had to be
re-derived, never merely restated.

the 80 `peer` cells are the box the rest of this file walks.

walked as a **20-cell core** (D2 × D3 — the mechanics) crossed with **4 modifier combos**
(D1 × D4 — who reads it, and whether the read channel answers). the inventory verdicts the core
in full, then names which modifier combos produce a *distinct* experience rather than a repeat.

## 🔴 .the SECOND box the walk missed — the enroll that PRECEDES every say

the five axes above decompose one verb. and a `say` has a precondition no axis of it can express:
**the target must exist.** the wish names `say`, so the vision decomposed `say` — and the drive then
had to enroll peers to exercise it, which surfaced three experiences with no cell to sit in.

⇒ **they are not out of scope; they were mis-scoped.** `rule.require.experience-catalog-evolution`'s
answer is to grow the contract, and the honest growth is a **second box** rather than more values on
D1: D1's declared subject is *"who dispatches the say"*, so an `enroll` value there would overload the
axis outright (`rule.forbid.domain-term-ambiguity`). enroll varies over axes of its own.

### E1 — enroll depth · how deep in the clone graph the caller sits

| value | the caller |
|---|---|
| `depth-0` | a human, or a process with no `RHACHET_CLONE_DEPTH` — may enroll a peer |
| `depth-1` | a clone. its peer would sit at depth 2 — **refused**, exit non-zero |

closed by the budget itself: the bound is 1, so a caller is under it or at it. the axis exists
because the two values are **different experiences** rather than two readings of one — `depth-0`
enrolls and gets a clone, `depth-1` is refused and must say to an extant peer instead.

🔴 **the budget is a recursion bound, and the harm it prevents is unbounded fan-out.** a clone that
may enroll a clone that may enroll a clone consumes the host without a ceiling, and each level costs a
brain-cli process plus a pty. ⇒ refused at the env grain, before any spawn.

### E2 — attendance · whether a human watches the enrolled clone

| value | the enroll |
|---|---|
| `attended` | a tty is present — a human at a terminal, the clone's output mirrored to them |
| `detached` | no tty — a daemon, a CI step, a `spawnSync` caller |

🔴 **and BOTH values are REACHABLE, which is the whole claim.** attendance is a **mode** (is anyone
watching?); reach is a **channel** (can a peer be heard?). they are independent, and a contract that
made a tty a precondition of reach conflated them — which is what
`define.invariant.clone-attendance-is-a-mode-never-a-reach` settles.

⇒ **this axis is the loop directive's own precondition.** *"spawn a peer clone and say to them
reliably"* is issued by a clone, whose enrolls are detached by construction — so a `detached` enroll
that read unreachable would make the goal unreachable by construction, whatever the say path did.

### the enroll product

```
E1 depth (2) × E2 attendance (2)  =  4 cells
```

small by nature: enroll has one decision (may I?) and one mode (is anyone watching?). the inventory
verdicts all four.

🟡 **the two boxes MEET at one place and it is worth naming** — a `detached` enroll produces a clone
whose screen feed is not yet live, which is D4's `feed-not-live` value. so E2 is not a separate
universe; it is where D4's third value comes from (case=4's honest degrade).

## .the hidden dimension the walk surfaced

`unattended × input-dirty` is the cell no free-list produced and the issue files as
**"secondary"**. the walk ranks it the **highest-cost cell the issue NAMES**:

- a daemon fires at a clone whose human is mid-type
- today's `say` writes blind, so the paste lands **on top of** the half-typed text
- the `\r` then submits **both as one garbled turn** — the human's in-flight words, destroyed,
  with no record of what they were

⇒ every failure cell the issue names loses a *nudge*. this one loses a **human's work**, and it is
the one cell the transcript can never see. it is promoted to critipath on that ground.

🔴 **and `unattended × modal` then outranks it** — that cell costs an **approval** rather than a
sentence, so its harm is not bounded by the conversation at all. the two are the box's top two by
cost, in that order, and neither is the cell the issue reports.

## .what did NOT earn an axis

| candidate | why not |
|---|---|
| 🔴 **the target's human** (a third D1 value) | **not a dispatcher, so not a value of this axis — and they are the actor who BEARS the two highest costs in the box** (a destroyed sentence, a forged approval). they take no `say` action, so they cannot vary the mechanics; what they vary is *who pays*, which is a property of a cell rather than an axis of it. ⇒ recorded in `1.vision.experience.case=_.md`'s **`borne by`** index column instead, so the box's blind spot is on the page rather than in a reader's head |
| message length | already governed by `computeCloneSubmitDelay`; it scales the submit delay and changes no verdict |
| current-turn duration | not a state to verdict — a **constraint**: it is unbounded, so `say` must report `enqueued` promptly rather than wait the turn out |
| concurrency (two says at once) | `genCloneWriteQueue` serializes them (`genCloneSocketServer.integration.test.ts` case3). each say then walks this box alone |
| output mode (tree vs json) | folded into D1 — the actor and the render it reads are one choice, not two |
| **sequence** (two says in series) | 🔴 **not an axis, and not therefore out of scope.** a sequence is a **traversal** of the box: each tick is one cell, and what a later tick does depends on the verdict an earlier one returned. so it multiplies no cell and it is where the retry hazards live (an `enqueued` re-sent doubles the nudge; a `withheld` not retried drops it). covered by **case=7** as a dense journey rather than by any cell — see `define.experience._.metric=boundary-density` |
| 🔴 **`--await <enqueue\|release>`** | **a modifier of the READING, never a state of the message.** the flag selects which row of the ordered verdict table terminates the poll — `enqueue` stops at `enqueued`, `release` waits for a transcript rise. the message walks the identical box either way; what differs is where the caller stops to watch. so it multiplies no cell, and it is a genuine discovered experience — ⇒ **itemized** in `case=_`'s modifier table (r5.n1) |
| 🔴 **`--debug`** | **a modifier of what the dispatch LEAVES BEHIND**, not of what it returns. V13 binds the stdout record to be unchanged by the flag, so by construction it crosses no cell boundary — it adds an artifact beside the verdict. ⇒ an alterpath, **itemized** (r5.n2) |
| 🔴 **`clone get`'s foreign-transcript exclusion (`exidsForeign`)** | **an experience of the READ verb, not of the say.** a `get` that finds a live peer's transcript linked under this clone reports it as foreign rather than renders it as ours. it is real and user-visible, and it varies over no axis this box declares — a say's fate is untouched by whose transcript a later `get` reads. ⇒ **itemized** (r5.n3) |

🟡 **the last three rows are a discovered-modifier class rather than a rejected-candidate one**, and the
table now holds both kinds. that is deliberate: a reader who scans for *"was this considered?"* looks
here first, and an itemized modifier is easier to find beside the axis it modifies than in an inventory
three files away. each row names where its record lives.
