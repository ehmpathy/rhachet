# case=3 — a genuine drop says the message is stuck in the input line

`operator × idle-clean × uncommitted × probe-capable` · **feel** sharp · **care** critipath
(freq: rare — the raced-submit, at an idle target · cost: a real lost message, and today's only
truthful use of the error text)

⇒ **rank 3= by boundary-density** (2 boundaries: the paste-commit race, and the input-line read that
names the recovery). this is the case today's error message *describes correctly* — and
the fix must keep it loud while it ceases to fire on case=1.

## .the narrative — the operator's pov

i run `rhx clone say @:beav-1 --what "<a 3700-char brief>"` by hand. the clone is idle.

the paste lands, the `\r` fires too early, claude has not committed the buffer yet, and the Enter
submits an empty line. my brief sits in the input box, whole, unsent.

**today** i get `MalfunctionError: message was written to the clone but did NOT leave its input
buffer — the brain never submitted it`. that text is *accurate here* — and i have learned to
distrust it, because i have seen it fire a dozen times on messages that landed fine (case=1). so i
shrug and assume it landed. it did not, and i find out an hour later.

**post-fix** i get the same severity with a verdict attached:

```
💥 MalfunctionError: the message sits in the clone input box but the submit did not take

{
  "hint": "do NOT re-send (it would append) — verify the clone accepts a submit, or retry with --await release",
  "metadata": {
    "verdict": "buffered",
    "reason": "input-region-holds-text",
    "serial": "..."
  }
}
```

🟡 message + hint are the shipped `input-region-holds-text` copy, byte-for-byte
(computeCloneSayReport.ts REASON_COPY — the authoritative rendered contract).

🟡 that frame is the repo's, not a coinage: `<glyph> <ClassName>: <message>` then a hint-first
metadata block (`asCliErrorFrame.ts:34-41`), on **stderr**, with the glyph read off the thrown
class (`asCliErrorGlyph.ts:29-32`).

the difference is not the words. the difference is that this error now **only** fires when it is
true, so i believe it — and it tells me the message sits in the box but the submit did not take, so
i do NOT blind re-send (it would append); i verify the clone or retry with `--await release` rather
than leave me to guess.

## .the bdd timeline

```
given [case3] a LIVE probe-capable clone @:beav-1, idle, input line empty
  and  a ~3700-char message (long enough that the paste commit is slow)
  and  a human operator at a second terminal

when  [t0] the operator dispatches `rhx clone say @:beav-1 --what "<3700 chars>"`
then       the probe reads `clear`, so the dispatch proceeds

when  [t1] the socket bulk-writes the content, waits computeCloneSubmitDelay, writes `\r`
then       the ack is `delivered` (the bytes reached the pty, whole)
  and      the `\r` lands BEFORE claude committed the paste — the Enter submits an empty line

when  [t2] `say` polls the transcript for its message
then       it is absent
  and      the 15s bound elapses with the message still absent

when  [t3] `say` probes to settle WHY it is absent
then       the input line reads `dirty`
  and      the LINE's needle count ROSE against the pre-write probe — our own text, uncommitted
  and      🟡 a rise rather than a presence, per `case=_` invariant 6 — and on this surface it also
           parts our stuck paste from case=2's dirty line, where the count did not move at all

then  [t4] `say` fails LOUD with the `buffered` verdict
  and      exit code = 1 (a MalfunctionError: ours to fix, not the caller's)
  and      stdout is EMPTY — a failure rides stderr (withCliOutputErrors.ts:20-22)
  and      stderr json = { class: 'MalfunctionError',
                           message: 'the message sits in the clone input box but the submit did not take',
                           hint: 'do NOT re-send (it would append) — verify the clone accepts a submit, or retry with --await release',
                           metadata: { verdict: 'buffered', reason: 'input-region-holds-text', ... } }
  and      🔴 `verdict` rides `metadata` ONLY — a top-level key is fulcrum **F09**, unruled
  and      🟡 message + hint are the shipped `input-region-holds-text` copy, byte-for-byte
           (computeCloneSayReport.ts REASON_COPY). the shipped hint already names the safe move for
           BOTH actors — do NOT re-send, verify the submit, or retry `--await release`. a PER-ACTOR
           split (an operator's "press Enter" vs a daemon's escalate) is a future refinement, NOT
           the shipped contract, so it is a design aside rather than an asserted render here
  and      the message is NOT re-sent automatically (that would double it on the line)
  and      🔴 and a re-send is unsafe for a SECOND round too, which is what makes the contradiction
           above a wedge rather than a duplicate: our needle now sits in the region, so the next
           dispatch's pre-check reads it as dirty and returns `withheld` — every tick, forever
  and      ⇒ the daemon's move is `--force` against its OWN needle: the pre-check reads the region
           as `input-region-dirty` — its one dirty slug, and a stuck needle is just dirty content —
           and `--force` overrides that dirty refusal (V3, F06). the pre-check does NOT distinguish
           our-own-needle from a human's dirt: that 4th-slug read couples to F12/Q22 (does a forced
           write overwrite the region or append to it?), unmeasured, so the shipped set is 3 slugs
```

## .how it fails safe — fast · loud · teaches the fix

| property | how |
|---|---|
| **fast** | one probe after the bound, not a second 15s wait. the diagnosis costs one round-trip |
| **loud** | exit 1, `MalfunctionError`, a named verdict. never a false `delivered` — `define.invariant.clone-say-delivery`'s third foreclosed mode |
| **teaches the fix** | it says *where* the message is (the input box) and *what to do* (do NOT re-send; verify the submit, or retry `--await release`) — a recoverable state, named as one |

## 🟡 .why this case is the reason the fix must not be a longer timeout

the cheap fix for case=1 is to raise `CLONE_SUBMIT_VERIFY_TIMEOUT_MS` from 15s. that trade is bad
in exactly this cell:

- a longer bound makes case=1's false failure **rarer**, never absent — a turn can outlast any
  fixed number
- and it makes case=3's **true** failure slower to surface, by the same amount

⇒ a bound cannot tell `not yet` from `never`, so every value of it is a choice about which of these
two cells to harm. the screen read removes the choice: case=1 and case=3 differ by one observable
fact — **is our text in the input line** — and the bound becomes a mere trigger to go look.
