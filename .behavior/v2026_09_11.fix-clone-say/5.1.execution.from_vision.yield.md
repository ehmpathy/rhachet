## .A1 — what the codebase already asserts

`getCloneSubmittedCount.ts:12-14` and `getCloneTranscriptText.ts:8-10` both state, in prose, that the brain records a USER turn to its transcript the MOMENT it is submitted. so a queued (not-yet-submitted) message is absent from the transcript by that same logic — which is the root: `say` polls this count, a queued message never ticks it, so the poll times out and reports a false failure.

this corroborates A1 from the code's own comments. it does NOT measure it. the dogfood still must prove, against a live brain, that a message dispatched into an in-flight turn is:

- absent from the transcript while the turn is in flight, AND
- present on the pty screen (the `enqueued` basis), AND
- present in the transcript once the prior turn finishes and it dispatches

## .A1 — the measurement result (CONFIRMED 2026-09-13)

`blackbox/cli/clone.transcript-lag.realbrain.acceptance.test.ts` ran vs a live claude (haiku), 28s, 4 of 4 assertions passed:

1. M1 was submitted — the brain was genuinely busy on an in-flight turn
2. the queued M2 rendered on the pty screen (`bg.getOutput()` held it)
3. **A1 core — M2's transcript count was 0 while it sat queued** behind M1's turn
4. the transcript LAGGED — M2's count rose to ≥ 1 only after M1's reply finished and M2 dispatched

⇒ the diagnosis is measured, not testimony (V12 discharged). the false `MalfunctionError` is exactly `getCloneSubmitLanded` as it polls a transcript that a still-queued message never reaches. the read-channel design premise holds. the test stays as a permanent clamp: a future brain-cli that wrote a queued message to the transcript at once would turn assertion 3 red.

## .the emulator contract (confirmed from `@xterm/headless@6.0.0` `.d.ts`, 2026-09-13)

the read API the screen feed + `readScreen` build against — settled once, so the build does not re-derive it:

- **construct** — `new Terminal({ cols, rows, scrollback, allowProposedApi: true })`
  - 🟡 `.buffer` is a PROPOSED api — a `.buffer` read THROWS without `allowProposedApi: true` (build gotcha)
  - `scrollback` defaults to 1000 (Q14)
- **feed** — `write(data: string | Uint8Array, callback?: () => void): void`
  - parse is ASYNC — `await` the callback before a buffer read, or the read races the parse (Q25)
  - `write` returns void and does not throw on malformed ansi — but the listener stays fault-isolated per V16
- **read a row** — `terminal.buffer.active.getLine(y)?.translateToString(trimRight?, start?, end?)` returns the rendered row (Q15 confirmed)
  - cursor: `buffer.active.cursorX` / `cursorY` / `baseY` / `length`
- **resize** — `resize(cols: number, rows: number): void` (V14 — re-flow on every pty resize)
- **cost** — pure js, no native addon (Q27); ~1.96MB unpacked, 7 files (Q18)

## .the measured screen (real haiku v2.1.87, 120x40 — todo 2 dogfood, 2026-09-13)

raw grids: `5.1.execution.research.screens.captured.md`. the structural conclusions the build rests on:

### the input box locator

the brain draws the input box at the viewport foot as a three-row band:

```
──────────────  (a full-width row of ─, 120 cols)
❯ <box content>
──────────────  (a full-width row of ─)
```

⇒ `readScreen` locates the input region as the `❯`-led row(s) between the LAST pair of full-width `─` rules near the viewport bottom. `focus: 'input'` = that band is present.

### clear vs dirty — the box content

| state | the `❯` box holds | classify |
|---|---|---|
| idle | the PLACEHOLDER — `Try "write a test for <filepath>"` | `clear` |
| empty | `❯` alone, no text after the glyph | `clear` |
| dirty | real content (`❯ DIRTY-mu03aque`), not the placeholder | `dirty` |

⇒ `input: 'dirty'` = box content is non-empty AND not a known placeholder (`Try "…"`). the placeholder is grey in the tui but `translateToString` drops color, so it reads as the literal `Try "…"` string — match on that prefix.

### the transcript / turn markers

- `❯ <text>` on a scrolled-up row = a SUBMITTED user turn
- `● <text>` = an assistant response turn (its first row)
- a `✻`-led spinner row (a status verb + `(…)`) = the brain is BUSY, a turn in flight — the enqueue-vs-release discriminator
- `countOnScreen` = a count of `●`/`❯` turn-rows on the grid

### 🔴 buffered vs enqueued CANNOT be read from one snapshot — the rise rule is CONFIRMED

state B (dirty, unsubmitted) and state C (a message dispatched into a busy turn) BOTH render as `❯ <text>` in the same box band. a single grid snapshot cannot part them.

⇒ the design's pre/post baseline is not a nicety, it is FORCED: probe the box before the write, probe after, and read the RISE — box still holds our text → `buffered`; box went clear AND a turn-count rose → `enqueued`/`released`. this is exactly the vision's *"every condition is a RISE, never a presence"*, now measured.

### 🔴 Q10 — a raw `\n` SUBMITS a line (the soft-newline mandate, measured)

state D dispatched `ML-…\nSECOND-LINE\nTHIRD-LINE` RAW (not through `asCloneDispatchFrame`). the brain submitted each line as a SEPARATE turn — `THIRD-LINE` landed as its own `❯ THIRD-LINE` turn, the earlier lines consumed before it.

⇒ confirms `asCloneDispatchFrame` MUST map interior newlines to soft-newlines, and `readScreen` classifies a multi-row REGION (the soft-newline-joined band), never a single row (V — the region rationale).

### the modal signal (Q8)

the trust menu is pre-accepted so it was not captured, but its signature is known from `driveTrustMenus`: a `❯ <Option>` menu + a `confirm` footer + a `Yes,…folder`/`No, exit` choice list — a MENU of `❯` options, distinct from the input box's single `❯` between rules. `focus: 'modal'` = a `❯`-led option menu with a confirm footer, no input-box band.

🟡 the **auth-conflict banner** (`⚠Auth conflict: Both a token … and an API key …`) is NOISE, not a modal — a warn region above the box. `readScreen` must not mistake it for a modal (it has no `❯` option menu, no confirm footer).

### Q11 — render latency floor ≈ 28ms

m2 appeared on the rendered grid 28ms after `sayClone` resolved. so a `--await` poll interval of ~100-200ms clears the floor comfortably; the 15s transcript bound is no longer the decider.

### the daemon reads the INNER pty (cleaner than this capture)

this dogfood fed the OUTER pty (rhachet emits + brain tui merged), so the scrollback carries rhachet's `{"outcome":"baked",…}` handoff + an auth banner. the daemon feeds the INNER pty (brain output only) into the emulator, so the box-locator (last `❯` band near the viewport foot) is unaffected by that scrollback noise.

## .todo 5 — the `clone get` input-state read, over the socket (DONE 2026-09-13)

the read channel now reaches the daemon's `readScreen` over the wire. five files, all green (socket integration 32/32, types clean):

- **`socket/asCloneGetReply.ts`** — the reply type + parse. `CloneGetReply = { probe: 'capable'; state: CloneInputState } | { probe: 'unsupported'; reason: 'feed-not-live' }`. `asCloneGetReply({ line })` throws a `MalfunctionError` on bad json or an unknown probe — the read never fails silent (`rule.forbid.failhide`).

- **`socket/getCloneInputState.ts`** — the client. connect, write one `{ kind: 'probe', needle }` frame, read exactly one reply frame (the `asCloneDispatchFrameSplit` reassembler), parse, `replyTimeoutMs ?? 5000` bound (a `MalfunctionError` on timeout). the caller-side param stays `message` for symmetry with `say`, mapped to the wire `needle` field; empty reads focus + input only.
- **`socket/genCloneSocketServer.integration.test.ts`** — case9 (a LIVE screen → `probe: capable`, the classified state matches the rendered grid, and the capture sink stays empty — a probe writes NO bytes to the pty) + case10 (the default `feed-not-live` → `probe: unsupported`, no write). a real socket roundtrip through `getCloneInputState`, never a mock.

## .todo 6 — the six-verdict `say` + server-side dequeue pre-check (DONE 2026-09-13)

the six-way decision is pure and in one place, and the refusal is decided where the read is current — at dequeue, server-side. all green (verdict unit 24 · report unit · precheck unit · write-queue · socket integration incl. case17):

- **`socket/computeCloneSayVerdict.ts`** — the pure six-way map (`released`/`enqueued`/`buffered`/`withheld`/`absent`/`unreadable`) from one `CloneSayObservation`. ordered by strength, first match wins, `absent` the residual. `withheld` first (a refusal means no write, so no rise to read); `released` (transcript rose) over `enqueued` (box) over `buffered`; `unreadable` when the feed was never live. a new verdict is a compile error here, never a silent fall-through.
- **`socket/computeCloneDispatchPrecheck.ts`** — the dequeue gate. a `focus` whitelist: proceed ONLY on `focus: 'input'` + clear region (or dirty-and-forced). the two focus refusals (`modal-holds-focus`, `focus-unrecognized`) are checked FIRST, so `--force` can NEVER reach a modal (V3, case=6) — it overrides only `input-region-dirty`.
- **`socket/computeCloneSayReport.ts`** — the rendered face: `released`/`enqueued` on stdout (exit 0); `withheld` on stderr as `constraint` (exit 2, a caller MAY amend); `buffered`/`absent`/`unreadable` on stderr as `malfunction` (exit 1). one message + safe-action hint per reason slug.
- **`src/.test/assets/stubBrainCli.cjs`** — renders a minimal `❯`-fenced input box so the new live-screen pre-check classifies the stub `input`/`clear` and a say reaches the child (else the boxless stub read `unrecognized` and the pre-check withheld every write).
- **`socket/genCloneSocketServer.integration.test.ts` [case17]** — the dequeue pre-check end-to-end: withheld on a dirty region (no bytes written), forced override (bytes written), modal-under-force still withheld (the safety guarantee, over a real socket).

## .todo 7 — the additive machine channel (DONE 2026-09-13)

- **`getCloneSayObservation.ts`** — polls the transcript (the `released` basis) and the rendered screen (the `enqueued`/`buffered` basis) until the `--await` target state or the bound. the first poll cycle is reserved for the transcript to settle, so an idle say never mis-reads an in-flight release as `enqueued` (case=5). every field is a RISE vs a pre-dispatch baseline.
