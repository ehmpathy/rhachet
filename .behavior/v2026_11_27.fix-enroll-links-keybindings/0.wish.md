# wish: an enrolled clone gets the human's keybindings

## .outcome
when rhachet enrolls a clone, it links the human's `keybindings.json` into the clone's claude config dir, beside the login link it already makes. where the source file is absent, the link is skipped, with no error. an enrolled clone then shows and honors the same submit key a bare claude shows.

## .why
an enrolled clone names ctrl+x ctrl+s as its submit key, while a bare claude shows ctrl+enter. ctrl+enter sends in both, so the harm is a wrong hint to the human at every enrolled pane.

## .done means
- an enroll with a source keybindings.json leaves a link to it in the clone config dir
- an enroll with no source keybindings.json leaves no link and exits as before
- a re-enroll is idempotent: the link is found, never doubled or clobbered with other bytes
- a test per case, red without the change, green with it
- a pr opened and green on `--watch`; no merge, no release

## .bounds
- no merge, no `--apply`: the commander reviews the pr

## .contracts
- subrock://rhachet/ergonomics

this section rides every dispatch; the sprout adds it to the wish.

  - e.g. `- <the decision> — <where it was made> — overturned by <the stat or read>`

- a pushback with no stat or read behind it is no pushback: keep the prior decision, or go get the read
