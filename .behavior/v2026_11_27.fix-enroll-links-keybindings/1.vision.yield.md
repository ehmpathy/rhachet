# 1.vision: an enrolled clone gets the human's keybindings

## .what this builds

the brain dir layout findsert (`setBrainDirSettingsLayout`) lays two more arrows, beside the grove
arrows, whenever `~/.claude/keybindings.json` is a file:

```
<brainDir>/keybindings.json               -> .home/.claude/keybindings.json      # relative
<brainDir>/.home/.claude/keybindings.json -> <home>/.claude/keybindings.json     # the one name for this box
```

no source file → no arrow is laid. our arrows from a prior run are removed; a foreign arrow, real
file, or dir at the top name is not rhachet's and stays. `.home/` is rhachet's own namespace, so
whatever sits at the home name goes. an arrow already in place is left be.

## .why it works

- claude 2.1.332 joins `keybindings.json` onto a dir (`Fn(rt(),"keybindings.json")` in the bundle),
  and the evidence says that dir is its config dir (see the first `[research]` row). a clone spawns
  with its actor's brain dir as that dir (`asBrainCliSpawnEnv.ts:99`), so today a clone reads no keybindings and
  shows claude's default submit hint. the arrow hands it the human's file
- the layout findsert is the one op every actor's brain dir passes through — `enroll`, `init`, and the
  derived-actor sync — so every actor, the repo actor included, gets the same two names
  (`define.brain-dir-layout-is-one-for-every-actor`)
- the brain dir `.gitignore` is an allowlist with `/*` first, so both names stay out of git with no
  `.gitignore` edit; no machine path is committed (`rule.forbid.machine-names-in-committed-config`)
- a symlink, not a copy: a home edit reaches every clone at its next read

## .the outcome world

| | before | after |
|---|---|---|
| bare `claude` | hints the human's submit key | same |
| enrolled clone | hints `ctrl+x ctrl+s`, a default key the human's file unbinds | hints the human's submit key |
| box with no keybindings file | default hint | default hint, no new file, no notice |

the aha: two panes, one keystroke, one hint — the clone reads like the human's own claude.

## .mental model

a human says: *"clones now use my keyboard shortcuts."* the analogy is the settings grove — the
clone borrows the human's file by reference, the way it already borrows `~/.claude/settings.json`.

## .evaluation

- **solves the goal**: the one cause of the wrong hint (no keybindings file in the config dir) is removed
- **pro**: one findsert, every actor, no git noise, live edits propagate
- **con**: a clone that runs `/keybindings` on a box with no source writes its own real file
  (`/keybindings` writes `ifAbsent`, so it never replaces an arrow). if the human later creates a
  source, the next findsert replaces that clone file with the arrow (fulcrum F2)
- **edge**: a source that is a dir, or an arrow left by a removed source, never yields an unreadable
  arrow — see the inventory

## .open questions & assumptions

- **[research]** does claude read `<configDir>/keybindings.json`? the bundle shows
  `Fn(rt(),"keybindings.json")`; `rt` is a minified local whose definition was not found. the
  evidence is specific: the human's file on this box holds `"ctrl+x ctrl+s": null`, which unbinds
  the exact key the clone hints, so a clone that read it could not show that key. proof owed at
  verification: a real clone pane shows the human's hint after the change
- **[research]** does the hot-reload watcher see an edit to the arrow's target? it polls every
  2000ms, and a poll stats through a link. proof owed at verification; if it fails, the edit lands
  at the next spawn instead (case=3 [t1] weakens, the cure holds)
- **[answered]** does claude follow the arrow on read? yes: the loader is a node read, which follows
  links, and the settings grove has relied on the same for `settings.json`
- **[answered]** could a gate hide the file anyway? `if(!NEe()||Xr("keybindings"))` skips user
  customization; it is open on any box where a bare claude honors the file, which is the box the
  wish describes
- **[answered]** the wish's premise is stale: it names "the login link it already makes". no such
  link exists since the cure that retired the 1.48.0 per-actor login (`invokeEnroll.ts:727-732`);
  the arrow sits beside the settings arrows instead (fulcrum F3)
- **[answered]** why no arrow when the source is absent? an arrow to an absent file is harmless to a
  read (ENOENT → defaults) and would let a live clone pick up a file the human creates later. but
  `/keybindings` in a clone writes a template when the file is absent, and the bundle does not show
  whether that write follows the arrow; if it does, a clone would create the human's home file
  unasked. the wish's mandate rules that out; the cost is the "source created after spawn" time row, cured by
  the next `rhx init` or enroll
- **[answered]** a human whose bare claude uses a custom `CLAUDE_CONFIG_DIR` keeps their file outside
  `~/.claude`; the clone misses it, as it misses their grove today. out of scope, consistent with the grove
- **[answered]** which docs move? `define.brain-dir-layout-is-one-for-every-actor` lists the layout
  and gains the two arrows; `rule.forbid.brain-dir-layout-divergence` names "the box decides" for the
  grove and extends it to `keybindings.json`. both land with the code
- **[wisher]** the fulcrums, each best-guessed with a clean rework, for the commander's review at
  the pr: `.fulcrums/inventory.of=fulcrums._.md` — F1 two arrows via `.home/` (75%), F2 a real file
  is replaced (70%), F3 the layout findsert hosts it (90%)
