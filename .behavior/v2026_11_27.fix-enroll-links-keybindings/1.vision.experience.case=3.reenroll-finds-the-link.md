# 1.vision.experience.case=3.reenroll-finds-the-link

> critipath · happy · cell `file × our-arrow`

## .narrative

kai enrolls a second clone of the same actor, then runs `rhx init`. each run meets both arrows
already in place, aimed where they belong, and leaves them be: no swap, no copy, no second link,
no effect row. kai's `keybindings.json` bytes are never read into the brain dir — the link is a
reference, so a later edit kai makes at home reaches every clone of every actor at its next read.

## .bdd sketch

```
given a brain dir the layout findsert already ran on, with ~/.claude/keybindings.json present
  when [t0] the layout findsert runs again
    then both arrows are unchanged (same target, same inode)
    then the effects hold no row for keybindings
  when [t1] the human edits ~/.claude/keybindings.json
    then a read of <brainDir>/keybindings.json yields the new bytes, with no re-enroll
```
