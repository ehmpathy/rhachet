### #1 — no timeout on the say/get ack round-trip — FIXED (the review's top item)
the review is right and this is a real fail-fast violation: sayClone AWAITs the ack with no bound, so a
server that accepts the connection but never writes the ack (crash mid-write, deadlocked pty, wedged
brain) hangs a cron/comms caller forever with no signal.
- fix: the ack await is now BOUNDED (default 5s IsoDuration); a timeout aborts + FAILS-LOUD
  MalfunctionError (exit 1) that names the wedged-clone cause + the fix (check `get`, or re-enroll).
  covered by a sayClone.integration ACK TIMEOUT case (a silent-server stub → rejects within the bound,
  never hangs).
- verdict: FIXED — the caller can no longer wedge indefinitely.
