## blockers

### #1 — TOCTOU race in genClone findsert-by-slug (concurrent same-actor bake) — FIXED
the review is exactly right: two concurrent `enroll --as @:driver` of the SAME actor both observe
"no owner" in the find-first read (`getOneCloneByRef(slug) → computeCloneSlugDecision`), both classify
`bake-fresh`, both mint distinct serials + sockets, and setCloneSlugIndex's collision guard only fired
on a DIFFERENT-actor claim — so last-write-wins left the loser a live, fully-spawned, socket-bound
clone reachable only by a serial no caller holds. a real orphan.
- fix: the AUTHORITATIVE winner-election is now an **atomic exclusive `symlink(2)`** in
  setCloneSlugIndex — it FAILS with EEXIST if `.slugs/<slug>` already exists, so it is lock-free and IS
  the serialization point. the FIRST bake to create the symlink wins; the loser gets EEXIST-same-actor
  and, in genClone, **self-reaps** (unlink its just-bound socket via delFileSync + remove its serial
  dir) and REUSES the winner the index now names, via a re-read of `.slugs/<slug>` → the won serial. so
  `--as @:driver` converges to ONE reachable handle; the loser is never left live-but-unreachable.
- landed: setCloneSlugIndex.ts (atomic exclusive symlink), genClone.ts (loser-reap), covered in
  genClone.integration.test.ts FINDSERT-BY-SLUG + the winner-election path.
- verdict: FIXED — the exact hazard named is closed by the atomic-symlink election + self-reap.

### #2 — Clone hydration enrichment (actor + historyDir) has no single named seam — FIXED
the review is right and it names the precise defect class the blueprint already extracts four other
seams for ("one decision re-derived per caller, drifts"). `Clone.actor` + `Clone.historyDir` were
DERIVED-NOT-PERSISTED, attached by each reader on its own after getCloneIdentity — one omitted
attach in a future hydrator (the dream's wake/fork) would yield a Clone with an undefined `actor` ref,
silently, since no type-checker guards a convention-populated field.
- fix: extracted **`hydrateClone({ actorDir, serial }) → Clone`** — the ONE seam that composes
  getCloneIdentity (parse) + reconcileCloneSlug (display slug) and attaches `actor` (RefByPrimary from
  the parent `actor.via.hash=` segment) + `historyDir`. EVERY reader (getAllClonesForActor,
  getOneCloneByRef, getAllClonesGroupedByActor) now composes it — a Clone is never hand-assembled, so
  the enrichment cannot drift caller-to-caller.
- landed: hydrateClone.ts + hydrateClone.integration.test.ts (dogfooded cross-reader field-equality),
  the readers updated to compose it, Clone.ts DERIVED-NOT-PERSISTED note updated to name the seam.
- verdict: FIXED — exactly the extract-and-compose the review asked for.

### #3 — slug-index-write vs socket-bind order (a second startup race) — FIXED
the review is right that this is the identical race SHAPE as i011-r11-5, one write later: a window
where identity.json is live + serial-enumerable but `.slugs/<slug>` is not yet written, so a
`say @:<slug>` in that window gets a false "unknown slug" for a live clone.
- fix: formalized the write sequence as a NAMED one-directional invariant — socket LISTENING →
  identity.json (socketEligible=true) → `.slugs/<slug>` LAST. so **slug-resolvable ⟹ live +
  enumerable-by-serial**, never the reverse. the reverse lag is BENIGN + truthful, NOT a published
  lie: an absent `.slugs/<slug>` is a TRUE NEGATIVE ("this handle is not yet published"), self-heals
  on retry once enroll returns — the KEY difference from i011-r11-5, where socketEligible=true before
  bind was a FALSE POSITIVE. serial-works-while-slug-lags for the same clone is two truthful answers
  (serial baked, slug not yet published), by design, slug last.
- landed: the SLUG-INDEX ORDER note in the genClone codepath order block + a genClone.integration
  SLUG-INDEX ORDER assertion (the invariant at every instant + the benign reverse-lag dogfooded).
- verdict: FIXED — named + tested, like every other race in the doc.
