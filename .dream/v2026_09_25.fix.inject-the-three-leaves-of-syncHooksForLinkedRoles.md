# 🌙 dream: inject the three leaf collaborators of `syncHooksForLinkedRoles`, so its unit needs no `jest.mock`

- kind: fix
- owner: `ehmpathy/rhachet` (this repo)
- caught 2026-09-25

## .the cue that fired

a peer review lane (`5.3.verification` i003, r9.n1) read
`src/domain.operations/init/hooks/syncHooksForLinkedRoles.test.ts:10-12` and named its three
`jest.mock` calls against `rule.forbid.unit.remote-boundaries`, whose enforcement clause reads
*"mock usage in unit tests = **BLOCKER**"*.

the lane then conceded, in the same report, that the rule's **remote-boundary** clause is not
violated here — these are in-process leaves, not `fs`/db/http — and offered a refutation as
acceptable. so the concern was disputed for this round (`F45`), and the compliant shape is owed
as its own work.

## .the gap, precisely

the orchestrator reaches its three leaves by **direct import**, so a unit that wants to force a
leaf failure has no seam but `jest.mock`:

```ts
jest.mock('@src/domain.operations/brains/getLinkedRolesWithHooks');
jest.mock('@src/domain.operations/brains/pruneOrphanedRoleHooksFromAllBrains');
jest.mock('@src/domain.operations/brains/syncAllRoleHooksIntoEachBrainRepl');
```

checkable: the three `jest.mock` lines are at the head of that file, and
`rule.forbid.unit.remote-boundaries` names **fakes** + **dependency injection** as the sanctioned
alternative to exactly this.

⚠️ the two other doors are both worse, which is why this is a dream rather than a quick fix:

- a move to `.integration.test.ts` **destroys the subject** — the case exists to prove the
  collector gathers N leaf failures into one operator report, and a real leaf offers no seam to
  fail at, so the branch would go uncovered
- a bare deletion of the mocks leaves the case a happy-path walk

## .the shape of the fix

the leaves join the orchestrator's injected surface, so the test supplies **fakes** rather than
mocks:

1. widen the orchestrator's second argument (it already takes a `ContextCli`) so the three leaves
   arrive as injected deps — a `deps` sub-object keeps `ContextCli` itself unpolluted, since these
   are collaborators rather than ambient context
2. default each dep to its real implementation at the CALL SITES, never inside the operation — an
   in-body default re-creates the direct import the injection exists to remove
3. the unit then passes three fakes, each of which throws on demand. no `jest.mock`, and the
   error-collection branch stays covered
4. sweep the callers: the signature is read by every one, so this is the ripple that made the fix
   dirty — enumerate them first with a grep for `syncHooksForLinkedRoles(`

🟡 the leaves each keep their own direct coverage, so their tests do not move.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** step 4 is the problem — this is a signature change on a production
orchestrator with live callers, landed from a **verification** stone whose diff is tests and a
yield. it ripples well outside the change this route opened, and to reverse it later is a second
signature change plus an unwind of any caller written against the new shape in between
(`rule.always.fix-forward-under-scouts-honor`, the dirty branch).

the judgment to defer is itself recorded, per the same rule, as `F45`.
