## .the gap, precisely

`blackbox/cli/__snapshots__/keyrack.list.acceptance.test.ts.snap`, the `case-reach t0` row:

```
🔐 keyrack list
   ├─ testorg.test.API_KEY
   │  ├─ env: test
   │  ├─ org: testorg
   │  ├─ mech: PERMANENT_VIA_REPLICA
   │  └─ vault: os.direct
   └─ testorg.test.API_KEY
      ├─ env: test
      ├─ org: testorg
      ├─ reach: beav@ehmpathy.com
      ├─ mech: PERMANENT_VIA_REPLICA
      └─ vault: os.direct
```

**two rows, one label.** the entries are parted solely by a `reach:` line nested three lines deep,
and they sort adjacent — so a human who scans the tree reads a duplicate, not a distinction.

🚨 **the machine twin already solved this.** the `--output json` contract appends `@<reach>` to the
key, so the two entries carry distinct identifiers there. so the human surface is the one that
lost the discriminator, and the fix is a projection the json render already performs.

that asymmetry is what makes it worth a repair rather than a shrug: `rule.forbid.ambiguous-labels`
grades *"an output value with no unit/state label where its sense is ambiguous"* a blocker, and the
`reach` value IS the state label the human row omits from its title line.

## .the shape of the fix

1. find the human tree's row-label render in `keyrack list` (its json peer already appends the
   reach, so the projection exists — reuse it, never re-derive it, so the two surfaces cannot drift)
2. render the label as `slug@reach` where a reach is present, bare `slug` where it is absent
3. resnap `keyrack.list.acceptance.test.ts.snap` and **read** the diff — the whole point is that a
   human can tell the rows apart, so a human must confirm they now can
4. check whether any other human-faced keyrack render (`keyrack status`, `keyrack get`) shares the
   omission — `rule.forbid.host-specific-cures-in-hints`'s own lesson was *"check every row, never
   only the guilty one"*, and the same discipline reads here

⚠️ **one owner, never a per-render patch.** if the json render's `slug@reach` projection is inlined
at its call site rather than named, the repair owes an `asKeyrackKeyLabel`-shaped transformer first
— otherwise the third render repeats the defect (`rule.forbid.decode-friction-in-orchestrators`, and
the `asCloneAddressHuman` precedent this repo already paid for).
