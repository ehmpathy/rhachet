# 🌙 dream: learn whether claude's `/keybindings` writes through a dead arrow

- kind = fix
- owner = rhachet
- caught 2026-11-27, on `v2026_11_27.fix-enroll-links-keybindings`

## .the cue that fired

a peer review asked: once the human deletes `~/.claude/keybindings.json`, the clone's arrow dangles
until the next findsert. if claude's `/keybindings` opens the file with create, a clone would write
the human's home file through that dead arrow.

## .the gap, precisely

the grove chain ends inside the brain dir on a box with no grove, so no write can reach the home.
the keybindings chain cannot end there: its whole point is to aim at the home. between the delete
and the next `rhx init` or enroll, a dead arrow stands. whether claude follows it with create is
unmeasured.

## .the shape of the fix

1. measure: in a clone with a dead arrow, run `/keybindings`, and see where the file lands
2. if it lands in the home: decide whether that is harm (the human asked a clone to make the file,
   and the home is where a bare claude would write it) or a leak
3. if a leak: remove the dead arrow at clone spawn as well as at findsert

## .why it is not done in this round

it needs a live tui clone, a slash command driven by hand, and a judgment on whether the home write
is the human's intent. no part of the wish depends on it: the layout removes a dead arrow at every
findsert.
