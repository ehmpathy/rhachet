## .the gap, precisely
- trace lines carry no pid, so seats that share one trace file interleave
- `rhx hooks.dispatch.cost` derives the before shape only from a saved settings file
- the dispatcher never ran on a real bash 3.2 (only the bash < 5 branch, via `RHACHET_HOOKS_DISPATCH_SOURCE=0`)
- `IFS= read -r -d ''` reads a pipe one byte per syscall; a large Write payload's cost is unmeasured
- a clone's dispatcher settings, hand-added hook retention through the cli, and per-event sync rows
  are asserted but not snapped

## .the shape of the fix
1. a ` · pid=<n>` column on each trace line, masked in the `[t25]` snapshot
2. `hooks.dispatch.cost` derives the before shape from the manifest, so no saved settings file is
   needed (its integration test landed at 5.3)
3. a macos ci job that runs `hooks.dispatch.acceptance` under `/bin/bash` 3.2
4. measure a ~1 MB Write payload through `hooks.dispatch.cost`; if the read shows, read stdin in
   blocks (`read -N` on bash ≥ 4.1, a fallback below)
5. snapshots for the three reader views
