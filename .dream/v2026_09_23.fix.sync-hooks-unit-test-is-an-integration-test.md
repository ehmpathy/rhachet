# 🌙 dream: `syncHooksForLinkedRoles.test.ts` is an integration test under a unit test's name

- **kind** = fix
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-23, in the `3.3.1.blueprint.product` self-review `has-thorough-test-coverage`

## .the cue that fired

the blueprint declared F8's actor-walk coverage as `[~] syncHooksForLinkedRoles.test.ts`. before i
accepted that, i checked what tier the file actually sits at — and found it crosses the boundary it
is named to stay inside.

## .the gap, precisely

`src/domain.operations/init/hooks/syncHooksForLinkedRoles.test.ts` is named `.test.ts`, so jest runs
it in the **unit** tier. measured in the file:

| line | what | the rule it breaks |
|---|---|---|
| 62 | `genTempDir({ slug: 'sync-hooks-err' })` | `rule.forbid.unit.remote-boundaries` — *"if it touches the outside world, it's not a unit test"* |
| 115 | `genTempDir({ slug: 'sync-hooks-discover-err' })` | same |
| 10 | `jest.mock('@src/domain.operations/brains/getLinkedRolesWithHooks')` | same rule — *"mock usage in unit tests = **BLOCKER**"* |
| 11 | `jest.mock('…/pruneOrphanedRoleHooksFromAllBrains')` | same |
| 12 | `jest.mock('…/syncAllRoleHooksIntoEachBrainRepl')` | same |

⇒ **two distinct blocker-grade violations in one file**: a filesystem boundary, and three mocks.

## 🔴 .why it matters beyond tidiness

`npm run test:unit` is supposed to be fast, deterministic, and parallel-safe. a temp-dir write in
that tier makes it none of the three — and the mocks mean the suite verifies the mock setup rather
than the orchestration. so the file reports green for a codepath it does not exercise.

**and it actively misled this blueprint.** the file's coverage gap read as *"nobody got around to a
test for the actor walk"*, when the truth is *"the actor walk cannot be tested at this tier."* a
blueprint that trusted the first read would have declared new coverage in the one place it is
forbidden.

## .the shape of the fix

1. **rename** → `syncHooksForLinkedRoles.integration.test.ts`. the `genTempDir` cases are legitimate
   integration tests; only the tier label is wrong.
2. **drop the three `jest.mock` calls.** `rule.forbid.integration.mocks` forbids them at the
   integration tier too, so this is the real work. the three collaborators are already injectable or
   can be — replace each mock with a **fake** passed through context
   (`rule.require.dependency-injection`).
3. if a collaborator resists injection, that resistance **is** the discovery — record it, and the
   operation is the defect rather than the test.

⚠️ the order matters: rename first (the `genTempDir` cases go green immediately at the right tier),
then unpick the mocks one at a time. a combined change cannot be bisected.

## .why it is not done in this round

**SAFE** — ✅ yes, it touches no production code.
**CLEAN** — 🔴 **no.** the mock-removal reaches into three operations this wish never opened, and the
wish's bound is explicit: *"do not widen into unrelated boot work the refactor may have left nearby
— catch it as a dream instead."*

⇒ so the deferral is the wish's own instruction rather than a judgment call, and the blueprint routes
around it cleanly: F8's coverage lands in a **new** `syncHooksForLinkedRoles.integration.test.ts`,
which needs no edit to the mis-tiered file at all.
