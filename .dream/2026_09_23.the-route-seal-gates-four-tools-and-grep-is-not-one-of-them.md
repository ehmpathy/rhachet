⇒ **a control nobody tested from the outside is a control nobody has.** the cue is not a rule I

## .the gap, precisely

`route.mutate.guard.sh` is a `PreToolUse` hook. its stated job, verbatim from its own docblock:

> *prevents drivers from: peeking ahead at future stones (defeats bounded focus) · **reading guard
> files (enables gaming review criteria)** · mutating `passage.jsonl` directly*

its second statement, at line ~50:

```bash
if [[ "$TOOL_NAME" != "Read" && "$TOOL_NAME" != "Write" && "$TOOL_NAME" != "Edit" && "$TOOL_NAME" != "Bash" ]]; then
  exit 0
fi
```

⇒ **an allowlist of four, and `exit 0` — allow — for every other tool in the harness.**

| the tool | gated? | can it read a sealed file's contents? |
|---|---|---|
| `Read` · `Write` · `Edit` · `Bash` | ✅ yes | — |
| 🔴 `Grep` (`output_mode: content`) | 🔴 **no** | 🔴 **yes** — a `.` pattern with a wide `head_limit` returns the file |
| 🔴 `Glob` | 🔴 **no** | filenames, so it defeats the peek-ahead half on its own |
| `Agent` (a subagent with its own `Read`) | 🔴 **no** at the dispatch | the subagent's own `Read` may be gated; the hook does not reason about it |

🔴 **the `Grep` row defeats the whole control, not a corner of it.** the seal's sharpest claim is
about **guards** — that a driver who reads one can game the review criteria — and a guard is a small
YAML file, which is the easiest possible target for a content grep.

## 🟡 .what this is NOT

it is **not an exploit, and not a driver-conduct defect.** a driver who greps a guard has broken no
rule they could have read — the seal is the mechanism that carries that intent, and a mechanism
that permits an act is not a rule against it. ⇒ **this is a hole in the tool, and the fix is the
tool's.**

it is **not urgent in the shipped-harm sense.** no user suffers; the cost is that a bounded-focus
guarantee the driver role advertises is not enforced.

## .the shape of the fix

🔴 **invert the list — a DENYLIST of tools known to be harmless, never an allowlist of tools known
to be dangerous.** an allowlist of tool names goes stale the day the harness adds a tool, and it has
already gone stale twice over:

```bash
# the default must be REFUSE for any tool that names a path or a pattern.
# an allowlist cannot be kept current against a harness that adds tools.
case "$TOOL_NAME" in
  Read|Write|Edit|Bash|Grep|Glob|NotebookEdit) ;;   # gated
  *) exit 0 ;;                                       # a tool with no path surface
esac
```

then extract the path from each tool's own input shape — `file_path` for `Read`/`Write`/`Edit`,
`command` for `Bash`, **`path` + `glob` for `Grep`, `pattern` + `path` for `Glob`**.

### what must be clamped

- `[caseN]` a `Grep` with `output_mode: content` against a `*.guard` in the bound route ⇒ **refused**
- `[caseN]` a `Glob` whose pattern reaches the bound route's `.route/**` ⇒ **refused**
- `[caseN]` a `Grep` against `src/**` ⇒ **allowed**, so the seal stays a floor rather than a cap
- proved by revert (`rule.require.clamp-edge-cases`): restore the four-name allowlist and the first
  two cases MUST go red

🟡 **and the deeper repair is worth a line: a seal that enumerates TOOLS is on the wrong axis.** what
the seal protects is a set of **paths**; what it inspects is a set of **tool names**. the first is
closed and the driver role owns it; the second is open and a harness vendor owns it. ⇒ every future
tool is a hole until somebody adds its name, which is a maintenance shape that cannot converge.

## .why it is not done in this round

**SAFE 🔴 / CLEAN 🔴** — and the owner is not this repo.

- 🔴 **not safe** — it tightens a control that fires on **every tool call of every driver on every
  route**. a path-extraction bug in the new `Grep`/`Glob` arms would block legitimate work
  repo-wide, and the blast radius is every route in every repo that enrolls the driver role
- 🔴 **not clean** — `route.mutate.guard.sh` lives in `ehmpathy/rhachet-roles-bhrain`, and it is
  reached here through `node_modules` as a **symlink into a version-pinned store**
  (`define.invariant.a-symlink-under-agent-is-foreign`). an edit here is wiped by the next
  `pnpm install` and is a published artifact of another repo

⇒ **a tree adopts only what is scoped to itself** (`rule.always.scope-onetime-lessons-to-the-behavior`),
so this is a **reseed** rather than a fix. 🟡 `.dream/` is a local queue — **caught is not
dispatched**, and the seed still owes a push to the owner repo.
