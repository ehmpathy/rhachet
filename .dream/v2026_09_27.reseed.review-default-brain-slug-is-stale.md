# 🌙 dream: the review skill's default brain slug no longer resolves

kind = reseed · owner = rhachet-roles-bhrain · caught 2026-09-27

## .the cue that fired

every level-1 peer lane on `5.1.execution.from_vision` returned `unreadable`. each given's stderr held
`BrainChoiceNotFoundError: brain not found: fireworks/deepseek/v4-flash`.

## .the gap, precisely

`rhachet-roles-bhrain@0.37.2` hardcodes `fireworks/deepseek/v4-flash` as its default in three places:

- `dist/contract/cli/review.js:40` — `DEFAULT_BRAIN`
- `dist/contract/cli/review.by.js:17` — `DEFAULT_REVIEW_BRAIN`
- `dist/domain.operations/route/genReviewBrainSupply.js:34` — `FIXED_FALLBACK_BRAIN`

the installed brain supplier lists `fireworks/deepseek/flash/v4.1` and `fireworks/deepseek/pro/v4`, and
no `v4-flash`. so any guard lane that omits `--brain` crashes before it reads a file.

## .the shape of the fix

in `rhachet-roles-bhrain`: repoint the three constants to a slug the current brain supplier exposes
(`fireworks/deepseek/flash/v4.1`), declared once and imported by all three. add a test that resolves
the default against the installed brain registry, so a rename upstream fails there and not in a guard.

## .why it is not done in this round

it belongs to another repo; this tree adopts only what is scoped to itself, and the wisher asked that
no task be dispatched to supplier repos. the local remedy here was a guard edit that pins
`--brain fireworks/deepseek/flash/v4.1` on each level-1 lane.
