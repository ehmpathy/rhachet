# 🌙 dream: acceptance children inherit the host's CLAUDE_CONFIG_DIR

kind = fix · owner = rhachet (blackbox test infra) · caught 2026-10-25

## .the cue that fired

`init.incremental` [case1] went red locally on one extra line, while CI stayed green:

```
│    note: this clone's config dir is $REPO_ROOT/.agent/.actors/actor.via.repo=ambient/brain/.claude; …
```

## .the gap, precisely

- `invokeRhachetCliBinary` passes the parent env through to the child cli
- a test run from inside an enrolled clone carries `CLAUDE_CONFIG_DIR` (set by `rhx enroll`)
- the roles-ehmpathy mechanic init (`init.claude.permissions.sh`, `print_config_dir_note`) prints a
  note whenever `CLAUDE_CONFIG_DIR` is set and differs from the repo dir
- ⇒ any snapshot that holds a mechanic init screen differs by host: a clone sees the note, CI does not
- measured: `blackbox/cli/__snapshots__/init.incremental.acceptance.test.ts.snap` case 20/22, on
  branch `beav/fix-init-refuses-ambient-claude-link`; the leaked line was cut by hand to match CI

## .the shape of the fix

- in `blackbox/.test/infra/invokeRhachetCliBinary.ts`, drop `CLAUDE_CONFIG_DIR` (and audit for
  other enroll-set vars) from the child env by default, unless a case passes it explicitly
- a clamp: a case that sets `CLAUDE_CONFIG_DIR` in the parent env and asserts the child screen lacks
  the note
- then resnap from inside a clone and confirm zero diff against CI

## .why it is not done in this round

- safe: yes. clean: no. the change moves the env of every acceptance suite, and the enroll and clone
  suites may read `CLAUDE_CONFIG_DIR` on purpose. that audit is a pr of its own, not a ride-along on
  an init fix
