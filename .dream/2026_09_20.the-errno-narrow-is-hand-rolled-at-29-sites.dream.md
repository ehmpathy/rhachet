# 🌙 dream: the errno narrow is hand-rolled at 29 sites, and it fails OPEN when it is wrong

**kind** = repair
**owner** = this repo (`ehmpathy/rhachet`) — `src/infra/filesystem`
**caught** = 2026-09-20

---

## .the cue that fired

`review.peer r011` raised the vanish-race classifiers as a `rule.prefer.wet-over-dry` fold
candidate. the fold it named does not survive (three deliberately-distinct messages; the walk's
non-vanish arm is a `continue` no callback can express) — **but the read it forced found a
different duplication, one order of magnitude larger and with a worse failure mode.**

## .the gap, precisely

```
$ rg "code\s*[!=]==?\s*'ENOENT'" src --count
   29 occurrences across 25 files
```

every one of them is the same expression, hand-written:

```ts
if ((error as NodeJS.ErrnoException)?.code !== 'ENOENT') throw error;
```

the 25 files span **six unrelated subsystems** — keyrack daemon, clone sockets, clone identity,
role link/unlink, upgrade, boot. no two of them share a caller.

### 🔴 why it matters more than an ordinary triplication

**the expression fails OPEN, in both directions, and both failures are silent:**

| the slip | what ships |
|---|---|
| the literal is mistyped (`'ENONET'`) | the narrow never matches ⇒ a caller-fixable race escapes **unclassified**, which `getExitCodeFromError` defaults to exit **1** — a malfunction code for a fault the server did not commit |
| the comparison is inverted (`===` for `!==`) | the narrow matches everything *else* ⇒ a real fault (`EACCES`, `EIO`) is swept into the caller's bucket, which is `rule.forbid.failhide` exactly |

⇒ neither slip throws, neither is visible in a diff at a glance, and **neither has a test that
would catch it** unless that site happens to carry an errno-specific clamp. most do not.

🟡 the cast makes it worse: `error as NodeJS.ErrnoException` is an assertion, so the compiler
checks the property name against no declared shape at all. a `.errno` for a `.code` compiles clean.

### what a fix looks like

one predicate, in `src/infra/filesystem/`:

```ts
/**
 * .what = whether a thrown error is the kernel's "no such file or directory" refusal
 */
export const isErrorFileAbsent = (error: unknown): boolean =>
  (error as NodeJS.ErrnoException)?.code === 'ENOENT';
```

⇒ it does not shorten a call site by much. **what it buys is that the literal and the cast exist
once**, so the two silent slips above become one reviewable line rather than 29.

🟡 and the shape generalizes: `EACCES`, `EEXIST`, `EISDIR`, and `ELOOP` are each hand-rolled at
several sites too. a taker should decide whether the artifact is one predicate per errno or a
single `isErrnoOf(error, 'ENOENT')` — a real fork, and not one to guess at.

## .why it is not done in this round

- **not clean.** to extract and adopt at the **5** sites this behavior touches, while **24** stay
  on the raw form, is the braided trail `philosophy.pavement-saves-nature` names: two paths for one
  check, neither authoritative, and the next author picks whichever they saw first
- **not safe at the full scale.** to sweep all 29 opens keyrack's daemon, the clone socket server,
  and `execUpgrade` — three subsystems this wish never touched. that is `rule.forbid.scope-leaks`,
  and `rule.require.review-test-changes` on top: several of those sites gate behavior whose clamps
  this behavior has no standing to re-bless
- **the fork above is a real judgment.** one-predicate-per-errno vs a parameterized `isErrnoOf`
  changes 29 call sites either way, and it is an owner's call rather than a rider on a boot-budget
  diff

## ⚠️ .what this does NOT excuse

**the branch did not introduce this.** 24 of the 29 predate it; the 5 it adds are each individually
correct and individually tested. this is a **discovery**, never a regression.

⚠️ **and it does not excuse the count.** `readOneBootSpecFile.ts` once carried a docblock claiming
*"two usages is one short of the bar"* — false when written, and the reviewer is what found it. the
claim is now cut rather than corrected, because the count was never the reason the fold was refused
(`rule.forbid.defensive-essay-docblocks`).
