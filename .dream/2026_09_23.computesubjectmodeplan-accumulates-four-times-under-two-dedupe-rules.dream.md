## .the gap, precisely

`src/domain.operations/boot/computeBootPlan.ts:244-402` accumulates one `BootPlan` through **four
near-identical blocks**, under **two different dedupe rules**.

| block | lines | what it adds | the dedupe rule |
|---|---|---|---|
| 1 | `279-289` | `always` say | none — first writer wins by construction |
| 2 | `291-303` | `always` ref | skip where already said |
| 3 | `333-360` | subject say | **demote to ref** where already said |
| 4 | `362-377` | subject ref | skip where already said **or** already ref'd |

every block runs the same four moves — push to a result array, mark a `said*` set, mark a
`claimed*` set, and repeat the whole shape once for briefs and once for skills. so the file carries
**eight** copies of one accumulation step, at two grains.

🔴 **and the two dedupe rules are the reason a naive extraction is wrong.** blocks 2 and 4 *skip* a
duplicate; block 3 **demotes** it — a say resource already said becomes a ref rather than a no-op:

```ts
    // add subject say resources (say wins over ref)
    for (const ref of subjectResult.briefsSay) {
      if (saidBriefs.has(ref.pathToOriginal)) {
        // already said, add as ref (dedupe)
        const alreadyRef = briefsRef.some(
          (r) => r.pathToOriginal === ref.pathToOriginal,
        );
        if (!alreadyRef) {
          briefsRef.push(ref);
        }
      } else {
```

⇒ **a shared helper that collapses all four to "skip a duplicate" would silently drop the demote,
and a resource that two subjects both name would vanish from the payload entirely.** that is a
payload defect the budget gate cannot see: the boot renders fewer bytes, and the count is correct
for the bytes it rendered.

### the checkable evidence

```
rhx grepsafe --pattern 'claimedBriefs.add|claimedSkills.add' --path src
→ 8 sites, all inside one 160-line function

rhx grepsafe --pattern 'saidBriefs.has|saidSkills.has' --path src
→ 6 sites, 2 of which branch to a DEMOTE and 4 to a SKIP
```

## .the shape of the fix

one named operation per accumulation step, parameterized by the **dedupe rule** rather than by the
section:

```ts
type DedupeRule = 'skip' | 'demote';

const addResourcesToPlan = (input: {
  plan: BootPlanDraft;          // say[], ref[], said<Set>, claimed<Set>
  resources: RoleBriefRef[];    // or string[] for skills
  tier: 'say' | 'ref';
  onDuplicate: DedupeRule;
}): void => { … };
```

then the four blocks read as four calls:

| the call | tier | onDuplicate |
|---|---|---|
| `always` say | `say` | `skip` |
| `always` ref | `ref` | `skip` |
| subject say | `say` | 🔴 `demote` |
| subject ref | `ref` | `skip` |

⇒ **the rule becomes a named argument at the call site rather than a shape a reader must diff two
blocks to see.** the demote stops to be an easy-to-lose asymmetry and becomes the one row in the
table that differs.

🟡 **the brief/skill split is the second half, and it is a generics question rather than a logic
one:** the two differ only in the identity key (`ref.pathToOriginal` vs the path itself). a
`keyOf: (r: T) => string` parameter collapses the pair without a cast.

### what must be clamped before any of it moves

the demote is the behavior a refactor can lose in silence, so it is clamped first:

- `[caseN]` two subjects that both `say` the same brief ⇒ it appears **once in `say`, once in
  `ref`**, never twice in `say` and never absent
- `[caseN]` a brief said by `always` and ref'd by a subject ⇒ stays in `say`, absent from `ref`
- `[caseN]` a brief ref'd by two subjects ⇒ appears **once** in `ref`
- proved by revert per `rule.require.clamp-edge-cases`: replace `demote` with `skip` and the first
  case MUST go red

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), answered honestly:

| question | answer |
|---|---|
| is it **SAFE**? | 🔴 **no.** it rewrites the operation that decides what every boot renders. a lost demote is a silently shorter payload — and the budget gate would report a correct count for a wrong set |
| is it **CLEAN**? | 🔴 **no.** it ripples into `computeBootPlan`'s snapshot set, the `--subject` acceptance tier, and the `also` computation that reads the same `claimed*` sets |

⇒ **both answers are no, which is the row that earns a dream rather than a fix-forward.** and the
scope call is the wisher's: `0.wish.md` bounds this behavior to the manifest source and the budget
gate, and `computeSubjectModePlan` predates both — it is neither.

🟡 **and the deferral was correct twice before it was recorded once.** two prior rounds reached this
same verdict and left no artifact, so this dream's real cost is the two re-derivations it should
have prevented.
