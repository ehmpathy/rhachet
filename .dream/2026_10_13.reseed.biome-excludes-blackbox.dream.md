## .the cue that fired

`.agent/repo=.this/role=any/skills/test.file.unused.imports.sh` exists only because biome never reads
`blackbox/`. its own header says so: *"biome ignores `blackbox/`, and tsc does not flag an unused
import there, so a split or a trim leaves dead imports no gate reports."* a skill that patches a
gap in the linter's scope is a workaround, and the defect behind it is the scope.

## .the gap, precisely

- `biome.jsonc` → `files.includes` names only `**/src/**/*.ts` and `**/provision/**/*.ts`
- so the 195 `.ts` files under `blackbox/` go unformatted and unlinted, acceptance tests and harness alike
- `!**/.test*` in the same list also hides `blackbox/.test/infra/` even once `blackbox/` is added
- measured 2026-10-13 with `**/blackbox/**/*.ts` added temporarily, then reverted:

| defect | count |
|---|---|
| format | 118 files |
| `lint/suspicious/noControlCharactersInRegex` | 17 |
| `lint/correctness/noUnusedImports` | 4 |
| `lint/style/useImportType` | 1 |

the 17 control-char hits are ANSI-strip regexes (`/\x1b\[[0-9;]*m/`) in test infra that reads tty
output. they are deliberate, not defects.

## .the shape of the fix

1. **upstream, in `declapract-typescript-ehmpathy`** — the declared `biome.jsonc` covers the
   blackbox test dir (`**/blackbox/**/*.ts`), and decides whether its `.test/` infra stays excluded
   or is covered too (it should be covered: infra is code, and its dead imports are the same defect)
2. **the ANSI regexes** — one `biome-ignore lint/suspicious/noControlCharactersInRegex: <reason>`
   per site, or an `overrides` entry scoped to `blackbox/**` that turns the rule off. prefer one
   named transformer (`asTextWithoutAnsi`) that holds the regex once, with one ignore
3. **here, after the upgrade lands** — `npm run fix` for the 118 format diffs, hand-fix the 4
   unused imports and 1 type import, then retire `test.file.unused.imports.sh` and drop its
   mention from briefs

## .why it is not done in this round

safe, but not clean: a 118-file format diff would bury the `fix-config-blend` change it rode in on,
and the config is stamped by an upstream practice — a local edit would drift from it and be
overwritten by the next `declapract.upgrade`. so the fix belongs upstream, then lands here via an
upgrade, in a PR of its own.
