# 🌙 dream: decide whether `rhx init` re-renders actor corpora

- kind  = feat
- owner = ehmpathy/rhachet
- caught 2026-09-23, on `.behavior/v2026_09_22.feat-boot-briefs-into-claude-md`, stone
  `3.3.1.blueprint.product`, iteration i012

## .the cue that fired

i012 r011 asked that F8's corpus render be ejected out of `syncHooksForLinkedRoles` into a peer
orchestrator. to compose the peer, the blueprint had to name its call site — and a search for the
extant function's callers returned **two**, not one:

```
src/domain.operations/upgrade/execUpgrade.ts:324   ← F8's declared subject
src/contract/cli/invokeInit.ts:165                 ← 🔴 a path F8 never names
```

⇒ the ejection forced a decision that the graft had made silently, and made the wrong way round: a
branch inside a shared function fires for **every** caller, not for the one the author had in view.

## .the gap, precisely

the blueprint specifies the corpus render on the **upgrade** path (`execUpgrade.ts:324`). it says
naught about `rhx init`, and `rhx init`'s own criteria say naught about an actor corpus.

so the peer is composed at `execUpgrade` alone, and **`rhx init` does not re-render**. that is a
faithful read of what was specified — it is **not** a considered answer to the question the two
call sites raise:

> **should `rhx init`, run against a repo that already has enrolled actors, refresh their brief
> corpora?**

the argument each way, stated fairly:

| for | against |
|---|---|
| an init that re-links roles changes what a corpus WOULD render to, so a stale corpus is the same drift F8 exists to prevent | `init` is the repo-scaffold verb; `upgrade` is the refresh verb. an actor-fleet write under `init` is a side effect its name does not promise |
| a human who re-inits after a role edit reasonably expects their clones to see it | the drift guard (`#20` / F18) is the designed answer to a stale corpus, not an eager re-render at every verb |

🟡 **the failure mode, if the answer is "yes" and we ship "no":** a human edits a role's briefs,
runs `rhx init`, opens a clone, and reads the previous corpus. the symptom is indistinguishable from
a brief that did not save.

🟡 **the reason it stayed invisible until now:** on a *fresh* init the actor set is empty, so the
render is a no-op either way. only a **re-init of an established repo** can tell the two answers
apart, and that is the rarer path.

## .the shape of the fix

the operation already exists after this feature ships — `syncActorBriefCorporaForLinkedRoles`. so
the whole change is one composed line plus its coverage:

```
[~] invokeInit.ts:165
     ├─[○] syncHooksForLinkedRoles({ brains }, context)
     └─[+] syncActorBriefCorporaForLinkedRoles({}, context)   ← the one line, IF the answer is yes
```

plus:
- an acceptance case over `rhx init` against a repo with ≥1 cloned actor, that reads the corpus
  digest before and after
- a census cell in `1.vision.experience.case=_` — the upgrade re-render already grew `#27–#29`;
  an init re-render is the same axis at a different verb, and owes its own row either way

⇒ and if the answer is **no**, the fix is cheaper still and it is not a no-op: `invokeInit`'s own
docblock should say that a corpus is deliberately NOT refreshed here, and name the verb that does.
an unstated "no" is what let the graft's "yes" pass unnoticed.

## .why it is not done in this round

**SAFE** — no. it changes what `rhx init` writes, for every repo with enrolled actors. `rhx init`
is a contract this feature otherwise touches only for the S13 anchor.

**CLEAN** — no. the answer is a scope call, not a judgment the driver holds: the wish's own bound
reads *"do not widen into unrelated boot work the refactor may have left nearby — catch it as a
dream instead."* an init-path corpus render is exactly the neighbour boot work that bound names.

⇒ both questions answer NO, so the deferral is legitimate.

### 🔴 and NO fulcrum is owed beside it — which is worth stating, because the default is that one is

`rule.always.fix-forward-under-scouts-honor` says a deferral for **dirt** owes a fulcrum, since a
dirt call is *"a judgment about ripple cost, and a judgment made alone is what a fulcrum list exists
to surface."* ⇒ the test is whether the driver made a judgment.

**here the driver made none.** the wish already ruled it, in its own words: *"do not widen into
unrelated boot work the refactor may have left nearby — catch it as a dream instead."* an init-path
corpus render is that boot work exactly, and the wish names the artifact it wants — this one.

🟡 **and F8 is NOT the home for it.** F8 is **RULED (S16)** and its row reads *"settled on both the
rule and the measure."* a settled fulcrum cannot carry an open question; to hang one on it would
re-open a verdict the wisher already gave, under cover of a citation. ⇒ F8's row records that the
blueprint now pays its **placement** too, and stops there.
