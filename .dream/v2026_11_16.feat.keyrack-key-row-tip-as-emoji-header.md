# 🌙 dream: the keyrack key row's tip renders as a `💡 tip` header node

- kind = feat
- owner = rhachet keyrack
- caught 2026-11-16

## .the cue that fired

peer round i003 r001 blocker.1 on `v2026_11_14.feat-keyrack-github-app-off-ec2`: the key row renders its tip as `└─ tip: <head>`. the `:` joins a label to its detail on stdout (`rule.forbid.colons-in-stdout`), and an actionable advisory renders as an emoji-headed node, never a flat `tip:` line (`rule.prefer.emoji-language` §the tip form).

## .the gap, precisely

`src/domain.operations/keyrack/cli/asKeyrackTipLines.ts` writes the head as `${indent}└─ tip: ${head}` and each further `;` part as a sub-leaf. every keyrack key row (locked, absent, errored, omitted) renders through it.

## .the shape of the fix

render the header alone, every part as a child:

```
   └─ 💡 tip
      ├─ <head>
      └─ <next part>
```

one line in `asKeyrackTipLines` (the header), and each part (head included) as a child leaf. update `asKeyrackTipLines.test.ts`. then resnap the keyrack acceptance suites that hold a key-row tip (about 100 lines in 22 suites at the time this was caught: the vault, reach, org, status, source, and sdk source suites) and read each diff.

## .why it is not done in this round

the render is shared by every keyrack key row, and the off-ec2 pr's wish is the off-ec2 mint. the change would move snapshots in 22 suites off that pr's surface. as its own pr it is one line plus one resnap a reviewer can read whole. fulcrum F13 holds the call.
