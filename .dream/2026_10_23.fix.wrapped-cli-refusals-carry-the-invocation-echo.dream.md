# 🌙 dream: wrapped cli refusals carry the invocation echo

- kind = fix
- owner = rhachet
- caught 2026-10-23
- status = resolved 2026-10-23, in #649 (fulcrum F11 ruled (b)): `withCliOutputErrors` takes the
  root program's parsed argv and prints `[args]` through `asCliArgsEchoLine`, the one owner the
  last handler shares; json output carries no echo

## .the cue that fired

a peer reviewer of the enroll focus feature flagged that every new `enroll` refusal snapshot ends
after its metadata, while the `init`, `upgrade` and `roles` refusals of the same pr end with an
`[args] …` line.

## .the gap, precisely

`rule.require.refusals-carry-context` holds that a refusal a human reads must echo the invocation,
and names its absence a blocker. two renderers own the cli error frame:

- `src/contract/cli/emitCliErrorAndExit.ts` — the last handler — prints `[args] ${input.args}`
- `src/contract/cli/withCliOutputErrors.ts` — the wrapped path of six verbs (enroll, actor list,
  clone list/say/get/whoami/prune) — prints no echo, and the first file's note says the wrapped
  path "does not want the line"

so an enroll refusal read from a cron log or a paste names its hint and no way to reproduce it.

## .the shape of the fix

- give `withCliOutputErrors` an `args: string[]` input; each of the six invokers passes the argv it
  parsed; under `--output tree` print `[args] …` after `asCliErrorFrame`, exactly as the last
  handler does (one owner of the line, so the two paths cannot drift)
- leave `--output json` untouched, or add an `args` field to the json shape
- re-snap every refusal frame of the six verbs (~40 frames in the enroll suites alone, plus the
  clone and actor suites); real-brain journeys re-snap under their own credential
- delete the "does not want the line" note

## .why it is not done in this round

dirty. the frame is shared by six verbs, and the re-snap spans extant suites the focus feature does
not touch, some real-brain. see fulcrum F11 of `v2026_10_21.feat-enroll-role-subject-focus`.
