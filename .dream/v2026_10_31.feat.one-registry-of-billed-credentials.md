# 🌙 dream: one registry of billed credentials, read by the clamp, the strip list and the notice

- kind = feat
- owner = rhachet
- caught 2026-10-31

## .the cue that fired

a peer review of the live-brain clamp found the keys that carry money named in four places, with
the clamp blind to all of them.

## .the gap, precisely

- the keys that bill a vendor are listed apart in `role=test/keyrack.yml` (`OPENAI_API_KEY`,
  `XAI_API_KEY`, `ANTHROPIC_API_KEY`), in `BRAIN_AUTH_ENV_KEYS` (claude's three), in the realjest
  strip list `VENDOR_KEYS` (five), and as literals in `getContextOpenAI` and `caseAskable`
- no clamp marker fires on a read of a billed key (`process.env.OPENAI_API_KEY`) or on a vendor
  host (`api.anthropic.com`, `api.openai.com`), so a raw `fetch` with an inline key passes the scan
- `BRAIN_AUTH_ENV_KEYS` marks `ANTHROPIC_AUTH_TOKEN` as `bills: 'api'`. claude code sends it as a
  bearer, so behind `ANTHROPIC_BASE_URL` (a gateway) it bills the gateway, not anthropic; the
  notice's "this clone bills the anthropic api" is then too strong

## .the shape of the fix

1. one table, `{ key, vendor, bills }`, beside `liveBrainRegistry.ts` or under `brain/auth`
2. derive from it: `BRAIN_AUTH_ENV_KEYS`, the realjest strip list, and two 'tests' markers (a read
   of a billed key, a vendor host literal)
3. a unit row per key; a test that the keyrack manifest declares each `tests`-tier key
4. the notice: say "bills the anthropic api" only when `ANTHROPIC_BASE_URL` is unset, else "bills
   the endpoint at `$ANTHROPIC_BASE_URL`", with a cited source for the bearer behavior

## .why it is not done in this round

it reshapes a prod contract (`BRAIN_AUTH_ENV_KEYS`, the notice text and its snapshots) and adds
markers that would need every key-read suite classified. that ripples past this diff; the clamp
as it stands already catches every live path in use (a supplier, a vendor sdk, the claude cli).
