# 🌙 dream: an errored key's hint renders as a tree, as the blocked report's does

- kind = feat
- owner = ehmpathy/rhachet (keyrack cli render)
- caught = 2026-11-16

## .the cue that fired

peer round i001 of `5.3.verification` on `beav/feat-keyrack-github-app-off-ec2`, r006 blocker.1:
the aws.params no-identity tip and the github-app mint-fault cures render as one `tip:` leaf of
several hundred characters, which wraps mid-phrase in a terminal.

## .the gap, precisely

`asKeyrackErroredKeyTip` joins the bare message and the error's `hint` into one string, and every
errored or locked row on `unlock` and `get` prints it as one leaf. `getKeyrackBlockedReport` splits
the same kind of hint on `;` into a nested `hint:` subtree. one fault class, two renders.

## .the shape of the fix

`asKeyrackErroredKeyTip` returns `{ headline, branches }`, the hint split on `;` (and a long
command set on its own branch); the unlock and get row renders put the headline on the `tip:` line
and each branch as a child. a clamp snapshots one long tip (the aws.params no-identity one) as a
tree; every snapshot that holds a tip is resnapped and reviewed once.

## .why it is not done in this round

the render is shared by every vault and every fault, so the change reshapes snapshots far past
this pr's two hints; fulcrum F11 hands the call to the commander at the pr.
