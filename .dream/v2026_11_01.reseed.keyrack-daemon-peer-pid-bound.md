# 🌙 dream: the keyrack daemon's peer-pid lookup keeps a 5s `ss -xp` bound, in a sync exec

kind = reseed · owner = rhachet (keyrack daemon) · caught 2026-11-01

## .the cue that fired

`v2026_11_01.fix-clone-auth-lookup-timeout` raised the clone's `ss -xp` bound from 5s to 60s
because `ss -xp` passes 5s on a loaded box. the daemon runs the same scan.

## .the gap, precisely

`src/domain.operations/keyrack/daemon/svc/src/infra/getSocketPeerPid.ts:77-80` —
`execSync(..., { timeout: 5000 })`. on the same loaded box, a keyrack get could fail its session
gate for the same reason.

🔴 the bound cannot simply be raised: the call is `execSync`, so a 60s bound would freeze the
daemon's event loop — every other caller of the daemon — for up to a minute per slow lookup.

## .the shape of the fix

1. `getSocketPeerPid` → async, `ss` read via `execFile` with no shell (as `getSocketPeerCred` does)
2. `verifyCallerLoginSession` → async; `handleKeyrackDaemonConnection` awaits it (the
   `verifySession` injection type in `createKeyrackDaemonServer` follows)
3. share `SOCKET_PEER_CRED_LOOKUP_TIMEOUT_MS` (`src/infra/socket/constants.ts`) between the two
   readers, and move the daemon onto `asSocketPeerPidFromSsPeerLine` (#686); best done by first
   extract of the leaves both readers repeat — the fd → inode read, the signed/unsigned inode pair,
   and the bounded `execFile('ss', ['-xp'])` read with its named faults (no shell, no `grep`:
   `getSocketPeerCred` dropped both) — then switch the daemon onto them
4. audit the keyrack client's own socket timers: each must sit above the lookup bound, or the
   same inversion #678 had (outer timer below inner lookup) moves to the daemon
5. clamp with `genSceneWithFakeSsOnPath` (`src/.test/assets/`): a slow `ss` under the bound → the get passes;
   the daemon still answers a second caller while the first lookup crawls

## .why it is not done in this round

a sync→async contract change across the daemon's access gate (three files plus the client timer
audit), in the keyrack domain, outside the clone wish. it warrants its own focused review.
