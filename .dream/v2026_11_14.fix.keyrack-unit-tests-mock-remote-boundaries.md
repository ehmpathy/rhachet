# 🌙 dream: keyrack's vault and relock unit tests inject their boundaries, never `jest.mock` them

- kind = fix
- owner = rhachet (keyrack)
- caught 2026-11-14, on `beav/fix-keyrack-export-single-flight` (#656)

## .the cue that fired

the test-scope-purity reviewer flagged `jest.mock` of remote boundaries in two unit files this pr
touched: `vaultAdapterAwsConfig.test.ts` and `relockKeyrack.test.ts`.

## .the gap, precisely

- `vaultAdapterAwsConfig.test.ts` mocks `node:child_process`, `node:fs`, `fs/promises`,
  `@aws-sdk/credential-provider-sso` and `getAllAwsSsoCacheEntries`. all on `main`
- `relockKeyrack.test.ts` mocks `../daemon/sdk`, the daemon socket. on `main`; #656 added two entries
- `rule.forbid.unit.remote-boundaries` forbids mock usage in a unit test and has no documented-exception
  clause: a unit test injects fakes, or the case moves to an integration suite

## .the shape of the fix

1. give the vault adapter a context of its collaborators (exec, the fs reads, the sso provider, the
   export ops), with the real ones as the default the factory wires
2. give `relockKeyrack` the daemon sdk calls through its context
3. rewrite the two unit files to pass fakes; move any case that needs the real disk or daemon to the
   extant integration suites
4. clamp: no `jest.mock` left in either file

## .why it is not done in this round

the cure reshapes two extant prod contracts and every caller of each, in a pr bound to nano. the call
is fulcrum F19 (`.behavior/v2026_11_08.fix-keyrack-export-single-flight/.fulcrums/inventory.of=fulcrums.case=F19-extant-unit-mocks-stay-in-their-files.md`),
a clean rework the wisher may pull in.
