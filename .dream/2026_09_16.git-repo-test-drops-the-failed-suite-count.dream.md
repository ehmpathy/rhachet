# 🌙 dream: `git.repo.test` must report FAILED SUITES, not only a suite total

- **kind** = reseed — the skill lives in `ehmpathy/rhachet-roles-ehmpathy`, not here
- **owner** = `repo=ehmpathy/role=mechanic`, skill `git.repo.test`
- **caught** = 2026-09-16, at `.behavior/v2026_09_11.fix-clone-say` stone `5.3.verification`

## .the cue that fired

a thorough acceptance run reported:

```
suites: 134 files
tests: 2739 passed, 13 failed, 8 skipped
```

and its own log held **~60 `● Test suite failed to run`** entries. a suite that fails to LOAD runs no
test, so its tests land in no count — not passed, not failed, not skipped. against that suite's clean
baseline of `3588 passed`, **849 tests silently vanished** while the headline said `13 failed`.

⇒ the cue was not the failure. it was the **arithmetic**: the passed-count had dropped by a quarter
and no number on the summary accounted for it.

## .the gap, precisely — the parser reads the right line and takes the wrong field

`node_modules/rhachet-roles-ehmpathy/dist/domain.roles/mechanic/skills/git.repo.test/git.repo.test.sh`,
lines 1168–1173:

```bash
# parse Test Suites line: "Test Suites: 3 passed, 3 total" or "Test Suites: 1 failed, 2 passed, 3 total"
suites_line=$(grep -E "Test Suites:" "$stdout_file" | tail -1 || true)
JEST_SUITES=$(echo "$suites_line" | grep -oE "[0-9]+ total" | grep -oE "[0-9]+" || echo "")
```

🔴 **the comment documents the failed-suite form, and the code then extracts only `N total`.** jest
knows the split and hands it over on that very line; the skill parses past it.

rendered at lines 1309 and 1378 as `suites: ${JEST_SUITES} files` — a bare total, which reads as a
scope report rather than a result. ⇒ so these two runs render **identically** in the suite row:

| reality | what the summary shows |
|---|---|
| 134 suites loaded, 13 assertions failed | `suites: 134 files` |
| **60 suites never loaded**, 13 assertions failed | `suites: 134 files` |

⚠️ **a channel that reports a verdict it cannot justify** — the same class the behavior that found it
exists to close, one layer up.

## .the shape of the fix

1. capture the failed count beside the total, from the line already in hand:
   ```bash
   JEST_SUITES_FAILED=$(echo "$suites_line" | grep -oE "[0-9]+ failed" | grep -oE "[0-9]+" || echo "0")
   ```
2. render it only when non-zero, so a green run's output is byte-identical to today's:
   ```
   ├─ suites: 134 files, 🔴 60 failed to run
   ```
3. 🟡 **and treat a failed-to-run suite as its own exit class.** it is not an assertion failure — the
   fix is a load error (an absent `dist/`, a bad import, a syntax error), so the hint should differ:
   *"a suite failed to LOAD — check dist/ is built and no build ran under this one"*.

the snapshot clamp is cheap: a fixture stdout with `Test Suites: 60 failed, 74 passed, 134 total` fed
to the parser, asserted to surface `60`. red under the extant `[0-9]+ total` extraction by
construction.

## .why it is not done in this round

**ownership, never dirt.** the skill is published by `rhachet-roles-ehmpathy` and reaches this repo
through `node_modules` — an edit here would be written into a dependency's `dist/`, so it would be
erased by the next install and would never reach the repo that owns it
(`rule.always.scope-onetime-lessons-to-the-behavior`: a tree adopts only what is scoped to itself).

⇒ so no fulcrum is owed — the deferral is not a judgment about ripple cost, it is a hard boundary.

🟡 the **local** half of this lesson was fixed forward in this round rather than dreamed: the hazard
that produced the contaminated run is now
`.agent/repo=.this/role=any/briefs/rule.forbid.builds-while-a-blackbox-run-is-inflight.md`.
that brief tells a reader of this repo how to avoid the trap; this dream is what makes the trap
**visible in the report** for every repo the skill serves.
