```ts
// blackbox/.test/infra/RUN_PERF_TEST.ts
export const RUN_PERF_TEST = !!(process.env.CI || process.env.PERF);
```

🚨 **`rule.forbid.failhide` names `given.runIf` explicitly, and this use does not commit the harm
the rule exists to prevent.** the rule's own reason is *"hidden lies that pass ci"* — and these
**RUN in ci**. the flag defaults ON there, and `PERF=true` forces them locally. so the absence from a
default local run is a **declared scope**, never a hidden one.

⇒ that is a distinction the rule does not currently draw, and it deserves one: what makes a skip a
lie is that its absence is **invisible and unnamed**, never the api that produced it. a named,
documented, ci-default-on boolean is a tier selector.

## .the shape of the fix — for what remains

**class B — decide the policy once, then apply it.** the question is not per-file:

> **should the repo run real-brain integration tests in CI, or route them to a separate
> opt-in tier?**

🚨 **class C is the extant pavement, and it is a better answer than the one first proposed here.**
an earlier draft pointed at the `*.realbrain.acceptance.test.ts` filename convention. a filename is
a scope a runner selects on; a `RUN_*` boolean is a scope a runner **and a human** can flip, with the
reason written next to it. the repo already has the second, in eight files, with an `infra/` module
to hold the flag.

so the shape:

1. add `blackbox/.test/infra/RUN_BRAIN_TEST.ts` (or the `src/.test/infra` twin) on the
   `RUN_PERF_TEST` model, with its own docblock that states the cost and the credential it needs
2. convert all 14 class-B rows from `given.skip(...)` to `given.runIf(RUN_BRAIN_TEST)(...)`
3. decide the default — the one real decision: `!!(process.env.CI || process.env.BRAIN)` bills every
   ci run against live brains; `!!process.env.BRAIN` alone keeps ci free and makes the tier opt-in
4. where the gate is ON and the credential is absent, **fail loud** (`rule.require.failfast`) rather
   than skip — that is the half the current `.skip` cannot do at all

⇒ steps 1, 2, and 4 are mechanical. **step 3 is the wisher's**, because it is a question about what
ci costs per run.
