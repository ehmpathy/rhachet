## .the cue that fired

a `--as arrived` passed its 600s tool timeout and moved to the background while l3 lanes ran
(~12–14 min each). the onStop hook then fired on every turn with *"🍵 tea first … to refuse is not
an option"* and pushed the driver toward `--as arrived` again. a second arrival re-runs every lane
not yet cached clean — a parallel duplicate round, paid twice. the wisher caught the attempt.

## .the gap, precisely

- `stepRouteDrive.ts`, the `hook.onStop` branch: no case for "guard round in flight". the stone's
  latest passage row is `arrived` (reason `entered guard reviews`, written by `setStoneAsPassed`
  on guard entry) or `poured` (a level began) for the whole round, and that row's disposition is
  `push` — so the hook blocks the stop and counts toward the 21-block escalation
- the only exits the hook offers are `arrived` · `passed` · `blocked`; each is wrong mid-round
  (`arrived` duplicates, `passed` re-runs the guard, `blocked` summons a human for no wall)

## .the shape of the fix

1. `setStoneAsPassed`, right after the `entered guard reviews` row: write
   `.route/.inflight/<stone>.pid.json` = `{ pid, stone, sinceMs }`; remove it on `exit`,
   `SIGINT`, `SIGTERM`, `SIGHUP` (only if the file still names this pid)
2. in the `hook.onStop` branch, before the blocker report: in flight ⟺ the latest row for the
   stone is `poured`, or `arrived` with reason `entered guard reviews`, **and** the pid file's
   process is alive — `process.kill(pid, 0)` succeeds (or `EPERM`), and on linux
   `/proc/<pid>/cmdline` still holds `route.stone.set` and the stone name (guards a reused pid).
   then return stdout only (allow the stop) with a `⏳ guard reviews inflight (guard pid N alive)`
   tree that says *do not re-arrive; address the givens that already landed, or wait for the verdict*
3. a round killed mid-flight — an interrupt, a SIGKILL, a closed terminal — leaves its marker row,
   but its pid is dead (or its pid file removed), so the hook pushes as today. no clock guess:
   an mtime bound either goes quiet on a dead round or goads the driver while a slow live one runs
4. snapshot the new tree; cases: pid alive (allow), pid dead with marker row (push), pid reused
   by another process (push), no pid file (push), round ended (push), a driver
   `conceded`/`absorbed` row mid-round (push — forward motion)
5. pairs with `.dream/v2026_09_23.reseed.route-guard-await-inflight-reviews.md` (an explicit
   wait skill); this fix alone removes the goad, that one gives the driver a lever

the local patch implements steps 1–3 verbatim, in
`node_modules/rhachet-roles-bhrain/dist/domain.operations/route/stones/setStoneAsPassed.js` (the
writer) and `…/route/stepRouteDrive.js` (the reader); it is lost on the next install.

## .why it is not done in this round

the code lives in another repo (a reseed); a `node_modules` patch is a bridge, not a fix.
