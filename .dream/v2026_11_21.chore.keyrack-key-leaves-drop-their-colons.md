## .the cue that fired

peer review i001 r001 (repo-rules) blocker.1: the status render emits `expires in: 52m`, a `:` separator on stdout that `rule.forbid.colons-in-stdout` forbids.

## .the gap, precisely

every keyrack key branch, in `status` (`asKeyrackStatusKeyBranch`) and in `unlock` / `get` (`emitKeyrackKeyBranch`), opens with three colon leaves: `env: camp`, `org: ahbode`, `expires in: 52m`. the renew leaves this branch added take the tree form (`renewed = 2x`, `renew = on`). 18 snapshot files carry `expires in: `, 16 of them acceptance suites outside the renew.

## .the shape of the fix

1. one leaf form for the three: `env = camp`, `org = ahbode`, and `expires in 52m` (prose, per the rule's repair table)
2. apply it in both renders in one change, so a key branch never mixes forms
3. resnap the 18 files on one independent run, scoped to the keyrack suites

## .why it is not done in this round

it fails the CLEAN test of fix-forward: the change ripples to 16 acceptance suites (several need live vault keys) and to `unlock`'s output, none of which the renew touches. one leaf alone would leave `env:` and `org:` beside it, so a key branch would mix two forms. fulcrum F22.
