# 🌙 dream: roles boot drops its tail past 64KB when the pipe reader is slow

kind: fix · owner: rhachet · caught 2026-10-13

## .the cue that fired

`roles.boot.published.acceptance` [t1] failed on ci (pr #600): `the whole payload reaches a pipe`
— the stdout ended mid-brief, no closed `<stats>`, exit 0. it passed on the prior ci run.

## .the gap, precisely

- `./bin/run.bun.rhachet-roles.bc roles boot --repo ehmpathy --role mechanic | (sleep 1; wc -c)`
  prints `64956`; a fast reader gets `261990`. deterministic with a 1s reader delay
- the published v1.49.1 binary does the same, so it predates this branch
- exit 0, empty stderr. under `strace` all bytes land (timing-sensitive)
- a minimal bun binary that `console.log`s 300KB, with or without a prior `execSync`, keeps every
  byte under the same slow reader — so the drop is specific to the rhachet roles entry
- an `await process.stdout.write('', cb)` before the entry returns did NOT help; the callback
  fires before the pipe drains

## .the shape of the fix

bisect the roles entry against the minimal probe: add commander, the emoji shim, then the boot
action, until the slow-reader probe drops bytes. likely suspects: an fd flipped to O_NONBLOCK by a
dependency (`fcntl(11, F_SETFL, O_NONBLOCK)` shows in the trace), or bun's exit path when a
`process.stdout` listener (exitCleanOnClosedPipe) is attached. clamp it with an acceptance case that
reads the boot through a delayed reader and asserts the closed `<stats>` tail.

## .why it is not done in this round

the root cause is not yet found, the defect predates the branch, and the round is a prod release
of an unrelated fix. the ci failure is this defect firing under load, so the shard is retried.
