- **kind** = repair
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-25 · **narrowed** 2026-09-25 (one of its two sites was closed)

## .the cue that fired

a peer reviewer (`mech-test-scope-purity`) graded two `jest.mock` declarations a blocker against
`rule.forbid.unit.remote-boundaries`, which names three remedies — a fake, dependency injection, or
a move to `.integration.test.ts` — and forbids the mock outright.

## 🔴 .what was CLOSED, so this dream does not re-claim it

the dream opened with **two** sites. one of them was never dirty, and a re-raise proved it.

| site | disposition |
|---|---|
| `syncHooksForLinkedRoles.test.ts` → `getAllActorsOndisk` | ✅ **closed.** the mock is deleted; the case writes a real `.agent/.actors/actor.via.hash=<hash>/actor.json` and the REAL read finds it. zero production change, **11 passed** |
| `execUpgrade.test.ts` → `syncHooksForLinkedRoles` | 🔴 **open.** what this dream now carries |

⇒ **the first site needed no seam at all** — the collaborator was a pure filesystem read, so a real

## .the gap, precisely

`execUpgrade.ts:373` reaches `syncHooksForLinkedRoles` by static import (`:6`) and reads its
`errors` return. the case under test is a **fault** on that channel, and three facts block a real
drive:

| fact | where |
|---|---|
| the suite's shared context is a path that does not exist — `new ContextCli({ cwd: '/test' })` | `execUpgrade.test.ts:130` |
| the real actor read faults on it — `realpathSync` throws on an absent path | `getOneRepoPath.ts:20-29` |
| the suite mocks **nine** first-party siblings already, all on `origin/main` | `execUpgrade.test.ts:10-40` |

repo-wide context, checkable:

```
rhx grepsafe --pattern "jest.mock" --path src --glob '*.test.ts'   → 104 lines
```

🟡 the **drift** half of the harm is already closed here: the mock carries
`jest.MockedFunction<typeof syncHooksForLinkedRoles>`, so it cannot drift on shape. what is owed is
the seam, never the type.

## .the shape of the fix

1. add an **optional** collaborator slot, defaulted to the real import — so no caller changes and
   the seam exists:
   ```ts
   const hookSync = context.syncHooksForLinkedRoles ?? syncHooksForLinkedRoles;
   const { errors: hookErrors } = await hookSync({}, context);
   ```
2. widen the operation's context type (a narrow per-operation type, **not** `ContextCli` — that
   domain literal is shared repo-wide and must not grow a test seam)
3. swap the suite's `jest.mock` for a plain object handed through `context`
4. delete the module mock, re-run the suite

🟡 **step 1's default-to-the-real-import shape is what makes it safe** — `invokeInit.ts` and
`execUpgrade.ts` keep their current behavior with no edit.

⚠️ **step 2 is the open design question**, and it is why this stays a dream rather than a fix: an
optional field on an internal input collides with `rule.forbid.undefined-inputs`, so the seam wants
a declared home the repo does not yet have. that call is worth a deliberate round.

## .why it is not done in this round

run against `rule.always.fix-forward-under-scouts-honor`'s two questions, inside a
`5.3.verification` stone:

- **SAFE?** 🔴 no — it moves a production contract, and the stone came for verification
- **CLEAN?** 🔴 no — it opens a context-shape question (`rule.forbid.undefined-inputs`) this change
  never intended to open

⇒ deferred, and **conceded** rather than disputed. the severity is `better`: a compiler-checked mock
that can drift on behavior is a maintenance risk a future engineer pays, never a harm a user or an
on-call engineer suffers.
