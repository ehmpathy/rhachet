# 🌙 dream: gate the live-brain asserts in brain-dir-boot.journey

kind = fix · owner = this crew (rhachet) · caught 2026-11-06

## .the cue that fired

a local acceptance run of `blackbox/cli/brain-dir-boot.journey.acceptance.test.ts` failed 6 asserts
(`[t3]`, `[t3.1]`, `[t4]` ×3, `[t6]`), each an interactive clone whose screen read
`Credit balance too low · Add funds`. the asserts read `Received array: []` and failed as though
the boot were wrong (`.log/acceptance.manual/2026-11-06.independent.four.full.log`, 9 such notices).

## .the gap, precisely

the interactive-clone asserts run with no gate on the brain's reach. a brain that cannot answer —
no credit, no auth, a rate limit — surfaces as an assert failure about the boot, so the failure
names the wrong cause and sends a reader to debug code that is fine. the `claude -p` launches in
the same file answered, so the gap is the interactive path only.

## .the shape of the fix

- one probe per interactive clone, before its asserts: read the screen for a known refusal
  (`Credit balance too low`, an auth prompt, a rate-limit notice)
- on a hit, throw a `ConstraintError` that names the screen line and the fix, per
  `rule.require.failfast` (tests) — never a skip
- clamp: feed the probe a recorded refusal screen and assert the `ConstraintError`; red without
  the probe, green with it

## .why it is not done in this round

the fix touches acceptance test infra this diff does not, and its clamp needs an acceptance run.
the defect predates the branch; this pr's asserts (`[t3.0]`) pass.
