# 🌙 dream: the upgrade acceptance hook count reds on each upstream publish

kind = fix · owner = rhachet · caught 2026-11-18

## .the cue that fired

`blackbox/cli/upgrade.acceptance.test.ts` case11 and case12 pin `└─ 16 created`. the number went
from 14 to 16 when `rhachet-roles-ehmpathy@1.43.0` published, with no change in this repo.

## .the gap, precisely

the fixtures install a pinned `rhachet-roles-ehmpathy`, then `upgrade` pulls the latest from npm.
so the hook count follows the registry, and any publish that adds or drops a hook turns the test red.

## .the shape of the fix

- pin the version `upgrade` resolves: a local fixture registry, or an `upgrade --to <version>` the
  test passes
- once frozen, the literal count is a real regression read again, with no drift

## .why it is not done in this round

it needs a fixture registry or a new upgrade flag. both reach past the hook dispatcher pr, and the
drift predates it.
