# 🌙 dream: keyrack set echoes a secret typed just after its prompt

- kind = fix
- owner = rhachet (keyrack)
- caught 2026-11-18

## .the cue that fired

`keyrack.aws-params.githubApp` [case4] with the precise pattern `choice: |enter secret for`: the
helper sees `enter secret for XAI_API_KEY: `, waits 50ms, and writes the secret. the output then
reads `enter secret for XAI_API_KEY: xai-fixture-secret` and, on the next line, the 18 mask stars.

## .the gap, precisely

- the clear copy is the terminal driver's echo, so the bytes arrived while the tty was still in
  canonical mode with echo on — at least 50ms after the prompt text reached the pty
- a human who types or pastes a secret within that window sees it on screen and in scrollback.
  harm: a secret shown in the clear (reputation, security)
- `promptHiddenInput` itself prints and sets raw mode in one synchronous turn. two stubs that do
  the same, one prompt and a line prompt then a hidden prompt, show no echo
  (`blackbox/.test/assets/pty-with-answers.integration.test.ts` [case1], [case3]). so the window
  comes from what the real cli adds around the prompt — `withStdoutPrefix`, the bin path, or the
  mech flow before it. not yet measured

## .the shape of the fix

- measure first: log the time of the prompt write and of `setRawMode(true)` in the real `keyrack
  set` path, and find what sits between them
- then set raw mode BEFORE the prompt text is written, in `promptHiddenInput` and
  `promptLineInput`, so no byte can arrive in canonical mode once the prompt is visible
- clamp: [case4] with `choice: |enter secret for` — red with the window, green after

## .why it is not done in this round

#761 is the acceptance suite's box share. this is a keyrack product defect whose cause is not yet
measured, and it owes its own review.
