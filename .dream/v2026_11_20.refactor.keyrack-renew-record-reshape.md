## .the gap, precisely

- `renewOneEntry` writes five outcomes through five `setIfHeld` calls
- the record keeps the whole grant, secret included, past expiry for a marked entry, though the store purges expired secrets. the mech now reads its own field from the grant (`renewForDaemon({ grant })`), so only the record half remains
- the status render words a `lapsed` mark in sso terms (the vision's case 4 demo); a second renewable mech needs that text from its own adapter, not the generic render (i001 r011 #2)
- renew is an optional method on the shared adapter object, so the oidc alias drops it by rest-spread and the daemon loads guided setup code to renew; a `mech → renewer` registry makes absence the default (i001 r011 #4)
- `keyStore` and `renewRecord` both hold the grant by address, so every command must touch both; fold the renew facet into the store entry (i001 r011 #8)
- a marked entry pins the daemon with no bound; drop a mark some days past its cap (i001 r011 #9, F5)
- the status row decodes `expired` from `ttlLeftMs === 0 && mark`
- `inflight` is a bare `Set` threaded through two operations
- `getOneAwsSsoSessionProof` skips gate 1 under `AWS_SDK_MOCK`, an env a long-lived daemon inherits
- `vaultAdapterAwsConfig` keeps a partial mech adapter map beside `getOneKeyrackMechAdapter`

## .the shape of the fix

1. `asDaemonRenewEntryAfterOutcome({ entry, outcome }) → DaemonRenewEntry | null`, pure; the shell does one `setIfHeld` and the log line
2. `KeyrackDaemonUnlockRenewal` carries `source`; the record holds `{ identity, source, expiresAt, capAt, … }`, never a secret
3. `isExpired` on `DaemonStatusRow`
4. the record owns its inflight set
5. drop the env skip: the sdk gate is injected into the proof (#759), but its default still reads `AWS_SDK_MOCK`, an env a long-lived daemon inherits
6. one mech adapter lookup
7. a renewer registry keyed by `(vault, mech)`, not mech alone, whose renewer also owns its lapse text and fix note: the secret's shape is the pair's convention (`aws.config` stores a profile name), so a second vault under the same mech must not inherit a renew that reads its secret wrong (i004 r011 #5)
8. one store whose entry carries the renew facet; `del` and `entries` cover both
9. a bound on how long a mark keeps the daemon up
10. the mark typed as `{ kind: 'lapsed' } | { kind: 'halted'; cause: 'fault' | 'defect'; error }`, so the cli reads a field rather than the `💥 defect` prefix (i002 r011 #1)
11. one `asKeyrackDaemonPruneFixLeaves({ owner })` for the status halt and the skew warn (i002 r011 #2)
12. `asKeyrackStatusKeyBranch` split: the tree walker beside `asTreeBranch`, the fix command in its own file, one leaf producer per mark, in place of the two complementary spreads (i002 r011 #6, r004 nitpick.1)
13. the unlock opt-in extracted as `getOneKeyrackUnlockRenewal`, which the registry of item 7 answers (i002 r004 nitpick.2)
14. the UNLOCK handler parses `renewals` at the wire, so a `capAt` that does not parse is refused there, and the cap comparator then fails closed (i004 r011 #1)
15. the halt count derived as `ceil(windowMs / tickMs)` in the scheduler and injected, so "a full window of ticks" stays true when the window is tuned (i004 r011 #2)
16. the proof returns `{ live: false; gate; error }`, so a lapse mark carries its gate and headline (i004 r011 #3, r010 nitpick.2); `onInvalidLevel` leaves the proof
17. the unlock's three-way renew choice as a pure `getOneRenewChoiceForUnlock`, and the `renewable` reply by address, not slug (i004 r011 #4)
18. `asKeyrackStatusRow` spreads the row and fills only its optional keys, with a round-trip case (i004 r011 #6)
19. one lapse subtree per portal session in a multi-key rack, rather than one per key (i004 r010 nitpick.3)
20. a mark carries `since`, and its leaf shows it, so a lapse from minutes ago reads apart from one from the small hours (i005 r010 nitpick.4)
21. a key past expiry that still retries (a late wake, faults below the halt) keeps a status row, so status never goes blank while `get` says locked (i005 r010 nitpick.3, F15)
22. `--duration` help names that it is also the renew cap, and a keyrack brief names the renew, the lapse, and the halt (i005 r010 nitpick.6)

23. a held grant whose mech can renew, with no renew entry, carries `renew: { off: 'not filed' }`, so status reads `renew = off` and names the unlock that files one, never the same as a permanent key (5.3 frictionless walk, F30)

ship the wire change with a skew test, as the `renewable` reply did.

## .why it is not done in this round

each step moves the daemon wire or the record shape under a review that is otherwise closed, and the long-lived daemon makes a wire change a skew risk of its own. it earns its own pr.
