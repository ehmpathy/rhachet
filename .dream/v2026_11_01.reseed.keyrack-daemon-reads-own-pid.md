# 🌙 dream: the keyrack daemon's session gate reads its own pid as the caller's

kind = reseed · owner = rhachet (keyrack daemon) · caught 2026-11-01

## .the cue that fired

`v2026_11_01.fix-clone-auth-lookup-timeout` added a child-process-peer test for
`getSocketPeerCred`; it read the reader's own pid (3004316 = self; the peer was 3009574). the clone
reader was fixed there. the daemon reader shares the faulty parse.

## .the gap, precisely

`asSocketPeerPidFromSs` returns the `pid=` from the first `ss -xp` line that holds our socket inode
as any token. our inode shows on two lines: our own (local column, process = the reader) and the
peer's (peer column, process = the caller). the reader's line can win, so `getSocketPeerPid`
(`src/domain.operations/keyrack/daemon/svc/src/infra/getSocketPeerPid.ts`) may hand
`verifyCallerLoginSession` the daemon's own pid, and the session gate checks the daemon against
itself.

## .the shape of the fix

- switch `getSocketPeerPid` to `asSocketPeerPidFromSsPeerLine` (`src/infra/socket/`), the
  peer-column read the clone gate now uses; a peer this user cannot see yields null → refuse
- retire `asSocketPeerPidFromSs`, which then has no reader
- clamp: a child-process caller; assert the gate reads the child's pid, and that a caller outside
  the login session is refused
- care: this changes who keyrack admits (the real caller's session is checked for the first time);
  land with ehmpathy/rhachet#685 or right after it

## .why it is not done in this round

the wisher scoped this PR to the clone gate; a switch of the daemon's gate changes who keyrack
admits and owes its own review.
