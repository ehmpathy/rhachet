## .the cue that fired

the 5.3 snapshot-coverage lane (i004 r010, nitpick 3): vision case=5 `[t1]` and `[t2]` (a dead
`use`, and a dead row beside a live row in `get`) are critipaths with integration and unit proof
only; acceptance `[case5]` snaps the absent case alone.

## .the gap, precisely

- the built binary never classifies a real provider refusal as `dead`; every 401 path runs over an
  injected reply
- a positive leg needs no paid seat: a fabricated, unexpired grove login is refused by the real
  oauth host, so the signed-in row reads `dead` and `get` exits 2
- it needs network inside the acceptance tier, and it sends a fabricated refresh token to the real
  host

## .the shape of the fix

- a peer of acceptance `[case6]` with a future `expiresAt` and a made-up refresh token
- assert the row reads `dead`, the exit is 2, the hint names `set`, and stdout holds no token
- mark the leg as a network leg, so the credfree run and ci both know it reaches out

## .why it is not done in this round

whether the acceptance tier may reach the real oauth host is a tier call, not a test edit; the
credfree tier is built to run offline. F22 does not forbid it, since no route is added to the binary.
