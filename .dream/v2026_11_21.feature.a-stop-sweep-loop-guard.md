# 🌙 dream: one loop guard for the stop sweep's holds

- kind = feature
- owner = ehmpathy/rhachet
- caught 2026-11-21

## .the cue that fired

peer review r10 blocker.2 (i006) on `.behavior/v2026_11_21.fix-enroll-orphan-min-warns-onstop`: no code reads `stop_hook_active`, so a clone that will not repair a held defect is held on every stop.

## .the gap, precisely

claude passes `stop_hook_active: true` on a stop that follows a held one. `invokeRolesCostForHook` reads no stdin, so the budget hold and the content hold both re-fire without bound on a clone that cannot or will not repair (a read-only leaf, a print-mode clone).

## .the shape of the fix

- read the hook payload in `invokeRolesCostForHook`; parse `stop_hook_active`
- decide one policy for every hold kind (budget, content, mod drift), e.g. hold on the first stop, warn on a stop already held, with a count kept in the memo so the hold returns after N clean turns
- clamp: a stop with `stop_hook_active: true` on a held defect exits per the policy; red before, green after
- note it in `rule.forbid.content-checks-that-halt-enroll` and the budget brief

## .why it is not done in this round

the guard changes the budget hold too, a contract this pr does not touch; one hold alone that released would make the sweep behave two ways (fulcrum F25).
