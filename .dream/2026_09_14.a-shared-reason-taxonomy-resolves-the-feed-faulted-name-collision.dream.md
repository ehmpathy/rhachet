# 🌙 dream: a shared reason-taxonomy resolves the `'feed-faulted'` name collision across two closed sets

- **kind**: refactor
- **owner**: ehmpathy/rhachet (this repo)
- **caught**: 2026-09-14
- **fulcrum**: F20

## .the cue that fired

r011 (enroll-impl-arch-defects) decompose-for-recompose item 1: the literal `'feed-faulted'` is a
member of **two unrelated closed types** with **two different prose strings**, reached by two
different code paths — `CloneOperationalRejectReason` (pre-write dequeue reject, copy in
`computeCloneOperationalRejectClass.ts`'s `CLONE_OPERATIONAL_REJECT_COPY`) and the verdict-reason
set consumed by `REASON_COPY` / `DEGRADE_COPY` in `computeCloneSayReport.ts` (post-write
observe-degrade). no type forces the two to stay aligned if one changes.

## .the gap, precisely

three independent "reason → human copy" tables live in two files, and one literal (`'feed-faulted'`)
spans two of the three closed sets with no shared definition. the two strings are currently
consistent in MEANING (both name a faulted emulator feed), so this is a nitpick today — but a name
collision across unrelated closed sets is exactly the shape that drifts silently: an edit to one
copy leaves the other stale, and no type or test couples them.

## .the shape of the fix

1. introduce a shared reason-taxonomy module (e.g. `CloneScreenFeedReason`) that owns the
   `'feed-faulted'` / `'feed-not-live'` literals ONCE, as the single source both paths import.
2. or, if the two concepts are genuinely distinct (a pre-write reject vs a post-write degrade),
   RENAME one so `'feed-faulted'` names exactly one concept — e.g. the reject-path member becomes
   `'feed-faulted-at-dequeue'`.
3. re-point `CLONE_OPERATIONAL_REJECT_COPY` and `REASON_COPY` / `DEGRADE_COPY` at the shared
   taxonomy (or the renamed members).
4. resnap every error/report snapshot that carries the affected reason strings.
5. a unit clamp that asserts the two paths agree on the shared literal (or that the rename split
   them cleanly).

## .why it is not done in this round

it fails the CLEAN test (`rule.always.fix-forward-under-scouts-honor`): a cross-type taxonomy
extraction (or a literal rename across two closed sets) ripples into three copy tables, two files,
their consumers, and every snapshot that renders the affected reason strings — and it touches the
`computeCloneOperationalRejectClass` path, which is out of this wish's screen-read scope. the
reviewer graded it a nitpick, not a blocker (the strings agree in meaning today), so it is a
maintainability refactor that deserves its own dedicated PR per
`rule.forbid.deferrals-short-of-a-dedicated-pr`. the decision to defer is recorded as fulcrum F20.
