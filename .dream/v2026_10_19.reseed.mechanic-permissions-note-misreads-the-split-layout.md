# 🌙 dream: the mechanic permissions init prints a note the split layout made false

kind = reseed · owner = `ehmpathy/rhachet-roles-ehmpathy` (role mechanic) · caught 2026-10-19

## .the cue that fired

a 5.3 snapshot review of `blackbox/cli/__snapshots__/init.incremental.acceptance.test.ts.snap`. the
mechanic init now writes `.claude/settings.of.repo.json`, and its stdout also prints:

```
note: this clone's config dir is $REPO_ROOT/.agent/.actors/actor.via.repo=ambient/brain/.claude;
its settings.of.repo.json is derived from this file. ...
```

## .the gap, precisely

- the file it just wrote IS `settings.of.repo.json`, so "derived from this file" now says the file is
  derived from itself
- "this clone's config dir" names a grain this repo forbids: a clone has no config dir, it reads its
  actor's brain dir (`rule.forbid.clone-config-misnomer`)
- source: `rhachet-roles-ehmpathy@1.39.5`, `dist/domain.roles/mechanic/inits/init.claude.permissions.sh:129`

## .the shape of the fix

in that init, print the note only when the target file is not `settings.of.repo.json`, or reword it to:
`note: the repo actor's brain dir is $dir; every actor picks up new allows at the next rhx init --hooks,
rhx upgrade, or its own next rhx enroll.` then resnap the consumer snapshot here.

## .why it is not done in this round

the text lives in another repo's published package. this repo only snapshots what it prints. a fix here
would edit `node_modules`; the change belongs upstream.
