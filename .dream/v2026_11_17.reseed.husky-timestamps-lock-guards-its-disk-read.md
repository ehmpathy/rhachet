# 🌙 dream: the husky practice's timestamps lock guards its disk read and names its args

- kind = reseed
- owner = the declapract `husky` practice (ehmpathy)
- caught 2026-11-17

## .the cue that fired

peer review on `fix-keyrack-sso-self-renew` raised three defects in `.husky/check.timestamps.lock.sh`, a file `declapract apply --practice husky` writes. a local edit would be overwritten on the next apply.

## .the gap, precisely

- `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK")` is unguarded; a git failure reads as `✋ ConstraintError ... was changed` at exit 2, where the index read beside it routes a git failure to `timestamps_lock_malfunction` at exit 1
- the file opens with no `set -eu`, unlike its peers `check.timestamps.sh` and `check.secrets.sh`
- `timestamps_lock_halt` takes two positional args (`$1` found, `$2` where)
- `check.secrets.sh:48` and `check.timestamps.sh:67` scan through `grep … | head -n 1`, whose exit is `head`'s; a `grep` that rejects a bad pattern (exit 2) reads as no match, and the hook passes the commit silently

## .the shape of the fix

in the practice: `|| timestamps_lock_malfunction` on the `git hash-object` read; `set -eu` at the top; one pre-composed `found` string (or named args) for the halt helper; each scan captures `grep`'s own exit, absorbs 1 (no match), and raises a `💥 MalfunctionError` on any exit above 1. then `declapract apply` in each consumer.

## .why it is not done in this round

the file is generated; the fix belongs to the practice so every consumer gets it (fulcrum F14 on the route).
