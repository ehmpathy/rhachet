# 🌙 dream: the keyrack set unit tests leave module mocks for injected fakes

- kind = chore
- owner = ehmpathy/rhachet (keyrack tests)
- caught = 2026-11-16

## .the cue that fired

peer round i001 of `5.3.verification` on `beav/feat-keyrack-github-app-off-ec2`, r009 blocker.1
and nitpick.1: `setKeyrackKey.test.ts` and `setKeyrackKeyHost.test.ts` `jest.mock` the host and
repo manifest daos and the daemon sdk; `vaultAdapterOsSecure.integration.test.ts` mocks
`promptHiddenInput`. each mock predates the pr that drew the review.

## .the gap, precisely

a unit test may not cross a remote boundary or mock a module (`rule.forbid.unit.remote-boundaries`);
an integration test may not mock a module without a `.real` pointer (`rule.forbid.integration.mocks`).
the two unit files reach the filesystem daos and the daemon socket through module mocks.

## .the shape of the fix

the orchestrator cases that need a dao write move to the `.integration.test.ts` peers, which
already run over a temp home with the real daos; what stays a unit test takes the daos and the
daemon relock through its context, as the vault adapters already do. the os.secure integration
suite takes its secret prompt through the context, or its mock gains the `.real` pointer.

## .why it is not done in this round

the mocks are extant on main; the pr touched these files only to pass a new required field and to
add cases that use no module mock. fulcrum F12 hands the call to the commander at the pr.
