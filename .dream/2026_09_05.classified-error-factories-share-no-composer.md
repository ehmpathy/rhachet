## .the gap, precisely

there are **two** patterns at four sites each, and they are different patterns:

### pattern A — the classified-error factory

| factory | what decides the class |
|---|---|
| `asCloneSocketOmissionReasonError` | reads **platform support** — `MalfunctionError` on a supported host, `ConstraintError` elsewhere |
| `asPtyDeviceRefusedError` | **unconditionally** caller-fault |
| `asCloneSocketBindFaultError` | **unconditionally** ours |
| `asNpmInstallFailureError` | reads a **failure kind** enum |

### pattern B — the marker classifier

| predicate | what it matches on |
|---|---|
| `isPtyAddonLoadError` | errno **classes** (`ERR_DLOPEN_FAILED`, `MODULE_NOT_FOUND`) |
| `isCloneSocketBindFaultError` | **syscalls** (`chmod`, `listen`, `bind`) |
| `isPtyDeviceRefusedError` | message **markers** |
| `asNpmInstallFailureKind` | a **co-occurrence** guard over two signals |

they share `matchesAnyMarker` and no more.

## 🚨 .why it was NOT done in this round, and that reason is the sharp part

**SAFE:** yes — additive, and every site has clamps today.
**CLEAN:** no — **and not for a scope reason. the abstraction's shape is genuinely undecided.**

⚠️ **a composer that takes "the class decision" as a parameter has abstracted naught.** look at
pattern A's right-hand column: two are constant, one reads the platform, one reads an enum. hoist
that and the parameter *is* the function — every caller passes the whole behavior in, and the shared
piece holds only the `new XError(msg, {...})` call it was already one line to write.

pattern B is worse: four **different match axes** (errno class, syscall, message marker,
co-occurrence). a scaffold over those is a `switch` on which axis you meant.

⇒ this is `rule.prefer.wet-over-dry`'s own caution, in its own words: **a wrong abstraction is
dearer than the duplication.** the rule says abstract at 3+; it does not say abstract *badly* at 3.

✅ **so the honest state is: rule-of-three is crossed, the pull is real, and the shape is not yet
visible.** r011's own bound is the right trigger — *"worth a lightweight index/lint **if a 5th
appears**."*

## .the shape of the fix, when a 5th arrives

the 5th site is likely the **socket-bind-timeout class** (already dreamed), which would make pattern
A five-of-a-kind with a genuine third class-decision *kind*. at that point:

1. **the vocabulary clamp first, and it earns its keep even alone** — one test over every factory
   that asserts the shared surface: the `the reach socket is unavailable — ` prefix text, the
   `hostTuple` field name, the presence of a `hint`. it needs **no** composer, it closes r010's C.2
   outright, and it is the cheapest of the five points
2. **then the audit index** — one module that names every class decision, so r011 #4's
   *"no single place to audit"* has an answer
3. **only then the composer**, and only if step 1's clamp has made the shared surface explicit
   enough to name

⚠️ **do step 1 first even if 2 and 3 are declined.** a clamp on the vocabulary is what makes a drift
redden; the composer is what makes a drift impossible. the first is cheap and the second is the one
with the undecided shape.

## .why it is not done in this round

the wish bounds this round to *"how rhachet declares, installs, and loads node-pty; the notice it
prints when the load fails."* the factories were **authored** by this round, so a repair to them
would be in scope — but a repair is not what is owed here. what is owed is an abstraction whose
shape the round could not determine, and to guess at it under a scope bound is the worst of both.

✅ **and the residual risk is low and stated:** every one of the four sites has its own clamp today
(payload tests plus acceptance frames), so a drift is caught per-site. what is absent is that a
drift in one would not redden a **peer** — which is a real gap, and a narrower one than "there is
no composer."
