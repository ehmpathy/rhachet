## .the gap, precisely

no shared operation answers "which on-disk clone is this process?" or "where are this clone's dirs?". each command re-derives it, so a change to the env key or the fault text lands in one copy and not the others.

## .the shape of the fix

- `getOneCloneSelf({ env, repoPath }): CloneOndisk | null` — the env serial resolved to its clone, the malfunction when the serial names none
- a `cloneDir` / `actorDir` pair on `CloneOndisk`, or `getCloneOndiskDirs({ clone })`, so no command rebuilds them
- move `invokeCloneWhoami`, `invokeCloneGet`, and `invokeCloneBoot` onto both; their tests hold the behavior
