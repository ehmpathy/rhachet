# 🌙 dream: `rhx teesafe` wipes an extant destination, drops a final newline, and errors on its own stdout

- **kind** = reseed
- **owner** = `ehmpathy/rhachet-roles-ehmpathy` — `role=mechanic/skills/claude.tools/teesafe.sh`
- **caught** = 2026-09-25
- **severity** = 🔴 **data loss** — defect 3 below destroys a file's prior contents

## .the cue that fired

the `5.5.playtest` byhand walk used `rhx teesafe` to snapshot the default `boot.md` so two renders
could be compared byte for byte. the snapshot did not round-trip, and the skill reported a 💥 while
it wrote the file anyway.

```
$ cat .agent/.actors/actor.via.slug=.default/brain/.claude/boot.md \
    | rhx teesafe --into .temp/playtest/boot.snap1.md | wc -c
🪨 run solid skill repo=ehmpathy/role=mechanic/skill=teesafe
   └─ 💥 failed with an error

tee: 'standard output': Resource temporarily unavailable
65601
```

⇒ a caller who reads the count on stdout is told **65,601**. the source is **930,186**.

## .the gap, precisely — TWO defects, and they are independent

### defect 1 — the final newline is dropped (deterministic)

```
$ wc -c .agent/.actors/actor.via.slug=.default/brain/.claude/boot.md .temp/playtest/boot.snap1.md
 930186 .agent/.actors/actor.via.slug=.default/brain/.claude/boot.md
 930184 .temp/playtest/boot.snap1.md

$ diff .agent/.actors/actor.via.slug=.default/brain/.claude/boot.md .temp/playtest/boot.snap1.md
21722,21723c21722
< </brief.say>
<
---
> </brief.say>
\ No newline at end of file
```

the source ends `</brief.say>\n\n`; the snapshot ends `</brief.say>` with **no terminal newline**.
two bytes short, and `\ No newline at end of file` names the cause outright.

🔴 **two runs produced byte-identical output** (`diff boot.snap1.md boot.snap2.md` → no rows), so
this is not a race — it is a **deterministic transform**. the shape is the classic
`CONTENT=$(cat)` + `printf '%s' "$CONTENT"` pair: command substitution eats **every** terminal
newline, so the count of bytes lost equals the count of newlines the input ended with.

⇒ **`cmd | rhx teesafe --into f` is not an identity for a file that ends in a newline**, which is
most files. any comparison of a teesafe snapshot against its source reports a false difference.

### defect 2 — the stdout write fails, and the exit says 💥 although the file landed

```
tee: 'standard output': Resource temporarily unavailable
```

`EAGAIN` on fd 1 — the downstream pipe was in `O_NONBLOCK` mode and `tee` did not retry. so:

| what happened | what the caller sees |
|---|---|
| the file **was** written (930,184 of 930,186 bytes) | exit non-zero, banner reads `💥 failed with an error` |
| stdout carried a **partial** stream | a downstream `wc -c` reports a count that is neither the source's nor the file's |

the two runs printed **65,601** and **122,945** for the identical input, which is the tell: the
stdout half is nondeterministic while the file half is not.

🟡 the combination is the hazard. a `💥` beside a file that **did** land invites the caller to
retry, and a retry re-truncates the same two bytes and prints a third unrelated count.

### 🔴 defect 3 — a downstream pipe that closes early DESTROYS the destination

the severe one. found later in the same walk, **reproduced deterministically, and isolated to a
single trigger.**

**with a downstream `head` that closes the pipe — the file is wiped:**

```
$ printf 'world\n' | rhx teesafe --into .temp/playtest/tee.probe2.md --idem upsert | head -3
   └─ 💥 failed with an error
$ wc -c .temp/playtest/tee.probe2.md
0 .temp/playtest/tee.probe2.md          # it held 'hello'. it is now EMPTY.
```

**with NO downstream pipe — the very same call is correct:**

```
$ printf 'bravo\n' | rhx teesafe --into .temp/playtest/tee.probe3.md --idem upsert
$ wc -c .temp/playtest/tee.probe3.md ; cat .temp/playtest/tee.probe3.md
5 .temp/playtest/tee.probe3.md
bravo
```

⇒ 🔴 **the destination's fate depends on whether the CALLER stayed on stdout.** an early pipe close
leaves the file truncated and the body unwritten — the prior contents destroyed, the new contents
never delivered.

the mechanism follows from defect 2: the destination is opened for **truncate before** the body is
streamed, and the `EAGAIN`/`SIGPIPE` on fd 1 aborts the run **between** the truncate and the write.
so defect 2 is not a cosmetic `💥` — on an extant destination **it is the mechanism of the data
loss**, and the `| head` idiom is what reaches it.

it hit a real file before any probe did. the `5.5.playtest` walk ran:

```
$ printf 'a human hand-edited this door\n' \
    | rhx teesafe --into .agent/.actors/actor.via.slug=.default/brain/.claude/AGENTS.md --idem upsert \
    | head -3
   └─ 💥 failed with an error
$ wc -c .agent/.actors/actor.via.slug=.default/brain/.claude/AGENTS.md
0 …/AGENTS.md
```

🟡 the walk recovered because `rhx init --hooks` re-renders that exact file. **a destination with no
generator would simply be gone.**

⚠️ **and `| head` is the house idiom.** a hooked agent is steered to `teesafe` by
`pretooluse.forbid-suspicious-shell-syntax` and steered to `| head` to bound a skill's banner. the
two sanctioned habits compose into file destruction.

## .why it matters beyond this walk

`teesafe` is the sanctioned replacement for `>` on this fleet — `pretooluse.forbid-suspicious-shell-syntax`
names it as the alternative, so every redirect a hooked agent writes routes through it. a transform
that quietly alters what it stores sits on the one path a hooked agent cannot avoid.

⚠️ it cost this route real time: an earlier segment read two different `wc -c` counts off teesafe
snapshots of one render and treated the render as nondeterministic. the render was byte-stable all
along; **the instrument was the variable**, which is `rule.require.refute-a-premise-with-a-measurement`
read from the wrong end.

## .the shape of the fix

1. **stop the newline loss.** avoid `$(cat)` for the body. stream instead — hand the input to
   `tee "$DEST"` directly, or `cat` into `"$DEST"` under the `--idem` mode already declared. the
   skill already shells out to `tee`, so the strip is in the wrap around it, never in `tee`
2. **make the stdout write tolerant.** either retry on `EAGAIN`, or accept that a caller who
   discards stdout is the common case and let an unwritable fd 1 be a no-op rather than a 💥
3. **do not report 💥 for a write that succeeded.** the exit code owes the FILE's fate, never the
   mirror's
4. 🔴 **never truncate before the body is in hand.** write to a temp path beside the destination and
   `mv` it into place once the stream completes. a failed run then leaves the prior file untouched,
   which is what makes defect 3 impossible rather than merely rarer
5. **clamp all three.** a round-trip case — write a fixture that ends in a newline, read it back,
   assert byte equality — plus a large-input case that pipes stdout onward and asserts the file still
   matches — plus an **upsert-over-extant** case that asserts the destination is either the new
   content or the old, never empty

## .why it is not done in this round

- **SAFE?** 🔴 not applicable — the file lives in `node_modules/rhachet-roles-ehmpathy/`, a peer
  package. there is no edit to make in this repo at all
- **CLEAN?** 🔴 same — a change here would be a vendored patch that the next `pnpm install` erases

⇒ a **reseed**: the work belongs to the repo that owns the skill, and a tree adopts only what is
scoped to itself (`rule.always.scope-onetime-lessons-to-the-behavior`). no fulcrum is owed — the
deferral turns on ownership, never on a judgment about ripple cost.
