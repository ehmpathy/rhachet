# 🌙 dream: boot.cache.skills [case7] hangs on a local integration run, green on ci

- kind = fix
- owner = rhachet (this repo)
- caught 2026-11-18

## .the cue that fired
5.3 verification of `.behavior/v2026_11_17.feat-hook-dispatcher-one-process-per-event`:
`rhx git.repo.test --what integration --scope 'path://boot\.cache\.skills' --scope 'name://case7' --mode apply`
fails alone, both thens, `Exceeded timeout of 180000 ms`. the same test passes on ci at head `313d7c1`
(`test-shards-integration` 1–3 green), and each of the six skills answers `npx rhx <skill> help` in
under a second from a shell.

## .the gap, precisely
[case7] spawns `npx rhx <skill> help` six at once with `spawn` (stdin a pipe, left open) and waits on
`close`. locally one child never closes. `close` waits for every stdio fd, so either a child reads the
open stdin, or a grandchild (a daemon the env starts, e.g. keyrack's) inherits stdout and outlives it.
the test file is unchanged on this branch (last touched by #713).

## .the shape of the fix
1. record which skill hangs: settle each child on `exit` too, and print the ones whose `close` lags
2. if a grandchild holds stdout: spawn with `stdio: ['ignore', 'pipe', 'pipe']` and find the daemon
3. if a skill reads stdin on `help`: fix the skill's arg parse to answer help first

## .why it is not done in this round
it is outside the hook dispatcher change, green on ci, and the cause needs a probe of its own.
