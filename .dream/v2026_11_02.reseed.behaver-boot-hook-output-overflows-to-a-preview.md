# 🌙 dream: the behaver boot-behavior hook prints more than claude keeps, so a bound route mostly never reaches the brain

- kind = reseed
- owner = ehmpathy/rhachet-roles-bhuild (role=behaver, init `claude.hooks/sessionstart.boot-behavior`)
- caught 2026-11-02, in `.behavior/v2026_11_02.fix-boot-briefs-cacheable`

## .the cue that fired

`rhx boot.cache.probe --diff` logged the raw request a clone sends. block [1] of the first message reads:
`SessionStart:startup hook success: <persisted-output> Output too large (13KB). Full output saved to:
…/tool-results/hook-<uuid>-stdout.txt … Preview (first 2KB):`.

## .the gap, precisely

- the hook prints the bound route's wish and stones (13KB on this route); claude code persists hook output
  past its size limit to a file and shows a 2KB preview. the brain sees the first 2KB only
- the persisted path holds the session id and a hook uuid, so the block differs every session (harmless
  to the boot once the boot moves to the system prompt, but still a per-session value early in the prompt)
- the output grows as the route grows, so a route that boots fine on day one degrades silently

## .the shape of the fix

the hook prints a short pointer (route path, current stone, the paths to read) under the size limit, and
the brain reads the files on demand; or the hook prints only the wish and the current stone. clamp: a
test that the hook's stdout stays under claude's persisted-output threshold for a fixture route with many
stones.

## .why it is not done in this round

the hook lives in another repo (bhuild), and this route's wish is the boot corpus's cache seat, not hook
output size.
