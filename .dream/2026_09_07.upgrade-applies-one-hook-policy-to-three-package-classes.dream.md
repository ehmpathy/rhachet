# 🌙 dream: `rhx upgrade` applies ONE hook policy to three package classes, and only one of them is surveyed

- **kind** = repair
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-07

## .the cue that fired

the r011 (`enroll-impl-arch-defects`) lane, at i075 — the one lane in that set that ran to a verdict:

> *"`execUpgrade.ts` still applies one `lifecycleHooks: 'skip'` value across a heterogeneous install
> list (rhachet + role packages + brain packages) … a future native optional dependency with a
> non-no-op hook would still inherit `skip` silently, with only prose (not a type or a test)
> [that stands] guard."*

## .the gap, precisely — and it is NARROWER than the lane stated

`execUpgrade.ts` builds one list and hands it one policy:

```ts
const installList = buildInstallList({
  self: upgradeSelf,
  rolePackages: roleExpanded.packages,
  brainPackages,
  exclude: localRefDeps,
});

execNpmInstallLocal({ packages: installList, lifecycleHooks: 'skip' }, context);
```

🚨 **the "new dependency CLASS" case is already guarded, and it is guarded by the TYPE.**
`buildInstallList` takes a named-field input, so a fourth class cannot enter `installList` without a
fourth field — a compile-visible edit on the exact lines the `lifecycleHooks` note sits above. that
half of the lane's claim does not hold.

⚠️ **the real gap is the case it did not name: a new package added INSIDE an extant class.**

| the class | its hooks | what `skip` costs |
|---|---|---|
| role packages | pure content — briefs and shell skills, no hook declared | naught. `skip` takes none |
| `rhachet` itself | node-pty's hook, which only CHECKS for a prebuild and exits 0 | naught **today** — measured in `[case7]` of `getPtyModuleOrNull.consumer.integration.test.ts` |
| **brain packages** | 🔴 **UNSURVEYED** — third party, and the code says so outright | **unknown** |

⇒ a third brain package whose hook is not a no-op adds **no field**, passes **no reader**, and
inherits `skip` silently. no type sees it and no test reddens.

⚠️ and this is the same defect class as the wish that caught it: node-pty was broken on linux for ten
days-plus precisely because a build hook it needed did not run and nobody was told.

## .the shape of the fix

1. **survey the brain packages' hooks first** — this is the expensive half and the half no design can
   skip. `rhachet-brains-*` are third-party-adjacent; read each `package.json` for a lifecycle hook
   and record what it does. **the survey may well conclude `skip` is correct for all three classes**,
   and that outcome is a real result rather than a failure
2. **carry the policy WITH the packages, not beside them** — `buildInstallList` returns
   `string[]`, which is the shape that loses the class. return
   `{ package: string; lifecycleHooks: NpmInstallLifecycleHooks }[]` and the policy travels with each
   row, so a new package inherits its class's answer rather than the list's
3. **group by policy at the invocation** — one `execNpmInstallLocal` per distinct value. ⚠️ this is
   the part that changes behavior: one install becomes up to two, which alters the order of the
   installs and where an error is attributed, and rewrites the `execUpgrade` suite's `packages:`
   assertions
4. **clamp the survey, never the code alone** — a row that asserts each class's declared policy, so a
   future edit that flips a class reddens with the reason attached

## .why it is not done in this round

⛔ **the SAFE/CLEAN test fails on CLEAN, and it fails on the survey before it fails on the code.**

- the fix cannot be made correctly without the brain-package hook survey, and that survey is its own
  drive with its own evidence — `execUpgrade.ts`'s own note says as much, verbatim: *"`skip` is
  retained for them only because it is the extant behavior and a change here belongs to its own
  drive with its own evidence, never to a rider on this one"*
- step 3 splits one install into several, which is a behavior change to `rhx upgrade` inside a wish
  about node-pty's install. that is a scope leak in the shape of a cleanup
- the wish's own bound forbids it: *"do NOT edit the consumer repos' lockfiles as the fix"* is about
  a different surface, but the same principle — this drive fixes how rhachet declares and loads
  node-pty, not how it sequences every upgrade

✅ **and the deferral is honest rather than convenient, because the risk today is measured:** the one
class that could carry a live hook (`rhachet` → node-pty) is proven a no-op by a clamp, and the two
that are unsurveyed declare no hook at all in the packages currently shipped. the gap is a **future**
package, never a present one.

⚠️ per `rule.always.catch-dreams-for-followups` a deferral for DIRT owes a fulcrum. this one is
recorded as **F15** in `$route/.fulcrums/`, and its entry states the part that is genuinely
undetermined: **whether step 3 is needed at all depends on the survey's outcome.** if the survey
confirms `skip` is right for every class, the whole fix is step 4 — a clamp — and the rework was
clean. the deferral therefore rests on the survey's cost, never on a ripple estimate I did not take.
