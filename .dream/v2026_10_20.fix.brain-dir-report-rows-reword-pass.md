# 🌙 dream: one reword pass over the brain-dir report rows

kind = fix · owner = ehmpathy/rhachet · caught 2026-10-20

## .the cue that fired
four peer nitpicks on stone 5.3 of `v2026_10_15.fix-split-layout-local-settings-arrow` asked to
reword the same rows. each reword alone would move ~8 snapshot files.

## .the gap, precisely
- `replaced` carries three senses: a `moved (replaced)` suffix, an arrow swap, and a grove-less
  removal whose own row says `removed` (`asBrainDirLayoutReportGroups` hard-codes `label: 'replaced'`
  for both the REPLACED and REMOVED effects)
- `unexcluded` reads as "kept" and its row says `dropped`, while a separate `dropped` group means
  "rhachet owns the boot context"
- `its content is gone` prints for a committed file too, which git still holds
  (`upgrade.default-actor-migration.journey` [t4])
- `roles init`'s `🟡 the layout did not land; run rhx init to see why` names no cause, though the
  cause is known (`setRepoActorBrainDirLayout` returns null and drops it)

## .the shape of the fix
1. settle one vocabulary first: e.g. `replaced` (arrow took a real file's place), `removed` (no
   arrow, file gone), `dropped` reserved for one sense, `unexcluded` → a word that reads as removal
2. split the REMOVED effect into its own group in `asBrainDirLayoutReportGroups`
3. the replaced row: say `if it was committed, git still holds it` (or detect tracked state)
4. carry the layout fault out of `setRepoActorBrainDirLayout` (a result with the error, not null) so
   `invokeRolesInit` prints the class + message like `asBrainDirBootFailureLines`
5. one resnap per suite, each verified on an independent run

## .why it is not done in this round
safe but not clean: it moves the shared row source, a contract snapped in ~8 files, and (step 4)
the layout op's return contract. fulcrum F21 records the call.
