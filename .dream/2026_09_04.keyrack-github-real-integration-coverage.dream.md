## the itch

`rule.forbid.integration.mocks` is unambiguous: a `.integration.test.ts` that mocks
`node:child_process` proves the mock works, never the integration. the github vault does exactly
that, and carries no real-dependency suite to offset it.

a repo-wide search — `jest.mock('node:child_process')` + `genMockGhRun`, over
`src/**/*.integration.test.ts` — finds **five** files that fake github in the integration tier:

| # | file | fake | documented? |
|---|---|---|---|
| 1 | `github.secrets/vaultAdapterGithubSecrets.integration.test.ts` | `jest.mock('node:child_process')` | ❌ |
| 2 | `github.secrets/ghSecretSet.integration.test.ts` | `jest.mock('node:child_process')` | ❌ |
| 3 | `github.secrets/ghSecretDelete.integration.test.ts` | `jest.mock('node:child_process')` | ❌ |
| 4 | `mechanisms/genGithubAppSource.integration.test.ts` | `genMockGhRun` | ❌ |
| 5 | `aws.params/setKeyrackAwsParamGithubApp.integration.test.ts` | `genMockGhRun` | ✅ — `.creds` note, lines 37-39 |

⇒ **four genuine violations, one compliant.** row 5 states its reason inline (*"the github side is
faked via `genMockGhRun` + a temp pem, so no real github-app credentials are needed for the write
side"*) and dials **real** aws ssm for the half it is actually about, so it takes the exception the
rule allows. rows 1–4 take no exception and state no reason.

⚠️ the r3 lane named rows 1, 2, and 4. row 3 (`ghSecretDelete`) is the same violation, same
directory, and was missed — so the true count is four, not three.

## the contrast that makes it a defect rather than a preference

`aws.params` is the same kind of surface and has the coverage:

| suite | what it proves against real aws ssm |
|---|---|
| `getOneKeyrackAwsParam.integration.test.ts` | provisions its own SecureString, reads it back decrypted, asserts value + type, tears it down |
| `delKeyrackAwsParam.integration.test.ts` | the real destroy, a confirm-gone read, an idempotent re-del |
| `vaultAdapterAwsParams.integration.test.ts` | unlock → get → grant, plus the real absent-param and plaintext-`String` refusals |
| `setKeyrackAwsParamGithubApp.integration.test.ts` | the real write path |

each passes `endpoint: null` and takes creds from `useKeyrack()`, so the emulator override cannot
reach them. github has no member of this table.

## the dream

**one** real-dependency suite for the github vault — the floor the rule asks for, not a rewrite:

- calls the real github api (a real `gh` invocation, or the rest api directly)
- takes real credentials through `useKeyrack()`, so absent creds fail the suite loud rather than
  skip it
- validates real response shapes
- exercises at least one real error path (an absent secret, a permission refusal)

the four mocked suites may **stay**. they cover branch logic cheaply and there is no reason to pay
a network call for each. what the rule wants is that *some* test proves the integration is real —
and once one does, the four can each take the documented exception the way row 5 already does.

## why it is a dream, not that behavior

three grounds:

1. **not one of the four files is in this branch's diff.** `git diff origin/main --stat` over
   `github.secrets/` and `mechanisms/` is empty; the four last moved in `#462`, `#427`, and `#325`.
   the finding came from outside the target set the lane was handed — a property of pull focus,
   never a fault in the finding
2. **it is a credentials + budget decision.** a real github suite needs a github-app install (or a
   token) provisioned for ci, and puts a network call in every `test:integration` run. that is a
   foreman call, the same class as the real-brain skips
3. **the rework is clean.** a new test file adds coverage and removes none, so no work built on top
   has to be torn down (`rule.always.defer-fulcrums-to-last`)

## the sibling finding, same class, same round

r1's blocker.1 named `genFakeSsmServerDetached` in the **acceptance** tier — a fake where the tier
forbids one (`rule.forbid.acceptance.mocks`). the cure there is a two-line rename to
`.integration.test.ts`, and it is also pre-branch.

⇒ **two findings, one class.** both want a focused pass where the diff is legible, rather than a
tail-end edit at the close of a long drive. they belong in the same wish.

## the wisher call this dream asks for

- which credential does the real suite take — a dedicated test github-app install, or a fine-grained
  pat scoped to one throwaway repo?
- does the real suite run on every `test:integration`, or in a named on-demand tier alongside the
  11 real-brain skips (see `5.3.verification.handoff.v1.to_foreman.md`, item 2)? both are the same
  budget question and want one answer.

written 2026-09-05, after the acceptance suite `keyrack.vault.githubSecrets` was converted from a
PATH-stub mock to a real-`gh` **swap** (`genFakeGithubApiServer` + `ghApiStandInServer.cjs`).

**this dream's ask is unchanged** — a swap proves no fact about the wire hop, so the one
real-dependency suite is still owed, and the two wisher questions below still want one answer.

but two of its premises moved:

|---|---|

| a real github lane needs credentials + a network call | still true for the **integration** tier this dream asks for; but the acceptance tier no longer needs either |

⇒ and one adjacent opportunity now exists that did not before. **four other acceptance suites still
put a stub `gh` first on PATH** — `keyrack.infra`, `keyrack.aws-params.githubApp`,
`keyrack.vault.osSecure.githubApp`, `keyrack.vault.1password` (via `blackbox/.test/assets/mock-gh-cli/gh`).

⚠️ deliberately **not** done in the `fix-keyrack-all-skips-manifest` branch: not one of the four is

## ⚠️ what this dream is now scoped to — narrowed 2026-09-05

**a `.real` backstop landed, so this dream is no longer the only cover for the wire hop.**
`blackbox/.test/infra/verify.githubSecrets.wirehop.sh` dials real github and asserts each shape
the stand-in serves. run against `ehmpathy/rhachet`: **4/4 read shapes matched, 0 drifted** — among
them `actions/secrets/public-key` = `{key_id:string, key:string(44)}`, the contract the sealed box
depends on. teeth proven: pointed at an absent repo it names 2 drifted rows, exits 1.

⇒ what is left for this dream is **narrower than when it was filed**:

| residue | why it is still a dream |
|---|---|
| the `PUT`/`DELETE` sealed-secret hop | needs `--mode apply` against an administered repo; a write to a shared system, so it wants a deliberate owner |
| an **automated** lane for any of it | github's workflow `permissions:` schema has **no secrets scope** — ci's automatic `GITHUB_TOKEN` can never reach `actions/secrets/*`. `.github/workflows/.test.yml:231-233` sources creds from `toJSON(secrets)`, so a lane needs a **repo secret**, which only a repo admin adds |

⚠️ **the credential premise this dream was filed under was partly wrong.**
`ehmpathy.test.GITHUB_TOKEN` (github-app-minted) does exist on the box — `rhx keyrack list` shows
it. so the blocker was never *"no credential exists"*; it is *"no credential reaches ci without a
repo-admin write."* a much smaller ask, and the one a foreman should actually be handed.
