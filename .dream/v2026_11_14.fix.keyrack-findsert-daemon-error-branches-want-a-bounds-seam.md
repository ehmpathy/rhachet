# 🌙 dream: the findsert daemon spawn's two error branches want a bounds seam and a clamp

- kind = fix
- owner = rhachet (keyrack daemon sdk)
- caught 2026-11-14

## .the cue that fired

a peer reviewer of ehmpathy/rhachet#656 asked for integration cases on the two failure branches of
`findsertKeyrackDaemon`: the spawn-wait timeout and the unreachable-daemon timeout.

## .the gap, precisely

both bounds are module constants (spawn wait 60s, reachable wait 20s), with no seam. a test must wait out
a full bound per case, so neither branch has a test. the wait-past-bound mechanism is proven through
`genAwsProfileExport` [case9][t1]; findsert's own message and its hint are not.

## .the shape of the fix

- a `bounds: { spawnWait, reachableWait } | null` input on `findsertKeyrackDaemon`; null keeps the defaults
- case A: hold the spawn key in-test via `withDiskMutex` on the same dir and key, call findsert with a 1s
  spawn wait, assert the MalfunctionError and its hint
- case B: a socket path whose spawn never binds (a stub spawn via context), a 1s reachable wait, assert the
  MalfunctionError names the socket and the wait

## .why it is not done in this round

a contract change to an exported sdk op for test reach, outside the wish's nano bound (F21)
