### what the raw read costs

an unclassified `ENOENT` escapes as a raw `Error`, which `getExitCodeFromError` defaults to exit
**1** — a MALFUNCTION code for a fault the server did not commit
(`rule.require.exit-code-semantics`). the window is real for exactly the reason this repo makes it
real: `pnpm install` relinks `.agent/repo=*/role=*` symlinks, and **every one of the sites above
walks that tree**.

⇒ so a `pnpm install` concurrent with an enroll, an upgrade, a hook sync, or a role lookup can
crash any of them with a stack trace and exit 1.

## .the shape of the fix

the guard is three lines and it is already written twice in this tree:

```ts
const entries = ((): string[] => {
  try {
    return readdirSync(dir);
  } catch (error: unknown) {
    if ((error as NodeJS.ErrnoException).code === 'ENOENT') return [];
    throw error;
  }
})();
```

🔴 **`ENOENT`-only, never a bare `catch`.** a permission fault (`EACCES`) and a not-a-directory
fault (`ENOTDIR`) are not caller races, so they must escape unchanged or the skip becomes the
silent shape `rule.forbid.failhide` forbids.

⚠️ **the sweep is NOT a find-and-replace.** each site's early-return value differs (`[]`, a `Map`,
a filtered list), and two sites already have the guard — so a mechanical rewrite would both break
returns and double-wrap. it is ~20 hand edits, each one line of judgment.

### the clamp it owes

one shared clamp per the pattern, not per site: the narrowness case
(`getAllFilesFromDir.integration.test.ts` `[case4]` is the template — a path that is a FILE, so
`readdirSync` raises `ENOTDIR`, which must escape).

🟡 **the `ENOENT` arm itself has no deterministic drive at any of these sites**, for the same
reason it has none at `getAllFilesFromDir`: `existsSync` and `readdirSync` are two syscalls on one
path, and the window belongs to the kernel. a mock is forbidden at the integration tier
(`rule.forbid.integration.mocks`). ⇒ clamp the **width**, and say so.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **SAFE?** | ✅ the guard strictly narrows — it adds a skip on one errno and changes no other path |
| **CLEAN?** | 🔴 **no.** ~20 files across **eight** subsystems this behavior never opened — enroll, upgrade, keyrack, clone, link, hook sync, role lookup, brief read |

⇒ the one site this behavior's diff already owned (`getAllFilesFromDir`) was repaired in-round,
because every budget gate drives it. the rest ripple into a diff a budget behavior has no business
to carry — which is the CLEAN answer, and it is recorded in `F20` as the boundary rather than left
as a shortcut a reader must infer.

🟡 **and the deferral is a judgment about ripple cost, so it owes this dream AND a fulcrum.** the
fulcrum is `F20`, which already owns this exact fork — *close the door, or repair the walk?* — and
now carries the `2c` row that records the in-round half.
