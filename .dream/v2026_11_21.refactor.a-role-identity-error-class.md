# 🌙 dream: a `RoleIdentityError` class, so a content scan sets aside identity refusals only

- kind = refactor
- owner = ehmpathy/rhachet

## .the cue that fired

peer review r11 nitpick.1 (i005) on `.behavior/v2026_11_21.fix-enroll-orphan-min-warns-onstop`: `getOneRepoThisRoleContentDefectsOrNone` catches every `ConstraintError`, so a refusal of any other cause reads as no defect.

## .the gap, precisely

the identity checks (a role not linked, a mod that names a native role, a stale view) throw a bare `ConstraintError`. a caller that wants to set aside only identity refusals has no class to allowlist, so it allowlists the parent.

## .the shape of the fix

- declare `class RoleIdentityError extends ConstraintError` in `src/domain.objects/`
- throw it at each identity site; exit code stays 2, the header stays `✋ ConstraintError:` via the parent name, or names the subclass where the snapshots agree
- narrow the catch in `getOneRepoThisRoleContentDefectsOrNone` to `RoleIdentityError`
- clamp: a vanished brief between walk and read now raises from the scan; red before, green after

## .why it is not done in this round

the class touches every identity check across `role/` and `boot/`, sites this pr does not otherwise change, and moves their snapshots. fulcrum F9 holds the choice.
