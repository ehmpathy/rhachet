# 🌙 dream: audit which `~/.claude/` entries a clone lacks

- kind = feat
- owner = rhachet
- caught 2026-11-27, on `v2026_11_27.fix-enroll-links-keybindings`

## .the cue that fired

the keybindings wish showed one `~/.claude/` file a bare claude reads and a clone does not. the
vision's requirements review named others with the same shape and left them unaudited.

## .the gap, precisely

a clone's `CLAUDE_CONFIG_DIR` is its actor brain dir. a bare claude reads `~/.claude/`. any entry
claude loads from the config dir — `commands/`, `agents/`, `output-styles/`, a status line command
the settings name by a relative path — reaches a bare claude and not a clone. the settings grove and
now `keybindings.json` are arrowed; the rest is unknown.

## .the shape of the fix

1. list every path the claude bundle joins onto its config dir (`rhx claude.cli.strings`)
2. sort each: human preference (arrow it, like keybindings) · session state (stays per actor) ·
   a role's job (rhachet renders it)
3. for each preference entry with a harm a human sees, a wish of its own, same shape as this one

## .why it is not done in this round

the wish bounds the work to `keybindings.json`. no harm is evidenced for the other entries yet, and
each has its own semantics (a dir of commands may collide with a role's own).
