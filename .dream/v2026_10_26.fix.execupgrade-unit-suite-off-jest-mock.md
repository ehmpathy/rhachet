# 🌙 dream: move the `execUpgrade` unit suite off `jest.mock`

kind = fix · owner = rhachet · caught 2026-10-26

## .the cue that fired

peer lane `mech-test-scope-purity` (5.3.verification, i001 and i002) blocked a new `jest.mock` of
`assertRepoActorBrainDirReadyForRoleInits` in `src/domain.operations/upgrade/execUpgrade.test.ts`,
per `rule.forbid.unit.remote-boundaries` (mock usage in a unit test = blocker, no exception clause).

## .the gap, precisely

the suite holds eleven `jest.mock` calls (lines 11–90): npm installs, the global version read, the
role inits, the brain dir preflight, the hook sync, the boot sync. each stands in for a collaborator
that touches disk, npm, or a child process. the suite's gitroot is the fake path `/test`.

## .the shape of the fix

- give `execUpgrade` its collaborators through `context` (or a narrow `deps` field on it), defaulted
  to the real operations at the contract layer, so the unit suite injects fakes rather than mocks
- or split: keep the pure decisions (`asUpgradeFailureMessage`, the target expansion) as unit tests,
  and move the orchestration cases to an integration suite over a `genTempDir({ git: true })` repo
  with a self-linked rhachet, as `upgrade.acceptance` already stages

## .why it is not done in this round

dirty: it changes `execUpgrade`'s contract and every case of an extant suite, far past the one stub
pr #659 added (fulcrum F12 in `v2026_10_21.fix-init-refuses-ambient-claude-link`).
