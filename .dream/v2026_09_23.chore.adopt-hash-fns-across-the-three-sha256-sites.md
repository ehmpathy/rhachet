# 🌙 dream: three sites hand-roll a sha256 the repo has a dependency for

- **kind** = chore
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-23, in the `3.3.1.blueprint.product` self-review `has-consistent-mechanisms`

## .the cue that fired

the blueprint declares a new `asActorCorpusDigest` — *"sha256(body).slice(0,8)"*. before i passed it
as a clean new component, i searched for prior art. **two extant sites already do exactly that**, and
the repo carries a dependency built for it.

## .the gap, precisely

```
src/domain.operations/actor/enrolled/genEnrollmentHash.ts:28
  createHash('sha256').update(data).digest('hex').slice(0, 8)

src/infra/host/getHomeHash.ts:24
  createHash('sha256').update(realPath).digest('hex').slice(0, 8)

(blueprint, not yet authored) asActorCorpusDigest
  sha256(body).slice(0, 8)
```

⇒ **three call sites of one expression**, which is exactly `rule.prefer.wet-over-dry`'s rule-of-three
threshold.

and **`hash-fns@1.1.0` is a production dependency** (`package.json:118`) whose stated purpose is this
job — *"easily create, assess, and assure hashes within a pit-of-success"*. it exports
`asHashSha256`, a branded `Hash` type, and `isHashSha256.assure`.

⚠️ **it also ships the variant these sites actually want**, and none of them uses it:

> `asHashShake256(message, options?: { bytes })` — *"ideal when you need a **specific hash length**,
> such as for compact tokens, **extended fingerprints**, or key material"*

⇒ all three reach an 8-char fingerprint by a **truncation of a 64-char digest**. that is the
improvised form of an operation the dependency supports directly.

## 🔴 .the question the fix must ANSWER, never skip

the duplication is syntactic. **the three do not share a stability contract:**

| site | what its value IS | what a shape change costs |
|---|---|---|
| `genEnrollmentHash` | a **path on disk** — `actor.via.hash=<hash>/` | 🔴 **orphans every extant actor dir, on every machine.** its own docblock says so: a hash-shape change is a versioned-prefix migration, never an in-place edit |
| `getHomeHash` | a **socket filename** under `$XDG_RUNTIME_DIR` | a stale socket per host; recoverable, but live clones go unreachable |
| `asActorCorpusDigest` | a **drift comparator**, compared only against itself | ⚠️ near zero — both sides re-derive |

⇒ **a shared helper couples three independent stability requirements to one function's future.** the
adoption is correct only if the helper is versioned, or if `genEnrollmentHash` keeps its own
expression and only the other two migrate. **settle that before the first edit.**

## .the shape of the fix

1. **settle the contract question above first**, on the page. it is the whole risk.
2. **migrate `asActorCorpusDigest`** (once it exists) — the zero-risk site, and the one that proves
   the ergonomics.
3. **migrate `getHomeHash`** — behind a check that no live socket is orphaned by the change.
4. 🔴 **`genEnrollmentHash` LAST, or never.** if it migrates, it needs a versioned prefix
   (`actor.via.hash2=…`) plus a read-both-forms fallback. *"never"* is a legitimate outcome — an
   identity contract may keep its own frozen expression, **said out loud rather than left as an
   accident.**

⚠️ **`hash-fns`' API is async** (`Promise<Hash>`). so each migration ripples an `await` into every
caller — `asActorCorpusDigest`'s callers include `genActorBriefCorpus` and the `#20` resume clamp.
that ripple is the bulk of the work, and it is why this is not a find-and-replace.

## 🟡 .a rider, since this dream already opens the file — `genEnrollmentHash`'s PREFIX

`gen` means **findsert** — *"find or create, preserve extant"* (`rule.require.get-set-gen-verbs`).
`genEnrollmentHash` is a **pure** function: it finds naught, creates naught, and returns a cast of
its input. the sanctioned prefix for a cast is **`as*`**.

⇒ so the correct name is **`asEnrollmentHash`**, and the 2026-09-23 blueprint's new peer
(`asActorCorpusDigest`) already takes that form deliberately rather than copy the extant defect.

⚠️ **a rename is cheap ONLY if it rides this migration.** on its own it is churn across every caller
for no behavior change; bundled with the async ripple this dream already forces through those same
callers, it costs one extra token per call site. **take it then, or leave it.**

🔴 **and it is strictly a NAME change — never a hash-shape change.** the dir-orphan hazard above
belongs to the digest's *bytes*, not its identifier. do not let the two travel as one decision.

## .why it is not done in this round

**SAFE** — ⚠️ **no.** `genEnrollmentHash` is an identity contract whose shape decides a path on disk.

**CLEAN** — 🔴 **no.** three files across two subsystems (`domain.operations/actor` and
`infra/host`), an async signature change with callers, and a branded-type introduction.

⇒ both answers are no, so the deferral is the wish's own instruction rather than a judgment call:
*"do not widen into unrelated boot work the refactor may have left nearby — catch it as a dream
instead."* `getHomeHash` names sockets and `genEnrollmentHash` carries enrollment identity;
**neither is the brief boot path this wish bounds.**

🟡 and the blueprint's own site is **deliberately left to match its neighbours** rather than migrated
alone — a conversion of one of three leaves the codebase with **two** conventions where it now has
one, which is worse than either end state.
