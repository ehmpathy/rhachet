# 🌙 dream: git.repo.test's unscoped acceptance run stalls where the same files by path pass

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=git.repo.test)
- caught 2026-11-08

## .the cue that fired

`rhx git.repo.test --what acceptance --against local --env test --mode apply`, with no scope, in
ehmpathy/rhachet on `beav/fix-keyrack-export-single-flight`, ran past 36 min and then, on a rerun, past
10 min. Neither run reached a result. The plan showed `matched: 5 files`. The same 5 files, passed as
`--scope 'path://(…)'`, pass together in 135s (229 tests). Each file passes alone, and every pair of
them passes.

## .the gap, precisely

- the unscoped mode adds `--changedSince=<ref>` (git.repo.test.sh ~L306, ~L390). the scoped mode passes
  `--testPathPatterns` instead
- the stall shows only in the `--changedSince` mode, so the mode itself changes how jest runs these files
- while it runs, the skill prints only `💤 inflight (Ns)`, and it writes no log until jest exits. a stall
  leaves no trace of which test or which phase hung

## .the shape of the fix

1. find what `--changedSince` changes: is the file set the same, or how workers are scheduled, or the
   haste crawl over a large untracked tree?
2. for the unscoped form, pass the file list the plan already computed (`--runTestsByPath <files>`), so
   plan and apply run the same set the same way
3. stream jest's output to the log while it runs, so a stall can be read
4. add a no-progress bound that fails loud and names the last test that started

## .why it is not done in this round

the skill belongs to another repo. in this repo the files it picks pass when run by path, which is the
proof this route's verification needs.
