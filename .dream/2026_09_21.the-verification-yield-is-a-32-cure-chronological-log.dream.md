# 🌙 dream: condense the verification yield from a per-cure log into a statement of what holds

- kind = `refactor`
- owner = `ehmpathy/rhachet`
- caught 2026-09-21

## .the cue that fired

the wisher, mid-loop: *rip out chronological accretion and dense up prose and comments as you see it.*

the file I was about to append to is the largest instance in the repo.

## .the gap, precisely

`.behavior/v2026_09_11.fix-clone-say/5.3.verification.yield.md` is **4,726 lines across 32 `## cure N`
sections**, ordered by the round each cure landed in.

that is the shape `rule.always.yield-the-output-not-the-archaeology` forbids outright — *"a yield is the
output, never the archaeology"* — and `rule.forbid.chronological-accretion`'s `iteration log` smell, at
document scale:

| the rule's smell | the instance |
|---|---|
| iteration log — *"i002 fixed X. i003 fixed Y."* | `## cure 23` … `## cure 32`, in round order |
| append-over-revise | each cure appended beneath the last, never folded into a statement of current truth |

checkable: `npx rhx grepsafe --pattern '^## cure' --path .behavior/v2026_09_11.fix-clone-say` returns the
ordered list, and `wc -l` returns the 4,726.

🟡 **the exemption does not cover it.** `rule.forbid.chronological-accretion` exempts *"a changelog or an
audit log whose declared purpose IS the time-order"*. a **verification** yield's declared purpose is to
state what is verified — the round a cure landed in is incidental to that claim, and git holds it.

⇒ the cost: a reviewer who asks *"is the dirty/clear read verified?"* must read 32 sections to learn
whether a later cure superseded an earlier one's claim. the answer exists and is unfindable
(`rule.forbid.diffusion`).

## .the shape of the fix

**one section per SUBJECT, never per round.** the subjects are already visible in the cure titles — the
screen read, the verdict map, the report copy, the wire protocol, the await mode, the test harness.

1. group the 32 cures by the surface each one verifies
2. per surface, state what holds NOW — the invariant, its clamp path, its mutation proof, its dogfood
3. the per-round trail, where a reader genuinely wants it, refs out to
   `rule.require.archaeology-in-notes`' target — `.agent/.notes/`, cited by path
4. the residuals that are still open (cure 32's unreproduced pollution window, cure 30's daemon-age
   caveat) survive as their own section — a reader must ACT on those

⇒ the test per line: **would a reviewer act differently if this line were absent?** the mutation results
and the residuals pass it. *"the gate, re-taken again"* for the ninth time does not.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** the restructure rewrites ~4,700 lines of the one artifact the route's
verification stone is graded on, so it lands in no diff a cure already opened, and it ripples into every
peer review lane bound to `.behavior/**`. `rule.always.fix-forward-under-scouts-honor`'s CLEAN question
refuses it, and its own anti-pattern — *"the smuggled refactor"* — names it exactly.

🟡 and the loop is still **live**: the wisher's directive remains open, so cure 33 may yet land. a
condense performed now would be re-accreted on by the next round.

⇒ so the honest move is the fix-forward I did take: cure 32 was written dense, with its residual stated
rather than padded. the whole-file condense is this dream.
