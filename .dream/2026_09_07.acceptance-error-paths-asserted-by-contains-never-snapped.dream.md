# 🌙 dream: five acceptance suites lock their error paths with `toContain` and no snapshot

- **kind** = repair
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-07

## .the cue that fired

the r002 `ergo-contract-snapshots` lane, re-run **scoped** to `blackbox/cli/**` after it went dark
at i002 (`rule.always.rerun-dark-review-lanes-scoped`). it returned 5 blockers and 2 nitpicks, and
**its intersection with this behavior's diff is zero** — every file it named predates this branch.

the rule it fires on, verbatim:

> every output variant a caller can encounter (positive, negative, edge) must be snapshotted. the
> reviewer relies on snapshots to catch drift; text-contains asserts alone cannot surface a
> reworded or restructured error.

🚨 **the sharpest row is `keyrack.prikey`**, and its own assertion is the demonstration:

```ts
expect(output).toMatch(/prikey|no match|decrypt/i);
```

that regex passes on a **correct** error, on a **reworded** error, on a **truncated** one, and on an
error whose hint was dropped entirely. it proves the word `decrypt` appears somewhere in a stream —
never that a human reads a usable sentence.

## .the shape of the fix

**per suite, never a sweep.** each suite owns a different contract and each resnap must be read by a
human on its own terms:

1. pick ONE suite from the table
2. for each row asserted only by `toContain` / `toMatch`, add a `toMatchSnapshot` **alongside** the
   extant assertion — never in place of it (`rule.require.snapshots.[lesson]`: assertions verify
   function, snapshots verify appearance; both are owed)
3. where the row carries a uuid, a path, or a timestamp, route it through `asSnapshotSafe` first
4. 🚨 **read every new snapshot as a human before you accept it.** a first snapshot is not a
   regression check — it is a **claim that this output is correct**. an unread `--resnap` writes a
   defect into the contract and calls it a baseline
5. where the row's output goes through a **readout** (`asCliErrorFrameFromOutput` and its peers),
   say so in a comment — see the caveat below

⚠️ **step 4 is the whole risk.** the rows are unsnapped *because nobody has looked at them*, so a
sweep that accepts every generated snapshot converts an unproven output into a proven-wrong one.

## ⚠️ .the caveat this same lane run demonstrated — a readout is INVISIBLE in a `.snap`

the r005 `ergo-snapshot-visual-blemishes` lane, run in the same pass, raised 2 blockers + 1 nitpick
that were **all one false positive**: it compared a snapshot taken through
`asCliErrorFrameFromOutput` (a structural span, which drops the chrome around it by design) against
a snapshot of **raw stderr** (which keeps the render's own blank-line pad), and read the difference
as a render inconsistency across paths.

⇒ **a reviewer who reads only the `.snap` file cannot tell which snapshots went through a readout.**
so whoever takes this dream should assume the next reviewer will make the same read, and either
name the readout in a comment beside the `toMatchSnapshot`, or keep one suite's readout choice
uniform.

## .why it is not done in this round

**its intersection with this behavior's diff is zero.** none of the seven files is touched by
`fix-node-pty-install`, and the wish's scope bound is explicit that a per-consumer patch is the
workaround this task exists to retire — the same logic reads on a per-suite snapshot sweep.

⇒ and the second reason is the one that matters more: **step 4 needs a human to read each new
snapshot**, and a round that adds forty unread snapshots to five untouched suites has not improved
the contract; it has widened the surface a future reviewer must trust.
