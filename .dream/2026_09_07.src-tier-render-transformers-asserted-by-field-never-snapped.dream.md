## .the gap, precisely

both are user-faced render transformers whose whole output a human reads, and both are graded only
by fragment:

| transformer | variants asserted | snapped |
|---|---|---|
| `asCloneReachError` | 3 — `DEAF`, `DEAD-same-host`, `DEAD-cross-host` | **zero** |
| `asKeyrackErroredKeyTip` | 5 — constraint with hint, constraint with none, malfunction, a hint that wraps, an unclassified error | **zero** |

`asCloneReachError.test.ts` reads its output through `toContain` on `message` and `metadata.hint`;
`asKeyrackErroredKeyTip.test.ts` through `toEqual` on the whole string plus two `not.toContain`
rows. neither can see an added field, a dropped field, a re-ordered key, or a hint whose wrap moved
— which is exactly the class `rule.forbid.snapshot-visual-blemishes` exists to catch.

🚨 **`asCloneReachError` is the sharper of the two.** its three variants are the reach vocabulary a
human reads when a clone cannot be reached, and `DEAD-same-host` vs `DEAD-cross-host` differ ONLY in
their hint — the one span a field assert samples rather than locks.

## .the shape of the fix

**per transformer, never a sweep**, and the pattern is already proven twice in this tree —
`asCliErrorJson.test.ts` `[case11]` and `withCliOutputErrors.integration.test.ts` `[case2]`:

1. add ONE final case per file — `given('[caseN] every variant a caller could read')`
2. inside it, one `toMatchSnapshot` over a **map keyed by variant name**, so the whole set reads as
   one screen in a pr rather than as N unrelated blobs
3. keep every extant field assert **alongside** it, never in place of it
   (`rule.require.snapshots.[lesson]`: assertions verify function, snapshots verify appearance)
4. 🚨 **read each new snapshot as a human before you accept it.** a first snapshot is a CLAIM that
   the output is correct, not a regression check. an unread `--resnap` writes a defect into the
   contract and calls it a baseline

## .why it is not done in this round

- **safe?** ✅ yes — a test-only addition, no production line moves
- **clean?** ⚠️ **no.** neither file is in this branch's diff, and the wish is scoped to node-pty's
  install and the report it leaves. to add cases to two untouched subsystems widens the diff a
  reviewer must read, for a gap that predates the branch (`rule.forbid.scope-leaks`)

⇒ the CLEAN gate fails, so a dream is the correct outcome rather than a fix
(`rule.always.catch-dreams-for-followups`).
