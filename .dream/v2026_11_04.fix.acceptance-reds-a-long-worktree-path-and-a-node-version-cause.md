# 🌙 dream: two acceptance families go red on a host defect, not a code defect

kind · fix
owner · rhachet, `blackbox/.test/infra/` (keyrack sockets) + `blackbox/sdk/importEsmSafe.realnode`
caught 2026-11-04

## .the cue that fired

a full acceptance run in the worktree `rhachet.fix-boot-briefs-cacheable` (2026-11-04T09-05-32Z) went
red on 90 tests that this branch never touched, and that main left as they are.

## .the gap, per host fact

| host fact | reds | cause |
|---|---|---|
| a long worktree path | 89, five `blackbox/sdk/keyrack.*` suites | the daemon socket lands at `<repo>/.temp/genTempDir.symlink/<stamp>.<slug>/.xdg-runtime/keyrack.<n>.<hash>.sock`, ~165 chars, past the ~108-char `sun_path` cap, so `connect` fails `EINVAL`. a short worktree name passes. the clone sockets dodge the same cap with a short `$XDG_RUNTIME_DIR`; the keyrack fixtures do not |
| a node on PATH other than the `.nvmrc` pin (v22.21.0) | 1, `importEsmSafe.realnode` | the received cjs namespace keys hold `"module.exports"`, which the snapshot, taken on the pin, lacks |

## .the shape of the fix

1. keyrack fixtures: point `XDG_RUNTIME_DIR` at a short dir per test (a short hash under a short root),
   and fail fast with a ConstraintError that names the cap when a socket path would pass it
2. importEsmSafe: assert the keys the test cares about and let the node-version key ride free, or fail
   fast with a ConstraintError when `process.version` is not the `.nvmrc` pin

## .why it is not done in this round

both sit in shared test infra outside the boot cache wish, and neither is caused by this branch. the
director settled it as a host defect (F16).
