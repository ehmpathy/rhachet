# 🌙 dream: rhachet-roles-ehmpathy must declare the brain package its index requires

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy · caught 2026-09-28

## .the cue that fired

the upgrade acceptance journey went red at `exits 0`: `rhx upgrade` in the `with-roles-linked`
fixture now exits 1 with `💥 MalfunctionError: upgrade landed, hooks did not`.

## .the gap, precisely

`rhachet-roles-ehmpathy@1.39.1` `dist/index.js` → `contract/cli/index.js` →
`guardBorder.onWebfetch.js` → `getAllGuardBorderBrainAtoms.js` requires
`rhachet-brains-fireworksai`, which appears in neither `dependencies` nor `peerDependencies`
(`npm view rhachet-roles-ehmpathy@1.39.1 peerDependencies dependencies`). a consumer that lacks it
cannot load the role package, so hook discovery faults and the role's hooks are never installed.
rhachet now reports that fault with exit 1 (r004 b2), where before it swallowed it.

## .the shape of the fix

in rhachet-roles-ehmpathy: declare `rhachet-brains-fireworksai` as a dependency, or lazy-load it
inside the guardBorder brain lookup so the package index loads without it.

## .why it is not done in this round

it belongs to another repo, and this route does not dispatch to suppliers. the fixture
`blackbox/.test/assets/with-roles-linked/package.json` declares the brain package meanwhile, so the
journey tests the migration rather than the supplier's manifest.
