- **kind** = repair
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-07

## .the cue that fired

the `mech-external-contracts` lane (`rule.require.external-contract-integration-tests`), re-run
scoped after it went dark on a push-mode overflow. **it raised this class TWICE — at i005 (3
blockers) and again at i006 (2 blockers) — and one file is named in both.**

🚨 **the recurrence is the cue, and what i005 did with it is the defect this dream repairs.** at

*"is this owed here?"* and says naught about *"is the gap real?"* — so a true gap left the round
with no record, and the next reviewer found it again. `rule.always.catch-dreams-for-followups`

⇒ the scope refutation stands, unchanged. what was owed alongside it is this file.

## .the gap, precisely

the branch touches **no** file under `keyrack/`:

```sh
$ git diff --name-only origin/main...HEAD -- src/domain.operations/keyrack/
(no output)
```

so every item is `rule.forbid.scope-leaks` against this change, and true about the tree. a grep
found **three** suites, one more than the lane named:

| file | tier | what it mocks | the rule it breaks |
|---|---|---|---|
| `…/aws.sso/setupAwsSsoProfile/logoutAwsSsoSession.integration.test.ts` | **integration** | `@aws-sdk/client-sso` — `SSOClient` + `LogoutCommand` | `rule.forbid.integration.mocks` |
| `…/vaults/aws.config/clearAwsSsoCacheForDomain.test.ts` | unit | `@aws-sdk/client-sso` | `rule.forbid.unit.remote-boundaries` |
| `…/vaults/aws.config/vaultAdapterAwsConfig.test.ts` | unit | `@aws-sdk/credential-provider-sso` | `rule.forbid.unit.remote-boundaries` |

🚨 **the integration one is the sharpest, and it is a blocker on its own terms.**
`rule.forbid.integration.mocks` permits a mock only when the circumstance is unavoidable **and**
documented inline with `.mock` / `.why` / `.real`. what the file carries instead is a bare
parenthetical:

```ts
// mock AWS SDK client (don't call real AWS)
```

that states **what** it does and never **why it is unavoidable** nor **where the real call is
proven** — so by the rule's own enforcement line (*"undocumented `jest.mock()` = blocker"*) it is
undocumented. a suite named `.integration.` that proves no integration is the exact false-confidence
shape the rule exists to retire.

⚠️ **and an adjacent find, out of this dream's subject:** the same file writes a fixture into the
real `~/.aws/sso/cache` on the host. that is a hermeticity concern (`rule.require.hermetic-tests`),
not a mock concern, and it wants its own look.

## .the shape of the fix

**per file, never a sweep** — and the two tiers want opposite cures, which is why one sweep would be
wrong:

### 1. the integration suite — make it real, or rename it

it is an aws sso **logout**, so a real call needs a live sso session. two honest outcomes:

- **real** — unlock via keyrack (`rhx keyrack unlock --owner ehmpath --env test`), call the real
  `LogoutCommand`, and fail loud with a `ConstraintError` that names that command when the
  credential is absent (`rule.require.failfast`). ⚠️ logout is destructive to the caller's own
  session, so it may genuinely be unavoidable — in which case
- **documented** — keep the mock and write the exception the rule demands: `.mock`, `.why` (why a
  real logout cannot run in ci), `.real` (the manual check, and its cadence). ⚠️ if it stays mocked
  it is a **unit** test and owes the rename off `.integration.`, since the tier name is a claim

### 2. the two unit suites — split the seam, drop the mock

the pattern is already in this tree, proven four times by this branch, and the same worked examples
the `upgrade` dream cites: hoist the pure half into an `as*` transformer graded with no mock, and
give the impure half an **optional injected seam** typed as `typeof <the real one>`, so a stand-in
the producer cannot emit is a type error. `execNpmInstall.ts`'s `options.spawn` is the closest read.

## .why it is not done in this round

- **safe?** ✅ yes — the unit cure is additive (an optional defaulted seam); the integration cure is
  test-only either way
- **clean?** ❌ **no.** `keyrack/` is untouched by this branch, and the wish is scoped to node-pty's
  install and the report it leaves. to rework three suites in an unrelated subsystem would bury the
  pty repair under a test-infrastructure overhaul (`rule.forbid.scope-leaks`)

⇒ the CLEAN gate fails, so a dream is the correct outcome — which is what i005 owed and did not
produce.
