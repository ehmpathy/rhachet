# 🌙 dream: acceptance tests inherit the runner's CLAUDE_CONFIG_DIR

- kind = fix · owner = ehmpathy/rhachet · caught 2026-11-07

## .the cue that fired

a local `--resnap` of `blackbox/cli/init.incremental.acceptance.test.ts`, run from inside an enrolled
clone, wrote a line CI never prints into case1's snapshot:

```
│    note: this clone's config dir is $REPO_ROOT/.agent/.actors/actor.via.repo=ambient/brain/.claude; …
```

CI's case1 passed without it, so the line came from the runner's env, not the code.

## .the gap, precisely

the mechanic role's claude-config init reads `CLAUDE_CONFIG_DIR` and prints the note when it is set.
the acceptance harness spawns the cli with the runner's env, so every enrolled clone that resnaps this
suite captures its own config dir into a shared snapshot — a non-hermetic test
(`rule.require.hermetic-tests`). the line was cut by hand before commit on
`beav/feat-brain-credential-pool-rotation`.

## .the shape of the fix

strip `CLAUDE_CONFIG_DIR` (and the other brain-cli env the enroll sets) from the env the blackbox
harness hands each spawn, in `blackbox/.test/infra/invokeRhachetCliBinary.ts`, unless a test opts in.
clamp it: a test that sets `CLAUDE_CONFIG_DIR` in the outer env and asserts the summary carries no
`config dir is` line — red before the strip, green after.

## .why it is not done in this round

safe but not clean: the harness is shared by every blackbox suite, so the strip can move other
snapshots, and this route's diff is a vision doc plus a resnap for a role bump.
