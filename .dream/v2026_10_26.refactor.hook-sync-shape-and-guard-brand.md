# 🌙 dream: brand the inside-repo guard, and reshape the hook sync

kind = refactor · owner = rhachet · caught 2026-10-26

## .the cue that fired
the l3 review of `v2026_10_26.fix-init-never-writes-outside-repo` found two writers that wrote
before any guard: `setRepoActorBrainDir` (a legacy move and a mkdir) and
`findsertAgentEphemeralGitignore` (the `.agent/.actors/.gitignore`). both were fixed and clamped
there. each was a guard a human had to remember to place.

## .the gap, precisely
- `assertBrainDirInsideRepo` returns void, so a writer stays inside the repo only where someone
  called it first. six call sites place it by hand
- `syncHooksForLinkedRoles.ts` holds eight private procedures; faults travel on three channels
  (`syncResult.errors`, root `faults`, discover errors), summed by hand in `countRootFaults`
- the root shield wraps every brain's sync, so a claude brain dir outside the repo also skips a
  non-claude brain
- an actor fault row prints the actor's brain dir as `path =`, never the errno's own `.path`

## .the shape of the fix
1. `genBrainDirInsideRepo({ repoPath, brainDir }): BrainDirInsideRepo` — a branded path; every
   brain dir writer takes it in place of a bare string. a writer with no proof fails to compile
2. one fault collector, `{ push(row), count, rows }`, shared by every phase
3. split the root sync: `brains.filter(claude)` inside the shield, the rest outside it; merge the
   two prune and sync results
4. eject `withRepoBrainDirShield` and the actor settlement to their own files
5. a fault row reads `path` off the errno when it carries one
6. the per-actor read-only probe moves out of the derive `try`, so a probe fault keeps the actor's
   `+N` row and reports as a note; the skip `⚠️` block dedupes by path across phases
7. one `isPathOutsideRepoByRealpath({ path, repoPath })` beside `getRealpathOfNearestExtant`, used
   by the guard, the gitignore writer and the probe; a shared case table runs it and the adapter's
   `assertSettingsDirWithin` side by side
8. the ephemeral gitignore writers take `repoPath` as input, print a named warn on a skip, and
   write through `setFileAtomic`; one brief declares what the invariant covers (brain dirs and the
   two ephemeral gitignores), so the edge at `execRoleLink` is a decision
9. the guard verdict carries `scope: 'repo-actor' | 'actor'` and a display path relative to the
   repo's realpath, in place of the `basename(dirname(dirname(path)))` read; `withRepoMutex` takes
   `within: repoPath`
10. the hook sync reads its bound from `context.gitroot` at its five `context.cwd` sites, the same
    bound the boot sweep and enroll use; update the test contexts to carry `gitroot`
11. coverage: a CLI scene with a snapshot for `settings.of.repo.json` as an arrow out (pinned
    after step 2 unifies skip-or-fail); an axis-C row and a scene for `rhx roles link`; enroll's
    `HelpfulError` printer renders a tree, not raw JSON metadata
12. the memo writers (`setOneRepoThisBootBudgetMemo`, `setOneBrainTokenMemo`) and
    `genCloneOndisk`'s brain dir `mkdirSync` take the same guard as the brain dir writers; axis C
    gains `rhx clone` beside `roles link`
13. `rhx upgrade` reports a skip in its final summary (not only the `⚠️` block above it), with an
    acceptance scene for upgrade over a skipped repo actor; a legacy-adapter acceptance scene with
    a 0444 home (vision case=4 [t2], case=5)
    - the same summary block, in `invokeUpgrade.ts`, uses `:` as a separator on stdout
      (`role(s) upgraded: …`, `brain(s) upgraded: …`, `hint: hooks did not land — …`), against
      `rule.forbid.colons-in-stdout`. the repair is the block as one tree, header then
      subbranches (`✨ rhachet upgraded` / `├─ roles = …` / `└─ hint = …`), with
      `upgrade.acceptance.test.ts` [the hook-fault case] and its snapshot moved in the same change.
      seen at 5.3 through acceptance case12; the lines predate this diff (#584), so F6 holds them
14. the hook sync summary header is always `💥 MalfunctionError: N hook sync error(s)` and init
    exits 1, even where every row is a `✋ ConstraintError` the caller must fix (EACCES, a dir at
    `settings.of.repo.json`). the header names the system as the fixer while the rows name the
    caller. the shape: when every fault is a ConstraintError, the header is `✋ ConstraintError`
    and the exit is 2 (`rule.require.exit-code-semantics`); a mixed set keeps `💥` and exit 1.
    it moves the exit code `rhx init` and `rhx upgrade` promise, so it wants its own change and
    the wisher's nod. seen at 5.3's ergonomics review; the header predates this diff (F6)

## .why it is not done in this round
dirty, not unsafe: each step touches every writer or every phase, and the hotfix that
dev-env#167 waits on would carry that ripple. fulcrum F9.
