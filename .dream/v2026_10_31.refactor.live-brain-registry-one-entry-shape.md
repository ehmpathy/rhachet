# 🌙 dream: one entry shape for the live-brain registry, with marker ids and exact-set allows

- kind = refactor
- owner = rhachet
- caught 2026-10-31

## .the cue that fired

a peer review of the clamp found two entry shapes and three audits that do not match, after the
`allows` field landed on both suite exceptions and `none` infra modules.

## .the gap, precisely

- `suiteExceptions` is `Record<path, { reason, allows }>`; `infraModules` is
  `{ path, reach, reason, live, stub, allows }[]`. both are "a path that may hold markers, with a
  reason"
- the path-absent audit lives twice: a cause constant for suites, a `'<module absent>'` sentinel
  inside a list of export names for modules
- `getAllLiveBrainSuitesUngated` returns two claims in one list (an ungated suite, a stale or
  overreached exception)
- `allows` holds copies of derived marker names (`'a live entry point of …'`), so a path rename or
  a reworded template leaves a dangle; an allowed marker the file no longer holds goes unseen, so
  the pass can only widen

## .the shape of the fix

1. one `LiveBrainEntry { path, kind: 'suite' | 'infra', reach?, reason, allows }`
2. a marker `id`, with exported builders for the derived ids (`asMarkerIdOfLiveName`,
   `asMarkerIdOfModuleUse`), so `allows` cites ids, never prose
3. three ops, one per file: `getAllEntriesAbsent`, `getAllEntriesOverreached` (the exact set: a
   marker held and not allowed, and a marker allowed and not held), `getAllExportsUnclassified`
4. the integration test asserts each op's empty list on this repo; one disk case each

## .why it is not done in this round

it reshapes every registry entry, both scans and their tests at once; the clamp as it stands reads
every path, checks every `none` claim and every exception, and is bite-proven. the reshape is
maintenance, with no reach it would newly catch.
