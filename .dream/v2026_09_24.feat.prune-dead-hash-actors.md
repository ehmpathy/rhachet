# 🌙 dream: prune hash actors whose clones are all DEAD

- **kind** = feat
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-24

## .the cue that fired

roadmap p5 `[r011]`: `syncActiveActorBrainDirs` walks every `actor.via.hash=*` dir on each
`rhx init`, `rhx upgrade` and `rhx roles link`, live or dead, to find the few that are active.

## .the gap, precisely

`rhx enroll` mints one hash actor per distinct `{ brain, roles }` and never removes one. the sweep
pays one `readdir` per actor plus one reach probe per clone, via `getAllActorsOndisk` →
`isActorActive` → `getCloneReachState`. a DEAD socket refuses at once, so each dead actor costs a few
ms, but that cost grows without bound as rolesets churn.

a second effect: an actor enrolled in a role later unlinked, with a clone still LIVE or DEAF, fails
the sweep with exit 2 on each init until its clones end. a prune gives the human a third fix beside
"re-link the role" and "end the live clones".

checkable once the trigger fires:

```
rhx globsafe --pattern '.agent/.actors/actor.via.hash=*/actor.json'   # count the actor dirs
```

## .the shape of the fix

1. `rhx actor prune` — plan by default, as `clone prune` is (`define.invariant.clone-prune-safety`)
2. candidates = hash actors on this host with `isActorActive` false and no clone younger than a
   grace window
3. apply removes the actor dir whole, plus each entry under `getActorsIndexDir` that points into it
4. the slug and derived forms are out of scope; they are declared in `actors.yml`, never minted

## .why it is not done in this round

- **SAFE?** ✅ a plan-first prune of DEAD-only actors deletes no state a live brain reads.
- **CLEAN?** 🔴 no. it is a new cli verb with its own safety invariant, test tier, and help text: an
  actor-model feature, not a boot one. the blueprint scopes it out for that reason.

⇒ dirty to pull in; deferred with the cost measured and bounded.

## .the revisit trigger

more than 50 actor dirs in one repo, or `rhx init` slower by more than 1s against the pre-release
baseline.
