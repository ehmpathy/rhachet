## .the gap, precisely

the diagnosis is **printed by the tool itself** and is unambiguous — from the overflowed lane's own
`🔍 lets see why...` block:

```
├─ targets
│  ├─ diffs: since-main
│  │  └─ files: 414
│  ├─ paths: (none)
│  │  └─ files: null
│  └─ joined via intersect
│     ├─ files: 369
│     └─ tokens: 892.1k
```

> **`paths: (none)` · `files: null`** — the glob was accepted at the command line, matched no file,
> and was then reported as though **no `--paths-with` had been passed at all**.

so `--join intersect` had no second set to intersect with and degenerated to the raw diff: 369 files,
892.1k tokens, 94.0% of the window. the lane was configured to grade 20 snapshots and was handed the
whole branch.

two defects compose here, and the second is the expensive one:

1. **the parse** — a brace in the **extension** slot (`'**/*.{ts,md}'`) does not expand; a brace in
   the **directory** slot (`'{src,blackbox}/**'`) does. the asymmetry is undocumented in `--help`.
2. **the silence** — a `--paths-with` that matches zero files is indistinguishable, in the report,
   from a `--paths-with` that was never passed. so a **narrowed** lane and an **unbounded** lane print
   the same `paths: (none)`, and the author of the guard reads their own bind as applied.

⇒ defect 2 is what makes defect 1 cost hours: the tool's own diagnostic actively points away from the
bind, and a driver reasonably concludes the corpus is simply too large.

## .the shape of the fix

pick either, and **defect 2 is the one to fix regardless**:

- **fail loud on a zero-match path bind.** a `--paths-with` that expands to zero files is almost never
  intended — refuse with a `ConstraintError` that echoes the glob verbatim and names the likely cause:
  ```
  ✋ --paths-with matched 0 files: '**/*.{ts,sh,md,snap}'
     ├─ a brace in the EXTENSION slot does not expand — a brace in the DIRECTORY slot does
     └─ fix: repeat the flag per extension — --paths-with '**/*.ts' --paths-with '**/*.md'
  ```
- **and/or expand the extension-slot brace**, so `'**/*.{ts,md}'` means what every reader thinks it
  means. `fast-glob` already supports it; the loss is upstream of the glob call, in `parseReviewArgs`.
- **distinguish the two states in the report** — `paths: (not passed)` vs
  `paths: <glob> → 0 files ⚠️`. one word, and the misdiagnosis becomes impossible.
- **document the asymmetry** in `rhx review --help`, beside `--paths-with` / `--paths-wout`.
