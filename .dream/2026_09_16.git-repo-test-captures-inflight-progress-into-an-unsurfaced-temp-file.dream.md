# 🌙 dream: `git.repo.test` captures in-flight progress into a temp file it never surfaces

- **kind** = reseed — the skill lives in `ehmpathy/rhachet-roles-ehmpathy`, not here
- **owner** = `repo=ehmpathy/role=mechanic`, skill `git.repo.test`
- **caught** = 2026-09-16, at `.behavior/v2026_09_11.fix-clone-say` stone `5.3.verification`

## .the cue that fired

a full acceptance run passed **4170s** — 1.53x its own clean baseline — and across that whole span the
only signal available was:

```
   │  ├─ 💤 inflight (4155s)
   │  ├─ 💤 inflight (4170s)
```

⇒ a number that counts up. it cannot say whether the run sits at suite 10 or suite 130, whether a
suite has already failed, or whether the run has wedged. **the one question a long run raises — *does
it still advance?* — is the one its output cannot answer.**

## .the gap, precisely — the progress IS captured, and then thrown away

`node_modules/rhachet-roles-ehmpathy/dist/domain.roles/mechanic/skills/git.repo.test/git.repo.test.sh`:

```bash
1103: TEMP_STDOUT=$(mktemp)
1104: TEMP_STDERR=$(mktemp)
...
1626: run_single_test "$WHAT" "$TEMP_STDOUT" "$TEMP_STDERR" || NPM_EXIT_CODE=$?
...
1754:   cp "$TEMP_STDOUT" "$STDOUT_LOG"
1755:   cp "$TEMP_STDERR" "$STDERR_LOG"
```

and the trap that closes the loop:

```bash
161: trap 'stop_timer; rm -f "$TEMP_STDOUT" "$TEMP_STDERR"' EXIT
```

🔴 **jest writes its per-suite progress into those temp files, live, for the entire run.** the skill
then `cp`s them to `.log/…` **only at completion**, and the trap deletes the originals.

⇒ so the data a watcher wants exists the whole time, at a path the watcher is never told, and is
destroyed at the moment the permanent copy appears. the two facts together are the defect: it is not
that progress is unavailable — it is that it is **available and unaddressable**.

| what a watcher wants | what is emitted |
|---|---|
| which suite is in flight | `💤 inflight (4170s)` |
| how many have passed so far | `💤 inflight (4170s)` |
| whether one has already failed | `💤 inflight (4170s)` |
| whether it has wedged | `💤 inflight (4170s)` |

## .the shape of the fix

the cheapest form changes no behavior and prints two lines:

1. emit the temp paths in the `status` header the timer already opens, beside the elapsed counter:
   ```
   ├─ status
   │  ├─ watch: tail -f /tmp/tmp.aBc123   (stdout)
   │  ├─ watch: tail -f /tmp/tmp.XyZ789   (stderr)
   │  ├─ 💤 inflight (15s)
   ```
2. 🟡 **and reconsider the trap.** the paths are useless after `rm -f`, which is correct for tidiness
   and wrong for a post-mortem on a killed run. a run that is interrupted (`ctrl-C`, a timeout kill)
   currently persists **no log at all** on the `LOG_MODE != always` path — the temp files die with the
   trap and the `cp` never ran. so an aborted long run leaves zero forensic trace.
3. a stronger form, where the sequence is cheap to change: `cp` on a heartbeat rather than only at
   exit, so `.log/…/${ISOTIME}.stderr.log` is the live file and the extant path is the only path
   anyone needs. ⇒ this subsumes (1) and (2) and adds no new vocabulary.

the clamp is cheap for (1): assert the emitted header holds a path that exists while the run is live.

## .why it is not done in this round

**ownership, never dirt.** the skill is published by `rhachet-roles-ehmpathy` and reaches this repo
through `node_modules`, so an edit here would be written into a dependency's `dist/` — erased by the
next install, and never delivered to the repo that owns it
(`rule.always.scope-onetime-lessons-to-the-behavior`: a tree adopts only what is scoped to itself).

⇒ so no fulcrum is owed — the deferral is a hard boundary, never a judgment about ripple cost.
