# 🌙 dream: a self-review promise hands out the next review, but records no ask for it

- kind = reseed (owner: `ehmpathy/rhachet-roles-bhrain`, role=driver, `route.stone.set`)
- caught 2026-11-27

## .the cue that fired

a documented command failed: the promise output said *"when you've truly reflected, run `… --as
promised --that <next-slug>`"*, and that exact command then refused with `🍃 no ask on record`.

## .the gap, precisely

on route `v2026_11_27.fix-mods-never-block-enrollment`, stone `1.vision`:

1. `--as promised --that has-grounded-in-reality` passed and printed review 2/5 with its promise
   command
2. the printed promise for `has-experience-coverage` refused: `no ask on record`
3. `--as arrived` re-printed the same review and recorded its ask; the promise then passed
4. the same three steps repeated for review 3/5

so every review after the first costs one extra arrive, and a review file written before that
arrive is older than its ask — the freshness bar then reads it as stale.

## .the shape of the fix

when `--as promised` passes and renders the next review, record that review's ask in the same
call, as `--as arrived` does. a clamp: promise review N, then promise review N+1 directly, with no
arrive between — must pass.

## .why it is not done in this round

the tool is another repo's (`rhachet-roles-bhrain`); a fix there is its own pr.
