## .the gap, precisely

both rows wait on one signal: the client's `queued` read (`computeCloneInputState`, the dim
`Press up to edit queued` hint inside the box, `INPUT_QUEUE_HINT_MARKERS`). on this host today it
never fires while the brain holds a message, so `computeCloneSayPollStep` lets the transcript rise
win and returns `released`.

not caused by route v2026_11_16: the bisect with its one pty-path change (the async mirror) turned
off read the same 8 rows red (`.../what=acceptance/2026-11-17T[time]Z.stderr.log`), and the
branch does not touch the verdict path (`computeCloneSayVerdict`, `computeCloneSayPollStep`,
`getCloneSayObservation`, `computeCloneInputState`). the tier is gated off cicd, so main has not
run it since it last passed (2026-09-19 per the suite's notes).

## .the shape of the fix

1. capture one held screen on a live brain with `clone say --debug` and `clone get --what queue`;
   read whether the hint row is absent, reworded, or drawn without the dim attribute
2. if absent or reworded: widen `INPUT_QUEUE_HINT_MARKERS` from a fresh probe
   (`rhx claude.cli.strings --pattern 'edit queued'`), with a unit fixture of the new grid
3. if drawn bright: decide whether the dim-only guard still holds, with the forge case it exists for
4. if the brain no longer holds (the turn ends first, e.g. a fast model prints 3000 lines at
   once): change the m1 arrange to one the brain cannot finish fast (a tool call that sleeps)
5. rerun the tier: `BRAIN_LIVE_SCOPE=all rhx git.repo.test --what acceptance --against local --env test --scope 'path://realbrain' --mode apply`
