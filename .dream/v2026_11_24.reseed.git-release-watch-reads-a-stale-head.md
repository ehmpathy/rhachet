# 🌙 dream: git.release --watch reports the prior head's verdict right after a push

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic role, skill git.release) — reseeded as ehmpathy/rhachet-roles-ehmpathy#1478
- caught 2026-11-24

## .the cue that fired

on #808, `rhx git.commit.push` then `rhx git.release --watch` printed `👌 all checks passed` and
`0s watched`. `gh pr view 808` at that same moment showed head `5274813` with `install / pnpm` in
progress. a second `--watch` call, after the run had registered, said the same. the real run took
~6 minutes and was watched via `gh pr checks 808 --watch`.

## .the gap, precisely

the watch reads a check verdict that is not keyed to the pr's current head sha, so in the window
before the new run registers it reports the PRIOR head's green as this push's green. a driver that
trusts it reports a push as green while its run has not begun.

## .the shape of the fix

key every read to the pr's `headRefOid`: when no check run exists for that sha yet, report
`💤 awaits the run for <sha>` and keep the watch open, never `all checks passed`. clamp it with a
push whose run has not registered.
