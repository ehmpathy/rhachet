## `rhx clone actor://<slug>` — spawn a clone from a declared actor

separate the *declare-an-actor* act from the *spawn-a-clone* act. today `rhx enroll <brain> --roles`
does both in one shot. this dream splits them:

- **declare** an actor once, by slug, in a manifest.
- **spawn** clones of it on demand: `rhx clone actor://mechanic`.

`rhx clone` is a thin verb over `rhx enroll` — it resolves a slug to a declared actor (brain +
roles) and invokes enroll against it. no new spawn machinery; just slug resolution + delegation.

### the manifest — `.agent/repo=.this/actors.yml`

a repo prescribes its own custom actors by slug:

```yaml
actor:
  - slug: mechanic
    brain: claude
    roles:
      - ehmpathy/mechanic
      - ehmpathy/architect
      - ehmpathy/ergonomist
      - bhrain/driver
      - bhrain/learner
```

### shipped actor declarations (the useful part)

most valuably: each `rhachet-roles-<supplier>` package ships the actors *it recommends*, so folks can
enroll a curated, supplier-blessed actor without hand-assembly of the role-set:

```bash
rhx clone actor://mechanic            # repo/local slug
rhx clone actor://ehmpathy/mechanic   # supplier-qualified, for when disambiguation is needed
```

`actor://<slug>` resolves local (`.agent/repo=.this/actors.yml`) first, then supplier-qualified
`actor://<supplier>/<slug>` from the installed role packages.

### fork a clone — `rhx clone clone://<serial>` (a common usecase)

the same `rhx clone` verb takes a **second scheme**: `clone://<serial>`. where `actor://<slug>`
spawns a *fresh* clone from a declared actor, `clone://<serial>` **forks an extant clone** — it
seeds a new serial from the root serial's identity + resume handle (`exid`), so the fork branches
from where that clone is, not from scratch. a common move: take a live or paused clone and split a
new line of work off it.

two schemes, one verb:

| invocation | what it does | seeds from |
|---|---|---|
| `rhx clone actor://mechanic` | spawn a fresh clone of a declared actor | actor declaration (brain + roles) |
| `rhx clone clone://<serial>`  | fork a new clone from an extant one | that clone's identity + `exid` (native resume) |

the fork relies on the `enroll-with-interface` frame: the root clone's `serial` record carries the
brain-cli session `exid`, so the fork can hand that `exid` to the brain-cli's native resume and
branch a new serial from it.

### the full verb grammar — `gen <make|fork|wake>` (prescribed here for this dream's build)

`rhx clone`'s create/reopen family is one verb — **`gen`** — with three **mechanisms**. `gen` is the
default, so it is implicit unless the token after `clone` is one of the reach verbs (`get`/`say`/
`list`, which land in `enroll-with-interface`). canonical internal form:

```
rhx clone gen <make|fork|wake> <uriOfSource> [--as <slugOfClone>]
```

```bash
rhx clone make actor://<slug>     [--as @:<slug>]   # NEW clone from an actor's config (fresh)
rhx clone fork clone://<serial>   [--as @:<slug>]   # NEW clone from a clone (seeded from its exid/history)
rhx clone wake <uri>              [--as @:<slug>]   # reopen an EXTANT clone — revive if dead, return if live

# a bare source URI implies its scheme's CREATE mechanism (gen still implicit)
rhx clone actor://<slug>          ≡  rhx clone make actor://<slug>
rhx clone clone://<serial>        ≡  rhx clone fork clone://<serial>
```

`--as` takes the clone address form `@:<slug>` (the `@:` prefix is mandatory — see
`.agent/repo=.this/role=any/briefs/define.address-sigils.md`).

| mechanism | source uri | what it does | idempotent? |
|---|---|---|---|
| `make` | `actor://<slug>` | a NEW clone from the actor's config (fresh) | ✅ only with `--as`; else a fresh serial each call |
| `fork` | `clone://<serial>` | a NEW clone from a clone, seeded with its `exid`/history | ✅ only with `--as`; else a fresh serial each call |
| `wake` | `clone://` or `actor://` | reopen an EXTANT clone — revive if dead, return if live | ✅ by the target (serial, or actor + `--as`) |

- **`wake` vs `make`** is the clear minimal pair — reopen an extant clone vs create a new one. `fork`
  is `make`-from-a-clone: it carries the root's `exid`/history seed.
- **`--as <slug>`** fixes the new clone's identity so a repeat converges — the clone-level twin of the
  actor's `--slug`/hash identity (name it → idempotent by slug; omit it → a fresh, auto-serial'd
  clone). so `make`/`fork` are honestly idempotent exactly when you supply the identity.
- `gen` is the one sanctioned verb (`rule.require.get-set-gen-verbs`); `wake|fork|make` are its
  **findsert** / **construct** subtypes. ubiqlang caveat: `make` reads as a create-family word
  (`rule.forbid.nonidempotent-mutations`) — defensible as a `gen` sub-mechanism (idempotent with
  `--as`), with `mint`/`spawn` as clean-rework fallbacks if a reviewer objects.

### why this is a follow-up, not this behavior

the `enroll-with-interface` behavior delivers the frame (`.agent/.actors/`) + the clone ipc + the
**reach** surface that proves the ipc — enroll already creates the clone to reach, so that behavior is
end-to-end testable on its own. this dream sits *on top* of that frame and adds the **lifecycle**:

- the frame gives clones a durable actor identity to belong to.
- `actors.yml` + `rhx clone <make|fork|wake>` give that identity a **slug** and a **declaration
  source**, so a clone is spawnable by name instead of by a re-typed `--roles` spec every run.

the split, plainly:

| surface | verbs | behavior |
|---|---|---|
| reach — prove the ipc | `clone list` / `say` / `get`, `actor list` | `enroll-with-interface` |
| lifecycle — create clones | `clone make` / `fork` / `wake` + `actors.yml` | **this dream** |

pairs cleanly with the `enroll-with-interface` open-question #7 (declare-actor vs spawn-clone seam).

### the mandated steel-test critipath — the redteam fan-out

when this dream is built, its acceptance bar includes the **max-boundary fan-out** from the clone
experience inventory
(`.agent/repo=.this/role=user/briefs/actors/inventory.of=experience._.md` → case=2.redteam-fan-out). it is a
**mandated acceptance critipath**: an acceptance test must exercise it against real clones and **clamp**
it — a regression test that goes red the moment it breaks (`rule.require.clamp-edge-cases`). it is the
premier steel-test because one path exercises every lifecycle boundary at once — `make` + `fork` +
`--say` on spawn + `+role` deltas on a fork + inter-clone observation via `get`. the
`enroll-with-interface` vision assigns this clamp here (its own reach flow is clamped in that behavior).
