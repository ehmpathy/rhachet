# 🌙 dream: snapshot the `roles boot` negative stderrs

kind: chore · owner: ehmpathy/rhachet · caught 2026-09-24

## .the cue that fired

the contract-snapshot-exhaustiveness audit on stone `5.3.verification` of
`v2026_09_22.feat-boot-briefs-into-claude-md` walked every contract this branch changed and asked,
per path, *"is the whole render pinned, or only a fragment?"* every row answered "pinned" except one:
`roles boot`'s negative paths.

the same audit found `roles link` had **no** `.snap` file at all and fixed that in-stone. this is
the residual it could not take with it.

## .the gap, precisely

`roles boot` refuses on four paths, and each is asserted by a `toContain` fragment with no snapshot
around it:

- `blackbox/cli/roles.boot.acceptance.test.ts:227` — `stderr` names the orphan file
  (`toContain('orphan.md.min')`)
- `blackbox/cli/roles.boot.bootyaml.acceptance.test.ts:111` — a `boot.yml` validation refusal
- `blackbox/cli/roles.boot.bootyaml.acceptance.test.ts:171` — a second validation refusal
- `blackbox/cli/roles.boot.bootyaml.acceptance.test.ts:194` — `toContain('mixed mode not allowed')`

`blackbox/cli/__snapshots__/roles.boot.acceptance.test.ts.snap` does not exist; the peer file
`roles.boot.bootyaml…snap` holds only the three whole-**stdout** positive renders.

⇒ a reviewer who reads a pr that changes one of those refusals sees a green suite and no render. the
fragment holds; the sentence around it — the hint, the glyph, the path — can drift unseen
(`rule.require.contract-snapshot-exhaustiveness`, `rule.require.snapshots`).

## .the shape of the fix

in each of the four `when` blocks, add one `then` beside the extant fragment assert:

```ts
then('the whole refusal render is locked', () => {
  expect(asSnapshotSafe(result.stderr)).toMatchSnapshot();
});
```

`asSnapshotSafe` already masks the temp-dir prefix and the boot census char count, so the renders
are stable across hosts. **keep** the `toContain` asserts — they name the fragment a caller depends
on, and the snapshot names the render around it. this is purely additive, so it can only tighten.

then run `rhx git.repo.test --what acceptance --against local --env test --mode apply --resnap
--scope 'path://roles.boot'` and read the four produced blocks before you trust them.

## .why it is not done in this round

safe, and **not clean**: those four refusal paths are byte-identical to `origin/main`, so they are a
bar main does not clear. `rule.forbid.gates-main-does-not-clear` forbids a hold of this stone on
them, and to widen the branch's diff into untouched negative paths would enlarge a review surface
that is already the largest gap of this stone (nine of eleven reviewer lanes overflowed on it).

the branch's own change to `roles boot` is its **positive** render, and that is snapped three times
over in `roles.boot.bootyaml.acceptance.test.ts.snap`. the gap here predates the branch and outlives
it, which is exactly what a dream is for.
