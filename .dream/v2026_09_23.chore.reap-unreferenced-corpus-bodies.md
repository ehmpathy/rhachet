# 🌙 dream: reap the unreferenced bodies under `<brainDir>/.corpus/`

- **kind** = chore
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-23

## .the cue that fired

F17 moved the corpus record from a sidecar file to a **content-addressed body under a symlink**, so
the torn pair two concurrent renders produced is gone. the cost it accepted, in its own words:

> `.corpus/` keeps one file per distinct render — bounded by *(rolesets × brief revisions)* for ONE
> actor. kilobytes. a reaper is a dream, never a blocker.

⇒ the fulcrum named the garbage at the moment it accepted it, which is the whole reason this file
exists rather than a surprise three rounds from now.

## .the gap, precisely

every render writes `<brainDir>/.corpus/<digest>.md` and swaps `AGENTS.md` to it. **naught deletes
the body the previous render pointed at.** so an actor whose role briefs change N times keeps N
bodies, of which exactly one is reachable.

checkable today, once the feature ships:

```
ls <actorDir>/brain/.claude/.corpus/ | wc -l     # grows by 1 per distinct render
basename $(readlink <actorDir>/brain/.claude/AGENTS.md)   # names the ONE that is live
```

⚠️ **the magnitude is small and the direction is one-way.** a corpus is tens of kilobytes; an actor
that re-renders daily for a year holds single-digit megabytes. it is untidy long before it is
expensive — which is exactly why it is a chore and not a fix.

## .the shape of the fix

a `delUnreferencedCorpusBodies({ repoPath, hash })` under `src/domain.operations/corpus/`:

1. `readlink(AGENTS.md)` → the one live digest
2. list `.corpus/*.md`
3. `del` every body whose name is not that digest

**where it is called** is the real question, and it has two candidate answers the implementation
must choose between:

| call site | the case for it | the case against |
|---|---|---|
| inside `setActorBriefCorpus`, after the swap | the writer cleans up after itself; no new entry point | 🔴 **it races the very hazard F17 closed** — a concurrent render may hold the body a reaper is about to delete |
| `rhx upgrade`'s sweep, once per actor | single-threaded by the sweep's own shape; already walks every active actor | one more responsibility on a sweep that already does two |

🔴 **the second is almost certainly right, and the reason is the first row.** a reaper inside the
writer re-opens a concurrency window in an operation whose whole design is the absence of one.

🟡 **and a grace rule is owed either way:** keep the N most recent bodies, or keep any body younger
than some age, so a live clone that has not yet re-read its corpus is never left with a link that
reaches naught.

## .why it is not done in this round

- **SAFE?** 🔴 no. a reaper that deletes a body a live clone still reads through would break a
  session in flight — and the grace rule that prevents it is a design question, not a one-liner.
- **CLEAN?** 🔴 no. it needs a new operation, a call site chosen against the race table above, and
  its own integration test.

⇒ both questions answer no, so `rule.always.fix-forward-under-scouts-honor` routes it here rather
than into this diff. and the wish's bound is explicit: *"do not widen into unrelated boot work."*
**the corpus's correctness is this round's; the sweep of its leftovers is not.**

## .the revisit trigger — so it does not sit here forever

a dream with no trigger has no owner, and nobody is prompted to re-open it. **two triggers, either
one suffices:**

| trigger | how to check it |
|---|---|
| **any actor's `.corpus/` holds more than 20 bodies** | `ls <actorDir>/brain/.claude/.corpus/ \| wc -l` — 20 distinct renders for one actor means the role packages churn fast enough that the garbage is no longer hypothetical |
| **the next `syncHooksForLinkedRoles` refactor** | that sweep is the preferred call site (the table above), so whoever next opens it is already in the one file this fix touches — the cheapest moment it will ever have |

🟡 **the first is a MEASURE, not a guess.** 20 bodies at tens of kilobytes each is still under a
megabyte, so the threshold does not fire on cost — it fires on the evidence that the growth is
real rather than theoretical.
