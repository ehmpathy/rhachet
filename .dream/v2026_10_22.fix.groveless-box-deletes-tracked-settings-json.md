# 🌙 dream: a box with no grove deletes the tracked `settings.json` arrow

- kind = fix
- owner = rhachet
- caught 2026-10-22

## .the cue that fired

a peer reviewer of `v2026_10_22.fix-claudemd-excludes-common` traced the layout step for a box with
no `~/.claude/settings.json` (a fresh ci runner, a new devcontainer).

## .the gap, precisely

- the repo actor's brain dir tracks `settings.json` — a relative arrow to `settings.of.grove.json`,
  machine-agnostic (`git ls-files` lists it)
- `setBrainDirSettingsLayout.ts`: when the grove is absent, it calls `delEntryIfPresent` on both
  `settings.json` and `settings.of.grove.json`, so no arrow points at an absent file
- ⇒ on that box, `rhx init` / `rhx enroll` leaves a deleted tracked file, and `git status` is dirty

## .the shape of the fix

pick one answer and clamp it with a box that has no grove:

- keep `settings.json` on a groveless box. claude reads an absent target as no user layer, which
  equals the delete's effect; measure that claude starts clean with the dangle first
- or untrack `settings.json` as well (add it to `BRAIN_DIR_NAMES_UNTRACKED`), so a box that drops
  it touches no tracked path. the cost is a fresh clone with no arrow until its first sync

clamp: an integration test that commits the brain dir, syncs under a HOME with no
`.claude/settings.json`, and asserts `git status --porcelain` is empty.

## .why it is not done in this round

not clean: it reverses a layout decision (`define.brain-dir-layout-is-one-for-every-actor`: no
arrow to an absent file) and names no machine, so it sits outside this wish's bound.
