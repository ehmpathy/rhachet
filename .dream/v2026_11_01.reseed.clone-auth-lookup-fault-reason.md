# 🌙 dream: a peer-cred lookup fault replies `auth-denied`, whose hint is a false cure

kind = reseed · owner = rhachet (clone) · caught 2026-11-01

## .the cue that fired

issue #678 lists three further cures; `v2026_11_01.fix-clone-auth-lookup-timeout` adopted only the
bound change.

## .the gap, precisely

when `getSocketPeerCred` throws (exec kill past 60s, maxBuffer, no fd), `awaitCloneAuthGate` maps
it to `deny`, and the server replies `rejected (auth-denied)` with a hint to run as another user.
for a same-user caller that hint is wrong.

## .the shape of the fix

- a fourth gate verdict, `fault`, distinct from `deny`, still fail-closed, replied as
  `auth-lookup-fault` with a hint that names the host lookup
- optional: the kernel-perm fallback from the issue (accept on lookup fault only when the socket
  and its parent dir are owned by this uid and the dir mode `& 0o077 === 0`)
- optional: read the peer pid without a full `ss -xp` scan (e.g. `ss -xp` filtered by inode
  `src`, or `/proc/net/unix` + a narrower fd walk)
- signal of done: `genCloneSocketServer.integration.test.ts [case20]` snaps today's `auth-denied`
  copy for a lookup fault; the fix moves that snapshot on purpose. `computeCloneAuthGateAction`
  gains a `nack-lookup-fault` verdict beside its two refusals

## .why it is not done in this round

the wish scopes the outcome to the two bounds; each cure is additive and owes its own clamp.
