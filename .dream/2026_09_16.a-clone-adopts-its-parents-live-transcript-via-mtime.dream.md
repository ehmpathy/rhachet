## .the cue that fired

a `rhx clone get @:loopcheck4 --tail 30` returned **my own assistant messages, verbatim**, every one
of them labelled `🎧` — the glyph that asserts *heard FROM the clone*. my own `🎙️ say` to it appeared
nowhere at all.

a control read of a peer clone (`@:geofix`) was clean: `🎙️` my say, then `🎧` its reply. so the
defect is per-clone, never global — which is what made it worth a dig rather than a shrug.

## .the gap, precisely — `mtime` is a CORRELATE of creation, and a live session breaks it

```ts
// isTranscriptWithinSpawnWindow.ts:21-29
export const isTranscriptWithinSpawnWindow = (input: {
  transcriptMtimeMs: number;
  spawnedAt: IsoTimeStamp;
}): boolean => {
  const spawnedAtMs = Date.parse(input.spawnedAt);
  return input.transcriptMtimeMs >= spawnedAtMs - CLONE_SPAWN_WINDOW_TOLERANCE_MS;
};
```

🔴 **its own docblock states the intended rule in the other vocabulary**, two lines above the code:

> *"a transcript **created** before this clone spawned cannot be ours"*

**created** is `birthtime`. the code reads **`mtime`**. for a transcript nobody appends to again the
two agree, which is why this held for so long — and a **live parent session is appended to on every
turn**, so its `mtime` is always `now`, hence always `>= spawnedAt`, hence **in-window for every
clone, forever**.

### 🔴 and BOTH guards miss it, for independent reasons

`genCloneHistoryLink` has two protections and neither fires:

| the guard | why it does not catch this |
|---|---|
| the spawn-window filter | `mtime` makes the parent's transcript permanently in-window — see above |
| the ambiguous-refuse (`eligible.length >= 2`) | the clone's OWN transcript did not exist yet, so the parent's was the **only** candidate. `length === 1` takes the fast path and claims it |

⇒ **the refusal guard is armed for the two-clone race and blind to the one-parent case**, because one
candidate reads as certainty rather than as a missed expectation.

## .the proof, on disk

every clone has exactly one history link. one has two:

```
.agent/.actors/actor.via.hash=8967acd9/clones/serial=69e36faa-…/history/
  T+0h00m  1a62a867-caa0-4c91-a993-fdf1f35474d6.jsonl   ← its own, at spawn
  T+2h29m  9351d10b-b63e-41f3-ab59-d07464ce6a2f.jsonl   ← 🔴 the PARENT session
```

`9351d10b-b63e-41f3-ab59-d07464ce6a2f` is the enroller's own claude session id. it was linked
**two and a half hours after the clone's own spawn**, by the per-episode re-link poll the docblock
describes as *"safe to run repeatedly."*

🟡 the two mtimes are rendered as an OFFSET from spawn rather than as wall clocks. what the proof
rests on is the GAP — a link made hours later cannot be this clone's own session — and a raw
`HH:MM:SS` in a committed record reads as a reproducible value it is not (the repo's own
`.husky/check.timestamps.sh` refuses one).

⇒ it is safe to re-run only under birthtime semantics. under mtime semantics **each poll is a fresh
chance to adopt the parent**, so the exposure grows with the clone's lifetime rather than shrinks.

## 🔴 .why it is worse than a wrong read — it FORGES a verdict

this repo is mid-wish on `clone say`'s verdict set, and `released` is defined as *the transcript
count rose*. so:

| what happens | what `say` reports |
|---|---|
| the peer takes the message and answers | `released` ✅ |
| 🔴 the peer is deaf, and **the enroller writes one line of its own output** | `released` — **unearned** |

⇒ **a false `released` is the exact inverse of the defect this wish exists to cure.** the wish fixes
*a landed say reported as a failure*; this produces *a never-landed say reported as a success*, which
is the strictly worse direction: the first costs a retry, the second costs a silent drop.

⚠️ and it poisons its own proof. a dogfood that says *"reply with token `X`"*, then reads `X` back
from a transcript that is the enroller's own, has **measured the enroller**. the token appears
because the enroller wrote it into the prompt.

## .the shape of the fix

1. **read the record, never the correlate** — gate on `birthtimeMs`, which is what *created* means.
   🟡 with a bound: `birthtime` is `0` or falls back to `ctime` on some filesystems, and a naive swap
   would put **every** transcript out of window and give every clone an empty history. so the
   predicate takes both and requires in-window by `mtime` **and** by `birthtime` *where birthtime is
   trustworthy* (non-zero, not later than mtime).
2. **exclude the enroller's own session outright** — the surest cure, and narrower than (1): a clone
   must never link the transcript of the process that spawned it. this needs the parent's session
   id, which the enroller holds and does not currently pass down.
3. **re-arm the refusal at `length === 1`** — the ambiguity guard treats a single candidate as
   certainty. an own-transcript that has not appeared yet is not certainty, it is an absence
   (`define.invariant.empty-render-names-its-cause`).
4. 🟡 **and the direction glyph is a second, separable defect**: a linked transcript's messages are
   rendered `🎧` *heard from the clone* with no check that the clone authored them. a mis-linked
   transcript therefore arrives with **false provenance**, which is what made the read persuasive.

the clamp: a clone spawned against a transcript dir that holds a **continuously-appended** parent
file must link **zero** transcripts, never that one. it goes red under the extant `mtime` predicate.

## ✅ .the cure — landed 2026-09-17, same stone

the deferral above read: *"it is not verifiable here"* — the integration tier was credential-halted
on an `aws sso` prompt. **that halt lifted** (`keyrack: unlocked ehmpath/test`), so the clamp became
runnable and the cure was owed in this round rather than deferred out of it.

`isTranscriptWithinSpawnWindow` now reads **creation**, with the trustworthiness bound this dream's
own `.the shape of the fix` named:

```ts
const observedAtMs =
  input.transcriptBirthtimeMs !== null &&
  input.transcriptBirthtimeMs > 0 &&
  input.transcriptBirthtimeMs <= input.transcriptMtimeMs
    ? input.transcriptBirthtimeMs
    : input.transcriptMtimeMs;
```

three clauses, each against a real filesystem: **present** · **non-zero** (no creation time kept) ·
**no later than mtime** (a stamp the filesystem reports and does not keep). every untrustworthy read
degrades to mtime — the exact behavior that predates the fix, so candidacy is **narrowed where
creation is knowable and never widened where it is not**.

### the clamp, proven red at BOTH grains

`rule.require.clamp-edge-cases` demands the clamp **bite**. it was dogfooded by mutation — the
predicate reverted to `observedAtMs = input.transcriptMtimeMs`, the suites re-run, the fix restored:

| grain | the clamp | under the mutation | restored |
|---|---|---|---|
| unit | `a LIVE PEER transcript — created hours before spawn, written after it — is out-of-window` | 🔴 **1 failed** / 8 passed | ✅ 9 passed |
| integration | `[case7] a LIVE PEER marker — born before spawn, written after it` | 🔴 **1 failed** / 6 passed | ✅ 7 passed |

⇒ **exactly one case went red at each grain, and it was the live-peer case.** a mutation that fails
many cases proves the suite runs; one that fails exactly the clamp proves the clamp measures *this*.

### 🟡 and not one extant fixture was disturbed

`[case2]`'s `utimesSync(…, 1_000_000, 1_000_000)` is byte-identical to before. it survives because

untrustworthy-birthtime fallback. ⇒ the fix **added** coverage and changed no prior assertion,
which is what `rule.forbid.test-intent-violations` asks for.

### item 4 — cured by the read-time gate

`getCloneOutput.ts:63-75` refuses an out-of-window episode at READ time and reports it as
`exidsForeign`, so a transcript linked before the gate existed (or by hand) never renders as `🎧`.

⇒ the TRANSCRIPT is the only grain where authorship data exists: `direction` derives from
`record.type` (`assistant` → `out`, `user` → `in`, `asCloneMessage.ts:93-101`), so within one
in-window transcript every assistant record IS that session's own reply. the false `🎧` came
entirely from a wrong file, which the gate now refuses.

### 🔴 item 3 — its stated cure would empty every clone's history

*"refuse at `length === 1` too"* has no discriminator behind it. a blanket refusal takes the
`ambiguous` branch on every single-candidate case — which is the NORMAL case — so every clone links
zero transcripts, forever. **an empty history reads as a deaf clone**, so the fix would produce a
worse defect than the one it aims at.

the residual it aims at is real: after we claim our own transcript, it leaves the eligible pool, so a
later poll can see a co-located peer's fresh transcript as the only candidate and claim it. but
birthtime cannot part *our second episode* from *a peer's first* — both are born after our spawn.

⇒ so item 3 needs POSITIVE identification, and `--session-id <uuid>` supplies it (measured 2026-09-18:
the transcript filename is the assigned uuid, created at spawn, even when the run fails). that cure
subsumes items 2 and 3 together and is `dirty`, so it is its own dream + fulcrum **F29**.
