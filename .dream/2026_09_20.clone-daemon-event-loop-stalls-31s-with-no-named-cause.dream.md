## .the gap, precisely

🔴 **the fork the lag watch was built to settle is now SETTLED, and it landed on `the loop stalled`.**
`genCloneLoopLagWatch` measures `drift = now - tickedAt - tickMs` at `tickMs: 1000`, and node fires a
missed interval once on unblock — so `30034ms` means **the timer callback did not run for ~31s of wall
clock**. that is a measurement of the loop, never an inference from an outcome.

three facts bound the shape:

- `acksSeen: ["queued"]` — the first ack left before the stall; the second never left, because **no
  handler ran** to send it
- `silentMs: 30066` ≈ `stalled 30034ms` — the client's wedge window and the loop's stall are the
  **same** 30 seconds, never two coincident ones
- the brain answered the turn anyway — `get --tail 10` holds `JOKER-TURN-3-…` with its joke. the
  brain-cli is a separate process, so a blocked daemon loop never touched it

⇒ **so the `.catch` cure on the dequeue path cannot fix this.** a `.catch` handles a *rejected
promise*; a blocked loop produces no rejection, only synchronous work that does not yield. the cure
is correct for its own class and this is a different class.

### 🔴 what is NOT the cause — three candidates ruled out by extant measurements

| candidate | its measured bound | verdict |
|---|---|---|
| the screen read (`genCloneScreenFeed.read`) | **2.38ms** at the 1000-row scrollback cap (`.agent/.notes/tool.measure-screen-read-cost.js`) | four orders of magnitude short |
| the emulator settle (`settle`) | **250ms**, `SCREEN_SETTLE_TIMEOUT_MS`, unconditional | two orders short |
| the submit-ready wait (`awaitCloneSubmitReady`) | **5,000ms**, `CLONE_SUBMIT_READY_BUDGET_MS` — and it `await`s, so it yields each poll | one order short, and it does not block |

⇒ **no candidate on the dispatch path that has been read accounts for 31 seconds.** the honest state is
`measured THAT it stalled, not measured WHAT stalled it` — so a cure shipped now would be a mechanism
inferred from an outcome (`rule.forbid.mechanism-inferred-from-outcome`).

### 🟡 a second, smaller defect found in the same capture

the debug capture's own two timestamps disagree:

```
at            T+25.4s   (from the temp dir's own enrollment stamp)
threw after   30143ms    from the dispatch write
```

the dispatch write necessarily FOLLOWED enrollment, so a capture 25.4s after enrollment cannot also
be 30.1s after that write. ⇒ `at` does not name the moment the capture describes. one of the two
numbers is unusable, and a reader cannot tell which
(`rule.require.read-the-record-not-the-correlate`).

🟡 both stamps are rendered as an OFFSET rather than as wall clocks. what the contradiction rests on
is the **arithmetic** — 25.4s against 30.1s, where one interval strictly contains the other — and a
raw `HH:MM:SS` in a committed record reads as a reproducible value it is not (the repo's own
`.husky/check.timestamps.sh` refuses one).

## .the shape of the fix

the lag watch answers *when*. the absent instrument answers *who*, and it is the same shape one grain
deeper — a latched phase plus the drift already in hand:

1. **latch a phase string** the dispatch path sets as it enters each synchronous stage (`feed`,
   `settle`, `read`, `classify`, `write`, `submit`), injected the way `trace` already is
2. **report it beside the drift** — `clone daemon event loop stalled 30034ms during phase=<x>`. one
   line, and it converts an unbounded hunt into a named stage
3. **if the phase is unset at the stall**, the block is outside the dispatch path — and *that* is the
   decisive finding, since it redirects the whole hunt away from this wish's own machinery
4. **repair the capture's `at`** so it stamps the throw rather than the write of the file

⇒ step 3 is the one that matters most: it is the only step that can **exonerate** the screen feed, and
every candidate ruled out above is already pointing that way.

## .why it is not done in this round

- the cause is **unidentified**, so a cure would be guessed. the wish's own rule set forbids exactly
  that (`rule.forbid.mechanism-inferred-from-outcome`), and the three ruled-out candidates are the
  evidence that the obvious guess — the always-on emulator — does not fit the magnitude
- the fix is a **new instrument plus a new injected seam** through the dispatch path, which ripples
  into `genCloneSocketServer`, `genCloneWriteQueue`, and `genCloneScreenFeed` and their clamps. that
  fails the CLEAN half of the scouts-honor test (`rule.always.fix-forward-under-scouts-honor`)
- 🟡 and the defect is **intermittent**: `modalprobe` and `transcript-lag` both ran green in the same
  invocation, so a clamp for it needs a reproducer before it can have teeth
  (`rule.require.clamp-edge-cases` — a clamp not seen to go red is a guess)

## .the workaround used in this round

none. the wedge is reported honestly by the contract — `MalfunctionError`, `reachCause: wedged`,
`acksSeen` enumerated, and now a daemon trace line that names the class. so the failure is **loud and
correctly attributed**, which is the state this wish's own `rule.forbid.failhide` asks for. what is
absent is the cure, never the diagnosis channel.
