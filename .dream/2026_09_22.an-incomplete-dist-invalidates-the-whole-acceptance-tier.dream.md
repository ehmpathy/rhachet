# 🌙 dream: an incomplete `dist/` invalidates the whole acceptance tier, and the tier blames your diff

- **kind** = defect
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-22, at `v2026_09_17.feat-boot-manifest-and-budget` `5.1.execution`, on the
  close-out tier for the snapshot + `rhx` alias work

---

## .the cue that fired

a full acceptance tier ran **3,032 seconds** and reported:

```
Snapshot Summary
 › 13 snapshots failed from 5 test suites. Inspect your code changes or run `... -u` to update them.

Test Suites: 96 failed, 3 skipped, 37 passed, 133 of 136 total
Tests:       44 failed, 4 skipped, 1893 passed, 1941 total
```

🔴 **not one of those numbers named the cause, and the one sentence that offered a direction pointed
at the reader's own diff.** the real cause was a single absent build artifact, and it is printed 96
times in the body of the same log — where nobody reads after a summary that says *"inspect your code
changes."*

⇒ the cue is the 50 minutes, but the defect is the **misdirection**. a tier that cannot run is
reported as a tier that ran and disagreed with you.

## .the gap, precisely

every one of the 96 failed suites carries the **identical** load error:

```
● Test suite failed to run

  ENOENT: no such file or directory, open '<repo>/dist/contract/sdk.keyrack.js'
    at Object.<anonymous> (jest.acceptance.env.ts:8:18)
```

`jest.acceptance.env.ts` is the `setupFiles` entry for **every** acceptance suite, so one absent
artifact under `dist/` takes down every suite that jest had not already loaded.

### 🔴 the three failures that compound

| # | what it does | what it costs |
|---|---|---|
| 1 | the env **reads `dist/` with no preflight** | 96 suites each rediscover the same absent file, one at a time |
| 2 | jest **runs the whole tier anyway** | 50 minutes spent to learn one fact available in the first second |
| 3 | 🔴 the **summary names snapshots** | the reader is pointed at their own diff, and at `-u` — the one action that would bake a defect in |

🔴 **#3 is the sharpest, and it is actively dangerous.** the summary's literal advice is *"inspect
your code changes or run `-u` to update them."* a reader who takes the second branch resnaps 13
snapshots against a half-built tree. `rule.forbid.blanket-resnap-after-rebase` exists for exactly
this, and here the harness recommends the violation by name.

green with no code change**, which establishes the class; the final row is left to the dream that
already owns it rather than absorbed here on a guess.

### 🔴 the same pollution hit the INTEGRATION tier, and there one failure WAS real

a co-scheduled integration run (`2026-09-22T16-59-36Z`, 614s) returned **5 failed of 1,390**:

| rows | verdict |
|---|---|
| `sshPrikeyToAgeIdentity` · `invokeClone [case4]` · `keyrack daemon [case10]` `[case11]` | 🟡 the documented host-state family |
| 🔴 `invokeRolesBoot.budget [case2]` — the subject-mode halt snapshot | 🔴 **real, and mine** — a `+1` line, the `rhx cost` pointer |

🔴 **that 1-in-5 is the whole reason this dream matters.** the acceptance tier's 44 were *all*
artifacts; the integration tier's 5 were *four* artifacts and one genuine snapshot that needed a
resnap. ⇒ **a reader who learns to discount a red tier discounts the one row that was theirs** —
which is the cost `2026_09_18.three-integration-suites-fail-on-host-state-not-code` named as a
hazard and this run demonstrates as an event.

### 🟡 the cause of the absent artifact is itself unsettled

`blackbox/cli/build.artifacts.acceptance.test.ts:20` states *"the acceptance config runs `npm run
build` before the suite"*, and `build:complete` rewrites `dist/package.json` — so the tier both
**depends on** `dist/` and **writes** it. whether this instance was a partial prior build, an
interrupted one, or a write that raced the runner is **not established here**.

🔴 **and it does not need to be, because the repair is the same either way.** a tier that reads a
build artifact owes a preflight whether the artifact went absent by a race or by a stale tree.

## .the shape of the fix

🔴 **the pavement already exists one level down, and the repair is to lift it up one.** six
`blackbox/sdk/*.realnode.acceptance.test.ts` suites each already guard their own artifact:

```ts
// blackbox/sdk/importEsmSafe.realnode.acceptance.test.ts
'built dist/infra/importEsmSafe/importEsmSafe.js absent — run `npm run build` first'
// blackbox/sdk/keyrackEsmRequire.realnode.acceptance.test.ts
{ vaultDistPath, hint: 'run `npm run build` first, then re-run acceptance' }
```

⇒ the shape is settled, named, and in use. `jest.acceptance.env.ts` — the one file **every**
acceptance suite loads — is the one that does not use it.

1. 🔴 **preflight the env.** in `jest.acceptance.env.ts`, before any dist read, assert the entry
   artifacts exist and throw a `ConstraintError` that names `npm run build`. one clear refusal in
   second one, rather than 96 ENOENTs over 50 minutes
2. **halt rather than continue.** a `globalSetup` that throws stops the run; a `setupFiles` throw
   fails each suite in turn. the preflight belongs at the **global** grain so the tier ends at once
3. 🟡 **stop the summary from misdirection.** a run whose suites failed to *load* must not close
   with a snapshot verdict at all — the snapshot count is a property of suites that ran, and here
   5 of 136 did. the `git.repo.test` skill already parses this output; it is the natural place to
   lead with the load-failure count when one is present

⇒ #1 and #2 are ~10 lines. #3 lives in `rhachet-roles-ehmpathy`'s `git.repo.test` and is the one
that survives a jest upgrade.

---

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **SAFE?** | 🔴 **no** for #1/#2 — `jest.acceptance.env.ts` is loaded by **every** acceptance suite, so a throw added there changes the failure mode of all 136 at once |
| **CLEAN?** | 🔴 **no** — this behavior's diff touches `boot/`, `manifest/`, `contract/cli/invokeRoles*`, and `blackbox/cli/roles.*`. the jest env and the test skill are in neither |

🔴 **#3 is not even in this repo.** `git.repo.test` ships from `rhachet-roles-ehmpathy`, so it is a
**reseed**, not a local repair — a tree adopts only what is scoped to itself
(`rule.always.scope-onetime-lessons-to-the-behavior`).

🟡 **the deferral is for DIRT, not merely scope**, so it owes a fulcrum beside this dream: the
judgment that a guard in the shared jest env ripples across 136 suites is an estimate of ripple
cost, and an estimate made alone is what a fulcrum list exists to surface
(`rule.always.itemize-the-fulcrums-you-best-guess`).
