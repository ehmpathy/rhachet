# 🌙 dream: one published home for the live-brain clamp, so the fleet reuses it

- kind = feat
- owner = rhachet (or test-fns)
- caught 2026-10-31

## .the cue that fired

a peer review read the registry's claim that a peer repo supplies its own registry and reuses the
scan operations, and found no package exposes them.

## .the gap, precisely

- `tsconfig.build.json` excludes `**/.test/**/*`, and `package.json` `exports` lists only the
  `sdk.*` entries, so the clamp's operations never ship
- the other repos the wish names (bhrain, bhuild, rhight, mhedic, brains-anthropic) can only copy
  ~10 files, which then drift

## .the shape of the fix

1. move the registry-free operations to one published home — a `rhachet` test subpath export, or
   `test-fns`: `getAllLiveBrainSuitesUngated`, `getAllNonTestModulesReachUnregistered`,
   `getAllInfraModuleExportsUnclassified`, `getAllSuitesGated`, `getAllTestFilePaths`,
   `getCauseOfSuiteUngated`, `getMarkersOfContent`, `getNamesOfExports`,
   `asLiveBrainMarkersOfRegistry`, `describeBrainLiveOnDemand`, `isBrainLiveScopeAll`, the
   `LiveBrain*` types
2. keep each repo's `LIVE_BRAIN_REGISTRY` in its own tree, as data
3. a peer repo's integration test reads its registry through the published operations
4. dispatch a task to each fleet repo once the home ships

## .why it is not done in this round

it adds a published contract (a subpath export and its build), which is a release decision, and
each fleet repo is its own tree; this round holds the clamp in rhachet, where the spend was.
