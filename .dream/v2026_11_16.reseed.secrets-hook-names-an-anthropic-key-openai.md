# 🌙 dream: the practice's secrets hook names an anthropic key openai, and refuses its own fixtures

- kind = reseed
- owner = declapract-typescript-ehmpathy (the `husky` practice)
- caught 2026-11-16

## .the cue that fired

`.husky/check.secrets.integration.test.ts` in ehmpathy/rhachet drove one fake key per shape the
hook knows, and fed the hook a real acceptance test of the repo. two defects surfaced:

1. a staged `sk-ant-…` key halted the commit, but its `shape:` line read `openai-style key`
2. a test that writes a fake pem fixture (a pem `BEGIN RSA PRIVATE KEY` header on its own line)
   halted the commit, with no way to declare the key fake. in rhachet ~40 files hold such a line

## .the gap, precisely

1. `SHAPES` is walked in order, halt on first hit. `openai-style key` (`sk-(proj-)?…`) sat ahead
   of `anthropic key` (`sk-ant-…`), and `ant-…` fits the openai tail
2. the hook scans each whole staged blob, with no allow form for a declared fake key

## .the shape of the fix

both are fixed in ehmpathy/rhachet's local copy of `.husky/check.secrets.sh`; port them to the
practice template:

- `anthropic key` sits ahead of `openai-style key` (narrow before wide), with a comment that says so
- a line that carries `check.secrets:allow` is skipped (`grep -vF 'check.secrets:allow'` after the
  shape grep), and the refusal names that marker as its last branch:
  `└─ a fake fixture, never a real key? mark its line with check.secrets:allow`
- pin one fake key per shape, the marker's line scope, and a marked fixture pass in the practice's
  own tests (rhachet's `check.secrets.integration` [case2], [case4] are a template)

## .why it is not done in this round

the hook is practice-owned. the local copy is fixed in this pr, so this repo commits clean today;
the next practice apply overwrites it with the template, so the template must carry the same fix.
