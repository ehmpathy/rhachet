# 🌙 dream: one dispatcher per event for actors declared in `.agent/actors.yml`

- kind = feat
- owner = rhachet (this repo)
- caught 2026-11-19

## .the cue that fired
the rebase of `.behavior/v2026_11_17.feat-hook-dispatcher-one-process-per-event` onto main, which
had gained `.agent/actors.yml` (#699); the deferral is fulcrum F32.

## .the gap, precisely
under a manifest, each actor's hooks come per rule from the linked roles' in-mem union
(`getAllHooksOfLinkedRolesForClaudeCode`, `hooksVia: 'brain'`), and `genBrainCliConfigArtifact`
skips `setActorHookDispatchManifestDerived`. so an `actors.yml` clone still starts one process per
rule per tool call — the cost the dispatcher removes everywhere else.

## .the shape of the fix
1. under a manifest, narrow the union's rules to the actor's roles (`asHookDispatchRulesForRoles`)
2. write them to the actor's own `hooks.dispatch.manifest`, before its settings
3. hand the actor's settings one dispatcher per event that names that manifest
   (`asSettingsWithHookDispatchers`); the repo actor holds its authorless hooks, as main does
4. clamp: `enroll.actors-yml.integration` [case2] asserts the dispatcher shape and that each
   actor's manifest holds its own roles' rules alone

## .why it is not done in this round
the two features met at a rebase. the safe merge holds every rule's verdict as on main; the process
cut for `actors.yml` repos is additive, and no repo in this org declares a manifest yet.
