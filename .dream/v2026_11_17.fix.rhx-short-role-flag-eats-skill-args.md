# 🌙 dream: `rhx <skill> -r` reaches the skill, not rhx's `--role`

- kind = fix
- owner = rhachet (this repo)
- caught 2026-11-17

## .the cue that fired
`rhx rmsafe -r --path review` failed with `no skill "rmsafe" found with --role --path`.

## .the gap, precisely
`src/contract/cli/invokeRun.ts:124` declares `-r, --role` on the `run` command, and the
positional-skill form (`rhx <skill> …`) rewrites to `run --skill <skill> …`. commander then reads a
skill's own `-r` (here `rmsafe -r` = recursive) as `--role`, and takes the next token as its value.
a skill flag is silently eaten; the error names the wrong cause.

## .the shape of the fix
in the positional-skill form, every token after the skill name belongs to the skill: stop rhx's own
option parse at the skill slug (or drop the `-r` short alias). clamp: `rhx <skill> -r --x y`
reaches the skill with `-r --x y` intact.

## .why it is not done in this round
it changes the cli arg contract of every skill call; out of scope for the hook dispatcher pr.
