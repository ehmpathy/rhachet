# 🌙 dream: a say that lands but exits nonzero invites a double post

kind = followup · owner = rhachet (clone say) · caught 2026-11-02

## .the cue that fired

the blueprint for `v2026_11_01.fix-tests-mock-the-claude-cli` made the test harness's say retry
idempotent: before a re-send, it counts the clone's `in` transcript lines, and re-sends only if the
count did not rise. a peer review noted the harness retry exists to model a consumer who re-says a
wedged dispatch (`blackbox/.test/infra/enrollCloneHarness.ts:877-885`). the harness no longer
double-posts; that consumer still can.

## .the gap, precisely

`rhx clone say` can exit nonzero after the brain took the message: the say reached the pty and the
brain wrote its user turn, but the `delivered` ack or the reply poll ran out. a consumer — a human,
or a clone that drives another — reads exit 2 as "not delivered" and re-says. the brain then holds
the message twice, and answers it twice.

## .the shape of the fix

one of, to be chosen in its own behavior:

- the say's refusal names the case: when the transcript already holds this say's `in` line, the
  exit-2 output says the message landed and only the ack or reply is late, with the command to
  read it (`rhx clone get`), so a re-say is no longer the obvious next move
- or a `--idem` flag on `clone say` that applies the same count check the harness now uses

either needs a measurement first: how often a real say lands but exits nonzero (the
`rule.forbid.sync-invoke-while-a-pty-is-live` case was one such cause, in tests).

## .why it is not done in this round

it is product behavior of `clone say`, and this wish is about which tests reach anthropic. a fix
here changes a published cli contract; it needs its own vision and the wisher's call.
