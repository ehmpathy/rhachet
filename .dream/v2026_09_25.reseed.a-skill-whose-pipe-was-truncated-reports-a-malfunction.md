# 🌙 dream: a skill whose pipe was truncated reports a 💥 malfunction

- **kind** = reseed
- **owner** = `ehmpathy/rhachet` (the skill runner's exit render) — and possibly
  `ehmpathy/rhachet-roles-ehmpathy` (the bash skills themselves)
- **caught** = 2026-09-25

## .the cue that fired

a routine census during review 7 of stone `5.3.verification`:

```
$ rhx grepsafe --pattern '^<(readme|brief\.say|…)' --path '…/boot.md' | head -30
…30 lines of real output…
🪨 run solid skill repo=ehmpathy/role=mechanic/skill=grepsafe
   └─ 💥 failed with an error
```

the census was correct. `head` closed the pipe at line 30, the shell executable took `SIGPIPE`, and
the runner rendered that as a **malfunction**.

## .the gap, precisely

a truncated pipe is a **normal end** — `yes | head` exits 0 — yet the skill runner reports `💥`, the
glyph reserved for *the server must fix this* (`rule.require.exit-code-semantics`). so a human who
pipes any skill into `head`, `less`, or `wc -l` with an early exit is told the skill broke.

⚠️ **this is a DIFFERENT path from the one repaired in this behavior.** the fix in this route
(`src/contract/cli/exitCleanOnClosedPipe.ts`) covers the cli's **own** stdout writes — proved clean
at `rhx init --hooks | head -3`, `PIPE_EXIT=0`. this gap is the runner's read of a **child
process's** exit status, where `SIGPIPE` yields 141 and is graded as a fault.

checkable:

```
rhx grepsafe --pattern 'a' --path package.json | head -1   # observed: … 💥 failed with an error
rhx grepsafe --pattern 'a' --path package.json | wc -l      # ✅ no 💥 — the full stream is read
```

## .the shape of the fix

1. in the skill runner, treat a child exit of `141` (or a `SIGPIPE` signal) on a **truncated stdout**
   as a normal end: no `💥` line, exit 0
2. hold the line `rule.forbid.failhide` draws — every other non-zero child exit stays a loud `💥`
3. clamp it as a **unit** over the exit-code classifier, not an end-to-end row: whether the child
   sees `SIGPIPE` before or after it finishes its write is a race, and a race clamp has no teeth
   (`rule.require.clamp-edge-cases` — the same reason this route's EPIPE clamp is a unit)
4. decide whether the bash skills should also trap `SIGPIPE` themselves, which is the
   `rhachet-roles-ehmpathy` half

## .why it is not done in this round

- **SAFE?** ✅ yes — one branch in the exit classifier
- **CLEAN?** 🔴 no — the render sits on the **skill-runner** path, which this behavior does not touch,
  and the second half of the fix belongs to another repo. a tree adopts only what is scoped to itself
  (`rule.always.scope-onetime-lessons-to-the-behavior`)
