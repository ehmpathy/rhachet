# 🌙 dream: the 3-suite cap on a tier-3 run is held in jest, not in a bash door

- kind = feat
- owner = rhachet
- caught 2026-10-31

## .the cue that fired

review i018 r011 (enroll-impl-arch-defects), nitpick 2, conceded `better`.

## .the gap, precisely

`BRAIN_LIVE_SCOPE=all` opens tier 3 wherever jest reads it (`isBrainLiveScopeAll`), but the cap of
3 suites per run lives only in `test.brain.live.sh`. a run that sets the flag itself, such as
`BRAIN_LIVE_SCOPE=all rhx git.repo.test --what integration --mode apply`, bypasses the cap and runs
every tier-3 suite. the door also keeps a text twin of `getAllSuitesGated`, held equal by a parity
row.

## .the shape of the fix

- a jest `testSequencer` on the integration and acceptance configs; it receives the matched test
  list after the path pattern
- when the flag is on, count the matched files that are wholly gated; past 3, throw a
  `ConstraintError` that names the `rhx test.brain.live --scope` hint
- confirm the sequencer sees the list after the path pattern and after `--shard`
- the door then only forwards; the bash twin and its parity row go

## .why it is not done in this round

it changes both jest configs, which every suite runs under, and needs a probe of the sequencer's
input under `--shard` first; that ripples past the files this stone touched.
