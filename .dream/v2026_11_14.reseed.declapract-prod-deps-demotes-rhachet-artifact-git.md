# 🌙 dream: the rhachet practice's prod-deps fix demotes a dep that rhachet itself imports at runtime

kind = reseed · owner = ehmpathy/declapract-typescript-ehmpathy · caught 2026-11-14

## .the cue that fired

`npx declapract apply --practice rhachet` (declapract-typescript-ehmpathy 0.50.0) applied
`practice:rhachet.bad-practice.prod-deps` to `package.json`. It moved `rhachet-artifact-git` from
`dependencies` into `devDependencies`.

## .the gap, precisely

the rhachet repo's own prod code imports `rhachet-artifact-git` at runtime:
- `src/contract/cli/invokeChoose.ts`
- `src/contract/cli/invokeRepoCompile.ts`, `src/contract/cli/invokeRepoIntrospect.ts`
- `src/domain.operations/template/useTemplate.ts`
- `src/domain.operations/role/getRoleBriefs.ts`

as a devDependency it is absent for every consumer of the published rhachet package. the rule fits a
repo that CONSUMES rhachet, not rhachet itself.

## .the shape of the fix

in the `rhachet` practice's `bad-practice.prod-deps` check, exempt the repo whose `package.json`
`name` is `rhachet`, or exempt any dep the repo's `src/` imports outside test files.

## .why it is not done in this round

the practice lives in another repo. here the move was reverted by hand, and the defect must be fixed
upstream.

also seen: the boot ran declapract 0.13.15 against declapract-typescript-ehmpathy 0.50.0. Its
`environments-aws` practice declares `checks: []`, and 0.13.15 rejects that, so the apply died. the
practice should pin a minimum declapract version (a peerDependency) so an older one fails with a
named cause.
