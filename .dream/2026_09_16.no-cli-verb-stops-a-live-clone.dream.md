# 🌙 dream: a `clone stop` verb that is discoverable and brain-independent

- **kind** = feat
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-16

## .the cue that fired

a detached enroll (`--async`, and the default with no tty) now re-execs itself as a host
process in its own session, so the clone genuinely outlives the terminal that made it. i went
to tear down the clones i had spawned across this drive and could not find a verb that does it.

🔴 **and that first draft was wrong.** a verb does stop a live clone, and i had not tried it:

```sh
rhx clone say '@:loopv2' --what '/exit'     # → verdict: released
rhx clone list                              # → @:loopv2  state=DEAD
```

⇒ measured 2026-09-16 on `@:loopv2`. the say reaches the brain's own `/exit` command, the brain
quits, the pty closes, the reach-state reads DEAD, and `clone prune` then reclaims the record.

so the capability is present. what is absent is narrower, and it is what this dream is for.

## .the gap, precisely

| what | state |
|---|---|
| a live clone **can** be stopped | ✅ via `say --what '/exit'` |
| a caller can **find** that | 🔴 no. `clone --help` lists list/say/get/whoami/prune, and the `prune` tip names only DEAD clones |
| it works for **any** brain | 🔴 no. `/exit` is a claude-cli word; another brain has its own, and the caller must know which |
| it works on a **wedged** brain | 🔴 no. a brain that cannot process input cannot process a quit command either |

⇒ the defect is **discoverability and brain-independence**, never capability. the paved path
exists and is unmarked, which is the worse of the two failure shapes — a caller who reads the
help concludes the lifecycle has no far end, exactly as this dream's first draft concluded.

### 🔴 the wedged row has TWO causes, and the second is one this wish adds on purpose

measured 2026-09-18. the row above reads the wedge as *"a brain that cannot process input"*. a second
cause reached it by a different road, and it is not a defect:

| cause | the brain | `say` | can `/exit` reach it? |
|---|---|---|---|
| the extant read — a hung or crashed repl | cannot process input | writes, into a void | no |
| 🔴 **a modal holds focus** | CAN process input | **refuses, correctly** (`withheld` / `modal-holds-focus`) | **no** |

`@:wedge1` sits in the second state: it raised its own `Edit` permission prompt, and `say` declines to
answer a modal at all — with no force path, by design (`V3`, `case=6`). so the `/exit` interim below is
**unavailable exactly when a caller most wants it**, and the refusal is the right behavior.

⇒ **so the SIGTERM step in the fix below is no edge case for a broken brain — it is the ONLY teardown
for a healthy clone parked on a prompt.** it moves from the last bullet to one the fix rests on, and
its pid-ownership check moves with it.

🟡 and the frequency is not incidental: a peer that carries the `driver` role drives the enroller's
route and raises its own permission prompts as it acts, so it reaches this state on its own
(`rule.forbid.peer-clones-that-carry-the-driver-role`). the two dreams meet here.

### 🔴 and for a DETACHED clone the second row has no human to wait for at all

measured 2026-09-18 against `@:wedge1`, after a wisher asked outright whether `prune` could reach it.
the row above reads the modal case as *"`/exit` is unavailable exactly when a caller most wants it"*.
the true state is worse, because **the remedy the error named does not exist**:

| fact | source |
|---|---|
| attendance is a **MODE**, never a reach | `define.invariant.clone-attendance-is-a-mode-never-a-reach` |
| **detached is the default** with no tty | `computeCloneEnrollMode.ts` |
| ⇒ a detached clone has **no tty** a human could clear the modal at | so *"wait for the human"* never resolves |
| and `clone list --output json` carries **no pid** | only `serial`, `slug`, `reachState`, `spawnedAt` |

⇒ so a caller at this wall had **no reachable actor and no CLI-reachable pid** — the pid lives only in
the clone's own `identity.json` (`hostPid`, `hostPidStartedAt`).

the error copy was cured at source in that round (`computeCloneSayReport.ts` — the hint now splits by
mode and declares the detached dead-end outright), but **the copy cure only tells the truth; it opens
no path.** the path is still this dream.

⇒ 🔴 **so the SIGTERM step does not merely carry weight — it is the SOLE teardown for a healthy
detached clone parked on a prompt**, and its pid-ownership check has a named field to key on:
`identity.json`'s `hostPidStartedAt`, which settles pid reuse in one comparison.

🟡 **`prune` was also measured rather than assumed, and it genuinely cannot help:** it listed the 3
DEAD clones and skipped `@:wedge1` outright, and `prune --help` carries no force lever — only
`--older-than`, `--mode`, `--output`. so `stop` is not a nicety beside `prune`; `prune` is
DEAD-only **by contract** (`define.invariant.clone-prune-safety`) and must stay that way.

⚠️ **this predates the detach and the detach sharpened it.** before, an attended clone died with
the terminal that held it, so no caller ever had to look for the stop path. now attendance is a
**mode**, never a reach — so the clone outlives its terminal and the unmarked path carries weight.

## .the shape of the fix

a thin `clone stop <address>` that wraps what already works and closes the three gaps above:

- **the quit word rides the brain adapter**, beside the extant `isBrainSocketCapable` axis — so
  `/exit` is claude's answer, never the cli's hardcoded assumption
- **dispatch it through the extant say path**, so a modal or dirty-region refusal is reported
  with the verdict vocabulary this wish already ships, rather than swallowed
- **then poll the reach-state to DEAD** (the `pollForCloneListState` shape)
- **then SIGTERM on a bound**, for the wedged-brain row — `genPtyCloneHostDetached.onSignal`
  already forwards it, and the clone's own record owns the pid
- **then reclaim** the way `prune` does — so `stop` is quit-then-reap, never a second record path
- ⚠️ scope it to ONE address by default. a `--all` must be an explicit opt-in
  (`rule.forbid.unscoped-process-kills`), and the pid must be checked against the record that
  claims it before any signal (pid reuse)

⇒ the acceptance clamp writes itself: enroll async, assert LIVE, `stop`, assert DEAD.

## .why it is not done in this round

**SAFE** = no. the wedged-brain row sends a signal to a pid, and this round's bound is the say
read channel. an ownership check authored under a different wish's review is the wrong place to
get pid reuse right.

**CLEAN** = no. it wants a new cli verb, a brain-adapter field, a record transition, its own
acceptance case, a `--all` policy call, and the help snapshot every cli acceptance case reads.

⇒ so it is caught rather than fixed, per `rule.always.fix-forward-under-scouts-honor`.

## .the interim, and it needs no code

```sh
rhx clone say '@:<slug>' --what '/exit'   # stop a live claude clone — ONLY if no modal holds focus
rhx clone prune                           # reclaim its record once DEAD
```

🔴 **and when a modal DOES hold focus, the interim above is unavailable — and there is NO interim.**

the only lever left is a SIGTERM, and the pid it needs is not reachable by any paved path:

| step | state |
|---|---|
| find the clone | ✅ `rhx clone list --output json` |
| read its pid | 🔴 **not in that output** — it carries `serial`, `slug`, `reachState`, `spawnedAt` |
| read it from disk instead | 🔴 the record is at `<actorDir>/clones/serial=<serial>/identity.json`, and `actorDir` is **content-hashed** (`getActorOndiskDir({ repoPath, hash })`) — so a human cannot type the path, only `find` for it |
| check pid reuse | 🔴 by eye, against `hostPidStartedAt` |
| signal it | `kill -TERM <hostPid>` |
| reclaim | ✅ `rhx clone prune`, once DEAD |

⇒ **three of the six steps have no paved path at all**, and the one that guards against a wrong kill
(pid reuse) is the one left entirely to the human's eye. that is the whole argument for the verb: the
capability exists, and its only route runs through a hashed internal dir.

## .the lesson beside the feature

the first draft of this dream asserted *"no verb stops a live clone"* from a read of `--help`
alone. one command settled it the other way. ⇒ `rule.require.search-before-you-claim-absence`:
an absence taken off a help text is a claim about the help text, never about the capability.
