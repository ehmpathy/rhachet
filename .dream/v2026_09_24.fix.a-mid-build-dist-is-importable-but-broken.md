# 🌙 dream: a mid-build dist is importable but broken

kind: fix · owner: ehmpathy/rhachet · caught 2026-09-24

## .the cue that fired

the journey acceptance run `2026-09-24T08-05-33Z` failed 11 of 74 with no code change, and the
same command passed 74 of 74 at `2026-09-24T08-35-42Z` with no edit between. the two `rhx` calls
that died did so identically:

```
Error: Cannot find module '@src/domain.objects/ContextCli'
Require stack:
- dist/domain.operations/config/genContextConfigOfUsage.js
- dist/contract/cli/invoke.js
- bin/run.jit
```

the calls on either side of them exited 0. after the run, `dist/` held no `require("@src/…")`
anywhere.

## .the gap, precisely

- `build:compile:tsc` = `tsc -p ./tsconfig.build.json && tsc-alias -p ./tsconfig.build.json`
  (`package.json:71`). between the two, every emitted `.js` in `dist/` carries an unresolved
  `@src/…` specifier
- `bin/run.jit:2` is `require('../dist/contract/cli/invoke')`, so **every** `rhachet` and `rhx`
  call on the jit path reads `dist/` live, off disk
- ⇒ a call that lands inside that window dies `MODULE_NOT_FOUND` on a `dist/` that exists, is
  the right shape, and is wrong
- the freshness marker cannot tell the two apart: `build:complete` `touch`es `dist/.build.stamp`
  only after `tsc-alias`, and `build:ifstale` (`package.json:79`) reads the stamp's mtime alone —
  there is no *"a build is in flight"* state, only *fresh* and *stale*
- `build:clean` `rm -rf dist/` opens a second, louder window of the same kind

what is **not** established: which process held the build at `08:05`. the window is proven from
the scripts and the stack; the writer is not. so the fix is to close the window, never to hunt
the one writer.

## .the shape of the fix

build to a scratch dir, then swap — so `dist/` is only ever whole:

```
build:compile:tsc  → tsc -p tsconfig.build.json --outDir dist.next
                     && tsc-alias -p tsconfig.build.json --outDir dist.next
build:complete     → write dist.next/package.json, touch dist.next/.build.stamp,
                     then `mv dist dist.prev && mv dist.next dist && rm -rf dist.prev`
```

the same temp-then-rename shape `setFileAtomic` and `build:compile:bun:run` already use
(`package.json:75` builds to `.next.bc`, then `mv -f`). a reader in the swap window sees the old
whole `dist/` or the new one, never a half-aliased one.

clamp: a test that spawns `bin/run.jit` while a build runs, and asserts exit 0 — or, cheaper, an
assertion in the acceptance global setup that `dist/` holds no `@src/` specifier, so a broken
`dist` fails once, named, instead of N tests with a stack.

## .why it is not done in this round

the wish is the brain-dir boot transport; the build pipeline is neither its subject nor its
seam. the flake costs a re-run, it is loud, and it never reaches a consumer — the published
package ships a `dist/` built whole. it belongs with the other build-pipeline items seeded
upstream (`declapract-typescript-ehmpathy#622`, the `build:ifstale` work), not in this tree.
