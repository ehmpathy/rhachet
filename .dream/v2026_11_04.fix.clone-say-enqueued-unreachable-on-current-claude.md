- kind = fix
- owner = ehmpathy/rhachet, clone socket + screen read
- caught 2026-11-04

## .the cue that fired

ehmpathy/rhachet#706 at 7c1d8cb: the realbrain shard went red on
`clone.transcript-lag.realbrain` (A1) and `clone.screen-dogfood.realbrain`. on the rebased head
both suites sit behind `BRAIN_LIVE_SCOPE=all` (main, #649), so cicd skips them and the red no
longer shows.

## .the gap, precisely

- run with the gate open on a live credential, A1 fails in 11s: M2's say prints the plain
  success head `😶🎙️ said to @:<serial>`. no degrade leaf, so the probe ANSWERED, and its screen
  read found no queue
- the same run passes `the queued second message rendered on the pty screen`, so the brain did
  hold M2
- ⇒ the queue read (`computeCloneInputState`, the `❯ Press up to edit queued messages` hint)
  does not see a queue the current claude cli renders. the hint text or its dim style likely
  moved past v2.1.87, the build it was measured on
- #649 gated the suites as "a spent anthropic credit"; with a live credit the red is real, and
  `enqueued` is unreachable for every busy real clone (vision R3)

## .the shape of the fix

1. `rhx claude.cli.probe` the host's claude version; `rhx claude.cli.strings --pattern 'queued'`
   to find the current hint text
2. capture a queued screen on that version (screen-dogfood [t0] does it) and fix the hint match
   in `computeCloneInputState`, with a unit clamp on the new grid
3. run A1 and screen-dogfood with `BRAIN_LIVE_SCOPE=all`; both green

## .why it is not done in this round

#706 is the peer-cred lookup timeout. the queue read is a separate surface: this PR's diff
leaves the verdict and the screen read untouched (it adds only the `probe-unanswered` degrade,
and A1's say showed no degrade), and main gates the suite off cicd. a run on a clean main
checkout would confirm the attribution; it was not made. a fix here would ride a scope the commander did not review.
