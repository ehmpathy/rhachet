## .the cue that fired

`rhx init --roles -xyz` was meant to drop `xyz` from the `prepare:rhachet` entry in `package.json`.
`.behavior/v2026_07_07.fix-rhx-init` asked, as vision open question 6, *"should incremental interact
with `--keys` / `--hooks` / `--prep`?"* — and marked it answered from code: *"they compose with
whatever set the incremental step produces"*. its execution yield then logged *"`--keys`/`--prep`
narrows to `adds` in incremental mode"* as *"⚠️ by design"*. so the removal unlinks `xyz`, and the next
install links it back. every test stayed green: none held the requirement, because the route never
wrote it down as one.

the wisher, 2026-10-02: *"i cant believe that clamp got lost"*.

## .what the behaver lacks

the route carries requirements as prose in a wish and a vision. no stone itemizes them, so:

- a requirement can be answered away by a read of the code — code shows what IS, never what was asked
- a review checks the diff against the vision's prose, never against a list it can tick off
- once the behavior closes, its requirements leave with it; the next behavior on the same surface never
  sees them

## .the fix — teach the behaver

1. **itemize.** each wish and each vision ends with a numbered list of behavioral requirements — each an
   observable behavior, in the words a user would check it by. an open question about a behavior is
   answered by the wisher, never closed from code
2. **inventory.** each requirement lands in the repo's durable inventory — rhachet's shape:
   `.agent/repo=.this/role=any/briefs/behavior/inventory.of=requirements._.md` plus one
   `inventory.of=requirements.case=<n>.<slug>.md` per entry (requirement · clamp · proof · source ·
   status `owed` | `proven`). the inventory outlives the behavior
3. **prove.** the execution stone's guard checks that every itemized requirement maps to a proof test
   cited by path; a requirement with no proof is `owed`, and an owed requirement blocks passage
4. **never drop.** ship the rule `rule.forbid.dropped-behavioral-requirements` with the role: a
   requirement narrows or leaves only by the wisher's amendment
