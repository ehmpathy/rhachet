# 🌙 dream: one spec, two ref rosters — the count turns on the ARM that boots it

- **kind** = fix
- **owner** = `ehmpathy/rhachet` (this repo)
- **caught** = 2026-09-24, mid-`5.1.execution`, while a ref-dominated fixture was sized

---

## .the cue that fired

a fixture was built to breach its cap on the strength of its **ref roster**. sized against
`roles cost --what <path>` at the repo root, the roster measured **149 tokens**. the identical
spec, booted in a temp repo by `roles cost --repo .this --role any`, reported **`0 ref`** and no
roster at all.

the fixture was then re-shaped and the case landed green, so the sizing problem is closed. **the
asymmetry it surfaced is not.**

---

## 🔴 .the gap, precisely

three measurements, one spec file, three different answers:

| # | invocation | the spec's own `briefs.ref` | reported |
|---|---|---|---|
| 1 | `roles cost --what …/boot.sayonly.yml` (repo root) | 🔴 **declared NONE** | `2 say · 1 ref` — `briefs.ref` = **149** |
| 2 | `roles cost --what …/boot.yml` (repo root) | `refs/**/*.md` | `2 say · 1 ref` — `briefs.ref` = **149** |
| 3 | `roles cost --repo .this --role any` (temp repo) | `refs/**/*.md` | 🔴 **`2 say · 0 ref`** |

⇒ **rows 1 and 2 disagree with the SPEC** — a manifest that declares no `ref` at all still
emitted, and still paid for, a 149-token roster. **rows 2 and 3 disagree with EACH OTHER** — the
same file, the same role dir, the same glob, and a roster in one arm and none in the other.

🔴 **the budget consequence is the part that matters.** the gate counts the full emitted payload,
so a spec can be **under its cap at one gate and over it at another**, with no edit between. that
is precisely the class of silent divergence requirement 2 exists to forbid, at a seam no case in
the suite currently crosses.

🟡 **row 3's roster returned once the ref files moved from `role=any/refs/` to
`role=any/briefs/refs/`.** so the role arm appears to reach only beneath `briefs/`, which is where
every real spec happens to put them — which is exactly why no extant fixture could catch this.

## 🔴 .DIAGNOSED 2026-09-24 — the mechanism is DECLARED, in two docblocks, with a stated reason

**raised at `5.1.execution` i026 by `enroll-impl-arch-defects`**, which ranked the diagnosis above
the directory split and called this *"a correctness bug in the budget's core promise."* the
diagnosis half is SAFE ✅ / CLEAN ✅ — a read changes no code — so it was taken on contact
(`rule.always.fix-forward-under-scouts-honor`).

⚠️ **the cause is READ rather than inferred**, which is what
`rule.forbid.mechanism-inferred-from-outcome` asks for. one predicate carries the whole
divergence — `getAllBriefCandidateFiles.ts:25-28`:

```ts
const isWithinUniverse = (path: string): boolean =>
  source.dirBriefs
    ? path.startsWith(source.dirBriefs)            // ROLE arm — the briefs/ subtree ALONE
    : path !== source.pathToReadme                 // MANIFEST arm — EVERY neighbor,
      && !path.startsWith(source.dirSkills);       //   minus the readme and the skills dir
```

and `BootSource.ts:32-37` states the split outright:

> the dir that carries brief candidates, **or null when the whole `rootDir` does**
> `.note` = **null is the manifest case.** a route dir has no `briefs/` subdir and globs files
> that sit directly beside the spec — so a `briefs/` requirement would render it empty

### each row, explained

| row | why |
|---|---|
| **3** — `0 ref` | role arm ⇒ `dirBriefs` is set ⇒ universe is the `briefs/` subtree **alone**, and the fixture's files sat at `role=any/refs/`, outside it. 🔴 **the dream's own control proves the predicate**: the roster returned the moment they moved to `role=any/briefs/refs/` |
| **1, 2** — `149` even with **no** declared `ref` | manifest arm ⇒ `dirBriefs` is null ⇒ universe is **every neighbor**. the say/ref partition then assigns each in-universe file the spec did not match to `ref` — so a spec that declares no `ref` key still emits, and pays for, whatever sits beside it |

### 🔴 what the diagnosis CHANGES

> **this is not one defect. it is two DECLARED behaviors whose composition surprises.**

neither half is an accident, and each has a reason on the page: the asymmetric universe exists
because a `briefs/` requirement would render every manifest empty; the ref-by-default partition is
`computeBootPlan`'s documented *"say matched, ref unmatched"*.

⇒ **so no mechanism hunt remains, and the residual work SHRINKS.** what stands is step 2 alone —
the **contract** question — and it was already reserved for the wisher. the arm divergence is a
consequence of that contract rather than a bug beneath it.

⚠️ **and one claim in the original cue is now too strong.** *"rows 1 and 2 disagree with the SPEC"*
reads as a violation; they agree with the spec **as this codebase defines a spec**, where an
undeclared in-universe file is a `ref` by default rather than an exclusion. whether that default is
right is exactly step 2.

## .the shape of the fix

1. ~~**diagnose** which code path emits the roster in each arm~~ 🔴 **DONE 2026-09-24** — one
   predicate, `getAllBriefCandidateFiles.ts:25-28`, and it is declared behavior. see above
2. **settle the contract question the rows raise**: may a resource the spec never declared enter
   the payload — and therefore the budget — at all? row 1 says it does today
3. **make the two arms agree**, whichever way (2) settles — 🟡 and note the cost of *"just require
   `briefs/` in both"*: `BootSource.ts:34-36` says it renders every manifest empty, so the
   symmetric repair is the one that cannot be taken
4. **clamp it** with the case no fixture has: one spec, booted by BOTH arms, asserted to report the
   same batch counts and the same total. that is a cheap, race-free, fixture-constructible clamp

---

## .why it is not done in this round

**it fails CLEAN, not SAFE-versus-large** (`rule.always.fix-forward-under-scouts-honor`). the
repair reaches the shared render path every extant boot flows through — the one path requirement 4
pins byte-identical — so it ripples into snapshots across four acceptance suites and two
integration suites, none of which this stone's diff otherwise touches.

⇒ and step 2 is a **contract** question rather than a mechanical one: whether an undeclared
resource may be budgeted is a call about what `budget.tokens` means, adjacent to `F41`'s open
wisher question about whether a ref line should be budgeted at all. to settle it inside an
execution stone would settle by side effect a question the wisher reserved.

🟡 **it predates this behavior, and is not a regression this stone introduced.** the budget gate
made it *visible* by giving the payload a number that refuses — it did not create the divergence.
