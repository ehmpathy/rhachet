# 🌙 dream: the input-state classifier is color-blind, so a greyed placeholder suggestion reads as a dirty box

- **kind**: fix
- **owner**: ehmpathy/rhachet (this repo)
- **caught**: 2026-09-16
- **scope**: PRIOR behavior (the screen feed + classifier), a KNOWN-LIMIT peer of the modal
  over-match (F11) and the soft-newline dream — outside this wish's read-channel scope

## .the cue that fired

the full acceptance run failed 4 tests in `blackbox/cli/clone.joker.realbrain.acceptance.test.ts`
(a PRIOR #465 realbrain conversation, unchanged in this PR). every failure was a turn-3+ `say` that
returned exit 2 / `verdict: withheld` / `reason: input-region-dirty` against a live haiku v2.1.87
joker. two runs disagreed — one 2 failures, one 4 — the signature of a nondeterministic screen read.

the failure diagnostic captured the brain's own screen at the refusal moment. the LIVE input box
(between the last two full-width `─` rules) was EMPTY — `❯ ` plus a cursor. below it, claude v2.1.87
drew a CONTEXTUAL greyed placeholder suggestion — `Another joke?` — as a dim hint, the way it
proposes a likely next turn after a reply.

## .the gap, precisely

`computeCloneInputState` classifies the input band's content as `clear` only when it is empty or
matches `INPUT_PLACEHOLDER_MARKERS` — today a single shape, `/^Try ["“][^"”\n]*["”]$/` (the generic
empty-box hint measured in the F-series dogfood). claude ALSO draws contextual suggestions
(`Another joke?`, and others that vary per conversation), which do not match that shape.

the deeper cause is that the read is **color-blind**: `genCloneScreenFeed` renders the grid with
`translateToString`, which drops SGR attributes. the greyed suggestion is drawn with `\x1b[2m`
(dim) — the one signal that would part a claude-drawn hint from a human's typed text — and that
signal is gone by the time the classifier sees the row. so `Another joke?` reads as literal box
content, non-empty and non-placeholder → `dirty` → the pre-check withholds with `input-region-dirty`.

this is the classifier's DOCUMENTED fail-safe (`computeCloneInputState.ts:86` — "unsure → dirty,
which refuses safely and is forceable"), so it is design-correct, not a prod defect: given only the
literal string, a dim suggestion is genuinely indistinguishable from a human mid-type, and a refusal
(forceable) is the safe call. but the effect is that a daemon that drives a multi-turn conversation
with a real claude gets `withheld` on any turn where a contextual suggestion is on screen, unless it
dispatches with `--force`.

evidence: `.log/role=mechanic/skill=git.repo.test/what=acceptance/2026-09-16T03-44-29Z.stdout.log`
lines 113-206 — the `⛈️` diagnostic, the `input-region-dirty` json, and the raw screen that shows an
empty `❯` box above the dim `Another joke?` suggestion.

## .the second symptom — it also makes `enqueued` unreachable, not only `withheld`

caught 2026-09-16 at the 5.3 verification gate, by a live self-dogfood against a clone enrolled on
this build (serial `42dfc607`). three consecutive dispatches, each with a distinct needle (one with
an em-dash, one plain ascii, one fed via stdin so the needle never rendered in the command line):

| # | needle | verdict | probe | delivered | the message arrived? |
|---|---|---|---|---|---|
| 1 | `dogfood ping v2 — ignore` | `absent` | `capable` | true | **yes** — it landed as a live turn |
| 2 | `plainascii probe alpha` | `absent` | `capable` | true | **yes** |
| 3 | `bddbf3889cbb…` (git sha, via `@stdin`) | `absent` | `capable` | true | **yes** |

`probe: capable` proves the feed is live and the read channel answered. so this is NOT `unreadable`
— the screen WAS read, and the read did not support `enqueued`.

`isCloneSayEnqueuedShape` demands all three: `focus === 'input'` **and** `input === 'clear'` **and**
`countOnScreenRose`. a box that reads `dirty` at OBSERVE time fails the second conjunct, so the
verdict falls past `enqueued`, past `buffered` (the needle is not in the box), and lands on the
`absent` residual — a **failure channel, exit 1, on a message that demonstrably landed**, which is
the R1 defect class this wish exists to kill, one surface over.

the sequence that produces it:

1. baseline probe — box `clear`, so the counts are measured (not null)
2. dequeue pre-check — box still `clear`, so the write proceeds and acks `delivered: true`
3. the brain takes the message into its queue and re-renders
4. claude draws a contextual greyed suggestion into the now-empty box
5. observe probe — `input: 'dirty'`, so the enqueued shape fails → `absent`

⚠️ **a rival cause is not excluded.** the same `absent` is produced if `countOnScreenRose` is false
instead — the sliding-frame residual already clamped at `computeCloneInputState.ts:169-175` (the
viewport window advances as the turn writes rows, so a needle can scroll off the top between the
baseline and the post read). both causes collapse to the identical residual, and **the CLI cannot
part them**: `say` reports the verdict, never the classification it was computed from.

⇒ that inability IS fulcrum F15's cost, measured. with no read surface for the input state, a human
who holds a clone that returns `absent` has no instrument to ask *"what does my clone's screen say
right now?"* — so the diagnosis stalls exactly where it did here.

**the measurement that parts them**: one probe reply captured at observe time (`focus`, `input`,
`countInInput`, `countOnScreen`) against a live busy session. `input: 'dirty'` → this dream's cause;
`input: 'clear'` with `countOnScreen` flat → the sliding-frame residual. either way the fix below
(an attribute-aware band read) is owed, and F15's read surface is what makes the next one diagnosable
in one command rather than six.

## .the shape of the fix

1. make the screen feed attribute-aware for the input band — retain the dim (`\x1b[2m`) flag per
   cell (or per row) rather than flatten it with `translateToString`. `@xterm/headless` exposes cell
   attributes on `buffer.active.getLine(y).getCell(x)` (`.isDim()`), so the band read can ask whether
   the box content is DIM (a claude-drawn placeholder → `clear`) or BRIGHT (a human's typed text →
   `dirty`).
2. with a dim-aware read, `INPUT_PLACEHOLDER_MARKERS` collapses to "an all-dim band is `clear`" — the
   whitelist need not enumerate every contextual suggestion string, and a daemon no longer has to
   `--force` past its own brain's hints.
3. re-run the joker realbrain conversation WITHOUT `force: true` and assert it round-trips green.
4. clamp with a unit case in `computeCloneInputState.test.ts`: a band whose content is all-dim →
   `input: 'clear'`; a band with bright content → `input: 'dirty'`.

## .why it is not done in this round

- it is a change to PRIOR prod behavior — the screen feed (`genCloneScreenFeed`) and the classifier
  (`computeCloneInputState`), both wish-adjacent surface but NOT the read-channel contract this wish
  ships. an attribute-aware feed ripples into the whole grid read and every classifier case, so it
  wants its own PR + a fresh dogfood measurement of which cells claude marks dim, per the adapter-seam
  discipline (`define.pty-stream-vs-screen`).
- it fails the CLEAN test (`rule.always.fix-forward-under-scouts-honor`): the dim-vs-bright geometry
  of v2.1.87's placeholders is unmeasured this session, and a feed change touches the surface every
  green deterministic + realbrain test rests on.
- the wish's shipped contract is unaffected and fully green: the pre-check's `withheld`/dirty behavior
  is design-correct and forceable, and a daemon-owned box (no human) forces past its brain's own
  suggestion exactly as the shipped consumer contract prescribes. the joker conversation is retargeted
  to dispatch with `force: true` (the faithful daemon path) so the gate is honest without a color-aware
  feed — the same move Q10 took (retarget the probe, dream the prior-behavior fix).

## ✅ RESOLVED 2026-09-18 — all four steps discharged, in this stone

the deferral above rested on one premise: *"the dim-vs-bright geometry of v2.1.87's placeholders is
unmeasured this session."* that premise was then **removed** — the geometry was measured against a
live peer, so the feed change became designable and landed here rather than in a follow-on PR.

| step | state | what closed it |
|---|---|---|
| 1 — an attribute-aware feed for the input band | ✅ **done** | `genCloneScreenFeed.asBrightOnlyRow` — a per-cell `isDim()` read, emitted as a second `linesBright` grid beside the full one |
| 2 — collapse the marker whitelist to "an all-dim band is `clear`" | ✅ **done** | the classifier reads the bright-only band, so no contextual suggestion string needs enumeration |
| 3 — the joker conversation re-run WITHOUT `force` | ✅ **done** | all 5 turns dispatch unforced against a real claude, and the suite is green: **19 passed, 0 failed, 139s** |
| 4 — a unit clamp: all-dim → `clear`, bright → `dirty` | ✅ **done** | `[case2b]` + 4 classifier tests, mutation-proven red under the flattened read |

### 🔴 the measurement found a defect step 1 could not have anticipated

step 1 proposed a dim read **per cell or per row**. a per-row read would have been defeated outright,
and the per-cell read was defeated once too:

- a tui paints a legible block cursor by **re-emission of the character under it at default
  intensity**
- so exactly ONE cell of an otherwise-dim ghost row comes back BRIGHT
- ⇒ `contentBright` was `'s'` — length 1, non-empty — so the band read `dirty` and the peer was
  re-deafened by the very cure meant to hear it

⚠️ **`@xterm/headless` is a parser with no renderer, so it composites no cursor into a cell.** the
bright cell is the brain's own bytes, which is why no emulator option can suppress it. the cure
blanks the cursor-painted cell on **POSITION** rather than on intensity, and the cursor's absolute
row is `buffer.baseY + buffer.cursorY` (`cursorY` is viewport-relative — a raw `cursorY` blanks a
cell in the wrong row once the scrollback grows).

**measured live**, one clone each side of the cure, same cursor position:

| clone | cursor | the bright row it read | verdict |
|---|---|---|---|
| `@:dim1` (pre-cure) | `(x:2,y:18)` | `❯ s` | `withheld` |
| `@:ghost2` (post-cure) | `(x:2,y:18)` | bare `❯` | `released` |

⇒ so a dim-aware feed is necessary and was not sufficient.
