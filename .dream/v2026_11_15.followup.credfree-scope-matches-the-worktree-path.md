# 🌙 dream: a credfree --scope must not match the worktree's own path

- kind = followup
- owner = rhachet (`.agent/repo=.this/role=any/skills/test.acceptance.credfree.sh`)
- caught 2026-11-15

## .the cue that fired

`rhx test.as.ci test.acceptance.credfree --scope 'brains.auth'`, run in the worktree
`rhachet.beav.feat-brains-auth-use-get-set`, ran all 158 acceptance suites, not one. a scoped run
became a full local sweep, which `rule.forbid.local-full-test-sweeps` refuses, and no line warned.

## .the gap, precisely

- the skill passes `--scope` to jest as `--testPathPatterns <scope>`
- jest matches that regex against each test file's ABSOLUTE path
- a worktree is named after its branch, and a branch is named after its feature. so a scope that
  names the feature matches the worktree dir, and with it every file under the root
- the run reports no match count up front, so the widened scope shows only after the run ends

the same cause bites `git.repo.test` upstream: `v2026_11_14.reseed.git-repo-test-dotted-scope-matches-the-tier`
(ehmpathy/rhachet-roles-ehmpathy#1343). one fix shape serves both.

## .the shape of the fix

- match the scope against the path relative to the repo root: anchor the pattern after the root,
  e.g. `^<root>/(.*/)?.*<scope>` with the root regex-escaped
- before the run, print the matched-file count (as `git.repo.test` does) and refuse when a scope
  matches every suite in the tier
- a clamp: a temp repo whose dir name holds the scope term, with two acceptance files; assert one runs

## .why it is not done in this round

the fix changes how every caller's `--scope` regex is read, and wants its own clamp and review. the
brains auth PR does not touch the skill's scope path. the workaround for now is a path-prefixed
scope, e.g. `--scope 'blackbox/cli/brains\.auth'`.
