# 🌙 dream: bind the STATIC half of the adhoc corpus through `CLAUDE.md`, per tree

- kind  = feat
- owner = **ehmpathy/rhachet** (this repo) + **ehmpathy/rhachet-roles-bhuild** (the hook it retires)
- caught 2026-09-25

## .the cue that fired

a driver on this route argued a `boot.yml` point from a `grep` of `src`, got it wrong, and was told to
read the blueprint and the vision. it had read neither — and the reason was not negligence alone:

> the `sessionstart.boot-behavior` hook emitted **108,425 bytes**. the brain received **~2,048** — a
> preview — plus a file path. **~2% of the corpus arrived.**

the design question then asked: whether the adhoc corpus could ride `CLAUDE.md` as the role corpus
now does, keyed per tree rather than per actor — perhaps a dir scanned per tree for brain binds per
role.

## .the measured defect

```
SessionStart:compact hook success: <persisted-output>
Output too large (102.3KB). Full output saved to: …/hook-9ebc4a4d-…-stdout.txt
Preview (first 2KB):
💪 init role repo=bhuild/role=behaver/init=claude.hooks/sessionstart.boot-behavior
==================================================
BOUND BEHAVIOR: v2026_09_22.feat-boot-briefs-into-claude-md
==================================================
<behavior scope="wish" path=".../0.wish.md">
```

what landed was the header and the start of `0.wish.md`. the **vision** and the **blueprint** — the two
artifacts a driver is told to read first — sat in the 106KB that did not.

⚠️ **the truncation is silent to the reader who needs it.** the line says `hook success`; the byte count
is a parenthetical beside that word. no row says *"98% of this is elsewhere"*.

## 🔴 .the gap, precisely — D1's `adhoc` position holds TWO change rates, and the vision collapses them

`1.vision.experience.dimensions.md` D1:

| position | binds at | changes mid-session | transport layer |
|---|---|---|---|
| `role` | clone enrollment | ❌ never | layer 2 — `<brainDir>/AGENTS.md`, cached prefix |
| `adhoc` | route progression | ✅ on purpose | layer 3 — conversation, append-only |

**invariant 2** bars `adhoc` from the cached prefix: *"a mid-route rewrite of a prefix file is
cache-hostile whether or not it is inert, and a re-read that lands at an unpredictable moment is worse
than one that never lands."*

🔴 **that argument is sound and it reaches only half of what `adhoc` names:**

| half | what it is | changes | delivered by | prefix-safe? |
|---|---|---|---|---|
| **the behavior corpus** — wish · vision · blueprint · criteria | static for the route's life; moves only when a human edits an artifact | rarely, and **out of session** | `boot-behavior`, on SessionStart | ✅ **yes** |
| **the route position** — the live stone, the guard's halt | on every stone passage | constantly, **in session** | `route.drive`, on Stop | 🔴 no — invariant 2 binds here |

the volatility invariant 2 rests on belongs to the **second** row. the first row is `role`-like: bound
once at route-bind, static thereafter.

### and the two channels already refresh at the SAME moments

| channel | when it refreshes |
|---|---|
| `CLAUDE.md` | session start · **re-read from disk after `/compact`** · re-injected on `--resume` |
| an `onBoot` hook with no filter ≡ `SessionStart` | **new session + compaction** |

⇒ **identical cadence.** so no delivery-cadence argument keeps the static corpus on stdout. what the
hook buys over `CLAUDE.md` is naught; what it costs is a size cap that truncates at 2%.

## .the shape of the fix

### 1. render the static corpus to a file, and reference it from the door

the pattern this route just built for briefs, reused verbatim: render the behavior corpus to a file and
let the door reference it. a file read has no stdout size cap, and an `@`-reference keeps the door small.

### 2. 🔴 the per-tree grain — the open question, and it is a THIRD grain

`catalog.of=actor-clone-design` gives one test for placement:

> **"does this derive from `{ brain, roles }`, or from THIS RUN?"**

for a behavior corpus the answer is **neither**. it derives from the **tree** — the worktree and the
branch bound to it (`.behavior/$slug/.bind/$branch.flag`). so:

| grain | owns | the behavior corpus? |
|---|---|---|
| **actor** | what derives from `{ brain, roles }` | ❌ no — two actors in one tree share one bound behavior |
| **clone** | what derives from this run — serial, transcript, socket | ❌ no — it outlives every clone in the tree |
| 🔴 **tree** | what derives from the worktree + its branch | ✅ **this, and the model does not name it** |

🔴 **a correction, measured after this was first written: the actor DIR is already tree-local, so it is
a legal home.** the claim here was that an actor is reachable from many trees, so a tree-bound corpus in
the actor dir would leak into another tree's clones of the same actor. `.agent/.actors/.gitignore` refutes
it — `/*` plus an allowlist of `.gitignore` and `actor.via.slug=.default/` — so every actor dir but the
default is untracked and never crosses a tree, and the default's own `boot.md` is gitignored beside it.

⇒ the **tree** grain is real, and the actor dir already expresses it. `rule.forbid.per-clone-config`
stays satisfied for the reason that matters: the corpus derives from the tree, never from a clone's run,
so it belongs to the actor rather than under `clones/`.

⇒ so a per-tree dir for brain binds names a real absent grain. the open sub-questions, stated rather
than guessed:

- **where** — a per-tree dir (`.agent/.binds/` ?) beside `.agent/.actors/`, or under the extant
  `.behavior/$slug/.bind/`, which already keys by branch
- ✅ **per role, or per tree? — ANSWERED: per ACTOR.** the peer dream's `rhx boot set --manifest $x
  --for @<actorSlug>` settles it. the key is **tree × actor**, and both halves are already on disk: the
  tree by the untracked actor dir, the actor by its hash or slug. an actor, rather than a role, is the
  grain because the door itself is per actor (`<actorDir>/brain/.claude/AGENTS.md`)
- **how the door composes two sources** — the actor's role corpus and the tree's bind corpus must both
  reach one clone. `AGENTS.md` holds one `@boot.md` today; two refs, or one rendered union?
- ✅ **what a bare clone gets — ANSWERED by the same flag.** `--for` omitted binds the **default** actor,
  whose brain dir *is* `<repo>/.claude` (`define.brain-dir-repo-vs-actor`), which D5's `bare` position and
  S13's ancestor walk already reach. so a bare clone inherits the tree's bind exactly when a human omits
  `--for` — a decision at the keyboard rather than an accident in the resolver

### 3. leave the live stone where it is

`route.drive` on Stop is the correct transport for the volatile half, and invariant 3 (*"an append
cannot bust a prefix"*) holds it up untouched. **this dream does not move it.**

## .why it is not done in this round

- the route is at `5.5.playtest`, halted on human approval. a corpus-transport change is neither SAFE
  nor CLEAN at the final gate
- the fix spans **two repos**: the render and the door are this repo's; the hook it retires is
  `rhachet-roles-bhuild`'s (`rule.always.scope-onetime-lessons-to-the-behavior`)
- 🔴 and the **third grain is a real model extension**, not an implementation detail. it wants a
  `define.` brief and a verdict on the four sub-questions above before a line is written

## .the lesson beneath it, for a durable rule

> **an instruction corpus delivered through a channel with a size cap is not delivered.** the cap is a
> property of the channel; the corpus grows with the work. so past a bound it does not control, a
> transport must reference rather than inline.

⇒ this route proved that claim once, for briefs. the behavior corpus is the second instance, and it was
live the whole time the route repaired the first.
