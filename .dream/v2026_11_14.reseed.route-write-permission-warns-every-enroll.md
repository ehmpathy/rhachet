- kind: reseed
- owner: the role package whose init writes `Write(.route/**)` into `settings.of.repo.json` — most
  likely bhrain's driver (it sits beside the `route.*` hooks); confirm before the dispatch
- caught 2026-11-14

## .the cue that fired

a dogfood walk of `rhx enroll` printed, on every spawn (verbatim):

```
Permission allow rule (.agent/.actors/actor.via.hash=2e77f741/brain/.claude/settings.of.repo.json): Write(.route/**) is not matched by file permission checks — only Edit(path) rules are. Use Edit(.route/**) instead (Edit rules cover all file-editing tools).
```

## .the gap, precisely

claude (2.1.280 here) no longer reads `Write(path)` as a file permission rule; only `Edit(path)`
covers file edits. the rule is dead weight, and claude says so in yellow on every clone boot — a
friction every human sees and none can act on from rhachet. the same file already carries
`Edit(.route/**)`, so the `Write` twin can simply go (and its `Write(*/**/.route/**)` peer with it).

## .the shape of the fix

in the owner role's init: drop the `Write(<path>)` allow entries that have an `Edit(<path>)` twin.
then `rhx init` re-derives every actor's file, and the yellow line no longer prints.

## .why it is not done in this round

the rule is written by a role package, not by rhachet's enroll; this route fixes attribution only.
