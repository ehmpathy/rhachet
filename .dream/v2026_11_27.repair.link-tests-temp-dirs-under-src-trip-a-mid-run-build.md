# 🌙 dream: the link tests' temp dirs under `src/` trip a mid-run rebuild of `dist/`

- kind = repair
- owner = rhachet
- caught 2026-11-27

## .the cue that fired

an integration run scoped over `enroll.mods` and `execRoleLink` / `execRoleUnlink` together failed 44 tests with `Cannot find module '@src/infra/git/getGitRepoRootOrNull'` from `dist/`. each group passes alone.

## .the gap, precisely

- `execRoleLink.integration` and `execRoleUnlink.integration` make their temp dirs with `genTestTempDir({ base: __dirname })`, so each run writes files under `src/domain.operations/invoke/link/.temp/`
- `build:ifstale` (package.json) rebuilds when `find src … -newer dist/.build.stamp` finds a file; it excludes `*.test.ts` and `*.snap`, but not `.temp/`
- `test.acceptance.credfree.integration` invokes the credfree skill, which runs `build:ifstale`. with the link tests' temp files present, it runs `build:inplace` over the real `dist/` while other suites spawn the cli
- a cli spawned mid-build loads a `dist/*.js` that tsc wrote and tsc-alias has not rewritten yet, so an `@src/` import is unresolved

## .the shape of the fix

either, or both:
1. the two link tests take a temp base off `src/` (`genTempDir` from test-fns), per `rule.forbid.adhoc-gentempdir-reimpl`
2. `build:ifstale` adds `-not -path '*/.temp/*'` to its `find`

## .why it is not done in this round

- fix 2 edits `package.json`, which this route must leave alone
- fix 1 touches two test files no change in this branch reaches, and the defect predates the branch: it surfaces only when a run mixes those suites with the credfree skill test. the proof for this route runs the groups apart
