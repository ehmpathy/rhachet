dream = keyrack set auto-ensures the org's AWS_PROFILE is unlocked before the reference roundtrip-verify

## .what

when `keyrack set --vault aws.params` stores a `PERMANENT_VIA_REFERENCE` key for a *specific*
org, the set path already roundtrip-verifies the reference — which needs that org's AWS
identity. today, if the org's SSO session is expired, set fails with a blocked report that
now names the fix (`rhx keyrack unlock --owner <owner> --env <env>`). the human must run that
unlock by hand, then re-run set.

the dream: set auto-ensures the org's `{org}.{env}.AWS_PROFILE` peer key is unlocked *itself*,
before the roundtrip-verify — so the human runs one command, not two.

## .why

- the failure is a two-step dance the machine could collapse to one (rule.require.fewer-paths-via-idempotency spirit)
- set already knows the org, the env, and the peer profile slug — it has all it needs to unlock
- a pit-of-success: the common case (i want to store a reference, my session lapsed) just works

## .the machinery already exists

- `getOneKeyrackAwsParamOrgProfile` — derives the `{org}.{env}.AWS_PROFILE` peer slug (or null for `@all`/non-aws.params)
- `unlockKeyrackKeys` — the extant unlock operation set could chain on that peer slug
- so the shape is: before roundtrip-verify, if org is specific and profile peer exists, `unlockKeyrackKeys` the peer slug, then proceed

## .the caveats (why it was kept as-is for now)

1. **crosses the deliberate set/unlock separation** — today set does not launch credential flows;
   it assumes creds are ready. auto-unlock folds an unlock into set.
2. **makes set potentially interactive** — an expired SSO session means auto-unlock launches
   an AWS SSO login (browser/device flow) mid-set. set stops being a quiet, non-interactive op.
3. **verification needs a foreman/SSO session** — end-to-end proof requires a real org profile
   with a live-or-launchable SSO, which the test box lacks; so this is not a quick unit-test win.

## .decision

kept as-is on 2026-08-03. current behavior: set fails fast with a blocked report that names
the exact unlock command. this dream captures the upgrade for a later pass once the
interactive-set + foreman-verification tradeoffs are worth the collapse.
