# 🌙 dream: flip two pin-bound integration tests when the role packages bump

kind = reseed (this repo, the PR that bumps `rhachet-roles-ehmpathy` ≥ 1.40.0 and `rhachet-roles-bhrain` ≥ 0.42)
owner = whoever lands the bump
caught 2026-10-26, on `beav/fix-init-never-writes-outside-repo`

## .the cue that fired
5.3 verification ran integration on a box whose `node_modules` held newer role packages than
`package.json` pins (an uncommitted local bump). three tests went red that are green in CI on the
committed pins (PR #641's three integration shards, all pass):

- `src/contract/cli/invokeInit.integration.test.ts` [case2][t0]: asserts the repo actor's
  `settings.of.repo.json` does NOT contain `"permissions"`. its own comment says this waits on
  ehmpathy/rhachet-roles-ehmpathy#895, a role init that writes `settings.of.repo.json` by name.
  1.40.0 ships #895, so the role's permissions now land there
- `src/.test/defaultPeerReviewerBrain.integration.test.ts` [case1] (two thens): requires
  `rhachet-roles-bhrain/dist/domain.operations/review/DEFAULT_REVIEW_BRAIN.js`, which 0.42.3 no
  longer ships at that path

## .the gap, precisely
both tests pin facts of a dependency version, not of rhachet. the bump that moves those facts must
move the tests in the same PR, or the bump lands red.

## .the shape of the fix
- invokeInit [case2][t0]: flip to `toContain('"permissions"')`, and reword the comment: the role
  init now writes `settings.of.repo.json` by name, so its permissions survive the layout findsert
- defaultPeerReviewerBrain: read the constant from wherever 0.42.x exports it (its package
  `exports` map, never a deep dist path), so a file move inside bhrain cannot break it again

## .why it is not done in this round
the bump is not part of this fix: `package.json` and `pnpm-lock.yaml` stay uncommitted here by
the director's instruction. to flip the tests without the bump would make them red in CI.
