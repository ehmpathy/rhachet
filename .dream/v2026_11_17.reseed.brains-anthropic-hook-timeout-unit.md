# 🌙 dream: the in-repo `_topublish` claude adapter lags the published one on the hook timeout unit

- kind = fix
- owner = rhachet, `src/_topublish/rhachet-brains-anthropic/`
- caught 2026-11-17

## .the cue that fired
the hook-dispatcher execution review compared a settings timeout with a manifest timeout and read
the `_topublish` adapter source as the shipped one.

## .the gap, precisely
the published `rhachet-brains-anthropic@0.4.3` writes a hook timeout in seconds
(`dist/domain.operations/hooks/translateHook.js:41`) and reads it back as `{ seconds }` (`:74`). the
in-repo copy `src/_topublish/rhachet-brains-anthropic/src/hooks/translateHook.ts` still writes
`toMilliseconds(hook.timeout)` (`:40`, `:49`) and reads `{ milliseconds }` (`:101`, `:112`, `:131`),
with tests that pin the ms values. a reader of this repo meets the stale unit first, and one design
round was built on it.

## .the shape of the fix
sync the `_topublish` copy to the published source (or delete the copy if the published repo now owns
it alone): write `Math.round(toMilliseconds(timeout) / 1000)`, read back `{ seconds }`, update its tests.

## .why it is not done in this round
it touches no shipped code path, and the copy's ownership (keep and sync, or delete) is a call for the
adapter's owner, outside the dispatcher pr.
