# 🌙 dream: rhachet-brains-anthropic writes hook timeouts in seconds

- kind = reseed
- owner = rhachet-brains-anthropic (published), whose source is `src/_topublish/rhachet-brains-anthropic/` here
- caught 2026-11-17

## .the cue that fired
the hook-dispatcher execution review compared a moved role hook's settings timeout (`30000`) with its
manifest timeout (`30`) and found two units for one duration.

## .the gap, precisely
`src/_topublish/rhachet-brains-anthropic/src/hooks/translateHook.ts:40-49` writes
`timeout: toMilliseconds(hook.timeout)` into claude settings, and reads it back as
`{ milliseconds: h.timeout }` (`:101`, `:112`, `:131`). claude reads a hook `timeout` in **seconds**,
so a role hook declared `PT30S` ran under a ~30000s limit. its tests pin the ms value
(`translateHook.test.ts:36`, `:62`, `:96`).

## .the shape of the fix
write `Math.round(toMilliseconds(timeout) / 1000)` and read back `{ seconds: h.timeout }`; update the
tests; publish; bump here. with the dispatcher in place, the only role-authored hooks the adapter writes
are the dispatchers, whose timeout rhachet already hands in seconds — so the fix touches each
dispatcher hook's written value and a hand-declared role hook outside rhachet's sync.

## .why it is not done in this round
it is a separate published package, and its read-back unit feeds every sync diff; a change there is a
contract change in its own pr. the dispatcher enforces the declared timeout per rule meanwhile (F7).
