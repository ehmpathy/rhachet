# 🌙 dream: remove the D8 birth-time branch from `asCloneConfigDir`

- **kind** = chore
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-24

## .the cue that fired

roadmap p3 `[r011]`: D8 routes a clone to `~/.claude` when it was spawned before its actor's brain
dir was born. that branch exists only for clones alive across the upgrade that ships brain dirs, so
it has a natural end date.

## .the gap, precisely

`src/domain.operations/clone/asCloneConfigDir.ts` compares `spawnedAt` against the brain dir's
birth time, and `getCloneConfigDir.ts` returns `~/.claude` when the brain dir is absent. once every
live clone postdates its brain dir, both branches route no real clone, yet each read still pays a
`statSync` and each reader still has to reason about two config dirs.

checkable once the trigger fires:

```
rhx clone list    # every live clone's spawn time postdates the release that shipped brain dirs
```

## .the shape of the fix

1. `getCloneConfigDir` returns `getBrainOndiskDir({ actorDir })`, no stat, no home
2. delete `asCloneConfigDir` and its unit test
3. drop `getCloneConfigDir.integration` case1 (absent brain dir → `~/.claude`); keep case2
4. `invokeClone.integration` case8 stays as the clamp that `clone get` reads the brain dir

⚠️ a clone older than the release that shipped brain dirs will then read an empty history. that is
the accepted cost, and the reason the trigger waits two minor versions.

## .why it is not done in this round

- **SAFE?** 🔴 no. clones alive across this very upgrade still write under `~/.claude`; removal now
  empties their `clone get` output.
- **CLEAN?** ✅ yes, and that is why the fix above is three small steps.

⇒ unsafe now, safe later. the defer is a matter of time, not of design.

## .the revisit trigger

the first release two minor versions past the one that ships brain dirs (e.g. ships in `1.48.x` →
remove in `1.50.0`).
