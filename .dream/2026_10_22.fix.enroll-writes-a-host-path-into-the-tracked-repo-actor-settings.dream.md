# 🌙 dream: enroll writes a host path into the repo actor's tracked settings

- kind  = fix
- owner = ehmpathy/rhachet (`src/domain.operations/enroll/genBrainCliConfigArtifact.ts`)
- caught 2026-10-22, by `.behavior/v2026_10_21.feat-enroll-role-subject-focus` (stone 5.1, i004
  r011 blocker.5)

## .the cue that fired

the l3 arch lane found `claudeMdExcludes: ["/home/vlad/.claude/CLAUDE.md", ...]` in
`.agent/.actors/actor.via.repo=ambient/brain/.claude/settings.of.repo.json` — a tracked file —
after a local `claude` (an enroll into the repo actor) ran in this worktree.

## .the gap, precisely

- `genBrainCliConfigArtifact` sets `claudeMdExcludes` on the actor's `settings.of.repo.json` at
  every spawn, with the home dir expanded (`asClaudeMdExcludesOutsideDirs`)
- for a hash or slug actor that file is untracked, so the host path is harmless
- for the repo actor (`actor.via.repo=ambient`) the same file is TRACKED, so every local enroll
  dirties it with a path that names one human's home dir, and a careless commit ships it
- the same code is on main; this branch only caught it in a diff

## .the shape of the fix

either:
- write a host-neutral form (`~/.claude/CLAUDE.md`, if claude expands `~` in `claudeMdExcludes` —
  measure it first), or
- keep spawn-time keys out of the repo actor's tracked file: pass them via the `--settings` the
  clone spawns with, or a gitignored peer file the layout already reads

then clamp it: an acceptance case that enrolls into the repo actor and asserts the tracked file
holds no absolute home path.

## .why it is not done in this round

**safe, not clean.** it changes how every enroll writes every actor's settings — the layout
contract `define.brain-dir-layout-is-one-for-every-actor` governs — far outside the focus wish.
this round removed the leaked block from the tracked file by hand.
