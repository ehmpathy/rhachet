# 🌙 dream: disambiguate the five senses of `boot`

- kind  = chore
- owner = `ehmpathy/rhachet`
- caught 2026-09-23

## .the cue that fired

a peer reviewer on `3.3.1.blueprint.product` graded `boot` a **blocker** under
`rule.forbid.ambiguous-terms`, with the count stated exactly:

> *"the term `boot` carries at least five distinct referents in one document, without canonical
> disambiguation … a reader must infer each time which of the five is meant."*

the reviewer is right, and the overload is **the repo's**, not that document's. the blueprint
merely happens to be the first artifact that uses all five senses on one page.

## .the gap, precisely

| # | the sense | where it lives | rename cost |
|---|---|---|---|
| 1 | the **subcommand** — prints a role's corpus to stdout | `rhx roles boot`, `bin/run.bun.rhachet-roles.bc` | 🔴 a published cli surface; every role readme and hook config invokes it |
| 2 | the **role manifest** — `say:` / `ref:` per role | `boot.yml`, one per role, in **every** role package | 🔴 cross-repo: `bhrain`, `bhuild`, `ehmpathy`, `ghlitch`, `bhrowser`, `rhachet` |
| 3 | the **repo anchor body** | `<repo>/.claude/boot.md` | ⛔ **the wisher named it** — see the bound below |
| 4 | the **SessionStart hook** — two kinds, `role` and `adhoc`, different authors | `.claude/settings.json` | 🟡 a config key plus the code that filters on it |
| 5 | the **scope** — "the boot path", the feature area | prose only | 🟢 free; prose is not a contract |

⇒ **senses 1 and 2 are the expensive pair, and they are also the two a newcomer reads first.**

## .the shape of the fix

the ubiqlang repair is **one canonical word per concept**, and the domain already supplies most of
the candidates:

| # | candidate | why |
|---|---|---|
| 1 | `roles corpus` — the subcommand emits a **corpus** | `term=brief.corpus._.choice._.md` is already declared, and the operation renders exactly that |
| 2 | `corpus.yml` — the manifest declares what enters the corpus | same term, same concept, one hop up |
| 3 | **unchanged** — see the bound |
| 4 | `session hook` / `enroll hook` | it fires at SessionStart; `boot` adds no information the kind field lacks |
| 5 | `the enrollment path` | names the mechanism rather than the moment |

**the migration order matters** — a partial rename yields **six** senses rather than five, which is
strictly worse than the extant state:

1. **sense 5 first** (prose only, zero callers) — proves the vocabulary reads well
2. **sense 4** (one config key + its filter) — contained in `rhachet`
3. **sense 2** with a **dual-read window**: accept `corpus.yml` **or** `boot.yml`, ship it, let the
   role packages migrate on their own release cadence, then drop `boot.yml`
4. **sense 1 last**, as an **alias** (`roles corpus` beside `roles boot`), never a break

⚠️ **step 3 is the one that cannot be skipped.** role packages release independently, so a hard
cutover on `boot.yml` breaks every repo that has not yet upgraded — the exact failure this feature's
own version floor exists to prevent.

## .why it is not done in this round

**SAFE?** 🔴 no. senses 1 and 2 are contracts with cross-repo consumers; a rename ripples into role
packages this route cannot release.

**CLEAN?** 🔴 no. it touches every role package's manifest and the cli surface — a diff this wish
never intended to open.

⇒ both questions answer no, so the fix-forward rule routes it here rather than into the round
(`rule.always.fix-forward-under-scouts-honor`).

## ⛔ .the bound — sense 3 is NOT in scope, at any time

`<repo>/.claude/boot.md` was **named by the wisher**, verbatim, in the seed that made the repo
anchor a hard requirement. to rename it is to overturn what the wisher settled, which is the
wisher's call and never a driver's — even in a later round, even under this dream.

⇒ a future traveler who picks this up renames **1, 2, 4, 5** and leaves **3** alone, unless the
wisher says otherwise.
