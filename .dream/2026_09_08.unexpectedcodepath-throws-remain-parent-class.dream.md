# 🌙 dream: migrate every `UnexpectedCodePathError` throw to `MalfunctionError`

**kind** = repair
**owner** = ehmpathy/rhachet
**caught** = 2026-09-08

## .the cue that fired

a scoped re-run of the `repo-rules` review lane
(`rhx review --rules '.agent/repo=.this/**/rule.*.md' --focus pull`) returned **13 blockers**
where the push-mode lane had returned an overflow. eleven of them name the same class of defect,
in eleven distinct files, and **none of them is this branch's**.

the branch that surfaced them migrated `BadRequestError` → `ConstraintError` on an explicit ask.
`rule.forbid.helpful-error-parents` forbids **both** parents, so the mirror half —
`UnexpectedCodePathError` → `MalfunctionError` — is real work that the same rule mandates and
this wish's scope does not reach.

## .the gap, precisely

`rule.forbid.helpful-error-parents` states that exactly two error words may be thrown:

- `ConstraintError` — exit 2, the caller's to amend
- `MalfunctionError` — exit 1, ours to fix

`BadRequestError` and `UnexpectedCodePathError` are their **parents**, and neither may appear in a
`throw` statement or a `.throw()` call. they are legal only in a type signature or a `catch` clause.

the eleven sites, already enumerated by the review — each verified as **outside every hunk this
branch touched**, so each is an extant condition rather than a regression:

## .the shape of the fix

mechanically small, and it has **exactly one judgment per site**: is this condition genuinely
ours, or is it the caller's?

every one of the eleven reads as **ours** on inspection — they are all internal-invariant guards
(`'todo'`, `'roleFound null without ifPresent'`, `'this should not be possible'`,
`'unsupported context.from'`). so the expected migration is uniform:

```diff
- throw new UnexpectedCodePathError('roleDir null without ifPresent', { opts });
+ throw new MalfunctionError('roleDir null without ifPresent', { opts });
```

with the import swapped in the same edit. **`UnexpectedCodePathError` must stay imported wherever
a `catch` or a type signature still reads it** — the rule forbids the throw, never the reference.

### 🚨 the rule predicts a red suite, and the redness is the fix rendered

`rule.forbid.helpful-error-parents` says outright: *"an acceptance suite that pins the old code
goes red. that redness is the fix rendered, not a regression."*

the `BadRequestError` half of this migration broke **8 acceptance snapshot files** for exactly
that reason — `✋ BadRequestError:` became `✋ ConstraintError:`, glyph unchanged. expect the same
shape here: `✋ UnexpectedCodePathError:` → `✋ MalfunctionError:`.

⚠️ **and expect an exit-code change too, which the `BadRequestError` half did NOT have.**
`ConstraintError` and `BadRequestError` both carry exit 2, so that migration moved only the class
name. `MalfunctionError` carries exit **1** where `UnexpectedCodePathError` carries none — so any
test that asserts an exit code on these paths will move, and a caller that branched on a nonzero
code may see a different number. that is a real behavior change and it wants its own read.

### the clamp it owes

per `rule.require.clamp-edge-cases`, the guard is the same artifact as the proof. the sharpest
form is a repo-wide grep assertion rather than eleven per-site tests:

```ts
// a source-level clamp: no production file may THROW a helpful-errors parent
then('no src file throws a helpful-errors parent class', () => { … });
```

that is one test for the whole class, it goes red today, and it stays red for site twelve.

## .why it is not done in this round

it fails the CLEAN half of the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`).

- **safe?** ✅ each edit is mechanical and locally provable
- **clean?** ❌ **no.** eleven files across three layers (`contract/`, `domain.operations/`,
  `infra/`), an exit-code change on every one, and a predicted acceptance-snapshot break in a
  wish whose deliverable is a node-pty install fix. the ripple reaches contract-layer tests that
  have naught to do with this behavior

`rule.forbid.scope-leaks` is the other half: an item whose line sits outside every hunk this
branch touched is not this branch's to fix. **twelve of the thirteen blockers were refuted on
exactly that ground**, and to then fix eleven of them inside the same bounded wish would refute
the refutation.

⚠️ the twelfth blocker (`genContextBrain.ts`'s `@throws` tags) **was** repaired here, because its
line sat inside a hunk this branch edited. that asymmetry is the rule working, not an
inconsistency.
