# 🌙 dream: pty-with-answers races a hidden prompt, and orphans its child on timeout

- kind = fix
- owner = rhachet (blackbox test infra)
- caught 2026-11-16

## .the cue that fired

ci run 43825797977, shard 1: `keyrack.aws-params.githubApp` [case4] `set` exited `null` after
60s. the raw output ends at `enter secret for XAI_API_KEY:` with no mask stars, so the answer never
landed. the run's leak sweep then named two survivors with this run's id: `script -qec … keyrack
set …` and its `node … run.jit keyrack set` child. a rerun of the same sha is the flake check.

## .the gap, precisely

`blackbox/.test/assets/pty-with-answers.js` has two defects:

1. **the race.** it writes each answer 50ms after the prompt text shows. a hidden-input prompt
   sets its tty mode after it prints, and input that arrives first is dropped. on a loaded runner,
   50ms is too short, so the secret is lost and the cli waits forever. the helper's own docblock
   says a timing delay is flaky; the 50ms is that delay
2. **the orphan.** the caller's `spawnSync({ timeout })` signals only the helper. the helper
   neither forwards the signal nor ends `script`'s group, so `script` and the cli outlive the test

## .the shape of the fix

- spawn `script` with `detached: true`, and on SIGTERM, SIGINT, SIGHUP or exit, signal the whole
  group (`process.kill(-child.pid, 'SIGTERM')`). own the child, as `spawnRhachetCliBackground` does
- give the helper its own deadline under the caller's (e.g. 50s), which ends the group and exits
  with a legible stderr line naming the prompt it last saw and the answer it was owed
- for the race: after an answer, if the pty shows no new output within a bound, re-send it once.
  a hidden prompt that dropped the first copy reads the second; a prompt that took the first has
  moved on
- clamp: an integration test that runs the helper against a stub cli which sets its hidden mode
  only after a 300ms sleep (red under the 50ms helper, green after), and one that kills the helper
  and asserts no pid of its group lives on
