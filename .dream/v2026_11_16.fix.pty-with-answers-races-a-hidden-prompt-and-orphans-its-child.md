# 🌙 dream: keyrack.aws-params.githubApp [case4] sends its secret early, and the set hangs

- kind = fix
- owner = rhachet (blackbox test infra)
- caught 2026-11-16

## .the cue that fired

ci run 43825797977, shard 1: `keyrack.aws-params.githubApp` [case4] `set` exited `null` after
60s. the raw output ends at `enter secret for XAI_API_KEY:` with no mask stars. it reproduces
locally on a shared box, under `rhx test.acceptance.credfree`.

## .what is settled

- the survivors of that run (`script -qec …` and its `node … keyrack set` child) are cured in #761:
  the helper leads its child group, forwards an end signal to it, and ends itself a second later.
  `blackbox/.test/assets/pty-with-answers.integration.test.ts` [case2] pins it
- the lost answer is a defect of the call site, not of the helper's 50ms delay. measured:
  - [case4] passes the pattern `choice|secret`. the menu line `static secret (api key, password)`
    matches it, so the helper counts the menu as prompt 1, sends `1`, then counts `choice: ` as
    prompt 2 and sends the secret there, before the hidden prompt exists
  - `promptLineInput` stops at the first newline of a chunk and drops the rest. when both early
    answers reach the cli in one chunk, the secret is dropped and the hidden prompt waits to the
    caller's 60s timeout. in the green runs the two answers arrive as two chunks
  - every peer call site already passes the precise `choice: |enter secret for`

## .the gap, precisely

[case4] still passes `choice|secret`, so it stays a flake. the precise pattern cures the hang
(measured: the set exits 0), but then the secret lands after its prompt and the terminal echoes it
in the clear, so the mask assertion and the snapshot go red. the green snapshot pins the early send.
that echo is a product defect: `v2026_11_18.fix.keyrack-set-echoes-a-secret-typed-just-after-its-prompt.md`.

## .the shape of the fix

1. fix the echo window in the product (the dream above)
2. then set [case4] to `choice: |enter secret for`, and resnap that one snapshot, which will hold
   the mask stars of a secret sent after its prompt
3. optional: have `promptLineInput` and `promptHiddenInput` `unshift` the bytes after the Enter back
   onto stdin, so typeahead is never dropped

## .why it is not done in this round

step 2 needs step 1, and step 1 is a product change whose cause is not yet found.
