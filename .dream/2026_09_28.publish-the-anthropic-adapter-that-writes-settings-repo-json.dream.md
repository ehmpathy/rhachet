## .the cue that fired

the dogfood `rhx init` of `.behavior/v2026_09_26.fix-config-blend` loaded the PUBLISHED adapter
(`rhachet-brains-anthropic@0.4.3`, from `node_modules`). it writes `<repo>/.claude/settings.json` by
name — and that name is now an arrow to `~/.claude/settings.json`. 21 role hooks landed in the human's
home settings.

## .what holds today

`withBrainDirSettingsShield` (in `syncHooksForLinkedRoles`) swaps the arrow for a real copy of
`settings.of.repo.json` while the adapter runs, folds any write back into `settings.of.repo.json`, and
relinks. it works for an old adapter and a current one alike — but it is a stopgap around a stale
dependency.

## .the fix

1. publish the adapter from `src/_topublish/rhachet-brains-anthropic/` — its `config.dao.ts` reads and
   writes `settings.of.repo.json` by name, via temp + rename, and never reads a `settings.json` arrow
2. bump `rhachet-brains-anthropic` in `rhachet`, and in each role repo that pins it
3. once no supported adapter writes `settings.json`, drop `withBrainDirSettingsShield` and its
   integration test
