# 🌙 dream: the keyrack daemon suite's teardown races its own daemon

kind = fix · owner = rhachet (this repo) · caught 2026-11-13

## .the cue that fired

a full integration run on `beav/feat-actors-yml` failed one suite with 2219 tests green:

```
FAIL src/domain.operations/keyrack/daemon/daemon.integration.test.ts
  Test suite failed to run
  ENOENT: no such file or directory, unlink '/tmp/keyrack-chunked-1845082.sock'
  > 948 | if (existsSync(chunkedSocketPath)) unlinkSync(chunkedSocketPath);
```

the suite passed alone on the next run (25/25), so it is load-dependent.

## .the gap, precisely

the teardown checks for the socket, then unlinks it. the daemon under test removes its own socket on
exit, and under load that exit lands between the check and the unlink. there are 16 such
exists-then-unlink pairs in the file (lines 40–46, 460–482, 930–949, 1023–1041).

## .the shape of the fix

replace each pair with `rmSync(path, { force: true })`. `force` makes an absent path a no-op, so the
check and the race both go. import `rmSync` from `node:fs`. no behavior change on a quiet host.

## .why it is not done in this round

safe, but not clean: the file is a keyrack suite that `feat-actors-yml` does not otherwise touch, and
a 16-site edit there would widen an already large review diff into an unrelated domain.
