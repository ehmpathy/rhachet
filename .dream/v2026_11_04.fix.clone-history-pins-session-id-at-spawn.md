# 🌙 dream: a clone's history links its own session by id, never by a spawn window

kind · fix
owner · rhachet, `src/domain.operations/clone/` (spawn + history link) + `src/contract/cli/invokeEnroll.ts`
caught 2026-11-04

## .the cue that fired

the boot cache gate reads a lead's progress off its `history/`. a stub fleet of four clones of one actor
left four `.exids/*.ambiguous` and an empty `history/`; on an idle box a clone spawned under 2s after a
said peer linked that peer's transcript and read as started.

## .the gap, precisely

- clones of one actor share one transcript dir, so every peer's transcript is a candidate
- the link admits by birth within `spawnedAt − 2s`; two candidates → refuse all; one → adopt it, whose
  it may be
- `define.invariant.clone-history-holds-only-its-own-session` names the residual: provenance unchecked

## .the shape of the fix

1. at spawn, mint a uuid and pass `--session-id <uuid>` to the brain-cli; store it in the clone dir
2. link `history/` by that id alone (`<uuid>.jsonl`); drop the window and the ambiguous refusal for it
3. keep the window as the fallback for a brain-cli that takes no session id, declared
4. clamp: a stub fleet of four, spawned back to back, each `history/` holds exactly its own transcript

## .why it is not done in this round

it changes the clone subsystem's identity rule, a core contract with many callers, so it is planned as
its own dedicated PR: ehmpathy/rhachet#703. the gate fails safe meanwhile (fulcrum F13).
