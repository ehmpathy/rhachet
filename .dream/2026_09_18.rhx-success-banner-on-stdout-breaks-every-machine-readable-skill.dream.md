# 🌙 dream: the rhx success banner sits on stdout, so no skill can offer a clean `--format json`

- kind  = repair
- owner = `ehmpathy/rhachet`
- caught 2026-09-18

## .the cue that fired

`calc.tokens --format json` advertises *"json for a pipe"*, and a bare pipe to `jq` fails:

```
$ rhx calc.tokens --paths 'src/utils/formatTokens.ts' --format json | jq
parse error: Invalid numeric literal at line 1
```

## .the gap, precisely

`src/contract/cli/invokeRun.ts` emits the same banner on two paths, to two different streams:

| path | line | stream |
|---|---|---|
| failure | `:202-211` | 🔴 **stderr** — with the comment *"print header + status to stderr (so it shows when stdout hidden)"* |
| success | `:71-75` | 🔴 **stdout** |

⇒ so the repo has already settled once that this banner is **chrome**, and the success path
never took that settlement. the consequence is general rather than local: **no skill can offer
a machine-readable stdout under `rhx`**, because two lines of chrome always precede it.

`calc.tokens` is merely the first skill to want one.

## .the shape of the fix

move `:71-75` from `console.log` to `console.error`, to match `:202-211`. the same treatment
is owed to the `💪 init role …` banner at `:43-47`.

## .why it is not done in this round

🔴 **it fails the CLEAN half of the scouts-honor test, on cited evidence.** the banner's stream
is a **declared contract of a prior behavior** (`v2026_02_22.graceful-skill-errors`):

```ts
// blackbox/cli/run.graceful-errors.acceptance.test.ts:27-28
then('stdout contains skill identifier', () => {
  expect(result.stdout).toContain('🪨 run solid skill');
});
```

that is a named assertion, deliberately set, and `rule.require.review-test-changes` forbids a
change that degrades a prior behavior's clamp without its owner re-deciding it.

the ripple beyond it: `run.skill`, `rhx.pnpm-hoisted`, `run.graceful-errors`, and
`calc.tokens` acceptance snapshots, plus four `logSpy` assertions in
`invokeRun.integration.test.ts`.

⇒ this behavior's scope is `roles boot --manifest` + `budget.tokens`. a re-decision of the
generic skill runner's output contract is a separate wish, and it owes the graceful-errors
behavior's owner a say.

## .what the round did instead

stated the true contract in `calc.tokens`'s help and named the recipe that works
(`| tail -n +3`), so a caller succeeds first try rather than discovers the banner by a parse
error. the friction is removed; the cause is not.

⇒ the fulcrum that records the deferral: `F21`.
