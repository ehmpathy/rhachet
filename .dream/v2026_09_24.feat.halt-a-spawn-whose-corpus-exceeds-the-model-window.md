# 🌙 dream: halt a spawn whose boot corpus exceeds the model's context window

kind: feat · owner: ehmpathy/rhachet · caught 2026-09-24

## .the cue that fired

the p9 dogfood of `feat-boot-briefs-into-claude-md`: a bare `claude -p` on haiku in this repo
answered `Prompt is too long · the request is ~274685 tokens (limit 200000)`, exit 1. the default
corpus is 805,793 chars; `rhx init` rendered it and printed a census line, and no part of rhachet
compared that size to a model.

## .the gap, precisely

- vision `1.vision.experience.case=4.corpus-exceeds-its-transport.md` `[t1a]` asks the bind to halt
  when a role corpus exceeds what the new transport can carry, and to name the limit, the corpus
  size, and the four remedies
- no criteria, blueprint or roadmap row carries `[t1a]` (a grep of the route for `t1a` hits case 4
  alone)
- the measured cap is not the transport: `CLAUDE.md` delivered 805,793 chars whole (opus 1M quoted
  a sentinel from it). the cap is the model's context window, which the actor never names
- the failure is loud (exit 1, a named token count), so the silent #18 cell does not apply. the cost
  is a clone that cannot answer at all, found only at its first ask

## .the shape of the fix

- the census at render already knows the chars; add an `o200k_base` token estimate beside it
- at spawn (`rhx enroll`, `rhx clone make|fork|wake`), where a `--model` is known, compare the
  estimate to that model's window and refuse, exit 2, with the corpus tokens, the window, and the
  remedies: a larger-window model, fewer roles, `.min` briefs, `ref` over `say`
- where no model is named, print one notice line when the estimate passes 200k tokens, the
  smallest current window

## .why it is not done in this round

the blueprint did not carry `[t1a]`, and a model-window table is new scope with its own source of
truth to keep current. the failure it guards is loud, so the deferral ships no silent harm. see
fulcrum F35.
