# 🌙 dream: decide whether a dir reachable by two routes should emit its files once or twice

- kind  = `decide`
- owner = `ehmpathy/rhachet`
- caught 2026-09-18, during `v2026_09_17.feat-boot-manifest-and-budget`

## .the cue that fired

a cycle guard was added to `getAllFilesFromDir` to close an `ELOOP` crash. the first draft keyed on
an **ever-visited** set, which terminated the cycle **and** collapsed a dag to one route.

that second effect went red against a clamp a prior behavior had already set:

```ts
// src/infra/filesystem/getAllFilesFromDir.test.ts:128
then('traverses symlinked directory', () => {
  const result = getAllFilesFromDir(resolve(testDir, 'symlink-dir'));
  expect(result).toHaveLength(2);   // 🔴 TWO — one per route
});
```

⇒ the guard was narrowed to the **ancestor chain**, which repairs the crash and changes naught
else. the prior contract stands.

## .the gap, precisely

a directory reachable by two sibling routes — a real dir plus a symlink alias beside it — yields
its files **once per route**. the walk terminates; the output carries duplicates.

```
.agent/repo=x/role=y/
  ├─ briefs/            ← a real dir
  └─ briefs-alias  ->  briefs
```

a boot over that tree emits `briefs/core.md` **twice**, under two paths.

**checkable:**

```bash
rhx git.repo.test --what integration --scope 'path://getAllFilesFromDir' --mode apply
# [case3] then: the file is yielded once PER ROUTE  → 2
```

## 🟡 .what this is NOT

it is **not a budget defect.** `calcBootPayloadTokens` counts the exact emitted string, so a file
emitted twice is counted twice — the gate is honest either way. the budget neither hides the
duplication nor is misled by it.

it is a **render** question: does a reader want one brief under two names?

## 🔴 .what the BUDGET changed about it — raised 2026-09-20, `review.peer r010` §4

the render read above is correct, and it understates the stakes **after** this behavior ships:

| | before a declared budget | 🔴 after one |
|---|---|---|
| what a duplicate costs | a repeated line in the payload | 🔴 **twice the tokens against a cap that HALTS** |
| what the author sees | an oddity, if they read closely | a refusal whose arithmetic they cannot reconcile |
| what the remedies offer | n/a | 🔴 **no rung names the cause** — catalogize · condense · reference · eliminate each assume the set is what the author declared |

⇒ **the gate stays honest** (it counts the exact emitted string), and the author is now asked to
trim a payload whose size they did not author. the halt cannot name the cause by design — `F13`
forbids a per-resource breakdown, and a per-cause hint is that breakdown under a different name.

🔴 **so this dream's open question is worth more than when it was caught.** *does any `.agent/` tree
in the wild carry an aliased dir?* — a `yes` used to cost a duplicated line; a `yes` now costs a halt
the author cannot diagnose. ⇒ answer that question first, and the render decision follows cheaply
either way.

## ✅ .the BOOT half is TAKEN — 2026-09-23

> **the deferral below was framed at the WALK grain, where both its answers really are `no`. at the
> PAYLOAD grain both flip, and a third option sits between the two the table offers.**

the decision the table poses is *"which guard does `getAllFilesFromDir` use?"* — and at that grain
the deferral stands, because either guard is a change to the walk's contract and its five callers.
what the table does not hold is a **third** place to put the dedupe:

| grain | the question it answers | a dag duplicate is |
|---|---|---|
| the walk (`getAllFilesFromDir`, 5 callers) | *"what is reachable?"* | ✅ correct — two routes exist |
| 🔴 **between them** (`getAllFilesOncePerRealPath`) | — | the seam this takes |
| the payload (`genBootPayload`) | *"what does the reader receive?"* | 🔴 waste — one file, learned once |

⇒ `getAllFilesOncePerRealPath` keys on `realpathSync` and keeps the FIRST path per inode. the caller
sorts before it calls, so the survivor is deterministic rather than a function of disk order.

**what it does NOT touch:** `getAllFilesFromDir`'s guard, its contract, its `traverses symlinked
directory` clamp, or its four other callers. so both `no`s above are answered rather than overruled —
the clamp's owner is not asked to re-decide anything.

- SAFE ✅ — one caller, `genBootPayload`, and the only test it flips is the one THIS behavior authored
  as a flip-trigger (`genBootPayload.integration.test.ts` `[case3]`, 2 → 1)
- CLEAN ✅ — the edit is one new operation plus one call site

⇒ and the open question (*"does any tree in the wild carry an aliased dir?"*) no longer gates the
boot half: a `yes` costs a duplicated line rather than an undiagnosable halt, whatever the answer is.

## 🔴 .what is LEFT open — the walk grain, for four other callers

the four callers that are NOT `genBootPayload` still receive a dag's files once per route, and that
is still the right default for a question about reachability. worth a look, per caller:

- `discoverInitExecutables` / `discoverSkillExecutables` — each yields a **command list**, so a
  duplicate is a command offered twice. closest in shape to the payload grain
- the other two read for reachability, where the duplicate is correct

⇒ the fulcrum that records the original judgment, and its reversal: `F23`.
