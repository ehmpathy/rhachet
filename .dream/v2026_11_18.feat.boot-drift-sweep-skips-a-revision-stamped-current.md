# 🌙 dream: the boot drift sweep skips a revision whose drift is stamped against the current boot

kind = feat · owner = rhachet · caught 2026-11-18

## .the cue that fired

the level 3 review of `.behavior/v2026_11_17.feat-live-clones-take-boot-drift` (r10.nitpick.6, i006)
named the sweep's cost: `setActorBootDrift` parses both boots before it learns the drift on disk
already matches, so an unchanged revision costs a full parse.

## .the gap, precisely

every render (`rhx init`, each `rhx enroll`) re-computes the delta of every revision under
`<actor>/boots/`. one delta of a 441KB boot costs ~31ms. a revision stays until `rhx clone prune
--mode apply` reaps it, so between prunes the sweep's cost grows with each distinct boot a clone
spawned on. no test measures it past a handful of revisions.

## .the shape of the fix

write `boot.current.hash` beside each revision's `CLAUDE.md`, the hash of the current boot the drift
was computed against. the sweep reads that one line and skips the parse when it equals the current
boot's hash. the drift reader's stale check stays as it is. add an integration case over ~300
revisions with a time bound.

## .why it is not done in this round

the cost is linear and small at today's counts (one revision per boot a clone spawned on); `clone prune`
bounds the count, and the stamp adds a third file to the revision layout that F23 holds at two.
