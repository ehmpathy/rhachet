## .the gap, precisely

`getOneCommonDirPrefix` computes the longest prefix common to **every** path in the roster. so a
prefix common only to a **subtree** is emitted once per member of that subtree.

measured on this repo's own mechanic boot, live in the render:

```
<briefs.ref base=".agent/repo=ehmpathy/role=mechanic/briefs/practices/">
code.prod/consistent.contracts/ref.package.as-command.[ref].md
code.prod/evolvable.procedures/rule.forbid.positional-args.md.pt2.md
code.prod/evolvable.repo.structure/rule.prefer.dot-dirs.md
code.prod/pitofsuccess.procedures/rule.forbid.hidden-side-effects.md
code.prod/pitofsuccess.procedures/rule.forbid.magic-values.md
code.prod/pitofsuccess.procedures/rule.forbid.order-dependence.md
```

`code.prod/` is restated on 59 lines. `pitofsuccess.procedures/` — 33 chars — is restated on 13.
**neither is reachable by B**, because neither is common to the whole set.

⇒ **the wisher's measurement for D: 19,609 B / ~9,765 tokens**, against a payload whose ref roster
already measured **57%** of the total (`F41`).

## .the shape of the fix

`asBootRefBlock` returns a flat list under one base. the fold makes it a **tree**: group by
directory, emit each directory once, and indent its members beneath it.

```
<refs base=".agent/repo=ehmpathy/role=mechanic">
briefs/practices/code.prod/pitofsuccess.procedures/
  rule.forbid.nonidempotent-mutations.md
  rule.forbid.undefined-inputs.md
```

three properties to hold, each already established by the extant code:

| property | why |
|---|---|
| group **by segment**, never by character | `asBootRefBlock.ts:7-9` already refuses a character-wise prefix — it would cut `term=a` and leave a base no reader could open |
| a directory with **one** member does not earn its own line | the fold must be net-negative per group, or a flat tail costs more than it saves |
| an empty roster still emits **no** block | `define.invariant.empty-render-names-its-cause` |

## .why it is not done in this round

**the CLEAN half of the SAFE/CLEAN test fails.**

| question | answer |
|---|---|
| **SAFE?** | ✅ yes — a render change with no semantic reach. the roster's members are identical; only their layout moves |
| **CLEAN?** | 🔴 **no.** it changes the bytes of **every** boot render in the repo, so every boot `.snap` needs a resnap — files this round never opened |

and it is an **enhancement** rather than a defect repair, raised at `5.3.verification`, whose
mandate is to verify what was built.

🔴 **the fulcrum that owns it is `F41` — *should a ref line be budgeted at all* — and `F41` is
OPEN, reserved for the wisher.** D is the one option on that fulcrum that needs no contract
verdict: it is pure render arithmetic, no semantics. ⇒ **so it is the first item of whichever
round takes `F41` up**, and this dream exists so that round inherits the measurement rather than
re-derives it.
