## .the cue that fired

a snapshot census for the 5.3 buttonup gate hit a contradiction it could not explain: the branch's
own render line appears in the snapshots under **two different path tokens**, both paired with the
same char mask.

```
init.*        boot.md (default): $REPO/.agent/.actors/…         — 2 roles, __CHARS__ chars
journey/clone boot.md (default): /TMP_TEST_DIR/.agent/.actors/… — 5 roles, __CHARS__ chars
```

one mask cannot emit both. so two of them do.

## .the gap, precisely

there are **three implementations of "mask the boot census"**, and they overlap on the char span:

| mask | where | covers |
|---|---|---|
| `asSnapshotSafe` | `blackbox/.test/infra/invokeRhachetCliBinary.ts:69` | the char count only — `(\d+ roles?, )\d+ chars` → `__CHARS__` |
| `maskBootCensusVolatiles` | `blackbox/.test/infra/maskBootCensusVolatiles.ts` | the path **and** the char count, in one regex, writes `$REPO` |
| `asMaskedInitReport` | `src/contract/cli/invokeInit.integration.test.ts` | the char count, the repo root (by VALUE, both names), and a `.bak.` clock stamp |

🔴 **the third was added 2026-09-25 and is the one that crosses a tier.** the `src/` integration
tier cannot reach the blackbox infra — `code.test.accept.blackbox` forbids the blackbox tier an
internal import, and the dependency the other way is no better, since it would make a production
suite rest on acceptance infra. so this instance is not careless duplication; it is the seam the
two-tier split leaves open, and it is why the fix below needs a **shared** home rather than a winner
among the extant three.

⚠️ it also demonstrates the sharper half of the lesson: written independently, it reached for
`/TMP_REPO` and `__CHARS__` (the `asSnapshotSafe` vocabulary) and **not** `$REPO` — so the token
inconsistency the fix must settle now carries a 2:1 split rather than 1:1.

🔴 **and the composition order makes the second one inert.** four journey call sites read:

```ts
maskBootCensusVolatiles(asSnapshotSafe(init.stdout))
```

`asSnapshotSafe` runs first and rewrites `41397 chars` into `__CHARS__ chars`. the outer mask
anchors on a literal digit run before `chars`, so it can no longer match — **the whole replace is
inert at all four sites.** that is why those snapshots keep `/TMP_TEST_DIR/` rather than `$REPO`.

⇒ the outer call is a **safety net that cannot catch**. it reads as defense in depth and supplies
none: if `asSnapshotSafe`'s temp-dir rule ever misses a path shape, the fallback is structurally
unable to mask it, because the upstream mask already consumed the span it keys on.

🟡 **no leak occurs today** — `asSnapshotSafe` masks the temp dir by a separate rule, and the
acceptance tier is green. this is a latent hazard and a dead call, never a live defect.

## .the shape of the fix

🔴 **the tier seam rules out "pick a winner among the extant three."** a `src/` suite may not reach
blackbox infra and must not be reached into, so the char-count rule needs a home BOTH tiers may
import — a plain module with no test-tier dependency (`src/.test/assets/`, or a tiny published util).
that is the one step this dream did not originally hold, and the third implementation is what
surfaced it.

then, beneath it:

1. **decide the canonical token.** `$REPO` and `/TMP_TEST_DIR/` name one concept two ways, which
   `rule.forbid.domain-term-inconsistency` forbids once a canonical word is declared. `/TMP_TEST_DIR`
   is the incumbent across the whole blackbox tier, so it is the likely keeper
2. **make the path rule independent of the char rule** — split `maskBootCensusVolatiles` into two
   replaces, so a pre-masked char count cannot disable the path mask
3. **or retire `maskBootCensusVolatiles` entirely** and fold its path rule into `asSnapshotSafe`, so
   one seam remains. the four `init.*` suites that import it today do not call `asSnapshotSafe`, so
   they would adopt it instead
4. re-snap the affected suites and confirm the role counts and labels survive untouched

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`) fails on **clean**:

- **safe** — ✅ confined to test infra; no production code and no contract moves
- **clean** — 🔴 **no.** any of the three fixes changes the path token in extant snapshots, so it
  needs a re-snap plus an acceptance re-run (~36 min) to prove, and it re-opens files this branch's
  subject never touched

so the cheap, safe, clean half WAS taken this round: `maskBootCensusVolatiles.test.ts` now exists,
and its `[case3]` **pins the inert composition explicitly** rather than a limit rediscovered later
by accident. the clamp was proven to bite — a mutation of the regex's optional plural turned it red
(2 of 9), and its restoration turned it green.

🟡 the deferral is a **size** call rather than a dirt call, so it owes this dream and no fulcrum.
