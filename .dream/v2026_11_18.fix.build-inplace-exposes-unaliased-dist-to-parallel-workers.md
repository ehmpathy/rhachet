# 🌙 dream: build:inplace exposes an unaliased dist to parallel test workers

- kind = fix
- owner = rhachet (build scripts + blackbox test infra)
- caught 2026-11-18

⇒ a second occurrence of `v2026_09_24.fix.a-mid-build-dist-is-importable-but-broken.md`, which
holds the mechanism and the fix shape. this file adds the ci occurrence and the test-time rebuild
as the trigger; fold it into that dream when either is worked

## .the cue that fired

on ci, after the rebase of #761 onto main, `test-shards-integration (3, 3)` went red (job 134688162235).
`measure.acceptance.share.integration.test.ts` [case8] failed in its nested acceptance run: `bin/run.jit`
died with `Cannot find module '@src/infra/git/getGitRepoRootOrNull'` from
`dist/domain.objects/ContextCli.js`. the same file passes alone on a local box (37/37). the code is
sound; the fault is a race.

## .the gap, precisely

- `build:inplace` runs `tsc`, then `tsc-alias`. between the two, every `dist/*.js` holds raw `@src/...`
  requires, and any load of `dist` in that window fails
- `build:ifstale` can trigger `build:inplace` from inside a test run, while other jest workers spawn
  `bin/run.jit` against the same `dist`
- the job log does not show the rebuild, because child output is captured. so the mechanism is
  inferred, not measured. confidence ~70%: only an unaliased or half-written `dist` fits the error

## .the shape of the fix

- first, measure: print the `build:ifstale` verdict to stderr, so a ci log shows whether a rebuild ran
  inside a test
- make the build atomic for readers: compile into an adjacent `dist.next/`, run `tsc-alias` there, then
  swap by rename. a reader sees the old `dist` or the new one, never a half-built one
- and/or: an integration test never rebuilds the shared `dist`; it asserts the stale-check verdict with
  a stub
- clamp: a test that loops `bin/run.jit` spawns while `build:inplace` runs, and asserts no
  `MODULE_NOT_FOUND`. red before the swap, green after

## .why it is not done in this round

the fix touches build scripts every consumer of this repo runs, and it needs its own clamp and review.
#761's scope is how the acceptance suite shares the box. this race predates the rebase and surfaced
only now.
