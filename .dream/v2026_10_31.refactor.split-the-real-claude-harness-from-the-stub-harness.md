# 🌙 dream: split the real-claude harness out of enrollCloneHarness, so a path decides live

- kind = refactor
- owner = rhachet
- caught 2026-10-31

## .the cue that fired

a peer review of the clamp found the `names` reach, and its export audit, exist for one mixed
module.

## .the gap, precisely

- three of the four `names` modules export only live names (`genRealBrainSlot`,
  `genIsolatedClaudeHome`, `getContextOpenAI`); they are `import` modules in all but name
- `blackbox/.test/infra/enrollCloneHarness.ts` alone mixes them: 6 live and 10 stub exports in
  ~1,200 lines, so every new export must be classified by hand, and stub suites load live code

## .the shape of the fix

1. move `getRealClaudeBinPath`, `isRealClaudeAuthed`, `getRealClaudeOrThrow`,
   `setRealClaudeFirstRunAccepted`, `enrollRealClaudeAndWaitReach`, `sayAndPollForMarker` and the
   private operations they call into `blackbox/.test/infra/enrollRealClaudeHarness.ts`; register
   it `import`
2. register the other three `names` modules as `import`
3. remove `reach: 'names'`, the `live` and `stub` lists, `getNamesOfExports`,
   `getAllInfraModuleExportsUnclassified` and the scan's [t2]
4. one import edit per importer; the realbrain suites keep their gates

## .why it is not done in this round

it moves ~400 lines of shared harness and touches every real-claude suite's imports; the export
audit holds the same line today, bite-proven, at the cost of one classification per new export.
