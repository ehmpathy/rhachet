# 🌙 dream: `git.release --watch` waits on the pushed head, never a prior one

kind = reseed · owner = ehmpathy/rhachet-roles-ehmpathy (mechanic `git.release`) · caught 2026-11-27
task = ehmpathy/rhachet-roles-ehmpathy#1515 (open; it names this defect: a queued or red pr read as all
checks passed). this dream adds one instance to it and dispatches no twin

## .the cue that fired
right after a push to pr #847, `rhx git.release --watch` printed `👌 all checks passed`,
`🫧 no runs inflight`, `✨ done! 0s in action`. `gh pr checks 847` showed 14 checks unresolved on the new
head at that same moment, so the watch read the prior head's rollup. this happened twice, a minute apart.

## .the gap, precisely
the watch reports a verdict on checks that are not the pushed commit's. a driver that trusts it calls a
head green before ci has run on it, and `rule.require.watch-release-after-push` is then met in form only.

## .the shape of the fix
key the watch on the local `HEAD` sha. until the pr's `headRefOid` equals it and runs for that sha exist,
print `⏳ wait for runs on <sha>` and poll. never print `all checks passed` for a rollup whose sha
differs. clamp: push, then run the watch at once, and it must wait.

## .why it is not done in this round
the skill lives in another repo, and #1515 already holds the fix there. here, `gh pr checks 847 --watch`
was the fallback, and it confirmed the green.
