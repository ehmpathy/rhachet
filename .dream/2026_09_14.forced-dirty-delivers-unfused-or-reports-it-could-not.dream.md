# 🌙 dream: forced-dirty delivers unfused (or reports it could not), over append-and-`released`

- **kind**: fix
- **owner**: ehmpathy/rhachet (this repo)
- **caught**: 2026-09-14
- **fulcrum**: F12
- **gates**: case=2 / F06 — a `--force` say into a dirty box must not silently FUSE with the human's text

## .the cue that fired

r007 (arch-hazards-behavior) n2 + r009 (ergo-friction-hazards) b1, restated by r010 (behavior-intent) b2:
a `--force` say into a DIRTY box overrides the pre-check and writes — but the human's uncommitted text is
STILL in the box. the forced write appends to it and submits BOTH as one fused turn, then reports
`released` as though it landed cleanly. the caller is told success; the human's half-typed line was
silently merged into the message.

## .the gap, precisely

`--force` overrides the `input-region-dirty` refusal (correct — that is F06's decided force path), but it
leaves the human's text in the region untouched. two honest outcomes are missing:

1. **deliver unfused** — clear the human's text out of the box (preserving it) before the forced write, so
   only the say's message submits; or
2. **report it could not** — if the box cannot be safely cleared, land a verdict that says the message
   FUSED, never a clean `released`.

today it does neither: it appends and reports `released`.

## .the shape of the fix

1. measure **Q22** — can a multi-row input region be cleared deterministically (the emulator's clear
   semantics across soft-newline-wrapped rows)? this decides whether outcome 1 is even reachable.
2. a wisher verdict on **F06** — whether `--force` should CLEAR-then-write or WRITE-fused-then-report, and
   whether F02/F03 permit reading enough of the region to preserve the human's text.
3. if clear-then-write: preserve the evicted text (to a scratch), write the message alone, land `released`.
4. if report-fused: a verdict distinct from `released` that names the fusion, so the caller knows the
   human's text rode along.
5. a realbrain acceptance test: `--force` into a real dirty box, assert the human's text is NOT fused into
   the submitted turn (or that the verdict names the fusion).

## .why it is not done in this round

it clears the ONE bar `rule.forbid.deferrals-short-of-a-dedicated-pr` leaves open — a change gated on BOTH
a measurement (Q22) AND a wisher verdict (F06), whose branches are mutually exclusive:

- "deliver unfused" needs Q22 (multi-row clear), unmeasured this session.
- "report it fused" is barred by the socket's content invariant (F02/F03) unless the wisher amends it — the
  server may classify the region but not read the human's bytes back to the client.
- a refuse-branch would REVERSE the already-decided F06 force path (that `--force` DOES override a dirty
  box). so the fix cannot proceed without the wisher ruling F06's shape.
- ⇒ it fails the CLEAN test (`rule.always.fix-forward-under-scouts-honor`): it ripples into the dequeue
  write path, the verdict set, and (possibly) the socket content invariant, and hinges on a reserved
  wisher call. the decision to defer is recorded as fulcrum F12.

**and the current force path is defensible to ship now:** `--force` is an EXPLICIT opt-in past a refusal
that names the dirty box and the `--force` fix (`[case9]` proves the unforced say withholds with that
copy). a caller who forces has been told the box holds uncommitted text. the fusion is a named, opt-in
hazard behind an explicit flag, not a silent default — and the unfused/report-fused upgrade is a follow-on
PR, gated on Q22 + a F06 verdict, not a gap this PR leaves broken.
