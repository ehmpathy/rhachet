# 🌙 dream: mask the third-party model catalog a discovery snapshot pins

- kind  = chore
- owner = ehmpathy/rhachet
- caught 2026-09-24

## .the cue that fired

a snapshot census for the 5.3 buttonup gate found `genContextBrain.discoveryNotFound…snap` with a
**19 / 15** diff — the most balanced snapshot change on the branch, and the shape that hides a
quiet re-snap. it turned out to be legitimate, and the reason is the problem:

```
rhachet-brains-fireworksai  0.1.6 → 0.1.7
```

**one patch bump of a dependency rewrote 34 lines of this repo's snapshot.** the models that left
(`fireworks/qwen/3.7-plus`, `fireworks/minimax/2.7`, `fireworks/gpt-oss/20b`) and those that
arrived (`fireworks/glm/5.3`, `fireworks/glm/5.3-flash`, `fireworks/kimi/k3`,
`fireworks/deepseek/v4.1-flash`, `fireworks/nemotron/3.5-lightning`) are **a vendor's catalog**,
never this repo's behavior.

## .the gap, precisely

the test's subject is `genContextBrain`'s **not-found error render** — that it names the choice it
could not look up, and lists what IS available so a human can correct the typo. that claim is about
**shape**: a `🔭 available brains` header, a tree, a truncation suffix, and a json `available` array.

the snapshot instead pins **the catalog's contents**, which no line of this repo produces:

```
   ├── ○ fireworks/glm/5.2
   ├── ○ fireworks/minimax/m3
   …
   └── (and 8 more)
```

⇒ so the file is a **standing false positive generator**: every `rhachet-brains-*` bump, forever,
turns a green suite red and asks a human to eyeball a vendor's model list for a defect that cannot
be there. and the cost is worse than the churn — a reviewer who learns that this snapshot always
needs a re-snap stops to read it, which is exactly when the one change that DID matter slips past.

🟡 **the truncation count makes it concrete**: `(and 6 more)` → `(and 8 more)`. that number is a
real assertion about the render, and it is buried among two dozen lines that are not.

## .the shape of the fix

mask the vendor-owned fields at the serializer, the way the suite already masks a temp dir and a
char count (`__CHARS__`, `/TMP_TEST_DIR/`):

1. replace each catalog row with a stable token — `├── ○ __BRAIN_SLUG__` — so the **tree shape,
   the glyph column** (`↻` live vs `○` declared), and the row count stay asserted
2. keep `(and N more)` **unmasked** — it is a real claim about the truncation window
3. replace the json `available` array's members likewise, and keep its **length** asserted
4. add one positive assert **outside** the snapshot that a known-stable slug is present
   (`anthropic/claude/code`), so the list is proven non-empty and correctly sourced

⇒ the render contract stays locked; the vendor's catalog stops to be this repo's test data.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`) fails on **clean**:

- **safe** — ✅ the change is confined to one acceptance suite's serializer
- **clean** — 🔴 **no.** the file is inherited, untouched by this branch's subject (boot briefs),
  and a serializer change cannot be proven without a re-run of the acceptance tier, which is a
  ~36-minute sweep. that ripple lands squarely outside the diff this round opened

so it is deferred with a record rather than smuggled in. 🟡 the deferral is a **size** call rather
than a dirt call, so it owes this dream and no fulcrum — the judgment is not about a design fork.
