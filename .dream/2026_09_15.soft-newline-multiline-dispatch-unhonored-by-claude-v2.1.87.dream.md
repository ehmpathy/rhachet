# 🌙 dream: the soft-newline multi-line dispatch does not land on claude-code v2.1.87

- **kind**: fix
- **owner**: ehmpathy/rhachet (this repo)
- **caught**: 2026-09-15
- **status**: ✅ **RESOLVED 2026-09-17** — see `.the resolution` at the foot
- **scope**: PRIOR behavior (on `main`), pulled INTO this wish by wisher directive

## .the cue that fired

the new Q10 screen-dogfood probe (`blackbox/cli/clone.screen-dogfood.realbrain.acceptance.test.ts`)
dispatched a real multi-line message (`"ML-…\nSECOND-LINE\nTHIRD-LINE"`) through `sayClone` and asserted
its lines render across ≥2 grid rows. against a live Claude Code v2.1.87 (Haiku 4.5) the assertion got
`Received: 0` — the marker lines never rendered anywhere. the captured grid (25875-char stream, full
scrollback held) showed the single-line dispatches (`m1`, `m2`) render fine, but the multi-line message
left the input box EMPTY and produced no marker row at all.

## .the gap, precisely

`asCloneDispatchFrame` (`src/domain.operations/clone/socket/asCloneDispatchFrame.ts`, on `main`) maps each
interior `\n` to `CLONE_SOFT_NEWLINE` = `\x1b\r` (ESC + CR) — the injectable Shift/Option-Enter that is
meant to insert a newline in the brain-cli's edit buffer. against Claude Code v2.1.87 that sequence is NOT
honored as a buffer newline: the ESC is consumed as an escape and the message never enters the buffer as
multi-line text, so the whole dispatch is eaten (the box reads empty afterward).

evidence: `.log/dogfood-multi-capture.txt` from the 2026-09-15 run — `m1`/`m2` present, zero `ML-`/
`SECOND-LINE`/`THIRD-LINE` rows, empty `❯` box.

## .why it is a real finding, not this wish's defect

- `asCloneDispatchFrame`, `CLONE_SOFT_NEWLINE`, and `invokeCloneSay` all live on `main` already — the
  soft-newline multi-line dispatch is prior behavior, not a surface this wish (the read channel) built.
- the wish's shipped contract — that `computeCloneInputState` reads a multi-ROW REGION (never a single row),
  so a multi-line message that DOES render across rows is counted correctly — is proven deterministically by
  the unit clamp in `computeCloneInputState.test.ts` (the r010-i021-b1 case, `countInInput` 0 → 1).
- so the region read (this wish's job) is correct; only the prior DISPATCH keybinding is stale.

## .the shape of the fix

1. discover the correct multi-line-insert keystroke for the pinned Claude Code version (v2.1.87) — the
   candidate is a bracketed-paste wrap (`\x1b[200~ … \x1b[201~`) rather than the per-line `\x1b\r`, which is
   the more portable way to inject a multi-line buffer without a per-version keybinding.
2. update `CLONE_SOFT_NEWLINE` / `asCloneDispatchFrame` to that mechanism, behind the adapter seam the
   version pin already implies (a v-diff ejects into the adapter, per `define.pty-stream-vs-screen`).
3. re-run the Q10 realbrain probe against the fix and assert the ≥2-row render holds end to end.
4. clamp `asCloneDispatchFrame` with a unit test that fixes the chosen escape shape.

## .why it is not done in this round

- it is a change to PRIOR prod behavior (`asCloneDispatchFrame` on `main`), outside this wish's declared
  read-channel scope — `rule.require.review-test-changes` bars a scope-creep rewrite of an unrelated
  dispatch path inside this PR.
- it fails the CLEAN test (`rule.always.fix-forward-under-scouts-honor`): the right escape sequence for
  v2.1.87 is unmeasured this session, and a change to the frame builder ripples into every `clone say`
  caller (single-line and multi-line alike), so it wants its own PR + realbrain verification.
- the read-channel behavior this wish ships is unaffected and unit-proven; the Q10 probe is retargeted to
  verify the region-read rationale (V) against multi-row content the real brain DOES render, so the gate is
  honest without a fake pass on a false premise.

## ✅ .the resolution — 2026-09-17

the wisher overruled the deferral above, in two words: **"fix it"**, then **"fundamentally"**. so the
scope argument in `.why it is not done in this round` no longer holds, and the fix landed in this PR.

### the correction to `.the gap, precisely`

the 2026-09-15 read was **imprecise**. measured again 2026-09-17 against a live claude-code v2.1.87 by
a read of the RECORDED TURN (not the grid): `\x1b\r` does not eat the whole dispatch — the ESC is eaten
and every line but the **LAST** is discarded, silently. a three-line say arrives as its final line alone.
that is worse than an empty box, because it delivers a message the caller never sent.

### the three mechanisms, measured

| mechanism | honored? | verdict |
|---|---|---|
| `\x1b\r` (ESC+CR, injectable Option/Shift-Enter) | **no** — every line but the last discarded | the defect |
| `\` + CR (claude's documented portable multi-line key) | yes, one turn — but each non-final line keeps a **literal `\`** in the recorded turn | corruption, refused |
| bracketed paste (`\x1b[200~` … `\x1b[201~`) | **yes** — verbatim, three rows, no residue | **adopted** |

### the second, deeper defect this uncovered

the frame swap alone did not land it: the paste sat `buffered` forever, because the write path
**guessed** the commit interval with a blind `computeCloneSubmitDelay` sleep (50ms floor) while the
daemon already held a live rendered screen. the guess errs both ways — too short loses a paste, too
long taxes every short say.

⇒ cured by `awaitCloneSubmitReady`: the daemon polls its own box for a **rise** above a pre-write
baseline and submits the instant the content is OBSERVED committed. an unreadable feed degrades to
exactly the prior blind sleep and reports `observed: false`, so a degraded feed is never made worse.

### the shape-of-the-fix checklist, closed

1. ✅ mechanism discovered — bracketed paste, chosen after all three were measured live
2. ✅ `CLONE_SOFT_NEWLINE` retired; `CLONE_PASTE_OPEN`/`CLONE_PASTE_CLOSE` replace it
3. ✅ Q10 realbrain probe re-pointed at a real 3-line dispatch; asserts all three lines land on
   **distinct** rendered rows with no marker residue
4. ✅ `asCloneDispatchFrame.test.ts` clamps the frame shape; `awaitCloneSubmitReady.test.ts` clamps
   the observed-submit, the rise-not-presence rule, the budget, and the degrade path

### the live proof

a fresh clone, three lines, one turn, verbatim — `{ "delivered": true, "verdict": "released" }`,
and the recorded turn reads `alpha line one` / `bravo line two` / `charlie: reply with exactly CURED-OK`.
