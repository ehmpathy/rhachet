# 🌙 dream: `git.repo.test` gates its perf tier on an env var where every peer widener is a flag

- **kind** = reseed
- **owner** = `ehmpathy/rhachet-roles-ehmpathy` — 🔴 **foreign to this tree**
- **caught** = 2026-09-20, at `v2026_09_17.feat-boot-manifest-and-budget` `5.1.execution`, `i009`
  blocker.3 (the budgeted-boot latency clamp)

---

## .the cue that fired

the wisher asked it outright, having watched four consecutive commands block: *"why isnt that a
flag? --perf?"*

the trigger was a new perf suite that a `given.runIf(RUN_PERF_TEST)` gates, so every local run of it
needs `PERF=true rhx git.repo.test …` — and that prefix is what kept blocking.

---

## .the gap, precisely

```ts
// blackbox/.test/infra/RUN_PERF_TEST.ts — THIS repo, and correct as written
export const RUN_PERF_TEST = !!(process.env.CI || process.env.PERF);
```

the env var is the right *mechanism* for a jest-side gate. the gap is that the **runner offers no
way to set it**, so the caller must reach around the runner:

| the widener | its form | discoverable from `--help`? |
|---|---|---|
| run the full suite, not the changed set | `--thorough` | ✅ flag |
| update snapshots | `--resnap` | ✅ flag |
| 🔴 **run the perf tier** | 🔴 **`PERF=true` env prefix** | 🔴 **no** |

three defects follow, and the third is the one that cost real turns:

1. **undiscoverable** — `PERF` appears in no help text. the only way to learn it is to read
   `RUN_PERF_TEST.ts`, which is a file in the *consumer* repo, not the runner
   (`rule.require.discoverability`, ergonomist — *"a step a human cannot find is a step a human
   cannot take"*)
2. **asymmetric with its own peers** — `--thorough` already occupies exactly this slot, so perf is
   the one widener that is spelled a second way (`rule.prefer.symmetric-term-pairs`)
3. 🔴 **an env prefix defeats the permission allowlist.** `rhx git.repo.test …` is a pre-approved
   **prefix**; `PERF=true rhx git.repo.test …` matches no entry at all, so it blocks on every
   invocation. a `--perf` flag would ride the extant permission for free.

⇒ **measured, 2026-09-20: four consecutive blocks in one session**, each of them the identical
command differing only by that prefix.

---

## .the shape of the fix

in `ehmpathy/rhachet-roles-ehmpathy`, `skills/git.repo.test/git.repo.test.sh`:

1. accept `--perf` in the arg loop, beside `--thorough` and `--resnap`
2. `export PERF=true` when it is present — **set the extant env var rather than replace it**, so
   every consumer's `RUN_PERF_TEST` keeps working unchanged and `CI=true` still fires on its own
3. add the row to `show_help` and to the docblock's `usage:` block
4. resnap the skill's acceptance snapshots — the docblock renders as help
   (`rule.always.resnap-a-docblock-that-renders-as-help`)

🟡 **the env var does not go away, and should not.** `CI=true` must keep firing the tier with no
flag at all, and a consumer's jest config reads `process.env`. the flag is a *front door* onto the
extant mechanism, never a second mechanism.

---

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **SAFE?** | ✅ yes — a new optional flag, additive, no extant caller changes |
| **CLEAN?** | 🔴 **no — the file is not in this tree** |

```
$ git check-ignore -v '.agent/repo=ehmpathy/role=mechanic/skills/git.repo.test/git.repo.test.sh'
fatal: pathspec '…' is beyond a symbolic link
```

🔴 **that error IS the verdict.** `.agent/repo=ehmpathy/**` is a symlink into a version-pinned pnpm
store, so an edit here is wiped by the next `pnpm install` and is a published artifact of another
repo (`define.invariant.a-symlink-under-agent-is-foreign`).

⚠️ **and `file` says the opposite**, which is the trap worth recording: it follows the link and
reports an ordinary executable. **only a tool that refuses to cross the link reports the
ownership.** `file` answers *what is at the other end*; `git` answers *whose it is*.

⇒ so the fix is **re-seeded** to the tree that owns it rather than adopted here
(`rule.always.scope-onetime-lessons-to-the-behavior` — *a tree adopts only what is scoped to
itself*).
