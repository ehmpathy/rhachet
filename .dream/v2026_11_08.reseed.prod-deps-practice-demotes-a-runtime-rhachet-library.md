# 🌙 dream: the `rhachet` practice's prod-deps fix demotes a runtime library to devDependencies

- kind = reseed
- owner = ehmpathy/declapract-typescript-ehmpathy (practice `rhachet`, `bad-practice.prod-deps`)
- caught 2026-11-08

## .the cue that fired

`npx declapract apply --practice rhachet` (declapract-typescript-ehmpathy@0.50.0) applied
`practice:rhachet.bad-practice.prod-deps` and moved `rhachet-artifact-git` from `dependencies` to
`devDependencies` in this repo's package.json.

## .the gap, precisely

the check treats every `rhachet-*` package in `dependencies` as a role or brain package, which a
consumer should only need at dev time. `rhachet-artifact-git` is a runtime library: prod source
imports it as a value (`src/contract/cli/invokeChoose.ts`, `src/domain.operations/template/useTemplate.ts`,
`src/domain.operations/role/getRoleBriefs.ts`, `src/contract/cli/invokeRepoCompile.ts`). had the
move shipped, every consumer install of rhachet would omit it and the cli would fail at import.

the fix was reverted by hand in this round; the next `declapract apply --practice rhachet` will
re-apply it.

## .the shape of the fix

scope the prod-deps check to role and brain packages — `rhachet-roles-*` and `rhachet-brains-*` —
never the whole `rhachet-*` prefix. libraries such as `rhachet-artifact`, `rhachet-artifact-git`
stay legal in `dependencies`. clamp it with a fixture repo whose prod source imports
`rhachet-artifact-git`: the practice must leave it in `dependencies`.

## .why it is not done in this round

the defect lives in another repo's practice; a tree adopts only what is scoped to itself.
