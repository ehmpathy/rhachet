# 🌙 dream: the "driver-owned" guard-edit lever is a hook's name, and a human grant

- **kind** = reseed
- **owner** = `ehmpathy/rhachet-roles-bhrain` (role=driver briefs)
- **caught** = 2026-09-25

## .the cue that fired

a dark lane needed a narrower bind. two driver briefs name the remedy, both as **driver-owned**:

- `rule.always.spend-own-levers-before-escalation` — *"🔴 `rhx route.mutate.guard` — the stone's own
  `--paths-with`, `--conversation`, `level`, `budget` | **driver**"*
- `rule.forbid.hand-run-reviews` — *"🔴 `rhx route.mutate.guard` — narrow its `--paths-with` … **then
  let the guard run it**"*
- `rule.always.diagnose-reviewer-malfunctions` — *"narrow the REVIEWER, in the guard"*, with
  `rhx route.mutate.guard` in a fenced block

all three were followed. all three failed, for the same two reasons.

## .the gap, precisely

**1. `route.mutate.guard` is not a guard editor. it is the PreToolUse hook that SEALS guards.**

`.agent/repo=bhrain/role=driver/skills/route.mutate.guard.sh:1-27`:

```
# .what = pretooluse hook to protect route stones, guards, and metadata
# .why = prevents drivers from … reading guard files (enables gaming review criteria)
# usage: configured as PreToolUse hook via getDriverRole.ts
```

⇒ so `rhx route.mutate.guard …` invokes the **sealer**, which then blocks the invocation as a
protected-path read. the brief's fenced command cannot ever have worked.

**2. the real editor is `rhx route.mutate`, and it is HUMAN-GATED.** same docblock:

```
# privilege:
#   human can grant via: rhx route.mutate grant allow
#   creates flag at: $route/.route/.privilege.mutate.flag
```

and `.route/**` is itself sealed, so a driver cannot even check whether the grant exists.

## 🔴 .why this costs more than a wrong command name

the ownership table is the artifact a stuck driver reads to decide **whether to escalate**. a lever
filed under `driver` that is in fact human-gated produces the exact failure
`rule.always.spend-own-levers-before-escalation` was written to prevent — in reverse:

| the brief's own lesson | what this row does |
|---|---|
| an absent row *"reads as 'not mine'"*, so a driver never reaches for it | a **mis-attributed** row reads as *"mine"*, so a driver spends rounds on a door that cannot open, and never surfaces the ask |

🟡 and the mis-attribution carries weight in a second place: `rule.forbid.hand-run-reviews` forbids a
hand-run review **on the grounds that the guard edit is the sanctioned substitute**. where that
substitute needs a human grant, a driver with a dark lane has *no* driver-owned remedy at all — and
the forbid rule still binds, correctly. the rule is right; its stated alternative is not available.

## .the shape of the fix

1. **rename or disambiguate** — the hook and the editor must not share a name. the hook is
   `route.mutate.guard`; the editor is `route.mutate`. the briefs cite the former for the latter's job
2. **move the row** in `rule.always.spend-own-levers-before-escalation`'s owner table from **driver**
   to **human**, phrased as the grant: `rhx route.mutate grant allow`
3. **add the driver's half** — what a driver does *before* the ask: name the lane, name its overflow
   size, and name the `--paths-with` it would take, so the human grants against a concrete diff
4. **amend `rule.forbid.hand-run-reviews`** — keep the forbid, and say plainly that where the grant
   is absent the remedy is an **ask**, never a hand-run
5. **amend `rule.always.diagnose-reviewer-malfunctions`** — its overflow row carries the same command
