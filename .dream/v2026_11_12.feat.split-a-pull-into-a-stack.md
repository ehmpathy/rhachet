## .the cue that fired

has no paved command.

## .the gap, precisely

every paved git verb acts on the current branch of the current worktree:

| the stack needs | paved? |
|---|---|
| a new branch, cut from a named base | no. `git checkout` is denied; `rhx permissions.get --for 'git switch -c …'` reads "no paved path fits this part" |
| a commit of a chosen file set onto it | yes, via `git.stage.add` + `git.commit.set` |
| a push of that branch | yes, via `git.commit.push` (current branch only) |
| a pull whose base is the slice below, not main | no. `git.commit.push` opens against main; `gh pr edit` and `gh pr create` are denied |
| close the source pull with a comment that links the stack | half. `git.pull.comment` comments; `gh pr close` is denied |

⇒ a stack of N pulls needs N branches, and this tree can address one.

## .the shape of the fix

one skill, `git.pull.stack` (or a `git.branch.split` + `--base` pair), plan/apply:

- input: the source branch, plus an ordered list of slices, each a slug and a set of path globs
- per slice: cut `<branch>.pNN` from the slice below (p01 from origin/main), check out exactly its
  paths from the source head, commit as seaturtle with the sponsor trailer, push, findsert the
  pull with `--base` set to the slice below
- after the last slice: assert the union of slices equals the source diff (no file dropped, none
  in two slices), comment the stack on the source pull, close it
- plan mode prints each slice's file list and line count, so the ~1300-line read cap is checked
  before any push
