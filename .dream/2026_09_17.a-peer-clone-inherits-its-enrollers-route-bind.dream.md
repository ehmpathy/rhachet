## .the cue that fired

succeeded. then the transcript read showed a **third** turn nobody dispatched:

```

├─ 🎧 T0+00H00M   LOOP1-ALIVE

                     ├─ route = .behavior/v2026_09_11.fix-clone-say
                     └─ stone = 5.3.verification
                  … ~300 lines of the enroller's stone text …
```

⇒ the peer answered its one question, then was handed the **whole 5.3.verification stone** as its next
turn, by a hook it inherited rather than earned.

## .the gap, precisely

a route bind is worktree-scoped (`.behavior/…/.route/.bind.<user>.<branch>.flag`), and a peer clone is
spawned with the enroller's `cwd`. so the peer's `hook.onStop` fires `route.drive`, finds the bind, and
emits the bound stone into the peer's own context.

checkable, from the capture above and from the `--debug` grid of the same peer, whose rendered rows 0-10
are the enroller's stone rather than the peer's own work:

```
      4 │     ├─ are you here?│
      6 │     │  │  └─ rhx route.stone.set --stone 5.3.verification --as arrived│
      8 │     │     └─ rhx route.stone.set --stone 5.3.verification --as passed│
```

### 🔴 the harm, and why it is not merely untidy

| cost | what it does |
|---|---|
| **context** | ~300 lines per Stop, every turn, for the life of the peer — an unbounded tax on the peer's own budget |
| **steer** | the stone's own text says *"when ready to continue, run `--as passed`"*. the peer is instructed to drive a route it was never enrolled onto |
| **collision** | two clones on one bind can each signal the same stone, so a passage record gains entries from a party that did no work |
| 🔴 **delegation** | the loop directive's aim is a peer that takes *delegated* work. a peer steered toward the enroller's route is not one |

⇒ **the third row is the sharpest**, because it writes to shared state rather than merely wastes the
peer's tokens.

### 🔴 the harm escalates — measured 2026-09-18, the peer EDITS the enroller's source

the table above reads the steer as an instruction the peer *received*. a second dogfood, one day on,
proves the peer **acted on it**:

| # | fact | evidence |
|---|---|---|
| 1 | `@:wedge1` spawned with default roles, answered `reply with exactly: PONG` | `clone say` → `released` |
| 2 | 2m46s later its own transcript holds an `Edit` tool call | `c96bc868-…jsonl`, its `timestamp` 2m46s past the reply |
| 3 | the target is `computeCloneInputState.ts` — a file the ENROLLER held open mid-edit | the `old_string` is the enroller's own uncommitted docblock |
| 4 | 🔴 the edit did NOT land. the brain-cli's permission prompt halted it | `grepsafe 'BOTH halves are required' --path src` → 0 matches |
| 5 | and `clone say` REFUSED to answer that prompt | `withheld` / `modal-holds-focus` / `delivered: false` |

⇒ **rows 4 and 5 are why this is a near-miss rather than an incident**, and neither was designed for
this: a permission prompt the peer raised for its own reasons, plus this wish's own V3 refusal
(`case=6`). **two independent guards composed to save an uncommitted file.** remove either and the
enroller loses work with no report.

⇒ so the steer row's cost is understated. the true harm is **an unannounced concurrent writer in a
shared worktree**, and the harm table's `collision` row is about a passage ledger where it should be
about source.

### 🟡 the operator-level mitigation — available today, and now mandated

`--roles -driver` drops the role whose boot reads the bind, and it is already supported in both
argv forms (`rule.require.roles-flag-dual-format`):

```sh
npx rhx enroll claude --as @:peer1 --roles -driver --async
```

measured the same day: `@:nodrive1`, so enrolled, replied `PONG` and took no further act — no route
boot, no edit, no prompt.

⇒ **this does not retire the dream.** it is a call-site discipline, so it holds only where the
enroller remembers; the A/B/C fix below is what makes it structural. the discipline is enruled at
`.agent/repo=.this/role=any/briefs/rule.forbid.peer-clones-that-carry-the-driver-role.md`, booted at
`say` tier because the cue fires before the enroll command is typed.

## .the shape of the fix

the honest question is *which* clones a bind governs, and the bind was written before a clone could
enroll a peer at all — so the question had one answer and now has two.

| candidate | what it does | cost |
|---|---|---|
| **A — a peer is unbound by default** | the enroll spawn clears the bind for the child (an env opt-out the Stop hook reads) | the peer loses the route's guard rails, which a peer enrolled *to help on this route* may want |
| **B — the bind carries an actor** | `route.drive` emits the stone only to the actor the bind names | a truer model, and it touches the bind's own file shape |
| **C — an enroll flag** | `enroll --route inherit\|none` names it at the call site | explicit, and it pushes the call onto every enroller |

⇒ **B is the shape that matches the domain** — a bind already names a branch and a user, so an actor is
the axis it is short. A is the cheap stopgap and C is the escape hatch B would make unnecessary.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE — no.** it changes when `route.drive` emits at all, which is the mechanism every route on
  every branch depends on for its own progress. a wrong read there silently stops a human's drive
- **CLEAN — no.** it ripples across three subsystems this wish never opens: the bind file shape
  (`route.bind.*`), the Stop hook contract (`route.drive --when hook.onStop`), and the enroll env
  handoff (`asCloneDetachHostArgv`, the spawn env)

⇒ so it is a dirt deferral, and per that rule a dirt deferral owes a **fulcrum** beside this dream:
the choice among A/B/C is a wisher call, since B amends a contract (`route.bind`) outside this wish's
declared scope.
