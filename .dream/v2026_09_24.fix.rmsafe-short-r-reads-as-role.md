# 🌙 dream: `rhx rmsafe -r <dir>` reads `-r` as `--role`

- **kind** = fix
- **owner** = unsettled — the `rhx` skill dispatch in `ehmpathy/rhachet`, or the `rmsafe` arg parse in `ehmpathy/rhachet-roles-ehmpathy`
- **caught** = 2026-09-24

## .the cue that fired

a documented form in the `rmsafe` header failed on first use: `rmsafe.sh -r 'path/to/dir'  # recursive (like rm -r)`.
the named form `--path <dir> --recursive` worked.

## .the gap, precisely

`rhx rmsafe -r .agent/.actors/actor.via.slug=.default` did not remove the dir; the `-r` was taken as
`--role` before it reached the skill. the header of `rmsafe.sh` still advertises `-r` as the
recursive short flag, so the paved path fails.

checkable:

```
rhx mkdirsafe --path .temp/rmsafe-probe
rhx rmsafe -r .temp/rmsafe-probe          # expected: removed. observed: -r parsed as --role
rhx rmsafe --path .temp/rmsafe-probe --recursive   # removed
```

## .the shape of the fix

1. find which layer claims `-r`: the `rhx` dispatch (a global `-r` alias for `--role` applied before
   the skill's own args) or the skill's parse
2. if the dispatch: stop a parse of short flags after the skill name — args after the skill belong
   to the skill
3. if the skill: honor `-r` as the header says, or drop it from the header
4. clamp: a test that runs `rhx rmsafe -r <dir>` and asserts the dir is gone

## .why it is not done in this round

- **SAFE?** ✅ yes
- **CLEAN?** 🔴 no — the owner is not yet known, and either home is outside this route's diff (a
  dispatch change touches every skill's argv; a skill change belongs to another repo)
