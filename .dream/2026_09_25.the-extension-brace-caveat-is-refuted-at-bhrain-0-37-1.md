# 🌙 dream: a bind caveat three briefs repeat is false at the version we run

- **kind** = reseed
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-25

## .the cue that fired

`rule.always.diagnose-reviewer-malfunctions` carries this, verbatim:

> 🟡 **a `--paths-with` glob with a brace in the EXTENSION slot is silently dropped**
> (`'**/*.{ts,md}'` → the bind never applies and the reviewer runs unbounded); a brace in the
> **directory** slot (`'{src,blackbox}/**'`) works.

`rule.always.raise-a-blocker-a-taken-cannot-close` repeats it. a driver read it, believed it, and
spent a round on a root-cause hypothesis it made plausible.

## 🔴 .the gap, precisely — it is false at `rhachet-roles-bhrain@0.37.1`

the reviewer writes its own scope resolution to `input.scope.debug.json` before it validates. five
lanes bound `'**/*.{ts,sh,md,snap}'` and the artifact reports:

| the bind | `targetFilesFromPaths` | after the intersect |
|---|---|---|
| `'**/*.{ts,sh,md,snap}'` | **5,223** | 360 |
| `'**/*.test.ts'` + `'**/*.snap'` | 934 | 71 |
| `'{src,blackbox}/**/*.test.ts'` | 752 | 52 |

⇒ the extension brace expanded to 5,223 real paths. it applied.

🔴 **and the code refuses the failure mode the caveat describes.** in `stepReview.js`:

```js
if (!pathsRequested) return targetFilesFromDiffs;   // :344 — the ONLY unbound return
if (joinMode === 'intersect') {                      // :347
  const pathsSet = new Set(targetFilesFromPaths);
  return targetFilesFromDiffs.filter((file) => pathsSet.has(file));
}
```

`pathsRequested` is `positivePathGlobs.length > 0` — true whenever a `--paths-with` was passed, no
matter what it resolved to. so a glob that matched **zero** files takes the intersect branch against
an empty set, returns zero targets, and trips the empty-scope guard at `:383`.

⇒ **an unbound run is unreachable from a dropped glob.** the caveat's stated consequence cannot
occur by the stated mechanism.

## .why the mis-attribution is expensive

the caveat is **load-bearing in a diagnosis**, which is the worst place for a false one:

- it names a silent failure, so a driver cannot refute it by absence of an error
- it perfectly correlated with the five dark lanes here — every lane that carried the brace was
  dark, every lane without it ran — so the coincidence read as a cause
- ⇒ a driver who trusts it repairs the brace, sees the lane still overflow, and has spent a round
  on the one hypothesis the brief handed them

the true cause was mundane: the bind was **wide** (360 files, 1,226.9k tokens against a 1,048,576
token window), never broken.

## .the shape of the fix

1. **delete the extension-brace row** from `rule.always.diagnose-reviewer-malfunctions`'s bind
   caveat table, and from `rule.always.raise-a-blocker-a-taken-cannot-close`
2. **keep the unknown-flag row** — that one is real and untested here: an unrecognized flag name is
   dropped with no error and no warn, so a misspelled bind reads as applied
3. **replace the deleted row with the check that does work** — the reviewer writes
   `input.scope.debug.json` into its log dir on every run, **before** validation, so it survives a
   malfunction. it carries `args.pathsWith` beside `resolution.targetFilesFromPaths` and
   `resolution.targetFiles`. one read settles whether a bind applied, how wide it resolved, and what
   the intersect kept — no inference needed
4. if the caveat was ever true, **name the version it was true at**, so a reader can tell whether it
   applies to the bhrain they run

🟡 **step 3 is the part worth the most.** the briefs teach a driver to infer scope from the `.given`
summary line. the reviewer already writes the ground truth to disk, and no brief mentions it.

## .why it is not done in this round

graded against `rule.always.fix-forward-under-scouts-honor`'s two questions:

- **SAFE?** ✅ yes — a prose edit to a brief
- **CLEAN?** 🔴 no — the briefs live in `rhachet-roles-bhrain`, a different tree. a tree adopts only
  what is scoped to itself (`rule.always.scope-onetime-lessons-to-the-behavior`)

⇒ caught as a reseed rather than fixed here.
