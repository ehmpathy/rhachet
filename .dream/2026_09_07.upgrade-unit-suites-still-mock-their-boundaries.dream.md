# 🌙 dream: retire the two upgrade unit suites that still mock their boundaries

- **kind**: repair
- **owner**: ehmpathy/rhachet
- **caught**: 2026-09-07

## .the cue that fired

the `mech-test-scope-purity` lane (i001 r008) graded six blockers on
`rule.forbid.unit.remote-boundaries`. four were repaired in this branch. **two were not, and
both are files this branch never authored.**

## .the gap, precisely

two unit suites replace remote boundaries with `jest.mock`, and both patterns are present at
`origin/main` **verbatim** — confirmed by `git show origin/main:<path>`:

| file | what it mocks | at origin/main? |
|---|---|---|
| `src/domain.operations/upgrade/execNpmInstallGlobal.test.ts` | `jest.mock('node:child_process')` | ✅ yes, lines 6-8 |
| `src/domain.operations/upgrade/execUpgrade.test.ts` | eight collaborator modules + `jest.spyOn(console, 'log')` | ✅ yes, lines 8-30 |

so every `then` in each file asserts against the test's own `mockReturnValue` rather than
against a real call — the "mocks test the mock" failure mode the rule names.

⚠️ **`execNpmInstallGlobal.test.ts` is the sharper of the two.** it clamps that the global
install carries `--ignore-scripts` and a `timeout`, and those are exactly the arguments a real
`spawnSync` could reject or ignore. it is also the twin of `execNpmInstallLocal.test.ts`, which
this branch DID repair — so the pair now disagrees on discipline, which is its own small hazard
for the next reader.

## .the shape of the fix

**the pattern to copy is already in the tree, three files over.** this branch repaired the
same defect in four places, and each is a worked example:

| the repair | where to read it |
|---|---|
| split the command into a pure value, unit-test it with no mock | `asPnpmVersionProbeCommand.ts` + `.test.ts` |
| split the classification into a pure transformer | `asPnpmPresenceFromProbeResult.ts` + `.test.ts` |
| add an optional communicator seam, inject a typed fake | `execNpmInstall.ts`'s `options.spawn`, driven by `execNpmInstall.test.ts` |
| add an optional trace sink rather than spy a stream | `genCloneSocketServer.ts`'s `options.trace` |
| capture console output for real, never with a spy | `withCapturedStreams` (`src/.test/assets/`) |

so, concretely:

1. **`execNpmInstallGlobal.test.ts`** — give `execNpmInstallGlobal` the same `options.spawn`
   seam `execNpmInstall` now carries, and hand it a `genSpawnThatRecords` fake. `isPnpmAvailable`
   should reach for `getPnpmPresence` (which is now seam-injectable) rather than its own
   `spawnSync`.
2. **`execUpgrade.test.ts`** — the eight module mocks are a symptom of an orchestrator whose
   collaborators are imported rather than injected. the cure is one `options` bag of seams,
   defaulted to the real operations, and typed as `typeof <the real one>` so a stand-in the
   producer cannot emit is a type error. the `console.log` spy goes to `withCapturedStreams`.

## .why it is not done in this round

**SAFE:** yes — every change is additive (an optional seam, a defaulted option).

**CLEAN:** ❌ **no.** `execUpgrade.test.ts` is 1113 lines and `execNpmInstallGlobal.test.ts` is
823; a rewrite of both is roughly the size of this whole branch's source diff, in a subsystem
whose behavior this wish does not change. it would bury the node-pty repair under an unrelated
test-infrastructure overhaul and make the diff unreviewable — `rule.forbid.scope-leaks`.

⇒ so it is caught rather than done, and the fulcrum that records the deferral decision is
`inventory.of=fulcrums.case=F16-upgrade-suite-mock-debt`.
