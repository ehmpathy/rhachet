# 🌙 dream: `rhx init` and `rhx upgrade` never prune the settings backups they write

- kind  = chore
- owner = ehmpathy/rhachet
- caught 2026-09-25

## .the cue that fired

a human opened `.agent/.actors/actor.via.slug=.default/brain/.claude/settings.json` to ask why boot
hooks still fire, and the dir contents beside it showed **11 `settings.*.bak.json` files** across a
three-day span.

the question they asked was answered and is NOT this dream: the brief-boot hook is gone, the
transport moved to `CLAUDE.md -> AGENTS.md -> @boot.md`, and the three `SessionStart` hooks that
remain are role-declared (`route.drive`, `notify-permissions`, `boot-behavior`) with jobs unrelated
to briefs. the litter **beside** that answer is what this dream holds.

## .the gap, precisely

every `rhx init --hooks` / `rhx upgrade` that rewrites a brain dir's `settings.json` writes a backup
beside it and **never removes one**. the count grows without bound, per actor, forever.

checkable:

```sh
tree -a '.agent/.actors/actor.via.slug=.default/brain/.claude' -L 1
```

measured 2026-09-25 in the `beav/feat-boot-briefs-into-claude-md` worktree — 11 backups across
2026-09-22 → 2026-09-24:

```
settings.2026-09-22T17-31-46Z.bak.json
settings.2026-09-22T17-31-46Z.3642284.bak.json
settings.2026-09-24T05-22-56Z.3661778.bak.json
settings.2026-09-24T07-47-45Z.bak.json
…6 more
```

two name shapes appear — a bare clock-stamped one, and the same stamp plus a pid suffix — so a
single run can leave **two** files rather than one.

🔴 **it hides by construction.** `.agent/.actors/` is gitignored (`findsertAgentEphemeralGitignore`
declares the tree ephemeral), so no diff ever shows the growth and no reviewer meets it. only a
human who opens the dir by hand does — which is exactly how it surfaced.

## .the shape of the fix

cap the set at the write site, never by a sweep elsewhere:

1. **read the pid-suffixed twin FIRST.** if two backups per run is itself a defect, a prune papers
   over it rather than cures it. answer this before step 2, or the fix buries a second bug
2. find the writer — the temp-write + rename guard on the brain-dir settings path
3. after a successful rename, list siblings that match `settings.*.bak.json`, sort by name (the
   iso stamp sorts lexically, so name-sort IS time-sort), and unlink all but the N most recent.
   N = 3 is a defensible floor
4. **clamp it, and clamp the direction**: a unit that writes N+2 backups, runs the prune, asserts N
   survive — *and asserts the survivors are the NEWEST*. a prune that keeps the oldest passes a
   count-only assertion while it destroys the rollback a human actually wants

⚠️ step 4's second half is the whole clamp. a count-only row is the shape
`rule.require.clamp-edge-cases` calls a clamp with no teeth.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), both halves:

- **safe** — 🔴 **no.** it adds an unlink to a write path this branch already changed, and an unlink
  that picks the wrong survivors destroys a human's only rollback of their own settings
- **clean** — 🔴 **no.** it needs a new clamp plus a resnap of the acceptance tier that the
  `5.3.verification` stone is about to verify as byte-neutral — so it re-opens the one property the
  round rests on

both halves fail, so this is a **dirt** deferral rather than a size one, and it owes a **fulcrum**
beside this dream, never a dream alone.
