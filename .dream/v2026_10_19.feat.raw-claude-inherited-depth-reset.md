# 🌙 dream: a raw `claude` in a pane that inherited a clone's depth starts at depth 0

kind: feat · owner: ehmpathy/rhachet-brains-anthropic · caught 2026-10-19 · status: a planned pr

## .the cue that fired

execution of the spawn depth limit (`.behavior/v2026_10_07.fix-clone-spawn-depth-limit`) reached
fulcrum F7: reset the depth via `env` in the repo brain dir's settings. it measured the premises
before it relied on them, and one failed (F8).

## .the gap, precisely

- a tmux pane split from a clone's pane inherits `RHACHET_CLONE_DEPTH=1`
- a human opens a raw `claude` there. its tool shell has no tty and reads depth 1, so its guard's
  `rhx enroll claude -p …` mints depth 2 and is refused: `clone spawn depth limit reached`
- `rhx enroll` at the same tty is already cured, since a tty enroll is top-level. a raw `claude` is
  not an rhachet process, so no rhachet code runs before its tool shell inherits the var
- the cure today is manual. the refusal hint says to clear the `RHACHET_CLONE_DEPTH` env var

## .what already landed, in the rhachet pr

the strip. `asSettingsWithoutCloneIdentityEnv` drops every `RHACHET_CLONE_*` key from the `env` map
before `genBrainCliConfigArtifact` writes an enrolled clone's `--settings` file. a reset key in the
repo settings can no longer reach an enrolled clone. the guard is clamped by
`asSettingsWithoutCloneIdentityEnv.test.ts` and `genBrainCliConfigArtifact.integration.test.ts`
[case6]. so the supplier pr below can add the key and re-open no defect.

## .the planned pr

**title:** `feat(hooks): reset an inherited clone depth for a raw claude session`
**repo:** `ehmpathy/rhachet-brains-anthropic`

**the bounded diff:**

1. measure Q11 first. does a claude settings `env` key override a var the `claude` process already
   inherited? run `claude.cli.probe`, then a session whose tool shell echoes the var
2. if yes: `genBrainHooksAdapterForClaudeCode` findserts `env.RHACHET_CLONE_DEPTH = "0"` into the
   repo `.claude/settings.json`, and only there
3. if no: a SessionStart hook that writes `RHACHET_CLONE_DEPTH=0` to `CLAUDE_ENV_FILE`, in the
   repo scope only
4. clamp: case 7 [t3]–[t4] of the route's experience catalog. a raw claude in an inherited pane has
   a tool shell that reads 0, and its guard reviewer spawns at 1. an enrolled depth-1 clone's tool
   shell still reads 1, which the rhachet strip guarantees
5. a version bump of `rhachet-brains-anthropic` in rhachet, which carries no code change

## .why it is its own pr

the writer of the repo settings file is the supplier's hooks adapter, in a second package with its
own release. the rhachet half that needed to land first, the strip, is in. see fulcrum F8.
