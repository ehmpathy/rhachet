# 🌙 dream: a raw `claude` in a pane that inherited a clone's depth starts at depth 0

kind: feat · owner: ehmpathy/rhachet-brains-anthropic · caught 2026-10-19 · status: a planned pr,
its write path re-opened by #600

## .the cue that fired

execution of the spawn depth limit (`.behavior/v2026_10_07.fix-clone-spawn-depth-limit`) reached
fulcrum F7: reset the depth via `env` in the repo brain dir's settings. it measured the premises
before it relied on them, and one failed (F8).

## .the gap, precisely

- a tmux pane split from a clone's pane inherits `RHACHET_CLONE_DEPTH=1`
- a human opens a raw `claude` there. its tool shell has no tty and reads depth 1, so its guard's
  `rhx enroll claude -p …` mints depth 2 and is refused: `clone spawn depth limit reached`
- `rhx enroll` at the same tty does not cure it either: a tty with a depth var reads that var + 1
  (F13), so a clone cannot reset its chain through a fresh pty
- the cure today: a fresh terminal, which inherits no var. the refusal hint names that, and never
  names the var (to clear it by hand is the bypass)

## .what already landed, in the rhachet pr

the strip. `asSettingsWithoutCloneIdentityEnv` drops every `RHACHET_CLONE_*` key from the `env` map
when `genBrainCliConfigArtifact` writes any actor's `settings.of.repo.json`, the repo actor's
included. a reset key can no longer reach an enrolled clone at the `--settings` rank. clamped by
`asSettingsWithoutCloneIdentityEnv.test.ts` and `genBrainCliConfigArtifact.integration.test.ts`
[case7].

## 🔴 .why the planned write path no longer holds (#600)

#600 (`d91e8270`) gave every actor one brain dir layout. in it:

- `<repo>/.claude` is a link to the repo actor's brain dir, and its `settings.json` is the grove
  arrow to `~/.claude/settings.json`, the human's own file
- `settings.of.repo.json` reaches claude only via `--settings`, so only an enrolled clone reads it.
  a bare `rhx enroll claude -p` (a guard's reviewer) is a clone of the repo actor, so a reset key
  there would reset that reviewer to depth 0, the defect the wish names. the strip forbids it
- ⇒ a raw `claude` reads only the grove. no repo-scoped file reaches it, so the reset has no
  repo-scoped home. a write into `.claude/settings.json` would land in the human's home file

## .the planned pr — re-scoped

**title:** `feat(hooks): reset an inherited clone depth for a raw claude session`
**repo:** `ehmpathy/rhachet-brains-anthropic`

1. measure Q11 first. does a claude settings `env` key override a var the `claude` process already

   beyond the fresh terminal

   a tool shell that reads 0, and its guard reviewer spawns at 1. an enrolled depth-1 clone's tool
   shell still reads 1, which the rhachet strip guarantees
