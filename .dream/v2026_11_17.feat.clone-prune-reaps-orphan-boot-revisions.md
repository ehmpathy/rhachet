# 🌙 dream: clone prune reaps boot revisions no clone refers to

kind = feat · owner = rhachet · caught 2026-11-17

## .the cue that fired

the vision of `.behavior/v2026_11_17.feat-live-clones-take-boot-drift` adds
`.agent/.actors/<actor>/boots/sha256=<h>/`, one per boot revision a clone spawned on. naught removes one.

## .the gap, precisely

a revision dir outlives the last clone whose `boot.spawned.ref` names it. each holds a full copy of a
boot (441,263 chars for the repo actor, 2026-11-17), and the render re-writes its delta on every
`rhx init`.

## .the shape of the fix

`clone prune` (plan by default, `define.invariant.clone-prune-safety`) also lists each `boots/sha256=*/`
that no `clones/serial=*/boot.spawned.ref` names, and reaps it on apply. a revision referred to by a
DEAD clone stays until that clone is pruned, so a wake keeps its baseline.

## .why it is not done in this round

the wish is a p0 fast follow due the same day; the growth is one dir per spawn revision, slow, and
harmless until disk matters.
