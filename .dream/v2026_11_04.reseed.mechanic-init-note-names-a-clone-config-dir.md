# 🌙 dream: the mechanic role init's note names a clone's "config dir"

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (the mechanic `init.claude.permissions` output)
- caught 2026-11-04, in `.behavior/v2026_11_02.fix-boot-briefs-cacheable` 5.3 self review 4

## .the cue that fired

the resnap of `blackbox/cli/__snapshots__/init.incremental.acceptance.test.ts.snap` (a role bump, not
this branch's code) adds this line to the mechanic init output:

```
note: this clone's config dir is $REPO_ROOT/.agent/.actors/actor.via.repo=ambient/brain/.claude; its settings.of.repo.json is derived from this file. ...
```

## .the gap, precisely

- `rule.forbid.clone-config-misnomer`: a clone has no config dir; it reads its actor's **brain dir**.
  the path printed is the repo actor's brain dir
- `rule.forbid.colons-in-stdout`: `note:` is a label run on into its detail
- the claim "its settings.of.repo.json is derived from this file" is stale under the split layout:
  since `rhachet-roles-ehmpathy >= 1.40.0` the init writes `settings.of.repo.json` by name
  (`inventory.of=requirements.case=8`), so there is no second file to derive from

## .the shape of the fix

in the mechanic init's output, a treestruct leaf in place of the note:

```
🔐 mechanic permissions configured successfully!
   ├─ .claude/settings.of.repo.json
   ├─ .claude/settings.of.repo.$TIMESTAMP.bak.json
   └─ the repo actor's brain dir holds it; each actor picks up new allows at its next rhx init --hooks, rhx upgrade, or rhx enroll
```

then this repo resnaps `init.incremental.acceptance` on the bump that carries it.
