# 🌙 dream: a hook sync with no hooked role prunes the stale rows its last role left

kind = fix · owner = rhachet (`src/domain.operations/init/hooks/`) · caught 2026-11-27

## .the cue that fired
a role dropped its `hooks` key. `rhx init --hooks` printed `🫧 no roles with hooks found`, and the
manifest kept the rows that role wrote.

## .the gap, precisely
the hookless branch of `syncHooksForLinkedRoles` settles the root's wires (F11, in #847): it repairs a
corrupt manifest and takes back wires at an absent one. it does not prune role rows whose author is no
longer linked, and it skips the enrolled-actor pass. so a seat whose last hooked role drops its hooks
still runs that role's rows. this is the same on main, and the `*` wire does not change it: the
dispatcher filters each row by its own matcher, so a stale row fires on the same calls under either
wire shape.

## .the shape of the fix
in the hookless branch, run the orphan prune for every role-authored row, with an empty desired set. do
it through the manifest adapter, without the one-time migration, so no manifest is written where none
is. then run the actor pass. clamp: [case8] with a readable manifest whose role leaves. its row must be
gone after the sync. red without, green with.

## .why it is not done in this round
the `*` wire leaves this harm as it was (S3), and the prune's adapter path runs the migration, which
would write a manifest into every hookless claude repo. a prune that skips the migration is its own
change, with its own clamp.
