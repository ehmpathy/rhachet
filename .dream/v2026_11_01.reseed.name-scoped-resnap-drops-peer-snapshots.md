# 🌙 dream: a name-scoped resnap must not delete the snapshots outside its scope

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=git.repo.test)
- caught 2026-11-01

## .the cue that fired

`rhx git.repo.test --what acceptance --scope 'path://blackbox/cli/keyrack.fill' --scope 'name://case7b' --mode apply --resnap` passed (8 passed, 46 skipped), and the diff of the `.snap` file showed the `[case8]`–`[case11]` entries deleted. the tests still exist; jest `-u` treats every snapshot of a skipped test as obsolete and removes it.

## .the gap, precisely

`--resnap` with a `name://` scope passes `-u` together with `--testNamePattern`. under that pair jest writes the scoped snapshots and deletes the rest of the file. the run reports green, so the loss is silent until a reviewer reads the diff, or cicd runs with `--ci` and fails on absent snapshots.

## .the shape of the fix

when `--resnap` meets a `name://` scope, pass `--ci=false -u` with jest's obsolete-snapshot removal off. jest has no flag for that, so the cure is one of these:
- refuse `--resnap` with a `name://` scope, and name the fix: resnap by `path://` only
- or, after the run, restore any snapshot key that was removed while its test was skipped

plus a clamp: a fixture suite with two named cases, resnapped by one name; assert the other's snapshot survives.

## .why it is not done in this round

the skill lives in another repo's role package; a fix here would be a fork of its code. recovery here: a run without resnap rewrote the dropped entries, byte-identical to HEAD.
