## .the shape of the fix

```
src/domain.operations/boot/
  source/   getOneBootSource + its 4 arms, BootSource, getOneBootSourceFromSpecPath
  spec/     parseRoleBootYaml, readOneBootSpecFile, computeBootMode, computeBootPlan, isBootSpecForeign
  payload/  genBootPayload + the as* render leaves, getAllBootSayResources, filterBootResourcesByGlob
  budget/   assertBootWithinBudget, getOneBootBudgetRung, asBootOverageLines, asBootRemedyMode
  cost/     getAllRepoBootSpecCosts, asBootCostReadout, asBootCostSweep*
```

**the dependency direction is the point, not the folders.** `source → spec → payload → budget`, with
`cost` a peer consumer of `spec` + `payload`. once that holds, a cross-concern import is a
**directory** boundary a reviewer checks mechanically, rather than a convention re-verified by a
re-read of 36 files every round.

### what must be clamped

- `[caseN]` `dpdm` reports no cycle across the five sub-namespaces — the extant lint gate already
  runs it, so this is a re-use rather than a new instrument
- `[caseN]` the `GLOBS_DEFAULT` unification: add a spec location to the source resolver and the
  sweep MUST see it. **proved by revert** (`rule.require.clamp-edge-cases`) — restore the hand-list
  and the case goes red
- every migrated snapshot carries over **byte-identical**, which is what proves the move changed no
  behavior it was not meant to (the i016 split used exactly this check)

## .why it is not done in this round

**SAFE 🟡 / CLEAN 🔴.**

- 🟡 **not fully safe** — the parse path (`spec/`) is flowed through by **every extant role boot**,
  and item 3's shared-key authority is a change to it on a round that seeks to close
- 🔴 **not clean by a wide margin** — ~36 source files move, every importer updates, and the diff
  touches essentially the whole feature. that is the *smuggled refactor* shape
  `rule.prefer.scouts-honor`'s CLEAN question exists to refuse

⇒ and the honest counter-pressure: **a move-only diff of 36 files is expensive to review and cheap
to get right**, so the argument against it is review cost rather than risk. that trade deserves a
fulcrum in the round that takes it up, not a silent yes or no here.

## .what to do first, when it is taken up

1. **move only** — no rename, no logic edit, one commit. the snapshots prove it
2. then item 2, the `GLOBS_DEFAULT` unification — it is the item with a nameable harm (a silent
   undercount) and it is the one the split exists to make possible
3. then items 1, 3, 4 opportunistically, each now a within-concern extraction rather than a
   cross-directory one
