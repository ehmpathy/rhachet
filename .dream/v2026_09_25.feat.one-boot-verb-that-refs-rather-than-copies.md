# 🌙 dream: ONE boot verb — `rhx boot --manifest $x` — whose output REFS rather than copies

- kind  = feat
- owner = **ehmpathy/rhachet** (the verb + the render) · **ehmpathy/rhachet-roles-bhuild** (the hook it thins)
- caught 2026-09-25

## .the cue that fired

a driver on this route argued a `boot.yml` point from a `grep` of `src`, got it wrong, and was told to
read the blueprint and the vision. it had read neither — the `sessionstart.boot-behavior` hook emitted
**108,425 bytes** and the brain received **~2,048** of them, a preview plus a file path. **~2% arrived.**

that exposed a second transport with the exact defect this route was built to repair — and the design
question that followed reframed the whole thing: one boot verb, invoked per manifest, whose output is a
list of **references** rather than a pile of copies.

## .the two measurements this dream rests on

```
     9  .agent/.actors/actor.via.slug=.default/brain/.claude/AGENTS.md    <- the door
930186  .agent/.actors/actor.via.slug=.default/brain/.claude/boot.md      <- inlined copies
```

**930KB of copies behind a 9-byte door.** and:

```
SessionStart:compact hook success: <persisted-output>
Output too large (102.3KB). Full output saved to: …/hook-9ebc4a4d-…-stdout.txt
Preview (first 2KB):
```

⇒ two corpora, two transports, two size problems — and one shape that repairs both.

## 🔴 .the gap, precisely — there are TWO renderers with TWO output shapes

| corpus | rendered by | output shape | its failure |
|---|---|---|---|
| **role** — the enrolled roles' briefs | `rhx init --roles\|--hooks` · `rhx upgrade` · `rhx roles link` | a **file** of inlined bodies | 930KB; and every body is a **copy** that lies until re-rendered |
| **behavior** — wish · vision · blueprint | `sessionstart.boot-behavior`, a bhuild init executable | **stdout** | a harness size cap truncates it to 2% |

⚠️ neither failure is the corpus's fault. one is a **copy** problem, one is a **channel** problem, and a
single output shape answers both.

## .the shape of the fix

### 1. one verb — `rhx boot --manifest $pathToBootYml`

it takes any `boot.yml` and compiles it. the callers become thin:

| caller | today | after |
|---|---|---|
| `rhx init` · `upgrade` · `roles link` | assemble the role corpus inline | `rhx boot --manifest <role boot.yml>` |
| the driver's `onBoot` hook | cat a 102KB corpus to stdout | **upsert a registration** — see §4 |

🔴 **the size cap disappears because the CHANNEL changes, never because the corpus shrank.** the hook
stops being a **transport** — the bytes never cross stdout at all. that is the same move this route
already made for briefs, applied one level out.

⇒ and it is a rung climb: the hook today does its own assembly (🔩 rung 3 — it reads a bind, walks
artifacts, concatenates). after, it is one deterministic call (🪨 rung 4), and the assembly is tested
once in the verb rather than once per hook (`philosophy.entoolment-is-the-pinnacle`).

### 2. 🔴 the output REFS the source — `@path/to/brief.md.min` — rather than copying its body

the render emits, per manifest entry:

| tier | emitted | resolved by |
|---|---|---|
| `say` | `@.agent/repo=$r/role=$o/briefs/$b.md.min` | the cli's own `@`-import, against the **live source** |
| `ref` | a bare path, unprefixed | a human or brain, on demand |

what it buys:

- 🔴 **no staleness.** a copy lies the moment a brief is edited; a reference cannot. today `boot.md` is
  correct only between a brief edit and the next `rhx init`, and **naught reports that window**
- **930KB → ~N lines.** a human can read `boot.md` and see what a clone was given
- **the two tiers collapse to one mechanism** — the difference becomes the `@` sigil alone, rather than
  two code paths (inline a body vs print a path)
- **one output shape for ANY manifest**, which is precisely what makes the behavior corpus ride the same
  verb with no special case

### 3. the per-tree registry — a gitignored dir of symlinks

a tree registers an extra manifest by symlink into a gitignored dir; `rhx boot` compiles each into a
`boot.also.md` the door references beside `@boot.md`.

✅ **the precedent is exact and already in this repo:**

```
.agent/.actors/.gitignore     -> /*  + an allowlist   (the actor dir is tree-local by declaration)
<brainDir>/.claude/.gitignore -> boot.md              (the rendered corpus is never tracked)
```

so *gitignored ⇒ tree-local* is the mechanism this route already ships. the split is the right one: the
symlink **target** (`.behavior/$slug/boot.yml`) stays **tracked** — reviewable, shared — and only the
**binding** is tree-local.

⚠️ **and it answers the third-grain question the actor/clone model could not.**
`catalog.of=actor-clone-design`'s test — *"does this derive from `{ brain, roles }`, or from THIS RUN?"* —
returns **neither** for a behavior corpus: it derives from the **tree**. a gitignored per-tree dir names
that grain without a new concept, because the filesystem already keys it.

🔴 **and the tree key is narrower than a whole new dir — see §5.** the actor dir is itself untracked, so
it is already tree-local; the registry's real key is **tree × actor**, and both halves exist on disk
today. `rule.forbid.per-clone-config` is untouched either way: what is registered derives from the tree,
never from a clone's run.

⚠️ one verdict owed: the extant route bind (`.behavior/$slug/.bind/$branch.flag`) is **tracked** and keyed
by **branch**. a gitignored registry is keyed by **tree** and does not survive a fresh clone. two bind
mechanisms with different survival wants one decision, never two accidents.

### 4. 🔴 the hook becomes a REGISTRAR — `set` / `del` over what is bootable

the driver's `onBoot` hook does not render and does not transport. it **reconciles the registry with
reality**: it upserts which manifests this tree boots.

```sh
rhx boot.also set --manifest .behavior/$slug/boot.yml   # register — this tree boots it
rhx boot.also del --manifest .behavior/$slug/boot.yml   # deregister — idempotent, no-op if absent
rhx boot.also get                                       # what does this tree boot?
```

that lands squarely on the extant verb quad (`rule.require.get-set-gen-verbs`): `get` reads, and
`set` / `gen` / `del` are the idempotent mutation triad. a tree's boot set is a **declared existence
state** — exactly what `gen` ↔ `del` are for, ensure-present ↔ ensure-absent.

🔴 **the cost per boot goes from O(corpus) to O(1).** today every SessionStart re-transports 102KB.
after, it writes or confirms one symlink, and the corpus reaches the brain through the door.

🔴 **and `del` is the half that is absent today, with a real consequence.** when a route finishes or a
branch is abandoned, the bind lingers and the hook keeps transporting a dead behavior's corpus — because
deregistration is an *absence* rather than an *act*. the quad's own mirror prompt catches it: *"if you
can gen it, can you del it?"*

⚠️ a registration change is still only **seen** at the next door read (session start · `/compact`), so
this does **not** deliver the volatile half. the live stone stays on the Stop append, where invariant 3
holds it. the registry carries what is bootable; `route.drive` carries where we are.

### 5. 🔴 the bind is `rhx boot set --manifest $x --for @<actorSlug>` — and it REFUSES an over-budget corpus

```sh
rhx boot set --manifest .behavior/$slug/boot.yml                  # --for omitted = the DEFAULT actor
rhx boot set --manifest .behavior/$slug/boot.yml --for @self      # 🔴 the caller's OWN actor — the hook form
rhx boot set --manifest .behavior/$slug/boot.yml --for @foreman   # a named actor's door, in this tree
rhx boot del --manifest .behavior/$slug/boot.yml --for @self      # idempotent, a no-op if absent
rhx boot get --for @self                                          # what does this actor boot, here?
```

⚠️ **this supersedes §4's `boot.also` verb name** — one command carries the whole quad, rather than a
second namespace beside it.

#### 🔴 `--for @self` — the caller names itself, so a hook never PICKS an actor

a hook fires **inside** a clone, and a clone already knows whose config it reads: `CLAUDE_CONFIG_DIR`
points at `<actorDir>/brain/.claude`. so the reflexive form costs no lookup and admits no wrong guess.

🔴 **without it, §5 as first written has a defect.** a hook told to pass `--for @<slug>` must first
discover which actor it runs as — and an **enroll** actor has no slug at all (it is
`actor.via.hash=$hash`, `define.enrollment-identity-is-the-roleset-hash`). so the flag would be
unfillable for exactly the actors `rhx enroll` mints, which is most of them.

| caller | the form it uses | why |
|---|---|---|
| an `onBoot` hook | `--for @self` | it IS the actor; a choice would be a guess it need not make |
| a human, for one actor | `--for @foreman` | an explicit door, named |
| a human, for the tree | omitted → the default actor | the repo door, which a bare clone also reads |

#### 🔴 the fan-out is STRUCTURAL — the role's enrollment set is the loop

the hook is declared by a **role**, and `genBrainCliConfigArtifact` projects each actor's hook set
filtered to the roles that actor enrolled. so a `driver`-declared `onBoot` hook exists only in the
settings of actors enrolled as drivers, and it runs only there.

⇒ **five actors enrolled as drivers means five hook invocations, each `--for @self`, each into its own
door.** the hook never asks how many there are.

| the alternative | what it must know | how it breaks |
|---|---|---|
| a tree-wide registry | the full actor set in this tree | an actor enrolled after the write is missed until a sweep |
| a hook that enumerates actors | the set, and which of them want this | it duplicates the filter `genBrainCliConfigArtifact` already applies |
| 🔴 **`--for @self`, once per invocation** | only itself | naught to miss — the projection IS the loop bound |

that is the sync invariant read forward: the registration set and the enrollment set are **the same set,
by construction** rather than by a reconcile pass. and it collapses §3's per-tree dir from a fan-out
mechanism to a plain per-actor record: each door holds its own, and `rhx boot get --for @self` reads one.

⚠️ 🔴 **but the `del` half inverts, and this is the sharp edge.** an actor that drops the `driver` role
loses the hook — so the hook never runs again, so `del` never runs, so its registration **lingers with no
declarer left alive**. deregistration cannot be the job of a hook that no longer exists.

⇒ the extant pavement answers it: `pruneOrphanedRoleHooksFromAllBrains` already sweeps hooks whose
declarer role is gone, on `rhx init` · `upgrade` · `roles link`. a registration wants the same treatment,
which means it must **record which role declared it** so the sweep can tell an orphan from a live bind.

⚠️ **`@self` must fail loud outside a clone, never fall back.** in a bare shell there is no ambient brain
dir, so a silent fall-through to the default actor would let a hook that lost its env rebind the **repo**
door for every actor in the tree. an absent ambient actor is a `ConstraintError` that names the fix
(`rule.require.failfast` · `rule.forbid.unexpected-defaults`).

🟡 two small consequences of a reserved word: `actors.yml` must refuse to declare an actor named `self`,
and the address stays `@self` rather than `@:self` — it names the **actor** whose corpus this is, and a
clone-grain form would invite exactly the per-clone copy `rule.forbid.per-clone-config` bars.

#### 🔴 a correction — the actor dir is ALREADY tree-local, so no new grain is owed

the peer dream argues a tree-bound corpus cannot sit in the actor dir, since an actor is reachable from
many trees. **that argument is wrong, and one file settles it:**

```
.agent/.actors/.gitignore  ->  /*   !/.gitignore   !/actor.via.slug=.default/
```

every actor dir but the default is **untracked**, so it never crosses a tree at all — worktree A and
worktree B hold separate `.agent/.actors/` even for one identical hash. and the default actor's dir,
though tracked, gitignores its own `boot.md`. ⇒ **every rendered corpus on disk is tree-local today.**

so `--for @<slug>` needs no new dir. the registry's key is **tree × actor**, and the filesystem already
holds both halves — which closes the peer dream's *"per role, or per tree?"* sub-question in favor of
per **actor**, the grain the door itself lives at.

#### what `--for` buys, past a mere scope

| it answers | how |
|---|---|
| **whose door composes this** | the door is `<actorDir>/brain/.claude/AGENTS.md` — per actor. a tree-wide registry must fan out to every actor dir at boot; an actor-scoped one writes one door |
| **what a bare clone gets** | `--for` omitted = the default actor, whose brain dir **is** `<repo>/.claude` (`define.brain-dir-repo-vs-actor`). the repo door carries it, so an unenrolled claude inherits it — by decision, never by accident |
| 🔴 **which window the budget is measured against** | an actor names its brain (`actor.json` = `{ brain, roles }`). a bind with no actor cannot know the window it must fit; `--for @<slug>` is what makes the budget computable at bind time |

#### 🔴 why the budget belongs HERE — a ref hides size, and the bind is the one place that looks

§2 turns the corpus into a list of refs. that repairs the channel cap and the staleness, and it **hides
the magnitude**: a 40-line `boot.md` can pull 900KB behind it. a human who reads the file sees a tidy
index; the clone pays the whole bill.

⇒ **the budget guard is not an addition to the ref design. it is the counterweight the ref design
demands.** the file's own size stops serving as a proxy for the corpus's size, so a mechanism must
measure the expansion — and the bind is where a human acts, so it is where a refusal reaches whoever
caused it.

that is `rule.prefer.prevent-over-correct`'s ladder, read honestly:

| rung | where | what it costs a human |
|---|---|---|
| 3 — catch it early | 🔴 **`rhx boot set` refuses the manifest** | one command, one message, before a clone exists |
| 4 — report it well | a spawn-time halt | a clone that will not boot, plus a diagnosis backwards to a bind made hours earlier |

⚠️ **two gates, never one.** the bind refuses a manifest you are about to add; a source can still grow
after a clean bind, so the spawn-time halt stays as the backstop
(`v2026_09_24.feat.halt-a-spawn-whose-corpus-exceeds-the-model-window`). `rhx roles cost` is the
measurement both gates read.

## 🔴 .the three risks — each stated, one of them load-bearing

### (a) 🔴 does `@` recurse from an IMPORTED file? — this gates everything

`CLAUDE.md` → `AGENTS.md` → `@boot.md` is **proven**; this route shipped it. whether `boot.md`'s own
`@brief.md` resolves is a **second hop**, and it is unmeasured. claude code documents nested
`CLAUDE.md` imports to a max depth of 5, so it likely does.

⚠️ **but if it does not, `boot.md` becomes a list of paths nobody reads and the corpus vanishes in
silence** — the worst failure shape there is, since the render succeeds and the tests pass.

⇒ **this is a ~10-minute probe and no line should be written before it.** the probe: render one `@ref`
into a brain dir's `boot.md`, spawn a clone, ask it for a fact that lives only in the referenced brief.

### (b) 🔴 the cache boundary MOVES — a deliberate consequence, not a surprise

| | today | after |
|---|---|---|
| what busts the prefix | a **re-render** (`rhx init`) | a **brief edit**, on the next session |

that is *more* correct — a clone reads the brief that exists rather than the brief that was current at
render time. and it is **not** a mid-session bust, so invariant 3 (*"an append cannot bust a prefix"*)
stands untouched.

⚠️ but the render step stops being the cache boundary, which is a change to the model this route just
shipped. it wants a verdict in the vision, not a discovery later.

### (c) tier legibility

`@path` = say, bare `path` = ref is clean to a machine and opaque to a human. the render should label
the two groups, so a reader can see the say/ref budget the manifest declared
(`rule.prefer.rules-that-refout` depends on that split being legible).

### 🟡 a hazard checked and probably already answered

this repo's briefs are full of `@mechanic` / `@:driver` literals (`define.address-sigils`). if
`@`-resolution choked on those it would **already** be broken, since `boot.md` inlines those bodies
today — so they are presumably ignored as non-paths. worth one confirming look, since a ref-emitting
`boot.md` puts more `@`s at line starts.

## 🔴 .the normal `boot.md` must move too — or the verb is a fiction

the whole value of `rhx boot --manifest $any` is **one verb, one output shape, two corpora**. if the
role render inlines bodies while the behavior render emits refs, there are two boot dialects wearing one
command name, and every later consumer must ask which it got.

⇒ so this is not "refs for the new corpus, copies for the old one." it is one render, and the role
corpus is its first subject.

## .the open sub-questions left

§5 closes two of the peer dream's four (the actor key, and what a bare clone gets). what remains:

- 🔴 **risk (a) — does `@` recurse from an imported file?** the probe below gates every line of this
- **how the door composes two sources** — the actor's role corpus and the tree's registered corpora both
  reach one clone. `AGENTS.md` holds one `@boot.md` today; two refs, or one rendered union?
- ⚠️ **which bind mechanism survives** — the extant `.behavior/$slug/.bind/$branch.flag` is **tracked**
  and keyed by **branch**; a `rhx boot set` registry is untracked and keyed by **tree × actor**. two
  mechanisms with different survival wants one decision, never two accidents
- **what the budget's units are** — a byte cap, a token count, or a fraction of the actor's brain window.
  `rhx roles cost` already measures one of these; the bind must refuse against the same number

## .why it is not done in this round

- the route is at `5.5.playtest`, arrived and halted on human approval. this changes **what `boot.md`
  is** — the central artifact of the route — so it is neither SAFE nor CLEAN at the final gate
- 🔴 it turns on an **unmeasured resolver property** (risk (a)). a fix that rests on an unprobed
  assumption is not ready to be written
- it spans **two repos**: the verb and the render are this repo's; the hook it thins is
  `ehmpathy/rhachet-roles-bhuild`'s (`rule.always.scope-onetime-lessons-to-the-behavior`)

## .the lesson beneath it, for a durable rule

> **a corpus transported by copy has two failure modes a reference does not: it goes stale, and it is
> bounded by its channel.** the copy's size is the channel's problem; the copy's age is no one's, which
> is why it goes unreported.
