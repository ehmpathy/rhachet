# 🌙 dream: scope the vendor keys to the live suites, so a missed reach finds no credential

- kind = feat
- owner = rhachet
- caught 2026-10-31

## .the cue that fired

a peer review noted that `jest.integration.globalSetup.ts` and `jest.acceptance.globalSetup.ts`
source the `role=test` `env.test` keys into every suite, so any reach the registry misses bills
silently, since the credential is already there.

## .the gap, precisely

- `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` and `XAI_API_KEY` reach every suite of a run
- only the tier-2 suite and the gated tier-3 suites read them
- cicd's `keyrack firewall` lifts the keys for the whole job
- the clamp is a list of known shapes; a shape it lacks meets a live credential

## .the shape of the fix

1. globalSetup unlocks no vendor key
2. the tier-2 suite and the gate source the key themselves (a lenient `useKeyrack`, or a
   `getContextOpenAI`-style getter read on use)
3. an unregistered reach then finds no credential and fails loud
4. cicd narrows the firewall lift to the tier-2 run
5. a first, smaller step for cli children: `asEnvForSpawn` (the one owner of the harness child
   env) and the pty spawner strip each `BRAIN_AUTH_ENV_KEYS` key that bills the api, as they strip
   the runner's clone identity; `enrollRealClaudeAndWaitReach` and `[case2f]` set it back through
   `env`. the api-billed notice then leaves the host-dependent output, and its three masks go

## .why it is not done in this round

it changes how every live suite and the cicd job obtain a credential, a cross-cut the fulcrums
(F1) weighed only at globalSetup; it needs its own design and a commander call on the cicd step.
