# 🌙 dream: the `rhx` shorthand cannot reach `roles`

- **kind** = feat
- **owner** = `ehmpathy/rhachet` — `bin/rhx`
- **caught** = 2026-09-25

## .the cue that fired

review 6 of stone `5.3.verification` (`has-critical-paths-frictionless`) walked `rhx help` and then
tried `rhx roles boot` on the same shorthand. the walk ruled it **out of scope as a friction** and
owed this dream as the record of the call.

## .the gap, precisely

`bin/rhx` short-circuits a fixed verb set before its fallthrough:

```
help|--help|-h · list · keyrack · upgrade · enroll · actor · clone · init
   … all else → exec "$SCRIPT_DIR/run" run --skill "$@"
```

`roles` is **not** in that set, so `rhx roles boot --repo .this --role any` degrades into
`run --skill roles` and fails with *no skill "roles" found*. the canonical form works:

```
npx rhachet roles boot --repo .this --role any   # ✅
npx rhx      roles boot --repo .this --role any   # ✋ no skill "roles" found
```

⚠️ **this is a reachability-parity gap, not a broken promise.** `rhx help` does not advertise
`roles`, so no contract is violated — the shorthand simply covers less of the cli than the full
binary does, and a human who learned `roles` from `rhachet --help` meets a rejection they cannot
place when they reach for the shorthand.

## .the shape of the fix

1. add `roles)` to the `case` in `bin/rhx`, so it forwards to `run roles "$@"` (which `bin/run.bun`
   already dispatches to `run.bun.rhachet-roles.bc`)
2. add `roles` to the `rhx help` verb list, so the surface it advertises matches the surface it serves
3. clamp: an acceptance row that invokes `rhx roles cost --repo .this --role any` through the `rhx`
   binary and asserts exit 0 — `invokeRhachetCliBinary({ binary: RHX_BIN, … })` already supports it
4. while there: decide whether the fixed verb list should instead be **derived** from the registered
   command names, so the next command added cannot drift out of the shorthand

## .why it is not done in this round

- **SAFE?** ✅ yes — an added `case` branch cannot break the branches beside it
- **CLEAN?** 🔴 no — it touches the `rhx` dispatch table **and** the `help` text, neither of which is
  in this behavior's diff, and step 4 opens a design question (derive vs enumerate) the fix should
  settle rather than dodge
