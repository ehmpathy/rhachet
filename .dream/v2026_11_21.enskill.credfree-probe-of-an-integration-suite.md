# 🌙 dream: a skill that runs one integration suite through the credfree runner

- kind: enskill
- owner: rhachet (`.agent/repo=.this/role=any/skills/`)
- caught 2026-11-21

## .the cue that fired

the same five steps ran by hand more than ten times in one route: copy an `*.integration.test.ts` to `blackbox/cli/probe.<name>.acceptance.test.ts`, copy its snap, rewrite each `./x` import to `@src/...`, run `rhx test.acceptance.credfree --scope 'probe\.'`, then move the snap back and remove the probe.

## .the gap, precisely

the integration tier's globalSetup requires four brain api keys, even for suites that call no brain. on a host whose keyrack lacks them, `rhx git.repo.test --what integration` exits 2, so a driver proves an integration suite only through this hand-run copy. each copy risks a stale probe left in the tree, or a snap moved back from the wrong run.

## .the shape of the fix

either:
- a skill `test.integration.credfree --scope <path>` that does the copy, the import rewrite, the run, the snap return and the cleanup, and refuses to leave a probe behind on any exit; or
- a globalSetup that asks for the brain keys only where a suite in the run calls a brain (the cause, preferred)

## .why it is not done in this round

it touches test infra that every suite shares, which the wish does not reach. a change to globalSetup needs its own clamp and its own review.
