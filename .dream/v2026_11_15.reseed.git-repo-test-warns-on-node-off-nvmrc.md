# 🌙 dream: git.repo.test warns when the node it runs differs from `.nvmrc`

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic, `git.repo.test`)
- caught 2026-11-15

## .the cue that fired

a full impacted acceptance run showed 9 red suites. 8 were green when rerun under the node
`.nvmrc` pins; the box's default node was v24.21.0, the pin v22.21.0. no output named the gap.

## .the gap, precisely

`git.repo.test` runs under whatever `node` is first on the PATH. a version off the pin shifts
behavior a test can see:

- node 24 refuses (`connect EINVAL`) a long unix socket path that node 22 accepts
- node 24 adds a `module.exports` key to a cjs import's dynamic keys

the red reads as a product defect, and the cause is unnamed.

## .the shape of the fix

in `git.repo.test`, before the run: read `.nvmrc` if present, compare to `node --version`, and on
a mismatch print a `⚠️` branch that names both versions and the cure (`fnm use`, `nvm use`).
a warn, not a halt: a deliberate off-pin run stays possible.

this repo paves a stopgap meanwhile: `rhx test.as.ci <skill> …` runs a test skill under the pin.

## .why it is not done in this round

the skill lives in another repo; a change there is a reseed, dispatched to its owner.
