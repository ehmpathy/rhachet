## .the gap, precisely

- `rhx enroll claude --resume <id>` spawns on the actor's CURRENT boot revision
- the brain cli replays the system prompt the session first recorded, so that session holds the OLD
  bytes while its drift base is the new revision
- ⇒ its drift reads empty, and every edit between the first spawn and the resume is absent from the
  session with no word said

## .the shape of the fix

built once, then pulled; restore from the pr's history (pre-F7 tree) as a start:

- `asBrainCliResumeSessionId({ args })` — the session id from `--resume <id>`, `-r <id>`, or the
  joined `--resume=<id>`; null for a bare `--resume` (the picker)
- `getOneCloneBootSpawnedRefBySession({ actorDir, sessionId })` — the ref of the clone whose
  `history/` links `<id>.jsonl` (an `lstat`, so a dangled link still counts)
- `genCloneBootRevisionForSpawn` — on a resume, spawn on that ref's revision (its drift is already
  current: every render re-writes every revision's drift); else the current boot
- a miss (no clone record holds the session, or its revision was reaped) says so on stderr in one
  line, with the cure: respawn fresh to take the whole boot
- an unreadable ref fails loud with its path, before the brain cli starts
- proofs: unit over the flag forms; integration over carried · unrecorded · reaped · unreadable;
  `enroll.acceptance` case2 `[t1]` carried and `[t2]` uncarried

pairs with `v2026_11_17.feat.bare-resume-picker-says-its-baseline.md`, which needs this first.
