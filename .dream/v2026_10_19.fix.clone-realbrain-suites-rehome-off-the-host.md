# 🌙 dream: six clone realbrain suites still run a real claude on the host HOME

kind = fix · owner = `ehmpathy/rhachet` · caught 2026-10-19

## .the cue that fired

peer review r2 nitpick.1 at stone 5.3 of `v2026_10_15.fix-split-layout-local-settings-arrow`: that
branch moved one import in `blackbox/.test/infra/enrollCloneHarness.ts`, and the file still carries
`setRealClaudeFirstRunAccepted`, which writes the host `~/.claude.json`.

## .the gap, precisely

- `enrollCloneHarness.ts:369` — `setRealClaudeFirstRunAccepted` writes `join(homedir(), '.claude.json')`
- `enrollCloneHarness.ts:204` — the creds read off the host `~/.claude/.credentials.json`
- six suites call it and spawn a real claude on the host HOME: `clone.realbrain`,
  `clone.screen-dogfood.realbrain`, `clone.modalprobe.realbrain`, `clone.saybulk-probe.realbrain`,
  `clone.transcript-lag.realbrain`, `clone.joker.realbrain`
- `rule.require.real-brain-tests-in-isolated-tempdir-and-home` forbids all three (host HOME, a write
  to the host `~/.claude.json`, inherited `CLAUDE*` env)

## .the shape of the fix

1. `setRealClaudeFirstRunAccepted({ dir, home })` — write `<home>/.claude.json`; drop the host default
2. each of the six suites builds its home via `genIsolatedClaudeHome` (it links only the host
   credential) and passes `HOME` plus the dropped `CLAUDE*` vars into the enroll env, as
   `brain-config.grove-vs-repo.realbrain` does
3. run each suite scoped on a funded key; the clone socket path stays under `$XDG_RUNTIME_DIR`, so the
   new HOME does not move it

## .why it is not done in this round

dirty, not unsafe: the fix spans six suites the split-layout branch never touched, and each owes a
real-claude rerun to prove it. the branch's one edit to the harness is an import path. fulcrum F17 holds
the call.
