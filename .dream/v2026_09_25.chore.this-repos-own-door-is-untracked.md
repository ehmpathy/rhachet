## .the gap, precisely

`define.brain-dir-repo-vs-actor.md` states the contract:

> *"`AGENTS.md` and the `CLAUDE.md` symlink stay tracked in the default actor's dir, the one dir
> under `.agent/.actors/` that git sees."*

and `.agent/.actors/.gitignore` is written to make exactly that possible — it ignores `/*` and then
**negates** two paths so git can see them:

```
/*
!/.gitignore
!/actor.via.slug=.default/
```

⇒ the intent is unambiguous: the default actor's dir is **meant** to be tracked. in this worktree it
is not. `git status --untracked-files=all` lists five addable paths, every one of them `??`:

```
?? .agent/.actors/.gitignore
?? .agent/.actors/actor.via.slug=.default/brain/.claude/.gitignore
?? .agent/.actors/actor.via.slug=.default/brain/.claude/AGENTS.md
?? .agent/.actors/actor.via.slug=.default/brain/.claude/CLAUDE.md
?? .agent/.actors/actor.via.slug=.default/brain/.claude/settings.json
```

so a merge of this branch ships the **pre-feature** shape for this repo: a real `.claude/` directory
that holds a tracked `settings.json`, with no symlink, no `AGENTS.md`, and no door.

🟡 **the feature itself is not defective.** the journey acceptance test proves the whole behavior in a
tree where the door files ARE committed — `[t8.1]` runs `git add -A`, commits, clones, and asserts the
clone arrives with the symlink and no `boot.md`. the gap is this repo's own staged tree, not the code.

## .why the harm is bounded — and why it is still owed

`package.json:99` runs the repair on every non-CI clone:

```json
"prepare": "if [ -e .git ] && [ -z $CI ]; then npm run prepare:husky && npm run prepare:rhachet; fi",
"prepare:rhachet": "rhachet init --keys --hooks --roles mechanic behaver driver …"
```

⇒ a fresh clone that runs `pnpm install` — the standard install path — rebuilds the symlink and the
door. so no security, safety, monetary, reputation, or behavioral harm ships: the grade is **better**,
never urgent (`rule.require.grade-a-concession-by-its-harm`).

what is still owed is the **contract**: a brief this branch ships says the files are tracked, and they
are not. a reader who greps for the door in a fresh clone finds a brief that misreports it.

## .the shape of the fix

1. decide the intent explicitly — is this repo's own door a **tracked artifact** (what the brief and
   the `.gitignore` negation say) or a **built-on-install artifact** (what the tree does today)?
2. if tracked: stage the index change as one move — `git rm --cached .claude/settings.json`, then add
   `.claude` as a symlink (mode `120000`) and the five paths above
3. if built: amend `define.brain-dir-repo-vs-actor.md` so the brief stops to claim they are tracked,
   and say instead that `prepare` builds them
4. either way, clamp it — an acceptance case over a fresh `git clone` of THIS repo that asserts the
   chosen shape. today only the journey's own temp tree is clamped, never the real repo's index

## .why it is not done in this round

- **SAFE?** 🔴 no — a removal of `.claude/settings.json` from the index changes what every future clone
  of rhachet receives, and it touches the `moved:` migration path that `init.incremental` snapshots
- **CLEAN?** 🔴 no — it restructures the branch's staged shape (253 files already staged) from the
  playtest gate, which is not the diff this stone is in

⇒ a dirty deferral, so it owes a **fulcrum** beside this dream
(`rule.always.fix-forward-under-scouts-honor`), recorded as
`.fulcrums/inventory.of=fulcrums.case=F49-this-repos-own-door-is-untracked.md`.
