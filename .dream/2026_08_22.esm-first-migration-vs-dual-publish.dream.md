dream =

fix the CJS→pure-ESM wall (ehmpathy/rhachet#468) at its true root — a module-system
posture decision — instead of the per-dependency lazy-import ceremony we ship today.

---

## the wall (why we deal with this at all)

a CommonJS artifact CANNOT statically `require()` a pure-ESM package. rhachet publishes
CJS; `age-encryption` and `@octokit/auth-app` are `type: module` with no `require` export
condition. tsc down-levels our `import age from 'age-encryption'` → `require('age-encryption')`
in the shipped dist, so a consumer's CJS `require('rhachet')` (a jest CJS testEnvironment, or
a brain package's compiled CJS) throws `Must use import to load ES Module`, which silently
empties brain auto-discovery (#429 `atoms: []`).

## the tempting-but-WRONG root: dual-publish

dual-publish (ship both builds behind `exports: { import: dist-esm, require: dist-cjs }`)
does NOT fix #468. trace the two consumers:

| consumer | routed to | outcome |
|----------|-----------|---------|
| `import ... from 'rhachet'` (ESM) | dist-esm | native `import 'age-encryption'` stays ESM → loads ✅ (was never broken) |
| **`require('rhachet')` (CJS)** ← the #468 victim | dist-cjs | tsc still emitted `require('age-encryption')` → still throws ❌ |

dual-publish routes each consumer to a build by THEIR module system, but the CJS half is
still a CJS artifact that cannot statically require a pure-ESM dep. it helps the ESM
consumers (who were fine) and does no good for the CJS consumers (who break). net effect on
#468 = zero. dual-publish is a real ergonomics win (tree-shakeable ESM build, no interop
default-export weirdness) but it is ORTHOGONAL to #468 — a layer on top of the lazy fix,
never a replacement for it. a future traveler must not rediscover this dead-end.

## the genuine roots (only two, plus a tailwind)

1. **lazy `import()` — what we ship today.** keep CJS, defer each pure-ESM load to a runtime
   `import()` node handles as ESM. removes the static require (the literal cause), works for
   BOTH consumer kinds. now guarded by two real-node acceptance clamps
   (`keyrackEsmRequire` + `brainContextEsmRequire`) that fail loud on any NEW eager pure-ESM
   require, via a subpath-precise detector (`blackbox/.test/infra/detectEsmLandmine.cjs`).
   cost: a per-dep loader ceremony + the contained `new Function` indirection in
   `importEsmSafe`. this is a legit pragmatic root-guard — the equilibrium we are in.

2. **go ESM-only (drop the CJS build) — the actual dream.** then native `import` just works,
   no per-dep ceremony, no clamps needed. BUT this breaks every CJS consumer — including the
   brain-package-compiled-CJS `require('rhachet')` path that is CENTRAL to #468's own
   scenario — unless the whole ecosystem (brain packages + downstreams) migrates to ESM too.
   this is a multi-repo migration with real blast radius, not a rhachet-local change.

3. **the tailwind (defer, let it age out):** node ≥22.12 / ≥20.19 can `require()` a pure-ESM
   module (absent top-level await). as consumers upgrade, the throw ages out on its own. this
   is exactly why our detector reads static file TYPE, not "does require() throw" — so the
   clamps do not rot when this lands. but you cannot control consumers' node versions or their
   deps' TLA, so you cannot bet the fix on it today.

## the dream, scoped honestly

evaluate an ESM-FIRST rhachet posture, GATED on:
- node `require(esm)` maturity across the consumer floor we support, AND
- brain-package + downstream ESM readiness (they must load an ESM rhachet)

if/when both hold, ESM-only removes the lazy ceremony AND the clamps at once — the true
root fix. dual-publish may ride along as an ergonomics improvement but is EXPLICITLY NOT the
#468 fix.

until then, the lazy-import + clamp equilibrium stands: it fixes the literal cause and fails
loud on regressions. do not trade it for dual-publish (a no-op on #468) or for an
ESM-only flip (breaks the very CJS consumers #468 is about) before the ecosystem is ready.

## acceptance signal for the dream

a downstream repo's CJS jest test auto-discovers real brains with a PLAIN jest config (no
`NODE_OPTIONS`, no `transformIgnorePatterns`), AND rhachet ships no per-dep lazy-import
ceremony AND no esm-require clamps — because the wall no longer exists. that is the day the
dream is realized; today's lazy+clamp fix is the bridge to it.
