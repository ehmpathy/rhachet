## .the gap, precisely

| capability | what it does | discovery, today |
|---|---|---|
| `BrainAtom` | single API call, stateless | `getBrainAtomsByAnthropic()` |
| `BrainRepl` | tool-use loop, stateful session | `getBrainReplsByAnthropic()` |
| 🔴 **`BrainCli`** | **cli spawn, interactive terminal** | **no factory, no discovery, no type** |

checkable evidence, this worktree:

- `getAvailableBrains()` returns `{ atoms, repls }` — there is no `clis` key
- the cli spawn path is **not a capability**; it is three loose operations under
  `src/domain.operations/enroll/` — `asBrainCliSpawnArgs.ts`, `genBrainCliConfigArtifact.ts`,
  `enrollBrainCli.ts`
- `asBrainCliSpawnArgs.ts:3` names the seam and its cost in its own docblock: the flag order *"is a
  contract with the brain cli"* that *"deserves ONE named owner + a unit clamp on its exact order"*
  ⇒ **the file knows it is a capability boundary with no capability behind it**
- ⇒ so there is **no programmatic route to a cli brain**. `rhx enroll` is the only door, and an
  orchestrator that wants to set a config and spawn cannot compose one

## 🔴 .why this round makes it URGENT rather than merely nice

the boot-briefs work lands **four** more claude-specific facts inside that unowned seam:

1. `CLAUDE_CONFIG_DIR=<actorDir>` on the spawn **environment** (an env var, beside the flags)
2. `<actorDir>/AGENTS.md` as the corpus destination — a **claude filename**
3. a `pluginConfigs: { "agents-md@builtin": … }` key in the settings artifact — a **claude plugin id**
4. a `<actorDir>/CLAUDE.md` symlink (F7) — a **second** claude filename

each is correct, and each is a supplier detail that has no owner to live in. #398 had already drawn
the boundary they belong behind:

| adapter | responsibility | what this round would hand it |
|---|---|---|
| `BrainCliConfigBootsAdapter` | read/write boot content | the rendered corpus, its filename, the symlink |
| `BrainCliConfigHooksAdapter` | read/write hooks config | `settings.json`, and now `pluginConfigs` |
| `BrainCliConfigAuthAdapter` | read/write credentials | the relocated `.credentials.json` |

⇒ **without the promotion, `rhachet` core accretes claude trivia it cannot name.** a second cli —
cursor, opencode, codex — has no seam to enter through.

## .the shape of the fix

follow #398's design, corrected where this round's evidence moved it:

1. **publish the interfaces in core** — `BrainCli`, plus the three `BrainCliConfig*Adapter`s, plus
   one `setBrainCliConfig({ roles, scope }, { adapters })` orchestrator
2. **suppliers implement them** — `rhachet-brains-anthropic` exports
   `getBrainClisByAnthropic()` and `genBrainCliForClaudeCode({ slug })`, and owns every claude fact
   above
3. **widen discovery** — `getAvailableBrains()` returns `{ atoms, repls, clis }`, so the factory
   pattern matches atoms and repls exactly
4. **move the extant three operations behind it** — `asBrainCliSpawnArgs` becomes the boots/spawn
   adapter's internals, and its unit clamp moves with it rather than dies with it
5. ⚠️ **carry the spawn ENVIRONMENT, not only the argv.** #398's interface shape predates
   `CLAUDE_CONFIG_DIR`; `BrainCli.spawn` must own env vars as first-class, or this round's transport
   has no home in it

🔴 **what NOT to carry from #398:** its `scope=$hash` namespace under
`.agent/.brain/claude/config/`. the actor/clone model landed since, and `.agent/.actors/actor.via.*`
is the extant, governed home (`define.actor-clone-hierarchy`, `rule.forbid.per-clone-config`). the
adapter writes **into the actor dir**; it does not mint a parallel identity space.

## .why it is not done in this round

**SAFE?** ❌ no. it changes a published contract (`getAvailableBrains`) and moves a spawn path every
enroll depends on. the blast radius is every consumer of `rhachet`, not this feature's surface.

**CLEAN?** ❌ no. it ripples into a **second repo** (`rhachet-brains-anthropic`), it needs three new
published interfaces, and it rewrites a clamp test that exists specifically to catch this file's
change (`asBrainCliSpawnArgs.test.ts:39-45`).

⇒ both answers are no, so the deferral is `rule.always.fix-forward-under-scouts-honor`'s own verdict
rather than a preference. and the wish forbids a widened scope outright.

## .the sequence constraint

**after the boot-briefs behavior lands, and before a second brain cli is added.**

the sequence is not arbitrary. this round is what makes the seam's cost legible — it is the round
that adds four claude facts to an unowned boundary. do it **before** and the adapter is designed
against a transport that had not yet been ruled; do it **much after** and a second cli arrives with
no door.
