# 🌙 dream: git.release reads a red head as all passed

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic, `git.release`)
- caught 2026-11-24

## .the cue that fired

on `ehmpathy/rhachet#759`, `rhx git.release --watch` and `rhx git.release --retry` both printed
`👌 all checks passed` and `🫧 no runs inflight`, while `gh pr checks 759` listed a failed
`suite / test-shards-integration (dynamic, 2, 3)` on the head `81fe33e4`, and earlier a fresh
head whose runs were queued. so `--retry` retried naught and `--watch` watched naught.

## .the gap, precisely

the skill's status read does not key on the pr's current head sha: right after a push it
reports the prior head's checks, and on a red head it reports green. a driver who trusts it
reports ci green that is not.

## .the shape of the fix

read check runs for `headRefOid` of the pr (`gh pr view --json headRefOid`), treat a head with
no runs yet as `inflight`, never `passed`, and have `--retry` rerun the failed jobs of that
head's runs. clamp: a temp pr whose head has one failed job must read red and retry it.

## .why it is not done in this round

the skill lives in `rhachet-roles-ehmpathy`, not this repo; the fix is that repo's to ship.
