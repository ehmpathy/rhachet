# 🌙 dream: the next run names the processes an aborted run left

- kind = fix
- owner = rhachet
- caught 2026-11-16

## .the cue that fired

a peer review of `v2026_11_14.fix-acceptance-suite-shares-the-box` asked what happens to a
non-stub child when a human hits ctrl-c on an acceptance run. `jestAbortLeavesNoStub.integration`
proves the stubs end: each one ends on the ctrl-c, on its input end, or at its hard cap. a child
that is no stub has none of those.

## .the gap, precisely

- a ctrl-c ends jest before `onRunComplete`, so `ReporterAcceptanceBox` never sweeps
- a child a test spawned detached, in a session of its own, with no cap, hears no ctrl-c and
  lives on. it still carries the aborted run's `TEST_FNS_RUN` in its env
- the next run sweeps only its own run id (`getOneRunIdMintedHere`), and the residue notice counts
  only stub processes and dirs. so such a child is neither ended nor named

## .the shape of the fix

in `jest.acceptance.globalSetup.ts`, beside the residue notice, read every process whose env holds
a `TEST_FNS_RUN` and a `RHACHET_ACCEPTANCE_RUN_MINTER` whose minter pid is dead. those are an
aborted run's leftovers, from this checkout or a peer's. name them in the leftovers notice with
their pid, argv and cwd. do not kill them: a cmdline or env match can reach a peer's processes, so
the notice names them and leaves the act to the human (`rule.forbid.unscoped-process-kills`). a unit test of the "minter is dead" read, plus an
integration case that aborts a run with a detached child and checks that the next run names it.

## .why it is not done in this round

the wish asks that no brain stub and no fixture dir outlive a run, and both hold under an abort.
an arbitrary detached child is a wider class. its notice must not kill a peer's process, which
needs a design the reviewer did not ask for and this route did not vision.
