# 🌙 dream: one git-root resolver per cli

kind: fix · owner: ehmpathy/rhachet · caught 2026-09-24

## .the cue that fired

a self review for consistent mechanisms on `v2026_09_22.feat-boot-briefs-into-claude-md` found two
git-root algorithms in one cli.

## .the gap, precisely

- `src/infra/git/getGitRepoRootOrNull.ts` walks up to the nearest `.git`, a dir or a file, and
  returns null at the fs root
- `rhachet-artifact-git@1.1.5` `getGitRepoRoot` runs `find-up` for a `.git` dir and a `.git` file
  in parallel, then prefers the dir. so a worktree nested inside a repo's tree resolves to the
  OUTER repo (upstream `rhachet-artifact-git#19`, `#20`)
- the strict one is still called from `src/contract/cli/invokeRepoCompile.ts:43`,
  `src/contract/cli/invokeRepoIntrospect.ts:46` and
  `src/domain.operations/template/getTemplateValFromArtifacts.ts:12`
- ⇒ in a nested worktree, `rhx keyrack` and the cli context see one root, while `repo compile`,
  `repo introspect` and template artifacts see another

## .the shape of the fix

add `src/infra/git/getGitRepoRoot.ts`, a strict wrapper:
`getGitRepoRootOrNull({ from }) ?? BadRequestError.throw('not inside a git repository', { from })`.
point the three callers at it and drop the package import. clamp it with a nested-worktree case in
`getGitRepoRootOrNull.integration.test.ts`: the strict and nullable forms must agree.

## .why it is not done in this round

safe, but not clean for this pr: the `.git` walk (F30) is a scope rider whose ship-or-split call is
open with the wisher. to widen it to three commands the wish never touched would grow a rider the
wisher may split out. if the rider ships, this fix is a small follow-up. if it splits, the fix
rides with it.
