# 🌙 dream: `git.release --watch` must never report green while checks hold no conclusion

kind = reseed · owner = ehmpathy/rhachet-roles-ehmpathy (role=mechanic) · caught 2026-11-27

## .the cue that fired

right after `git.commit.push` opened pr #847, `rhx git.release --watch` printed
`👌 all checks passed` · `🫧 no runs inflight` · `✨ done! 0s in action, 0s watched`.
`gh pr checks 847` at once listed 13 jobs not yet concluded (types, unit, integration and
acceptance shards).

## .the gap, precisely

a fresh push has check runs queued that the watch does not count as inflight, so it reads zero
inflight as all-passed. a false green at the gate the rules name as proof of release readiness
(`rule.require.watch-release-after-push`).

## .the shape of the fix

read the pr's check rollup (`gh pr checks` states), not only runs inflight; treat queued and
unconcluded checks as inflight; refuse to report green while any required check holds no
conclusion. clamp: an integration case that watches a pr whose checks are queued and asserts the
watch waits.

## .why it is not done in this round

the skill is owned by another repo; a tree adopts only what is scoped to itself.
