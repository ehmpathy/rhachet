## .the cue that fired

peer review lane `enroll-verif-snapshot-blemishes` (i005 r010) on stone `5.3.verification`, route

> *"On a bind-fault, a human's terminal shows two differently-shaped outputs for one failure: a
> bare, unframed diagnostic line … immediately followed by the properly classified
> `💥 MalfunctionError:` frame. Every peer case in the same file (4–7) shows only the single clean
> framed report — so this is a real, visible shape inconsistency, not a hypothetical one."*

## .the gap, precisely

`blackbox/cli/__snapshots__/enroll.reach.acceptance.test.ts.snap` `[case8]` locks a screen that
holds **two** renders of one fault:

```
clone socket ready rejected with a bind fault: listen EACCES: …
💥 MalfunctionError: …
```

`[case4]`–`[case7]` each hold exactly one. so the inconsistency is measured, on a locked screen,
rather than argued.

it is **not** an oversight. `genCloneSocketServer.ts`'s `ready.catch` docblock states the trade
outright: the `ready` promise is unawaited on that path, so it needs *some* channel or a fault is
dropped in silence (`rule.forbid.failhide`). the test's own docblock says the row *"does NOT bless
that shape … makes the cost visible so the trade can be judged on a rendered screen."*

⇒ the row was written as an invitation to judge, and the judgment is what is owed.

## .the shape of the fix

route the unawaited `ready` rejection through the **same** composer the awaited path uses, so one
fault renders one frame:

1. in `genCloneSocketServer.ts`, replace the bare emit in `ready.catch` with a hand-off that reaches
   `asCloneSocketBindFaultError` — the classified error already exists and already renders correctly
   on the awaited path
2. keep a channel for the case where no consumer is attached yet; the requirement is that the fault
   is never dropped, and that does not compel a **second, unframed** render
3. re-snap `[case8]`; the expected diff deletes the raw line and leaves the frame

⚠️ **the anti-goal, stated so a later reader does not take the cheap route:** do NOT simply delete
the raw emit. it is the one channel that keeps this race from a silent drop, and its removal would
retire the escape and the evidence together. the fix is to give the fault a framed channel, never
to give it none.

## .why it is not done in this round

- **safe?** ⚠️ no. the emit sits on an unawaited-promise path, which is the shape most likely to
  behave differently under a real race than under a test. to move it needs its own clamp, and the
  clamp needs a way to provoke `EACCES` deterministically
- **clean?** ⚠️ no. it changes production error-flow in `genCloneSocketServer.ts`, which this
  branch's wish does not name — the wish is scoped to node-pty's install and the report it leaves.
  the bind-fault render was touched here only because it shares the classified-error composer

⇒ neither gate clears, so a dream is the correct outcome rather than a fix
(`rule.always.fix-forward-under-scouts-honor` → `rule.always.catch-dreams-for-followups`).
