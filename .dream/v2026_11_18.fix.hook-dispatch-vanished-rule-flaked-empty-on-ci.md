# 🌙 dream: the hook dispatcher once exited 0 with no rule stdout on ci

- kind = fix
- owner = rhachet (this repo)
- caught 2026-11-18
- status = fixed 2026-11-18, same branch

## .the cue that fired
ci run 44256732003, shard `test-shards-acceptance (dynamic, 5, 5)`, head `313d7c1`:
`blackbox/cli/hooks.dispatch.acceptance.test.ts` `[t18] a rule file vanished since the sync` got
`code 0` and `stdout ""`, where it expects `declared command ran`. the rerun of that shard passed.

## .the cause, found
the dispatcher stops its watchdog with a signal the moment the last rule ends. a child signaled
before its first command runs the parent's traps, so the watchdog ran the dispatcher's TERM trap
and then its EXIT trap, which removed the call's per-call files. the merge then read each absent
output file as a refusal. measured: `rhx bash.trap.inherit.probe`, 120 of 200 early-signaled
children ran the parent's EXIT trap; local suites showed `[t5]`, `[t10]`, `[t26]` flake with exit 2.

## .the fix
- the watchdog is stopped by USR1, which the dispatcher does not trap: an early USR1 ends it with
  no trap run
- the EXIT clean-up runs only where `BASHPID == $$` (bash ≥ 4)
- clamp: `[t27]`, 240 parallel one-rule calls. red with the fix reverted (4 false refusals), green
  with it
