- kind = reseed

## .the cue that fired

`rhx git.repo.test --what acceptance --scope 'path://brains.auth' --mode apply --resnap` matched
158 acceptance files, and the resnap rewrote five snapshots this change does not own before the
run was stopped. the same scope as a full path, `path://blackbox/cli/brains.auth.acceptance.test.ts`,
matched one file. a skill's own scope cue turned a scoped run into a sweep of the whole tier, plus a
blanket resnap.

## .the gap, precisely

a `path://` scope with a `.` in it matches every file of the tier. the cause, measured 2026-11-15 on
the credfree twin (`v2026_11_15.followup.credfree-scope-matches-the-worktree-path`): jest matches
the scope as a regex against each file's ABSOLUTE path, the `.` matches any char, and this worktree
is `rhachet.beav.feat-brains-auth-use-get-set`, so `brains.auth` matches the `brains-auth` in the
root dir of every file. so:

- the plan shows the 158 matches, but a `--mode apply` with `--resnap` gives no pause before it
  rewrites snapshots across the tier
- a dotted name is the natural way to scope a file named `brains.auth.acceptance.test.ts`

## .the shape of the fix

- treat a `path://` scope as a literal path fragment (escape regex metachars), or document it as a
  regex and escape `.` in examples
- refuse `--resnap` when the match covers more than a handful of files, unless a flag says so; name
  the count and the scope that produced it
- a clamp: a temp repo with `a.b.test.ts` and `axb.test.ts`; `--scope 'path://a.b'` matches one

## .why it is not done in this round

the skill lives in another repo (`rhachet-roles-ehmpathy`); here it is linked from node_modules.
the run was stopped, the five snapshots were restored to HEAD, and every run since then scopes by
full path.
