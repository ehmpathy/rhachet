dream =

we'd like the set of supported brains to be **open**, not a hardcoded Record in this repo — so
anyone can publish a brain-supplier package (`rhachet-brains-anthropic`, `rhachet-brains-openai`,
`rhachet-brains-google`, …) that declares its own brain-cli descriptor, and rhachet pulls it in.

## the seam today

right now `src/domain.operations/brain/getSupportedBrainCommand.ts` is the ONE source of truth for
two facts about a brain, and it is a literal map:

```ts
const brainCommands: Record<string, SupportedBrainCommand> = {
  claude:        { command: 'claude', socket: true },
  'claude-code': { command: 'claude', socket: true },
};
```

that `{ command, socket }` descriptor drives all the downstream facts:

- `command` — the executable `enrollBrainCli` / `genBrainCliPtyClone` spawn
- `socket` — the per-brain capability that gates `say` / `get` / the observe adapter, and decides
  whether a clone comes up LIVE (socket-eligible) or **MUTE** (no socket to hear a `say`)

so to add a brain today you must edit this core file. that is the friction.

## the dream

a brain SUPPLIER package declares its own descriptor and rhachet discovers it — the same way
`rhachet-roles-<supplier>` packages are discovered/linked into `.agent/repo=*/role=*` today. a
supplier ships a manifest (a `rhachet.brains.yml`, or an exported descriptor) that carries, per brain
slug:

- `command` — the cli executable to spawn
- `socket` — whether it can be routed through a managed-pty socket (say/get/observe)
- the per-brain **adapter refs** the socket needs: the observe-transcript reader (today
  `asCloneOutputText`, claude-jsonl-shaped), the native **resume** flag + how it surfaces the session
  `exid`, and the **dispatch** frame (the char-at-a-time / submit protocol)

`getSupportedBrainCommand` then becomes a lookup over the discovered descriptors instead of an inline
map. `rhx enroll <brain>` resolves the brain from any linked supplier; an unknown brain still fails
loud, but the supported set is now open.

## why

- **anyone can add a supplier we pull in** — a new brain-cli (codex, gemini, a local ollama wrapper)
  ships as its own package; no core edit, no PR to this repo
- it makes **"non-socket-capable brain" a REAL, testable case** — a supplier that declares
  `socket: false` is a live instance of the MUTE trigger that is only a latent branch today (the
  enroll-with-interface round left it untested on purpose because no such brain exists). a real
  supplier closes that branch honestly, with a real acceptance test, not a fabricated fake in the
  prod registry
- it is the natural home for the **per-brain observe adapter** the enroll-with-interface blueprint
  flagged as HELD — "reactive-lift when a 2nd brain ships". a 2nd brain is exactly what a supplier
  package is; the adapter (transcript shape, resume/exid, dispatch frame) lives beside the brain that
  needs it, not in a core switch that only grows

## sketch (a dream, not a spec)

```bash
# a supplier package, once published + linked, just works
rhx enroll anthropic/claude       # supplier-qualified brain slug
rhx enroll openai/codex           # a new brain, zero core edits
rhx enroll local/ollama --no-socket   # a supplier that declares socket:false → MUTE by design
```

- discovery: mirror the role-supplier pattern (node_modules resolution + a `rhachet brains link`, or
  the `.agent/repo=<supplier>/brain=*` layout) — reuse the extant supplier machinery, do not invent a
  parallel one
- the descriptor is versioned: the brain-cli contract (resume flag name, transcript path shape,
  dispatch protocol) can drift, so the supplier pins the cli version it adapts

## open threads

- manifest shape — a `rhachet.brains.yml`, or an exported typed descriptor const? (roles use the
  `.agent` link layout; brains could ride the same or ship a manifest)
- does `socket` decompose into finer capabilities — `pty?` `resume?` `dispatch?` `observe?` — so a
  brain can be observe-only (get, no say) vs fully MUTE? (this maps cleanly onto the LIVE/MUTE model:
  a brain with `observe:true, dispatch:false` is get-only, which IS what MUTE already means)
- slug resolution order across suppliers — local override, then supplier-qualified, then error that
  names the candidates (same shape as the actor-slug resolution in the clone-actor dream)
- how a supplier ships the observe adapter (`asCloneOutputText` equivalent) as code, not just config —
  a manifest can carry data, but the transcript reader + dispatch frame are logic
