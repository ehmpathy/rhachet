# 🌙 dream: git.commit.push garbles its pr number; git.release --watch reports green over pending checks

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic)
- caught 2026-11-27

## .the cue that fired

The push for ehmpathy/rhachet#846 hit both defects in one run.

## .the gap, precisely

1. **`git.commit.push --auth as-human`** printed `pr: pr #846\n1 (created)`. It then fed `846\n1` to `git.pull.watch set --which`, which refused it. The pr number read carries a second line, likely a count or a second gh output that was not trimmed.
2. **`git.release --watch`**, run seconds after the push, printed `👌 all checks passed` and `no runs inflight`, while `gh pr checks 846` showed unit, types, integration and acceptance all `pending`. The suite had not yet registered its jobs, and the watch read the absence of runs as a pass.
   - 🔴 this is a false green: a driver that trusts it reports a pr green that has not been tested.

## .the shape of the fix

1. Trim the pr number to its first `[0-9]+` match, and fail loud if the result is not an integer.
2. In `git.release --watch`, treat zero runs or any pending check as "not yet". Poll until checks register, with a bound, and never print `all checks passed` while `gh pr checks` lists a pending row.
   - Clamp: a test that stubs a pr whose checks are pending, which asserts the watch does not exit green.

Both skills live in another repo; the fix is a reseed there, not an edit here.
