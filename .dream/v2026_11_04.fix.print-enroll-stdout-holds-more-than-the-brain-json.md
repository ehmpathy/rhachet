# 🌙 dream: a print-mode enroll's stdout holds more than the brain's json

- kind = fix
- owner = rhachet (`invokeEnroll`, the print-mode spawn)
- caught 2026-11-04, in `.behavior/v2026_11_02.fix-boot-briefs-cacheable` 5.3 self review 7

## .the cue that fired

a captured run, not a tty:

```
$ npx rhx enroll claude --roles -driver -p 'reply with exactly OK' --model haiku --output-format json
😶 clone enrolled
   ├─ 🎙️ rhx clone say @:aff951a3 --what "…"
   └─ 🎧 rhx clone get @:aff951a3 --tail 50

{"duration_api_ms":808, … ,"result":"OK","type":"result", … }
[?25h
```

## .the gap, precisely

- a caller who asked for `--output-format json` gets a treestruct plus a blank line ahead of the json,
  so `| jq` fails. `boot.cache.probe` has to filter for lines that start with `{`
- the say and get hints name a clone that a print turn has already left DEAD
- a raw cursor escape (`ESC[?25h`) ends a stream that is no tty

🟡 the capture held stdout and stderr together, so which stream carries the receipt is not yet
measured. the first step of the fix is that read: `… >out.json 2>err.log`, then a look at each.

## .the shape of the fix

in print mode, keep the enroll receipt off stdout (stderr, or none), and emit no tty escape to a
pipe. pin it with an acceptance case: a print enroll's stdout parses as json whole.

## .why it is not done in this round

the receipt and the mirror predate this branch, and this wish does not ask for them. the fix touches
the enroll output contract that many snaps pin, so it needs its own change.
