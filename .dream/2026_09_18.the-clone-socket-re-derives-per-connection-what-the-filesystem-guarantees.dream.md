# 🌙 dream: drop the per-connection `ss` scan the clone socket's auth gate spawns

- kind = fix
- owner = ehmpathy/rhachet
- caught 2026-09-18

## .the cue that fired

a joker `clone say` wedged at 30s inside an 11-suite clone acceptance tier. the wedge report —
newly instrumented the same day — named which silence it was:

```
"wedgedMs": 30000, "reachCause": "wedged", "acksSeen": [], "silentMs": 30092
```

`acksSeen: []` means the server never acked at all, so the stall sat BEFORE the first frame. the one
step between accept and the first frame is the same-user auth gate, and that gate shells out to
`ss -xp` — a scan of **every unix socket on the host**, each mapped to the pid that holds it —
spawned fresh per connection. the host at the time carried 3 live brains and 15+ stale LIVE clones.

⇒ the immediate silence is **already cured** (`awaitCloneAuthGate` bounds the gate and NACKs
`auth-gate-timeout`, so the stall is now a classed, named, bounded reject). this dream is the
remaining question: **why is the scan there at all?**

## .the gap, precisely

a clone socket lives under `XDG_RUNTIME_DIR` — on this host `/run/user/1000/`, which systemd
creates mode `0700` and owned by uid 1000:

```sh
$ stat -c '%a %U %G' /run/user/1000
700 vlad vlad
```

so **the kernel already refuses a foreign uid at `connect()`** — a different user cannot traverse
the directory to reach the socket path, whatever the socket's own mode. the `ss -xp` scan therefore
re-derives, per connection, at O(host processes × fds), a fact the filesystem enforces for free.

checkable evidence:
- `src/infra/socket/getSocketPeerCred.ts` — `await execAsync('ss -xp | grep -E ...', { timeout: 5000 })`
- `src/domain.operations/clone/socket/isCallerSameUser.ts` — awaits it, compares uids, carries no
  bound of its own (the bound is now above it, in `awaitCloneAuthGate`)
- `getCloneSocketPath` — the path root is `XDG_RUNTIME_DIR`

## .the shape of the fix

`rule.prefer.prevent-over-correct` rung 1 (make it impossible) over rung 3 (catch it early):

1. **assert the directory guarantee at bind time, once per clone** — stat the socket's parent, and
   refuse to bind unless it is mode `0700` and owned by our own uid. a bind-time refusal is loud,
   happens once, and costs no per-connection work
2. then **drop the per-connection `ss` scan** — the gate becomes free, and the accept path writes
   its first frame with no async wait at all, which removes the whole class of silence the cure
   above had to bound
3. keep `SO_PEERCRED` as the ideal: node exposes no peer-cred read on a unix socket, which is why
   `ss` was reached for. if a native/`node:` surface appears, that is rung 1 done properly — a
   kernel-supplied uid, no subprocess, no directory inference

⚠️ what the fix must NOT do: drop the scan and assert naught. the directory guarantee is real and it
is also an **assumption about the host** — a clone bound outside `XDG_RUNTIME_DIR` (a repo-local
path, a shared `/tmp`) has no such protection, so step 1 is what makes step 2 safe.

## .why it is not done in this round

**SAFE: no. CLEAN: no.**

- it **weakens a declared auth gate** — `define.invariant.clone-socket-brain-cli-only` and its
  same-user companion are the whole "no shell access via a clone's socket" guarantee. to trade an
  explicit per-connection check for a bind-time directory assertion is a security-posture decision,
  and `F03` in `.behavior/v2026_09_11.fix-clone-say/1.vision.yield.md` already records that the
  socket's read/auth surface is **the wisher's call**
- it **ripples**: `getSocketPeerCred` has other callers, and the bind path in
  `genCloneSocketServer` would grow a new refusal with its own reason slug and its own clamp
- the measured symptom is already cured by a strictly-safer change (a bound can only refuse more),
  so the remaining benefit is cost, not correctness
