# 🌙 dream: confirm a live clone still reloads boot.md on /compact under claude-code ≥ 2.1.293

kind: fix · owner: rhachet · caught 2026-10-08

## .the cue that fired

`brain-dir-boot.journey` `[t4]` — *"after /compact the live clone quotes the new sentinel"* — went
red 2 of 2 in CI once the unpinned test install pulled claude-code 2.1.294. it passed on 2.1.292
(CI) and 2.1.283 (local) for the same commit.

## .the gap, precisely

- on 2.1.294 the compacted clone quoted `sntlshaperhead…` and `sntlshapertail…` but never
  `sntlshapernew…`, the line appended to `a.head.md` before `rhx init` re-rendered `boot.md`
- the same release moved the `haiku` alias to `claude-haiku-5-5`, so two variables changed at once
- the test install is now pinned to 2.1.292 (`CLAUDE_CLI_VERSION_PINNED` in
  `blackbox/.test/infra/genIsolatedClaudeHome.ts`, and the global install in
  `.github/workflows/.test.yml`), so the gap is hidden until the next bump

## .the shape of the fix

1. bump the pin to the newest claude-code in a branch of its own
2. run `[t4]` with `--model claude-haiku-4-5` and with `--model haiku` — tells the cli change from
   the model change
3. if the cli no longer reloads memory files on `/compact`: the sync invariant's *"live clones on
   their next read"* clause needs a new trigger (or a narrower promise in
   `define.brain-dir-repo-vs-actor`); if it is the model: sharpen the sentinel ask

## .why it is not done in this round

the local box timed out on clone spawns, so the two variables could not be split here; the fix may
change a product promise, which is a scope call beyond a boot-budget release.
