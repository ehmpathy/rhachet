# 🌙 dream: a `.agent/repo=.this` role declares its own brain hooks via a hooks file

- kind = feature
- owner = ehmpathy/rhachet
- caught 2026-10-06, at `v2026_09_17.feat-boot-manifest-and-budget`, after the route closed

## .the cue that fired

the boot-budget behavior needed an onStop hook for `.this` roles. a `.this` role has no package, so
it had no way to declare a hook, and the drive built `role=*/hooks.yml` as that channel. the wisher
saw it as a good idea in general, but too large a surface to ride along in a budget PR. the budget
hook became a framework-owned built-in instead, and the general file was pulled out to its own PR.

## .the gap, precisely

- `src/domain.operations/brains/getLinkedRolesWithHooks.ts` reads hooks only from a role
  **package** (`Role.hooks.onBrain`, via a dynamic import). a role under `.agent/repo=.this` is a dir,
  not a package, so it cannot declare a hook at all
- so a repo that wants a hook for itself hand-edits `.claude/settings.json`. that file is the brain
  adapter's output: the sync rewrites it, and the hand edit is not relayed to an actor's brain dir
- the one hook a `.this` role does get, the boot-budget onStop gate, is framework-owned and built in;
  that is the sole exception, and it does not generalize

## .the shape of the fix

one file per `.this` role, beside `boot.yml`, with the same contract a package declares in code:

```
onBrain:
  onBoot:  [{ command, timeout: PT30S, filter?: { what } }]
  onTool:  [{ command, timeout, filter?: { what, when: before|after } }]
  onStop:  [{ command, timeout }]
  onTalk:  [{ command, timeout }]
```

- a reader beside `getLinkedRolesWithHooks`, which turns each `.this` role dir with the file into a
  `HasRepo<Role>` (`repo: '.this'`) and pushes it into the same sync as a supplier's roles. the
  author label stays `repo=.this/role=$slug`
- validate with zod; an ISO 8601 timeout; a malformed file is an error for that one role, never a
  throw that sinks the sync for all others
- the read IS the check (no `existsSync` race); a vanished file re-classes to a `ConstraintError`
- the full prior implementation, schema and tests, sits in this branch's history under
  `getAllRepoThisRolesWithHooks.ts` before its hooks-file read was removed

### 🔴 the open choice the PR must settle first — the format

| | `hooks.yml` | `hooks.jsonc` |
|---|---|---|
| for | every peer file a role dir declares is yaml (`boot.yml`, `keyrack.yml`, `actors.yml`); the contract is rhachet's own vocabulary (`onStop`, `PT30S`), not one brain's | claude's `settings.json` is json, so a hook reads close to where it lands; the repo already keeps `.jsonc` for `.meter/*` state |
| against | a hook copied from `settings.json` must be re-shaped | the one json file among yaml peers; couples the look to one brain adapter |

the wisher leaned `hooks.jsonc` for the consistency with claude's settings, and asked whether both
could be kept. the drive advised **one format only**: two parsers, two error vocabularies, and a
rule for when both are present (refuse? merge? which wins?) all buy naught a single format lacks.

## .why it is not done in this round

safe, but not clean. it is a new public config surface, a contract every `.this` role author would
learn, and it deserves its own review rather than a footnote in a budget PR. the wisher moved it out
by name.
