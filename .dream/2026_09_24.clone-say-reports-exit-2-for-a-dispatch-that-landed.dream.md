# 🌙 dream: `clone say` reports exit 2 for a dispatch that DID land

- kind   = fix
- owner  = ehmpathy/rhachet (this repo)
- caught = 2026-09-24, at `5.3.verification` of `v2026_09_17.feat-boot-manifest-and-budget`

## .the cue that fired

the acceptance tier returned 5 failures. four were mine (an inherited-clone-env leak, repaired
this round). the fifth — `clone.joker.realbrain.acceptance.test.ts` `[t3]` — was **not**, and the
first two stories for it were both refuted by measurement:

| the story | what refuted it |
|---|---|
| *"the same clone-env leak — `[t3]` is the only BY-SERIAL turn"* | `invokeCloneWhoami.ts` is the **only** consumer of `RHACHET_CLONE_SERIAL` on the cli path. a `say --to @:<serial>` never reads it |
| *"a co-scheduled real-brain flake"* | it reproduces no failure in isolation (19/19), which is **consistent** with a flake and proves none. the log settled it instead |

## .the gap, precisely

`sayAndPollForMarker` (`blackbox/.test/infra/enrollCloneHarness.ts:590-694`) prints a rich
diagnostic — `say.status`, `say.stderr`, the last `get` read, the brain's own screen — on **one**
condition: every attempt spent with the marker never landed (`landed: false`, `:676`).

**that diagnostic does not appear in the failing run's log.**

```
$ Grep 'dispatch NEVER landed' .log/…/what=acceptance/2026-09-24T13-41-13Z.stderr.log
No matches found
```

⇒ the loop returned from **inside** its poll (`:657-658`), which is the one path that returns
`landed: true`. and `said` latches that same attempt's say result. so what the run observed is:

```ts
expect(turn.said.status).toEqual(0);   // ← RED: received 2
// landed === true — the marker DID appear in `clone get --tail 10`
```

> 🔴 **`clone say` exited 2 — the declared fail-loud "not delivered" — for a message that was
> delivered.** the marker `markerFor(3)` is unique per turn, so no prior turn's tail can supply it.

### why that is a PRODUCT defect and not a test flake

the harness states the shipped consumer contract verbatim (`:626-634`):

> *"a wedged/undelivered say is the FAIL-LOUD signal (exit 2), and the wish's real consumer (a
> cron/comms handler) RETRIES it."*

⇒ if exit 2 can also mean *delivered*, then **the documented consumer double-sends**. a comms
handler re-dispatches a message the brain already received and answered. the retry contract rests
on exit 2 being a reliable negative, and this run measured it as a false one.

🟡 **so the test is doing its job and must not be weakened.** to relax `expect(said.status).toEqual(0)`
to accept 2, or to assert only `landed`, would convert a caught product defect into a green run —
the exact shape `rule.forbid.failhide` names, and what the `5.3` stone's *"preserve test intentions"*
clause forbids (*"the test knew a truth"*).

## .the shape of the fix

**1 — locate the delivery confirmation and make exit 2 a true negative.** the say path returns a
`ConstraintError` exit before the socket write is confirmed, or it confirms on a signal that races
the brain's input-reader settle window (the same window `:626-634` already documents for the
*wedge* direction). the two candidate repairs:

| repair | shape |
|---|---|
| **confirm-then-exit** | the say does not exit until the write is acknowledged, so exit 2 cannot follow a delivery |
| **a third exit code** | keep 0 = confirmed, 2 = confirmed-not-delivered, and add one for *unconfirmed* — the state the consumer must poll rather than blind-retry |

⇒ prefer the first. a third code grows the consumer's branch set; the second only relabels the
ambiguity a consumer must still settle for itself.

**2 — clamp it (`rule.require.clamp-edge-cases`).** the natural clamp is the one that already
caught it: assert that a say whose marker lands within the poll exited **0**. it needs to bite
under the settle-window race, so the clamp is a real-brain or a stub-brain suite that dispatches
into the window deliberately rather than by luck.

**3 — make the SUCCESS path observable too.** the diagnostic at `:676` fires only on exhaustion, so
a `landed: true` with a non-zero `said.status` passes through the harness in total silence and
surfaces only as a bare `Received: 2` at the caller's `expect`. one line at the return site —
*"landed on attempt N, say exited M"* — would have named this in the first read rather than the
fourth.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** the repair changes when `clone say` is permitted to exit, on the socket dispatch path. this behavior (`feat-boot-manifest-and-budget`) touches the boot renderer and does not reach `clone say` at all — so a change there is behavior beyond what this diff came for, on a path this diff cannot exercise |
| **CLEAN?** | no. it ripples into the documented consumer contract, its exit-code semantics, and every caller that branches on exit 2 |

⇒ row 3 of the verdict table — **unsafe is a harder stop than unclean** — so it defers, and the
deferral owes both a dream (this file) and a fulcrum, because the dirt call is a judgment about
ripple cost (`F45`).

### 🔴 what the deferral does NOT get to claim — a correction, made against this file's own table

an earlier draft of this section read: *"the deferral is **bounded** rather than open: the failure
reproduces under co-schedule, **never in isolation**, so it does not block this round's green tier."*

🔴 **that is the exact inference the table at the top of this file refutes**, restated 80 lines later
as a premise. row 2 there says a clean isolated run *"is **consistent** with a flake and proves
none."* a bound built on it is built on the refuted half.

and it matters, because **this file's own `.the shape of the fix` names a settle-window race.** a
race is **load-dependent**, never co-schedule-dependent:

| what the bound assumed | what a race actually implies |
|---|---|
| it fires only when suites run together | it fires whenever the window is missed — a loaded CI runner, a slow host, a busy prod box |
| 19/19 solo on this machine ⇒ bounded | 19/19 on **one machine, once** ⇒ a sample, never a bound |

⇒ **the honest statement is that the trigger is unknown**, and the two ways to settle it are each
refused for a reason: N solo runs of a real-brain suite cannot prove a negative, and the suite costs
money and time per run (`rule.forbid.local-full-test-sweeps`).

🔴 **so the disclosure goes UP, not down.** the SAFE verdict is unchanged — severity is not an input
to SAFE/CLEAN — but this defect is recorded as **trigger unknown, possibly live**, rather than as an
artifact that a real deployment would never meet. what it blocks is the claim that exit 2 is a
reliable negative, and that claim belongs to the clone behavior rather than to this one.
