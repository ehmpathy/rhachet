# 🌙 dream: the hook sync reports `~N updated` for hooks it did not change

- kind  = fix
- owner = **ehmpathy/rhachet** — `syncAllRoleHooksIntoEachBrainRepl` + the claude-code adapter's `upsert`
- caught 2026-09-25

## .the measured defect

two back-to-back `npx rhachet init --hooks` on this repo. the second is a pure no-op, and the tracked
`settings.json` is byte-identical to its staged form after both (`git diff --stat` empty):

```
🪝 apply hooks to brains...
   ├─ bhrain/driver → anthropic/claude/code: ~5
   ├─ bhrain/learner → anthropic/claude/code: ~1
   ├─ bhuild/behaver → anthropic/claude/code: ~1
   └─ ehmpathy/mechanic → anthropic/claude/code: ~14

✨ hooks
   └─ 21 updated

🧢 apply hooks to enrolled actors...
   ├─ 8169357d: ~21
   ...
```

⇒ **`~` counts a rewrite, never a change.** every extant hook is upserted and tallied as `updated`,
whether or not a byte moved.

## .why it matters

- `rule.require.status-feedback` — *"after a mutation, name what changed."* a report that names 21
  changes when none occurred is a false report, not a verbose one
- 🔴 it erases the one signal the tree is there to carry: a human cannot tell a real hook drift (a role
  bumped a timeout, a command moved) from the steady state, because both print `21 updated`
- the brain-dir tree beside it already holds the right contract — *a no-op emits naught* — so the two
  adjacent reports in one stdout disagree on what silence means

## 🔴 .and a snapshot already defends it

`brain-dir-boot.journey` pins `~1 updated` on an idempotent re-run (`[t4]`, `[t5]`, `[t5.1]`). that is
the mechanism `v2026_09_25.reseed.a-snapshot-defends-an-output-shape-nobody-reviewed` names: the
overclaim reads as contract because it is green.

## .the shape of the fix

- the adapter's `upsert` compares the desired entry to the found one and returns `found` when they are
  equal, `updated` only when a field differs
- the sync tallies only `created` · `updated` · `deleted`; an unchanged hook is silent
- a fully unchanged sync prints `✨ hooks: no changes needed` — that branch is already in place
  (`syncHooksForLinkedRoles.ts`, the `else if` beneath the tally) and is simply never reached
- ⚠️ resnap owed: every snapshot that pins `~N` on a re-run changes, and each such hunk is the fix, never
  a regression

## .why it is not done in this round

- it is **pre-extant on `main`** — this branch never touched the upsert path — so it is outside the
  route's wish (`rule.always.scope-onetime-lessons-to-the-behavior`)
- the route is at `5.5.playtest`, halted on human approval
