# 🌙 dream: a PER-FILE emit may lift the adhoc boot's bound, and the cap's scope is unmeasured

- **kind** = feature
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-22

> 🟡 **this is an OPTIMIZATION of a path this behavior already settles, never a gap in it.**
> `.seeds/…case=S10` rules that adhoc boots take **candidate A** — a declared token budget that
> halts at authoring time. this dream carries the idea that could later raise A's bound, plus the
> one measurement that decides whether the idea works at all.

## .the cue that fired

the wisher observed that **behaviors easily go over 10k**, and asked whether a boot invoked as
`rhx boot --when hook.onBoot` could **partition each brief file into its own stdout emit** — so
that the hard bound binds **per file** rather than per corpus.

⇒ the arithmetic, if it holds:

| | one emit | per-file emits |
|---|---|---|
| the hard bound | 10,000 chars, for the whole corpus | 10,000 chars, **per brief** |
| a corpus of 40 briefs | ~250 chars each — unusable | up to 400,000 chars |

🟢 **and the partition is natural rather than contrived.** a brief file is already the unit of
authorship, so there is no chunk scheme to invent, no reassembly to perform, and no split that
lands mid-rule. *"each file must fit; the whole boot need not"* is a contract a human can hold in
their head.

the external research stone settled it from first-party docs, so no probe is owed:

> *"Claude Code measures each string on its own, even when several hooks run for the same event."*

⇒ **N briefs emitted as N fields each clear the 10,000-char bound independently.** the arithmetic in
the table below holds as written, and the *"aggregate"* row is struck.

🟡 **two riders the answer carries:**

- **no env var raises the cap** — surveyed by that stone and not found. so the per-field partition
  is the only lever, never one lever among several
- overflow still lands in a session-dir file plus a **≤2,000-char preview Claude is never asked to
  read** `[B-17]` ⇒ the interim manifest-header design below stays correct, because a per-file emit
  bounds each brief and a single over-large brief still truncates

🔴 **candidate A is unchanged**, per the section below: this raises the bound A enforces and does
not retire A.

⇒ **what remains is step 2 alone** — the render mode on `genBootPayload`, which waits on that peer
branch and on `F13`'s verdict about which round owns the adhoc half.

## 🔴 .the gap, precisely — the cap's SCOPE was never measured (ANSWERED, above)

the 10,000-char cap landed at **2.1.89**. the changelog states the bound; **it does not state
what the bound applies to.** two readings, and the partition idea lives or dies on which is true:

| reading | consequence for the partition |
|---|---|
| **per hook invocation** — each hook's stdout gets its own allowance | 🟢 the idea works. N hooks, N allowances |
| **aggregate** — all hooks on one event share one allowance | 🔴 the idea buys naught. the partition just relocates the truncation |

### ⚠️ this session's evidence CANNOT discriminate, and it reads as though it can

15 role boots totalling **625,561 chars** fired on one `SessionStart` here and **every one
arrived whole**. that reads as proof of the per-invocation reading, and it proves naught:

> **the binary that wins `PATH` on this host is `2.1.87` — below the cap's own version.** so the
> cap applied to neither the parts nor the whole, and a whole-corpus survival at 62× the bound
> is exactly what an absent cap looks like.

⇒ **the probe must run on a binary at or above 2.1.89.** `2.1.278` is installed on this host
(`~/.local/share/fnm/aliases/default/bin/claude`), so the measurement needs no new machine.

## .the shape of the fix

### ✅ step 1 — the measurement, which is the whole gate — **ANSWERED, no probe owed**

> settled from first-party docs by external research T3 `[B-17]`: **per field**. the probe design
> below is retained as the record of what would have been run, and is now moot.

two `SessionStart` hook entries on one event, each emitting **6,000 chars** with a distinct
marker at its head and its tail. 6,000 + 6,000 = 12,000, over the bound; each alone is under it.

```
both tail markers survive  →  per-invocation  →  the partition works
either tail marker absent  →  aggregate       →  the partition is struck
```

run it under `2.1.278` with a `--settings` file, so the repo's own hooks do not enter the count.

### step 2 — the emit seam, only if step 1 returns per-invocation

🟢 **the seam already exists and points the right way.** the peer branch's `genBootPayload`
assembles the corpus to a **buffer** and returns it without emit, precisely so that several
consumers may render it differently. a per-file emit is a **render mode** on that buffer — one
more consumer of an extant seam, never a second renderer.

⇒ so the change is bounded: `--when hook.onBoot` selects a render mode that walks the corpus and
emits one hook output per brief, where every other destination emits one buffer.

⚠️ **and the two bounds must stay separate in the contract.** `budget.tokens` remains the
**corpus** bound the author declares; the 10,000 chars becomes a **per-file** bound the renderer
enforces. a design that conflates them re-creates the very cap it set out to lift.

## .what this does NOT change

🔴 **candidate A stands either way.** the budget gate is not a workaround this dream would
retire — the wisher framed its cost as its benefit: *a declared bound is what makes folks write
thinner behavior yields*, and its four remedies (catalogize · condense · reference · eliminate)
each improve the artifact rather than merely shrink it.

⇒ **a per-file emit would RAISE the bound A enforces. it would not remove A.**

## .why it is not done in this round

the SAFE/CLEAN test:

- **safe?** ✅ **yes** — the probe touches no production code, and the render mode is additive
- **clean?** ⚠️ **no.** it needs a measurement the round did not take, and its outcome is
  **binary**: one answer makes it a small render-mode change, the other strikes it entirely. to
  build against an unmeasured fork is to build twice

🔴 **and the wisher bounded the scope directly:** *"the most important is the role boots; the
adhoc boots can be better supported separately."* the role corpus rides the **system-prompt
file**, which this cap does not touch at all — so the cap's scope has **no bearing on the p0**.

⇒ **this dream is an adhoc-path optimization, and the p0 is a role-path repair.** they part
cleanly, and that is why the deferral costs the deadline naught.

## .the interim design the wisher ruled — degrade with dignity

until the probe runs, the adhoc hook emits a payload built to survive its own truncation:

1. **a header that enumerates the whole boot manifest** — every file, by path, as a `ref`
2. **then the content that was asked for**, in priority order
3. **authored in the knowledge that most of it will be truncated**

⇒ 🟢 **that order is what turns a silent defect into a legible one.** truncation cuts the
**tail**, so a manifest at the **head** always survives — and a clone that holds the full list of
paths can `Read` what it was not handed. it is cell #4's failure mode converted from *"briefs
silently absent"* into *"briefs named and fetchable."*

⚠️ **the manifest is a fallback, never a substitute** — a path a clone *may* read is weaker than
a brief it *was given*. the fallback's job is to make the loss visible and recoverable, and that
is the whole of its job.
