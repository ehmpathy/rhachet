# 🌙 dream: `getOneRepoPath` does not collapse a git WORKTREE, and two docblocks claim it does

- **kind** = fix
- **owner** = `ehmpathy/rhachet`
- **caught** = 2026-09-23

## .the cue that fired

a peer review lane graded a claim in `3.3.1.blueprint.product.yield.md` that had been **inherited on
faith** from a docblock and then used as evidence. the blueprint checked it against source and the
lane was right: the docblock is false in half of what it asserts.

⇒ every other claim in that document is checked rather than assumed; this was the one place the
discipline lapsed, and it lapsed because a `.note` *sounded* authoritative.

## .the gap, precisely

`src/infra/host/getOneRepoPath.ts` canonicalizes with exactly one call:

```ts
const real = realpathSync(input.from);   // expands SYMLINKS only
```

and its own docblock says:

> *"expand symlinks (realpathSync) to the true path, and drop a trailing slash, so a
> **worktree**/symlinked cwd always canonicalizes to the same string"*

| the hop | collapsed? |
|---|---|
| a symlinked cwd — `/tmp/link → /home/repo` | ✅ yes |
| a slash at the end — `/repo/` | ✅ yes |
| 🔴 a **git worktree** — `_worktrees/repo.branch` | ⛔ **no** |

**a git worktree is not a symlink.** it is a genuinely distinct directory tree, joined to the main
repo through `.git` refs, never through an fs-level indirection. `realpathSync` cannot collapse it
and does not.

⇒ and `getActorsRootDir` roots the actor tree *inside* what it expands to — `join(repoPath,
'.agent', '.actors')` — while it repeats **the identical unverified claim** in its own `.note`.

⇒ **two worktrees of one repo enroll two fully independent actors**: separate corpus, separate role
history, separate clones, no error, no warn, no cross-link.

checkable today:

```
# from two worktrees of one repo
node -e "console.log(require('fs').realpathSync(process.cwd()))"
# → two different strings ⇒ two different <repoPath>/.agent/.actors/ trees
```

## .a DOC defect for certain, and a BEHAVIOR question that needs a human

these are two different claims and they must not be settled together:

| the claim | status |
|---|---|
| the docblocks say `realpathSync` collapses a worktree | 🔴 **false, certainly.** a doc defect, and cheap |
| one-actor-**per-repo** is the intended behavior | ⚠️ **unknown.** nobody has stated it |

⇒ the second is the expensive one, and the harm exists only if the answer is *per-repo*: a human
enrolls in one worktree, expects the same actor from the next worktree over, and gets silent
divergence instead. **per-worktree may well be correct** — a worktree often holds a different branch
with a different roleset, and an actor that followed a human across worktrees would carry the wrong
briefs.

## .the shape of the fix

**part 1 — the doc defect, unconditional.** drop `worktree` from both `.note`s and state what is
actually true: *"expand symlinks and drop a trailing slash, so a symlinked cwd canonicalizes to the
same string. ⚠️ a git worktree is a distinct tree and is NOT collapsed — each worktree enrolls its
own actor."* two files: `getOneRepoPath.ts`, `getActorsRootDir.ts`.

**part 2 — a clamp, so the behavior stops being folklore.** an integration test that canonicalizes
from two worktrees of one temp repo and asserts they **differ**. it costs a `git worktree add` in a
temp dir and it pins whichever behavior the verdict settles on.

**part 3 — only if the verdict is one-actor-per-repo.** expand to the **common** dir
(`git rev-parse --git-common-dir`, then its parent) rather than the cwd. ⚠️ that is a real behavior
change with extant callers and its own migration: every actor dir under a worktree would be
orphaned, so it needs the versioned-prefix treatment
`define.enrollment-identity-is-the-roleset-hash` already prescribes for a hash-shape change.

## .why it is not done in this round

- **SAFE?** 🔴 no, for parts 2–3. `getOneRepoPath` is extant with callers across enroll, clone, and
  the actor tree; a change to what it returns relocates **every** actor dir on disk.
- **CLEAN?** 🔴 no. it ripples into `getActorsRootDir`, `findsertActorOndisk`, and any test that
  pins an actor path — files this wish never intended to open.

⇒ both answer no, so `rule.always.fix-forward-under-scouts-honor` routes it here. and the wish's
bound is explicit: *"do not widen into unrelated boot work."* **this defect is upstream of aught the
boot refactor touches** — it predates the wish and survives it either way.

🟡 **part 1 alone is safe and clean**, and would normally ride along under scouts honor. it is held
back only because it is the *evidence* for parts 2–3: to correct the docblock and leave the behavior
unruled would hand the next reader a fact with no owner. ⇒ ship part 1 **with** the verdict.

## .the revisit trigger — so it does not sit here forever

| trigger | how to check it |
|---|---|
| **a human reports an actor "absent" after a worktree switch** | the actor is not gone; it belongs to the other worktree. this is the symptom the harm predicts, and the first report settles part 2's verdict |
| **the next change to `getOneRepoPath` or `getActorsRootDir`** | whoever opens either file is already in the one place part 1 lands, and will read the false claim on the way past |
